Measure how much a label must change

A typed course label may be close to the intended label but contain an extra, missing or wrong character. Edit distance measures the least cost of converting one string into another using specified operations. Here inserting, deleting or replacing one character each costs one. Keeping an equal character costs zero.

For CAT and CUT, keep C, replace A with U, and keep T. The distance is one. For an empty source and target AB, insert A and B, giving distance two. These examples show why the boundary states cannot all be zero as they were for LCS.

The model matters. Swapping two adjacent letters is not a primitive operation in this lesson. AB to BA costs two, through two replacements or a deletion and an insertion. A distance model allowing transposition could give another answer. State the allowed operations before comparing two distance values.

Edit distance is useful for approximate matching, but a small numeric distance does not automatically mean two labels have the same real meaning. The algorithm reports a character-edit cost under its model. Choosing a correction suggestion or accepting a name match also depends on the surrounding application's rules.

        dp[i][j] = min(diagonal, dp[i-1][j]+1, dp[i][j-1]+1)
        record diagonal, up, left in that tie order
walk predecessors; reverse the alignment operations
return distance and edits

Step 1, state: dp[i][j] is the minimum cost to convert the first i source characters into the first j target characters. Row zero represents an empty source, and column zero represents an empty target. Set dp[i][0]=i for deletions and dp[0][j]=j for insertions.

Step 2, recurrence: compare three candidates. A diagonal predecessor costs dp[i-1][j-1] plus zero for equal final characters or one for replacement. An up predecessor costs dp[i-1][j]+1 for deletion of the source endpoint. A left predecessor costs dp[i][j-1]+1 for insertion of the target endpoint. Take the minimum.

The meanings of up and left follow the direction source-to-target. Moving up removes a source character from the remaining conversion problem, so it explains a deletion. Moving left removes a target character that must have been inserted. Switching the interpretation while keeping the recurrence values gives the right number but a wrong edit explanation.

Fill the prefixes and save a direction

Step 3, order: fill rows i=1..n and columns j=1..m. Diagonal, up and left dependencies are complete before the current cell. The C code tries diagonal first, then replaces it only for a strictly cheaper deletion or insertion. This gives the tie order diagonal, up, left.

At CAT versus CUT, matching C creates dp[1][1]=0. Prefix CA versus CU has unequal endpoints A and U. Its diagonal candidate is 1, while insertion and deletion candidates are 2. The table saves replacement. The final matching T extends that alignment without increasing the cost.

Step 4, reconstruction: start at the bottom-right state. Identify a predecessor whose transition equals the stored value, using the same tie order. A diagonal with equal characters emits no paid operation; an unequal diagonal emits a replacement. Up emits deletion, and left emits insertion. Continue until both prefix lengths reach zero.

The lab shows those directions in a grid and highlights the recovery path. It reverses the recovered paid edits before displaying them. The C implementation instead recurses to each predecessor before printing the current paid edit. Both present a forward alignment rather than backward recovery order.

Read the edits as a forward alignment

The operation descriptions identify source and target characters in alignment order. They do not include mutable string indices. To apply the alignment interactively, keep a cursor in the current string. A match or replacement advances the cursor, an insertion writes before it and then advances, and a deletion removes the current source character without advancing past the next one.

If a program must emit executable indexed edits, it should also retain matches or explicit aligned coordinates so cursor movement is known. Printing delete A alone is ambiguous when several A characters occur. The current exercise asks for an explanatory alignment, and its deterministic rule chooses one of several possible minimum explanations.

Boundary recovery is essential. When i=0 and j>0, only insertions remain. When j=0 and i>0, only deletions remain. A loop that stops when either coordinate becomes zero would omit those operations. That stopping condition worked for LCS because its remaining empty-prefix length is zero, but not for edit distance.

For identical strings, the path consists entirely of free diagonal matches and prints no paid edits. For an empty source, all operations are insertions. For an empty target, all are deletions. A complete implementation covers these with its normal boundary checks rather than inventing a mismatch symbol to stand for emptiness.

The last aligned operation is exhaustive

Take any valid alignment converting the two prefixes. Its final action either pairs their final characters, deletes the source endpoint, or inserts the target endpoint. Those actions lead exactly to the diagonal, up and left predecessor states. Removing the final action leaves a conversion of the corresponding smaller prefixes.

If that smaller conversion were not optimal, replacing it with a cheaper one would improve the whole alignment. Thus an optimal alignment uses an optimal predecessor for one of the three actions. Conversely, adding the action to any valid predecessor creates a valid current conversion. Taking the minimum of their costs is both attainable and no greater than any other alignment.

The boundary costs count the necessary edits against an empty string. Inducting over i+j proves the recurrence values. Every dependency decreases that sum, so the chosen table order respects the proof. During reconstruction, following a cost-equal predecessor preserves the stored optimum, and decreasing coordinates guarantees termination at (0,0).

Unit nonnegative costs also explain some basic checks. Distance is zero for identical strings. It is at least the absolute difference of their lengths, because replacement cannot change length. It is at most max(n,m), by replacing the shared-length portion and inserting or deleting the excess. These inequalities are useful independent checks on table outputs.

Prefix pairs determine work

The full table contains (n+1)(m+1) cells. Each interior cell compares three constant-time candidates, giving Θ(nm) time for nonempty lengths and Θ(nm) table space. Recovery visits at most n+m transitions. A forward-recursive recovery uses O(n+m) stack depth in addition to the table; an iterative recovery can store and reverse the path instead.

Two rows suffice when only the distance is needed. Retain the previous row and current row while scanning columns, using O(min(n,m)) table memory after choosing the shorter column dimension. As with LCS, that compressed calculation does not preserve every predecessor for the simple recovery routine.

The bounded demonstrations use at most sixteen characters in either input, so distances are at most sixteen under unit costs. int easily holds all entries. A weighted variant with large operation costs needs a wider range calculation. Numeric safety must account for a predecessor plus its operation cost, not only the final answer.

Different costs define different recurrences

If insertion, deletion and replacement have fixed nonnegative costs, multiply the boundary values by the corresponding operation cost and adjust each candidate. If replacement costs more than deletion plus insertion, the minimum may choose those two operations instead of a replacement. The three-candidate recurrence already permits that route.

Character-dependent costs may reflect a keyboard or a domain-specific penalty, but their meanings must be written explicitly. Costs depending on a whole run, such as a special price for a block insertion, can require additional states. Reusing the unit-cost table unchanged would not model that dependency.

Threshold queries ask whether the distance is at most a budget. The exercise computes the complete distance, then compares it with that budget. More advanced banded evaluation may skip cells when a small threshold restricts feasible alignments, but it needs careful unreachable handling. Returning early on the first large cell is not valid because another path may still be cheap.

Keep costs and directions consistent

Zeroing the first row and column allows characters to appear or disappear for free. Initialise them to their prefix lengths under unit costs. Adding one for a matching diagonal is also wrong; keeping an equal character should cost zero. CAT to CAT is a quick test for that mistake.

A replacement changes one source character into one target character. It does not consume only one of the strings. Decrement both coordinates for diagonal recovery. For insertion decrement only j, and for deletion decrement only i. These coordinate meanings should match the arrows and the printed operation names.

Comparing this distance with the LCS deletion formula can expose a model mix-up. AB to AC needs one replacement here but two total deletions to make both strings equal. Both numbers are correct for their own permitted actions. Avoid applying the deletion-only identity to a problem that also permits replacement.

C17 text limits

The programs use string.h for strlen and strcmp, with buffers of seventeen characters for sixteen input letters plus a null terminator. Whitespace-token exercises use - to represent empty input. The algorithm treats bytes as characters, suitable for the stated uppercase Latin alphabet; multi-byte Unicode text would need decoding into the intended character units first.
