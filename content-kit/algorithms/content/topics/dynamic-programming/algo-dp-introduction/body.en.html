Remember an answer instead of repeating work

Imagine being asked the same small calculation several times while solving a larger problem. You could recalculate every time, or write the answer down and reuse it. Dynamic programming, often shortened to DP, organises this reuse. It solves a family of related subproblems and stores their answers.

A state describes exactly which smaller problem an entry answers. A transition explains how one state depends on others. A base case gives an answer without further dependencies. Once those pieces are clear, you can decide whether to compute states on demand or fill them in a planned order.

Fibonacci numbers make the mechanics visible. Define F(0)=0, F(1)=1 and F(n)=F(n-1)+F(n-2) for n>=2. The first values are 0,1,1,2,3,5,8,13. Fibonacci is not an optimisation problem, but its repeated dependencies clearly demonstrate why remembering states helps.

For optimisation problems, you also need optimal substructure: an optimal answer can be assembled from appropriate optimal subproblem answers. Overlap and optimal substructure are different properties. Overlap explains saved work; optimal substructure justifies the recurrence used to select the best answer. Fibonacci demonstrates overlap without requiring a maximum or minimum objective.

State and recurrence before a table

dp[0] = 0; if n >= 1: dp[1] = 1
for i = 2 to n
    dp[i] = dp[i - 1] + dp[i - 2]
return dp[n]

Step 1, state: dp[i] means the exact Fibonacci value F(i). The index is not a recursion depth or a count of calls. Step 2, recurrence: for i>=2, dp[i]=dp[i-1]+dp[i-2]. Set dp[0]=0 and dp[1]=1 when the requested range includes index one. These meanings completely specify each table entry.

Step 3, filling order: increasing i works because both dependency indices are smaller. Step 4, reconstruction: Fibonacci returns one number, so there is no chosen path or sequence to recover. Read dp[n]. You can still follow the dependency edges to explain that value, but those edges describe a sum of both children, not a choice between alternatives.

Three ways to evaluate the same recurrence

Naive recursion directly follows the definition. To compute F(7), it asks for F(6) and F(5). F(6) asks for F(5) again, so that whole calculation repeats. Smaller values are repeated still more often. The recursion is correct but its call tree is much larger than the set of distinct indices.

Memoisation keeps the recursive structure and adds a cache. Start unknown entries at -1, because valid Fibonacci values are nonnegative. Before solving a nonbase state, check the cache. If it is known, return it immediately. Otherwise compute its two dependencies once, store their sum, and return the stored value.

Tabulation starts from the bases and fills i=2,3,...,n. It never needs an unknown sentinel because the loop order guarantees every read is ready. Both approaches evaluate the same dependency graph. Memoisation follows requests from the desired answer; tabulation follows a known order from the bases.

Evaluate dependencies after their bases

For tabulation, use the invariant that all entries below i equal their defined Fibonacci values. The bases establish it before i=2. At iteration i, the previous two entries are correct by the invariant. Their sum is F(i) by the recurrence, so the new entry is also correct. At the end, dp[n] has its required value.

For memoisation, prove the same recurrence by induction on n. A cache hit returns a value stored by an earlier correct computation. A cache miss recursively computes smaller indices, combines correct values, and stores the correct result. The sentinel must be distinguishable from every valid result so a known zero is never mistaken for unknown.

Termination follows because recursive indices decrease until reaching 0 or 1. The tabulation loop instead increases toward n. Neither traversal can cycle in this dependency graph. In another DP, a recurrence referring back to a state currently being evaluated could cause a cycle, so dependency direction needs explicit attention.

Distinct states replace repeated calls

Naive Fibonacci recursion satisfies a branching recurrence and takes Θ(φ^n) time, where φ is the golden ratio. O(2^n) is a valid simpler upper bound. Its active stack depth is Θ(n), because one branch repeatedly subtracts one. Exponential total calls do not mean exponential simultaneous stack storage.

Memoisation solves n+1 distinct states, with constant work and at most two dependency calls per state. It takes Θ(n) time and Θ(n) cache space, plus Θ(n) stack depth. Tabulation also takes Θ(n) time and Θ(n) table space, but avoids recursive frames. These are fixed-width arithmetic bounds under the numeric limits used here.

When only F(n) is needed, keep the previous two values instead of the entire table. The rolling example uses Θ(1) auxiliary space and Θ(n) time. This removes access to old entries, so use a table when you need to inspect or answer many stored indices. Space compression should follow actual future dependencies.

When top-down and bottom-up differ

Memoisation can avoid states that no request reaches. Fibonacci reaches every smaller index, so it offers no such saving here. In sparse state spaces, demand-driven evaluation may be easier or cheaper. Tabulation can be simpler when dependencies have a clear rectangular or increasing-size order and most states are needed.

A cache belongs to a particular problem definition. If a state also depends on capacity, remaining items or another parameter, caching only n mixes different subproblems. Include every parameter that changes the answer. Correct state design is usually more important than choosing recursion or loops.

Fibonacci grows beyond fixed integer ranges. These demonstrations restrict n to at most 30 in table storage and at most 20 in recursion exercises. F(30)=832040 fits int on the recorded toolchain. General large-index Fibonacci requires a wider type, modular arithmetic, or arbitrary-precision arithmetic with a revised cost model.

Do not use a valid value as unknown

Initialising a cache to zero and interpreting zero as unknown fails to recognise the valid result F(0)=0. Use a separate known flag or an impossible sentinel such as -1 under a nonnegative contract. The memo example handles base values directly before consulting the cache.

Adding a cache but forgetting to return stored answers still repeats the original recursion. Store on a miss and reuse on a hit. Also avoid clearing the cache inside every recursive call, which discards all remembered work. Initialise it once before the initial request.

Reading dp[i-2] when i starts at one accesses a negative index. Begin transitions at two after setting the bases. Writing dp[1] unconditionally into a one-cell n=0 allocation is a different boundary error. The grid lab and the bounded C array use their own safe representations for these bases.

C17 recurrence storage

The C programs use int arrays with a fixed size sufficient for their documented index limits. The rolling version saves the new sum before replacing old values, preventing an update-order mistake. None of these techniques requires a C feature beyond the C17 baseline. Overflow remains a mathematical-range issue even when every array index is valid.
