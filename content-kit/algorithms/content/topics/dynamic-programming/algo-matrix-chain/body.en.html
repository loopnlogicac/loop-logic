Same product, different work

Matrix multiplication is associative: (A1A2)A3 and A1(A2A3) represent the same mathematical product when dimensions match. Yet the number of scalar multiplications can differ greatly. Matrix-chain multiplication chooses parentheses that minimise this arithmetic work while keeping the original matrix order.

Suppose A1 is 10×30, A2 is 30×5, and A3 is 5×60. Computing A1A2 first costs 10×30×5=1500 scalar multiplications and produces a 10×5 result. Multiplying that by A3 costs another 10×5×60=3000. The total is 4500.

Computing A2A3 first costs 30×5×60=9000 and creates a 30×60 result. Multiplying A1 by it costs 10×30×60=18000, for total 27000. Both orders produce a 10×60 result. Choosing parentheses saves work without changing which matrices are multiplied.

This DP computes the cost and order; it does not multiply the actual matrix entries. Its input is a sequence of dimensions. Once the order is known, a separate matrix routine can evaluate that plan. Floating-point rounding can make differently associated numeric evaluations differ slightly even though the algebraic product is associative; the optimisation here counts scalar arithmetic work.

State an interval of matrices

dp[i][i] = 0
for length = 2 to n
    for i = 0 to n-length: j = i+length-1
        for k = i to j-1
            try dp[i][k]+dp[k+1][j]+dims[i]*dims[k+1]*dims[j+1]
            keep smaller cost and its split k
print recursively using split[i][j]
return dp[0][n-1] and order

Write dims with n+1 entries for n matrices. Zero-based matrix i has shape dims[i]×dims[i+1]. Step 1, state: dp[i][j] is the minimum scalar multiplication count for matrices i through j inclusive. A single matrix requires no multiplication, so dp[i][i]=0.

Step 2, recurrence: the final multiplication splits the interval after some k with i<=k<j. Its left result has shape dims[i]×dims[k+1], and its right result has shape dims[k+1]×dims[j+1]. That last product costs dims[i]×dims[k+1]×dims[j+1]. Add the two optimal child costs and minimise over k.

The split table stores the k producing the best candidate. Scan k upward and replace only on a strictly smaller cost, so the smallest tied split is retained. Labels A1,A2,... in the printed answer are one-based names for the zero-based matrices in C. Keep this naming conversion separate from array indexing.

Fill short intervals before long ones

Step 3, order: increase interval length from two through n. For each start i, set j=i+length-1 and test every final split k. Both child intervals are shorter than the parent, even when one contains a single matrix. Their costs are therefore available before the parent is evaluated.

For three matrices, first calculate intervals [0,1] and [1,2]. Their costs are 1500 and 9000. Only then evaluate [0,2]. Split k=0 uses cost 0+9000+18000=27000. Split k=1 uses 1500+0+3000=4500. Save cost 4500 and split 1.

Step 4, reconstruction: if i==j, print that matrix name. Otherwise print an opening parenthesis, recursively print [i,split[i][j]], recursively print [split[i][j]+1,j], and close the parenthesis. The example returns ((A1A2)A3). Reconstruction follows a tree of saved decisions rather than a simple up-left grid path.

The grid displays only the upper triangular interval states, including the zero diagonal. Lower triangular cells remain empty because i>j is not a matrix interval. Each considered split highlights its two child cells, and the variable panel shows the candidate cost. During recovery, the selected interval cells form the parenthesisation tree.

Every parenthesisation has a final split

A complete parenthesisation is a binary tree with the matrices as leaves in their original order. At the root, the final multiplication separates two consecutive nonempty groups. Therefore it corresponds to exactly one k between i and j-1. Trying every k covers every possible final split.

For a fixed split, any optimal parenthesisation must use optimal orders inside both children. If a child were more expensive than necessary, replacing only that child's parentheses would preserve its result dimensions and reduce total cost. The final multiplication cost would remain unchanged. This is the optimal-substructure property supporting the recurrence.

The diagonal is correct because evaluating one existing matrix costs no multiplication. Assume all intervals shorter than the current length have correct costs. Each candidate then combines two correct child minima with the exact final product cost. Taking the minimum chooses an attainable cost no worse than any parenthesisation. Induction over length proves the top-right answer.

The saved split records an attaining candidate. Recursively following it ends at singleton matrices because both children are shorter. The printed plan keeps all original matrices exactly once and preserves their order. Its total arithmetic count equals the stored optimum, proving the recovered witness as well as the numeric cost.

Intervals times split positions

There are Θ(n²) nonempty matrix intervals. Each interval may try O(n) splits, giving O(n³) time. More exactly, summing split counts over all intervals yields n(n-1)(n+1)/6 candidates. That cubic count comes from the combination search within every interval, not from multiplying actual matrix entries.

The cost and split tables each require Θ(n²) space. The reconstruction tree has n leaves and n-1 internal nodes, so writing its matrix names and parentheses takes O(n) structural steps, aside from the digits in names. A skewed chosen order can require O(n) recursion depth during printing.

The examples bound n by twelve and each dimension by 100. Every scalar product cost is at most 100³, and at most eleven matrix products occur, so the optimum fits int. Candidate totals also stay well below the sentinel 1000000000. Larger dimensions require checking products before multiplication and may need a wider integer type.

Why a local dimension rule is unsafe

It is tempting to multiply the currently cheapest adjacent pair first. That local product changes the dimensions of future products, so a cheap early choice can create expensive later work. The DP compares complete child costs and the resulting parent dimensions. A rule inspecting only one immediate multiplication lacks that information.

Matrix order cannot be changed. Multiplication is generally not commutative, so swapping A1 and A2 may be invalid even if their dimensions happen to permit it. Parenthesisation changes grouping alone. A plan that sorts matrices by size solves neither the same algebraic product nor the same optimisation problem.

The uncut analogue here is a single matrix: zero work, no split, and one printed name. Two matrices have exactly one possible split. Equal-size square matrices may have many equally cheap orders because each multiplication costs the same amount. The tie rule chooses a reproducible answer without claiming a unique optimum.

Read dimension chains before allocating

A chain of matrices is represented compactly because adjacent dimensions match. If matrices are given as independent row-column pairs, first verify that each matrix's columns equal the next matrix's rows. Without that compatibility, no full parenthesisation can repair the mismatch. Every grouping preserves the required adjacency of the mathematical product.

The dimension-only DP is useful when matrices are large enough that evaluation dominates planning. For a fixed sequence of dimensions used repeatedly, the optimal split tree can be reused. If dimensions change between runs, the stored costs no longer describe the new problem and must be recomputed.

Alternative cost models can optimise memory footprint or parallel completion time instead of scalar multiplication count. Those objectives may depend on evaluation order as well as parentheses. The current recurrence does not automatically minimise memory or runtime on every machine. Its guarantee is the explicitly stated arithmetic-count objective.

Use the boundary dimensions at the split

For zero-based matrices i..j, the final product uses dims[i], dims[k+1] and dims[j+1]. Using dims[k] or dims[j] confuses matrix indices with dimension boundaries. Write the left and right result shapes beside a candidate to derive the factors rather than guessing offsets.

Filling the table in ordinary row-major order may read a longer uncomputed dependency. Increasing interval length makes availability clear. Also do not initialise all nontrivial intervals to zero: every multiplication cost is positive under positive dimensions, so zero would incorrectly defeat every real candidate.

A loop with k<=j creates an empty right child and accesses beyond the intended interval. Require k<j. During printing, use split+1 as the right start. Reusing split as both the left end and right start repeats a matrix and can prevent recovery from shrinking.

C17 triangular data in rectangular arrays

The C implementation reserves rectangular twelve-by-twelve arrays and uses their upper triangles. Zero initialisation supplies the diagonal costs; nontrivial intervals receive a large sentinel before their split loop. The mathematical interval convention is inclusive here, unlike earlier half-open array recursion. The lesson states that difference so each call and table coordinate has a consistent meaning.
