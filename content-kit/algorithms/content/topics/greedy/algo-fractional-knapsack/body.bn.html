শুরু করা যাক

ব্যাগের weight capacity সীমিত,material ভাগ করা যায়। প্রতি lot-এর weight ও total value আছে। যেকোনো fraction নিলে একই অনুপাতে value। Capacity-র মধ্যে maximum value fractional knapsack।

20kg grain100 টাকা হলে অর্ধেক10kg50। Proportional-value শর্ত অপরিহার্য। Device ভেঙে সমান কাজের fraction পাওয়া যায় না;পরে0/1 knapsack-এ অন্য method।

Weight positive,value nonnegative,capacity খালি রাখা চলে। প্রতি lot-এর সীমিত weight;শেষের পর copy নেওয়া নয়। Zero-value fit হলেও objective বাড়ে না।

সিউডোকোড ও ব্যবহারের নিয়ম

sort items by decreasing value / weight; tie by id
total = 0
for each item while capacity > 0
    take = min(weight, capacity)
    total = total + take * value / weight
    capacity = capacity - take
return total

Value/weight হলো density,এক weight-এর value। Decreasing ratio-তে sort। Take=min(weight,remaining),value-এ take×value/weight যোগ,capacity থেকেtake কমাও। শেষ lot partial হতে পারে;capacityzero-তে আর দরকার নেই।

Comparator integer division নয়,cross product:valueA×weightB বনাম valueB×weightA। Positive weight-এ direction ঠিক। Bound মেনে long long product। Equal ratio-তে original ID repeatable choice,optimal value একই।

পদ্ধতিটি কেন সঠিক

Feasible plan-এ lower density নেওয়া অথচ higher material বাকি ধরো। Equal অল্প weight exchange করো। Capacity এক,উচ্চ density-তে value বাড়ে;আগেরটি optimal হতে পারে না।

Higher lot full বা lower সরানো পর্যন্ত repeat। তাই strictly lower-এর আগে highest full করা optimum আছে। Equal density exchange-এ value এক। এরপর remainder-এ একই যুক্তি।

Proof arbitrary fraction চায়। Whole item-এ equal-weight exchange নাও সম্ভব। একই capacity50-তে whole item1,2-এর value220;ratio-first প্রথম দুই নিয়ে160,third ধরে না। Fractional20 unit নিতে পেরে240।

Invariant:processed material density-order-এ নেওয়া,এ choice মানা optimum আছে। Exchange next choice প্রতিষ্ঠা করে। Capacity/material শেষ হলে ওই optimum বাড়ানোর positive feasible extension নেই।

সময় ও মেমরির হিসাব

n lot sort উপযুক্ত sorter-এ O(n log n),fill worst Θ(n)। Capacity আগে ভরলে scan আগে থামে,sort হয়ে গেছে। বহু capacity query-তে ratio order reuse করা যায়।

Routine input record rearrange করে,double total ও integer capacity রাখে;scan auxiliary Θ(1)। সব taken fraction লিখলে output O(n)। Library sort-এর space implementation-নির্ভর;qsort standard cost বলে না।

Proof exact proportion-এর। C fractional contribution-এ double,two-decimal display। Ordering exact cross product-এ বলে rounding তা ঠিক করে না। Exact accounting চাইলে rational numerator-denominator বা স্পষ্ট rounding policy।

Whole-item ও zero-weight variant

Fractional optimum একই0/1 optimum-এর upper bound;প্রতিটি whole plan fractional-এও বৈধ। Feasible set বড়ে maximum ছোট নয়। কিন্তু fractional round করলেই whole optimum হয় না।

উদাহরণzero-weight reject করে। Positive-value zero-weight free contribution আলাদা,ordinary ratio undefined। Negative value-তে mechanical fill নয়,skip rule চাই। Contract-এ proof ও loop মিলিয়ে রাখো।

কখনো unit price সরাসরি দেয়,তখন সেটি compare। Total value বড় হলেও heavy lot-এর unit value কম হতে পারে। Number কী মাপে দেখে key বাছো।

Cross product-ও range চায়। Int multiply-এর পরে cast দেরি। আগে operand long long করো। Weight,value≤1000-এ product সহজে ধরে।
