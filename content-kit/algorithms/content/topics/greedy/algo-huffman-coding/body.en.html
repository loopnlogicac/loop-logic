Short codes for frequent symbols

Suppose a message contains some symbols much more often than others. Giving every symbol the same number of bits wastes opportunities. A frequent symbol could use a shorter bit string, while a rare symbol uses a longer one. Huffman coding constructs such variable-length binary codes from positive symbol frequencies.

Different code lengths create a decoding question. Where does one symbol end and the next begin? A prefix code answers it: no symbol's complete code is the prefix of another symbol's code. You can recognise a symbol as soon as its bits reach a leaf in a binary tree. No separator bit is needed between symbols.

The optimisation target is the total encoded message length, sum of frequency×code length over all symbols. This is the weighted external path length of the tree, because a code's length equals its leaf depth. The tree or codebook must also reach the decoder. Huffman minimises the data-bit objective for the supplied frequencies; it does not claim that codebook storage is free.

A fixed-length code for six symbols needs three bits per symbol. The frequency example contains 100 occurrences in total, so that would use 300 data bits. Huffman's tree uses 224. This saving depends on unequal frequencies and on both sides agreeing on the codebook. A very short message may not recover the cost of transmitting that codebook.

Leaves, weights and a min-heap

create a leaf for each positive frequency; push its ID
while heap size > 1
    left = pop minimum; right = pop minimum
    create parent with weight[left] + weight[right]
    attach left and right; push parent
root = final minimum; assign 0 left and 1 right
return codes and weighted bit count

Each leaf stores one symbol's frequency. Internal nodes store the sum of their descendants' frequencies. The priority queue contains roots of the currently available trees. Remove two smallest roots, create their parent, and insert that parent again. Continue until only one root remains. A forest of many single-symbol trees becomes one full prefix tree.

The C example uses arrays of Node records and a binary min-heap of node IDs. Lower weight has higher priority; lower ID breaks equal-weight ties. Leaf IDs are 0 through n-1 for symbols A onward. Internal IDs increase from n. The first minimum becomes the left child and contributes bit 0; the second contributes bit 1.

These tie rules make the codebook reproducible. Other tie choices can produce different equally optimal codes. Reversing every left and right branch also keeps all code lengths unchanged. A decoder must use the actual chosen codebook rather than assuming that optimality determines one unique sequence of bits.

Repeatedly merge the two least weights

For frequencies 5,9,12,13,16,45, first join 5 and 9 into 14. Next join 12 and 13 into 25. The queue now contains 14,16,25,45. Joining 14 and 16 gives 30. Joining 25 and 30 gives 55. Finally join 45 and 55 into the root weight 100.

The heap's push operation moves a new node upward while it is lighter than its parent. The pop operation removes the minimum root, brings the last entry down, and follows the lighter child. Each operation uses logarithmic heap height. The parent trees remain in the Node array even after their IDs leave the heap; removal from the queue is not deletion from the code tree.

The tree lab begins with every symbol as a separate leaf and no root selected. Each merge creates one internal node and attaches the two removed trees. The heap side list shows which subtree roots are still candidates. At completion, the final root reaches all leaves. The displayed codebook follows its left and right branches.

Encode and decode with the same tree

To encode, walk from the root to a symbol's leaf or use a saved symbol-to-bits table. Concatenate the code strings in message order. Under the demonstrated tie rule, F is 0, C is 100, D is 101, A is 1100, B is 1101, and E is 111. The message FACE becomes 01100100111.

To decode those bits, begin at the root. A zero chooses the left child and a one chooses the right. When a leaf is reached, emit that symbol and return to the root for the next symbol. The sequence 0 reaches F, then 1100 reaches A, 100 reaches C, and 111 reaches E. Reusing the root is essential after each completed symbol.

A valid complete bit stream ends at the root after its last emitted leaf. Ending partway down an internal path means the message is truncated. A decoder should also reject nonbinary characters and impossible child paths. A prefix code gives unambiguous parsing for valid streams; it does not itself detect every transmission error.

With one distinct symbol, the mathematical tree can use a zero-length code if the message length is supplied separately. These examples instead assign code 0 to that symbol. The decoder then emits one symbol per zero bit and rejects one bits. State this convention because the single-symbol bit cost differs from the sum-of-merges formula, whose merge sum is zero.

Why the two smallest weights are safe

In a full binary prefix tree, choose two sibling leaves at greatest depth. Such a pair exists because a deepest internal node has two leaf children. Let x and y be the two smallest frequencies. Moving x and y to those deepest sibling positions cannot increase weighted path length. Swapping a smaller weight downward with a larger weight upward changes cost by a nonpositive amount.

Therefore some optimal tree places x and y as deepest siblings. Replace them by one leaf with combined frequency x+y. Every other leaf keeps its depth, while x and y each lose one edge. The original tree cost equals the reduced tree cost plus x+y. If the reduced tree were not optimal, substituting a better reduced tree would improve the original, a contradiction.

This proves both required properties. Choosing the two least weights is a safe greedy choice, and the contracted alphabet is an optimal subproblem of the same form. Repeating the contraction reconstructs an optimal tree in reverse. The one-symbol convention is handled separately because the usual edge-depth objective has depth zero there.

A prefix tree need not be full if it contains redundant single-child internal nodes. Removing such a node shortens all leaves below it and cannot worsen the objective. Thus for positive frequencies, an optimum can be assumed full. That observation justifies using the full-tree sibling argument rather than assuming an arbitrary tree already has the desired shape.

Separate building from message processing

For n symbols, there are n-1 merges. Each merge performs two heap pops and one push, each O(log n). Inserting the initial leaves individually also costs O(n log n), so building the shown tree takes O(n log n) time. A bottom-up heap construction can reduce only the initial preparation to O(n).

A full tree has 2n-1 nodes, and the heap contains at most n IDs. Both use O(n) space. Printing all code strings costs time proportional to their combined lengths, which may be O(n²) in a highly skewed tree. A single traversal visits O(n) nodes, but printing every ancestor bit for every leaf is additional output work.

Encoding a message costs O(B) to emit B encoded bits once the code table is available. Decoding also costs O(B), moving one tree edge per bit. A worst-case Huffman depth can be n-1, so neither every code length nor total codebook output is guaranteed logarithmic. The heap height and code-tree height describe different structures.

Do not confuse queue removal with tree deletion

Deleting nodes after popping their IDs destroys subtrees needed later for encoding and decoding. Keep Node records alive until the codebook is no longer needed. The examples use bounded arrays, so no dynamic ownership is involved. A dynamic implementation must free each complete tree node exactly once after use.

Using a max-heap reverses the greedy rule and tends to push frequent symbols deeper. Selecting the two least original leaves once and then ignoring new internal weights is also wrong. Every new subtree must compete in the same queue. Its weight represents all descendant occurrences that would gain a bit at the next merge.

Assuming a fixed bit string for every tied frequency can reject a correct alternative tree. Compare weighted cost and prefix validity unless the task specifies tie rules. Also do not decode by consuming a fixed number of bits per symbol: variable lengths are precisely the feature that provides compression.

The demonstrations support at most sixteen symbols with frequencies at most 99. Arrays of 31 nodes hold exactly the largest possible full tree. A path buffer of 32 characters holds every possible code plus its terminating null character. Frequency sums fit int, and symbols A onward remain within the displayed teaching alphabet.

A safe merge creates an optimal code tree

Huffman coding repeatedly joins the two smallest available tree weights. A sibling exchange and contraction prove that this greedy step preserves optimality.
