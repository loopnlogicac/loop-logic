ল্যাবের এক machine,অনেক one-slot job। Deadline-এর মধ্যে শেষ হলেই profit। Job optional,slot-এ একটিই,maximum total profit চাই। এটি unit-processing-time deadline sequencing।

Slot1,2,…completion time-ই number। Deadline2-তে slot1/2,zero-তে কোনো positive slot নয়। C-তে slot t index t-1;গণিতের numbering ও index আলাদা।

প্রতিটি ঠিক এক slot। Two-slot job-এ resource আলাদা,এই test ভাঙে। সবাই slot1-এর আগে available,precedence নেই। Algorithm-এর assumption,উপেক্ষণীয় detail নয়।

সিউডোকোড ও ব্যবহারের নিয়ম

sort jobs by decreasing profit; tie by id
mark slots 1 through n free; total = 0
for each job with positive profit
    search slots backward from min(deadline, n)
    if a free slot exists: put job there; add its profit
return total and slots

Decreasing profit,tie-তে original ID sort। Positive-profit job-এ min(deadline,n) থেকে backward free slot খোঁজো। Latest allowed-এ বসাও,না পেলে reject। Optional nonpositive নেওয়ায় লাভ নেই।

n job-এ n slot যথেষ্ট,deadline বড় হলেও। Feasible set maxn job,left shift করে প্রথমn-এ শেষ হয়। Deadline cap feasibility রাখে,বড় array বাঁচায়।

পদ্ধতিটি কেন সঠিক

Unit-job set feasible iff প্রতি t-তে deadline≤t job সংখ্যা≤t। Necessity:প্রথমt slot-এ সবাই শেষ চাই। Sufficiency:deadline-sort-এ kth job deadline≥k,ক্রমে বসে।

Feasible A,B-তে|A|<|B| হলে B\A-এর কোনো job A-তে যোগ করা যায়। A-এর tight deadline prefix দেখো:t early job t slot ভরে। সব বাইরে job tight prefix-এ blocked হলে বৃহত্তম ওই prefix সব outside ধরে,B-এর feasibility ও বেশি size-এর বিরোধ।

Exchange property profit order safe করে। Accepted choice মানা optimum রাখো। পরের accepted greedy job না থাকলে feasibility রেখে conflicting later-considered job-এর বদলি। বাদটির profit বেশি নয়। তাই value না হারিয়ে optimum আরও এক choice মানে।

Latest-slot test accepted set-এর feasibility ঠিক বলে। নতুন deadline পর্যন্ত সব full হলে earlier-deadline occupant পরে যেতে পারে না;flexible occupant নিজের সময় latest-এ বসেছে। Blocking chain-এ saturated deadline prefix মেলে;নতুনটি capacity ছাড়াবে,তাই reject দরকার।

আলাদাভাবে প্রতিটি insertion-এর পরে deadline-prefix condition দিয়ে test করা যায়;ছোট reference হিসেবে ভালো। Proof unit duration চায়,তবেই job count=slot count।

সময় ও মেমরির হিসাব

উপযুক্ত sort O(n log n)। প্রতি n job-এ n slot দেখা placement worst O(n²),sort-কে dominate। শুরুতে sort দেখলেই whole O(n log n) নয়।

Slot arrayn,input order sort-এ বদলায়। Array বাদে placement variable Θ(1)। Advanced disjoint-set latest slot দ্রুত দিতে পারে। Structure বদলালেও profit order ও proof থাকে।

Zero-negative skip objective না-বাড়ানো কাজ দিয়ে slot নষ্ট এড়ায়। সবাই run বাধ্যতামূলক বা missing penalty হলে অন্য objective। Optional variant unprofitable কাজ রেখেও idle হতে পারে।

প্রতি deadline-এর অর্থ দেখো

সব deadlineone-এ greatest positiveprofit;সব≥n-এ সবpositive ধরে। Deadlinezero hugeprofit-ও বাদ। Profit,slot bound,feasibility আলাদা test।

Tied profit-এ অনেক optimum। ID repeatable answer,optimality proof-এর অংশ নয়। Slots-এ original ID রাখো,sorted position নয়।

Deadline release time নয়। Deadline4 আগে run করা যায়,ঠিক4-এ start চাইলে অন্য সমস্যা। Profit এক completion-এ একবার,available slot সংখ্যা দিয়ে গুণ নয়।

প্রচলিত ভুল

Forward earliest slot tight-deadline job আটকায়। Deadline থেকে backward যাও। Deadline পেরিয়ে বসালে সুন্দর total হলেও late job profit পায় না।

সব slot -1 initialize। Uninitialized-এ occupied বা real ID মনে হতে পারে। Zero valid ID বলে free marker নয়;negative স্পষ্ট।

Arbitrary duration-এ লাগাবে না। Long high-profit বনাম বেশি মোট-profit short job-এ profit-only ভুল হতে পারে। Unit duration-ই prefix exchange ও one-slot insertion সমর্থন করে।
