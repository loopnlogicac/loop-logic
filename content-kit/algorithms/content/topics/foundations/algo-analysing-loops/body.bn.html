আগে কোন operation গুনবে বাছো। এখানে visit মানে innermost body একবার চালানো। Assignment, কম্পারিজন, update-এর আলাদা কাউন্ট আছে। প্রশ্নে primitive operation চাইলে পরে মেলাবে। একটি universal convention-এর চেয়ে consistent থাকা জরুরি।

ধাপে ধাপে বোঝো

সরাসরি scan ও independent লুপ

i = 0 থেকে n - 1-এ body n বার। শেষ ব্যর্থ check-সহ condition n + 1 বার; update n বার। Empty ইনপুট-এ body নেই, কিন্তু check একবার। ওই failed check-এ ডেটা access যোগ করবে না।

তিন করে এগোলে i < n-এ 0,3,6,…। Positive n-এ কাউন্ট ceil(n/3), fixed ধাপ বলে Θ(n)। n করে এগোলে positive n-এ কনস্ট্যান্ট repetition। Update rule পুরো বিশ্লেষণ বদলাতে পারে।

পরপর দুই scan n+n = 2n; independent nested scan n×n = n²। Indentation দেখো। Inner লুপ m হলে দুই parameter রেখে Θ(nm)। কারণ ছাড়া m-কে n করলে rectangular ইনপুটের তথ্য হারায়।

Dependent limit-এ sum করো

Triangular লুপ-এ i = 1..n row-তে i visit। মোট 1+2+…+n = n(n+1)/2। প্রথম-শেষ জোড়ায় n+1। অর্ধেক factor exact answer বদলায়, leading quadratic term Θ(n²) দেয়।

Inner j = i থেকে n - 1 হলে row length n, n-1,…,1; একই sum উল্টো। j = i+1-এ self-pair নেই, তাই n(n-1)/2। ভিন্ন student-এর কম্পারিজন গুনতে পার্থক্য দরকার।

সব dependent লুপ quadratic নয়। Outer i = 1..n, inner j = i,2i,3i,…≤n হলে sum floor(n/i)। Harmonic series-এ Θ(n log n)। Actual row sum চাই; maximum inner কাউন্ট × n শুধু loose upper bound।

গুণ করে বদলালে logarithm আসে

Positive ইনডেক্স 1 থেকে দ্বিগুণে 1,2,4,…। k update-এর পরে 2^k। Stop 2^k ≥ n থেকে n ≥ 1-এ k = ceil(log2 n)। Zero থেকে শুরু হলে এগোবে না, কারণ 2×0 এখনও zero।

Positive ইন্টিজার n-এ remaining > 1 halving লুপ floor(log2 n) visit। n = 17-এ 17,8,4,2 দেখা যায়। ইন্টিজার truncation-এর জন্য power ও পাশের nonpower exact কাউন্ট আলাদা দেখো। Doubling ও halving logarithmic, rounding আলাদা।

Doubling-এর প্রতি লেভেল-এ n visit হলে Θ(n log n)। কিন্তু i দ্বিগুণের সময় inner length i হলে 1+2+4+… below n; geometric sum Θ(n)। Logarithmic row কাউন্ট মানেই logarithmic total নয়।

Branch, early return ও ডেটা dependence

Equality-তে return করা search এক ভ্যালু, prefix বা পুরো list দেখে। Best-worst আলাদা বলো। Average-এ probability মডেল চাই। সফল target n পজিশন-এ equally likely হলে expected কম্পারিজন (n+1)/2। মডেল ছাড়া “গড়ে অর্ধেক” আন্দাজ।

লুপের if-else-তে প্রতি repetition এক branch চলে। Branch-এর আগের কাজ ও নেওয়া branch ধরো। Worst upper bound-এ expensive branch নেওয়া যায়। Matching lower bound-এ সত্যিই প্রায়ই ওই branch নেওয়া ইনপুট family চাই।

লুপ ফাংশন ডাকলে তার cost ধরো। এক visible লুপ-এ n বার linear scan হলে quadratic। Invariant calculation বাইরে নিলে repeated কাজ বাঁচতে পারে। Class বলার আগে call chain পড়ো।
