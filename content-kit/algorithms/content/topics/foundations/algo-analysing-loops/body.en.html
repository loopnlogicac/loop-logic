Introduction

Counting loop work is like counting seats in rows. Equal rows invite multiplication. Rows of different lengths need addition. If you inspect only the number of loop headers, you can mistake a triangle for a square or a halving process for a long scan.

Choose the operation you want to count before starting. Here a visit means one execution of the innermost body. Assignments, comparisons and updates have their own counts. You can combine them later if a question asks for total primitive operations. Consistency matters more than choosing one universal counting convention.

Analysing Loops and Code step by step

Straight scans and independent loops

For i = 0 through n - 1, the body runs n times. The condition is checked n + 1 times, because the final failed check also occurs. The update runs n times. An empty input therefore executes no body but still checks the condition once. Do not add a data access for that failed check.

A loop advancing by three visits 0, 3, 6 and so on while i < n. For positive n, its body count is ceil(n/3). Its growth remains Θ(n), because the step size is fixed. If you instead advance by n, the number of repetitions becomes constant for positive n. The update rule can change the whole analysis.

Two consecutive scans cost n + n = 2n visits. Two independent nested scans cost n times n = n² visits. The indentation tells you which situation you have. If the inner loop runs m times, retain both parameters and write Θ(nm). Replacing m by n without a reason loses information about rectangular inputs.

Dependent limits form sums

In a triangular loop, outer row i contains i visits for i = 1 through n. Total work is 1 + 2 + ... + n = n(n + 1)/2. Pair the first and last terms: each pair totals n + 1. The factor one-half changes the exact answer, while the leading quadratic term determines Θ(n²).

For an inner index j = i through n - 1, row lengths are n, n - 1, down to 1. The same sum appears in reverse order. For j = i + 1, there are no self-pairs, so the count becomes n(n - 1)/2. This distinction matters when counting comparisons between different students.

Not every dependent loop is quadratic. Consider outer i = 1 through n and inner j taking i, 2i, 3i up to n. Its body count is the sum of floor(n/i). The harmonic series gives Θ(n log n). You need a summation over actual row lengths; multiplying the largest possible inner count by n gives only a loose upper bound.

Multiplicative updates create logarithms

If a positive index starts at 1 and doubles while it is below n, its values are 1, 2, 4 and successive powers of two. After k updates it equals 2^k. The stopping condition 2^k ≥ n yields k = ceil(log2 n) for n ≥ 1. Starting at zero would never progress because twice zero is still zero.

A halving loop with remaining > 1 makes floor(log2 n) body visits for positive integer n. For n = 17, the observed values are 17, 8, 4 and 2. Integer truncation explains why powers and nearby nonpowers need separate exact checks. Both doubling and halving have logarithmic growth, although their rounding differs.

For a nested loop that performs n visits at each doubling level, total work is Θ(n log n). However, if each level performs only i visits while i doubles, the total is 1 + 2 + 4 + ... below n. This geometric sum is Θ(n). A logarithmic number of rows does not automatically mean logarithmic total work.

Branches, early returns and data dependence

A search that returns on equality may inspect one value, some prefix, or the whole list. Give best and worst cases separately. Average-case analysis additionally requires a probability model. If a successful target is equally likely at each of n positions, expected comparisons are (n + 1)/2. Without that model, saying average is half is only a guess.

For an if-else inside a loop, only one branch executes on each repetition. Add the work before the branch, then account for whichever branch is taken. A worst-case upper bound can use the more expensive branch. A matching lower bound needs an input family that really takes expensive branches often enough.

When a loop invokes a function, include the function cost. Calling a linear scan n times creates quadratic work even if only one loop header is visible. Conversely, moving an invariant calculation outside the loop may remove repeated work. Read the complete call chain before assigning a complexity class.

C implementations and results

Count visits in a straight scan

The visit counter increases once at each index from zero through seven. It measures body executions, excluding the final failed condition.

Count a triangular pair loop

Rows of lengths one through eight contribute 36 inner-body visits. This exact count distinguishes dependent limits from a square grid.

Count repeated halving

Integer sizes 16, 8, 4 and 2 each execute the division body. The stop at one gives four visits, with no fifth body execution.

Why the method is correct

A counter inserted at the beginning of the innermost body has increased once for every completed visit. That is its invariant. It starts at zero and increases exactly where the selected operation occurs. After all loops finish, its value is the exact body count for that input. The three programs use this method rather than timing short loops.

For symbolic reasoning, check the first two rows and the final row against your summation. Then test n = 0 or n = 1 when permitted. These checks expose most endpoint errors. A proof still needs to show that every row length has the claimed formula.

Time and space reasoning

The worked catalogue below states its domains explicitly. Independent dimensions remain separate parameters. Logarithmic counts assume positive n and ordinary integer division. A bound describes body visits only unless the row says otherwise. Fixed-size examples demonstrate the pattern; the Θ statement describes the family where n varies.

Common mistakes

Multiplying dependent maxima

For rows of length i, n times n is an upper bound but not the exact count. Sum i first to retain the missing triangular factor.

Ignoring a reset

An inner counter initialised before the outer loop may run only once in total. A counter reset inside the outer loop can repeat all its work.

Forgetting the helper function

A constant-looking function call may contain its own full scan. Expand its cost before simplifying the outer loop.

C17 details

C17 integer division truncates towards zero. The positive halving loops therefore use floor division. All executable counters stay within the stated small input limits.
