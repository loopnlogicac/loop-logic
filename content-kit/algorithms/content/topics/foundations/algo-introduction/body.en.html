Introduction

Imagine adding laboratory fees from three slips. You read each amount, add it to a running total, and stop after the last slip. Someone else can follow those instructions and get the same answer. An algorithm is a finite sequence of clear steps for solving a stated problem.

You already use algorithms when you follow a timetable or divide a bill. Programming makes the instructions precise enough for a computer. This course asks three questions about every method: what answer should it produce, why does it produce that answer, and how much work does it need?

Pseudocode and conventions

sum = 0
for i = 0 to n - 1
    sum = sum + a[i]
return sum

What Is an Algorithm? step by step

Describe the problem before the steps

An algorithm starts with a contract. The input is the information you receive. The output is the information you must return. For the fee problem, input is a list of integer amounts and output is their sum. State whether negative adjustments are allowed. Also decide what an empty list means; here its total is zero.

A useful algorithm has definite instructions, permitted inputs, a stated result, effective operations, and a stopping rule. Definite means that two readers interpret a step the same way. Effective means that each operation can actually be carried out. Finite means that every permitted input eventually reaches an end. A procedure that repeatedly waits for another fee without an end signal has no such guarantee.

Distinguish a problem from one particular input. Adding [40,25,35] solves one instance. A general algorithm also handles [10], an empty list, or many fees. You should not hide the expected result inside the instructions. Writing return 100 describes one answer rather than a method for arbitrary fees.

Read pseudocode as a shared language

Pseudocode describes an algorithm without all the punctuation of C. We use zero-based array positions. An array a of length n has valid positions 0 through n - 1. A loop written from 0 to n - 1 includes both endpoints. If n is zero, that loop has no repetitions.

An assignment such as sum = sum + a[i] replaces the old sum. A comparison such as a[i] == target asks a yes-or-no question. Indentation groups the instructions controlled by a loop or condition. A return ends the current function. Later, a half-open interval [low,high) includes low and excludes high. Its length is high - low, including length zero.

Translate one idea at a time into C. A pseudocode array length is mathematical; a C array needs actual storage. The sum example uses int because three small fees fit. For an unrestricted input size or unrestricted amounts, you must choose a suitable larger type or detect overflow. The mathematical algorithm does not grant C integers unlimited range.

Separate correctness from efficiency

Correctness means returning the specified result for every allowed input. Efficiency describes the resources used to do so. A fast routine that forgets the last fee is still wrong. A slow routine that adds every fee correctly may still be useful for a short list.

You can compare two correct approaches before timing them. Adding each amount once needs n additions. Recomputing the entire prefix for every slip repeats earlier additions and can need quadratic work. Their results may match even though their costs differ. This distinction matters when a class grows from forty students to many thousands of records.

Testing helps you find counterexamples, but passing a few examples does not prove a universal claim. Test an empty list, one fee, equal fees, and a negative adjustment. Then explain what stays true during every loop repetition. That explanation connects the code to all permitted inputs rather than only the examples you happened to try.

How the topics fit a university course

The foundations introduce growth rates, loop counts, recurrences, and memory use. Searching and sorting then give concrete methods you can trace by hand. Later topics cover divide and conquer, greedy choices, dynamic programming, and graphs. These names describe different ways to organise a solution, rather than different programming languages.

In a university exam, a correct final array may earn only part of the marks. You may need to show each pass, justify a loop condition, or derive a cost. Practise writing the input assumption first and the result last. Between them, show the decisions that changed the state. This habit also makes debugging less mysterious.

For a programming laboratory, begin with a tiny input whose answer you can calculate yourself. Translate the pseudocode, run the program, and compare its changing variables with your hand calculation. Increase the input size only after the small case makes sense. If you cannot explain one iteration, adding more data usually hides the mistake.

Why the method is correct

Before iteration i, sum equals the sum of positions 0 through i - 1. Initially i is zero, so this is the empty sum, zero. The next addition includes exactly position i and keeps the statement true. When i reaches n, the statement covers every fee. This repeating fact is called a loop invariant.

Termination needs its own argument. The index starts at zero and grows by one, while n stays fixed. The number n - i of unprocessed amounts decreases each time. It cannot decrease forever while remaining positive. Correctness therefore combines a correct result when the loop stops with a reason it really stops.

Time and space reasoning

The fee algorithm reads n amounts and performs n additions. Its time grows in direct proportion to the number of fees. The variables sum and i use a fixed amount of extra memory. The input list itself occupies n cells, so distinguish input storage from extra working storage. You will give these observations formal names in asymptotic notation.

Common mistakes

Starting a maximum at zero

If every cricket score adjustment is negative, zero may not occur in the data. For a nonempty maximum problem, start with a[0]. Give the empty case a separate result.

Leaving the input rule unstated

A sum of positive fees and a sum allowing refunds are different contracts. Write the permitted range before choosing a C type.

C17 details

The fee total uses C17 int variables because the stated amounts are small. Larger unrestricted totals need a wider type or checked addition; mathematical sums do not remove C overflow limits.
