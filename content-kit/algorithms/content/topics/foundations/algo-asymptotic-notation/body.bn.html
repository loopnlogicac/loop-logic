শুরু করা যাক

কিউয়ের student দশ থেকে দশ হাজার হলো। প্রতিটি pair দেখা পদ্ধতি, প্রত্যেককে একবার দেখার চেয়ে অনেক দ্রুত কাজ বাড়ায়। Asymptotic analysis দীর্ঘমেয়াদি এই বৃদ্ধি তুলনা করে। ইনপুট সাইজ n সামনে রেখে মেশিন-নির্ভর timing আলাদা রাখো।

কোনো শুরুর পর ফাংশনকে ঘেরা বেড়া ভাবো। Upper bound বলে নির্দিষ্ট গুণিতকের চেয়ে দ্রুত বাড়বে না; lower bound বলে ধীর হবে না। কোনো বেড়া একা বলে না তুমি best নাকি worst ইনপুট দেখছ।

সিউডোকোড ও ব্যবহারের নিয়ম

choose the input-size parameter n
define a nonnegative cost f(n)
choose a positive comparison function g(n)
state the required inequality and its quantifiers
give constants and a threshold; prove the inequality

ধাপে ধাপে বোঝো

Upper, lower ও tight bound সংজ্ঞা দাও

f(n) nonnegative cost, যথেষ্ট বড় ইন্টিজার n-এ g(n) positive ধরো। Positive c, n0 থাকলে এবং সব n ≥ n0-এ f(n) ≤ c g(n) হলে f(n) ∈ O(g(n))। O upper bound। Loose bound-ও বৈধ: n হলো O(n²)।

Positive c, n0-এ সব n ≥ n0-এর জন্য f(n) ≥ c g(n) হলে Ω(g(n)), অর্থাৎ lower bound। Positive c1, c2, n0-এ c1 g(n) ≤ f(n) ≤ c2 g(n) হলে Θ(g(n))। একই growth-এর দুই বেড়া tight bound দেয়।

f(n) = 3n + 7-এ n0 = 1 নাও। 7 ≤ 7n বলে f ≤ 10n, তাই O(n)। আবার f ≥ 3n বলে Ω(n)। একসঙ্গে Θ(n)। শুধু একটি সাইজ নয়, পুরো tail-এ চলে এমন কনস্ট্যান্ট দেখাতে হবে।

Strictly ছোট ও বড় growth বোঝো

Little-o big-O-এর চেয়ে শক্ত দাবি। প্রতি c > 0-এর জন্য কোনো n0 থাকলে এবং সব n ≥ n0-এ 0 ≤ f(n) < c g(n) হলে o(g(n))। Threshold c-এর ওপর নির্ভর করতে পারে। g-এর কোনো positive fraction-ই শেষ পর্যন্ত f-এর নিচে থাকে না।

Little-omega উল্টো strict তুলনা। প্রতি positive c-এর জন্য threshold-এর পরে f(n) > c g(n) হলে ω(g(n))। Positive g-তে f/g zero-তে গেলে little-o, infinity-তে গেলে little-omega। Nonzero কনস্ট্যান্ট ratio কোনোটিই নয়।

তাই n ∈ o(n²), কারণ 1/n zero-তে যায়। উল্টো n² ∈ ω(n)। কিন্তু 3n হলো Θ(n), o(n) বা ω(n) নয়। ছোট চিহ্ন বড়টির নিখুঁত বানান নয়; quantifier আলাদা। Big-O-তে একটি কনস্ট্যান্ট, little-o-তে প্রতিটি positive কনস্ট্যান্ট সামলাতে হয়।

পরিচিত ফাংশন ক্রমে সাজাও

যথেষ্ট বড় n-এ সাধারণ ক্রম 1, log n, n, n log n, n², n³, 2^n, n!। পরেরটি একসময় আগেরটি ছাড়ায়। বড় কনস্ট্যান্ট-এ crossover দেরি হতে পারে। Asymptotic notation ছোট প্রতিটি ইনপুট-এ একই speed order বলে না।

Fixed valid base-এ log_b n = log_a n / log_a b, তাই base change কনস্ট্যান্ট multiplier। Base দুই বা দশ একই Θ(log n)। কিন্তু exact halving কাউন্ট-এ base গুরুত্বপূর্ণ; তখন বাদ দেবে না।

Exponential ও বড় polynomial আলাদা। n দ্বিগুণে n³ আটগুণ, 2^n আগের মানের square। Factorial আরও দ্রুত। তাই সব subset দেখা অচল হয়ে যেতে পারে, যখন cubic method মাঝারি ইনপুট সামলায়।

Bound-এর আগে ফাংশন বাছো

Bound দেওয়ার আগে ফাংশন বাছো। Nonempty linear search-এ প্রথমেই match হলে best কাউন্ট 1; শেষে বা absent হলে worst n। দুটোরই upper-lower bound আছে। Ω-কে best case বলা ইনপুট type ও inequality direction মিশিয়ে ফেলে।

Counted operation 5n² + 2n + 9 ধরো। n ≥ 1-এ অন্তত 5n², সর্বোচ্চ 16n²। Explicit কনস্ট্যান্ট-এ tight quadratic bound। ছোট term exact কাউন্ট-এ লাগে, eventual class বদলায় না। তথ্য থাকলে আগে exact ফাংশন লেখো।

পরপর phase-এর cost যোগ। Scan ও quadratic phase Θ(n + n²) = Θ(n²)। Independent nested লুপের প্রতিটি pair body চালালে কাউন্ট গুণ করো। Dependent লুপ-এ আগে sum, যেমন triangular লুপ।

Ratio দিয়ে strict দাবি যাচাই করো

n log n / n² = log n / n zero-তে যায়, তাই n log n হলো o(n²); শুধু loose O(n²)-এর চেয়ে শক্ত। কিন্তু (5n² + 2n + 9)/n² পাঁচে যায়, তাই Θ(n²), o(n²) নয়। Positive finite ratio একই growth বোঝায়।

বাকি সাইজ 16, 8, 4, 2। চার division-এ 1 হয়, logarithmic growth দেখা যায়।

পদ্ধতিটি কেন সঠিক

Upper proof-এ threshold-এর পরের arbitrary n নাও। ছোট term-কে dominant term-এর গুণিতকে বাঁধো। n ≥ 1-এ n ≤ n², 1 ≤ n² দিয়ে upper coefficient 16। Positive ছোট term বাদে lower coefficient 5।

n²-কে O(n) নয় দেখাতে fixed positive c ধরে proposed n0 ও c দুটোর চেয়ে বড় ইন্টিজার n নাও। তখন n² > cn, upper inequality ভাঙে। একটি খারাপ কনস্ট্যান্ট নয়, প্রতিটি সম্ভাব্য কনস্ট্যান্ট-কে হারায়।

সময় ও মেমরির হিসাব

তিন প্রোগ্রামে scan, triangular লুপ, halving গোনা। নির্বাচিত ইনপুট-এ 8, 36, 4; সাধারণভাবে Θ(n), Θ(n²), Θ(log n)। এগুলো mathematical operation, millisecond নয়। প্রতিটি কাউন্টার কনস্ট্যান্ট auxiliary space; time class আলাদা হলেও space একই হতে পারে।

f = O(g) প্রচলিত লেখায় bounded ফাংশন class-এর membership। O(g) একটি সংখ্যা নয়, ইচ্ছেমতো বিয়োগ করবে না।

c = n দিয়ে asymptotic proof হয় না। n বাড়লেও কনস্ট্যান্ট স্থির থাকতে হবে।

গুণফল থেকে logarithm ফেলে দেওয়া

n log n, n-এর চেয়ে দ্রুত বাড়ে। ধীরে বাড়লেও logarithm কনস্ট্যান্ট নয়।

C = 17-এর খুঁটিনাটি

C = 17 optimizer unused result-এর কাজ সরাতে পারে। এখানে কাউন্টার print হয়, তবু source-লেভেল operation কাউন্ট, executed machine instruction-এর প্রতিশ্রুতি নয়।
