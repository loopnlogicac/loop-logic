Introduction

Suppose you must reverse a row of numbered cards on a small desk. You can swap the two end cards using one free spot. Or you can copy every card onto another row. Both methods reverse the order, but the second needs much more desk space.

Space complexity describes how memory use grows with input size. The useful question is usually peak memory: how much storage must exist at the same time? A program may allocate and release many temporary objects over its lifetime while keeping only a small number alive together.

Pseudocode and conventions

left = 0; right = n - 1
while left < right
    saved = a[left]
    a[left] = a[right]; a[right] = saved
    left++; right--

Space Complexity step by step

Auxiliary space and total space

The input array occupies n element cells. Auxiliary space is the extra working storage used beyond the input, under a stated convention about output storage. Total space includes the input as well. Always state whether a separate returned output array is counted, because textbooks sometimes treat required output separately.

An iterative sum uses sum, i and a few fixed bookkeeping values. It needs Θ(1) auxiliary space even though reading its input array requires Θ(n) total storage. A copied reverse keeps a second n-element row, giving Θ(n) extra storage when that output is included. Returning the output does not make its cells disappear.

Measure growth in cells or words before converting to bytes. On a machine where an int occupies four bytes, an n-element int array needs 4n bytes for its elements. That exact byte count is platform-dependent. The Θ(n) classification does not depend on whether a cell occupies four or eight bytes. Use sizeof when a C program needs the actual local size.

Reverse by maintaining two boundaries

An in-place algorithm changes the input storage directly and uses only constant extra working space in the strict sense used here. The two-pointer reversal stores left, right and one saved value. Swap a[left] with a[right], then move both boundaries inward. No second row grows with n.

For [7,3,5,3,1], the first swap gives [1,3,5,3,7]. The second exchanges equal 3 values, leaving the picture unchanged. The boundaries meet at the middle 5, which needs no move. An even-length row stops when left passes right. An empty row starts with right = -1 and performs no array access.

The saved variable prevents losing a value during a swap. Assigning the left value directly into the right cell before saving the old right value would overwrite information. Memory savings do not excuse destructive updates that change the required multiset. Check both the final ordering and the preservation of every original value.

Recursion keeps frames alive

A function call stores information needed to return, such as local variables and a return location. We call this stored context a stack frame. A recursive call keeps its caller's frame alive. Even if every frame has only a few variables, a long chain can use much more than constant space.

For a function calling itself on n - 1 until zero, n + 1 frames may coexist. The stack cost is Θ(n). For one call on floor(n/2), depth is Θ(log n). The depth program reports four live levels for sizes 8, 4, 2 and 1. It counts the base frame too.

Two sequential recursive calls do not automatically double peak stack storage. In a balanced split, the left call returns before the right call begins. Maximum stack depth follows one root-to-leaf path, giving Θ(log n) frames with constant local data. Total calls may still be Θ(n). Time sums the branches; peak space follows simultaneous lifetimes.

Temporary arrays and allocation lifetimes

A merge sort can allocate one shared temporary array of n cells and reuse it across recursive calls. Its array workspace is Θ(n), and its logarithmic stack does not change that total extra order. If every recursive call allocates its own array, inspect when those arrays are released. Arrays along one halving path still sum geometrically, but retaining every completed level's arrays can use more.

Dynamic allocation moves storage to the heap; it does not remove it from space analysis. The heap is a region for objects whose lifetime you manage explicitly in C. Release each owned allocation with free after its last use. Returning a pointer to a local automatic array is invalid because its lifetime has ended.

The examples use small fixed capacities so you can focus on the algorithm. A declared int temp[64] occupies a fixed amount in that particular program. In the general merge algorithm, capacity must grow to handle arbitrary n, so its workspace classification is linear. State whether you analyse the fixed demonstration or the scalable method.

Memory tradeoffs guide implementation

Keeping a copy makes it easier to preserve the original input. An in-place method saves memory but may destroy the order the caller wanted to keep. Choose according to the contract. A university task that asks for the original row and its reversal requires either another output representation or a later restoration step.

Compacting adjacent duplicates illustrates useful reuse. Maintain a read position and a write position in the same sorted array. The write position never moves beyond the read position, so writing a kept value cannot destroy a future unread value. Only the prefix up to the returned length remains part of the result.

Do not confuse in-place with stable. Stability preserves the relative order of records with equal keys. In-place describes workspace. A selection sort can use constant extra storage while reversing equal-key records through a distant swap. These properties answer different design questions and need separate evidence.

Why the method is correct

Before each reversal iteration, positions outside [left,right] already hold their final reversed values. The remaining interval contains exactly the values still needing reversal. Swapping its two endpoints puts both in their final places, and narrowing the interval preserves the claim. When at most one value remains, every position is correct.

The unfinished interval shrinks by two each time, so the routine terminates. For compaction, a different invariant applies: a[0..used) contains one copy of each distinct value in the processed prefix, and used ≤ i before the next read. This second condition explains why reusing storage is safe.

Time and space reasoning

The reversal makes floor(n/2) swaps and uses three integer variables, so it takes Θ(n) time and Θ(1) auxiliary space. The copied reversal also takes Θ(n) time but needs Θ(n) result space under our counting convention. Neither comparison needs exact stack-frame byte sizes. Such sizes depend on the compiler, optimisation choices and calling convention, while growth follows the number of simultaneously live frames.

Common mistakes

Calling recursion free memory

A function with no explicit array can still accumulate frames. Include the maximum active call depth in its auxiliary cost.

Adding all allocations ever made

Peak usage concerns overlapping lifetimes. Storage released before the next phase can often be reused, so sequential peaks combine by a maximum.

Treating a fixed capacity as the general bound

A 64-cell demonstration is fixed. Describe how capacity would scale before claiming a general algorithm uses constant workspace.

C17 details

Automatic arrays and active function frames both occupy real storage in C17. Exact frame sizes are implementation-dependent, so the lesson measures growth rather than assuming a fixed frame byte count.

Summary

Distinguish input, output, auxiliary memory and active recursion frames before judging in-place algorithms.
