Slide a word across a sentence

Imagine looking for a short course code inside a notice. Place the code under the first possible text position and compare letters. If it fails, move it one position right and try again. Naive string matching applies this direct idea to every legal start.

Let n be the text length and m the pattern length. A complete pattern fits at starts zero through n-m when m<=n. Each alignment compares text[start+j] with pattern[j], beginning at j=0.

Our examples use nonempty lowercase Latin tokens and count overlapping occurrences. In ababa, the pattern aba appears at starts zero and two. The second occurrence shares the final a of the first. Whether overlaps count is part of the problem statement, not an implementation detail.

Keep the end of the window inside the text

Use the condition start+m<=n. The right boundary n is excluded, so a window ending exactly there is valid. Inside the window, j<m protects the pattern and text accesses.

The inner loop stops at its first mismatch or after m successful comparisons. Only j==m means a full occurrence. Matching a prefix of the pattern does not count.

The main program records character comparisons, including the mismatch that ends an alignment. This definition lets you compare the trace table with an actual operation count. It is different from counting successful comparisons only.

count = 0
for start = 0 while start + m <= n:
    j = 0
    while j < m:
        compare text[start + j] with pattern[j]
        if different: break
        j++
    if j == m: report start; count++

Restart the pattern at each alignment

For ababa against aba, start zero succeeds after three comparisons. At start one, b differs from a immediately. Start two succeeds after three more comparisons. The total is two occurrences and seven character comparisons.

After a match, moving one position preserves overlaps. Moving m positions instead creates a nonoverlapping policy. Both may be useful, but they answer different questions. The third example makes that alternative explicit.

A first-occurrence search may stop after its first match. Counting all occurrences must continue through the final legal alignment. Starting the next comparison from a remembered partial prefix would be a different algorithm and needs a reason for that reuse.

The lab displays the text, a separator and the pattern in one array. For an empty pattern, it explicitly matches all n+1 boundaries; the C token examples require nonempty patterns. An empty text with a nonempty pattern has no matches.

Include the mismatch comparison

The same text position can be compared at several alignments. That repeated work is the main inefficiency of naive matching. Later algorithms will use information from previous comparisons to avoid some repetitions.

No legal start is skipped

Before each outer iteration, every earlier start has been classified. The inner loop maintains that the first j pattern bytes equal the aligned text bytes. A mismatch proves this alignment cannot match; reaching j==m proves every pattern byte agrees.

The outer loop visits every fitting start exactly once. It therefore reports every occurrence and no invalid one. Overlaps need no special exception because starts advance by one regardless of the previous result.

Repeated prefixes create the worst case

For 1<=m<=n, there are n-m+1 starts, each requiring at most m comparisons. The worst-case time is O((n-m+1)*m), commonly written O(nm). A text of many a letters and a pattern of many a letters ending in b forces long failures repeatedly.

If every first comparison fails, the scan uses one comparison per start. Input reading still costs O(n+m). Searching needs O(1) extra working space beyond the strings and any retained list of matches.

When m>n, there are no search alignments. We use signed lengths in the bounded demonstrations, avoiding unsigned subtraction n-m that could wrap to a huge value.

Decide what an empty pattern means

The token interface does not accept an empty pattern. Some mathematical conventions match it at every boundary, giving n+1 starts; some applications reject it. Choose a policy before extending the program.

A one-byte pattern can occur at every text position. A pattern equal to the whole text has exactly one legal alignment. A longer pattern has none. These boundaries are useful checks for the outer-loop condition.

A partial match is not an occurrence

Counting whenever the first character matches overcounts longer patterns. Require all m comparisons to succeed. Another off-by-one error uses start+m<n and misses the window ending at the final byte.

Do not treat the zero terminator as another text character. strlen excludes it, and the search bounds should do the same. Byte positions here do not represent Bangla grapheme positions; multibyte text needs a specified encoding and index policy.

Keep a direct reference implementation

Naive matching is easy to inspect and useful for short strings or as a reference for a faster search. Test repeated letters, a missing first letter, an exact whole-text match and a pattern longer than the text.

Measure comparisons under a clear definition. A faster elapsed run on one short sample does not change the worst-case bound, and library optimisations can obscure small timing differences.

Bounded strings in C17

The input buffers hold twenty-four letters plus a terminator. Field widths and lowercase checks enforce the intended token domain. C17 string functions operate on bytes ending at a zero byte; they do not understand user-perceived Unicode characters.

Every fitting start gets a test

Naive matching classifies every legal alignment independently. Its simple invariant makes a useful baseline, while repeated prefixes reveal its O(nm) weakness. KMP improves that repeated work by remembering pattern borders.
