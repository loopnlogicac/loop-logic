Keep useful information after a mismatch

Searching repeated text can feel wasteful. After matching ababa, a mismatch should not make you forget that its final aba is also its beginning. KMP, named for Knuth, Morris and Pratt, stores this reusable pattern structure before searching.

A border is a prefix that is also a suffix. A proper border is shorter than the whole string. For ababa, the longest proper border is aba, of length three. The shorter border a also exists. Borders describe equal strings, not physical overlap restrictions.

The prefix function pi[i] gives the length of the longest proper border of pattern[0..i]. For ababaca, it is [0,0,1,2,3,0,1]. This table tells the matcher which already-known equality can survive a failure.

KMP never moves its text index backwards. It may compare the current text character with several pattern positions, but each fallback uses previously gained matched length. The complete process takes linear time in text plus pattern length.

Define matched length before indexing

During prefix construction, i is the new pattern position and j begins at pi[i-1]. That j is a candidate border length for the prefix ending just before i. Compare pattern[i] with pattern[j] to see whether the border extends by one.

On mismatch with j>0, set j=pi[j-1] and compare the same pattern[i] again. This follows the borders of the previous candidate. Once j reaches zero, there is no shorter nonempty candidate; compare with pattern[0] before assigning pi[i].

The matching phase uses the same fallback idea but reads text[i]. Here j is the number of pattern characters currently matched by a suffix of the consumed text. If j becomes m, report start i-m+1, then retain pi[m-1] for overlaps.

The code assumes a nonempty pattern, which guarantees pi[0] and pattern[0] exist. Its input bounds and token convention make that precondition explicit rather than relying on an accidental nonzero length.

pi[0] = 0
for i = 1 to m - 1:
    j = pi[i - 1]
    while j > 0 and pattern[i] != pattern[j]:
        j = pi[j - 1]
    if pattern[i] == pattern[j]: j++
    pi[i] = j

Follow a chain of shorter borders

For ababaca, the prefix ababa ends with border aba, so j is three before processing c. Compare c with pattern[3], which is b: failure. The next candidate is pi[2]=1, the border a. Compare c with pattern[1], another b: failure. Then j becomes pi[0]=0, and c differs from pattern[0]=a. Thus pi[5]=0.

At the final a, j begins at zero. It matches pattern[0], so pi[6]=1. The prefix table does not record how many times each character appears. It records the lengths of nested equal prefixes and suffixes.

The lab builds this table in an array display. Character comparisons colour the corresponding pattern positions, while the numeric array stores completed pi entries. Its fallback notes explain why a shorter candidate remains possible. It implements prefix construction, not the whole text search.

For searching ababa with pattern aba, a full match ends at text index two. Retaining pi[2]=1 keeps that ending a as the beginning of another occurrence. The next b and a complete the second match at start two without rereading the earlier text.

An empty lab pattern produces an empty prefix table. The C token input requires a nonempty pattern. The numeric array displays pi lengths, while the side list gives the actual letters at those positions.

Why the fallback skips no candidate

Suppose the current candidate prefix of length j already matches a suffix of the processed prefix. If the new character fails to extend it, any shorter successful candidate must itself be a border of that length-j string. Otherwise its earlier characters would not agree with the suffix already known to match.

The longest such candidate has length pi[j-1]. Following that link therefore skips only lengths that cannot be valid borders. Repeating the argument visits all remaining possible border lengths from longest to shortest. The first extension found is the longest; if none exists, zero is correct.

During text matching, the invariant says that pattern[0..j) equals the suffix of the consumed text of length j, and no longer candidate survives. A successful character comparison extends it. A failure follows the same exhaustive border chain, preserving possible alignments without decreasing i.

When j reaches m, the last m text bytes equal the pattern, so the reported position is a real match. Any future overlapping match must begin with a proper border of this completed pattern. Retaining its longest border and following further fallbacks preserves all such possibilities. Every occurrence is consequently reported.

Account for increases and decreases

The prefix-building outer loop advances i at most m-1 times. A successful extension increases j by one, so there are at most m-1 such increases. Every fallback strictly decreases j. Across the entire loop, these decreases cannot exceed the amount previously accumulated through increases.

This amortised argument bounds total fallback iterations by O(m), even though a single position may follow several links. Construction therefore takes O(m) time and O(m) space for pi. It is incorrect to multiply every outer step by m merely because a while loop is nested inside it.

The same reasoning applies to matching: consuming a text character advances i, while positive matched length can only be decreased after it was increased. Total matching work is O(n). Reporting z occurrences adds O(z), already at most O(n) for a nonempty pattern. Combined time is O(n+m), with O(m) auxiliary table space.

The bounded examples reserve twenty-four table entries regardless of shorter input. General asymptotic space describes a table sized to m, not the small fixed capacity selected for an educational program. Neither program stores a copy of every matched substring.

Repeated letters and missing text

For one pattern character, pi[0]=0 and each equal text character forms an occurrence. For aaaa, pi=[0,1,2,3], a long border chain. A pattern with no repeated border can have an all-zero prefix table and still match normally.

A missing pattern gives zero reports. A longer pattern also gives none. The examples accept nonempty text tokens, although the matching loop itself would handle n=0 once input parsing allowed it.

An empty pattern requires a separate policy because pi[0] and pattern[j] would be invalid under the current algorithm's assumptions. Reject it or handle boundary matches before entering prefix construction. Do not hide it inside a generic loop bound.

Some books use a failure array beginning with minus one or define a table indexed by matched length rather than character position. Those variants can be correct, but their update formulas differ. Keep this lesson's pi definition and indexing together.

Lengths are not indices of the same kind

Using j=pi[j] instead of pi[j-1] follows the wrong prefix. The current matched prefix has length j and ends at index j-1. Its longest proper border lives in that entry.

Resetting j to zero after every full match loses overlapping information. Decrementing the text index to compensate loses KMP's monotone text scan and can cause repeated work or missed positions.

A fallback should be repeated in a while loop, not performed once with if. The ababaca example needs more than one fallback at c. A single reduction may still leave a mismatching candidate.

Do not advance j after a mismatch at zero. Only equality extends the border. Reading beyond pattern[m-1] is also possible if a complete match is reported without resetting j before the next text iteration.

Explain pi with actual strings

When tracing, write the prefix and suffix corresponding to each positive pi value. Seeing aba at both ends is more informative than memorising the number three. Compare the final match positions with naive matching on short repeated strings.

Keep construction and search in separate functions so their shared fallback idea is visible without confusing their different outer inputs. For streaming text, carry j between input chunks and keep the pattern table; the text itself need not be retained in full.

Byte comparisons under C17

The examples validate lowercase Latin bytes and use twenty-five-byte string buffers. Prefix lengths fit int under this bound. KMP's mathematical logic applies to other token sequences, but a C char scan compares encoded bytes rather than Unicode grapheme clusters. Choose the sequence representation before interpreting reported positions.

A mismatch still leaves structure

KMP stores the pattern's border chain, then reuses it whenever a candidate fails or completes. The text index moves forward, while matched length absorbs the backtracking. Counting total increases and decreases proves the linear bound.
