Introduction

Choose one exam mark as a divider. Move smaller marks to one side and larger marks to the other. Then order each side independently. Quick sort uses this partitioning plan. Unlike merge sort, it performs the main rearrangement before sorting its children.

Quick sort can be fast with balanced divisions, but the pivot can create highly uneven work. The partition contract matters as much as the pivot choice. Lomuto and Hoare partitioning use different boundaries, so their recursive calls must follow their own rules.

Pseudocode and conventions

quick_sort(low, high): if low >= high: return
pivot = a[high]; i = low
for j = low to high - 1
    if a[j] <= pivot: swap a[i], a[j]; i = i + 1
swap a[i], a[high]; p = i
quick_sort(low, p - 1)
quick_sort(p + 1, high)

Quick Sort step by step

Lomuto partition places one pivot finally

The shown Lomuto routine uses the final value a[high] as pivot, with an inclusive interval [low,high]. Begin i = low. Scan j from low through high - 1. Values before i are at most pivot; values from i through j - 1 are greater. Values from j to high - 1 have not yet been classified.

When a[j] is at most pivot, swap a[i] and a[j], then increase i. Otherwise leave a[j] in the greater region. After the scan, exchange a[i] with the pivot at high. The pivot is now at final position p = i. Every earlier key in this interval is at most pivot and every later key is greater.

Sort [low,p - 1] and [p + 1,high], excluding p from both calls. Empty and singleton closed intervals need no work. Equal keys are assigned to the left side by this version's less-than-or-equal rule. That choice is valid but can produce an extremely unbalanced split when many keys equal the pivot.

Trace the final-element pivot

For [7,3,5,3,1], pivot 1 is smaller than all scanned values. No eligible value advances i. The final pivot exchange produces [1,3,5,3,7] with p = 0. Only the right interval remains nontrivial.

The next pivot is 7. Every scanned value is eligible, so several self-swaps occur and p becomes 4. On [3,5,3], pivot 3 moves the two 3 values into the left side and ends at index 2, producing [1,3,3,5,7]. The remaining nontrivial pieces are singletons.

A trace may show a swap whose two indices are equal. That operation preserves the array and still corresponds to the written Lomuto rule. If you count physical exchanges, you may choose to skip such self-swaps, but do not compare that count with a version that includes them without stating the convention.

Hoare partition returns a split boundary

Hoare's method commonly chooses a pivot value near the middle and starts scans outside both ends. Move i right until a[i] is at least pivot. Move j left until a[j] is at most pivot. If i has met or passed j, return j as the split. Otherwise exchange a[i] and a[j] and repeat the scans.

The scans advance before testing their next values. This is essential when keys equal pivot: after a swap, both scans must still progress. Choosing a pivot from within the interval guarantees that the initial scans meet a stopping value. Bounds and pivot conventions must be analysed together if you change that recipe.

The returned j is a boundary, not necessarily the pivot's final position. Recursion sorts [low,j] and [j + 1,high]. Using Lomuto's p - 1 rule with a Hoare boundary can skip an unsorted value. Conversely, including a Lomuto pivot again can prevent the interval from shrinking.

Hoare's scheme often performs fewer exchanges than basic Lomuto partitioning, especially with equal keys. It is still generally unstable because distant exchanges can cross equal records. Neither partition name alone promises constant recursion stack space or immunity from bad splits.

Balanced and unbalanced recurrence costs

A partition scans Θ(n) values. If the pivot divides into two roughly equal parts, T(n) is about 2T(n/2) + Θ(n), giving Θ(n log n). If one side is empty and the other has n - 1 values repeatedly, T(n) = T(n - 1) + Θ(n), giving Θ(n²).

With a final-element pivot, already ascending distinct input chooses the largest value every time. Reverse order also produces extreme splits. All-equal input is particularly bad for this Lomuto less-than-or-equal version: every value joins one side. The word sorted does not mean best case for every sorting method.

The ordinary two-recursive-call implementation has O(n) stack space in the worst case and O(log n) expected depth under random pivots. You can recurse on the smaller side and loop over the larger side to guarantee O(log n) stack depth. That transformation controls memory even when time remains quadratic.

Random pivots change the probability model

Randomised quick sort chooses a pivot index uniformly from the active interval, swaps it to high, and applies the same Lomuto routine. For distinct keys, expected work is Θ(n log n) for every fixed input order. Random choice makes consistently extreme ranks unlikely; it does not make them impossible.

The worst-case time remains Θ(n²). A fixed seed produces reproducible demonstrations, while a genuine uniform source supports the usual expectation proof. C rand can be seeded for an example, but rand() modulo the interval length may introduce bias. A production implementation should use an appropriate unbiased selection method.

For a small reproducible teaching program, an unsigned integer generator can use defined wraparound arithmetic and rejection sampling to choose a bounded index. It illustrates the mechanism without claiming cryptographic randomness. Analyse its pivot distribution separately from the pure partition correctness proof.

When duplicates dominate, three-way partitioning can group values below, equal to, and above pivot. The equal group then needs no recursive sort. This avoids the all-equal degeneration of basic Lomuto. It is an additional variant; the animation deliberately uses the stated two-way Lomuto contract so its decisions remain comparable with the first C example.

Why the method is correct

During Lomuto's scan, a[low..i) contains only keys at most pivot, a[i..j) contains only keys greater than pivot, and a[j..high) is unclassified. Swapping an eligible key into i and advancing both boundaries preserves these regions. Rejecting a large key extends the greater region. The pivot stays at high until the final exchange.

After that exchange, p is a valid final pivot position. Induct on interval length: the two shorter recursive intervals become sorted, and every left key is no greater than pivot while every right key is greater. Their concatenation is sorted and preserves the original records. Strictly shorter child intervals ensure termination.

Time and space reasoning

Lomuto partition takes linear time and constant local workspace. Balanced recursion gives logarithmic levels of linear total work, while a chain of sizes n, n - 1 and smaller creates quadratic work. The simple quick-sort routine is unstable and has potentially linear auxiliary stack space. Random pivot selection improves expected time for fixed distinct inputs, but does not change its deterministic worst-case bound.

Common mistakes

Mixing partition return contracts

Lomuto returns a final pivot index; Hoare returns a boundary. Use each implementation with its matching recursive intervals.

Calling quick sort on a pivot again

A repeated interval may never shrink. Exclude the final Lomuto pivot from both children.

Calling randomisation a worst-case guarantee

Random pivots support an expectation over pivot choices. An unlucky sequence can still make extreme splits.

C17 details

These partition routines use C17 signed indices for closed intervals. The reproducible pivot example uses uint32_t on systems providing this exact-width unsigned type.
