শুরু করা যাক

Tournament-এ বারবার strongest remaining player ওপরে ওঠে। Max-হিপ-এ parent দুই child-এর অন্তত সমান বড়, তাই root-এ একটি maximum। হিপ সর্ট root শেষে নিয়ে বাকি হিপ সারায়।

হিপ হলো অ্যারেতে রাখা logical ট্রি;ভ্যালু-প্রতি node object allocate নয়। Iterative repair-এ worst O(n log n) time ও কনস্ট্যান্ট auxiliary workspace একসঙ্গে পাওয়া যায়।

সিউডোকোড ও ব্যবহারের নিয়ম

for root = floor(n / 2) - 1 down to 0: sift(n, root)
sift(size, root): while root has a child
    child = index of larger child
    if a[root] >= a[child]: stop sifting
    swap a[root], a[child]; root = child
for end = n - 1 down to 1
    swap a[0], a[end]
    sift(end, 0)

ধাপে ধাপে বোঝো

অ্যারে-র ভেতরের ট্রি পড়ো

Zero-based root-এর left 2*root+1, right 2*root+2। ইনডেক্স active length সাইজ-এর নিচে হলেই child আছে। Nonroot i-এর parent floor((i-1)/2)। এটি left-to-right ভরা complete binary ট্রি।

হিপ rule parent-child তুলনা করে;left child right-এর ছোট বা এক subtree-র সবাই অন্যের আগে চাই না। তাই পুরো sorted অ্যারে নয়;শুধু root maximum নিশ্চিত।

[7, 3, 5, 3, 1]-এ root 7 child 3, 5-এর বড়। ইনডেক্স 1-এর3 child 3, 1-এর বড় বা সমান। Ascending না হলেও ইতিমধ্যে max-হিপ। Animation-এ হিপ order ও sorted order আলাদা বোঝায়।

ভুল parent sift-down করো

sift(সাইজ, root)-এ child subtree আগেই হিপ ধরে। বড় existing child বাছো। Parent তার অন্তত সমান হলে অন্য child-এরও, repair শেষ। নইলে সোয়াপ করে ওই child পজিশন থেকে আবার নাও।

সোয়াপ-এর পরে শুধু একটি downward path broken থাকতে পারে। ওপরে ওঠা মান নতুন জায়গায় দুই child root-এর বড়। ছোট displaced মান নিচে rule ভাঙতে পারে বলে root নামে। ছোট child নিলে বড় sibling-এর সঙ্গে ভুল থেকেই যায়।

Right child আছে দেখে তবেই পড়ো;complete ট্রি-র শেষ parent-এর শুধু left থাকতে পারে। Leaf repair চায় না। Iterative লুপ ordered parent বা leaf-এ থামে, তাই ফ্রেম নয়, fixed ইনডেক্স লাগে।

নিচ থেকে হিপ বানাও

প্রতি leaf নিজেই one-node হিপ। Last possible parent floor(n/2)-1 থেকে zero-এর দিকে sift করো। Parent-এ পৌঁছালে দুই child subtree আগেই repair করা। শেষে পুরো active অ্যারে max-হিপ।

এক sift O(log n) হলেও build Θ(n)। বেশিরভাগ node নিচে, অল্প নামতে পারে। প্রায় n/2 leaf, n/4 height 1, n/8 height 2, …। Weighted n(1/4+2/8+3/16+…) কনস্ট্যান্ট×n-এ bounded।

Coarse n log n upper bound বৈধ, tight নয়। Bottom-up ও empty হিপ-এ প্রতিটি ভ্যালু insert আলাদা। Repeated insertion worst Θ(n log n)। কোন construction দেখছ বলো।

Maximum suffix-এ নাও

হিপ হলে a[0], a[end] সোয়াপ;end শুরু n-1। Old root final sorted ভ্যালু। Active length end করে ওই cell বাদ;leaf থেকে আসা নতুন root sift লাগতে পারে।

এক active ভ্যালু পর্যন্ত exchange-repair। Suffix ডান থেকে বাঁয়ে বাড়ে;largest একদম ডানে, next তার আগে। Active হিপ-এ শুধু unplaced মান।

Repair সাইজ-এ completed suffix ঢোকাবে না। বেশি সাইজ final maximum ফের টেনে আনতে পারে। sift(a, end, 0)-এ end length, active 0..end-1;swapped cell end বাদ।

Guarantee ও সীমা বোঝো

Linear build-এর পরে সর্বোচ্চ n-1 extraction, প্রতি O(log n)। Ascending, reverse, adversarial-এও worst O(n log n)। Simple final-pivot quick সর্ট থেকে আলাদা। Practical speed access ও movement-এও নির্ভর করে।

Ordinary হিপ সর্ট unstable। [2A, 2B, 1] max-হিপ। Root-end সোয়াপ-এ2A শেষে, repair-এ2B ওপরে;final [1, 2B, 2A]। Strict child কম্পারিজন দূরের movement আটকায় না।

ইনপুট cell-ই হিপ। Iterative sift-এ root, child, সাইজ, temp সোয়াপ, তাই O(1) auxiliary। রিকার্সিভ sift O(log n) স্ট্যাক নিত;strict in-place দাবিতে detail জরুরি।

Priority কিউ-তেও পুরো সর্ট ছাড়া বারবার largest/smallest চাওয়া যায়। হিপ সর্ট পুরো হিপ খরচ করে ordered অ্যারে দেয়। Repair একই ধারণা, আউটপুট contract আলাদা।

পদ্ধতিটি কেন সঠিক

Sift-এর অনুমান দুই subtree হিপ। বড় child উঠলে নতুন parent rule মানে;শুধু displaced ভ্যালু-এর path ভুল থাকতে পারে। Path leaf-এর দিকে কঠোরভাবে এগোয়, তাই valid হিপ-এ থামে।

Extraction invariant:prefix max-হিপ, suffix sorted, কোনো prefix ভ্যালু suffix-এর কোনোটির বেশি নয়। Root suffix-এ নিলে largest ঠিক বসে। Suffix না ছুঁয়ে repair। হিপ one-এ নামলে sorted permutation।

সময় ও মেমরির হিসাব

Complete ট্রি height Θ(log n)। Build-এ সব node-এর full height নয়, নিজস্ব height যোগে Θ(n)। Extraction O(n log n), worst total Θ(n log n)। Iterative repair O(1) extra। Insertion-এর মতো adaptive নয়;আগে sorted হলেও এক linear verification-এ থামে না।
