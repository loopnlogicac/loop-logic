শুরু করা যাক

Tournament-এ বারবার strongest remaining player ওপরে ওঠে। Max-heap-এ parent দুই child-এর অন্তত সমান বড়,তাই root-এ একটি maximum। Heap sort root শেষে নিয়ে বাকি heap সারায়।

Heap হলো array-তে রাখা logical tree;value-প্রতি node object allocate নয়। Iterative repair-এ worst O(n log n) time ও constant auxiliary workspace একসঙ্গে পাওয়া যায়।

সিউডোকোড ও ব্যবহারের নিয়ম

for root = floor(n / 2) - 1 down to 0: sift(n, root)
sift(size, root): while root has a child
    child = index of larger child
    if a[root] >= a[child]: stop sifting
    swap a[root], a[child]; root = child
for end = n - 1 down to 1
    swap a[0], a[end]
    sift(end, 0)

ধাপে ধাপে বোঝো

Array-র ভেতরের tree পড়ো

Zero-based root-এর left2*root+1,right2*root+2। Index active length size-এর নিচে হলেই child আছে। Nonroot i-এর parent floor((i-1)/2)। এটি left-to-right ভরা complete binary tree।

Heap rule parent-child তুলনা করে;left child right-এর ছোট বা এক subtree-র সবাই অন্যের আগে চাই না। তাই পুরো sorted array নয়;শুধু root maximum নিশ্চিত।

[7,3,5,3,1]-এ root7 child3,5-এর বড়। Index1-এর3 child3,1-এর বড় বা সমান। Ascending না হলেও ইতিমধ্যে max-heap। Animation-এ heap order ও sorted order আলাদা বোঝায়।

ভুল parent sift-down করো

sift(size,root)-এ child subtree আগেই heap ধরে। বড় existing child বাছো। Parent তার অন্তত সমান হলে অন্য child-এরও,repair শেষ। নইলে swap করে ওই child position থেকে আবার নাও।

Swap-এর পরে শুধু একটি downward path broken থাকতে পারে। ওপরে ওঠা মান নতুন জায়গায় দুই child root-এর বড়। ছোট displaced মান নিচে rule ভাঙতে পারে বলে root নামে। ছোট child নিলে বড় sibling-এর সঙ্গে ভুল থেকেই যায়।

Right child আছে দেখে তবেই পড়ো;complete tree-র শেষ parent-এর শুধু left থাকতে পারে। Leaf repair চায় না। Iterative loop ordered parent বা leaf-এ থামে,তাই frame নয়,fixed index লাগে।

নিচ থেকে heap বানাও

প্রতি leaf নিজেই one-node heap। Last possible parent floor(n/2)-1 থেকে zero-এর দিকে sift করো। Parent-এ পৌঁছালে দুই child subtree আগেই repair করা। শেষে পুরো active array max-heap।

এক sift O(log n) হলেও build Θ(n)। বেশিরভাগ node নিচে,অল্প নামতে পারে। প্রায় n/2 leaf,n/4 height1,n/8 height2,…। Weighted n(1/4+2/8+3/16+…) constant×n-এ bounded।

Coarse n log n upper bound বৈধ,tight নয়। Bottom-up ও empty heap-এ প্রতিটি value insert আলাদা। Repeated insertion worst Θ(n log n)। কোন construction দেখছ বলো।

Maximum suffix-এ নাও

Heap হলে a[0],a[end] swap;end শুরু n-1। Old root final sorted value। Active length end করে ওই cell বাদ;leaf থেকে আসা নতুন root sift লাগতে পারে।

এক active value পর্যন্ত exchange-repair। Suffix ডান থেকে বাঁয়ে বাড়ে;largest একদম ডানে,next তার আগে। Active heap-এ শুধু unplaced মান।

Repair size-এ completed suffix ঢোকাবে না। বেশি size final maximum ফের টেনে আনতে পারে। sift(a,end,0)-এ end length,active0..end-1;swapped cell end বাদ।

Guarantee ও সীমা বোঝো

Linear build-এর পরে সর্বোচ্চ n-1 extraction,প্রতি O(log n)। Ascending,reverse,adversarial-এও worst O(n log n)। Simple final-pivot quick sort থেকে আলাদা। Practical speed access ও movement-এও নির্ভর করে।

Ordinary heap sort unstable। [2A,2B,1] max-heap। Root-end swap-এ2A শেষে,repair-এ2B ওপরে;final [1,2B,2A]। Strict child comparison দূরের movement আটকায় না।

Input cell-ই heap। Iterative sift-এ root,child,size,temp swap,তাই O(1) auxiliary। Recursive sift O(log n) stack নিত;strict in-place দাবিতে detail জরুরি।

Priority queue-তেও পুরো sort ছাড়া বারবার largest/smallest চাওয়া যায়। Heap sort পুরো heap খরচ করে ordered array দেয়। Repair একই ধারণা,output contract আলাদা।

পদ্ধতিটি কেন সঠিক

Sift-এর অনুমান দুই subtree heap। বড় child উঠলে নতুন parent rule মানে;শুধু displaced value-এর path ভুল থাকতে পারে। Path leaf-এর দিকে কঠোরভাবে এগোয়,তাই valid heap-এ থামে।

Extraction invariant:prefix max-heap,suffix sorted,কোনো prefix value suffix-এর কোনোটির বেশি নয়। Root suffix-এ নিলে largest ঠিক বসে। Suffix না ছুঁয়ে repair। Heap one-এ নামলে sorted permutation।

সময় ও মেমরির হিসাব

Complete tree height Θ(log n)। Build-এ সব node-এর full height নয়,নিজস্ব height যোগে Θ(n)। Extraction O(n log n),worst total Θ(n log n)। Iterative repair O(1) extra। Insertion-এর মতো adaptive নয়;আগে sorted হলেও এক linear verification-এ থামে না।

প্রচলিত ভুল

শুধু left child দেখা

বড় existing child ওঠাও। নইলে বড় right child-এর সঙ্গে rule ভাঙা থাকতে পারে।

Original n দিয়ে repair

Sorted suffix আর heap data নয়। প্রতি extraction-এর পরে reduced length পাঠাও।

Build-কে tight n log n বলা

Leaf পারে না এমন কাজ charge করে n log n tight বলবে না। Height-ভিত্তিক sum-এ linear build দেখো।

C17-এর খুঁটিনাটি

এখানে max64-তে C17 signed child index। Unrestricted size-এ 2*root-এর আগে উপযুক্ত type ও overflow guard নাও।
