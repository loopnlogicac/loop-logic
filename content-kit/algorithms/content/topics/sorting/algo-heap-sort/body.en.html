Introduction

A tournament repeatedly promotes the strongest remaining player. A max-heap arranges values so that every parent is at least as large as either child. Its root therefore gives quick access to a largest value. Heap sort moves that root to the end and repairs the remaining heap.

The heap is a logical tree stored inside an array. You do not allocate a node object for every value. This representation lets heap sort combine a worst-case O(n log n) time bound with constant auxiliary workspace when the repair routine is iterative.

Pseudocode and conventions

for root = floor(n / 2) - 1 down to 0: sift(n, root)
sift(size, root): while root has a child
    child = index of larger child
    if a[root] >= a[child]: stop sifting
    swap a[root], a[child]; root = child
for end = n - 1 down to 1
    swap a[0], a[end]
    sift(end, 0)

Heap Sort step by step

Read the tree inside the array

For zero-based position root, the left child is 2*root + 1 and the right child is 2*root + 2. A child exists only when its index is below size, the active heap length. For a nonroot position i, the parent is floor((i - 1)/2). These formulas describe a complete binary tree filled from left to right.

The heap rule compares a parent with its children. It does not require the left child to be smaller than the right child, or all values on one subtree to precede all values in the other. A heap is therefore not a fully sorted array. Only the root is guaranteed to be a largest active value.

For [7,3,5,3,1], root 7 dominates children 3 and 5. The parent 3 at index 1 dominates children 3 and 1. This input already happens to be a max-heap, although it is not ascending. That makes it useful for separating heap order from sorted order in the animation.

Sift a misplaced parent down

The sift(size,root) routine assumes the child subtrees are already heaps. Choose the larger existing child. If the parent is at least as large as that child, it is also at least as large as the other child, so repair is complete. Otherwise exchange the parent with the larger child and continue at that child's position.

Only one downward path can remain broken after a swap. The promoted value now dominates both child roots at its new position. The displaced smaller value may still violate the heap rule below, which is why root moves down. Choosing the smaller child could leave the larger sibling above the parent and fail to repair the heap.

Check the right child's existence before reading it. A complete tree can end with a node that has only a left child. Leaves have no child and need no repair. The iterative while loop stops either at a valid parent-child order or at a leaf, so it uses a fixed number of index variables instead of recursive frames.

Build from the bottom upward

Every leaf is already a valid one-node heap. The last possible parent is floor(n/2) - 1. Starting there, sift each parent down while moving root towards zero. When you reach a parent, both its child subtrees have already been repaired. At the end, the entire active array is a max-heap.

Building a heap is Θ(n), even though a single sift can cost O(log n). Most nodes are close to the bottom and can move only a little. Roughly n/2 nodes are leaves, n/4 have height one, n/8 have height two, and so on. The weighted sum n times (1/4 + 2/8 + 3/16 + ...) is bounded by a constant times n.

The coarse bound n times log n is a valid upper bound but misses this tighter result. Bottom-up build differs from repeatedly inserting each input value into an initially empty heap. Repeated insertion can require Θ(n log n) worst-case work. State which construction method you are analysing.

Extract a maximum into the suffix

Once the max-heap exists, exchange a[0] with a[end], where end starts at n - 1. The old root becomes a final sorted value at the right end. Decrease the active heap length to end, excluding that value. The new root came from a leaf and may need to sift down.

Repeat the exchange and repair until only one active value remains. The suffix grows in ascending final order from right to left: the largest value is furthest right, then the next largest immediately before it. The active heap contains only the still-unplaced values.

During a repair, never include the completed suffix in size. A too-large size could pull a final maximum back into the heap. In the C routine, sift(a,end,0) uses end as a length, so indices zero through end - 1 remain active. The exchanged position end is excluded.

Understand guarantees and limitations

Heap sort performs at most n - 1 extractions, each with O(log n) repair, after linear heap construction. It guarantees O(n log n) worst-case time even on ascending, reverse or adversarial input. This distinguishes it from simple final-pivot quick sort. Practical speed can still depend on access patterns and data movement.

Ordinary heap sort is unstable. Consider [2A,2B,1], already a max-heap. The first root-end exchange moves 2A to the final position. A repair promotes 2B in the active heap. The eventual ascending output is [1,2B,2A], reversing the equal records. Strict child comparisons do not prevent this distant movement.

Heap sort uses the input cells as its heap representation. The iterative sift needs only root, child, size and a temporary swap value. Therefore its auxiliary space is O(1), independent of n. A recursive sift would add O(log n) stack depth, so the implementation detail matters for the strict in-place claim.

Heaps also support priority queues, where you repeatedly request a largest or smallest item without sorting everything first. Heap sort instead consumes the whole heap to produce a final ordered array. The same repair idea appears in both uses, but their output contracts differ.

Why the method is correct

Sift assumes both child subtrees are heaps. When the larger child rises, its new parent position satisfies the heap rule; only the displaced value's downward path can remain invalid. The path strictly moves towards a leaf, so repair terminates with a valid heap.

The outer extraction invariant says the prefix is a max-heap, the suffix is sorted, and no prefix value exceeds any suffix value. Moving the root to the suffix places the largest remaining value correctly. Repair restores the prefix heap without touching the suffix. Shrinking the heap to one value therefore gives a sorted permutation.

Time and space reasoning

The height of a complete binary tree is Θ(log n). Build-heap sums node heights to Θ(n), rather than charging every node the full height. Extraction costs sum to O(n log n) and the worst-case total is Θ(n log n). Iterative repair keeps auxiliary space O(1). Heap sort is not adaptive in the same useful way as insertion sort: an already ordered array does not let this version stop after a single linear verification.

Common mistakes

Comparing only the left child

Promote the larger existing child. Otherwise a larger right child can still violate the parent rule after the exchange.

Repairing with the original n

The sorted suffix is no longer heap data. Pass the reduced active length after each extraction.

Claiming build takes n log n tightly

That charges leaves for work they cannot do. Sum the height-based costs to obtain the linear construction bound.

C17 details

Heap child formulas use C17 signed indices within a maximum length of 64 here. For unrestricted sizes, select an index type and overflow guards before computing twice a root index.
