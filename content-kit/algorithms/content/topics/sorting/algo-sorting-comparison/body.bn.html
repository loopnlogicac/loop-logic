শুরু করা যাক

এক খাতা ও হাজার খাতা একইভাবে বহন করবে না। সর্ট-ও কাজভেদে বাছতে হয়। Nearly ordered ছোট অ্যারে, কম মেমরি, bounded mark range, tie order—প্রতিটি অন্য পছন্দে নিতে পারে।

Contract-এর সঙ্গে guarantee মেলাও। রেকর্ড কাউন্ট, কী representation, workspace, stability আগে বলো;তারপর time। “Fastest সর্ট” স্লোগান উপযোগিতার শর্ত ঢাকে।

ধাপে ধাপে বোঝো

কম্পারিজন table শর্তসহ পড়ো

Best, average, worst আলাদা ইনপুট/probability assumption। Bubble-এর linear best-এ early flag, insertion-এ ascending ইনপুট। Selection order যাই হোক suffix scan। এখানে merge সবসময় divide-merge, no boundary skip।

Quick-এর expected n log n distinct কী-তে random pivot rank ধরে। Final deterministic pivot ascending-এ quadratic। হিপ worst n log n upper guarantee দেয়। Name দিয়ে pivot, duplicate বা রিকার্শন variation জানা যায় না।

Space ইনপুটের বাইরের auxiliary। Merge-counting বাফার, iterative হিপ অল্প ভেরিয়েবল। Simple রিকার্সিভ quick worst linear স্ট্যাক, যদিও partition কনস্ট্যান্ট। Strict convention-এ সেই রিকার্সিভ version guaranteed in-place নয়।

রেকর্ড movement-এ stability

আগে roll, পরে mark সর্ট ধরো। Stable mark সর্ট equal mark-এ increasing roll রাখে। Unstable সেটি গুলাতে পারে। শুধু ascending mark চাইলে দুই ফলই ঠিক;tiebreak roll চাইলে stable আচরণ যথেষ্ট।

দুই3-এর ইন্টিজার আউটপুট arrival দেখায় না। লেবেল বা দ্বিতীয় field নাও। Bubble-insertion strict movement, merge left-equality tie রাখে। Standard selection, quick, হিপ distant সোয়াপ-এ equal রেকর্ড পার করে।

Mark-এর পরে original পজিশন compare করে total order করা যায়। Unstable underlying সর্ট-এও deterministic tie হয়। কিন্তু extra field ও rule representation-এর অংশ;library অ্যালগরিদম stable হয়ে গেছে বলবে না।

Worst কম্পারিজন n log n লাগে কেন

n distinct কী-তে n! ইনপুট order। কম্পারিজন-only সর্ট-কে সেগুলো আলাদা করার তথ্য শিখতে হয়। দুই-outcome decision binary ট্রিতে leaf এক ordering outcome চেনে।

Height h-এ সর্বোচ্চ2^h leaf;তাই2^h≥n!, h≥log2(n!)। যথেষ্ট বড় n-এ factorial-এর অন্তত অর্ধেক factor≥n/2, তাই log2(n!)≥(n/2)log2(n/2)। Worst কম্পারিজন Ω(n log n) প্রমাণ।

Bound arbitrary distinct permutation ও কম্পারিজন-only তথ্যের। প্রতিটি ইনপুট n log n চায় নয়;adaptive method sorted ইনপুট linear-এ দেখে। Structured domain সরাসরি নেওয়া counting-radix-ও এর বাইরে।

Decision ট্রি worst path বলে, processor-এর measured second নয়। Long string বা বহু-field কম্পারিজন নিজে expensive হতে পারে। Cost nonconstant হলে ধরো, এক machine instruction ভাববে না।

C qsort contract নাও

stdlib.h-তে qsort। Base address, element কাউন্ট, সাইজ, comparator দাও। Comparator দুই const void পয়েন্টার পায়। সঠিক element-পয়েন্টার type-এ cast করে read করো, কোনোটিই বদলাবে না।

প্রথমটি আগে হলে negative, equal zero, পরে positive। Safe ইন্টিজার pattern (x>y)-(x<y)। x-y extreme signed কী-তে overflow, undefined behavior বা ভুল sign দিতে পারে।

Calling scope-এ actual অ্যারে হলে sizeof a[0] নাও, পয়েন্টার সাইজ নয়। Struct হলে সঠিক type ও field compare। সব কম্পারিজন এক consistent order মানবে;মতবদল comparator contract ভাঙে।

C standard qsort-এ quick সর্ট implementation, stability বা universal asymptotic cost বাধ্যতামূলক করে না। নাম ঐতিহাসিক;library অন্য method নিতে পারে। Strict resource/stability চাইলে documented guarantee-মেলা implementation নাও।

Constraint থেকে পছন্দ করো

ত্রিশ nearly ordered mark-এ insertion স্বচ্ছ পছন্দ:inversion-ভিত্তিক কাজ, কনস্ট্যান্ট extra। বড় arbitrary অ্যারে ও strict কনস্ট্যান্ট workspace-এ iterative হিপ worst bound দেয়। Fashion নয়, requirement অনুযায়ী।

Equal mark-এর roll order চাইলে linear বাফার থাকলে stable merge মানায়। ছোট ইন্টিজার range-এ n+k ও n log n তুলনা। ছোট কী width ও well-defined ডিজিট-এ radix-ও হতে পারে।

বিশেষ guarantee না লাগা app-এ library সর্ট implementation ভুল কমায়। Comparator তোমার দায়;equal ও extreme কী টেস্ট করো। Reliable API inconsistent বা overflowing comparator সারায় না।

পরীক্ষার design উত্তরে বাদ দেওয়া বিকল্পও বলো। Huge interval-এর দশ sparse কী-তে counting মেমরি waste। শুধু stable বলে bubble নিলে quadratic worst এড়ায় না। প্রতিটি constraint-কে property-র সঙ্গে মেলাও।

পদ্ধতিটি কেন সঠিক

ইন্টিজার relation তিনটি দেখো। x<y-এ0-1=-1, equal-এ0, x>y-এ1-0=1। শুধু boolean result বিয়োগ, extreme difference overflow নেই। সাধারণ consistent ইন্টিজার order হয়।

Universal winner নয়, required property প্রমাণ করো। Decision ট্রি worst কম্পারিজন, stable rule রেকর্ড order, workspace simultaneous বাফার-ফ্রেম গোনে। Contract-এর আলাদা প্রশ্নের উত্তর।

সময় ও মেমরির হিসাব

Table এখানকার implementation-এর। Counting range k, radix ডিজিট d/base b। Simple quick worst O(n) স্ট্যাক, random-এ expected log ডেপথ। Qsort-এ universal standard complexity/stability নেই। একই নামের সব version-এর গুণ ভাববে না।
