শুরু করা যাক

এক খাতা ও হাজার খাতা একইভাবে বহন করবে না। Sort-ও কাজভেদে বাছতে হয়। Nearly ordered ছোট array,কম memory,bounded mark range,tie order—প্রতিটি অন্য পছন্দে নিতে পারে।

Contract-এর সঙ্গে guarantee মেলাও। Record count,key representation,workspace,stability আগে বলো;তারপর time। “Fastest sort” স্লোগান উপযোগিতার শর্ত ঢাকে।

সিউডোকোড ও ব্যবহারের নিয়ম

compare(left, right): read keys x and y
return (x > y) - (x < y)
qsort(a, n, sizeof a[0], compare)
verify adjacent keys are nondecreasing

ধাপে ধাপে বোঝো

Comparison table শর্তসহ পড়ো

Best,average,worst আলাদা input/probability assumption। Bubble-এর linear best-এ early flag,insertion-এ ascending input। Selection order যাই হোক suffix scan। এখানে merge সবসময় divide-merge,no boundary skip।

Quick-এর expected n log n distinct key-তে random pivot rank ধরে। Final deterministic pivot ascending-এ quadratic। Heap worst n log n upper guarantee দেয়। Name দিয়ে pivot,duplicate বা recursion variation জানা যায় না।

Space input-এর বাইরের auxiliary। Merge-counting buffer,iterative heap অল্প variable। Simple recursive quick worst linear stack,যদিও partition constant। Strict convention-এ সেই recursive version guaranteed in-place নয়।

Record movement-এ stability

আগে roll,পরে mark sort ধরো। Stable mark sort equal mark-এ increasing roll রাখে। Unstable সেটি গুলাতে পারে। শুধু ascending mark চাইলে দুই ফলই ঠিক;tiebreak roll চাইলে stable আচরণ যথেষ্ট।

দুই3-এর integer output arrival দেখায় না। Label বা দ্বিতীয় field নাও। Bubble-insertion strict movement,merge left-equality tie রাখে। Standard selection,quick,heap distant swap-এ equal record পার করে।

Mark-এর পরে original position compare করে total order করা যায়। Unstable underlying sort-এও deterministic tie হয়। কিন্তু extra field ও rule representation-এর অংশ;library algorithm stable হয়ে গেছে বলবে না।

Worst comparison n log n লাগে কেন

n distinct key-তে n! input order। Comparison-only sort-কে সেগুলো আলাদা করার তথ্য শিখতে হয়। দুই-outcome decision binary tree-তে leaf এক ordering outcome চেনে।

Height h-এ সর্বোচ্চ2^h leaf;তাই2^h≥n!,h≥log2(n!)। যথেষ্ট বড় n-এ factorial-এর অন্তত অর্ধেক factor≥n/2,তাই log2(n!)≥(n/2)log2(n/2)। Worst comparison Ω(n log n) প্রমাণ।

Bound arbitrary distinct permutation ও comparison-only তথ্যের। প্রতিটি input n log n চায় নয়;adaptive method sorted input linear-এ দেখে। Structured domain সরাসরি নেওয়া counting-radix-ও এর বাইরে।

Decision tree worst path বলে,processor-এর measured second নয়। Long string বা বহু-field comparison নিজে expensive হতে পারে। Cost nonconstant হলে ধরো,এক machine instruction ভাববে না।

C qsort contract নাও

stdlib.h-তে qsort। Base address,element count,size,comparator দাও। Comparator দুই const void pointer পায়। সঠিক element-pointer type-এ cast করে read করো,কোনোটিই বদলাবে না।

প্রথমটি আগে হলে negative,equal zero,পরে positive। Safe integer pattern (x>y)-(x<y)। x-y extreme signed key-তে overflow,undefined behavior বা ভুল sign দিতে পারে।

Calling scope-এ actual array হলে sizeof a[0] নাও,pointer size নয়। Struct হলে সঠিক type ও field compare। সব comparison এক consistent order মানবে;মতবদল comparator contract ভাঙে।

C standard qsort-এ quick sort implementation,stability বা universal asymptotic cost বাধ্যতামূলক করে না। নাম ঐতিহাসিক;library অন্য method নিতে পারে। Strict resource/stability চাইলে documented guarantee-মেলা implementation নাও।

Constraint থেকে পছন্দ করো

ত্রিশ nearly ordered mark-এ insertion স্বচ্ছ পছন্দ:inversion-ভিত্তিক কাজ,constant extra। বড় arbitrary array ও strict constant workspace-এ iterative heap worst bound দেয়। Fashion নয়,requirement অনুযায়ী।

Equal mark-এর roll order চাইলে linear buffer থাকলে stable merge মানায়। ছোট integer range-এ n+k ও n log n তুলনা। ছোট key width ও well-defined digit-এ radix-ও হতে পারে।

বিশেষ guarantee না লাগা app-এ library sort implementation ভুল কমায়। Comparator তোমার দায়;equal ও extreme key test করো। Reliable API inconsistent বা overflowing comparator সারায় না।

পরীক্ষার design উত্তরে বাদ দেওয়া বিকল্পও বলো। Huge interval-এর দশ sparse key-তে counting memory waste। শুধু stable বলে bubble নিলে quadratic worst এড়ায় না। প্রতিটি constraint-কে property-র সঙ্গে মেলাও।

পদ্ধতিটি কেন সঠিক

Integer relation তিনটি দেখো। x<y-এ0-1=-1,equal-এ0,x>y-এ1-0=1। শুধু boolean result বিয়োগ,extreme difference overflow নেই। সাধারণ consistent integer order হয়।

Universal winner নয়,required property প্রমাণ করো। Decision tree worst comparison,stable rule record order,workspace simultaneous buffer-frame গোনে। Contract-এর আলাদা প্রশ্নের উত্তর।

সময় ও মেমরির হিসাব

Table এখানকার implementation-এর। Counting range k,radix digit d/base b। Simple quick worst O(n) stack,random-এ expected log depth। Qsort-এ universal standard complexity/stability নেই। একই নামের সব version-এর গুণ ভাববে না।

প্রচলিত ভুল

Arbitrary signed key বিয়োগ

x-y overflow করতে পারে। Relational comparison-এর boolean result বিয়োগ করো।

Qsort মানেই quick sort ধরা

API comparator অনুযায়ী order দেয়,নির্দিষ্ট algorithm বা stability নয়।

Key-domain size উপেক্ষা

Linear counting-এ k নিয়ন্ত্রণ চাই। Sparse huge range comparison sort-এর চেয়ে ধীর ও বড় হতে পারে।
