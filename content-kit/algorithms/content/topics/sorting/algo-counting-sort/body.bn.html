শুরু করা যাক

Class mark ছোট জানা range-এর integer। বারবার দুই mark তুলনা না করে কোনটি কতজন পেয়েছে গুনতে পারো। Counting sort frequency থেকে সরাসরি output position ঠিক করে।

এটি comparison-এর বাইরের তথ্য নেয়:offset-এর পরে key array index হয়। Speed record count ও key range দুটোর ওপর। একশ সম্ভাব্য score-তে হাজার mark ভালো;বিলিয়ন দূরের দুই key নয়।

সিউডোকোড ও ব্যবহারের নিয়ম

count[0..198] = 0; allocate output[0..n)
for i = 0 to n - 1: count[a[i] + 99]++
for key = 1 to 198: count[key] += count[key - 1]
for i = n - 1 down to 0: output[--count[a[i] + 99]] = a[i]
copy output into a

ধাপে ধাপে বোঝো

Key থেকে count slot

Minimum L,maximum U inclusive হলে k=U-L+1। count[0..k) zero করো। Key x-এর slot x-L। Negative key থাকলেও offset slot nonnegative রাখে।

C version -99..99 নেয়,k199,slot a[i]+99। -99→0,zero→99,99→198। Index করার আগেই range validate। বাইরের মানে memory corrupt হতে পারে।

এক input scan-এ প্রতি key-র slot বাড়াও। শেষে count[s] ওই key-র record সংখ্যা। Empty input-এ সবzero। Duplicate একই slot বাড়ায়,নতুন count position নয়।

Prefix total-এ boundary বানাও

Prefix sum আগের entry-সহ running total। s1 থেকে k-1-এ count[s]+=count[s-1]। পরে count[s] ওই slot-এর key পর্যন্ত input count।

[7,3,5,3,1]-এ1:1,3:2,5:1,7:1 frequency;prefix1,3,4,5। তাই3 output index1,2 নেয়। Cumulative3 group-এর excluded upper end,first index নয়।

Zero-frequency slot-ও prefix-এ অংশ নেয়। Key4 নেই,তবু prefix3। Display-তে খালি slot লুকাতে পারো;algorithm-এ পুরো range-এর অর্থ ঠিক চাই।

ডান থেকে বাঁয়ে output ভরো

n-record output নাও। Input শেষ থেকে প্রথমে scan। Slot-এর cumulative count আগে কমিয়ে নতুন মান position করো। End boundary3 হলে last valid2,তাই pre-decrement জরুরি।

পেছন থেকে কেন? Input3A,3B হলে আগে3B group-এর last slot পায়,পরে3A ঠিক তার আগে। Tie order থাকে। Prefix boundary ও reverse traversal মিলে stability দেয়।

একই decreasing-end rule-এ forward scan tie উল্টায়। Forward চাইলে increasing start-offset design নাও। Incompatible placement রেখে direction বদলাবে না।

Caller input-এ ফল চাইলে completed output copy back। Counting-placement থেকে আলাদা phase। Output আগেই ordered;copy শুধু storage location বদলায়।

Data-নির্ভর প্রতিটি সিদ্ধান্ত দেখো

Animation-এ input-প্রতি occupied frequency,পরে prefix end,তারপর খালি output-এ ডান input থেকে এক slot ভরা দেখায়। Placement পুরো শেষেই copy back।

Default-এ input1 output0,পরের3 position2,5 position3,আগের3 position1,7 position4। Visit reverse হলেও final key ascending,tie original order।

Integer ফল বলে না কোন3 আগে। Labelled example-এ key-এর সঙ্গে ID আছে। পুরো record copy করো। শুধু key গুনে value rebuild করলে student-এর associated data হারায়।

n ও key range k তুলনা

Count initialize-prefix Θ(k);count,place,copy প্রতিটি Θ(n)। মোট Θ(n+k),stable buffered auxiliary-ও Θ(n+k)। শেষে input replace করলেও output constant space নয়।

k=O(n) হলে n-এ linear,comparison sort-কে asymptotically হারাতে পারে। k≫n log n হলে খালি range scan waste। নির্দিষ্ট domain-এ simplify-এর আগে bound-এ k বলো।

Comparison-sort lower bound ভাঙে না। সেটি arbitrary key-এর comparison দিয়ে তথ্য শেখা ধরে। এখানে finite domain-এ direct address,আরও structured problem ও শক্ত input assumption।

Offset negative সমর্থন করে,arbitrary real mark নিজে slot নয়। Bounded exact encoding বা অন্য method চাই। Decimal scale-এ rounding-range সমস্যা;চুপচাপ truncate নয়,representation বলো।

পদ্ধতিটি কেন সঠিক

Reverse placement-এ end কমিয়ে unused slot নেয়। Frequency সংখ্যক record ঠিক block পূর্ণ করে;কিছু হারায় বা duplicate নয়। Later equal পরে বসে বলে stable। Copy completed order রাখে।
