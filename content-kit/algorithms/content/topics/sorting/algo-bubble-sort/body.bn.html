শুরু করা যাক

উচ্চতা অনুযায়ী student সাজাবে ভাবো। পাশাপাশি ভুল order-এ থাকা দুজনকে বদলে পুরো row হাঁটো। একবার শেষে সবচেয়ে লম্বা ডানে। Bubble সর্ট বাকি row-তে এই local repair করে।

Pass, কম্পারিজন, invariant শেখায় bubble সর্ট ভালো। সিদ্ধান্ত দেখা সহজ, কিন্তু worst কাজ quadratic। ছোট example-এ প্রতিটি সোয়াপ বোঝাও। বড় dataset-এর speed এর মূল শক্তি নয়।

সিউডোকোড ও ব্যবহারের নিয়ম

for pass = 0 to n - 2
    swapped = false
    for j = 0 to n - 2 - pass
        if a[j] > a[j + 1]
            swap a[j] and a[j + 1]
            swapped = true
    a[n - 1 - pass] is now in place
    if not swapped: stop early

ধাপে ধাপে বোঝো

এক pass maximum ডানে ঠেলে

Ascending-এ a[j], a[j+1] তুলনা; বাঁটি বড় হলেই সোয়াপ। দুইটির বড় ডানে যায়। পরের কম্পারিজন-এ carried maximum আবার পরেরটির সঙ্গে মেলে। তাই বড় ভ্যালু এক pass-এ অনেক cell যেতে পারে।

[7,3,5,3,1]-এ 7 প্রথমে 3, পরে5,3,1 পেরিয়ে [3,5,3,1,7]। Maximum final। পরের pass-এ final7 নয়, unsorted prefix দেখো।

ছোট ভ্যালু আলাদা চলে। শেষের1 প্রথম pass-এ মাত্র এক cell বামে, কারণ আগের pair দেখা হয়ে গেছে। Reverse order-এ বহু pass লাগে কেন বোঝা যায়। Local repair-এ দুজনই final হয় না।

Unfinished prefix ছোট করো

Pass zero থেকে। j zero থেকে n-2-pass পর্যন্ত, j+1 তুলনা। শেষ right ইনডেক্স n-1-pass। শেষে বৃহত্তম remaining ভ্যালু ওইখানে final suffix-এ যায়।

সর্বোচ্চ n-1 pass। এতগুলো maximum বসলে প্রথমটিও ঠিক। Singleton-এ pass নেই, empty-তে access নেই। ছোট case-এ signed ইনডেক্স দিয়ে n-1 expression সামলানো সহজ।

Pass মানে unfinished prefix জুড়ে sweep; কম্পারিজন এক pair check; সোয়াপ শুধু ভুল order-এ ডেটা movement। আলাদা গোনো। Same সাইজ-এ প্রথম pass কম্পারিজন এক হলেও সোয়াপ অনেক আলাদা হতে পারে।

পুরো pass বদল না হলে থামো

প্রতি pass শুরুতে swapped=false; exchange-এ true। পুরো pass-এ কোনো exchange না হলে unfinished prefix-এর সব adjacent pair ordered। Suffix আগেই final, তাই পুরো অ্যারে sorted; থামতে পারো।

Flag প্রতিবার reset চাই। আগের true থাকলে পরে sorted prefix early exit দেবে না। সর্ট ঠিক, best-case সুবিধা নেই। একটি কম্পারিজন-এর পর flag দেখলে পরের reversed pair থাকতেই থেমে যেতে পারো।

Already ascending n>1-এ n-1 কম্পারিজন, zero সোয়াপ, stop। Nearly sorted-এও লাভ হতে পারে, সব ছোট disturbance linear নয়। শেষের tiny ভ্যালু বামে আসতে বহু pass লাগতে পারে।

Equal-কী রেকর্ডের order রাখো

Stable সর্ট equal কী-এর আগের রেকর্ড order রাখে। 3A,3B দুই paper-এর arrival মনে রাখো। Strict greater-than equal neighbor সোয়াপ করে না। A-কে B পার হতে একসময় সোয়াপ লাগত, যা হয় না।

Greater-than-or-equal করলে এই যুক্তি ভাঙে। Equal রেকর্ড অকারণে বদলায়, equal ইনপুট-ও early stop নাও দেয়। Plain ইন্টিজার-এ tie reversal দেখা যায় না; লেবেল বা রেকর্ড ID ধরে বোঝো।

Bubble ইনপুট-এই বদলায়, কয়েক কাউন্টার, flag, saved ভ্যালু রাখে। Strict কম্পারিজন-এ stable এবং in-place। গুণ দুটি আলাদা; অন্য কনস্ট্যান্ট-space সর্ট tie order হারাতে পারে। Sorted number দেখে নয়, labeled equal রেকর্ড অনুসরণ করে তুলনা করো।

পদ্ধতিটি কেন সঠিক

Inner pass-এ current right endpoint-এ এতক্ষণ দেখা সর্বোচ্চ মান। পরের কম্পারিজন-এ invariant থাকে। তাই শেষে unfinished prefix-এর maximum ডানে। পরের pass-এর আগে suffix-এ already placed বৃহত্তম মানগুলো।

প্রতি pass suffix এক বাড়ায় বা no inversion বলে থামে। সোয়াপ দুই existing মান বদলায়, কিছু তৈরি-মুছে না। এতে order ও original collection থাকা দুটোই প্রমাণ হয়।

সময় ও মেমরির হিসাব

Worst কম্পারিজন (n-1)+(n-2)+…+1=n(n-1)/2। Distinct reverse order-এ তত adjacent সোয়াপ। তাই Θ(n²)। Uniform random permutation মডেল-এ average-ও Θ(n²)। Early exit-এ best Θ(n), auxiliary Θ(1)।
