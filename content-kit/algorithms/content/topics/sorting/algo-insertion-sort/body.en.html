Introduction

When you arrange playing cards in your hand, you usually take the next card and slide it into the right place among the earlier cards. Insertion sort treats the array the same way. A sorted prefix grows by one key at each outer iteration.

Insertion sort is useful for small arrays and nearly ordered data. It spends work on values that really need to move, rather than scanning every unfinished pair regardless of order. Its simple movement also makes stability easy to explain.

Pseudocode and conventions

for i = 1 to n - 1
    key = a[i]; j = i - 1
    while j >= 0 and a[j] > key
        a[j + 1] = a[j]; j = j - 1
    a[j + 1] = key
    a[0..i] is sorted

Insertion Sort step by step

Save the key before shifting

The first value is already a sorted prefix of length one. At index i, save a[i] as key. Begin j at i - 1 and compare earlier values with the saved key. While a[j] is larger, copy it one cell right and decrease j. The key remains safe in its separate variable while its original cell may be overwritten.

When the scan stops, place key in a[j + 1]. Either j is -1, meaning the key is smaller than every earlier value, or a[j] is at most key. In both cases the cell immediately after j is the correct insertion position. This is a shift-based algorithm, although an adjacent-swap variant also exists.

For [7,3,5,3,1], saving key 3 at i = 1 allows 7 to move right. The result becomes [3,7,5,3,1]. Next key 5 moves 7 again and settles between 3 and 7. The unsorted suffix is not assumed to have any order until its own keys are inserted.

Read the loop guard in a safe order

The C guard is j ≥ 0 and a[j] > key, written with the short-circuit operator &&. C evaluates the left operand first and skips the right operand when the left is false. Therefore a negative j never becomes an array access. Reversing these operands can read outside the array before discovering that j is invalid.

A signed index makes j = -1 a convenient stopping state. With an unsigned index, subtracting one at zero wraps to a large value instead of becoming negative. You would need a different loop design, such as tracking the hole position above zero. Do not copy signed-index conditions into an unsigned version without redesigning them.

During shifting, the visible array can temporarily contain repeated copies of one value. That does not mean the algorithm has lost the key: it is held separately. A correct trace displays the saved key so you can account for all values. Only after reinsertion should you compare the array's multiset with the original.

Nearly sorted input avoids movement

Ascending input makes the inner condition fail immediately for every new key. There are n - 1 key checks and no shifts, giving Θ(n) time. Reverse order makes key i move across all i previous values, producing 1 + 2 + ... + n - 1 shifts and Θ(n²) time.

An inversion is a pair of positions p < q with a[p] > a[q]. Each insertion shift crosses one such out-of-order pair. The total number of shifts equals the input inversion count. With I inversions, the usual insertion implementation takes Θ(n + I) time. This explains its advantage on data with few inversions more precisely than saying the list looks almost sorted.

A nearly ascending list with one small value at the very end can still require that value to cross many positions. That costs linear extra work, but may remain far below the quadratic worst case. Describe the actual disorder or inversion count when making a performance claim.

Keep equal keys in arrival order

The inner test shifts only values strictly larger than key. If an earlier equal record exists, shifting stops before crossing it. A later 3B therefore stays after an earlier 3A when keys are equal. This proves stability for the shift-based implementation.

Replacing the strict test with greater-than-or-equal moves the new key before equal earlier records. The numerical sequence remains sorted, but record order changes. Stability matters when you first sort records by one field and then stably sort by another field. The earlier order can serve as the tie order for the later sort.

Insertion sort needs only key and the indices in addition to the input array. It is in-place with constant workspace. Its worst-case quadratic time makes it unsuitable for very large random arrays, but many practical sorting designs use it on short subarrays where its small overhead is useful.

Why the method is correct

Before outer iteration i, a[0..i) is sorted and contains the original first i values. Save the next key. During the inner loop, values shifted to its right are all greater than key and remain in sorted order. When no larger predecessor remains, inserting key at j + 1 creates a sorted prefix of length i + 1.

The outer index grows to n. The inner index decreases until either an ordered predecessor appears or the left boundary is passed. Both loops therefore terminate. Every shift is paired with eventual reinsertion of the saved key, so each completed outer iteration preserves all input records.

Time and space reasoning

Best-case time is Θ(n); reverse-order worst-case time is Θ(n²). For uniformly random distinct permutations, the expected inversion count is n(n - 1)/4, giving quadratic average time. General time is Θ(n + I) for I inversions. Auxiliary storage is Θ(1), and strict shifting preserves stability. These conclusions apply to this insertion routine, not to every algorithm that happens to grow a prefix.

Common mistakes

Losing key during the first shift

Save a[i] before moving predecessors. Otherwise the original key can be overwritten by a larger value.

Reading a[j] before checking j

Put the boundary test first in the && expression so short-circuit evaluation protects the array access.

Inserting at j rather than j + 1

The stopped j points to an acceptable predecessor, or -1. The open cell is the position immediately after it.

C17 details

C17 guarantees left-to-right short-circuit evaluation for &&. Testing j >= 0 first prevents the insertion loop from evaluating a[j] after j becomes negative.
