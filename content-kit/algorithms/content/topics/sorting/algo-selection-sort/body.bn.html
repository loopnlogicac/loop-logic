শুরু করা যাক

Roll অনুযায়ী খাতা সাজাতে পুরো pile-এর সবচেয়ে ছোটটি আগে রাখো। বাকি থেকে সবচেয়ে ছোটটি দ্বিতীয়। Selection sort ঠিক এভাবেই বারবার বেছে নেয়।

এতে comparison খরচ করে swap বাঁচে। পুরো unfinished suffix scan করে সর্বোচ্চ এক exchange। Bubble sort-এর এক pass-এর অনেক neighbor exchange-এর সঙ্গে তুলনা করো।

সিউডোকোড ও ব্যবহারের নিয়ম

for i = 0 to n - 2
    min = i
    for j = i + 1 to n - 1
        if a[j] < a[min]: min = j
    if min != i: swap a[i], a[min]
    a[i] is final

ধাপে ধাপে বোঝো

Minimum-এর position মনে রাখো

Outer position i-তে min=i। এটি candidate index, smallest value-এর copy নয়। j=i+1 থেকে n-1 scan। a[j] ছোট হলে j মনে রাখো। Data নাড়ানোর আগে scan শেষ করো।

[7,3,5,3,1]-এ candidate 7 থেকে প্রথম3,শেষে1। এক swap-এ position0,4 বদলে [1,3,5,3,7]। Strict test-এ বাদ যাওয়া value scan-এর সময় সরেনি। Position বাছা ও record swap আলাদা।

Index রাখলে পরে a[i]-এর সঙ্গে exchange করা যায়। শুধু minimum value রাখলে displaced value বাঁচাতে original position-ও খুঁজতে হতো। একটি overwrite করে হারানো নয়, দুটো বিনিময় করো।

Final sorted prefix বাড়াও

Pass i-এর আগে নিচের position-এ sorted ছোটতম i value। Suffix i থেকে। তার minimum final prefix-এর পরের মান। a[i]-তে এনে prefix boundary বাড়াও।

Min=i হলে ইতিমধ্যে ঠিক, swap লাগে না। কিন্তু scan শেষ চাই; far end-এ ছোট মান থাকতে পারে। তাই ascending-এ ordinary selection comparison linear নয়।

n-1 pass-এর পরে শুধু শেষ value; সব ছোটটি আগে, final scan নেই। Empty-singleton-এ pass নেই। Duplicate numerical order ভাঙে না, কোন record বাছবে বদলাতে পারে।

Comparison ও swap আলাদা গোনো

Pass zero-তে n-1,পরে n-2,…,শেষে1 comparison। Initial order নির্বিশেষে n(n-1)/2। Minimum কোথায় তা scan length বদলায় না।

Self-swap বাদে সর্বোচ্চ n-1 real swap। Ascending-এ zero হলেও comparison সব। Reverse-এও সবসময় n-1 নয়; আগের exchange বড় মানটিকেও শেষে বসাতে পারে। Upper bound বলো, সব unsorted input পায় বলবে না।

Key comparison-এর চেয়ে বড় record নাড়ানো expensive হলে কাজে লাগতে পারে। কিন্তু library choice-এ cache,comparator overhead-সহ অনেক খরচ। অল্প swap একাই বড় array-র ভালো general sort করে না।

Distant swap tie উল্টাতে পারে

Equal record 2A,2B ধরো। [2A,2B,1]-এ শেষের1 ও 2A swap হলে [1,2B,2A]। Strict less-than হলেও tie cross করেছে। সাধারণ swapping selection unstable।

সমান pair সরাসরি swap নয়, record-এর ওপর লাফ দেওয়ায় stability ভাঙে। অন্য sort-এর proof-এও শুধু equal comparison দেখে হবে না; movement-এ order কী হয় দেখো।

Stable variant minimum সরিয়ে মাঝের record ডানে shift করতে পারে। Tie থাকে, movement বাড়ে। আলাদা implementation, আলাদা movement cost। পাঠ ও animation standard single-swap, তাই দেখানো instability প্রযোজ্য।

পদ্ধতিটি কেন সঠিক

Scan-এর ভেতরে min suffix-এর i থেকে j-1 পর্যন্ত একটি smallest value চেনে। min=i-তে শুরুতেই সত্য। a[j] ছোট হলে নতুন candidate,নইলে আগেরটি ঠিক। শেষে পুরো suffix-এর minimum।

Outer invariant: i-এর নিচের prefix sorted,ছোটতম i input value আছে। Suffix minimum বসিয়ে value না হারিয়ে prefix বাড়ে। প্রতি pass i বাড়ায়,শেষে এক value বাকি। Final হলো input-এর sorted permutation।

সময় ও মেমরির হিসাব

সব order-এ Θ(n²) comparison। সর্বোচ্চ n-1 nontrivial swap-এ O(n) exchange,auxiliary Θ(1)। Scan dominate করায় কম swap time class কমায় না। Ordinary selection in-place,unstable। Stable shift variant আলাদা বিশ্লেষণ করো।

প্রচলিত ভুল

ছোট candidate পেলেই swap

প্রতি ছোট candidate-এ swap করলে অন্য exchange-based পদ্ধতি,অনেক movement হতে পারে। আগে suffix minimum খোঁজা শেষ করো।

আগের pass-এর min রাখা

প্রতি scan-এর আগে min=i reset। নইলে finished prefix-এ point করতে পারে।

Strict comparison দেখেই stable ধরা

[2A,2B,1]-এ equal-কে smaller না বলেও distant swap tie উল্টায়।

C17 signed index suffix boundary ধরে। n<2-এ access-এর আগেই outer condition false। Candidate প্রতি pass নতুন হয়।
