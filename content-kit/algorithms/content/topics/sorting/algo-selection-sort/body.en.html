Introduction

Suppose you arrange answer scripts by roll number. Find the smallest roll in the whole pile and put it first. Then find the smallest roll among the remaining scripts and put it second. Selection sort follows exactly this repeated selection.

Selection sort spends comparisons to save swaps. It scans the whole unfinished suffix before making at most one exchange. This gives a useful contrast with bubble sort, where many neighbouring exchanges may occur during a single pass.

Pseudocode and conventions

for i = 0 to n - 2
    min = i
    for j = i + 1 to n - 1
        if a[j] < a[min]: min = j
    if min != i: swap a[i], a[min]
    a[i] is final

Selection Sort step by step

Remember the minimum position

At outer position i, begin with min = i. This is a candidate index, not a copy of the smallest value. Scan j from i + 1 through n - 1. Whenever a[j] is smaller than a[min], remember j as the new min. Wait until the scan is complete before moving data.

For [7,3,5,3,1], the candidate starts at 7, changes to the first 3, and finally changes to 1. A single swap exchanges positions 0 and 4, giving [1,3,5,3,7]. Values skipped by the strict comparison are not moved during the scan. This distinction separates selecting a position from actually swapping records.

Keeping an index lets you exchange the chosen minimum with a[i] afterward. If you stored only the minimum value, you would also need to locate its original position to preserve the displaced value. Data movement should exchange both values rather than overwrite one and lose the other.

Grow a final sorted prefix

Before pass i, positions below i already hold the smallest i values in sorted order. The unfinished suffix starts at i. Its minimum is exactly the next value that belongs in the final prefix. Swap it into a[i], then advance the prefix boundary.

If min equals i, the next value is already in place and no swap is necessary. The comparison scan still needs to finish: a smaller value could be waiting at the far end. This is why ascending input does not make ordinary selection sort's comparison count linear.

After n - 1 passes, only the last value remains. Every smaller value is already before it, so a final scan is unnecessary. An empty array and a singleton require no pass. Duplicates are allowed; they affect which record is selected, but not the numerical ascending-order result.

Count comparisons separately from swaps

Pass zero makes n - 1 key comparisons, pass one makes n - 2, and the last useful pass makes one. The total is n(n - 1)/2, regardless of the initial key order. The locations of the minima do not change the length of each scan.

There are at most n - 1 real swaps when self-swaps are skipped. Ascending data may need zero swaps while still making all comparisons. Reverse data does not necessarily need n - 1 swaps, because an early exchange can also place a large value at its final end position. State an upper bound rather than claiming every unsorted array attains it.

This pattern can be attractive when moving a large record is expensive relative to comparing its key. However, modern library choices depend on many costs, including cache behaviour and comparator overhead. The low swap count alone does not make selection sort a good general-purpose method for large arrays.

A distant swap can reverse a tie

Label equal records as 2A and 2B. For [2A,2B,1], the first selected minimum is 1 at the last position. Swapping it with 2A produces [1,2B,2A]. The equal-key records have crossed, even though the comparison used strict less-than. Ordinary swapping selection sort is therefore unstable.

The stability failure comes from jumping across a record, not from directly swapping an equal pair. This is a useful warning when proving stability for other algorithms. Checking only whether equal values compare as equal is insufficient. You must follow how record movement can change their order.

A stable selection variant can remove the minimum and shift the intervening records right instead of swapping. That preserves tie order but increases movement. It is a different implementation with a different movement profile. The lesson and animation use the standard single-swap form, so their instability example applies directly.

Why the method is correct

Inside the scan, min identifies a smallest value among suffix positions i through j - 1. Initialising min to i establishes the claim before the first comparison. Comparing a[j] either finds a smaller candidate or leaves the existing one valid. At the scan's end, min identifies a minimum of the entire suffix.

The outer invariant says the prefix below i is sorted and contains the smallest i input values. Installing the suffix minimum extends that prefix without losing any value. Each outer pass increases i, so the unfinished suffix shrinks until only one value remains. The final array is a sorted permutation of the input.

Time and space reasoning

All input orders make Θ(n²) comparisons. At most n - 1 nontrivial swaps give O(n) exchanges, while auxiliary storage is Θ(1). Few swaps do not reduce the total asymptotic time because comparison scans still dominate. Ordinary selection sort is in-place and unstable. A stable shift-based variant should be analysed separately rather than assigned the same exchange count.

Common mistakes

Swapping every time a smaller candidate appears

That becomes a different exchange-based method and may make many swaps. Finish finding the suffix minimum first.

Keeping min from an earlier pass

Reset min = i before each suffix scan. Otherwise it can point inside the completed prefix.

Inferring stability from strict comparison

The [2A,2B,1] trace reverses the tie through a distant exchange without ever comparing equal values as smaller.

C17 details

Selection uses a C17 signed index for its suffix boundary. For n below two, its outer condition fails before any access. The minimum candidate is reinitialised inside every pass.

Summary

Select each suffix minimum with few exchanges while keeping comparisons and stability claims separate.
