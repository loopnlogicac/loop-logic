Place queens without attacks

A queen attacks horizontally, vertically and diagonally. The N-Queens problem asks you to place n queens on an n-by-n board so none attacks another. It is a useful constraint problem because a new piece can invalidate a promising partial arrangement.

You can remove one source of conflict by design: place exactly one queen per row. Now a state only needs to remember the chosen column of each earlier row. Row r becomes the recursive depth, and col[r] stores that row's choice.

The aim here is to count all solutions and retain the first one for display. Reflections and rotations count as different boards. For n=4, the answer is two. For n=2 or n=3, there is no solution. An unsuccessful search is still a meaningful result.

Think of every row as a decision that must agree with all earlier rows. The search tries columns in ascending order, rejects attacks immediately, and returns to change an earlier queen when the next row has no legal choice.

Columns describe the board

The function safe(row, c) compares a candidate column c with every queen in a previous row. Equal columns mean a vertical attack. A diagonal attack occurs when the absolute column gap equals the row gap.

The row gap is row-prev, which is positive because prev is earlier. We compute the absolute column difference explicitly in the main solver. The independent board validator uses abs from stdlib.h. Neither method needs floating-point slopes.

The call search(row) assumes earlier queens are safe. At row==n, every row is filled and the counter increases. A separate first array receives a copy only at the first solution. Search then returns normally and continues counting other boards.

search(row):
    if row == n: count++; save first board; return
    for c = 0 to n - 1:
        if safe(row, c):
            col[row] = c
            search(row + 1)
            col[row] = -1

Check both diagonal directions

Suppose row zero contains column one. On row one, column one conflicts vertically. Columns zero and two conflict diagonally because their column gap is one, matching the row gap. Column three remains safe.

After choosing row one column three, row two may take column zero. Row three can then take column two. The complete vector is [1,3,0,2]. To count more boards, remove row three's queen and continue the surrounding loops.

The lab shows each candidate before deciding whether to place it. A rejected square means an earlier queen attacks it. Placement and removal are separate events. When counting finishes, the working board is empty again, and the saved first solution is restored for viewing.

Safe prefixes lead to safe boards

The invariant says that rows below the current row are undecided and every pair of earlier queens is nonattacking. It holds for the empty prefix. A safe candidate has no attack with any earlier queen, so appending it preserves the invariant.

When row reaches n, one queen occupies every row. Earlier checks establish different columns and diagonals for every pair, so the board is valid. Conversely, consider any valid board. Its chosen column at each row passes safe because it conflicts with no earlier queen. The loops try that column, so the complete board is eventually counted.

Each board has one unique row-to-column vector. Two recursive paths cannot yield the same vector because their first differing choice changes a row's column. Thus the count has neither omissions nor duplicates under the stated symmetry convention.

Count candidates and safety work

Column conflicts prevent reusing an earlier column, so the number of viable partial column vectors is bounded by the permutation tree. There are at most n! complete column arrangements before diagonal rejection. The safety check scans at most n earlier rows.

For this simple code, a conservative bound including failed column tests is O(n^2*n!) time. It uses at most n column trials per visited prefix and an O(n) safety test per trial. Common O(n!) descriptions suppress these polynomial factors or assume faster occupancy checks; state which implementation you analyse.

You can keep occupied-column and diagonal arrays for constant-time safety. The diagonals have identifiers row-c+n-1 and row+c, each in zero through 2n-2. Mark before recursion and clear on return. The working state, saved board and active stack all use O(n) space, excluding printed output.

No board can be the correct answer

A one-by-one board has one solution. Sizes two and three have none. The program accepts one through eight; size eight has ninety-two ordinary solutions, small enough for the demonstration counter.

An empty board is sometimes defined to have one empty arrangement, but this interface deliberately starts at one. If you extend it to zero, update both the input bounds and the meaning of the displayed witness.

Counting fundamental solutions requires identifying boards equivalent under reflection and rotation. Dividing the ordinary count by eight is unsafe because some boards have fewer than eight different symmetric images.

A column test alone misses attacks

Using only col[prev]!=c admits diagonal attacks. Add the coordinate-gap test for both diagonal directions. Checking only one signed difference catches one diagonal direction and misses the other.

Do not return success from search as soon as the first board appears when the task asks for all solutions. Save a copy and let the loops continue. The temporary col array will change again, so retaining only a pointer to it does not preserve that board.

Another bug prints col after the whole search. Cleanup has removed the queens by then. Print the saved first vector only when saved is true; otherwise no valid witness exists.

Separate deciding, counting and drawing

Use a small safe function so the geometric rule is visible. Test a complete vector with the independent validator before blaming the recursion for an unexpected drawing.

Keep symmetry policy beside the problem statement. If you optimise with occupancy flags, check every undo operation carefully. Comparing the fast and slow safety predicates on small boards is a useful development check.

Fixed bounds keep the board safe

The C17 examples use eight-slot arrays and reject larger board sizes before recursion. Small coordinate differences fit int, including the validator's abs argument. A larger solver needs wider counters and an explicit limit on recursion and runtime; factorial growth arrives long before ordinary display sizes become a memory issue.

One row, one reversible choice

N-Queens turns geometry into column and diagonal constraints. Safe prefixes grow one row at a time, and undo lets the search inspect every alternative. The saved witness and the total count answer different questions about the same search.
