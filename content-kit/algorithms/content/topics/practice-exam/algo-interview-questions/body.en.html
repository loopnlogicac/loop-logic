Practise the reasoning aloud

These fifty questions are grouped by technique so you can connect an implementation detail to a wider idea. Try answering aloud before reading each response. Name the precondition and guarantee first, then give a small example. A short answer should still explain why a tempting alternative fails.

Foundations

1. What distinguishes correctness from efficiency?

Correctness means the output meets the specification for every valid input. Efficiency measures the resources used. A fast program that omits a required case is still incorrect.

2. How do O and Theta differ?

O is an asymptotic upper bound. Theta supplies matching upper and lower bounds. A linear function is O(n squared) too, but its tight growth is Theta(n).

3. Does a nested loop always mean quadratic time?

No. Sum the actual iteration counts. An inner loop that doubles a counter can contribute logarithmic work, while dependent bounds may require an arithmetic-series sum.

4. How do you prove a loop correct?

State an invariant, show it holds initially, show an iteration preserves it, and combine it with the stopping condition. Also show termination, usually through a decreasing finite measure.

5. What belongs in auxiliary space?

Temporary arrays, data structures and the active call stack. Input storage and retained output should be stated separately so the accounting convention is clear.

Searching

6. What must hold before ordinary binary search?

The search range must be ordered according to the comparison rule. The interval convention must be consistent, and each update must strictly shrink the candidate range.

7. How do you avoid midpoint addition overflow?

Use low+(high-low)/2 when low and high are nonnegative valid bounds and their difference fits the index type. Do not assume low+high is safe merely because each bound is safe.

8. How do lower bound and exact search differ?

Lower bound finds the first position whose value is at least the target, possibly the end. Exact search additionally checks that this position exists and equals the target.

Sorting

9. What does stable sorting preserve?

The relative input order of records with equal keys. This matters when previous ordering carries information, such as sorting by a secondary key before a primary key.

10. When can insertion sort be useful?

Small or nearly sorted inputs can need little movement. Its worst case is quadratic, but its simple local operations and adaptive behaviour can make it practical for short runs.

11. Why is merge sort Theta(n log n)?

Each level merges a total of n items, and balanced halving creates logarithmically many levels. A standard array implementation also needs a linear merge buffer.

12. What gives quicksort a quadratic worst case?

Repeatedly choosing an extreme pivot creates subproblems of sizes zero and n-1. Summing the linear partition work over that chain gives quadratic time.

13. What does heap sort guarantee?

A comparison-based O(n log n) worst-case sort with constant array auxiliary storage in a typical iterative implementation. It usually does not preserve equal-key record order.

14. Why is counting sort not always linear in n?

Its cost includes the key-range size k: O(n+k) time and range storage. A huge sparse key range can dominate the number of records.

Divide and conquer

15. What are the three divide-and-conquer jobs?

Split into smaller subproblems, solve them recursively, and combine their results. The combine step and subproblem sizes determine the recurrence.

16. Why does fast exponentiation use logarithmic multiplications?

Each step halves the exponent and squares a power. Only odd exponents need an extra multiply, so the number of stages follows the exponent's bit length.

17. What must Kadane's algorithm change for all-negative input?

A nonempty maximum-subarray task must allow the best negative element as its answer. Initialising the best to zero would incorrectly permit an empty interval.

Greedy

18. What is a greedy exchange argument?

Show that an optimal solution can be modified to include the greedy choice without worsening its objective. Then apply the argument to the remaining subproblem.

19. Why does ratio-first fail for 0/1 knapsack?

Whole items cannot be divided to repair a locally attractive choice. For capacity 50 and items (10,60),(20,100),(30,120), ratio-first takes value 160 while the last two give 220.

20. Why choose the earliest-finishing activity?

An optimal schedule's first activity can be replaced by the earliest-finishing compatible one without reducing room for later activities. Repeating this exchange proves maximum count.

21. What makes a Huffman code prefix-free?

Only leaves carry symbols, so no symbol code ends at an internal node on another symbol's route. Traversing bits from the root identifies each leaf unambiguously.

Dynamic programming

22. What makes a DP state useful?

It contains enough information to determine future choices without the full history. A recurrence must express its answer through smaller or earlier states.

23. How do memoisation and tabulation differ?

Memoisation computes requested states recursively and caches them. Tabulation fills a chosen dependency order explicitly. Both reuse repeated states when they represent the same recurrence.

24. Why scan capacity downward for 0/1 knapsack?

Each update must use the previous item's states. A downward scan prevents the current item from being reused within the same pass.

25. Why can coin-change loop order change the answer?

Coin-first updates can count unordered combinations. Amount-first updates can count ordered sequences. The state meaning and loop order must match the requested counting policy.

26. How do you reconstruct an LCS?

Start at the final prefix-pair state. On equal characters record the character and move diagonally; otherwise follow a neighbour preserving the optimal length. Reverse the recorded sequence.

27. Why are LIS tails not necessarily a witness?

Tail entries summarise minimum possible ending values for different lengths and may come from incompatible histories. Store predecessor and original-index information to recover an actual subsequence.

Graphs

28. When does BFS give shortest distances?

In an unweighted graph, or when all edges have the same positive cost. FIFO exploration visits layers in nondecreasing edge count.

29. Why mark before enqueuing in BFS?

Otherwise several parents may enqueue the same vertex before it is processed. Early marking gives one discovery, one predecessor and a bounded queue entry per vertex.

30. How does directed DFS detect a cycle?

An edge to a grey vertex returns to the active recursion path and closes a directed cycle. An edge to a completed black vertex alone does not establish one.

31. When does a topological order exist?

Exactly for directed acyclic graphs. Kahn's method emits all vertices only when repeated indegree-zero removal can finish the graph.

32. What does a strongly connected component mean?

Every pair of vertices in the component can reach each other by directed paths. Contracting maximal such components produces a DAG.

33. What is relaxation in shortest paths?

Try replacing dist[v] with dist[u]+weight(u,v) when that candidate is smaller. A successful relaxation also records predecessor information for a route witness.

34. Why does Bellman-Ford use V-1 passes?

A simple shortest path has at most V-1 edges when no relevant negative cycle exists. Each full pass can propagate paths with one more edge.

35. Why is k the outer Floyd-Warshall loop?

The state allows intermediate vertices only from the first k choices. Both subpaths through k must use that same allowed set, so the recurrence follows increasing k.

36. How do Prim and Dijkstra choose keys differently?

Dijkstra minimises total source-path distance. Prim minimises the cost of one edge joining the current tree to a new vertex. Their heap mechanics can look similar while their objectives differ.

37. Why does Kruskal use union-find?

It tests whether an edge's endpoints already belong to one accepted component. If they do, adding that edge creates a cycle; otherwise merging components is safe for the forest construction.

38. What characterises a bipartite graph?

Its vertices can be split into two sets with no edge inside either set. Equivalently, an undirected graph is bipartite exactly when it has no odd cycle.

Backtracking

39. What must an undo operation restore?

Every shared state change belonging to the explored choice. The next sibling must receive the parent's state rather than leftover data from a failed child.

40. When is sum-exceeds-target pruning valid?

When every remaining contribution is nonnegative, since the partial sum cannot decrease. Negative remaining items require a different bound or no such prune.

41. Why use a depth-local duplicate set for permutations?

Equal values chosen at the same position lead to the same remaining multiset. A local set skips redundant branches while still allowing repeated values in later positions.

42. Why does a failed greedy colouring not prove impossibility?

Greedy commits to earlier colours and does not revisit them. Another vertex order or a different earlier assignment may use fewer colours.

Strings

43. What does the KMP prefix function store?

At index i, the longest proper prefix of pattern[0..i] that is also a suffix. It stores a border length, not a text position or a frequency.

44. Why does KMP retain pi[m-1] after a match?

The completed pattern's suffix may already be the prefix of an overlapping next occurrence. Keeping its longest proper border preserves that possibility.

45. Why verify Rabin-Karp hash hits?

Different strings may share a hash. Comparing characters after equality rejects spurious hits and makes the reported matches exact.

Number theory

46. Why begin sieve marking at p squared?

Every smaller composite multiple of p has a factor below p and has already been handled. Beginning at p would incorrectly mark the prime itself.

47. When does a modular inverse exist?

For modulus m>1, a has an inverse exactly when gcd(a,m)=1. Bézout supplies a coefficient x whose residue is that inverse.

Complexity

48. What is the distinction between NP-hard and NP-complete?

NP-hardness supplies reductions from every NP problem. NP-complete additionally requires a decision problem with polynomially verifiable yes-certificates.

49. Which direction proves a new problem B hard?

Reduce a known NP-complete source A to B in polynomial time, preserving yes and no instances. A fast solver for B would then solve A.

Strategy

50. How should you test an optimised solution?

Compare with an independently simple reference on tiny cases, include boundary and duplicate cases, and shrink disagreements. Then keep a proof of the step that discards work.
