Put prerequisites before their tasks

You cannot sit an advanced lab before completing its required introduction. A set of such prerequisites forms a directed graph. An edge u to v means u must come before v. A topological sort lists all tasks while respecting every directed edge.

The graph must be acyclic: it must contain no directed cycle. If A requires B and B requires A, neither can be first. A directed acyclic graph is often called a DAG. Topological ordering is useful for course plans, build dependencies and calculations where earlier results feed later ones.

A valid order need not be unique. Two unrelated tasks may appear in either order. The goal is to satisfy dependencies, not to sort names or weights. Both Kahn's queue method and reverse DFS finish order can produce a valid answer, sometimes with different tie choices.

Count what still enters each vertex

The indegree of a vertex is its number of incoming arcs. Kahn's algorithm places all zero-indegree vertices in a queue. They have no unmet prerequisites. Removing one from the graph conceptually satisfies each outgoing dependency and reduces its neighbours' indegrees.

The C graph keeps outgoing adjacency lists and a separate edge list. One scan of the edge list counts the initial indegrees. The queue begins with zero-indegree vertices in ascending letter order. Newly ready vertices join at the back, so this implementation gives FIFO tie handling rather than a globally smallest-letter order.

Topological scenario 0 orients the shared eight edges as AB, AC, BC, BD, CE, DE, DF and EF, with each pair read left to right. Scenario 1 is the directed cycle A to B to C to D to E to F to A. Scenario 2 isolates F, and scenario 3 has six independent vertices. Edge weights have no role in dependency ordering.

Remove a ready task, then its outgoing obligations

Kahn's algorithm appends the dequeued u to order. For every outgoing u to v, it decrements indegree[v] once. If the value becomes zero, v has become ready and is enqueued. Do not enqueue it while its indegree is still positive; that would place it before an unmet prerequisite.

An actual edge is not deleted from the stored graph. The indegree array represents how many incoming edges remain after conceptual removals. This avoids changing adjacency lists during traversal. The order array records what was removed, and count records how many vertices the algorithm successfully placed.

When the queue empties, compare count with V. If they are equal, the order includes every task. If fewer were removed, the remaining graph contains a directed cycle. A partial prefix can still be valid, but it is not a topological order of the complete cyclic graph.

The fourth example implements DFS-based sorting on four tasks. White vertices are unvisited, grey vertices are active, and black vertices have finished. An edge to a grey vertex proves a directed cycle. A vertex is appended only when its recursive call finishes, and the collected finish order is then reversed.

For an acyclic edge u to v, either DFS enters v from u and finishes v first, or v has already finished. A grey v would create a cycle and is rejected. Thus finish[u] exceeds finish[v] for every DAG edge. Reversing finish order places u before v, proving the DFS method correct.

Never print reverse finish order as a valid result after detecting a back edge. The dependency contract has failed. A program can report the existence of a cycle, or extend the DFS to recover one, but no ordering can satisfy all cycle edges simultaneously.

Ready means safe to place next

Kahn's invariant says indegree[v] equals the number of incoming arcs from vertices not yet removed. Initially the count comes directly from the edge list. Removing u subtracts exactly its outgoing arcs, so the invariant stays true. Each vertex is enqueued when this remaining count first reaches zero.

When u is appended, it has no incoming edge from a remaining vertex. Therefore every predecessor is already earlier in order. Induction over removals proves that the produced prefix respects every dependency whose destination has been placed. If all vertices are placed, the whole sequence is a valid topological order.

Why does failure imply a cycle? If a nonempty remaining directed graph has no zero-indegree vertex, every remaining vertex has a remaining predecessor. Follow predecessor choices backward. Because the graph is finite, some vertex repeats, yielding a directed cycle. Conversely, vertices on a directed cycle can never lose their final incoming cycle edge through this removal rule.

Account for arcs once

Kahn's indegree construction scans E arcs. Each vertex enters and leaves the queue once, and each outgoing arc is processed when its source leaves. Total time is O(V+E), with O(V) auxiliary space for indegree, queue and order. Adjacency-list graph storage is O(V+E) separately.

DFS-based sorting also costs O(V+E) with lists. Its colour array, finish list and recursive stack together need O(V) additional space. The small DFS example scans a four-by-four matrix, so that particular representation generalises to O(V²) time. The graph algorithm's list bound does not automatically apply to a matrix implementation.

If you need the smallest available task at every step, replace Kahn's FIFO queue with a min-priority queue. Queue operations then add O(V log V) work. Sorting the final output alphabetically would be wrong because that can destroy dependencies that were already respected.

Disconnected tasks and blocked tails

An isolated vertex has indegree zero and belongs in the initial queue. Scenario 2 therefore starts with A and F ready. F can appear before later tasks reached from A, despite its letter being last. Topological sorting must include vertices that no dependency mentions.

A cycle can also block vertices downstream from it. Those blocked vertices need not lie on the cycle themselves. Count less than V identifies that some cycle exists; it does not identify every remaining vertex as a cycle member. Recover a cycle with DFS or find strongly connected components when that distinction matters.

Do not change the meaning of indegree

Counting outgoing instead of incoming arcs

Outgoing degree counts dependants, not unmet prerequisites. Increment the destination for each u to v arc when building indegree.

Reducing an indegree twice

Process each outgoing arc exactly once when its source is removed. Decrementing during enqueue and again during dequeue can release tasks too early.

Assuming weights decide prerequisites

A low-weight edge still enforces its direction. Topological sorting is about ordering constraints, so weights do not choose the next vertex.

Check an order by positions

Build rank[v] from the proposed order. For every directed edge u to v, verify rank[u] is less than rank[v]. Also verify that every vertex occurs exactly once. This provides a direct way to review a hand-written answer even when your tie order differs.

Bounded queues in C17

The C17 implementation reserves one queue slot per vertex. Each indegree reaches zero at most once, so no vertex needs a second slot. The start argument is accepted for consistency with nearby graph examples but does not affect Kahn's all-vertex ordering.

Dependencies choose what is ready

A topological order exists exactly when the directed graph is acyclic. Kahn exposes readiness through indegrees; DFS exposes it through finishing times. Continue with Strongly Connected Components to group tasks that can reach one another even when cycles exist.
