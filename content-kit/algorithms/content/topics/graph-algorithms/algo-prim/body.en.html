Connect every room with less cable

Suppose six campus rooms need one connected cable network. You care about the sum of installed cable lengths, rather than travel distance from a particular room. A minimum spanning tree, or MST, connects every vertex with the smallest possible total edge weight.

A spanning tree uses every vertex, remains connected, and has no cycle. For V vertices, it contains V-1 edges. Adding a cycle wastes an edge for connectivity because one cycle edge can be removed while keeping the same vertices connected. With nonnegative installation costs, the tree picture directly matches the cable problem.

Prim's algorithm grows one connected tree from a selected start. At every step, it chooses the lightest edge that joins the current tree to a vertex outside it. The start changes the growth sequence, but any completed MST has the same minimum total weight. Different MST edge sets can still tie.

A key is one connection edge

Prim keeps used[v] to mark vertices already in the tree. For a vertex outside the tree, key[v] is the lightest edge found from the tree to v. It is not the length of a route from start. The source has key zero and no parent edge so that it can seed the tree.

A binary min-heap stores candidate triples of value, vertex and parent. The smallest key is removed first, with vertex index breaking equal-key ties. Whenever a lighter connection to v is found, push a new entry. Older entries remain until popped, when a used test or mismatched key identifies them as stale.

The C heap has space for 32 entries, enough for these fixed graphs. A general lazy heap needs storage that grows with successful key improvements. Unlike an indexed heap, it does not keep exactly one current record per vertex. The animation displays a sorted queue panel with the same minimum and tie behaviour.

Grow across the current boundary

The shared Prim input has undirected edges AB=4, AC=2, BC=1, BD=5, CE=8, DE=2, DF=6 and EF=3. From A, the boundary offers B at 4 and C at 2. Accept C, then replace B's key with 1 through C. This demonstrates why a key is an edge weight.

After B joins, D receives key 5. D then offers E at 2 and F at 6. E's old key 8 is replaced by 2. Accept E and improve F to 3 through E. The final selected edges are AC, CB, BD, DE and EF.

Every accepted edge has one endpoint already inside and one outside. Therefore it adds exactly one new vertex and cannot close a cycle. The growing object remains connected throughout. When all six vertices have joined, five accepted parent edges form a spanning tree.

Exchange a heavier crossing edge

A cut divides vertices into those already in Prim's tree and those outside. Assume some MST contains every edge accepted so far. Let e be the lightest edge crossing this cut. If that MST already contains e, the assumption remains true after accepting it.

Otherwise, add e to the MST. A tree plus one edge creates exactly one cycle. That cycle must cross the cut again, so it contains another crossing edge f. Earlier accepted edges lie entirely inside the current tree, so f is not one of those protected edges.

Because e is lightest across the cut, weight(e) is no greater than weight(f). Remove f from the cycle. The result is still a spanning tree, contains all earlier accepted edges and e, and costs no more than the original MST. It is therefore also minimum. This exchange proves the next greedy choice safe.

Initially any MST contains the empty selected edge set. Repeating the safe-choice argument until V-1 edges have been accepted gives a complete MST. The proof requires an undirected connected graph for one spanning tree; disconnected inputs need a forest or a clear failure report.

Heap entries follow key improvements

With adjacency lists, each accepted vertex scans its neighbours once. Across the graph, that is O(E) arc inspections. Each strict key improvement pushes one candidate, so at most O(E+1) lazy heap entries are created. Push and pop cost O(log(E+1)), giving O(V+E log(E+1)) time including initialisation.

A common simple-graph expression is O((V+E) log V). The lazy implementation may hold O(E) entries, while an indexed decrease-key heap can keep O(V). Key and used arrays require O(V) space. Include graph input storage separately when comparing implementations.

A dense implementation can scan all unused vertices to find the minimum key at each step. That version takes O(V²) time and avoids a heap. For a nearly complete graph, its simpler access pattern can be useful. A list-and-heap algorithm is not automatically faster merely because its heap operations are logarithmic.

Prim and Dijkstra store different meanings

Dijkstra's relaxation tests dist[u]+w against dist[v]. Prim compares w alone against key[v]. Dijkstra builds minimum source-route costs under nonnegative weights. Prim builds a minimum total-weight connecting tree in an undirected graph. Replacing one formula with the other changes the problem being solved.

Prim's cut proof also permits negative edge weights. The selected tree remains finite because it contains only V-1 edges and cannot repeat a cycle. This differs from shortest-walk problems, where repeating a negative cycle destroys a finite minimum. The provided Prim examples use positive weights for easier arithmetic.

Equal weights and missing connections

If two boundary edges have equal weight, either can be safe. The code keeps the earlier parent on an equal key and compares heap entries by vertex index. These choices make the demonstration reproducible; they do not prove that the MST is unique.

A vertex with key INF has no known edge from the current component. Such a key is never pushed. When the heap empties while unused vertices remain, there is no crossing edge to them. That is the precise reason the program reports disconnected input.

Keep route costs out of the key

Adding the parent's key

Prim's next connection costs only the candidate edge weight. Adding a source-prefix cost turns the key into something different and breaks the cut-choice implementation.

Accepting an old heap record

A previously improved key can leave a larger stale record in the heap. Reject entries for used vertices or values different from the current key before adding any weight.

Calling a partial tree spanning

A tree with fewer than V reached vertices does not span the input. Report the reached component or restart to build a forest.

Check tree shape and total separately

After tracing Prim, count V-1 accepted edges for a connected graph. Check that every vertex is reached and that no accepted edge closes a cycle. Add the weights independently; a correct sum alone does not establish a valid spanning tree.

Heap triples in C17

The Prim implementation uses C17 structure values for heap entries and bounded integer weights. Its maximum total magnitude is far below int limits. Larger applications need capacity checks and a total type wide enough for the sum of V-1 edge weights.
