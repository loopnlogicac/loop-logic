Allow negative edges without guessing a final vertex

A route can include a rebate. Its total cost may fall after another edge is added. Dijkstra's finalisation argument no longer works, because a currently expensive prefix may lead to a cheaper destination. Bellman-Ford handles directed negative edges by repeatedly relaxing every edge.

A negative cycle has total edge weight below zero. If you can reach such a cycle, each extra lap reduces the cost. Vertices reachable after that cycle have no finite minimum route cost. Bellman-Ford detects this situation instead of reporting an ordinary distance as if it were final.

The relevant cycle must be reachable from the selected source. A negative cycle in a disconnected region does not affect that source's routes. Even a reachable negative cycle does not invalidate every vertex: vertices that the cycle cannot reach may still have finite shortest distances.

Repeat a complete edge scan

Bellman-Ford stores dist[start]=0 and INF elsewhere. For each pass, it visits all directed edges in a fixed listed order. An edge u to v can improve v only if u is already reachable and dist[u]+w is smaller than dist[v]. The reachability guard prevents INF from participating in arithmetic.

The algorithm needs at most V-1 full relaxation passes before a cycle check. A changed flag allows early termination after a pass with no improvement. No change means another identical pass would start from exactly the same distances and also make no change.

Updates in these examples happen immediately within the pass. A newly improved vertex can help a later edge in that same scan. This can propagate farther than one edge per pass. The guarantee is at least all paths with up to the pass number of edges, not exactly one extra edge of progress.

dist[*] = INF; dist[start] = 0
for pass = 1 to V-1: changed = false
    scan every edge u -> v in its listed order
        if u is reachable and dist[u]+w < dist[v]: relax; changed = true
    if not changed: stop early
mark destinations of any still-relaxable reachable edges as affected
propagate affected forward along outgoing edges
report -INF for affected vertices, INF for unreachable ones

Use a directed variant with one negative arc

Scenario 1 adds E to B with weight -6. The cycle B,C,E,B costs -3+8-6=-1. A reaches it through B. From that cycle, D, E and F can also be reached, so B through F lose finite shortest distances. A remains at zero because no directed route returns from the cycle to A.

Scenario 2 removes the two arcs entering F while keeping the negative B to C edge. F is unreachable from A. Scenario 3 keeps all six vertices but removes every edge. Selecting F as source in scenario 1 leaves the negative cycle unreachable, because F has no outgoing arc.

Bound the number of edges in an optimal simple path

After pass p, dist[v] is no greater than the cost of any source-to-v path with at most p edges. The base case is the source with its zero-edge route. For the induction step, take a path whose last edge is u to v. Its prefix has at most p-1 edges and is covered before pass p begins.

When that final edge is scanned in pass p, dist[u] is already no larger than the prefix cost. Earlier updates during the pass can only improve it further. Relaxing therefore makes dist[v] no larger than the full path cost. Every finite distance is also the cost of an actual walk, so the algorithm never invents an unattainable cheaper value.

Without a reachable negative cycle, a shortest route can be chosen simple. Removing a repeated-vertex cycle of nonnegative weight does not increase cost. A simple route uses at most V-1 edges. Consequently the pass guarantee and attainable-walk property together make all reachable distances exact after V-1 passes.

If a reachable edge can still improve after those passes, the finite-simple-path conclusion is impossible. Some reachable negative cycle must exist. Equivalently, summing relaxation inequalities around a negative cycle shows that at least one cycle edge cannot satisfy a stable distance inequality.

Separate affected, finite and unreachable vertices

The extra scan marks the destination of every still-relaxable edge with a reachable tail. The program does not change distances during that scan. It then propagates the affected flag forward along outgoing edges. Up to V passes are sufficient to reach every downstream vertex in the six-node graph.

An affected vertex is printed as -INF, meaning no finite lower bound. An unreachable vertex is printed as INF, meaning no route from the source. All other vertices receive numeric distances. These are different conclusions and should never share one marker.

Marking only a single improved endpoint and stopping would miss other affected destinations. Marking every vertex whenever any negative cycle exists would also be wrong. In scenario 1 from A, the correct affected set is B,C,D,E,F. In the same graph from F, the affected set is empty.

Full scans multiply vertices by edges

There are at most V-1 main passes, each checking E edges. The extra detection scan takes O(E). Initialising distances takes O(V), so the usual worst-case bound is O(VE+V). When E is positive and scales with the graph, this is commonly abbreviated O(VE).

The bounded implementation propagates affected flags with another V complete edge scans. This also costs O(VE) and leaves the overall worst-case order unchanged. A queue could reduce only the propagation phase to O(V+E), while the main Bellman-Ford relaxation remains O(VE).

Working arrays dist and affected use O(V) auxiliary space. Input storage for the edge list takes O(E), plus the unused demonstration adjacency storage. No priority queue or recursion stack is required. Early stopping is useful for easy cases but does not remove the worst case where each pass still changes a value.

Undirected negative roads have a different consequence

Replacing an undirected negative edge with two directed arcs creates a negative two-arc walk cycle. You can travel across and immediately return for a lower total cost. Thus unrestricted shortest walks in a reachable undirected graph with a negative edge have no finite answer downstream.

A problem that forbids repeated vertices is asking about simple paths, which is a different contract. Bellman-Ford's negative-cycle diagnosis concerns unrestricted route walks. Do not silently reinterpret the problem to preserve a finite answer after detecting a reachable negative cycle.

Keep the source reachability guard

Relaxing INF plus a negative weight

A finite sentinel can become numerically smaller after adding a negative value. Check dist[u] is not INF before adding the edge weight, or you may create a route in an unreachable region.

Checking for a cycle after too few passes

An improvement in an early pass is normal. Use the additional scan only after completing V-1 passes, unless a no-change pass has already established stability.

Printing tentative cycle values as shortest costs

Values may keep falling around a reachable negative cycle. Label affected vertices -INF after forward propagation rather than presenting the last finite approximation.

Explain the pass convention

State whether updates are immediate or use a separate previous-pass array. Both versions have valid guarantees, but their intermediate tables can differ. Keep the edge order visible whenever you show immediate-update values.

Finite arithmetic in C17

Bellman-Ford's C17 distances use a one-million sentinel. With six vertices, at most nine edges and five main passes, even repeated negative-cycle improvements remain safely inside int range. Arbitrary graphs require wider types and explicit overflow bounds.
