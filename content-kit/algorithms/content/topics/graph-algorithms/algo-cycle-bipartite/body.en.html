Can every connection join opposite teams?

Suppose students must be divided into two lab groups, and every listed pair must belong to opposite groups. Model each student as a vertex and each restriction as an undirected edge. A bipartite graph permits exactly such a division into two sets.

You can test the condition by colouring adjacent vertices differently. Begin one vertex with colour 0. Give every newly reached neighbour colour 1, then alternate as the search spreads. If an edge joins equal colours, the proposed two-group assignment is impossible for that component.

Cycle detection asks a related but different question. A tree has no cycle and is always bipartite. An even cycle can also be bipartite. An odd cycle cannot. Therefore finding a cycle alone does not decide whether two colours suffice; its parity matters.

Track colours, parents and active calls

The BFS colouring program uses colour -1 for undiscovered, 0 for one side and 1 for the other. Parent records the edge that first discovered a vertex. A queue explores the component while assigning each newly discovered vertex the opposite colour to its parent.

The same undirected traversal can detect cycles in a simple graph. If an already discovered neighbour is not the current vertex's parent, the search forest already contains another route between them. That edge closes a cycle. The parent exception skips the reverse view of the same undirected tree edge.

Directed cycle detection needs another rule. A DFS edge to a grey, currently active vertex closes a directed cycle. An edge to a black, finished vertex does not by itself prove one. The fourth C example uses colours 0,1,2 for white, grey and black in that directed DFS context; those values describe call state, not a bipartition.

colour[*] = -1; parent[*] = -1; bipartite = true; cycle = false
for roots in cyclic order from start: if uncoloured, colour 0; enqueue
    while queue is nonempty: u = dequeue
        for each neighbour v
            if uncoloured: colour[v] = 1-colour[u]; parent[v] = u; enqueue
            else: if v != parent[u], cycle = true
                  if colour[v] == colour[u], bipartite = false
report colours, bipartite and cycle flags

Colour every connected component

The combined undirected program tries roots in cyclic order from start. At every still-uncoloured root, it assigns colour 0 and starts a fresh queue. Components are independent, so choosing colour 0 for every new root is harmless. You may swap both colours throughout one component without changing validity.

For each edge u to v in an adjacency list, a new v receives 1-colour[u], parent u and one queue insertion. A previously coloured v is checked for two conditions. If v differs from parent[u], set the cycle flag. If colour[v] equals colour[u], set bipartite false.

The implementation continues after a conflict so the final labels cover every vertex. A false bipartite result means those labels are an attempted colouring with contradictions. They must not be presented as a valid partition. The highlighted equal-colour edge is the reason the attempt failed.

The shared graph contains triangles A,B,C and D,E,F. Starting at A colours both B and C as 1. The BC edge then connects equal colours, proving failure. Scenario 1 is a six-node chain and succeeds. Scenario 2 isolates F but still contains the A,B,C triangle. Scenario 3 has no constraints and succeeds with all roots coloured 0.

For an undirected simple graph, a visited non-parent edge plus the search-tree route gives a cycle. A directed graph lacks the reverse travel that this argument assumes. Use the active-call test for directed edges instead of importing the undirected parent test.

To recover an actual odd-cycle witness, retain parents and depths at the first same-colour edge. Walk both endpoints upward until they meet, combining the two branches with that conflicting edge. The provided program reports the Boolean result and attempted labels; it does not print a full witness cycle.

Parity explains colouring success and failure

BFS assigns a colour equal to the parity of the tree-path length from its component root. Each tree edge flips colour, so all tree edges satisfy the opposite-colour rule. If every other edge also joins opposite colours, those colour classes are directly a valid bipartition. This proves success without needing any extra graph theorem.

If an edge u,v joins equal colours, their root-path depths have equal parity. Remove their common path prefix up to their lowest common ancestor in the BFS tree. The two remaining branches have an even combined length. Adding edge u,v creates a cycle of odd length.

An odd cycle cannot be two-coloured because every edge flips colour. After an odd number of flips, returning to the starting vertex demands the opposite of its original colour. This contradiction proves that one same-colour conflict makes every two-colouring impossible, rather than merely showing a poor root choice.

Conversely, if a graph has no odd cycle, the BFS process cannot find a same-colour edge, because such an edge would construct an odd cycle as above. Therefore a graph is bipartite exactly when it contains no odd cycle. The outer root loop applies the argument separately to every component.

Each component is explored once

Every undirected vertex changes from colour -1 only once. It enters one queue and has its adjacency list scanned once. The total work is O(V+E), including all component roots. The outer loop adds only O(V); it does not multiply a full traversal by V because already coloured roots are skipped.

Colour, parent and queue arrays use O(V) auxiliary space. Input adjacency lists use O(V+E) in a scalable representation. The directed grey-state DFS also costs O(V+E) with lists and may need O(V) recursive stack space. Its small matrix example generalises to O(V²) neighbour scanning.

A cycle test using union-find is another option for undirected edges processed once. If find(u) equals find(v), adding that physical edge closes a cycle. Do not feed both adjacency-list directions of one undirected edge into that test as separate physical edges, or every tree edge will appear cyclic.

Disconnected constraints and repeated edges

An odd cycle hidden in a component unreachable from A still makes the entire graph non-bipartite. That is why the colouring routine must restart at uncoloured vertices. One-source BFS alone can certify only its reached component.

An isolated vertex can belong to either colour class. A graph with zero edges is bipartite even if one class is empty. A self-loop immediately violates the opposite-colour condition and is a directed or undirected cycle according to the graph model.

Parallel undirected edges need care in cycle detection. Two distinct physical edges between the same pair form a length-two cycle in a multigraph. Skipping every edge to a parent vertex would miss it. Store parent edge ids when parallel edges are permitted; the shorter parent-vertex rule here assumes a simple graph.

Do not confuse cycles with odd cycles

Rejecting a square as non-bipartite

A four-edge cycle alternates 0,1,0,1 and closes consistently. Only odd-cycle evidence rules out a bipartition.

Using visited alone for a directed cycle

A directed edge may point to a finished vertex from another branch. A cycle is proved by reaching a grey ancestor, not merely any previously visited vertex.

Stopping after the first component succeeds

A successful colouring near the chosen source says nothing about disconnected components. Continue the root loop until every vertex is checked or a global failure is established.

State graph assumptions before tracing

Say whether edges are directed, whether parallel edges exist and what the colour values mean. Keep a separate cycle flag and bipartite flag. When failure occurs, name the conflicting edge so a reader can verify the reason directly.

Two different colour arrays in C17

Both examples use C17 integer arrays and bounded recursion or queues. The undirected BFS uses -1,0,1 for assignment state. The directed DFS uses 0,1,2 for call state. Reusing the word colour does not make those meanings interchangeable.
