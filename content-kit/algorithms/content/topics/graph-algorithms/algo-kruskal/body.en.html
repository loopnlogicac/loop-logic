Buy the cheapest safe connections first

Imagine a cable contractor offers every possible connection with a fixed price. You sort those offers from cheapest to most expensive. Take an offer only when it joins two currently separate groups. Kruskal's algorithm follows this rule to build a minimum spanning tree.

Unlike Prim, Kruskal does not grow only from one starting room. It begins with every vertex in its own component and gradually joins components. The selected edges form a forest at every stage. On a connected graph, the forest eventually becomes one tree spanning all vertices.

The hard part is checking whether an offered edge would create a cycle. Repeatedly searching the selected forest would waste work. A disjoint-set structure, also called union-find, tracks which vertices are already connected. It answers connectivity questions without storing the actual graph paths.

Sort edges and maintain representatives

Kruskal first sorts edges by nondecreasing weight. The C implementation uses stable merge sort, keeping original edge-list order for equal weights. Stability is a tie convention here, not a requirement for MST correctness. Any deterministic order among equal-weight edges can produce a minimum result.

Each disjoint set has a representative root. find(u) follows parent links to that root. Path compression changes links along the search path to point directly toward the root. Union by size attaches the smaller root below the larger one. Together these rules make a sequence of set operations very fast.

Do not confuse disjoint-set parent links with selected graph edges. A representative can change during union, and compression can connect two indices that have no direct graph edge. The selected tree is recorded by accepted edge ids, while the disjoint-set structure records only component membership.

sort edges by weight, preserving original edge order for ties
make one disjoint set per vertex; total = 0
for each edge (u,v,w) in sorted order
    a = find(u); b = find(v), using path compression
    if a == b: reject the edge because it closes a cycle
    otherwise union by size; accept edge; total += w
report total and V minus accepted edges as the component count

An edge is safe when its endpoints are separate

For each sorted edge u,v,w, compute a=find(u) and b=find(v). If a equals b, the selected forest already contains a path from u to v. Adding the edge would close a cycle, so reject it. Otherwise accept it, unite the sets and add w to the running total.

The common Kruskal graph uses AB=4, AC=2, BC=1, BD=5, CE=8, DE=2, DF=6 and EF=3. The sorted order is BC, AC, DE, EF, AB, BD, DF, CE. Equal-weight AC precedes DE because its original edge id comes earlier.

Initially the six components are A, B, C, D, E and F. BC merges B with C. AC joins A to that group. DE joins D with E, and EF adds F. AB is rejected because A and B already share a component. BD then joins the two remaining groups.

The code continues scanning after one component remains so the trace can demonstrate later rejections. Stopping after V-1 accepted edges is safe for a known connected input. On disconnected input, that count is never reached, so all edges must be considered before reporting the forest.

Each accepted edge reduces the component count by exactly one. Thus final components equals V minus accepted edges. This is true even when the graph is disconnected. It provides a compact check on both the selected edge count and the union operations.

Exchange across one forest component

Assume an MST contains every edge accepted so far. Consider the next edge e that joins two different forest components. Choose the cut consisting of one endpoint's current component and all other vertices. No previously accepted edge crosses that cut because each forest component already contains all of its selected internal connections.

Edge e is a lightest edge crossing this cut. If a lighter crossing edge had appeared earlier, its endpoints would then have belonged to different components and it would have been accepted. Components only merge; an earlier accepted crossing connection would mean the two current sides were already joined, which contradicts the chosen current cut.

If the preserving MST lacks e, add e and inspect the resulting cycle. Another edge f on that cycle crosses the cut. Since e is no heavier than f, replacing f with e keeps the tree connected and cannot increase its cost. The removed edge was not previously protected, so the new MST still contains every accepted edge.

This exchange maintains the invariant after each acceptance. Rejected edges need no exchange because they are not added. When the graph is connected, V-1 acceptances connect all V vertices, and the preserved MST is exactly the selected tree. For disconnected input, the same argument applies independently inside each original component.

Sorting dominates connectivity work

Merge sort handles E edges in O(E log E) time using O(E) temporary storage and O(log E) recursive depth. The C demonstration reserves a twelve-edge temporary array at each active merge call. It fits the fixed input; a scalable version can share one E-entry buffer across calls.

With path compression and union by size, a sequence of E find/union operations takes O((V+E) alpha(V)) amortised time including initial set creation. Alpha is the inverse Ackermann function, which grows extraordinarily slowly. This is an amortised sequence bound, not a claim that every individual find takes one machine instruction.

Combining sorting and set operations gives O(E log E+(V+E) alpha(V)) time. For a connected graph, the familiar summary is O(E log E). Parent and size arrays need O(V) space; edge storage and sorting workspace add O(E). Input and auxiliary memory should be separated when comparing with Prim.

The tiny implementation uses fixed capacities and a bounded recursion depth. If the temporary merge array were changed to an E-entry local array in every active call, peak storage could grow beyond one shared buffer. Keep the stated allocation strategy consistent with the memory bound you claim.

Choose union-find for connectivity, not paths

Union-find can tell you that A and F are connected after BD is accepted. It cannot directly print the cable route between them. To recover a route, keep the accepted graph edges and traverse that resulting tree. The disjoint-set parent forest is an implementation detail of connectivity maintenance.

Kruskal naturally produces a minimum spanning forest for disconnected graphs. Prim can do the same if restarted from every unused vertex. On a dense graph, a matrix-based Prim implementation may be convenient. When edges already arrive as a list, Kruskal's sorting and set operations often fit the representation well.

Equal weights do not imply one tree

Several equal-weight crossing choices can produce different MST edge sets with the same total. A stable edge order selects one reproducible result. To prove uniqueness, you need stronger information; matching one deterministic output is not enough.

Self-loops are rejected because both endpoints have the same representative. Parallel edges are allowed by Kruskal: the lighter useful one may be accepted, and later redundant ones are rejected. The fixed examples use simple graphs, but the union-find cycle test still works with these extensions.

Negative edge weights are also allowed for the spanning-tree objective. A tree cannot repeatedly traverse a negative cycle because it has no cycle at all. This differs from unrestricted shortest-walk problems. Keep the optimisation objective clear before applying a restriction borrowed from Dijkstra.

Keep roots and weights straight

Joining endpoint indices directly

After earlier unions, an endpoint may not be a representative. Find both roots first, then attach one root to the other.

Rejecting every repeated endpoint

A vertex may appear in many accepted edges without a cycle. Reject only when the two endpoints already belong to the same component.

Sorting weights without their endpoints

Moving only weight values disconnects costs from their actual edges. Sort complete Edge records so from, to and weight stay together.

Trace component membership

Beside each considered edge, record the two representatives before the decision. After an acceptance, update the component groups and total. At the end, check that accepted edges are acyclic and connect every original component internally.

Structure sorting in C17

Kruskal's C17 merge sort copies complete structures and compares weights without subtraction. The fixed totals fit in int. General code should use a wider total when many edge weights may accumulate, and should allocate sorting storage once when graph sizes grow.
