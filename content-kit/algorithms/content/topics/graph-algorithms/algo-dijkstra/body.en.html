Cheapest travel needs weights

A route with fewer roads is not always quicker. Two short roads may beat one long road. Dijkstra's algorithm finds minimum total weight from one source when every edge weight is nonnegative. Weights may represent minutes, metres or another cost that adds along a route.

A tentative distance is the cheapest route found so far. It is an upper bound on the true shortest distance, because it describes a real route. Initially only the source has a known route, of cost zero. Every other vertex begins at INF, a marker for no known route.

Dijkstra repeatedly chooses the unsettled vertex with the smallest tentative distance. Nonnegative weights make that chosen distance final. A priority queue makes the choice efficient when the graph is sparse. Compare with BFS: FIFO layers are enough for equal-cost edges, while varying costs require ordering by total route cost.

Relax a route and save its predecessor

Relaxing u to v asks whether dist[u]+w is smaller than dist[v]. If it is, save the smaller value and parent[v]=u. A predecessor array allows you to recover an actual shortest path after the distances are known. Strict improvement avoids changing parents for equal-cost routes.

The C implementation uses a binary min-heap of Entry values. Each entry contains value, vertex and parent fields. Dijkstra uses the first two to select and validate a queued distance; the parent array is updated at relaxation. Entries compare by value, then vertex index, so ties have a fixed order.

Rather than decreasing an existing heap entry, the program pushes a new entry after every improvement. Old entries stay in the heap. On removal, an entry whose value differs from dist[u] is stale and is ignored. This lazy approach avoids maintaining a heap-position array for every vertex.

dist[*] = INF; parent[*] = -1; dist[start] = 0; push (0,start)
while priority queue is not empty: pop minimum (value,u)
    if value != dist[u]: discard stale entry
    for each neighbour v of u with weight w
        if dist[u] + w < dist[v]: update dist[v] and parent[v]
            push (dist[v],v)
report distances; follow parents backward to recover paths

Settle one minimum, then inspect its roads

Dijkstra's shared undirected graph has weights AB=4, AC=2, BC=1, BD=5, CE=8, DE=2, DF=6 and EF=3. Start at A. Its first relaxations propose B at 4 and C at 2. Removing C next improves B to 3 and proposes E at 10.

Removing B at 3 proposes D at 8. The older B entry with value 4 will later be skipped. D does not improve E, because 8+2 equals 10. It proposes F at 14. E then improves F to 13. The old F entry at 14 is another stale entry.

Why the smallest unsettled value is final

Assume every previously settled vertex already has its true shortest distance. Let u have the smallest tentative distance among unsettled vertices. Consider a shortest route from the source to u. If the route crosses from the settled set into an unsettled vertex x, the crossing edge has already been relaxed.

The tentative distance of x is therefore no greater than the cost of that route's prefix to x. Since all remaining edges are nonnegative, that prefix costs no more than the entire route to u. The minimum-choice rule gives dist[u] no greater than dist[x], so dist[u] cannot exceed the true shortest cost to u.

Every finite tentative distance also comes from a real route, so it cannot be below the true minimum. The two inequalities make dist[u] exact. The source establishes the induction base with distance zero. Stale entries do not settle vertices again because they no longer equal the best saved distance.

A negative edge breaks finalisation

Consider directed edges A to B of cost 2, A to C of cost 5, and C to B of cost -4. A finalising Dijkstra version settles B at 2 before C at 5. But A,C,B costs 1. The proof fails because extending the prefix to C can reduce rather than increase its cost.

The lazy implementation without a settled flag may revisit a vertex after an improvement. This does not restore Dijkstra's nonnegative-weight correctness and complexity contract. Some negative-edge graphs happen to work, while a reachable negative cycle can keep generating improvements. Use Bellman-Ford for negative weights rather than relying on such accidental success.

A zero-weight edge is allowed. Nonnegative means zero or positive. Multiple equally good routes may exist, and a path through a zero-weight cycle need not be unique. The strict improvement rule avoids replacing parents merely because an equal route was rediscovered.

Charge heap work to successful relaxations

Once a vertex has a valid minimum removal, its adjacency list is scanned. Under nonnegative weights it cannot later receive a strict improvement. Across all valid removals, there are O(E) arc examinations. Each successful relaxation pushes one heap entry, and the source contributes one initial entry.

The lazy heap may contain O(E+1) entries over the run, including stale ones. Each push or pop costs O(log(E+1)), giving O(V+E log(E+1)) time including array initialisation. O((V+E) log(V+E)) is a convenient bound covering isolated vertices as well. For simple connected graphs, it is often written O((V+E) log V).

Distance and parent arrays take O(V) auxiliary space. Lazy heap entries can take O(E), whereas an indexed decrease-key heap keeps O(V) entries. The C demonstration reserves 32 heap slots; its eight undirected edges permit at most sixteen successful arc relaxations plus the initial source insertion, which fits safely.

Do not invent a path through INF

If the source is isolated, its distance is zero and every other distance remains INF. Do not follow a missing parent chain for an unreachable target. If source equals target F, the recovered path contains only F and has cost zero.

The sentinel INF is one million in these programs. A finite simple route has at most five edges with weight at most eight, so finite answers are at most forty. Integer sums stay far from overflow. Larger weight ranges need a derived bound, wider integers and guarded arithmetic; a sentinel is not mathematical infinity.

Distinguish costs from keys and layers

Using an ordinary queue for weighted roads

FIFO order can settle an expensive route before a cheap one arrives. Order tentative total costs with a priority queue.

Adding weights to an unreachable marker

Do not relax from a vertex without a finite route. Heap entries here are inserted only for reachable vertices, so the loop never pops INF.

Treating a predecessor as the final target

Parent links point backward. Collect them from the target, stop at -1, and reverse the collected vertices before printing.

Show stale entries honestly

When tracing the lazy heap, retain outdated entries until removal and explain why they are ignored. State your tie rule before comparing two route outputs. To verify a recovered path, add its edge weights and compare the sum with the reported distance.

Heap storage in C17

Dijkstra's C17 heap uses structure values and bounded arrays, without external libraries. The capacity proof applies to the six-node demonstrations. A general implementation must grow the heap or check capacity before inserting more entries.

Minimum tentative cost drives the search

Dijkstra combines relaxation, minimum selection and a nonnegative-weight proof to find shortest routes efficiently. Parent links recover one optimal route. Continue with Bellman-Ford Algorithm when routes may contain negative edges.
