Plan routes between every pair

Suppose you need a campus travel table, with one row per starting location and one column per destination. Running a single-source search repeatedly is one option. Floyd-Warshall instead updates the whole table through a carefully ordered dynamic program.

The algorithm asks which intermediate vertices a route may use. At first, routes may use a direct edge or stay at their starting vertex. It then permits A as an intermediate, then B, and so on. Each newly permitted vertex may join two known subpaths into a cheaper route.

Floyd-Warshall works with directed edges and can handle negative weights when relevant shortest paths remain finite. Its usual distance table needs special interpretation if a negative cycle is reachable between a pair. The runnable examples here use nonnegative edges, so every reachable pair has a finite answer.

Define the state before the loops

Let D(k,i,j) be the shortest cost from i to j using only vertices numbered below k as intermediates. Endpoints i and j are unrestricted. D(0,i,i)=0, direct edges initialise other reachable pairs, and absent routes start at INF. For parallel edges, choose the minimum direct weight.

The recurrence is D(k+1,i,j)=min(D(k,i,j), D(k,i,k)+D(k,k,j)). A best route either avoids intermediate k or uses it. In the second case, split the route at k. Both parts may use only earlier intermediate vertices. This gives the two candidate values.

The implementation stores one two-dimensional dist table and keeps k as the outermost loop. It tries every source i and destination j for that k. Before adding two entries, it checks that both are finite. This is the table-filling order required by the recurrence, rather than an arbitrary arrangement of three loops.

initialise dist[i][i]=0; absent arcs=INF; next[i][j]=j for arcs
for k = 0 to V-1
    for i = 0 to V-1, for j = 0 to V-1
        if both subpaths exist and dist[i][k]+dist[k][j] < dist[i][j]
            dist[i][j] = dist[i][k]+dist[k][j]; next[i][j]=next[i][k]
report matrix; follow next[current][F] to recover a route

Distances and next hops change together

Alongside distances, next[i][j] stores the first vertex after i on a chosen route to j. A direct i to j edge sets next[i][j]=j. An absent route keeps -1. If a cheaper route goes through k, its first hop is the first hop on the existing route from i to k.

Therefore an improving update assigns next[i][j]=next[i][k]. The destination j is not necessarily that first hop, and k is not necessarily adjacent to i. Saving either of those blindly would skip edges when recovering a multi-step route.

The Floyd-Warshall demonstration uses six directed vertices and the weighted arcs AB=4, AC=2, BC=1, BD=5, CE=8, DE=2, DF=6, EF=3. Scenario 1 is a positive directed ring; scenario 2 isolates F. Scenario 3 has only diagonal zero distances and INF between different vertices.

Partition routes by their newest allowed intermediate

Assume the table before outer iteration k contains shortest costs with only earlier intermediates. An optimal route with the enlarged allowed set either omits k or contains k. If it omits k, the existing entry already covers it. If it contains k, choose a shortest simple representative and split it at k.

The two subpaths use only previously allowed intermediate vertices, so their best costs are already available. Taking the smaller candidate yields an attainable route no more expensive than any valid route. This proves the recurrence by induction from the direct-edge base.

Why can the two-dimensional table be updated in place? Without negative cycles, dist[k][k] is zero. During iteration k, routes from i to k and from k to j cannot strictly improve merely by adding a zero-length visit through k. Those boundary entries remain stable, so candidate subpaths retain the meanings needed throughout the iteration.

Interchanging i and j inside a fixed k iteration is safe. Moving k inward breaks the phase invariant because some cells may consume paths with intermediates that other cells have not yet allowed. Certain graphs still produce correct answers under an incorrect loop order; that accidental success is not a proof.

Negative cycles change pairwise meaning

After Floyd-Warshall, a negative diagonal dist[k][k] indicates a negative cycle reachable from k and back. A pair i,j has no finite shortest cost when i can reach such a k and k can reach j. Repeating that cycle reduces the i-to-j cost without bound.

This affected-pair test requires both reachability conditions. A negative cycle elsewhere in the graph does not invalidate every matrix entry. Never follow next hops indefinitely for an affected pair; first classify the pair and suppress ordinary path reconstruction when no finite minimum exists.

The provided graphs contain no negative edge and no negative cycle. Their reconstruction loop therefore follows a valid finite route. Extending the code to signed inputs requires the diagonal test and affected-pair handling as well as a larger arithmetic range. Merely allowing a negative integer in the input would be incomplete.

An isolated vertex retains a diagonal zero and INF elsewhere. For scenario 2, F can reach itself but no other vertex can reach F. That distinguishes an empty route from an absent route. A zero-weight self-loop does not lower the already-zero diagonal.

Three dimensions of work, two dimensions of storage

The outer loop takes V choices of k. Each phase visits V possible sources and V possible destinations. That is exactly V³ candidate positions, so the time is Theta(V³), even when most routes are absent. Finite guards reduce arithmetic work inside a position but do not skip the loops themselves.

The distance and next-hop tables each store V² entries. Their combined space is Theta(V²); the temporary loop variables need constant additional memory. If you retained a separate matrix for every k phase, space would grow to Theta(V³), which is unnecessary when in-place updates satisfy the phase invariant.

Recovering one finite route takes O(L) time for L printed vertices, at most O(V) for a simple route. Printing the entire matrix costs Theta(V²). Those output costs fit below the cubic computation but still matter when comparing an all-pairs table with a single-source query.

Choose all-pairs work deliberately

For a small dense graph with many source-destination queries, Floyd-Warshall gives a compact implementation and constant-time distance lookup afterward. For one source in a sparse nonnegative graph, Dijkstra generally does less work. Bellman-Ford answers a single-source question while detecting reachable negative cycles.

Floyd-Warshall is dynamic programming over allowed intermediates. It is not repeated greedy finalisation and does not need a priority queue. The order of the outer phases is part of the state definition, much like the table-filling order in earlier DP lessons.

Two-dimensional arrays in C17

The Floyd-Warshall examples use fixed six-by-six C17 arrays. Finite simple paths cost at most forty, far below INF and int limits. The loops use C99-style local declarations and require no feature newer than the selected C17 baseline.
