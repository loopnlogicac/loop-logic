The best consecutive run

Suppose a club records daily changes to its cash balance. Positive numbers add money, and negative numbers spend it. You want the most profitable consecutive run of days. You cannot skip a bad day inside that run. A subarray is a contiguous interval of array positions, so choosing days one, three and five alone is not allowed.

Here the answer must contain at least one element. For [-8,-3,-6], the best sum is -3. Returning zero would mean choosing no day, which solves a different problem. Fix this convention before comparing algorithms. Several intervals can have the same best sum, so a task asking for boundaries also needs a tie rule.

The example [-2,3,-1,4,-5] has best interval [1,4), containing 3,-1,4. Its sum is 6. This lesson solves that same problem three ways. Brute force is useful as a small-input reference. Divide and conquer explains crossing intervals. Kadane compresses the information needed to extend a prefix into two running totals.

Kadane's two running answers

ending = values[0]; best = ending
for i = 1 to n - 1
    ending = max(values[i], ending + values[i])
    best = max(best, ending)
return best

The variable ending means the greatest sum of a nonempty interval ending exactly at the current index. The variable best means the greatest sum anywhere in the processed prefix. Those meanings are different. An earlier profitable interval may remain best even when the most recent day makes ending negative.

The C implementation starts both variables from a[0]. It then begins its loop at index one. That arrangement establishes the nonempty requirement without a special negative-infinity constant. The caller must provide at least one value. If an application allows an empty dataset, it must define a separate response rather than reading a[0].

Restart or extend

Consider the next value x. A nonempty interval ending here either begins here or extends an interval ending one position earlier. The best extension uses the previous ending, because every possible extension adds the same x. Therefore the new ending is max(x,ending+x). Comparing this with best maintains the best answer over the whole prefix.

For the daily changes, the first ending is -2. At value 3, starting anew gives 3 while extending gives 1, so restart. At -1, extension gives 2 and restart gives -1, so keep the existing run. At 4, extension reaches 6. The final -5 lowers ending to 1, while best correctly remains 6.

Brute force fixes a start lo and grows an end hi. Keep a running sum as hi moves right. That evaluates every nonempty interval using n(n+1)/2 additions. Recomputing each interval's sum from scratch would add an unnecessary third loop. The quadratic version is easier to trust when checking a faster implementation on short arrays.

Divide and conquer splits at mid. An optimal interval lies wholly left, wholly right, or crosses the boundary. The first two cases come from recursive calls. For the third, scan left from mid-1 for the greatest suffix sum and right from mid for the greatest prefix sum. Adding those two sums gives the best crossing interval.

The running totals explain why a temporary negative value inside the answer need not end it. The -1 day is worth keeping between profitable days 3 and 4. Kadane discards an earlier prefix only when its total would make every future extension worse. It does not discard every individual negative number.

Two meanings form the invariant

Before processing index i, ending is the best sum ending at i-1, and best is the best sum inside [0,i). Any interval ending at i either contains only a[i] or extends an interval ending at i-1. The recurrence chooses the better of those exhaustive possibilities. Updating best then compares the previous prefix answer with the best newly ending interval.

At the beginning, the only nonempty interval in the first-element prefix is that element itself. The invariant therefore holds after initialisation. Each iteration preserves both meanings. When the final index is processed, every possible nonempty interval ends somewhere in the processed prefix, so best covers all candidates. The loop terminates because i increases toward n.

For divide and conquer, the three location cases are exhaustive. A crossing interval must use a suffix of the left half and a prefix of the right half. Their choices are independent, so taking each greatest sum maximises their total. The nonempty base case returns its sole value. Induction over interval length proves the recursive results.

Count candidate intervals and scans

Brute force performs n+(n-1)+...+1 interval extensions, which is Θ(n²). It needs Θ(1) auxiliary storage. The recursive method does two half-size calls plus linear crossing scans. Its recurrence T(n)=2T(n/2)+Θ(n) gives Θ(n log n) time. The active recursion path uses Θ(log n) stack space.

Kadane visits each value once and uses a fixed number of arithmetic operations and comparisons per visit. Its time is Θ(n), and its two totals use Θ(1) auxiliary space. Returning interval boundaries adds only a few indices. Copying every candidate interval would destroy that constant-space advantage, so store boundaries and copy only the final answer when needed.

The loop bounds remain linear for positive, negative and mixed input. There is no sorting or early finish. Arithmetic width remains a separate concern: summing many large changes can overflow an int. The exercise bounds of sixteen values between -99 and 99 keep all intermediate sums safe, including the quadratic reference and crossing scans.

Boundaries and equal sums

To recover Kadane's interval, keep a tentative start for ending and final boundaries for best. When restarting is strictly better, move the tentative start to i. When ending strictly improves best, save that start and i+1. If ties must prefer the earliest start, extending on equal totals avoids throwing that earlier start away.

A single negative value returns itself. An all-positive array returns the full array sum. An all-zero array has many optimal intervals; the boundary exercise chooses the earliest start and earliest end. These cases test different parts of the contract. They do not require changing the recurrence or allowing an empty answer.

Do not confuse maximum subarray with maximum subsequence. A subsequence may skip positions, so it could add separated positive values. Also distinguish maximum sum from maximum length. An interval of length one may be the best sum, and a longer tied interval is not automatically preferred unless the problem says so.

Keep the answer nonempty

Initialising best and ending to zero makes negative-only input return the empty sum. Initialise from a real first value instead. Updating best before updating ending also misses intervals that improve at the current position. Compute the ending candidate first, then compare it with the global answer.

For crossing scans, force both sides to contribute at least one element. Starting suffix and prefix maxima at zero would again permit an empty side. The recursive code starts them at a[mid-1] and a[mid]. Half-open child calls keep those two positions distinct and cover the split correctly.

Sorting values before applying Kadane changes the sequence of days. It can produce an attractive sum for an interval that never existed in the original order. Keep the input order fixed and use brute force to check short cases. A useful disagreement case is [-2,3,-1,4,-5], where adjacency affects the winning run.

Safe C17 totals

The maximum-subarray programs use signed int values and integer indices. Their stated small bounds avoid signed overflow and permit negative input naturally. No special C17 library routine is needed for max; the conditional operator compares the two candidates explicitly. A production program with wider input bounds should widen both running and partial sums together.

An ending answer supports a global answer

Kadane keeps exactly the information needed for the next extension: the best interval ending here. A second total remembers earlier winners.
