শুরু করা যাক

কয়েকটি classroom row-এর ফি যোগ করবে। দুই group-কে আলাদা row-এর total করতে বলে পরে দুই উত্তর যোগ করো। প্রত্যেক group আবার ভাগ করতে পারে। Divide and conquer-এ সমস্যা ছোট করো, সমাধান করো, উত্তর মেলাও। ছোট অংশ একসময় সরাসরি সমাধানযোগ্য হবে।

রিকার্শন দিয়ে প্রকাশ করা যায়, কিন্তু রিকার্শন নিজে ভালো কৌশল নিশ্চিত করে না। একই ইনপুট-এ অনন্ত call-এ progress নেই;overlapping অংশ বারবার করলে waste। কোন সাইজ কমে ও প্রতি call কী ফেরায় চেনো।

Binary search এক half, merge সর্ট দুই half সাজিয়ে merge, quick সর্ট আগে partition করে বাকি region সাজায়। Divide-combine কাজ আলাদা বলে রিকার্শন shape আলাদা। নতুন design-এর আগে এগুলো দেখলে cost আন্দাজে বলতে হয় না।

সিউডোকোড ও ব্যবহারের নিয়ম

sum_range(a, lo, hi):
    if hi = lo: return 0
    if hi - lo = 1: return a[lo]
    mid = lo + (hi - lo) / 2
    left = sum_range(a, lo, mid)
    right = sum_range(a, mid, hi)
    return left + right

Sum routine [lo, hi) নেয়;lo included, hi excluded, length hi-lo। Equal boundary empty, lengthone singleton। mid=lo+(hi-lo)/2-এ disjoint child, একসঙ্গে ঠিক মূল element।

Call-এর আগে promise:sum_range a[lo]..a[hi-1] যোগ ফেরায়, ইনপুট বদলায় না। Empty-তে zero চলে। রিকার্সিভ maximum-এ nonempty চাই;সব ইন্টিজার ইনপুটের জন্য সাধারণ maximum identity নেই।

পদ্ধতিটি কেন সঠিক

Empty zero ও singleton a[lo] contract মেলে। সব ছোট interval সঠিক ধরে বড়টিকে দুই ছোট disjoint covering অংশ করো। Hypothesis-এ child exact sum, যোগে parent exact।

Length≥2-এ mid দুই boundary-র মাঝে, দুই child ছোট nonnegative length। বারবার ভাগে zero/one আসবেই। Base সত্য, combine রাখে, decreasing length অনন্ত call আটকায়—পূর্ণ proof।

Maximum-এর nonempty শর্ত রেখো। Baseone;বড় interval-এর দুই child-ই nonempty। দুই correct maximum-এর বড়টি union-এর maximum। Sum-এর মতো proof হলেও negative-only case-এ base contract জরুরি।

সময় ও মেমরির হিসাব

Sum-এর base কনস্ট্যান্ট;T(n)=T(floor(n/2))+T(ceil(n/2))+Θ(1)। Nonempty ট্রিতে n leaf, n-1 internal;প্রতি node কনস্ট্যান্ট, তাই Θ(n)। ডেপথ Θ(log n)।

Children পরপর, সব ফ্রেম একসঙ্গে নয়। Longest path-এ peak Θ(log n) স্ট্যাক। Total node-কে simultaneous মেমরি ধরবে না। Iterative sum Θ(n) time, Θ(1) space;এখানে ভাগ শেখায়, speedup নয়।

Merge local Θ(n), তাই2T(n/2)+Θ(n)। Binary search এক child:T(n/2)+Θ(1)। Quick:T(k)+T(n-k-1)+Θ(n), k balance-নির্ভর। রিকার্সিভ বললেই একটি complexity class নয়।

কাজে লাগে এমন ভাগ বাছো

নতুন সমস্যায় চার প্রশ্ন:call-এর region কোনটি, children-এর কোনটি, কোন ছোট case সরাসরি, কী তথ্য parent চায়? উত্তর দিলে চালানোর আগেই missing boundary ধরা পড়ে।

Extra organization সাশ্রয়ী হলেই balanced child লাভ। প্রতি call দুই half copy-তে allocation-copy বাড়ে। Shared অ্যারে boundary পাঠালে তা নেই। Merge-তে বাফার লাগে, sum-এ নয়। নিজের implementation-এর স্টোরেজ বলো।

Independent child আলাদা চলতে পারে বলে parallel কাজের ধারণা আসে। কিন্তু combine ও communication cost যায় না। এখানে C sequential, bound-ও sequential। দুই call নিজে দুই processor-এ চলে না।
