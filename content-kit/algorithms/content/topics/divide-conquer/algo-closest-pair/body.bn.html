শুরু করা যাক

Campus map-এ classroom ও service location অনেক। নিকটতম দুইটি পেতে সব pair মাপা সহজ, point বাড়লে expensive। Planar closest-pair দুই dimension-এর আলাদা point রেকর্ডের minimum Euclidean distance চায়।

আলাদা রেকর্ড একই coordinate-এ হলে distancezero বৈধ। দুইয়ের কম রেকর্ড-এ pair নেই। তাই উদাহরণে অন্তত দুই point। Same coordinate ও একই রেকর্ড দুবার নেওয়া আলাদা।

ইন্টিজার coordinate-এ squared distance তুলনা। Nonnegative-এ square root increasing, তাই একই pair minimum। Decision-এ rounding নেই। Metre চাইলে শেষে display-তে square root।

Combine কঠিন। Half সমাধানের পরেও ভালো pair crossing হতে পারে। সব cross pair দেখলে quadratic। Geometry কোথায় ও কত y-neighbor দেখতে হবে বাঁধে।

সিউডোকোড ও ব্যবহারের নিয়ম

sort points by (x, original ID)
closest(a, lo, hi):
    if at most 3 points: check pairs; sort slice by y; return best
    save mid and split_x before recursive calls
    best = min(closest(left), closest(right))
    merge both child slices by y
    gather strip where (x - split_x)^2 < best
    for each strip point: check at most 7 later y-neighbours
    return best squared distance

X-তে সর্ট, tie-তে original ID। রিকার্সিভ call ওই x-order-এর consecutive slice পায়। Minimum squared distance ফেরায় এবং slice y-তে rearrange করে। Order change contract-এর অংশ, accident নয়।

Child call-এর আগেই split_x save;রেকর্ড কাউন্ট-এ mid fix। Half membership original slice-এ বাঁধা। Equal x-তেও initial ID order ও positional split অস্পষ্টতা সরায়।

ধাপে ধাপে বোঝো

Child-এর ছোট distance d। আরও ছোট crossing pair-এর দুই endpoint dividing line-এর d-এর মধ্যে, নইলে horizontal distance-ই বড়। Merged y-order থেকে strip নাও;পরের y difference current best-এর নিচে থাকলেই compare।

সবসময় square রাখে। dx² best-এর নিচে হলে strip, dy² bound ছুঁলেই stop। Update-এর একই strict convention। শুধু minimum চাইলে equal-distance pair আবার দেখা লাগে না।

Child y-order ফেরায়, linear merge করো। প্রতি call strip নতুন সর্ট-এ extra log লাগে। Order contract রাখাই combine linear রাখে।

Base সর্বোচ্চ তিন রেকর্ড:সব local pair মাপো, ছোট slice y-তে insertion সর্ট। কনস্ট্যান্ট-সাইজ বলে দুটো কনস্ট্যান্ট। Merge copy-back-এর পরে একই scratch strip gathering-এ লাগে।

পদ্ধতিটি কেন সঠিক

Optimal pair child-এর ভেতর বা crossing। রিকার্সিভ প্রথমগুলো পায়। d ছাড়ানো উন্নত crossing-এ দুই endpoint strip-এ, vertical gap<d। তাই y-order-এ দরকারি কাছের successor দেখলে improvement বাদ যায় না।

Packing successor বাঁধে। Point-এর ওপরে width2d, heightd window ধরো। দুই half-এর widthd, প্রতিটিকে d/2 side-এর চার square করো। এক child-এর দুই point একই square-এ হলে distance<d, child minimum-এর বিরোধ।

দুই পাশে সর্বোচ্চ আট occupied square, starting point-সহ। তাই পরে সর্বোচ্চ সাত কম্পারিজন। Boundary equality consistent box-এ দাও;strict improvement-ই দরকার। Dividing x-এ থাকা point-ও original child identity রাখে, তাই per-child separation সত্য।

Bestzero হলে ছোট nonnegative distance নেই। Strip কিছু না নিলেও নিরাপদ। লক্ষ্য minimum, সব tied pair নয়। সব closest pair গুনতে duplicate অনেক হলে অন্য কাজ লাগে।

Small slice exhaustively সঠিক। Induction-এ child correct, y-merge correct, strip সব possible improvement দেখে। Minimum সব case-এর global answer। ছোট child base-এ যায়।

সময় ও মেমরির হিসাব

Guaranteed কম্পারিজন sorter-এ initial x-order O(n log n)। প্রতি node y-merge Θ(n), strip collect Θ(n), point-প্রতি সাত কম্পারিজন O(n)। তাই2T(n/2)+Θ(n), রিকার্সিভ Θ(n log n)।

Shared scratch O(n) রেকর্ড, active স্ট্যাক O(log n), ইনপুট বাদে auxiliary O(n)। প্রতি live call নতুন n-অ্যারে নিলে আলাদা হিসাব চাই। Reuse বাফার implementation-এর সঙ্গে proof মেলায়।

C example initial qsort নেয়। Standard order বলে, complexity নয়। পূর্ণ O(n log n) দাবি guaranteed merge সর্ট-এর মতো initial sorter ধরে। Correct initial sorter যা-ই হোক closest routine-এর recurrence একই।

Coordinate, duplicate ও চাওয়া আউটপুট

Subtract-এর আগেই coordinate wide করো। Int subtraction overflow-এর পরে cast দেরি। কোড (long long)a.x-b.x করে square। ছোট bound square-sum safe;extreme coordinate-এ আলাদা range calculation চাই।

Y-reorder-এর পরেও ID সঙ্গে। Actual pair চাইলে improvement-এ দুই ID রাখো। এখানে distance যথেষ্ট। ID tie rule চাইলে strict টেস্ট equality বাদ দেয় বলে অতিরিক্ত care।

Counting exercise আগে distance, পরে সব unordered pair scan। দ্বিতীয়টি quadratic, তাই পুরো প্রোগ্রাম quadratic। Small dataset-এ কাজে লাগে;বড় আউটপুট requirement complexity বদলায়। একবার closest ডাকলেই O(n log n) নয়।

প্রচলিত ভুল

প্রতি node strip সর্ট-এ O(n log² n)। Child থেকে y-order merge করো। Already y-sorted slice আবার current ইনডেক্সে split-ও ভুল;রিকার্সিভ region original x-order-এর। Parent y-তে বদলানোর আগেই child call হয়।

Child-এর পরে a[mid].x নিলে অন্য point হতে পারে, reorder হয়েছে। আগে split_x save। Seven-neighbor proof-এর পরেও all strip pair দেখলে answer ঠিক হলেও speed benefit যায়।

n1-এzero ফেরালে pair আছে বোঝায়, যা ভুল। Public n≥2 রাখো। Internal singleton-এ বড় sentinel চলে, অন্য child real pair দেয়। Coordinate bound-এর সব distance-এর বেশি sentinel চাই।

C17-এর খুঁটিনাটি

Point-এ ইন্টিজার coordinate ও original ID। Qsort comparator subtraction নয়, relational sign নেয়। Distance product long long। Bounded example-এ VLA বা হিপ ownership নেই, reusable অ্যারে পুরো search বাঁচে।

যা শিখলে
