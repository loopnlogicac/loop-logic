Multiply fewer times

Computing 3 to the thirteenth power by repeated multiplication takes thirteen factor updates. You can do much less work by reusing squares. First obtain 3², then 3⁴, then 3⁸. Since 13=8+4+1, multiply the selected powers 3⁸, 3⁴ and 3. This is exponentiation by squaring, also called binary exponentiation.

The exponent is a nonnegative integer. An exponent of zero returns the multiplicative identity 1. In these integer routines, the same convention defines power(0,0) as 1. Negative exponents would require reciprocal values and another numeric model, so they are outside this contract. State that restriction when using the function.

Large powers quickly outgrow fixed C integer types. Modular exponentiation asks only for the remainder after division by a positive modulus. Reducing intermediate products preserves that remainder while keeping stored values small. It does not automatically prevent overflow during the multiplication before reduction, so the permitted modulus still matters.

One half-power is enough

result = 1
while exponent > 0
    if exponent is odd: result = result * base
    exponent = exponent / 2
    if exponent > 0: base = base * base
return result

The recursive identity is base^exponent=(base^(exponent/2))², multiplied by one extra base when the exponent is odd. Integer division discards the final odd bit. Save the recursive half-power in a variable and use it twice. Writing two identical recursive calls recomputes the half-power and changes the recurrence from logarithmic work to linear work.

The iterative form keeps result, base and exponent. It consumes the exponent's binary digits from right to left. An odd exponent means the current squared base belongs in the result. Dividing exponent by two shifts attention to the next bit. Squaring base prepares the power associated with that next bit.

Track what remains to multiply

Start iterative power with result=1, base=3 and exponent=13. Because 13 is odd, multiply result by 3. Divide the exponent to get 6, and square the base to get 9. Six is even, so keep result unchanged. Another division and square produce exponent=3 and base=81. The remaining decisions select 81 and then 6561.

The plain integer routine avoids a final unused squaring after the exponent becomes zero. This detail matters near the type limit. The returned power can fit even when an unnecessary square would exceed the type. The exercise restricts base to 0..10 and exponent to 0..18, so every multiplication used to form the answer fits unsigned long long.

For modular power, replace multiplication by multiplication followed by remainder. Reduce the starting base first. Initialise result as 1 % modulus so modulus one is handled correctly. A modulus of zero is invalid because C remainder by zero has undefined behavior. The modular exercise rejects it before calling the function.

Keep the original power factored

For the iterative routine, the invariant is result×base^exponent equals the original requested power. Initially result=1, so this is true. For an odd exponent 2q+1, multiplying result by base and replacing the remaining base by base² with exponent q preserves the product. For an even exponent 2q, only the squaring and halving are needed.

When exponent reaches zero, base^0 is 1 and the invariant says result equals the original power. The loop terminates because every positive exponent is replaced by a smaller integer exponent/2. The plain routine may skip a last squaring because there is no remaining positive exponent to use that value.

For the recursive routine, exponent zero is the base case. Assuming the half-power is correct, its square gives the even power. Multiplying by one more base gives the odd power. This induction follows exponent size rather than array length. Only one recursive child is needed because both halves are the same calculation.

Modular correctness uses the product rule for congruences: reducing factors before or after multiplication gives the same residue. Apply the factoring invariant modulo the positive modulus. The result need only match the original power's residue, not its full value. This argument assumes the C multiplication itself represents the exact residue product before remainder.

Halving gives the logarithm

A positive exponent e has floor(log₂ e)+1 binary digits. Each loop iteration removes one digit and performs at most a constant number of multiplications. The iterative time is Θ(log(e+1)) for the fixed-width arithmetic model, with Θ(1) auxiliary storage. The recursive version follows T(e)=T(floor(e/2))+Θ(1) and uses Θ(log(e+1)) stack space.

These bounds count machine arithmetic operations. If the full power uses arbitrarily large integers, multiplication cost grows with the number of digits. Then a multiplication is not a constant-time operation. A logarithmic count of multiplications remains useful, but it is not a complete bit-complexity bound for enormous exact powers.

For e=0, both routines do constant work. For base zero and positive e, the answer is zero, although the general loop still inspects the exponent bits. You could add an early return for that special base, but it does not improve the worst-case complexity over all permitted bases.

Overflow before remainder

The modular exercise permits modulus at most 1000000000. After reduction, each factor is smaller than that modulus. Their product is below 10¹⁸, which fits the C minimum range of unsigned long long. The bound makes ordinary multiplication followed by % safe. An unrestricted 64-bit modulus would need a different multiplication method or a suitably wider implementation type.

Unsigned arithmetic wraps when it exceeds its range. Wrapping is defined by C, but it is generally the wrong remainder for an arbitrary modulus. Applying % after a wrapped product cannot restore the lost high bits. Therefore using unsigned long long avoids undefined signed overflow but does not remove the need for a numeric bound.

This pattern also works for associative operations with an identity. For example, square matrices can be raised to powers by matrix multiplication. The operation need not be ordinary scalar multiplication, but its order must remain consistent. That connection later explains fast Fibonacci methods, although the current routines use ordinary integer factors.

Do not recompute the half

A recursive expression with recursive_power(base,e/2) written twice creates duplicate work. Save it once as half. Another error tests oddness after halving, which reads the next bit too early. Decide whether to multiply result using the current exponent, then update exponent and base for the next iteration.

Starting result at zero makes every positive exponent return zero. The correct identity for multiplication is one. For modulus one, that identity must itself be reduced to zero. Distinguish these initial values rather than adding an unexplained special case after the loop.

A negative value read into an unsigned exponent may become a huge value. The exercises accept only the stated nonnegative input range. General user interfaces should validate text before conversion if malformed or negative tokens are possible. The algorithm's logarithmic loop does not make an incorrectly parsed request meaningful.

Integer operations in C17

C17 provides unsigned long long with at least 64 value bits, enough for the bounded powers and modular products here. The output conversion %llu matches that type. All exponents are unsigned int and are halved by ordinary integer division. No floating-point pow call is used, so the answers avoid rounding errors from converting through double.

Reuse repeated factors

Exponentiation by squaring saves work by computing one half-power and reusing it. The iterative invariant explains every odd-bit selection. Modular reduction supports large exponents only when residue multiplication is also safe. Closest pair next uses a geometric combine step to avoid checking every possible pair of points.
