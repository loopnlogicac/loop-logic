শুরু করা যাক

বর্ণমালায় সাজানো dictionary মাঝখানে খোলো। সেখানকার word target-এর আগে হলে বামের সব বাদ দিতে পারো। Binary search এই order দিয়ে প্রতি সিদ্ধান্তে বাকি candidate প্রায় অর্ধেক করে।

Order অপরিহার্য। Unsorted row-এর midpoint আগের-পরের সব মান সম্পর্কে বলে না। Animation আগে ascending copy দেখায়; তার সর্টিং cost আলাদা। Returned ইনডেক্স ওই copy-র, original অসাজানো ইনপুটের নয়।

সিউডোকোড ও ব্যবহারের নিয়ম

a = ascending copy of values (setup, before search)
low = 0; high = n
while low < high
    mid = low + floor((high - low) / 2)
    if a[mid] == target: return mid
    if a[mid] < target: low = mid + 1
    else: high = mid
return -1

ধাপে ধাপে বোঝো

Half-open interval ধরে রাখো

Low=0, high=n নাও; candidate [low, high)-এ, low থাকবে high নয়। low<high-এ ইন্টিজার division দিয়ে mid=low+(high-low)/2। এতে বড় দুই ইনডেক্স যোগ করতে হয় না। Interval nonempty বলে mid বৈধ element।

a[mid]=target হলে ফেরাও। ছোট হলে mid-সহ বামের সব ছোট, তাই low=mid+1। বড় হলে high=mid। Excluded upper endpoint বলে দ্বিতীয়টিতে এক বিয়োগ লাগে না। Empty হলে -1।

[1, 3, 3, 5, 7]-এ target 5। প্রথম [0, 5), mid = 2-তে 3, তাই low = 3। তারপর mid = 4-তে 7, high = 4। শেষে mid = 3-তে 5। Duplicate exact search ভাঙে না, তবে এই version যেকোনো match দেয়, first নয়।

রিকার্সিভ search-এ একই চুক্তি

রিকার্সিভ version সরাসরি low, high নেয়। low≥high base। বড় target-এ [mid+1, high), ছোটতে [low, mid)। Iterative-এর একই boundary-decision বলে trace তুলনা করা যায়।

প্রতি call ছোট interval নেয়, তাই stop ও logarithmic ডেপথ। Iteration অল্প ইনডেক্স, রিকার্শন লেভেল-প্রতি ফ্রেম রাখে। কম্পারিজন growth একই, auxiliary স্ট্যাক আলাদা।

Closed interval recipe মেশাবে না। [low, high]-এ high=n-1, প্রায়ই high=mid-1। আলাদাভাবে দুটো convention ঠিক হতে পারে। Initial ভ্যালু-update মেশালে edge candidate বাদ বা shrink না-হওয়া লুপ হয়।

Lower-upper bound-এ tie খোঁজো

Lower bound প্রথম পজিশন যার মান অন্তত target। সব ছোট হলে n। a[mid]<target-এ low=mid+1, নইলে equality-সহ high=mid। শেষ low insertion পজিশন, নিজে found element নয়।

Upper bound প্রথম strictly বড় পজিশন। Right condition a[mid]≤target। [1, 3, 3, 5, 7]-এ target 3-এর lower 1, upper 3; পার্থক্য দুই equal ভ্যালু গোনে। Equal range [1, 3), প্রথম বড়টি বাদ।

Lower bound থেকে exact membership-এ আগে পজিশন<n, তারপর a[পজিশন] compare। n বৈধ insertion পজিশন, element access নয়। Absent 4-এ দুই bound 3, countzero।

Answer-এর ওপর binary search

সবসময় explicit sorted অ্যারে লাগে না। Yes/no শর্ত একবার true হয়ে true থাকলে monotone। False-এর পরে true-এর row ভেবে প্রথম feasible answer খুঁজতে পারো।

[7, 3, 5, 3, 5] কাজ একই order-এ সর্বোচ্চ তিন দিনে করতে হবে। কাজ ভাঙা যাবে না, দিনের capacity-তে assigned সব ধরতে হবে। Proposed capacity-তে যত ধরে ভরো, পরেরটি না ধরলে নতুন দিন। ওই capacity-তে এতে সর্বনিম্ন দিন লাগে; boundary দেরি করলে বাকি capacity কমে না।

Capacity 7-এ পাঁচ দিন। 8-এ [7], [3, 5], [3, 5] চলে; বড়তেও ওই grouping চলে। Total 23 পর্যন্ত 1 থেকে ইন্টিজার search করো; largest job-এর নিচে infeasible। Feasible হলে high=mid, নইলে low=mid+1। উত্তর8।

দুটি cost: numerical range-এ logarithmic trial, প্রতিটিতে job scan। Answer range S হলে O(n log S)। বাইরের binary search দেখে O(log n) বলবে না।

ভ্যালু পড়ার আগে boundary বোঝো

Empty interval-এ midpoint element নেই। Singleton এক সিদ্ধান্তে match বা empty। সবার ছোট target high-কে zero, সবার বড় low-কে n নেয়। Extreme insertion পজিশন টেস্ট করতে ভালো।

এক query-র জন্য সর্ট scan-এর চেয়ে বেশি লাগতে পারে। আগে ordered ডেটা বা shared sorted representation-এ বহু search হলে লাভ। Original পজিশন চাইলে কী-এর সঙ্গে সেটি রাখো। নইলে সর্টিং returned ইনডেক্সের অর্থ বদলায়।

Animation ও C routine একই ascending ডেটা ও half-open নিয়ম নেয়। high-কে element-এর মাঝের boundary ভাবো, n হলেও। mid সবসময় element; excluded high-কে element হতে হয় না।

পদ্ধতিটি কেন সঠিক

Invariant: ফেরত না-আসা যেকোনো match [low, high)-এ। শুরুতে পুরো অ্যারে। Sorted order-এ mid ছোট হলে তার বাম, বড় হলে তার ডান বাদ নিরাপদ। Equality সরাসরি contract পূরণ করে।

Nonnegative high-low প্রতি nonreturn iteration-এ কমে। Zero-তে candidate নেই, absence প্রমাণ। Lower bound-এ শক্ত partition invariant: low-এর নিচে ছোট, high থেকে সবাই অন্তত target। Shrinking gap প্রথম eligible পজিশন দেয়।

সময় ও মেমরির হিসাব

Interval প্রায় অর্ধেক হারায়, তাই exact ও bound O(log n) কম্পারিজন। Iterative O(1), রিকার্সিভ O(log n) স্ট্যাক। Ascending display copy O(n) স্টোরেজ ও আলাদা সর্টিং লাগে। Already sorted search-এর logarithmic দাবিতে setup লুকিও না।

প্রচলিত ভুল

Mid বাদ দিয়েও low=mid রাখা

এক-element gap-এ mid=low হতে পারে। low না বাড়ালে থামে না। Mid ছোট হলে mid+1 করো।

n-এ bound dereference

Bound বৈধভাবে n দেয়। Dereference-এর আগে length-এর সঙ্গে ইনডেক্স দেখো।

প্রমাণ ছাড়া feasibility monotone ধরা

Answer search-এ এক false-to-true transition চাই। বড় answer আবার infeasible হলে আসল solution বাদ যেতে পারে।

C = 17-এর খুঁটিনাটি

C = 17-এ দেখানো ছোট সীমায় signed ইনডেক্স। Boundary n হতে পারে; পড়া midpoint তার নিচে।
