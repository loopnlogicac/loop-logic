শুরু করা যাক

অসাজানো roll number থেকে একটি student খুঁজবে। সঠিক position-এ লাফ দেওয়ার নিশ্চয়তা নেই। বাম থেকে একে একে roll দেখে match পেলেই থামো। এটি linear search।

দ্রুত মনে হওয়া পদ্ধতি শেখার পরেও এটি লাগে। Unsorted input নেয়, preparation নেই, প্রথম match-এ থামে। ছোট attendance list-এ আগে sort লাগা ভালো asymptotic bound-এর চেয়ে এগুলো বেশি কাজে লাগতে পারে।

সিউডোকোড ও ব্যবহারের নিয়ম

for i = 0 to n - 1
    if a[i] == target: return i
return -1

ধাপে ধাপে বোঝো

Match-এর অর্থ আগে বলো

এখানে target-এর প্রথম zero-based position ফেরাবে, না থাকলে -1। শুধু yes/no-এর চেয়ে position কাজে লাগে; caller record পড়তে বা বদলাতে পারে। Zero বৈধ success, failure-ও হতে পারে না।

a=[7,3,5,3,1],target=5-এ 7,3,5 দেখে 2 ফেরে; শেষ দুইটি পড়ে না। Target 3-এ প্রথম index 1, পরে 3 থাকলেও। Target 9-এ পাঁচ comparison ব্যর্থ, -1।

Input array বদলায় না। Equality ব্যর্থ হলে index এক বাড়ে। এগোনোর আগে test করো, নইলে প্রথম মান বাদ যাবে। i<n প্রতিটি read রক্ষা করে। Empty-তে a[0] না পড়েই -1।

নিজের storage থাকলেই sentinel

Sentinel এমন extra stopping value যেখানে scan পৌঁছাবেই। এখানে caller n data value-এর বাইরে একটি writable cell রাখে। a[n]=target বসিয়ে equality পর্যন্ত scan। Inner loop-এ প্রতিবার length check লাগে না।

এখন target পাওয়া নিশ্চিত, data-র ভেতরে পাওয়া নয়। শেষে i<n হলেই i ফেরাও। i=n হলে শুধু sentinel, আসল target absent। Empty-তেও a[0] reserved writable cell চাই। Storage-হীন pointer এই variant-এ চলে না।

আরেক বইয়ের version শেষ real element বদলায়। পুরোনো মান save-restore করে genuine last match ও temporary sentinel আলাদা করতে হয়। Extra-slot version-এ সেই restore লাগে না। দুটোতেই cell লেখার অধিকার চাই; normal n-element array-এর বাইরে লেখার ছাড় নয়।

প্রথম, শেষ ও সব match

Result contract বদলালে stopping rule বদলায়। First-match প্রথম equality-তে ফেরে। Last-match প্রতিটি index মনে রেখে শেষ পর্যন্ত যায়। Counting-এ প্রতিটি equality-তে counter, পুরো scan। All occurrence চাইলে early return নয়।

Record search-এ চাওয়া field তুলনা করো। Roll search roll, marks search mark দেখে। সমান mark ভিন্ন student-এর হতে পারে, unique record চেনে না। সব matching student চাইলে সব position ফেরাও বা print করো।

একটি করে input এলেও linear search চলে; পরের value-তে random access লাগে না। Linked structure-এ next node একই scan। Advance storage অনুযায়ী বদলায়, rejected prefix-এর invariant থাকে।

কখন scan-ই ভালো পছন্দ

Unsorted list-এ একটি query-তে সর্বোচ্চ n comparison। আগে sorting সাধারণত এক scan-এর চেয়ে বেশি। একই collection-এ অনেক query হলে ordered preparation কাজে লাগতে পারে। তুলনায় preparation-ও ধরো, শুধু পরের search নয়।

ঘন ঘন চাওয়া item সামনে রাখলে practical expected কাজ কমতে পারে। ওই usage pattern-এ লাভ, worst case নয়। Absent target এখনও সব candidate বাদ দিতে বাধ্য করে।

Animation-এ absent ও singleton নাও। Equality ব্যর্থ হওয়ার পরই position বাদ যায় দেখো। Rejected color ওই target-এর evidence, value-এর স্থায়ী পরিচয় নয়। Target বদলালে যুক্তি নতুন করে শুরু।

পদ্ধতিটি কেন সঠিক

i দেখার আগে নিচের কোনো position-এ target নেই। শুরুতে rejected prefix খালি, সত্য। a[i] ভিন্ন হলে i বাড়িয়ে prefix বাড়ে। সমান হলে আগের সবাই ব্যর্থ, তাই প্রথম match। i=n হলে সবাই ব্যর্থ, -1 ঠিক।

প্রতি unsuccessful iteration i বাড়ায়, n fixed; সর্বোচ্চ n data comparison। Sentinel-এ reserved cell target বলে n-এর মধ্যে equality হবেই। শেষে index test real data ও extra stopping cell আলাদা করে।

সময় ও মেমরির হিসাব

Nonempty first match-এ best Θ(1); absent বা last match-এ worst Θ(n)। Successful position uniform হলে expected (n+1)/2, এটিও Θ(n); probability assumption বলতেই হবে। দুই scan-এর working variable Θ(1); sentinel-এ বাড়তি এক writable cell চাই।

প্রচলিত ভুল

Missing result-এ zero নেওয়া

Zero বৈধ match। Missing marker -1 রাখো, returned index স্পষ্ট তুলনা করো।

সব match গোনার আগে return

Count-এ পরের equal value-ও লাগে। Early return সরিয়ে scan শেষ করো।

Reserved নয় এমন sentinel লেখা

n-element array-তে a[n] data cell নেই। n+1 reserve করো বা সাধারণ bounds-checked scan নাও।

C17-এর খুঁটিনাটি

সাধারণ C17 search input বদলায় না বলে const pointer। Sentinel writable storage নেয়, স্পষ্টভাবে extra cell চায়।
