Introduction

You have an unsorted row of roll numbers and want to find one student. There is no reliable way to jump to the correct position. Start at the left and check each roll until you find a match. This method is called linear search.

Linear search is useful even after you learn faster-looking methods. It accepts unsorted input, needs no preparation, and stops as soon as the requested first match appears. For a short attendance list, those advantages can matter more than a better asymptotic bound that requires sorting first.

Pseudocode and conventions

for i = 0 to n - 1
    if a[i] == target: return i
return -1

Linear Search step by step

Decide what a match means

The search contract here returns the first zero-based position whose value equals target. If no such value exists, it returns -1. Returning a position is more useful than returning only yes or no, because the caller can inspect or update that record. Index zero is a valid success, so it cannot also mean failure.

For a = [7,3,5,3,1] and target = 5, the routine checks 7, then 3, then 5. It returns 2 and never examines the final two positions. For target = 3, the first match is at index 1, even though another 3 appears at index 3. For target = 9, all five comparisons fail and the answer is -1.

The input array remains unchanged. The index increases by one after each failed equality. Test equality before moving forward; otherwise the first value could be skipped. The length condition i < n protects each read. An empty array returns -1 without trying to inspect a[0].

Use a sentinel only with owned storage

A sentinel is an extra stopping value placed where a search is guaranteed to meet it. In the sentinel example, the caller reserves one writable cell beyond the n data values. The routine sets a[n] = target and scans until equality. The inner loop no longer needs a length check on each iteration.

Finding target is now guaranteed, but finding it inside the data is not. After the loop, return i only when i < n. If i equals n, the match is the sentinel and the real target is absent. For an empty list, a[0] must still be a reserved writable sentinel cell. A pointer with no storage cannot be used for this variant.

Another textbook version temporarily replaces the last real element. That version must save and restore the old final value, then distinguish a genuine final match from the temporary sentinel. The reserved-extra-slot version avoids that restoration problem. Both versions require ownership or permission to write the chosen cell; neither permits writing past a normal n-element array.

First match, last match and all matches

Changing the result contract changes the stopping rule. A first-match routine returns on the first equality. A last-match routine remembers each matching index and continues to the end. A counting routine increments a counter for every equality and also scans the entire list. You cannot reuse an early return when the question asks for all occurrences.

When searching records, compare the requested field. A roll-number search compares roll numbers; a marks search compares marks. Equal marks can belong to different students, so marks do not identify a unique record. If a task needs every student with a given mark, return or print every matching position rather than assuming uniqueness.

Linear search is also appropriate when input arrives one item at a time. You do not need random access to later values. For a linked structure, moving to the next node fits the same scanning idea. The underlying storage changes how you advance, while the invariant about previously rejected candidates remains useful.

When scanning is the sensible choice

A single query on an unsorted list needs at most n comparisons using linear search. Sorting first typically costs more than this one scan. For many queries on a mostly unchanged collection, preparing an ordered representation may pay off. Include that preparation in the comparison rather than quoting only the later search cost.

Search order can improve practical behaviour when some items are requested more often. Frequently used entries near the front are found sooner. This changes expected work under that usage pattern, but it does not improve the worst case. An absent target still forces every candidate to be rejected.

Why the method is correct

Before testing position i, no position below i contains target. This is initially true because the rejected prefix is empty. If a[i] differs, advancing i extends that rejected prefix by one. If a[i] equals target, all earlier values have already failed, so i is the first matching index. If i reaches n, every value has failed and -1 is correct.

Each unsuccessful iteration increases i while n remains fixed. At most n data comparisons occur. The sentinel loop has a different stopping guarantee: the reserved cell itself equals target, so equality must occur by position n. Its final index check restores the distinction between real data and the extra stopping cell.

Time and space reasoning

Best-case search time is Θ(1) for an immediate first match on a nonempty input. Worst-case time is Θ(n) for absence or a last-position match. If a successful target position is uniformly distributed, expected comparisons are (n + 1)/2, also Θ(n). That average requires an explicit probability assumption. Both ordinary and extra-slot sentinel scans use Θ(1) working variables; the sentinel additionally needs one writable array cell.

Common mistakes

Using zero as the missing result

Position zero is a valid match. Keep -1 as the absent marker and compare the returned index explicitly.

Returning before counting all matches

A count must include later equal values. Remove the early return and finish the scan.

Writing an unreserved sentinel

An array of n elements has no a[n] data cell. Reserve n + 1 cells or use the ordinary bounds-checked scan.

C17 details

The C17 search uses a const-qualified input pointer because ordinary scanning does not modify data. The sentinel variant instead accepts writable storage and explicitly requires one extra cell.

Summary

Scan for a first match, analyse failed searches, and use a sentinel only with valid writable storage.
