Introduction

When you read a road sign before a junction, the destination may already be clear even if its exact position on a map is not. A compiler faces a similar situation when it emits a forward jump. It knows why the jump is needed, but may not yet know which instruction number will become the destination.

Backpatching records these unfinished jumps and fills their targets later. The technique is especially useful for Boolean expressions, if statements and loops. It keeps instruction generation moving forwards while allowing branch destinations to be discovered as more code is emitted.

A Boolean expression can produce a stored true/false value, or it can directly choose between two control paths. This lesson uses the second form. An expression B has a truelist and a falselist: lists of instruction indices whose targets are still unknown. These are lists of jump locations, not lists of possible numeric truth values.

Complete translations

A relational expression

For a relation a < b, emit a conditional jump and an unconditional false jump. The target blanks are deliberate until the surrounding statement supplies destinations. nextinstr means the index that will be assigned to the next emitted instruction.

Use makelist(i) to create a one-element list. Merge combines two lists without changing the emitted instructions. Backpatch(list, target) writes that target into every instruction named by the list. Apply backpatch only while those targets are unresolved, so accidental double patching cannot silently redirect a completed branch.

Short-circuit AND and OR

For B1 AND B2, evaluate B2 only when B1 is true. Patch B1.truelist to the first instruction of B2. The combined true list is B2.truelist. False can arise from either operand, so merge both false lists.

For B1 OR B2, evaluate B2 only when B1 is false. Patch B1.falselist to the beginning of B2. Merge both true lists, and keep B2.falselist as the combined false list. A logical NOT swaps the true and false lists without emitting an arithmetic negation.

Consider a < b AND c < d. The first true jump must enter the second comparison, while its false jump must skip it. This matters if the second operand has an effect or is unsafe unless the first condition succeeds, such as an array access protected by a bounds condition.

If and else with a join

The print operation is included to give the join a concrete instruction index. Some intermediate formats allow a label just past the last instruction. Others require an explicit exit block. State your convention instead of treating an out-of-range jump as an ordinary instruction index.

While with a backward edge

Translate while (i<n) i=i+1; print i;. Save the condition's start before emitting its comparisons. Patch the true list to the body and the false list to the loop exit. After the body, emit a backward jump to the saved condition start.

The backward jump targets the condition, not the body. Otherwise a true first test would make the loop repeat without checking i<n again. Zero iterations are possible: if the condition is initially false, control reaches instruction 5 without executing the update.

Composing statement sequences

A statement's nextlist contains unfinished jumps that should continue after that statement. For S1 followed by S2, patch S1.nextlist to start(S2). S2.nextlist then becomes the sequence's remaining nextlist. A statement that naturally falls through does not need an artificial jump merely to have a nextlist.

A break statement creates an exit for the nearest enclosing loop, not for every enclosing conditional. A continue statement targets that loop's next test or update according to the source construct. Maintain a loop-context stack if you extend the translator with these statements. Nested loops require separate exit lists.

Checking generated branches

To trace a condition, keep an instruction pointer and evaluate only the comparisons reached. For a=1, b=2, c=7, d=4, the AND conditional visits 0,2,3,6,7. It never executes instruction 4. For a=3 and b=2, it visits 0,1,6,7 and does not inspect c or d at all.

For the while example with i=1 and n=3, the visited instruction sequence is 0,2,3,4,0,2,3,4,0,1,5. The body executes twice, updating i to 2 and then 3. The final false branch is essential even though it performs no arithmetic itself.

A useful invariant during generation is that each unresolved branch occurs in the correct pending list. After patching a complete function, no blank target should remain. Every destination must refer to a valid instruction or a defined exit label. These structural checks find errors before executing a particular input path.

It helps to keep the generated instruction array separate from the pending lists. The array owns each branch record, and a list stores references or indices into that array. Once a list is patched, do not reuse it as a fresh unresolved list. If several grammar attributes share one list object, accidental mutation can redirect branches belonging to another construct.

A marker for the beginning of B2 must be saved before B2 emits its first instruction. Saving nextinstr afterwards would point beyond the comparison, skipping the decision that the first operand was supposed to reach. This is a frequent off-by-one mistake in handwritten translations. Write the marker value beside the code boundary before filling any list equation.

Backpatching is not machine branch relocation. This technique completes intermediate control-flow targets while constructing code. An assembler or linker may later adjust encoded addresses after layout. Both deal with destinations, but they operate at different representations and stages.

List merging can be efficient if lists are represented with tail pointers or another structure that avoids repeatedly copying long prefixes. A naive repeated list concatenation can become costly for a long Boolean chain. The classroom equations specify the logical contents; an implementation must also choose appropriate data structures.

Common mistakes

Patching the wrong side of OR

For OR, a false first operand leads to the second operand. Patching the first true list instead reverses the short-circuit decision. Write one concrete truth case before choosing the list equation.

Forgetting the jump around else

Without the skip jump, a successful then branch falls into the else assignment and overwrites its result. Add the unfinished skip jump before emitting else, then patch it at the join.

Rechecking only the body

A loop back edge must return to the condition's beginning. Returning to the first body instruction skips future tests. Trace both zero iterations and at least two iterations to expose this mistake.

Confusing pending exits with all branch instructions

Once a jump has a target, remove it from the unfinished obligation represented by the enclosing result lists. Keeping it in another pending list invites an incorrect later patch and hides which destinations are still missing.

Summary

Backpatching connects incomplete branches to destinations discovered later. True and false lists encode short-circuit choices; next lists connect statement continuations. Complete every pending target, then use basic blocks and flow graphs to inspect the resulting paths.
