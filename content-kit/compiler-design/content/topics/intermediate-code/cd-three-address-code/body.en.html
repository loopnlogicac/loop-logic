Introduction

A complicated arithmetic expression is easier to inspect when every line does one small job. Three-address code, usually called TAC, uses instructions such as t1 = bonus * 2. Two operands and one result give the familiar three-address form. Some instructions use fewer addresses, including copies, unary operations and jumps.

A compiler uses TAC as an intermediate representation between source syntax and machine instructions. Source expressions can be deeply nested. Machine instructions depend on a particular target. TAC exposes values and control flow while delaying many target decisions, so optimisation can work on a clearer common language.

For a fee calculation, base + rate * units becomes a multiplication followed by an addition. The temporary names hold intermediate results. A temporary is a compiler-created value name, not a promise that the target has a separate physical register for every such name.

Instruction forms and representations

Quadruples, triples and indirect triples

A quadruple stores operator, first operand, second operand and result. A triple stores operator and operands, referring to earlier results by instruction index. An indirect-triple representation keeps a separate list of pointers to triple records, allowing scheduling changes without moving those records.

Generate instructions from a tree

Postorder generation

Generate the left child, generate the right child, then emit their parent's operation. A number or identifier leaf returns its own spelling without emitting an arithmetic instruction. An internal node creates a fresh temporary and returns that name to its parent.

The invariant is useful: when emit returns a name, that name already denotes the value of the subtree. A leaf satisfies the invariant immediately. For an internal node, both child results exist before its new instruction runs. Therefore the parent instruction computes the correct subtree value under the language's evaluation rules.

For a tree with n nodes, ordinary postorder generation takes O(n) work and emits at most one arithmetic instruction per internal node. The implementation first gathers identifier names so fresh temporaries cannot collide with names such as t1. Its recursion uses space proportional to tree height, in addition to the instruction list.

Unary minus and assignment

For -(a + b) * c, first emit addition, then a unary negation, then multiplication. Represent a unary operation with one operand and an unused second-operand field. Do not change negation into subtraction with a missing left operand.

The expression generator does not parse assignments. It returns an operand for the final expression value; a surrounding statement translator could then append the copy row. Keeping those jobs separate makes it easier to add assignments without changing the meaning of arithmetic nodes.

Repeated expressions are still repeated

For (a + b) * (a + b), the plain AST generator emits two additions. Those are two distinct internal nodes. Recognising and sharing the repeated computation is a later optimisation, which needs evidence that the operands have not changed and the operations have no relevant effects.

Do not silently turn this into t2 = t1 * t1 when explaining an AST-only traversal. That shorter result comes from a DAG or common-subexpression analysis. It is a useful next step, but a different algorithm from the generator demonstrated here.

Scheduling safely

Independent operations may be reordered if the source rules permit it. For (a+b) * (c-d), the addition and subtraction do not use each other's results. Either can be scheduled first. Multiplication must remain after both producers. An indirect execution list makes such legal movement convenient, but does not decide legality for you.

If either operand involves a function call, memory write, exception, or volatile access, extra ordering constraints may apply. Our arithmetic examples have no such effects and use integer mathematics. A production compiler carries effect and type information alongside intermediate instructions when that information controls a transformation.

Respect arithmetic precedence

The first program generates code for a + b * c - d. Multiplication appears first because it belongs to the deeper subtree. Subtraction appears last because the parser groups addition and subtraction from left to right.

Read each temporary as a value defined exactly once in this expression. Later instructions use that value name. The final result line identifies the returned operand; it is a display convention rather than an extra TAC arithmetic instruction.

Generate unary instructions

The second program shows negation after its child addition. The generator returns the negation temporary to multiplication. This demonstrates why the AST needs a separate unary operation instead of relying on token position later.

The second operand printed as a dash in quadruple form means unused. A literal minus sign in source is instead an operator token. Representation conventions must keep those two meanings distinguishable.

Avoid temporary collisions

The third expression already contains source names t1 and t2. The generator reserves those spellings before allocating temporaries, so the new result begins at t3. Reusing t1 would incorrectly overwrite an input value.

Temporary numbering is local to one generator call. A whole-function compiler would keep a shared allocator across its statements, or use separate internal identities that cannot clash with user names. Printed names are only the readable surface of those identities.

Common mistakes

Scanning tokens instead of using the parse tree

Emitting operations in textual order gives addition before multiplication for a + b * c. Parse precedence first. Then generate from the tree whose grouping already matches the source language.

Moving triple records without repairing references

A triple operand such as (0) refers to a particular produced value. Renumbering the producer without updating its users changes the program. Stable records plus an indirect execution list avoid that specific bookkeeping problem.

Treating every TAC row as exactly three operands

A copy has one input. Negation is unary. A conditional branch uses a condition and a target. Three-address code names a family of small instruction forms rather than a requirement that every row fill three operand slots.

Python generator notes

The Python generator shares its scanner and AST representation with the earlier evaluator. It uses no Python evaluation of source text. Inputs longer than 100 characters or deeper than 30 nested operations are outside the practice limits. The generated arithmetic subset omits division, assignment parsing, memory access and function calls.

Summary

TAC makes expression dependencies explicit through small operations and intermediate results. Preserve grouping, generate operands before their users, and choose a representation whose references remain valid when instructions move. Next, compare an AST with a shared expression DAG.
