Introduction

At a road junction, several routes can bring you to the same place. A compiler faces the same uncertainty at a block with several predecessors. Which assignment could have supplied the current value of x? Will another instruction need that value later? Data-flow analysis answers such questions by propagating facts along a control-flow graph.

A fact may describe an earlier definition or a future use. The analysis associates sets with block boundaries, then repeatedly updates those sets until a whole round makes no change. This stable result is a fixed point. It handles loops without pretending that one textual scan sees every possible path.

We study two may analyses. Reaching definitions asks which assignments may reach a point. Live variables asks which values may be needed along some future path. Union is the merge operation because either incoming possibility matters. A may result is conservative: a listed possibility need not occur on every actual execution.

For reaching definitions, a definition reaches a point if some path brings it there without another assignment to the same variable. GEN[B] contains definitions from B that survive to its exit. KILL[B] contains other definitions of variables assigned in B. If a block assigns x twice, only the final assignment to x belongs in GEN.

Live variables on the same graph

A variable is live at a point when some path uses its current value before redefining it. USE[B] lists variables read before any local definition. DEF[B] lists variables assigned in B. The return z in B3 does not put z in USE[B3], because B3 defines z before reading it.

The backward equations are OUT[B] = union of IN[S] over successors S, and IN[B] = USE[B] union (OUT[B] minus DEF[B]). Give the exit an empty live set here, because return has already been represented inside B3. External observable memory would need an appropriate boundary or effect model.

At L1 entry, the initial definitions can arrive on the first iteration and the body definitions can arrive on a later iteration. A single forward textual pass that ignores the back edge misses the second possibility. Fixed-point iteration combines both without enumerating every iteration count.

Iteration, convergence and meaning

Start with the smallest sets for these may analyses. Apply the transfer equations and unions repeatedly. Facts only accumulate in the boundary solution as information travels through the graph. Each universe is finite: reaching definitions has finitely many labelled assignments, and liveness has finitely many variable names.

Monotone transfer functions preserve set inclusion. With a finite set universe and bottom initialisation, iteration must eventually stop growing. The result is the least fixed point for the chosen equations and boundary conditions. This is a statement about the analysis model, not a promise that all source paths are actually executable.

A block with two assignments to the same variable illustrates local preprocessing. For d6: x=1 followed by d7: x=2, only d7 can leave the block. A use of x between those assignments would still depend on d6 inside the block, but that does not put d6 in the block-exit GEN set. Block boundary facts and instruction-level facts answer different questions.

For liveness, scan statements backwards inside a block to refine boundary information. Starting from its OUT set, remove the destination of an assignment and add the variables read by its right-hand side. For x=x+1, removing x and then adding the right-side x keeps its incoming value live. Removing x after adding uses would incorrectly erase that dependency. The order follows the assignment's read-before-write behaviour.

A worklist implementation avoids revisiting unrelated blocks. For a forward analysis, when OUT[B] changes, schedule B's successors. For a backward analysis, when IN[B] changes, schedule B's predecessors. Recompute a block until its neighbours' latest facts no longer change its result. Always include a change test or a correct termination mechanism.

The graph normally overapproximates control flow. For example, a comparison that is always false might still have both outgoing edges until constant analysis removes one. Union therefore reports definitions and uses along structurally possible paths that may be infeasible for real values. Conservatism keeps transformations safe but can leave optimisation opportunities unused.

Reaching definitions supports use-definition chains and propagation decisions. Live variables supports dead-assignment removal and register allocation. Neither analysis alone decides every transformation: memory effects, types, exceptions and language semantics provide additional constraints. These sets are evidence for a decision, rather than an automatic instruction to delete code.

Checking a proposed fixed point

To verify a final table, recompute every IN from its graph neighbours and every OUT from its local transfer, or reverse those roles for liveness. Check the boundary separately. A table is not justified by the words no change unless the displayed sets actually satisfy all equations.

For B3 in the diamond, union({d2,d3},{d1,d4}) gives {d1,d2,d3,d4}. Adding GEN {d5} with no kills gives its displayed OUT. For liveness at B1, OUT {x,y} minus DEF {x} leaves {y}; union USE {y} still gives {y}. These small substitutions connect the equations to the completed tables.

Common mistakes

Mixing forward and backward neighbours

Reaching definitions takes information from predecessors. Liveness takes information from successors. Draw the direction beside the equations before filling a table, especially when the graph has a loop.

Putting every assignment into GEN

If x is assigned twice in one block, the earlier definition cannot reach that block's exit. Scan the block with overwrites in mind. GEN contains the final local definitions for each assigned variable.

Counting a locally defined return value as an incoming use

In B3, z is defined before return z. It is live between those two instructions but does not need an incoming value at B3 entry. USE records reads before local definition, not every read anywhere in the block.

Stopping after the first loop visit

A back edge can bring a fact discovered later back to an earlier block. Continue until no relevant boundary set changes. A stable result must satisfy all neighbour and transfer equations simultaneously.

Summary

Data-flow analysis propagates local facts through graph edges until their boundary sets stabilise. Reaching definitions moves forward; live variables moves backward. Preserve the stated boundary conditions and use the fixed-point facts when planning instruction selection and register allocation.
