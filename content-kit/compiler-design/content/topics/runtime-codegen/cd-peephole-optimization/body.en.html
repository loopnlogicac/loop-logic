Introduction

After generating target code, a compiler may notice a small awkward sequence that was difficult to avoid earlier. It might store a register value and immediately load the same value back. Peephole optimisation examines a short instruction window and replaces it with an equivalent, usually cheaper sequence.

Think of proofreading a few neighbouring words rather than rewriting an entire chapter. The window makes patterns easy to recognise, but it does not make outside context irrelevant. A register value, condition flag or branch label can be used beyond the window. A safe replacement must account for that live context.

Use ordinary non-volatile memory and the stated integer machine unless a worked case says otherwise. Loads and stores have no hidden device effects in this model. Real target rules may make a similar-looking sequence unsafe, so the assumptions travel with each rewrite.

Short-window rewrites

Remove a redundant reload

Consider LD R0,a; ST b,R0; LD R0,b. After the store, b contains the same value already in R0. The final load changes nothing if no intervening operation modifies b and a repeated load has no required side effect.

The shortened sequence retains steps 1 and 2. It still writes b and leaves R0 holding 7. Removing the store as well would require separate proof that b's updated memory value is never needed. Do not confuse a redundant reload with a dead store.

A store overwritten before any read

Now inspect ST a,R0; ST a,R1. If these are ordinary stores to exactly the same location and no intervening observer can see the first value, the first store is dead. The second store supplies the only value that remains afterwards.

An unknown alias can prevent a redundant-load rewrite too. For LD R0,[p]; ST [q],R1; LD R0,[p], the store may change the next loaded value if p and q alias. Memory independence must be proven rather than guessed from different pointer spellings.

Algebraic simplification with flags

For mathematical integers, adding zero preserves the numeric value and multiplying by one preserves it as well. Removing the target instruction is safe only if its other effects are irrelevant. Some machine arithmetic instructions set condition flags that a later branch reads.

Suppose ADD R0,0 is followed by a branch testing its zero flag. Removing ADD would let the branch read an older flag value. R0's numeric value staying unchanged does not preserve the branch's behaviour. Treat flags as live data dependencies, much like registers.

Redirect a jump chain

Let instruction 0 jump to L1, and let L1 contain only an unconditional jump to L2. Redirect instruction 0 to L2 when entering L1 performs no required work before that jump. This shortens a path without deleting the L1 label that other instructions may still target.

A chain can contain a cycle, such as L1→L2→L1. A chain-following implementation needs a visited set to avoid looping during optimisation. It must not invent an exit destination for a nonterminating cycle. Following labels is a graph operation even when the visible pattern is small.

Remove jump to the next instruction

If JMP Lnext is immediately followed by label Lnext, normal fallthrough reaches the same destination. The jump can be removed when it has no separately required effect. Retain the label because other branches might use it.

The conditional inversion pattern also requires arranging the then and else regions so fallthrough enters the intended branch, with any needed join jump retained. The complement a≥b is valid for the stated integer order. Floating comparisons involving NaN do not obey every ordinary complement identity, so target predicates must be chosen carefully.

Window context and repeated passes

A peephole pass matches a pattern, checks its preconditions and performs the replacement. Then it may look again near the changed region because the rewrite can expose another pattern. For example, redirecting a jump chain may produce a jump to the immediately following label, which can then be removed.

Keep a clear termination policy. Rewrites that always reduce a cost measure, such as instruction count plus a bounded jump-chain measure, are easier to reason about than rules that can undo one another. Two equally valid rewrites pointing in opposite directions can cause an endless optimisation loop unless the pass orders or restricts them.

A window can cross a block boundary only when the control-flow context is understood. If a label inside the window has another incoming edge, deleting or moving its instruction may affect a path that does not execute the window's first instruction. This is why basic-block boundaries and predecessor information remain useful even during local cleanup.

Check outputs, final live registers, live flags and required memory effects when comparing before and after. Dead registers may differ harmlessly, but live ones must preserve the values their later users expect. The same idea applies to exception behaviour whenever the language or target makes it observable.

Common mistakes

Deleting the store while removing its reload

The reload may be redundant because the register already has the value, while the memory write remains necessary. Analyse register and memory destinations separately. A shorter sequence that loses a needed memory update is wrong.

Ignoring labels in the middle of a pattern

An external jump can enter halfway through a proposed replacement. The pattern's initial register assumptions may then be false. Preserve all legal entry paths, or limit the rewrite to a region with a single entry.

Applying arithmetic identities without flag liveness

ADD by zero can preserve a number while changing condition flags. A following branch may depend on those flags. Remove the instruction only after proving the flags are dead or arranging an equivalent flag result.

Calling a target-specific pattern universal

A machine may provide an increment instruction, memory operand or special zero register that another lacks. A peephole rule must name the target semantics it relies on. Portability of the optimisation idea does not imply identical replacement instructions.

Summary

Peephole optimisation improves short target sequences when their context proves the replacement equivalent. Preserve live registers, memory, flags, labels and required effects. You can now combine the full pipeline in a calculator compiler or practise the worked exam problems.
