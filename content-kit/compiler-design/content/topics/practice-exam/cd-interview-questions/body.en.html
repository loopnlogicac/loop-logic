Introduction

Use these forty questions to practise explaining a compiler clearly in your own words. Start with a short definition, then give the distinction or condition that matters. A confident answer should also recognise the limits of its claim, such as the difference between a source-language rule and Python's behaviour.

Try answering before uncovering the explanation. For a follow-up, invent a small example that would expose the mistake named in the answer. A useful interview explanation combines the general idea with one concrete consequence, rather than reciting a term without knowing when it applies.

Forty short questions and answers

1. Compiler or interpreter?

What distinguishes compilation from interpretation?

Compilation produces another representation for later execution or processing. Interpretation executes a representation directly. A system can combine both, for example by compiling source to bytecode and interpreting that bytecode.

2. Translator and assembler

Where does an assembler fit among translators?

A translator converts one program representation into another. An assembler translates assembly language into machine-code objects, including relocation information when needed. It is more specialised than a high-level language compiler.

3. Front end and back end

Why separate a compiler front end from its back end?

The front end understands source syntax and meaning. The back end targets a machine or another execution format. A common intermediate representation can connect several source languages to several targets.

4. Token versus lexeme

How do a token kind and a lexeme differ?

A token kind is a category such as identifier or integer. A lexeme is the actual source spelling, such as marks or 42. A token record may also contain a value and source position.

5. Longest match

What does maximal munch mean in a lexer?

Prefer the longest source prefix that matches a token rule. If equally long rules match, use the language's stated priority. Recognising a keyword versus an identifier still needs that tie-breaking policy.

6. DFA versus NFA

How do deterministic and nondeterministic automata differ?

A DFA has one next state per state and input symbol in a complete table. An NFA can have several possible next states and epsilon moves. Subset construction represents sets of NFA states as DFA states.

7. Epsilon closure

Why apply epsilon closure during subset construction?

Epsilon moves consume no input. The active NFA set must include all states reachable by those moves before and after consuming a symbol. Omitting closure can lose valid accepting paths.

8. Minimisation

When are two DFA states equivalent?

They agree on acceptance for every possible remaining input suffix. Matching only their current accepting status is insufficient. Partition refinement repeatedly separates states whose transitions lead to distinguishable groups.

9. Regular expressions and nesting

Why is ordinary balanced-parenthesis syntax not a lexer regex job?

Arbitrarily deep balanced nesting requires remembering an unbounded nesting count. Finite automata have only finitely many states. A context-free grammar and parser naturally represent that recursive structure.

10. Input buffering

Why does a lexer buffer input?

Buffering reduces repeated low-level reads and supports lookahead across token boundaries. The lexer must still handle a token that crosses a buffer boundary. Buffer organisation must not change token meaning.

11. Grammar ambiguity

What makes a context-free grammar ambiguous?

Some string in its language has more than one parse tree, or equivalently more than one leftmost derivation. Two arbitrary derivation orders do not prove ambiguity if they describe the same tree. Grouping choices must differ.

12. Left recursion

Why does direct left recursion trouble a naive recursive-descent parser?

The parser calls the same nonterminal again before consuming input. This can recurse indefinitely. Rewrite the grammar or use a parsing strategy designed to handle left recursion.

13. Left factoring

What does left factoring solve?

It postpones a choice shared by alternatives with a common prefix. The parser consumes the common part before choosing a suffix. Factoring alone does not guarantee an unambiguous or LL(1) grammar.

14. FIRST versus FOLLOW

What is the difference between FIRST and FOLLOW?

FIRST describes terminals that can begin strings derived from a symbol or sequence. FOLLOW describes terminals that can appear immediately after a nonterminal in a sentential form. Epsilon can be in FIRST but is not an input symbol in FOLLOW.

15. LL(1) conflict

What does a collision in a predictive table cell mean?

The same nonterminal and lookahead select more than one production. The table cannot make a unique LL(1) decision. Keep the conflicting candidates visible instead of arbitrarily choosing one.

16. Recursive descent

Why use one parsing function per nonterminal?

The function mirrors the nonterminal's alternatives and returns its recognised structure or value. This makes precedence levels visible in call structure. Complete recognition still requires checking the remaining input.

17. Handle

What is a handle in bottom-up parsing?

It is a production occurrence whose reduction reverses one step of a rightmost derivation. Not every substring matching a right side is the correct handle. The parser state and context determine the valid reduction.

18. Shift-reduce conflict

What is a shift-reduce conflict?

One parser-table cell permits both consuming the lookahead and reducing a recognised right side. The conflict can reflect ambiguity or limitations of the table construction. A stated precedence policy may resolve some such conflicts.

19. LR closure

What does closure add to an LR item set?

When the dot precedes a nonterminal, closure adds items beginning its productions. Repeat until no new items appear. LR(1) closure also computes appropriate lookaheads from the remaining suffix and parent lookahead.

20. SLR lookaheads

How does SLR decide where to place a reduction?

It uses FOLLOW of the completed production's left-side nonterminal. LR(0) would place that reduction on every terminal. LR(1) carries more precise lookahead information in its items.

21. LALR merging

What must match before CLR states are merged for LALR?

Their LR(0) cores must be equal. Corresponding item lookaheads are united. This can introduce reduce-reduce conflicts even when the original CLR table had none.

22. Error recovery

What is panic-mode parser recovery?

Skip input until a synchronising token such as a semicolon or closing delimiter is found. Then resume at a suitable grammar boundary. Recovery helps report later errors but does not make the damaged statement valid.

23. Semantic errors

Can a syntactically valid program still be rejected?

Yes. An undeclared name or incompatible operand types can violate semantic rules despite valid grammar. Parsing and semantic analysis answer different questions.

24. Attribute direction

How do synthesised and inherited attributes differ?

Synthesised information is computed from children or local information. Inherited information supplies context from the parent and permitted neighbouring occurrences. Dependency constraints determine a valid evaluation schedule.

25. S and L attribution

Is every S-attributed definition L-attributed?

Yes. With only synthesised attributes, there are no inherited dependencies that violate the L-attributed restriction. The reverse is false because L-attributed definitions can pass context downwards.

26. Static and dynamic checking

Does static typing remove every runtime check?

No. A runtime array index can have type int while still being out of bounds. Static types and value-dependent safety checks address different properties.

27. Coercion versus cast

How does implicit coercion differ from an explicit cast?

A coercion is inserted according to language rules without a programmer-written conversion expression. A cast requests a conversion in source. Neither description alone guarantees freedom from range loss or rounding.

28. Scope versus lifetime

How do scope and lifetime differ?

Scope describes where a name can denote a declaration in source. Lifetime describes when an object exists during execution. A captured object can outlive the block in which its original name was visible.

29. Symbol tables

Why search nested symbol tables from inside out?

The nearest visible lexical declaration should win. Searching outside first defeats legal shadowing. Same-scope duplicate checks still examine only the current declaration table.

30. TAC representations

Why might quadruples be easier to reorder than ordinary triples?

Quadruple operands name explicit results rather than instruction positions. Moving a triple record can require repairing positional references. Indirect triples use a separate execution list to keep record identities stable.

31. AST versus DAG

What extra fact does a shared expression DAG express?

Several uses can refer to one equivalent computed value. Safe sharing requires unchanged operands and compatible effects. A plain AST records separate occurrences even when their text looks identical.

32. Backpatching

What does backpatching store before a target is known?

It stores indices of unfinished jumps in pending lists. When a destination is reached, those instruction targets are filled. The list contains branch locations rather than target values guessed in advance.

33. Short circuit

Why can eager evaluation change an AND expression?

Short-circuit AND skips its second operand when the first is false. Evaluating both can trigger an effect or failure that should not happen. The same control distinction matters for OR when its first operand is true.

34. Activation records

Why does recursion require separate activation records?

Each active invocation needs its own arguments, locals and return state. Sharing one local storage set would overwrite earlier calls. Records are normally unwound in reverse call order.

35. Reference and value

Does passing a pointer by value mean passing the caller variable by reference?

No. The pointer value is copied into a local parameter. The callee may modify the referenced object, but rebinding its local pointer does not rebind the caller's pointer variable.

36. Basic blocks

What are the standard leader locations?

Function entry, branch targets and instructions immediately after control transfers when present. Splitting at all these positions creates straight-line regions. Reachability is analysed separately after partitioning.

37. Reaching definitions

What question does reaching-definition analysis answer?

Which assignments may supply values at a program point without an intervening overwrite. It propagates forward and merges possibilities by union. Different assignments to the same variable need different definition identities.

38. Liveness

Why is live-variable analysis backward?

A value is needed because a future use may read it before redefinition. Successor needs therefore propagate towards predecessors. A locally defined value need not be live at block entry.

39. Register spills

What is a register spill?

Saving a live register value in memory allows that register to hold another value. The saved value must remain available to future uses. Target operand forms determine whether a separate reload is needed.

40. Peephole safety

Why can deleting ADD R,0 be wrong even for integers?

Although the register value is unchanged, the instruction may set condition flags. A later branch could read those flags. Delete it only when all relevant effects are preserved or dead.

Summary

A useful compiler explanation names the representation, describes the rule and gives its consequences. Revisit the worked numerical questions when you need to turn an explanation into a complete table or trace.
