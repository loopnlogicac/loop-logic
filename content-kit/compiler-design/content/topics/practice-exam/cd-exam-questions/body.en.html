Introduction

A compiler-design numerical is easier when you separate its jobs. First state the grammar or machine. Then name your conventions, build the table, and trace one input using that exact table. A correct final answer is more convincing when another student can reproduce every intermediate step.

This question set uses small complete examples so you can practise the whole method rather than stop halfway through a large construction. Cover the solution while working. Compare your intermediate sets before comparing the final accept or reject decision. State numbering can differ, but states with the same items and corresponding transitions represent the same construction.

For a timed practice session, spend about ten minutes each on the predictive and bottom-up constructions. Reserve another ten minutes for automata and intermediate code. If a cell contains two actions, retain the conflict and explain it; choosing one silently is not a valid parser construction.

Ten worked exam problems

FIRST and FOLLOW from a nullable prefix

Question 1. For S → A a and A → b | ε, compute nullable, FIRST and FOLLOW. Start with FIRST of terminals as themselves. A is nullable through its empty production. S is not nullable because terminal a remains after A.

Fixed-point facts for the nullable-prefix grammar
SymbolNullable?FIRSTFOLLOW
SNo{a,b}{$}
AYes{b,ε}{a}

FIRST(S) receives b from A and a because A can disappear. FOLLOW(A) receives a from the suffix in S→A a. Only the start symbol receives $ directly. There is no nullable suffix after A, so $ does not propagate to A.

The start subset is epsilon-closure({q0})={q0,q1}. Each transition takes move on its symbol, then epsilon-closure of the result. Include D so every DFA transition is defined. The accepting test is membership of q2 in the subset, not whether the subset contains the NFA start.

For aab, the state path is A,B,B,C and the word is accepted. For aa, it ends in B and is rejected. For bb, it reaches C after the first b but then moves to D, so early acceptance cannot replace checking the complete word.

Generate TAC and representation fields

Question 7. Translate (p-q)*(r+s) without algebraic optimisation. Generate each child before its multiplication parent. The result temporary t3 can then be copied to a surrounding assignment's destination if the source statement has one.

TAC, quadruples and triple references
IndexTACQuadruple (op,arg1,arg2,result)Triple (op,arg1,arg2)
0t1 = p - q(-,p,q,t1)(-,p,q)
1t2 = r + s(+,r,s,t2)(+,r,s)
2t3 = t1 * t2(*,t1,t2,t3)(*,(0),(1))

This representation preserves subtraction order. Exchanging p and q would change the result. A triple's (0) names the value of record 0, whereas a quadruple uses t1 explicitly.

Complete a forward branch

Question 8. Translate if (marks<40) result=0; result=result+1;. This conditional has no else branch. Its false path must join immediately after the then assignment, where both paths execute the increment.

If-without-else backpatch answer

0if marks < 40 goto 2True list [0] patched to then

For marks=30, the assignment sets result to zero before incrementing it to one. For marks=70, the old result is incremented directly. The continuation therefore needs an existing result value on the false path; whether that value was initialised is a separate semantic question.

Summary

For numerical answers, show the construction that justifies the result: sets before tables, states before actions, and branch targets before path traces. After solving these examples on paper, use the calculator project to connect source scanning, parsing, evaluation and TAC generation.
