Introduction

Build a calculator that explains an expression as well as evaluating it. Given 8-3*2, it should recognise the tokens, build the intended grouping, compute 2, and generate multiplication before subtraction. This project connects the earlier compiler phases into one small, inspectable pipeline.

The source language has ASCII integer literals, ASCII identifiers, parentheses, unary minus, and the binary operators +, - and *. Whitespace separates tokens when needed and does not otherwise change meaning. Division, decimal literals, assignment statements and function calls are not part of this version. Identifier values come from an explicit environment rather than from hidden input evaluation.

The compiler produces TAC rather than native machine code. Its evaluator is a separate consumer of the same AST. Comparing the evaluator's result with an execution of the generated TAC is a useful way to check whether the translation preserves meaning.

Language and phase contracts

For 10-3-2, left folding builds (10-3)-2 and gives 5. A right-recursive subtraction implementation would give 9 instead. Unary minus binds more tightly than multiplication, while parentheses override the ordinary grouping.

Token positions are one-based line and character column. A tab counts as one character, not a visual tab-stop width. The scanner accepts whitespace including newlines. The parser requires the end marker after its expression, so it rejects 2 3 rather than returning the first number and ignoring the rest.

AST and temporary decisions

Each AST node records an operation, an optional leaf spelling and a tuple of children. Negation has one child; binary arithmetic has two. Parentheses do not need their own node because grouping is already in the shape. Generate code in postorder and reserve all source identifier spellings before naming temporaries.

The evaluator does not execute generated Python source. It follows the known AST operation tags. The generator likewise emits only the small TAC instruction set. This keeps the supported language explicit and prevents an arithmetic input from becoming arbitrary host-language code.

Complete programs

Compile a numeric expression

The first standalone program prints tokens, AST, value and TAC for 8-3*2. Read the AST before looking at the value. The product node must be the right child of subtraction, matching the grammar's precedence.

The TAC display ends with result = t2. That line names the final operand for a later statement translator or interpreter. It is not a third arithmetic operation.

Compile an expression with a known name

The second program supplies marks=40 in an environment. Evaluation of marks+2*5 gives 50. TAC preserves the identifier marks as an input operand, because code generation does not replace every name with the evaluator's current value.

This distinction matters if you compile the expression once and run it later with different marks. Constant propagation would need a separate proof that the name's value is fixed for all relevant executions.

Report errors at the right boundary

The third program tries a missing operand, a missing right parenthesis, an unsupported character on a second line, an unknown name and an extra literal. Each is caught and printed as a controlled error. The scanner and parser include source positions; the evaluator identifies the unresolved name.

The example stops processing each damaged expression at its first error, then tries the next expression independently. It does not attempt statement-level recovery, because the language currently contains only one expression per compilation request.

Extending the language carefully

Adding division requires decisions beyond putting / in the scanner. Choose integer or real division, define negative-operand behaviour, specify zero-divisor errors, add parser precedence, evaluator semantics and a TAC operation. Update all consumers of the AST rather than letting one phase accept an operation another phase cannot handle.

Adding assignment requires a statement grammar and a writable environment. Decide when declarations happen and whether reassignment may change a name's type. A symbol table can keep declaration information, while a runtime environment keeps values. They are related maps with different jobs and should not be silently treated as one universal dictionary.

Adding typed real values would connect this project to the earlier type checker. A typed AST could insert int-to-real conversion nodes before TAC generation. If the generator instead guesses types from printed token strings, it will lose the semantic decisions made earlier.

Large inputs need explicit resource limits. Recursive descent and recursive AST processing can reach Python's recursion limit. The practice interface limits expression length to 100 characters and nesting to 30. These limits are suitable for classroom arithmetic, not a claim that the compiler handles arbitrarily deep untrusted programs.

Common mistakes

Accepting a valid prefix as the whole program

Parsing 2 from 2 3 is not success. Require the end token after the root expression. The extra token should produce an expected-end diagnostic at its own position.

Generating before checking the entire input

A malformed expression should not produce a believable partial program. Build the whole AST first. In the interactive interface, evaluation also succeeds before any value or TAC rows are printed, so an unknown name does not leave partial results.

Mixing binary subtraction with unary negation

The first minus in -2*3 is unary; the minus in 5-2 is binary. Separate parser positions determine the operation tag. The generator then handles one-child negation without inventing a missing operand.

Summary

The calculator connects clear phase boundaries: characters become tokens, tokens become an AST, and the AST supports evaluation and TAC generation. Extend each phase deliberately when adding a feature. Use the interview questions to explain the design choices aloud.
