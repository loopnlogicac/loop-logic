Introduction

A parse tree tells you how an expression is grouped. Imagine writing a small calculation beside every branch of that tree. The answer at the root becomes the answer for the whole expression. Syntax-directed translation attaches such rules to grammar productions, so meaning follows the structure you already recognised.

For a marks calculator, recognising 40 + 2 * 5 is only the first job. You also want the value 50. A compiler might want a type, a memory location, or an instruction sequence instead. These are different results computed from the same grammatical structure.

An attribute is information associated with one occurrence of a grammar symbol. Two occurrences of E can have different values. A semantic rule explains how one attribute depends on others. The rule is a description of a calculation, rather than an instruction to guess a traversal order.

Attributes and grammar rules

Use E → E + T or T, T → T * F or F, and F → number or ( E ). The lexer supplies number.lexval, the integer written in a number token. Every E, T, and F has a val attribute. Subscripts below distinguish occurrences in one production; they do not introduce new nonterminals.

A synthesised attribute obtains its value from children, or from information available locally at the node. Think of small results travelling upwards. An S-attributed definition uses only synthesised attributes. A bottom-up parser can compute these values when it reduces a production, because the children are already on its stack.

An inherited attribute receives context from its parent or appropriate neighbouring occurrences. A name needs the surrounding declaration environment before you can find its value. The name itself cannot tell you which scope is active. Inherited does not mean object-oriented inheritance; here the word describes information moving through a syntax tree.

An L-attributed definition allows inherited attributes of a right-side occurrence to depend on the parent's inherited attributes and earlier right-side occurrences. Synthesised values still travel upwards. This supports a left-to-right depth-first evaluation when the full dependency graph is acyclic. Every S-attributed definition is also L-attributed.

For A → B C, assigning B.in = C.val requires a later sibling. That equation violates the usual L-attributed restriction. You might evaluate C first using a general dependency schedule, but a straightforward left-to-right visit cannot supply B.in in time. Do not call a definition L-attributed merely because it has inherited attributes.

Checking a dependency cycle

Suppose A.x = B.y + 1 and B.y = A.x + 1 for the same parent-child pair. Neither value has a starting point. Drawing arrows gives A.x → B.y → A.x. There is no topological evaluation order for these equations.

A dependency graph has one vertex per attribute occurrence, not merely one vertex per attribute name. Otherwise separate E.val occurrences would collapse and create false cycles. This distinction is especially useful when you explain an annotated tree in an exam.

Executable evaluators

Evaluate precedence

The first program scans and parses integer arithmetic, then evaluates its AST. The AST omits punctuation nodes but preserves grouping. Unary minus is represented by its own node, so negation is not confused with subtraction.

The result 23 comes from multiplying before adding. The parser's term function builds the multiplication child first. Evaluation follows children before their parent, which implements the synthesised value rule.

Inspect the annotations

The second program lists postorder annotations for a parenthesised expression. Each row names an AST operation and its calculated value. You can use these rows to draw the corresponding annotated tree on paper.

Parentheses change which subtree reaches multiplication. They disappear from the AST because the new shape already records their meaning. This is why evaluating an AST still respects parentheses.

Supply an environment

The third program gives the identifier marks an inherited environment containing marks = 40. A number leaf needs no lookup. A name leaf obtains its value from that environment before the addition can finish.

The environment is passed explicitly rather than stored in a hidden global variable. That makes the dependency visible and lets you evaluate the same tree under another set of marks. An unknown identifier raises a language error instead of silently becoming zero.

Common mistakes

Confusing a definition with an action position

An attribute grammar states dependencies. A translation scheme places actions at particular points in a production. Putting a print action before its operands are available gives a different execution schedule. Decide whether you are describing equations or executable actions before tracing them.

Giving every occurrence one shared value

Two number leaves can represent 3 and 5 at the same time. Store attributes per node or per parser-stack entry. A single global variable called val loses one operand as soon as another token arrives.

Trusting syntax to supply a declaration

A grammar can recognise an identifier without knowing whether it was declared. Pass an environment or consult a symbol table for that question. Keep the parse error for missing punctuation separate from the semantic error for an unknown name.

Python representation notes

The programs use dataclasses and tuples, available before Python 3.12. Their arithmetic uses Python integers. Long expressions or very deep parentheses can reach the interpreter's recursion limit, so use fewer than 100 nested operators while practising. The language includes ASCII integer literals, identifiers, parentheses, unary minus, addition, subtraction, and multiplication.

Summary

Syntax-directed translation connects grammar structure to computed information. Check each attribute's direction, draw its dependencies, and choose an evaluation schedule that respects them. Next, use these ideas to reject incompatible operands in type checking.
