Introduction

Suppose students invent identifiers for a marks program. You cannot list every valid name: marks, roll2, total_marks, and many more. A regular expression gives one compact spelling rule. You can then ask whether a candidate name follows that rule.

A regular expression describes a set of strings. Concatenation joins patterns, a vertical bar offers alternatives, and repetition operators control how many copies are allowed. These operations help describe token spellings without storing every possible token in a list.

A regular definition gives a name to a useful pattern. You might define digit first, then use that idea in integer and decimal patterns. Python's re module does not automatically expand a textbook name such as digit inside a string. You must expand or compose the actual pattern yourself.

These examples use a deliberately small ASCII language. Identifiers start with A through Z, a through z, or underscore. Numbers use digits 0 through 9. This choice makes the accepted alphabet explicit, even when the host language supports a wider set of characters.

A character class matches one character from a set. Thus [0-9] consumes one digit, while [0-9]+ consumes one or more. Star permits zero copies, plus requires at least one, and question mark permits zero or one. Parentheses group a larger expression before a repetition applies.

The group (?:...) groups without capturing a result. Captures are useful when you need subparts later, but a token classifier often only needs success or failure. Avoid extra captures when they distract from the rule you are expressing.

A dot normally matches almost any character, rather than a literal decimal point. Escape it as \. inside a raw pattern string. A Python raw string keeps backslashes available for the regex engine instead of interpreting them as Python string escapes first.

Choose the matching operation

re.fullmatch asks whether the whole candidate belongs to the pattern's language. re.match asks whether a pattern matches at the beginning. re.search can find a match later in the text. Those are different questions, and each can be useful in the right interface.

A scanner normally needs a prefix at the current input position. After recognising it, the scanner continues at the next position. A form that asks for one complete identifier instead needs fullmatch. Rejecting roll@ as a complete name does not mean the valid prefix roll cannot be a token in a longer source.

Keywords create an overlap with identifier syntax. The spelling print follows the identifier pattern. After reading the entire name, look it up in the keyword set. This accepts print2 as an identifier while classifying exactly print as a keyword.

Numeric rules need equally clear choices. Our decimal pattern accepts 85 and 85.5, but rejects .5 and 85. The latter two are accepted by some real languages. They are rejected here because our rule requires digits on both sides of a present decimal point.

A leading minus is not included in these number patterns. A small language can recognise it as an operator, so x-5 becomes an identifier, a minus token, and a number. Including signs inside numbers can make tokenisation depend on spacing unless you carefully design the surrounding grammar.

Expose ordered alternation

Python re alternatives are tried from left to right. A successful short branch can win before a longer branch is attempted. Put overlapping fixed operators in descending length, or compare all token candidates explicitly.

Token overlap and longest match

Longest match means taking the greatest number of characters that forms any allowed token at the current position. It compares token candidates, not merely alternatives in one Python pattern. If two candidates have equal length, a language can resolve the tie by rule priority.

For text ==, ASSIGN can match one character and EQ can match two. Longest match chooses EQ. For text print, both the keyword rule and identifier rule match five characters. A keyword table or explicit tie priority chooses the keyword.

A master pattern can implement some priorities by ordering alternatives, but Python re does not automatically provide a lexer generator's longest-match semantics. In particular, =|== matches only the first = at the start of ==. Greedy repetition within one branch does not change the order of alternative branches.

The longest-prefix practice solution checks each token pattern and compares candidate lengths. Python's max keeps the first candidate on equal keys, so the listed order supplies tie priority. This method is readable for a small language, though repeatedly slicing a long source is inefficient. A position-aware matcher can avoid those copies.

Regular expressions describe spelling, not every structural relationship. Balanced parentheses of unbounded depth require more than an ordinary finite-state token rule. A lexer can return LPAREN and RPAREN tokens, while a parser checks how they nest. Do not burden the number pattern with an entire expression grammar.

Python's regex engine also supports features beyond the basic regular-expression model used in automata theory. Backreferences, for example, compare earlier captured text. The token patterns here use ordinary regular operations, so the finite-automaton connection remains appropriate.

Common mistakes

Using star when empty input is invalid

[0-9]* accepts the empty candidate. If a number needs at least one digit, use plus. Test an empty line explicitly; it is an easy case to overlook when every visible example contains digits.

Forgetting to escape a decimal point

A bare dot can allow a spelling like 8x5. Use a literal escaped dot when the language requires a decimal separator. Then test a letter where that separator should be.

Assuming backslash-d means ASCII only

With Python string patterns, backslash-d can recognise Unicode decimal digits. Use [0-9] when your source language specifies ASCII digits. Wider acceptance can be intentional, but must follow a stated rule.

Version notes

All four examples use established re operations available before Python 3.10. Their patterns avoid recent syntax additions. Raw strings, fullmatch, and noncapturing groups behave consistently in the Python 3.12 environment used here.

Summary

Define the token alphabet, compose patterns, and choose prefix matching or whole-word validation deliberately. Keyword ties and longest operators require a clear policy. In Finite Automata, the same regular languages become state transitions you can trace.
