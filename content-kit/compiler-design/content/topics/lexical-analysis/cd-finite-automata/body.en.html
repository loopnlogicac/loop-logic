Introduction

Imagine a switch that changes position whenever a b arrives. It stays in place when an a arrives. The switch has only two positions, yet it can recognise whether a word contains an even number of b symbols. A finite automaton turns that idea into a precise model.

A finite automaton reads symbols while remembering one of finitely many states. Its state summarises relevant history. It does not need to store the entire word. For the even-b problem, remembering parity is enough; the exact count is unnecessary.

Finite automata connect token patterns with executable scanners. A state can remember that a name has begun or that digits have followed a decimal point. The automaton's accepting states identify complete allowed spellings. For now, we recognise whole words before adding the scanner's boundary and priority rules.

Define a DFA and an NFA

A deterministic finite automaton, or DFA, is described by five parts: states Q, alphabet Σ, transition function δ, start state q0, and final-state set F. For a complete DFA, δ maps every state-symbol pair to exactly one state.

A nondeterministic finite automaton, or NFA, permits zero, one, or several destinations for a state-symbol pair. For an epsilon-free NFA, δ maps a pair to a set of states. An epsilon-NFA additionally allows transitions that consume no symbol. Some texts use NFA to include that extension.

A DFA follows one state sequence. An NFA may have many possible paths, but a simulator can track their active set together. NFA acceptance means at least one path consumes the whole input and ends final. Every path does not need to succeed.

The simulator stores a current state and looks up each next state. If a character is outside the alphabet, the interface returns rejection. This is separate from a transition inside the mathematical alphabet. Our table is complete for a and b, but it does not pretend that x belongs to Σ.

For a word of length n, this table-driven simulation uses n transitions. With constant-time table lookup, the running time is O(n). The current state uses constant extra space relative to input length. A printed trace can use additional output proportional to n.

Track all paths of an NFA

The final program recognises words ending in ab. It uses sets of active states rather than selecting one branch. This NFA has no epsilon edges, so each update needs only a union of consuming destinations.

The final active set contains 2, so aab is accepted. If another a arrives, 2 contributes no destination and 0 contributes {0,1}. The resulting set rejects until a later b completes a fresh pair. A path's earlier acceptance is not permanent acceptance of a longer word.

Nondeterminism does not let a finite automaton recognise every possible language. NFAs and DFAs recognise the same class of regular languages. Their difference is how conveniently they represent possibilities. Subset construction converts those sets into deterministic states.

In a lexer, final states may also carry token categories. Two final states can represent different kinds of tokens even when both mean acceptance in a yes/no recogniser. Later scanner construction must preserve those labels when applying priority or minimisation. This lesson's simulators answer only whole-word membership.

Boundaries that reveal wrong models

Empty input tests the start state's status. A single symbol tests whether one transition is correct. Two repeated b symbols test both directions of the parity toggle. An invalid character tests the interface rather than the parity calculation.

A dead state is a rejecting state from which no suffix can lead to acceptance. It usually loops on every symbol in a complete DFA. An NFA can instead represent a failed group of paths by an empty active set. These are related descriptions, but an empty set is not a missing step to be ignored.

When drawing a diagram, show the start arrow and all final marks. Include one edge or a grouped label for every table entry. If the diagram and table disagree, students cannot know which machine they are meant to simulate. Use traces to check both representations.

Common mistakes

Accepting after any visited final state

The whole word must be consumed. The parity machine visits E repeatedly, but a final trailing b can leave it in O. Decide at the end, not at the first accepting prefix.

Choosing one NFA branch

An arbitrary branch can reject a word that another branch accepts. Track all destinations. A set naturally removes duplicate states while preserving every possible future.

Using equal state counts as equal meaning

The parity DFA and ending-b DFA both have two states but recognise different languages. Explain each state's invariant. A shared size or diagram shape is not an equivalence proof.

Version notes

Python dictionaries and sets provide the transition tables here. The implementations need no external package and work on Python 3.10 onward. Sets are not printed in arbitrary iteration order; displayed traces use chosen labels or deterministic formatting.

Summary

A DFA remembers one state, while an NFA represents several possible paths. Both recognise regular languages. Define the alphabet, state meanings, start, finals, and complete transition rules before simulating. Continue with Thompson Construction to build an NFA from a regular expression.
