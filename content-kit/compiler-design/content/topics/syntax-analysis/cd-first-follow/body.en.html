Introduction

Imagine choosing a bus by reading its first destination sign. A parser also needs a small clue before choosing a rule. FIRST tells you which token may start a phrase. FOLLOW tells you what may appear immediately after a completed phrase.

For a symbol sequence α, FIRST(α) contains every terminal that can begin a string derived from α. It also contains ε when α can disappear completely. A sequence that can disappear is called nullable. For a terminal a, FIRST(a) is {a}; FIRST of the empty sequence is {ε}.

FOLLOW(A) contains terminals that may come directly after nonterminal A in a sentential form reachable from the start. Include $ when A can occur at the end. The end marker is a parser convention, not an ordinary grammar terminal. FOLLOW never contains ε because an empty sequence is not a next token.

Grammar and representation

E → T R
R → + T R | ε
T → F Q
Q → * F Q | ε
F → ( E ) | id

The expression grammar uses R for an addition tail and Q for a multiplication tail. Both tails can vanish. The start symbol E cannot vanish because F must eventually produce id or parentheses around another expression. Do not confuse a nullable suffix with a nullable whole production.

The Python representation maps each nonterminal to a list of tuple alternatives. An empty tuple represents ε. Symbols such as id remain complete strings; the algorithm never splits them into characters. How the parser works

Grow FIRST until no set changes

Start every nonterminal FIRST set empty. For each A → α, scan α from left to right. Add FIRST of the next symbol without ε. Continue only if that symbol can vanish. If every symbol vanishes, add ε to FIRST(A). Repeat all productions until a complete pass adds nothing.

The round table uses a snapshot of the preceding round to make dependencies visible. The implementation updates sets within a pass, so some information may arrive sooner. Both schedules reach the same least fixed point because sets only grow. A fixed point means another full application of the rules changes no set.

For E → T R, FIRST(E) begins with FIRST(T), excluding ε. T begins with F, and F begins with either ( or id. Since T is not nullable, R contributes no initial + to E. This is why a legal expression cannot start with + in this grammar.

Propagate FOLLOW through suffixes

Put $ into FOLLOW of the start symbol. For every occurrence A → α B β, add FIRST(β) without ε to FOLLOW(B). If β is nullable, also add FOLLOW(A) to FOLLOW(B). An empty β is nullable, so a final B always inherits FOLLOW(A). Repeat until stable.

FOLLOW(E) becomes {$,)} from its start position and its occurrence before a closing parenthesis. FOLLOW(R) inherits the same set. T can be followed by + from R, or by whatever follows E when R vanishes. F can be followed by * from Q, or by the complete FOLLOW(T) when Q vanishes.

Solve a nullable exam problem

S → A B A
A → a | ε

Nullable-prefix exam problem
NonterminalFIRSTFOLLOW

FIRST(S) includes a from the first A. If that A disappears, B contributes b. If B also disappears, the final A contributes a again. Since all three occurrences may disappear, ε also belongs to FIRST(S). Sets remove the duplicate a automatically.

For the first A, the suffix B A has FIRST {a,b,ε}. Therefore FOLLOW(A) gains a and b, and also $ from FOLLOW(S). The final A inherits $ directly. B sees the final A, so FOLLOW(B) receives a and $ but not b. Every occurrence matters, even when a symbol appears twice in one production.

The finite-set argument explains termination. There are finitely many nonterminals and terminals. Every successful update inserts a previously absent member, and no rule removes one. Thus only finitely many successful insertions are possible. Recursive grammar dependencies may need many passes, but they cannot keep adding new symbols forever.

The calculator is intended for small classroom grammars. If a pass scans P symbol positions and copies sets with at most t terminals, one pass costs roughly O(Pt). The number of passes depends on dependency chains and update order. A worklist can avoid rescanning unaffected productions, but the fixed-point version makes the rules easier to inspect.

FIRST and FOLLOW approximate possible token positions using grammar structure. They do not by themselves prove that an arbitrary input belongs to the language. A parser must still check the full token sequence. The sets guide production selection and later help restrict LR reductions.

A useful manual check separates direct contributions from inherited ones. First list the terminal that visibly follows each occurrence, or FIRST of its remaining suffix. Then draw an arrow from FOLLOW of the enclosing left side whenever that suffix can vanish. Propagate symbols along those arrows until none changes. This dependency picture is especially helpful for a cycle: the cycle shares information already introduced by a real terminal or the start marker; it does not invent new members.

Common mistakes

Copying ε into FOLLOW

A nullable suffix transfers FOLLOW of the enclosing rule. It never transfers ε as a token. Remove ε before every direct FOLLOW insertion.

Examining only the first right-side symbol

In A B c, both A and B may vanish. Scan through that nullable prefix so c is not lost.

Stopping after one pass

Indirect rules may reveal terminals several passes later. Stop only after a complete pass leaves every set unchanged.

Confusing token spelling with symbols

The token id is one symbol. Representing it as two characters i and d changes the grammar and produces incorrect sets.

Python version notes

The set operations and empty tuples work in Python 3.10 through 3.12. Sorting each displayed set makes its order predictable.

Summary

FIRST scans nullable prefixes; FOLLOW scans what remains after each nonterminal occurrence. Repeated set growth handles cycles safely. Use these results in LL(1) parsing to choose a production from one lookahead token.
