Introduction

Two railway platforms can have the same track layout but serve different destinations. Likewise, two LR states can have the same dotted productions while allowing different following tokens. CLR remembers those destinations; LALR combines states with matching layouts.

An LR(1) item has the form [A → α · β, a]. The dotted production records progress. The terminal a is a lookahead that may follow the completed A in this context. It is not necessarily the token currently under the dot, nor an instruction to consume a immediately.

Canonical LR(1), often called CLR, keeps distinct reachable sets of these full items. LALR(1) merges CLR states with identical LR(0) cores and unions lookaheads for matching dotted productions. This often saves many states, but combining contexts can introduce reduce/reduce conflicts.

A single shared item is insufficient. For matching cores, union the lookahead sets separately for each dotted production.

Number S alternatives 1 through 4, A → c as 5, and B → c as 6. After prefix a c, A may reduce before d while B may reduce before e. After prefix b c, those following-token roles are reversed. Each CLR context is deterministic: the same token never selects both reductions within one unmerged state.

The two completed states share the core {A → c ·, B → c ·}. Merging unions d and e onto both productions. The merged d cell now contains r5 and r6, and the merged e cell does too. The grammar is CLR(1) but not LALR(1). The Python example retains both conflicts instead of choosing a production by its number.

These containment statements describe grammar classes under the standard constructions. A language may have several grammars, and changing its grammar can change which parser method succeeds. A conflict in one grammar does not prove that the language cannot be recognised by another grammar in a smaller class. Do not confuse a grammar’s table properties with the language’s possible descriptions.

For the same grammar, LALR normally has the LR(0) state count, while CLR can need many more states. The two-group example makes the difference concrete: seven versus ten. More states do not make each ordinary parse step slower in principle; both methods use table lookups. The major tradeoff concerns construction cost, table size, and how much context the grammar requires.

Merging conflict-free CLR states cannot introduce a new shift/reduce conflict solely through equal-core merging. If one merged core has a shift on terminal t, every source state with that core has the same shift possibility. A reduction on t contributed by any source would therefore already have conflicted with its own shift. New reduce/reduce conflicts are possible because their distinct lookaheads can come from different source states.

The implementation stores each LR(1) item as a production number, dot offset, and terminal lookahead. A frozen set represents a state, allowing exact equality comparisons. Sorted outgoing symbols make state discovery deterministic. This representation stores separate items for different lookaheads; a display may group those items only after the algorithm has finished.

For an exam, show the FIRST(βa) calculation for at least one nontrivial closure. List all CLR states, mark equal cores, show merged lookahead unions, and fill the resulting ACTION/GOTO table. If a merged cell conflicts, name its competing productions and the source contexts that supplied them. The union operation explains the conflict more clearly than merely labelling a row “not LALR”.

Common mistakes

Using FOLLOW inside CLR closure

CLR predicts with FIRST(βa), including the parent lookahead after the remaining suffix. Replacing that calculation with global FOLLOW loses the precision CLR was meant to retain.

Merging states that share only one item

All dotted productions in their cores must match. Otherwise the merge changes both progress information and lookahead context.

Assuming fewer states imply equivalent conflict behaviour

The counterexample’s merged cores acquire two reduce/reduce cells. Always rebuild and inspect ACTION after unioning lookaheads.

Summary

CLR separates contexts with LR(1) lookaheads. LALR saves states by merging equal cores, which may combine incompatible reductions. Next, operator precedence parsing uses relations between terminals to locate expression handles.
