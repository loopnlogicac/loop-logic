Introduction

Imagine checking a course registration form. Each entry has a course code, then a section, then a credit value. Knowing which words are valid does not tell you whether their order is valid. A grammar supplies that structure.

A context-free grammar, or CFG, describes how a named part can expand into smaller parts. The left side of each rule is one nonterminal. A nonterminal is a name such as E for expression. A terminal is a token kind that appears in the final input, such as id or +.

The lexer from lexical analysis groups characters into tokens. The parser checks those tokens against a grammar. Thus roll + marks has three tokens here, even though its spellings use many characters. The grammar uses id for both names and leaves their actual values to later analysis.

Formally write G = (N, T, P, S). N is the nonterminal set, T is the terminal set, P is the production set, and S is the start symbol. N and T are disjoint. A production A → α replaces one occurrence of A by the sequence α, regardless of surrounding symbols.

A sentential form is any sequence reachable from the start symbol. It may still contain nonterminals. A sentence contains only terminals. The language L(G) consists of every terminal sentence derivable from S, not every intermediate form.

Find genuine ambiguity

Two trees for the same three identifiers
GrammarRoot splitGrouping
E → E + E | E * E | id+ at the rootid + (id * id)
E → E + E | E * E | id* at the root(id + id) * id

A grammar is ambiguous when at least one terminal sentence has two distinct parse trees. The flatter grammar lets either operator become the root for id + id * id. Assigning values 2, 3, and 4 gives 14 for one grouping and 20 for the other. That difference shows why a compiler needs a clear grouping rule.

The layered E, T, F grammar removes this expression ambiguity. E handles addition, T handles multiplication, and F permits parentheses. A plus cannot appear directly inside an unparenthesised T. This forces multiplication to group before addition in id + id * id.

Separate precedence from associativity

Precedence chooses which kind of operator groups more tightly. Associativity chooses grouping among operators at the same level. For subtraction, left association matters: 9 − 2 − 1 means (9 − 2) − 1 = 6. Right association would give 9 − (2 − 1) = 8. Use tree structure to express the intended choice.

Epsilon, ε, means an empty sequence. In L → id R and R → , id R | ε, R represents zero or more additional identifiers. Choosing ε adds no leaf token to the input. The list contains at least one id because L itself cannot disappear.

Reasoning and checks

To validate a derivation, check one replacement at a time. The unchanged prefix and suffix must remain identical. For a tree, check every parent and its ordered children against one grammar production. Finally compare the leaf sequence with the complete input, including punctuation.

To demonstrate ambiguity in an exam, give one sentence and draw two trees for it. Two leftmost derivations also suffice if their structural choices differ. Two ordinary derivations may differ only because independent nodes were expanded in a different order. Always identify the changed root split or nested grouping.

An unambiguous expression grammar solves a specific language-design problem. It does not provide a general algorithm for removing ambiguity from every CFG. Some context-free languages have no unambiguous grammar. In practice, you choose explicit grouping rules, then express them using grammar levels or parser declarations.

The dangling-else problem offers another ambiguity. In if a then if b then x else y, the else can attach to either if under the naive rule. A language may require attachment to the nearest unmatched if. A matched/unmatched statement grammar can encode that convention, or braces can make the grouping visible.

A parse tree includes grammar details such as E, T, F and parentheses. An abstract syntax tree usually keeps only meaningful operations and operands. For 2 + 3 * 4, its root is + and its right child is *. Removing grammar-only nodes must preserve the grouping established during parsing.

Context-free syntax cannot express every program rule conveniently. For example, a grammar can accept id + id without knowing whether either identifier was declared. Type checks and declaration checks belong to semantic analysis. Keeping those stages separate lets you explain whether a failure concerns token spelling, token order, or meaning.

Common mistakes

Calling two expansion orders ambiguous

A leftmost and a rightmost derivation can share one tree. Compare parent-child choices before claiming two meanings.

Treating ε as a printed token

An empty production consumes nothing. Do not place an ε character between two input tokens.

Fixing precedence but losing association

Separate operator levels and then inspect a chain of one operator. A grammar can enforce precedence while choosing the wrong subtraction grouping.

Summary

A CFG explains how tokens form nested phrases. Derivations expand those phrases, while parse trees make their grouping visible. Next, reshape grammar rules so a predictive parser can choose a production without looping.
