Introduction

Suppose you ask a friend how to recognise E. The answer begins, “first recognise E.” You ask the same question again without reading any input. A top-down parser can get trapped in exactly that conversation.

A grammar is left recursive when some nonterminal A can derive A α in one or more steps. The repeated A is at the left edge, so a parser expanding it has consumed no terminal first. Immediate recursion uses one rule; indirect recursion travels through other nonterminals.

A second difficulty is a shared beginning. With S → id = E ; | id ( A ) ;, seeing id does not tell you which rule to use. Left factoring delays that decision until the common prefix has been consumed. These two transformations solve different parser problems.

Grammar rewriting should preserve the set of terminal strings. It may change the parse-tree shape. If your parser builds an expression tree or computes a value, preserve the language’s grouping separately. Equivalent recognised strings do not automatically imply equivalent evaluation actions.

For A → A α₁ | A α₂ | β₁ | β₂, split alternatives into recursive and nonrecursive groups. Create a fresh R and write A → β₁ R | β₂ R. Then write R → α₁ R | α₂ R | ε. Each α must be nonempty for this direct rule, and each β must avoid starting with A.

The old grammar chooses a base β after expanding A repeatedly. Each expansion adds one α suffix. The new grammar chooses the base first and then repeats those suffixes through R. For E → E + T | T, both versions describe one T followed by zero or more + T pairs.

The original grammar has a cycle A ⇒ B a ⇒ A b a. No individual rule starts with its own left side, yet a naive recursive parser still loops. Order the names A then B. In B → A b, replace A using both its alternatives, obtaining B a b and c b.

After substitution, B has immediate recursion with suffix a b. Its bases are c b and d. The transformed B and R rules in the last row remove that recursion. Keep A → B a | c. A may call B, but B now begins with a terminal c or d rather than calling A again.

For A → α β₁ | α β₂, factor a shared nonempty α into A → α R, R → β₁ | β₂. Alternatives outside that prefix stay on A. Choose the longest useful common prefix, then repeat inside R if its alternatives still share a prefix.

The second row needs two stages because a b is shared by two alternatives, while all three share a. After consuming a, lookahead e selects the short branch. Lookahead b selects Q, and then c or d chooses the last token. Factoring turns one early guess into a series of later decisions.

The last row demonstrates an empty remainder. In S → a b | a, the second alternative ends exactly at the shared a. Therefore R needs ε. Replacing that empty remainder with another a would change the language and reject the original one-token sentence.

Reasoning and checks

Language preservation for immediate recursion follows from counting suffix repetitions. An old derivation with k recursive steps ends at β αₖ … α₁. The new R can choose those same k suffixes in their final order and then vanish. Conversely, every finite R expansion can be reproduced by old recursive choices in reverse selection order.

Tree shape deserves a separate check. Rewriting E → E - T | T as E → T R, R → - T R | ε creates a right-recursive tail. Evaluating that tail as right-associated subtraction would change 9-2-1 from 6 to 8. Use a running left accumulator, or build a left-nested operation tree while reading successive terms.

A degenerate rule A → A adds no terminals and cannot help generate a new sentence. Remove that self-loop before applying the nonempty-suffix formula. If A has no nonrecursive base at all, such as A → A a, it derives no finite terminal sentence. Inventing a new ε base would incorrectly add words to its language.

Nullable prefixes can hide recursion. In A → B A x | y with B → ε, A can return to itself before reading input even though its first written symbol is B. Compute which prefixes can vanish, then inspect left-edge dependencies. You may need epsilon elimination or a more general transformation before the ordered substitution method applies.

A practical grammar review uses both positive and negative examples. For the indirect example, compare c, d a, and c b a in both versions. Also check a and d, which should remain rejected from start A. Such samples catch copying errors, while the derivation argument explains preservation for arbitrarily many repetitions.

Common mistakes

Factoring the wrong end

A common suffix does not solve a predictive choice at the start. Factor prefixes that the parser encounters before its decision.

Dropping a base or ε alternative

Every old base must remain available. Test zero repetitions immediately after introducing a repetition tail.

Stopping after direct recursion is gone

Follow calls through other names and nullable prefixes. A parser can still cycle without an obvious A → A α rule.

Summary

Remove left recursion to avoid expansion loops, and factor shared prefixes to postpone choices. Then compute FIRST and FOLLOW to discover which lookahead tokens can actually select each alternative.
