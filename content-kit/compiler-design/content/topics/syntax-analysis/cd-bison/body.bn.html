পরিচিতি

ভাষা বড় হলে হাতে প্রতিটি পার্সার স্টেট লেখা কঠিন হয়। Parser generator গ্রামারের নিয়ম নিয়ে তোমার জন্য স্টেটের ব্যবস্থা বানায়। ভাষা, গ্রুপিংয়ের নিয়ম, semantic value ও ভুলের আচরণ তোমাকেই ঠিক করতে হয়।

Bison হলো Yacc পরিবারের parser generator। এর C পার্সার সাধারণত পরের টোকেন চাইতে yylex কল করে, তারপর LR টেবিল দিয়ে শিফট ও রিডিউস করে। সাধারণ C সেটআপে Bison-এর ডিফল্ট LALR; IELR ও canonical LR মোডও আছে। মোড বদলালেই দ্ব্যর্থক ভাষার সংজ্ঞা ঠিক হয় না।

নিচের calculator-এ সাইন ছাড়া পূর্ণসংখ্যা, +, -, * ও বন্ধনী চলে। প্রতিটি এক্সপ্রেশন ; দিয়ে শেষ। মান double হিসেবে থাকে, সফল প্রতি স্টেটমেন্টে একটি ফল প্রিন্ট হয়। Unary minus, ভাগ ও assignment নেই। মান ছোট ও সসীম রাখো; floating-point rounding এখানেও হয়।

ধাপে ধাপে উদাহরণ

calc.y-এর ঘোষণা অংশ পড়ো

%{
#include <stdio.h>
int yylex(void);
void yyerror(const char *message);
%}
%define api.value.type {double}
%token NUM
%left '+' '-'
%left '*'
%%

%{ ও %}-এর ভেতরের prologue তৈরি C সোর্সে কপি হয়। এতে stdio থাকে, আর পার্সার ব্যবহারের আগে স্ক্যানার ও error ফাংশন ঘোষণা করা হয়। api.value.type দিয়ে সব semantic value-এর টাইপ double নেওয়া হয়। NUM নাম দেওয়া টোকেন; যতিচিহ্নে সরাসরি ক্যারেক্টার কোড ব্যবহার হয়।

প্রথম %% ঘোষণা শেষ করে প্রোডাকশন শুরু করে। দ্বিতীয় %% প্রোডাকশন শেষ করে সাধারণ C সংজ্ঞা শুরু করে। দেখানো calc.y-এর তিন অংশ ওই ক্রমে বসিয়ে পুরো গ্রামার সোর্স বানাও। input-এর প্রোডাকশন আগে আছে বলে সেটিই শুরুর সিম্বল।

আসল semantic action-সহ প্রোডাকশন ব্যবহার করো

input:
    %empty
  | input expr ';'  { printf("%.10g\n", $2); }
  | input error ';' { yyerrok; }
  ;
expr:
    NUM                  { $$ = $1; }
  | '(' expr ')'         { $$ = $2; }
  | expr '+' expr        { $$ = $1 + $3; }
  | expr '-' expr        { $$ = $1 - $3; }
  | expr '*' expr        { $$ = $1 * $3; }
  ;

খালি input বিকল্পে শূন্য স্টেটমেন্ট চলে। Recursive বিকল্পে আরেকটি এক্সপ্রেশনের পরে ; নিয়ে তার মান প্রিন্ট হয়। অ্যাকশনে $$ হলো বাম পাশের semantic value। $1, $2 ও $3 ডান পাশের অবস্থান বোঝায়; terminal ও nonterminal দুটিই গোনা হয়।

expr + expr-এ $1 ও $3 অপারেন্ডের মান। $2 যোগের অবস্থান, সংখ্যার হিসাবে লাগে না। ( expr )-এ এক্সপ্রেশন দ্বিতীয় অবস্থানে, তাই $$ = $2 মানটি রাখে। input expr ;-এও এক্সপ্রেশন দ্বিতীয় স্থানে। সেমিকোলন চেনার পরেই স্টেটমেন্টের অ্যাকশন সম্পূর্ণ মান প্রিন্ট করে।

C-এর entry point দিয়ে calc.y শেষ করো

%%
void yyerror(const char *message)
{
    fprintf(stderr, "%s\n", message);
}

int main(void)
{

}

yyparse স্ট্যাটাস কোড main-এ ফেরায়। yyerror error stream-এ syntax error জানায়। ভুলের পরে recovery হলে yyparse পরে সফলভাবে শেষ করতে পারে। যেকোনো ভুলেই অ্যাপের শেষ স্ট্যাটাস ব্যর্থ চাইলে yyerror-এ আলাদা error counter রাখো। সফল recovery মানেই সব স্টেটমেন্ট বৈধ ছিল, এমন নয়।

Calculator গ্রামারে ঠিক করা সিদ্ধান্ত
সম্পূর্ণ নিয়মLookaheadসিদ্ধান্তকারণ
expr → expr + expr+রিডিউসসমান precedence ও %left।
expr → expr + expr-রিডিউস+ ও - একই বাঁ দিক থেকে গ্রুপ হওয়া স্তরে।
expr → expr + expr*শিফট* পরে ঘোষণা করা বেশি precedence-এর স্তরে।
expr → expr * expr+রিডিউসনিয়মের precedence বেশি।
expr → expr * expr*রিডিউসসমান স্তর ও %left।
expr → expr - expr-রিডিউসবাঁ দিক থেকে গ্রুপ করলে (9-2)-1 থাকে।
expr → expr + expr) বা ;রিডিউসসম্পূর্ণ এক্সপ্রেশন সীমানার আগে শেষ হয়।

Precedence-এর নিয়ম লাগানোর আগে ছোট expr গ্রামারটি দ্ব্যর্থক। প্রতিটি %left লাইন তার টোকেনগুলোকে একই precedence স্তর ও বাঁ দিকের associativity দেয়। পরের লাইনের precedence বেশি। প্রোডাকশন সাধারণত নিজের শেষ terminal থেকে precedence পায়। তাই শেষে expr লেখা থাকলেও গুণের নিয়ম *-এর precedence পায়।

Shift/reduce দ্বন্দ্বে দুই দিকেই precedence থাকলে lookahead টোকেন ও রিডাকশনের নিয়মের precedence তুলনা করো। টোকেনেরটি বেশি হলে শিফট, নিয়মেরটি বেশি হলে রিডিউস। সমান হলে associativity লাগে: %left রিডিউস করে, %right শিফট করে, %nonassoc ওই ব্যবহার বর্জন করে। ঘোষণা পার্সারের সিদ্ধান্ত মেটায়; মূল দ্ব্যর্থক গ্রামারকে দ্ব্যর্থকতাহীন বানায় না।

স্ক্যানারে তৈরি header রাখা হয়, যাতে NUM ও semantic value-এর টাইপ পার্সারের সঙ্গে মেলে। ডিজিটের অংশ পেলে strtod বানানকে সংখ্যায় বদলে yylval-এ রাখে, তারপর NUM ফেরায়। Range error হলে YYUNDEF ফেরায়, যাতে অবৈধ সংখ্যায় আগের মান ব্যবহার না হয়। একক যতিচিহ্ন unsigned character code হিসেবে ফেরে।

স্ক্যানারের খালি অ্যাকশনে whitespace বাদ যায়। শেষ dot নিয়ম অন্য সব ক্যারেক্টার পার্সারে ফেরায়; সমর্থন না থাকা ক্যারেক্টারে syntax error হয়। Flex ইনপুটের শেষে শূন্য ফেরায়; অবৈধ ক্যারেক্টারের জন্য শূন্য ফেরাবে না। তাতে নষ্ট suffix স্বাভাবিক ইনপুট শেষ বলে চাপা পড়ে যাবে।

Bison-এর -d অপশনে calc.tab.c-এর সঙ্গে calc.tab.h তৈরি হয়। স্ক্যানার কম্পাইলের আগে header বানাও। Flex থেকে lex.yy.c হয়, C কম্পাইলার তৈরি দুই সোর্স লিংক করে। noyywrap অপশন থাকলে বাইরের yywrap ফাংশন লাগে না। পুরোনো Yacc-এ সাধারণত y.tab.c ও y.tab.h হয়; নেওয়া আউটপুট নামের সঙ্গে include-এর নাম মেলাও।

দেখানোটি সাধারণ non-reentrant C ইন্টারফেস: yylex(void), global yylval, yyparse(void) ও yyerror(const char *)। Pure বা reentrant পার্সারে ফাংশনের signature ও মান পাঠানোর ধরন বদলায়। Reentrant স্ক্যানারেরও মিলিয়ে সেটআপ লাগে। দুই দিক না বদলে ভিন্ন ইন্টারফেসের ঘোষণা একত্র কোরো না।

সেমিকোলনে গিয়ে আবার শুরু করো

8+; 6*7;-এ error প্রোডাকশনের আচরণ
ইনপুটের অংশপার্সারের ফলপরের কাজ
8+;ডান অপারেন্ড নেই; yyerror কল করোনষ্ট এক্সপ্রেশন বাদ দিয়ে error প্রোডাকশনে যাও।
; সীমানাinput error ; মিলিয়ে yyerrok চালাওস্বাভাবিক error reporting আবার শুরু করো।
6*7;গুণ ও স্টেটমেন্ট সম্পূর্ণ করো42 প্রিন্ট করো।

বিশেষ error সিম্বল Bison-এর recovery ব্যবস্থা তৈরি করে; Flex সাধারণ শব্দ হিসেবে ফেরায় না। error শিফট করা যায় এমন স্টেট না পাওয়া পর্যন্ত পার্সার স্টেট পপ করে। তারপর ; দিয়ে recovery নিয়ম সম্পূর্ণ করা পর্যন্ত অনুপযুক্ত টোকেন বাদ দেয়। yyerrok recovery অবস্থা শেষ করে, যাতে পরের ভুল স্বাভাবিকভাবে জানানো যায়। EOF-এর আগে সীমানার সেমিকোলন না এলে recovery ব্যর্থ হতে পারে, yyparse ব্যর্থ স্ট্যাটাস ফেরায়।

কাজের precedence না থাকলে Bison সাধারণত shift/reduce দ্বন্দ্বে শিফট করে; reduce/reduce দ্বন্দ্বে আগের নিয়ম বেছে নেয়। এই ডিফল্ট ভাষার ভালো সংজ্ঞা নয়। Diagnostic, রিপোর্ট বা বিপরীত উদাহরণ দেখে অপ্রত্যাশিত দ্বন্দ্ব ঠিক করো। সম্পর্কহীন দ্বন্দ্ব চুপ করাতে precedence ঘোষণা দিলে গ্রামারের ভুল লুকাতে পারে। প্রতিটি ঘোষণা লিখে রাখা এক্সপ্রেশনের গ্রুপিং নিয়মের সঙ্গে মেলাও।

বড় calculator-এ unary minus-এর জন্য প্রায়ই আলাদা precedence নাম ঘোষণা করে unary প্রোডাকশনে %prec লাগে। %prec ডান পাশে বাড়তি lexer টোকেন না বসিয়েই নিয়মের precedence বদলায়। এই calculator ভাষায় ইচ্ছা করেই সেটি নেই। যোগ করতে precedence ঘোষণার সঙ্গে আসল unary গ্রামার নিয়মও লাগবে।
