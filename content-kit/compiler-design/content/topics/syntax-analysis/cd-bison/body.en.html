Introduction

Writing every parser state by hand becomes tiring as a language grows. A parser generator accepts grammar rules and builds the state machinery for you. You still decide the language, grouping rules, semantic values, and error behaviour.

Bison is a parser generator in the Yacc family. Its C parser normally calls yylex to request the next token, then uses LR tables to shift and reduce. Bison defaults to LALR in its usual C configuration; it also offers IELR and canonical LR modes. Changing a construction mode does not repair an ambiguous language definition.

The calculator below accepts unsigned integer spellings with +, -, *, and parentheses. Each expression ends with ;. Values are stored as double, and each successful statement prints one result. The language omits unary minus, division, and assignments. Keep arithmetic values small and finite; floating-point rounding still applies.

Worked examples

Read the declaration section of calc.y

%{
#include <stdio.h>
int yylex(void);
void yyerror(const char *message);
%}
%define api.value.type {double}
%token NUM
%left '+' '-'
%left '*'
%%

The prologue between %{ and %} is copied into the generated C source. It includes stdio and declares the scanner and error function before the parser uses them. The api.value.type declaration selects double for every semantic value. NUM is a named token; punctuation uses its character code directly.

The first %% ends declarations and begins productions. A second %% ends productions and begins ordinary C definitions. Put the three displayed calc.y parts in that order to form the complete grammar source. The start symbol is input because its production appears first.

Use productions with real semantic actions

input:
    %empty
  | input expr ';'  { printf("%.10g\n", $2); }
  | input error ';' { yyerrok; }
  ;
expr:
    NUM                  { $$ = $1; }
  | '(' expr ')'         { $$ = $2; }
  | expr '+' expr        { $$ = $1 + $3; }
  | expr '-' expr        { $$ = $1 - $3; }
  | expr '*' expr        { $$ = $1 * $3; }
  ;

The empty input alternative permits zero statements. The recursive alternative accepts another expression followed by ; and prints its value. Inside an action, $$ is the left-side semantic value. $1, $2, and $3 refer to right-side positions, counting terminals and nonterminals alike.

For expr + expr, $1 and $3 are operand values; $2 is the plus position and is not used numerically. For ( expr ), the expression is position 2, so $$ = $2 preserves its value. For input expr ;, position 2 is again the expression. The statement’s action prints that completed value only after the semicolon has been recognised.

Finish calc.y with its C entry points

%%
void yyerror(const char *message)
{
    fprintf(stderr, "%s\n", message);
}

int main(void)
{
    return yyparse();
}

yyparse returns a status code to main. yyerror reports syntax errors on the error stream. A recovered syntax error can allow yyparse to finish successfully later. If an application needs any error to make its final status fail, maintain an explicit error counter in yyerror. Successful recovery does not mean every statement was valid.

The compact expr grammar is ambiguous before precedence policies are applied. Each %left line gives its tokens one precedence level and left association. Later lines have higher precedence. A production normally inherits precedence from its last terminal symbol. Thus the multiplication rule has * precedence even though its final written symbol is expr.

When a shift/reduce conflict has precedence information on both sides, compare the lookahead token’s precedence with the reduction rule’s precedence. Higher token precedence shifts; higher rule precedence reduces. Equal precedence uses association: %left reduces, %right shifts, and %nonassoc rejects that combination. These declarations settle parser decisions rather than making the underlying ambiguous grammar unambiguous.

Connect the scanner through calc.tab.h

%option noyywrap nounput noinput never-interactive
%{
#include <stdlib.h>
#include <errno.h>
#include <math.h>
#include "calc.tab.h"
%}
%%
[0-9]+ {
    errno = 0;
    yylval = strtod(yytext, NULL);
    if (errno == ERANGE || !isfinite(yylval)) {
        return YYUNDEF;
    }
    return NUM;
}
[ \t\r\n]+  ;
.             { return (unsigned char) yytext[0]; }
%%

The scanner includes the generated header so NUM and the semantic-value type agree with the parser. For a digit run, strtod converts the spelling and stores it in yylval before returning NUM. A range error returns YYUNDEF so invalid numeric input cannot reuse a previous value. Single punctuation characters are returned as their unsigned character codes.

Whitespace is discarded by the empty scanner action. The final dot rule returns any other character to the parser, where an unsupported character causes a syntax error. Flex returns zero at end of input; do not return zero for an invalid character. Doing so would disguise a damaged suffix as normal input end.

Reasoning and checks

Understand generation order and interfaces

bison -Wall -d -o calc.tab.c calc.y
flex -o lex.yy.c calc.l
cc -std=c17 -Wall -Wextra calc.tab.c lex.yy.c -o calc
./calc

Bison’s -d option emits calc.tab.h along with calc.tab.c. Generate that header before compiling the scanner. Flex produces lex.yy.c, and the C compiler links both generated sources. The scanner’s noyywrap option removes the need for an external yywrap function. Traditional Yacc commonly uses y.tab.c and y.tab.h; keep the included name consistent with your chosen output names.

The shown interface is the ordinary non-reentrant C interface: yylex(void), global yylval, yyparse(void), and yyerror(const char *). A pure or reentrant parser changes the function signatures and how values are passed. A reentrant scanner also needs its own matching configuration. Do not combine declarations from those different interfaces without adapting both sides.

The reserved error symbol is generated by Bison’s recovery machinery, not returned as an ordinary word by Flex. The parser pops states until it can shift error, then discards unsuitable tokens until ; can complete the recovery rule. yyerrok ends the recovery state so later errors can be reported normally. If no synchronising semicolon appears before EOF, recovery may fail and yyparse returns a failure status.

For a conflict without usable precedence, Bison commonly defaults to shifting; reduce/reduce conflicts commonly choose the earlier rule. Those defaults are not a sound language specification. Inspect diagnostics, use reports or counterexamples, and repair unexpected conflicts. Adding a precedence declaration to silence an unrelated conflict can conceal a grammar mistake. Keep each declaration tied to a documented expression-grouping rule.

For unary minus, a larger calculator often declares a separate precedence name and uses %prec on its unary production. The %prec annotation changes that rule’s precedence without adding a lexer token occurrence to its right side. That extension is deliberately absent from this calculator language. Adding it requires an actual unary grammar rule as well as the precedence declaration.

Common mistakes

Returning NUM without setting yylval

The parser would see a token kind but no reliable operand value. Convert the matched spelling and assign the semantic value before returning NUM.

Giving Flex a separately invented NUM value

Token numbers are part of the generated interface. Include calc.tab.h so scanner and parser share the same definitions.

Declaring multiplication before addition

Later precedence lines bind more tightly. Reversing these declarations would make addition outrank multiplication in conflict resolution.

Treating recovery as a successful original statement

The error alternative prints no expression value. Record the diagnostic and resume at the next statement rather than inventing a result.

Summary

Bison combines grammar rules, semantic actions, and declared precedence into an LR parser. Flex supplies token kinds and values through a shared header. After syntax analysis, type checking examines whether operations have compatible operand types.
