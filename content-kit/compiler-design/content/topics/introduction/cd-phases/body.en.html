Introduction

Think of checking an exam answer in several passes. First you read the words. Then you check how the ideas fit together. Finally you check whether the answer makes sense. A compiler also separates different questions instead of trying to answer everything from raw characters at once.

A phase is a conceptual stage with a particular responsibility. Compiler phases recognise tokens, build structure, check meaning, and produce a target representation. A real implementation may combine several phases in one pass over its input. A pass is a traversal; a phase describes the work being done.

This separation helps you find mistakes. If @ is illegal in a language, the problem starts with character recognition. If + lacks a right operand, the pieces are recognised but their arrangement is wrong. If a name has no declaration, the arrangement may be valid while the meaning remains invalid.

Worked examples

Trace an integer assignment

Use total = base + 2 * 5;. Assume a small language with declared integer variables and ordinary multiplication precedence. Also assume this calculation stays within the allowed integer range. Those assumptions make the translation clear without hiding overflow or conversion rules.

Lexical analysis turns characters into tokens. A token records a category such as identifier or integer. The spelling base remains available as an attribute. Whitespace may separate words without becoming a token passed to the parser.

Syntax analysis determines how tokens form larger structures under the grammar. A grammar is a collection of rules for legal arrangements. The parser groups 2 * 5 as the right operand of addition. It does not group the expression as (base + 2) * 5.

Semantic analysis checks rules that structure alone cannot settle. Are both names declared? Can their types participate in these operations? Can the result be assigned to total? A well-shaped sentence can still violate such rules.

Make the intermediate operations visible

An intermediate representation is a form between source and final target. The temporary names t1 and t2 below stand for intermediate results. They need not become actual memory variables in the final program.

Optimisation changes the representation to improve some cost while preserving required behaviour. Replacing 2 * 5 with 10 is constant folding. The target still needs the value of base during execution. Optimisation is not permission to change an answer because another answer is faster.

Code generation chooses target instructions and storage locations. Our imaginary target uses register R1. A register is a small storage location used by instructions. Real targets differ in instruction names, operand rules, and available registers.

Follow the shared symbol table

A symbol table stores information about program names. Several phases can use it. The lexer can attach a spelling or name reference. Semantic analysis records declarations and checks types. Later phases may add storage details. The exact division of these tasks depends on the compiler.

Do not put every integer literal into the identifier table by habit. A token can carry the integer value 5 directly. Similarly, a temporary generated during translation differs from a source name the student declared. Keeping those roles clear makes later explanations of scope easier.

Locating and reporting errors

An error handler reports a useful message and helps the compiler continue where possible. Positions from early phases matter here. If a token retains its line and column, the parser can point to the unexpected token. Semantic analysis can then report an undeclared name at its use.

An error can disturb later analysis. Skipping one invalid character may let a lexer continue. A parser may skip to a semicolon after a broken statement. Recovery must move forward, but it should avoid pretending that the damaged fragment has a trustworthy meaning.

Compiler organisation often groups lexical, syntax, and semantic analysis into a front end. A back end works toward a chosen target, usually using an intermediate form. A middle portion can perform target-independent optimisations. These boundaries are engineering choices, so diagrams may draw them slightly differently.

Common mistakes

Giving the lexer the parser's job

The lexer can recognise an identifier and a plus sign without deciding whether the assignment is structurally complete. Use token rules for spelling and grammar rules for arrangement. A recognised sequence is not automatically a valid statement.

Evaluating unknown inputs during translation

The compiler may fold constants, but base is still a runtime value here. Keep a symbolic read in the intermediate code. Replacing it with a guessed mark changes the program.

Equating phases with file reads

Six conceptual phases do not require reading the source file six times. A compiler may build tokens and structure together. Explain the responsibility first, then discuss how an implementation schedules the work.

Summary

Each compiler phase answers a different question about the same program. Shared name information and source positions connect those answers.
