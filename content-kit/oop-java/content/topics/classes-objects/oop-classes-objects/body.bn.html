একজন শিক্ষার্থীর সম্পর্কিত ডেটা এক জায়গায় রাখো

একটি শিক্ষার্থীর রেকর্ডে রোল আর নম্বর থাকে। সেই নম্বরে পাস করেছে কি না, সেটাও জানতে চাও। ক্লাস দিয়ে সম্পর্কিত তথ্য আর কাজ একসঙ্গে বর্ণনা করা যায়। নির্দিষ্ট একটি শিক্ষার্থীর অবজেক্টে তখন একটি রেকর্ডের মানগুলো থাকে।

ক্লাসকে ফর্মের নকশা ভাবো। অবজেক্ট হলো নিজের পরিচয় থাকা পূরণ করা একটি ফর্ম। দুটি অবজেক্ট বানালে নম্বর রাখার দুটি আলাদা জায়গা পাও। একটি অবজেক্টের দুটি রেফারেন্স বানালে কিন্তু জায়গা একটিই থাকে।

এই পাঠে ছোট Student ক্লাস দিয়ে প্রতিটি ধাপ দেখবে। মেমরির ছবিটা পরিষ্কার রাখতে শুরুতে ফিল্ড সরাসরি ব্যবহার করা যাচ্ছে। পরে অ্যাক্সেস মডিফায়ার আর এনক্যাপসুলেশনে ফিল্ড রক্ষা করতে শিখবে।

ফিল্ডে স্টেট, মেথডে কাজ

ক্লাসের অংশ হিসেবে ঘোষণা করা ভেরিয়েবল হলো ফিল্ড। ইনস্ট্যান্স ফিল্ডের জন্য প্রতিটি অবজেক্টে আলাদা জায়গা থাকে। ইনস্ট্যান্স মেথড একটি অবজেক্টের মাধ্যমে চলে এবং তার ফিল্ড ব্যবহার করতে পারে। অন্যদিকে লোকাল ভেরিয়েবল একটি মেথড কলের নিজস্ব।

class Student {
    int roll;
    int mark;
    boolean passed() {
        return mark >= 40;
    }
}

passed মেথড যে অবজেক্টের মাধ্যমে কল হয়েছে, তার mark পড়ে। আলাদা mark প্যারামিটার লাগে না। দরকারি স্টেট সেই Student-এর কাছেই আছে। first.passed() কল করলে first-এর অবজেক্ট ব্যবহার হয়। second.passed() অন্য অবজেক্টের মান দেখতে পারে।

+---------------------+
| Student             |
+---------------------+
| roll: int           |
| mark: int           |
+---------------------+
| passed(): boolean   |
+---------------------+

এটি UML-এর মতো একটি সহজ ক্লাসের বাক্স। ওপরের ঘরে ক্লাসের নাম, মাঝের ঘরে অ্যাট্রিবিউট আর নিচের ঘরে অপারেশন থাকে। ডায়াগ্রাম একটি টাইপ বর্ণনা করে। ওই টাইপ থেকে বানানো প্রতিটি অবজেক্ট আলাদা করে দেখায় না।

রেফারেন্স আর অবজেক্ট আলাদা করে দেখো

first  -----> Student অবজেক্ট A
              roll = 17
              mark = 75

second -----> Student অবজেক্ট B
              roll = 24
              mark = 35

রেফারেন্স ভেরিয়েবল এমন একটি মান রাখে, যা দিয়ে একটি অবজেক্টকে চেনা যায়। new এক্সপ্রেশন অবজেক্ট তৈরি করে তার রেফারেন্স দেয়। অ্যাসাইনমেন্ট সেই রেফারেন্স ভেরিয়েবলে রাখে। কাজগুলো সম্পর্কিত, তবে শুধু ভেরিয়েবল ঘোষণা করলেই Student তৈরি হয় না।

new Student() চললে Java অবজেক্টের জায়গা তৈরি করে। initialization শেষ হওয়ার আগেই ফিল্ডে ডিফল্ট মান বসে। এখানে int ফিল্ডগুলো শূন্য দিয়ে শুরু হয়। কিন্তু লোকাল Student ভেরিয়েবলে নিশ্চিতভাবে মান অ্যাসাইন করার আগে পড়া যাবে না। ফিল্ডের ডিফল্ট আছে বলে সব লোকাল ভেরিয়েবল নিজে থেকে ব্যবহারযোগ্য হয় না।

Student second = first লিখলে রেফারেন্সের মান কপি হয়। তখন দুটি তীরই অবজেক্ট A-তে পৌঁছায়। পরে second.mark-এ মান দিলে সেই শেয়ার করা অবজেক্টের নম্বর বদলায়। নতুন Student তৈরি হয় না, first-এর তীরও সরে না।

C জানা থাকলে শেয়ার করা ডেটায় পৌঁছানোর দিক দিয়ে রেফারেন্সকে পয়েন্টারের সঙ্গে তুলনা করতে পারো। তবে Java এই অবজেক্টের জন্য পয়েন্টারের হিসাব বা নিজে free করার সুযোগ দেয় না। অবজেক্টে আর পৌঁছানো না গেলে garbage collection তার মেমরি ফেরত নিতে পারে। সঙ্গে সঙ্গে নেবে, এমন নিশ্চয়তা নেই।

Student ইনস্ট্যান্স বানাও, তুলনা করো আর শেয়ার করো

প্রথমে একটি Student বানিয়ে পাসের সিদ্ধান্ত কল করো। এরপর দুটি শিক্ষার্থী আলাদা রাখো, ইচ্ছা করে একই অবজেক্টের আরেক রেফারেন্স বানাও, আর ডিফল্ট ফিল্ড দেখো। কয়টি অবজেক্ট আছে অনুমান করতে new এক্সপ্রেশন গুনে দেখো।

একজন শিক্ষার্থীর ফল

অবজেক্টে roll হলো 17, mark হলো 75। passed সেই নম্বর পড়ে true দেয়।

স্বাধীন দুটি শিক্ষার্থী

first আর second আলাদা Student অবজেক্টে পৌঁছায়। তাদের নম্বর থেকে পাসের সিদ্ধান্তও আলাদা আসে।

এক শিক্ষার্থীর দুটি রেফারেন্স

দুই ভেরিয়েবল একটি অবজেক্টেই পৌঁছায়। second দিয়ে তার নম্বর বদলালে first দিয়েও পরিবর্তন দেখা যায়।

ফিল্ডের ডিফল্ট মান

int ফিল্ডের শুরুর মান শূন্য। শূন্য নম্বর পাসের সীমা পূরণ করে না।

মেম্বার বাড়ানোর আগে দায়িত্ব ঠিক করো

কাজের ক্লাসের দায়িত্ব নির্দিষ্ট থাকে। Student রোল আর ফলসংক্রান্ত স্টেট রাখতে পারে। কিন্তু ক্যাম্পাসের সব রিপোর্ট প্রিন্ট বা সব ইনপুট ফাইল পড়ার দায়িত্ব তার দরকার নেই। ইনপুটের কোড অবজেক্ট বানিয়ে তার অপারেশন কল করতে পারে। সম্পর্কহীন কাজ বাইরে রাখলে ক্লাস বোঝা সহজ থাকে।

নাম দেখে ক্লাসের বর্ণনা আর ইনস্ট্যান্স আলাদা বোঝা উচিত। Student ক্লাসের নাম। firstStudent বা applicant রেফারেন্সের নাম হতে পারে। ভেরিয়েবলের নাম অবজেক্টের পরিচয়ের অংশ হয় না। আলাদা নামের দুটি ভেরিয়েবল একই ইনস্ট্যান্স দেখাতে পারে।

আরেকটি ফিল্ডে ফল জমিয়ে না রেখে মেথড দিয়ে হিসাব করতে পারো। mark-এর সঙ্গে passed ফ্ল্যাগও রাখলে দুটিকে মিলিয়ে রাখতে হবে। mark থেকে passed হিসাব করলে একই তথ্য দুবার রাখতে হয় না। দুটি ফিল্ড একই তথ্য দিলে ভাবো, একটি অন্যটি থেকে বের করা যায় কি না।

Student রেফারেন্সের অ্যারে বানালেই Student অবজেক্ট থাকে না। new Student[n] এমন অ্যারে বানায়, যার সব এলিমেন্ট শুরুতে null। কোনো অবস্থান দিয়ে মেথড কলের আগে সেখানে বানানো Student বসাও। রাখার অ্যারে আর তার ভেতরের অবজেক্টগুলো আলাদাভাবে তৈরি হয়।

শুরুর স্টেটে নিয়ম লাগলে এই মডেল আরও কাজে দেয়। খালি অবজেক্ট বানিয়ে কয়েকটি অ্যাসাইনমেন্ট মনে রাখার বদলে কনস্ট্রাক্টর দিয়ে মান বসাতে পারো। পরের পাঠে মেমরির একই ছবির ওপর সেই ধাপ যোগ হবে।

ভেরিয়েবলের নামের বদলে অবজেক্ট গুনো

ঘোষণা করেই অবজেক্ট তৈরি হয়েছে ভাবা

মেথডের ভেতরে Student student; লিখলে অবজেক্ট হয় না। পড়ার আগে উপযুক্ত রেফারেন্স অ্যাসাইন করো। new দিয়ে সেই রেফারেন্স পেতে পারো। আগের কোনো রেফারেন্স কপি করেও পেতে পারো।

আরেকটি রেফারেন্সকে অবজেক্টের কপি ভাবা

অ্যাসাইনমেন্টে রেফারেন্সের মান কপি হয়। আলাদা স্টেট চাইলে আরেকটি অবজেক্ট বানাও। তোমার ডিজাইন অনুযায়ী দরকারি ফিল্ডের মান কপি করো। পরে সমতা আর শেয়ার করা নিয়ে আরও বিস্তারিত শিখবে।

মেথডকে ফিল্ড হিসেবে পড়া

passed()-এ বন্ধনী আছে, তাই এটি মেথড কল। mark হলো ফিল্ড ব্যবহার। মেথড প্রতিবার চলার সময় বর্তমান স্টেট থেকে নতুন উত্তর হিসাব করতে পারে।

সাধারণ ক্লাস দিয়েই শুরু করা যায়

Student মডেলে Java 17-এর সাধারণ ক্লাসের কাঠামো আছে। preview feature নেই। record আর বিশেষ ধরনের অন্য টাইপ পরে আসবে। আগে অবজেক্ট আর রেফারেন্সের মূল ছবি বুঝলে পরে বিকল্পগুলো বেছে নেওয়া সহজ হবে।

কোন অবজেক্টের স্টেট পড়ছ অনুসরণ করো

ক্লাস ফিল্ড আর অপারেশন বর্ণনা করে। new দিয়ে ইনস্ট্যান্স তৈরি হয়। রেফারেন্স আলাদা অবজেক্টেও যেতে পারে, একই অবজেক্টও শেয়ার করতে পারে। তৈরির সময়ই অর্থপূর্ণ স্টেট দিতে কনস্ট্রাক্টর শেখো।
