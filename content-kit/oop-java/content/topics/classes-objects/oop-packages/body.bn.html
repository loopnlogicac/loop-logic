বড় প্রজেক্টে টাইপের জন্য ঠিকানা দাও

দুটি বিভাগেই Result নামে ফর্ম থাকতে পারে। বিভাগের পুরো নাম থাকলে আলাদা করতে পারো। প্যাকেজ Java-র টাইপগুলোকে namespace দেয়। অর্থাৎ ছোট ক্লাসের নামটিও প্রোগ্রামের নির্দিষ্ট এলাকার অংশ হিসেবে চেনা যায়।

যেমন, campus.model.Student দিয়ে মডেলের টাইপ আর campus.app.App দিয়ে অ্যাপ্লিকেশন চালুর ক্লাস বোঝাতে পারো। ডট দিয়ে যোগ করা অংশগুলো qualified name তৈরি করে। টাইপের প্যাকেজ package-private আর protected অ্যাক্সেসেও প্রভাব ফেলে। তাই এটা শুধু ফোল্ডারের সাজসজ্জা নয়।

এই পাঠে তিনটি সম্পর্কিত বিষয় আলাদা করবে: সোর্সের নাম, ফাইল সাজানোর ধরন আর চালানোর সময় ক্লাস খোঁজা। এগুলো গুলিয়ে ফেললে চালু করার ভুল দুর্বোধ্য লাগে। স্তরগুলো আলাদা করে ধরলে প্যাকেজ কম্পাইল করা নিয়ম মেনে বারবার করতে পারবে। শুধু IDE-র ভেতরের রহস্য মনে হবে না।

ইমপোর্টের আগে প্যাকেজ ঘোষণা করো

সাধারণ compilation unit-এর শুরুতে package ঘোষণা থাকে, ইমপোর্ট আর টাইপের আগে। ওই সোর্সে ঘোষণা করা সব top-level টাইপ সেই প্যাকেজের সদস্য। প্যাকেজ প্রতিটি টাইপের পরিচয়ের অংশ।

package campus.model;

public class Student {
    private int roll;
}

এটি package কোথায় বসে দেখানোর জন্য ঘোষণার অংশ। প্রজেক্টে public Student টাইপ Student.java-তে থাকবে। অন্য প্যাকেজের অ্যাপ্লিকেশন পুরো নাম বা ইমপোর্ট দিয়ে এটি ব্যবহার করতে পারে। তবে টাইপ আর ব্যবহৃত কনস্ট্রাক্টর বা মেম্বারের অ্যাক্সেসও থাকতে হবে।

package campus.app;

import campus.model.Student;
import java.util.Arrays;
import static java.lang.Math.max;

ইমপোর্ট ঘোষণা ওই সোর্স ফাইলে নামটি ছোট করে ব্যবহারের সুযোগ দেয়। একই প্যাকেজের অন্য ফাইলে নিজে থেকে প্রযোজ্য হয় না। package ঘোষণা সদস্যপদ ঠিক করে। ইমপোর্ট শুধু অনুমতি থাকা টাইপ বা মেম্বারের নাম কীভাবে লিখবে, তাতে প্রভাব ফেলে।

একটি মূল ফোল্ডারের নিচে পুরো নামের পথ সাজাও

project/
  src/
    campus/
      model/
        Student.java
      app/
        App.java
  classes/
    campus/
      model/
        Student.class
      app/
        App.class

src-এর নিচে প্যাকেজের প্রতিটি অংশ অনুযায়ী সোর্স ফোল্ডার সাজানো আছে। কম্পাইলারের -d অপশন আউটপুটের মূল ফোল্ডার বেছে নেয়। javac তার নিচে কম্পাইল করা ক্লাসের জন্য প্যাকেজের ফোল্ডার বানায়। src আর classes প্রজেক্টের পছন্দ করা মূল ফোল্ডার। প্যাকেজের নামের অংশ নয়।

প্রজেক্ট ফোল্ডার থেকে নিচের মতো দুটি সোর্স classes-এ কম্পাইল করো। App-এ অ্যাপ্লিকেশন শুরুর প্রচলিত main মেথড থাকে। Student হলো App-এর ব্যবহারের অনুমতি থাকা টাইপ। কম্পাইলারের দরকার হলে নির্ভরতার সোর্স ফাইল বা উপযুক্ত classpath দাও।

javac --release 17 -d classes src/campus/model/Student.java src/campus/app/App.java
java -cp classes campus.app.App

চালু করার নাম campus.app.App, কোনো ফাইলের নাম নয়। classpath-এর মূল হলো classes। রানটাইম তার নিচে campus/app/App.class যোগ করে খোঁজে। classes/campus/app থেকে খোঁজা শুরু করলে এই পুরো নামের জন্য মূল ফোল্ডার অতিরিক্ত নিচে পড়ে যায়।

Classpath হলো ক্লাসের সংজ্ঞা আর রিসোর্স খোঁজার পথের তালিকা। ছোট এই কাঠামোতে একটি ফোল্ডারই যথেষ্ট। বড় অ্যাপ্লিকেশনে একাধিক মূল ফোল্ডার আর আর্কাইভ ফাইল থাকতে পারে। পুরো binary name আর অপারেটিং সিস্টেমের পথের বিভাজক আলাদা রাখো।

চালানোর উদাহরণগুলো নামহীন প্যাকেজে আছে, যাতে প্রতিটি একটি সম্পূর্ণ স্বতন্ত্র সোর্স হয়। লাইব্রেরি ইমপোর্ট দিয়ে একাধিক ফাইলের প্রজেক্ট ছাড়াই একই নামের নিয়ম দেখা যায়। package-এর অংশ আর ফোল্ডারের ডায়াগ্রামে নিজের নাম দেওয়া প্রজেক্ট টাইপে নিয়মের ব্যবহার দেখানো হয়েছে।

লাইব্রেরির টাইপ আর বাছা মেম্বারের নাম লেখো

Arrays-এর উদাহরণে সাধারণ টাইপ ইমপোর্ট আছে। LocalDate-এ পুরো নাম আর নির্দিষ্ট তারিখ আছে। Math-এ বাছা static মেথড ইমপোর্ট করা হয়েছে। StringBuilder দেখায় java.lang-এর টাইপ নিজে থেকেই ছোট নামে পাওয়া যায়।

লাইব্রেরির টাইপ ইমপোর্ট

ইমপোর্টে Arrays নামটি java.util.Arrays-এর ছোট নাম হয়। লাইব্রেরির কোড সোর্সে কপি হয় না।

পুরো নাম ব্যবহার

পুরো প্যাকেজের নাম থাকায় ইমপোর্ট লাগে না। নির্দিষ্ট তারিখ থেকে 2026-11-19 প্রিন্ট হয়। বর্তমান ঘড়ির ওপর নির্ভর করে না।

বাছা static অপারেশন ইমপোর্ট

static import থাকায় প্রতিবার কলের আগে Math না লিখেও max আর abs ব্যবহার করা যায়।

এক টাইপের নাম লেখার দুটি উপায়

StringBuilder আছে java.lang-এ। ছোট নাম আর পুরো নাম একই লাইব্রেরি টাইপকে বোঝায়।

ইমপোর্ট নাম চিনতে সাহায্য করে, কোড সরায় না

import java.util.Arrays-এর মতো সাধারণ ইমপোর্ট Arrays-কে ছোট টাইপের নাম হিসেবে দেয়। চাইলে প্রতিবার java.util.Arrays লিখতে পারো। দুটি নাম একই টাইপের। ইমপোর্ট লাইব্রেরির বাস্তবায়ন তোমার সোর্সে কপি করে না।

String, Integer আর StringBuilder-সহ java.lang-এর টাইপ ছোট নামে নিজে থেকেই পাওয়া যায়। একই প্যাকেজের ব্যবহারযোগ্য টাইপেও সাধারণ টাইপ ইমপোর্ট লাগে না। এই সুবিধা মানে স্ট্যান্ডার্ড লাইব্রেরির সব প্যাকেজ নিজে থেকে ইমপোর্ট হয় না।

টাইপের wildcard import একটি প্যাকেজের ব্যবহারযোগ্য টাইপগুলো ধরে। ভেতরের প্যাকেজগুলো একে একে ইমপোর্ট করে না। নামের ডটে সম্পর্ক থাকলেও java.util আর java.util.concurrent আলাদা প্যাকেজ। import java.util.* লিখলে concurrent-এর সব টাইপ ছোট নামে পাও না।

নির্ভরতা পড়া সহজ হলে নির্দিষ্ট ইমপোর্ট বেছে নাও। একাধিক wildcard-এর আড়ালে জরুরি নাম ঢাকার চেয়ে দীর্ঘ তালিকাও পরিষ্কার হতে পারে। ছোট উদাহরণে খুব কম ব্যবহৃত একটি টাইপের পুরো নাম লিখলেই যথেষ্ট হতে পারে। আরেকটি ইমপোর্ট লাগবেই না।

দুটি লাইব্রেরিতে Date থাকলে একই ছোট নামে দুটো single-type import দিলে দ্বন্দ্ব হয়। একটি ইমপোর্ট করে অন্যটির পুরো নাম লেখো। অথবা দুটিরই পুরো নাম লেখো। সাধারণ ইমপোর্টে as কিওয়ার্ড দিয়ে টাইপের বিকল্প নাম দেওয়ার ব্যবস্থা Java-তে নেই।

ইমপোর্ট করলেই সঙ্গে সঙ্গে ক্লাসের initialization হয় না। এটি কম্পাইলের সময় নাম চিনতে সাহায্য করে। রানটাইমে লোড আর initialization আলাদা ব্যবহারের নিয়মে হয়। ইমপোর্টে ক্লাসের নাম দেখেই static ব্লক চলবে ভাববে না।

static নাম ভেবে ছোট করো

Static import দিয়ে ব্যবহার করার অনুমতি থাকা static মেম্বার ছোট নামে পাও। import static java.lang.Math.max থাকলে Math.max(a, b)-এর বদলে max(a, b) লিখতে পারো। গাণিতিক কনস্ট্যান্টের মতো static ফিল্ডও ইমপোর্ট করা যায়।

static import অবজেক্ট তৈরির ব্যবস্থা নয়। অন্য মেথডের লোকাল ভেরিয়েবলও আনতে পারে না। private অ্যাক্সেস পাশ কাটায় না। পরিচিত কয়েকটি কাজের জন্য নির্দিষ্ট static import পরিষ্কার হতে পারে। কিন্তু অনেক ছোট নাম থাকলে কোন বিহেভিয়ার কোথা থেকে এসেছে, বোঝা কঠিন হয়।

ইনস্ট্যান্স মেথডের জন্য কল গ্রহণ করার অবজেক্ট লাগে। তাই আলাদা static অপারেশন হিসেবে সেটি ইমপোর্ট হয় না। নামের সুবিধায় মালিকানা বা অ্যাক্সেস বদলায় না। ছোট ইমপোর্ট করা নাম অস্পষ্ট হলে ঘোষণা করা টাইপের নিয়মে ফিরে যাও।

লোকাল ঘোষণা বা অন্য ইমপোর্টের মেম্বারের সঙ্গে নাম মিলে গেলে পুরো নাম লেখা পরিষ্কার করতে পারে। বুদ্ধি করে নাম মেলানোর চেয়ে ClassName.member লেখা প্রায়ই পড়তে সহজ। লক্ষ্য নির্ভরতা বোঝানো, প্রতিটি অক্ষর বাঁচানো নয়।

প্যাকেজের সীমানার বাস্তব প্রভাব আছে

package-private অ্যাক্সেসে সম্পর্কিত টাইপগুলো পুরো অ্যাপ্লিকেশনে public না হয়েও একসঙ্গে কাজ করতে পারে। যৌক্তিক সম্পর্ক আছে বলে টাইপ একসঙ্গে রাখো। কঠিন অ্যাক্সেস চেক অদৃশ্য হবে বলেই নয়। প্যাকেজে নির্দিষ্ট দায়িত্বের এলাকা বোঝা উচিত।

প্যাকেজের নাম ইনহেরিট্যান্সের সম্পর্ক তৈরি করে না। অ্যাক্সেস চেকে campus.model আর campus.model.internal আলাদা প্যাকেজ। নামে ভেতরের প্যাকেজ মনে হলেও তার টাইপ আগের প্যাকেজের package-private অ্যাক্সেস পায় না।

ছোট পরীক্ষায় নামহীন প্যাকেজ সুবিধার। কিন্তু আবার ব্যবহার করার অ্যাপ্লিকেশন টাইপের জন্য উপযুক্ত নয়। নামযুক্ত প্যাকেজের কোড নামহীন প্যাকেজের ক্লাস ইমপোর্ট করতে পারে না। প্রজেক্ট বড় হলে সহযোগী টাইপগুলো ভেবে নাম দেওয়া প্যাকেজে নাও।

এডিটর এই ফোল্ডারের কাঠামো সামলাতে পারে। তবুও সমস্যা খুঁজতে source root, output root আর চালানোর ক্লাসের সেটিং দেখো। ঘোষণা না বদলে নিজে ফোল্ডারের নাম বদলালে ফাইলের দেখা অবস্থান আর ঘোষিত টাইপের নাম অমিল হতে পারে।

প্রতিটি ধাপে ঠিক নামটি ব্যবহার করো

ক্লাসের নাম হিসেবে সোর্সের পথ চালানো

কম্পাইল করা প্যাকেজের ক্লাসে java-কে ডট দেওয়া নাম দাও। -cp দিয়ে মূল ফোল্ডার সেট করো। শেষে .class দেবে না, পুরো ক্লাসের নামেও পথের বিভাজক লিখবে না।

ইমপোর্ট অনুমতি দেবে আশা করা

public টাইপের কনস্ট্রাক্টর বা মেথড private হতে পারে। package-private টাইপ ইমপোর্ট করলেই public হয় না। নাম মেলানো আর অ্যাক্সেসের চেক আলাদা করে সমাধান করো।

ক্লাসের পরে package লেখা

ঘোষণাটি পুরো compilation unit-এর পরিচয় দেয়। ইমপোর্ট আর টাইপ ঘোষণার আগে আসে। main-এর ভেতরে বা প্রতিটি ফিল্ডের আগে বারবার বসানোর স্টেটমেন্ট নয়।

প্যাকেজ আর মডিউল আলাদা স্তর

নাম দেওয়া প্যাকেজ আর ইমপোর্ট উপরে দেখানো কাঠামোতে Java 17-তে চলে। static import এসেছে Java 5-এ। পরে Java মডিউল এসেছে, যা সাজানোর আরেকটি স্তর দেয়। শুধু প্যাকেজের নাম দিয়ে মডিউল ঘোষণা হয় না।

নামের এলাকা, ফাইলের পথ আর শুরুর মূল ফোল্ডার মেলাও

টাইপের নাম সাজাতে প্যাকেজ নাও। অনুমতি থাকা নাম ছোট করতে ইমপোর্ট নাও। কম্পাইল করা কোড চালাতে প্যাকেজের ফোল্ডারের ওপর classpath-এর মূল রাখো। এরপর প্রিমিটিভ মানকে অবজেক্টভিত্তিক API-র সঙ্গে যুক্ত করতে র‍্যাপার ক্লাস আর autoboxing শেখো।
