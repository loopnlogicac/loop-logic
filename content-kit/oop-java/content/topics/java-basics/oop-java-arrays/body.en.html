One ordered container, many values

A marks register needs more than one variable named mark. An array groups values of the same element type in a fixed sequence. You use an index to select a position, much like using a numbered row in a register.

In Java, an array is an object. An array variable holds a reference to that object, rather than the elements inside the variable itself. Creating another reference does not copy its elements. Creating another array gives you separate storage.

If you know C arrays, remember two differences immediately. Java arrays know their length, and every element access is checked. They do not decay into raw pointers for arithmetic. A two-dimensional Java array is also an array of row references, so rows need not have equal lengths.

Create an array and name its bounds

Use new when the length is known but values will arrive later. Use an initializer when the initial values are already known. The length is fixed for that object, even though a variable may later refer to a different array.

int[] marks = new int[3];
int[] rolls = {11, 12, 13};
int[][] groups = {{1, 2}, {3}};
int count = marks.length;

Array length is a field, so it has no parentheses. The first index is zero and the last is length minus one. A new int array starts with zero-valued elements. Other primitive arrays have their own zero-like defaults; reference arrays start with null references.

A jagged array has rows of different lengths. The outer length counts rows, not all integers. groups[0].length counts elements in the first row. A safe nested loop uses the current row's length for its inner bound.

Writing new int[3][] allocates only the outer array. Its three row references begin as null. You must allocate each row before reading its length or elements. Writing new int[3][2] creates the outer array and three allocated rows of length two.

An empty row and a null row are different. An empty row exists with length zero; a null reference points to no row. A foreach loop over an empty row performs no work. Trying to read length through a null row fails before any element loop begins.

Array allocation receives an int length. Zero is valid and produces an empty object. A negative length is invalid. Large lengths can exceed available memory, so practical input limits matter even when the index arithmetic looks correct.

Use the Arrays helpers deliberately

The java.util.Arrays class contains static array utilities. Import Arrays to shorten that fully qualified name. Arrays.toString produces readable text for a one-dimensional array. Printing the array reference directly does not list its contents in the same useful form.

Arrays.sort changes the array you pass to it. For an int array, it places values in ascending numeric order. Another reference to the same array sees that new order too. If you need to preserve the original order, make a copy before sorting.

A primitive array clone gives another array containing copied primitive values. For arrays of object references, copying the outer array still shares the referenced objects. This is a shallow copy. The distinction becomes important when you protect internal data in Encapsulation.

For a two-dimensional display, Arrays.deepToString can format nested contents. Understand the row structure before relying on the display. A neat printed rectangle does not prove that all possible arrays of that type must be rectangular.

When you trace a row sum, start a new accumulator for each row. Reusing the previous total without resetting it computes a running total across rows, which is a different question from independent row sums.

Respect both length and reference state

Using the last count as an index

An array of length three has positions zero, one and two. Accessing position three throws ArrayIndexOutOfBoundsException. Unlike C, a Java bounds error is checked rather than treated as an unchecked memory access.

Assuming every row matches the first

An inner loop bounded by values[0].length may fail on a shorter row. Use values[row].length after confirming that row exists. Keep the outer and inner counts separate in your trace.

Expecting assignment to duplicate elements

After int[] second = first, both variables reach one array. Sorting or writing through second changes what first sees. Request a new array and copy values when independent state is required.

No newer array syntax is needed

The array forms here work with Java 17 and much earlier releases. The utilities are standard library methods rather than new language syntax. No manual free operation is needed when an array becomes unreachable.
