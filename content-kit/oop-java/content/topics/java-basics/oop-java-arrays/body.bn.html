একটি সাজানো জায়গায় অনেক মান

নম্বরের রেজিস্টারে শুধু mark নামের একটি ভেরিয়েবল দিয়ে কাজ হয় না। অ্যারে একই এলিমেন্ট টাইপের একদল মান নির্দিষ্ট ক্রমে রাখে। রেজিস্টারের নম্বর দেওয়া সারি বেছে নেওয়ার মতো ইনডেক্স দিয়ে একটি অবস্থান বেছে নাও।

Java-তে অ্যারে একটি অবজেক্ট। অ্যারে ভেরিয়েবলের ভেতরে এলিমেন্টগুলো থাকে না; অবজেক্টটির রেফারেন্স থাকে। আরেকটি রেফারেন্স বানালে এলিমেন্ট কপি হয় না। নতুন অ্যারে তৈরি করলে আলাদা জায়গা পাও।

C-এর অ্যারে জানলে দুটি পার্থক্য শুরুতেই মনে রাখো। Java-র অ্যারেতে নিজের দৈর্ঘ্য থাকে, আর প্রতিবার এলিমেন্ট ব্যবহার করার সময় সীমা চেক হয়। অ্যারে সরাসরি পয়েন্টারে বদলে গিয়ে পয়েন্টারের হিসাব করতে দেয় না। দুই মাত্রার Java অ্যারেও আসলে সারির রেফারেন্সের অ্যারে। তাই সব সারির দৈর্ঘ্য সমান হওয়া জরুরি নয়।

অ্যারে বানাও, সীমা বুঝে নাও

দৈর্ঘ্য জানা আছে কিন্তু মান পরে আসবে, এমন হলে new ব্যবহার করো। শুরুর মানগুলো জানা থাকলে initializer নাও। ওই অ্যারে অবজেক্টের দৈর্ঘ্য স্থির। তবে ভেরিয়েবল পরে অন্য অ্যারেকে দেখাতে পারে।

int[] marks = new int[3];
int[] rolls = {11, 12, 13};
int[][] groups = {{1, 2}, {3}};
int count = marks.length;

অ্যারের length একটি ফিল্ড, তাই পরে বন্ধনী দেবে না। প্রথম ইনডেক্স শূন্য, শেষটি length থেকে এক কম। নতুন int অ্যারের সব এলিমেন্ট শুরুতে শূন্য থাকে। অন্য প্রিমিটিভ অ্যারেতে তাদের টাইপ অনুযায়ী শূন্যজাতীয় ডিফল্ট মান থাকে। রেফারেন্স অ্যারেতে শুরুতে null থাকে।

বাইরের অ্যারে আর সারিগুলো এঁকে দেখো

groups ----> বাইরের অ্যারে, দৈর্ঘ্য ৩
             [0] ----> [11, 12]   দৈর্ঘ্য ২
             [1] ----> [21]       দৈর্ঘ্য ১
             [2] ----> []         দৈর্ঘ্য ০

Jagged array মানে যে অ্যারের সারিগুলোর দৈর্ঘ্য আলাদা। বাইরের length দিয়ে সারির সংখ্যা পাও, মোট পূর্ণসংখ্যার সংখ্যা নয়। groups[0].length প্রথম সারির এলিমেন্ট গুনে। নিরাপদ nested loop-এ ভেতরের সীমা হিসেবে বর্তমান সারির length ব্যবহার করো।

new int[3][] লিখলে শুধু বাইরের অ্যারে তৈরি হয়। তার তিনটি সারির রেফারেন্স শুরুতে null। কোনো সারির length বা এলিমেন্ট পড়ার আগে সেই সারি তৈরি করতে হবে। new int[3][2] লিখলে বাইরের অ্যারের সঙ্গে দুই এলিমেন্টের তিনটি সারিও তৈরি হয়।

খালি সারি আর null সারি এক নয়। খালি সারি আছে, তার দৈর্ঘ্য শূন্য। null কোনো সারিকে দেখায় না। খালি সারিতে foreach লুপ কোনো কাজ করে না। কিন্তু null সারির length পড়তে গেলেই ব্যর্থ হবে; এলিমেন্টের লুপ পর্যন্ত পৌঁছাবে না।

অ্যারে তৈরির দৈর্ঘ্য int হয়। শূন্য বৈধ, এতে খালি অবজেক্ট হয়। ঋণাত্মক দৈর্ঘ্য অবৈধ। খুব বড় দৈর্ঘ্যে মেমরি ফুরাতে পারে। তাই ইনডেক্সের হিসাব ঠিক হলেও বাস্তবে ইনপুটের সীমা রাখা জরুরি।

ডিফল্ট মান, সাজানো আর নিরাপদ ব্যবহার দেখো

নতুন অ্যারেতে কী থাকে, লাইব্রেরির টুল কীভাবে ক্রম বদলায়, আর সারির দৈর্ঘ্য কেন সারির নিজের, উদাহরণে দেখবে। শেষের শর্তটি অবৈধ ইনডেক্সে পড়ার চেষ্টা হওয়ার আগেই তা সামলায়।

দৈর্ঘ্য আর ডিফল্ট মান

নতুন অ্যারেতে তিনটি int এলিমেন্ট আছে। প্রতিটির শুরুর মান শূন্য।

নম্বরের তালিকা সাজানো

সাজানোর ফলে marks নিজেই বদলায়। সহজে পড়ার মতো করে দেখালে পাও [40, 70, 90]।

আলাদা দৈর্ঘ্যের সারি

দুই মাত্রার অ্যারেতে সারির রেফারেন্স থাকে। এখানে সারিগুলোতে যথাক্রমে দুই, এক আর শূন্যটি এলিমেন্ট আছে।

পড়ার আগে ইনডেক্স যাচাই

length-এর সমান ইনডেক্স অ্যারের বাইরে। আগের শর্তটি ওই জায়গায় পড়ার চেষ্টা না করে Invalid index প্রিন্ট করে।

Arrays-এর সহায়ক মেথড বুঝে ব্যবহার করো

java.util.Arrays ক্লাসে অ্যারের জন্য static সহায়ক মেথড আছে। পুরো নাম ছোট করে লিখতে Arrays ইমপোর্ট করো। এক মাত্রার অ্যারেকে পড়ার উপযোগী টেক্সটে নিতে Arrays.toString ব্যবহার করো। সরাসরি অ্যারে রেফারেন্স প্রিন্ট করলে একইভাবে ভেতরের মানের তালিকা পাবে না।

Arrays.sort-কে যে অ্যারে দাও, সেটাই বদলে যায়। int অ্যারেতে ছোট থেকে বড় ক্রমে মান সাজায়। একই অ্যারের অন্য রেফারেন্সও নতুন ক্রম দেখবে। পুরোনো ক্রম দরকার হলে সাজানোর আগে কপি বানাও।

প্রিমিটিভ অ্যারে clone করলে নতুন অ্যারেতে প্রিমিটিভ মানের কপি পাও। অবজেক্ট রেফারেন্সের অ্যারেতে বাইরের অ্যারে কপি হলেও ভেতরের অবজেক্টগুলো শেয়ার হয়। একে shallow copy বলে। এনক্যাপসুলেশনে ভেতরের ডেটা রক্ষা করতে গেলে এই পার্থক্য কাজে লাগবে।

দুই মাত্রার অ্যারে দেখাতে Arrays.deepToString ভেতরের মানগুলোও সাজিয়ে দেয়। তবে আউটপুটের ওপর ভরসা করার আগে সারির গঠন বোঝো। সুন্দর আয়তক্ষেত্রের মতো প্রিন্ট হয়েছে মানেই ওই টাইপের সব অ্যারে আয়তক্ষেত্র হবে না।

প্রতিটি সারির যোগফল অনুসরণ করলে প্রতি সারিতে নতুন করে মোট শূন্য করো। আগের মোট রেখে দিলে সারি ধরে চলমান যোগফল হবে। সেটা প্রতিটি সারির আলাদা যোগফলের প্রশ্ন থেকে ভিন্ন।

দৈর্ঘ্য আর রেফারেন্সের অবস্থা দুটোই দেখো

এলিমেন্টের সংখ্যাকেই শেষ ইনডেক্স ধরা

দৈর্ঘ্য তিন হলে অবস্থান শূন্য, এক আর দুই। তিন নম্বর অবস্থান পড়লে ArrayIndexOutOfBoundsException হয়। C-এর মতো চেক ছাড়া মেমরি ব্যবহারের বদলে Java-তে সীমার ভুল ধরা হয়।

সব সারি প্রথমটির মতো ভাবা

values[0].length ধরে ভেতরের লুপ চালালে ছোট সারিতে ব্যর্থ হতে পারে। বর্তমান সারি আছে নিশ্চিত করে values[row].length নাও। হাতে হিসাবেও বাইরের আর ভেতরের সংখ্যা আলাদা রাখো।

অ্যাসাইন করলেই এলিমেন্টের কপি হবে ভাবা

int[] second = first-এর পরে দুই ভেরিয়েবল একই অ্যারেতে পৌঁছায়। second দিয়ে সাজালে বা লিখলে first-ও সেই বদল দেখে। স্বাধীন ডেটা চাইলে নতুন অ্যারে বানিয়ে মান কপি করো।

অ্যারের জন্য নতুন কোনো কাঠামো লাগছে না

এখানকার অ্যারের ধরন Java 17 আর অনেক পুরোনো রিলিজেও চলে। সহায়ক মেথডগুলো স্ট্যান্ডার্ড লাইব্রেরির অংশ, নতুন ভাষার কাঠামো নয়। অ্যারেতে আর পৌঁছানো না গেলে নিজে free কল করতে হয় না।

প্রতিটি রেফারেন্সের পেছনের অ্যারে অনুসরণ করো

একটি অ্যারের দৈর্ঘ্য স্থির। ইনডেক্স শূন্য থেকে শুরু হয় এবং সীমা চেক হয়। দুই মাত্রার অ্যারেতে সারির রেফারেন্স আর সারির নিজস্ব দৈর্ঘ্যের আরেক ধাপ যোগ হয়। এবার অ্যারের ডেটা রাখার সঙ্গে অপরিবর্তনীয় টেক্সট তুলনা করতে String আর StringBuilder শেখো।
