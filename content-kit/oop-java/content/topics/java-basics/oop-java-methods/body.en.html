Give a repeated calculation a name

Suppose three screens need the same credit calculation. Copying the arithmetic into each screen makes later changes harder. A method gives a piece of work a name, inputs and a result. You can call it wherever the same responsibility appears.

Java methods belong to a class. A static method belongs to the class rather than a particular instance. That is why a static helper can be called from static main without first constructing an object. Instance methods arrive later when their work depends on object state.

If you know C functions, parameters and return will feel familiar. Java's important rule is that every argument is passed by value. This remains true when that value is an object reference. Separating the copied value from the shared object will prevent a common misunderstanding.

Read a declaration as a promise

A method declaration states what callers may provide and what result they receive. The names inside its parameter list are local names used during that call. A non-void method must return an appropriate value along every normal path that completes.

static int totalCredits(int courses, int credit) {
    return courses * credit;
}
static void showHeading() {
    System.out.println("Result");
}

In an expression, a call such as totalCredits(4, 3) is replaced by its returned result. A void call is used for its action rather than a value. return can also leave a void method early without supplying an expression.

A copy of a reference is still a copy

An argument is the expression you supply at the call site. A parameter is the local variable that receives its value. For an int argument, the number is copied. Updating the parameter cannot change the caller's int variable. Return a changed number and assign it if that is your goal.

An array argument supplies a reference value. The parameter receives a second reference to the same array. Writing an array element through that reference changes the shared array object. Assigning a different array to the parameter changes only the parameter variable.

Think of copying a room number onto another slip of paper. Both slips can guide you to the same room. Changing the furniture affects everyone visiting that room. Writing another room number on one slip does not rewrite the other slip.

This is why Java is not pass by reference. The callee cannot directly reassign the caller's variable through an ordinary parameter. Sharing an object permits shared mutation, but sharing an object and sharing a variable are different mechanisms.

Overloads and recursive calls

Overloading means declaring the same method name with different parameter lists. The compiler chooses a suitable declaration using the argument types. An int argument can match an int overload, while a double argument can match a double overload. Return type alone cannot distinguish overloads. Overloading can make related operations easier to use, but unrelated work should have distinct names. A reader should expect all overloads of maximum to find a maximum. Avoid a set of overloads whose only connection is a convenient spelling. Recursion means a method calls itself. Each call has its own parameters and local variables. A base case answers a small problem without making another recursive call. The recursive case must reduce the problem towards that base case. For factorial, factorial(1) returns 1. factorial(2) waits for that result and multiplies it by 2. The waiting calls then multiply by 3, 4 and 5. The method does not reuse one n variable for all calls; each invocation keeps its own n. The call stack stores the work waiting to resume. Deep recursion can exhaust it and produce StackOverflowError. Java does not promise tail-call optimisation, so an iterative loop may be safer for very large input. Choose recursion when the problem structure makes it clear and the depth is bounded. Factorial also has a numeric limit. long can hold factorial values through 20, but not all larger factorials. A correct base case does not prevent arithmetic overflow. State the allowed input range and reason about both call depth and numeric growth.

Distinguish a result from a side effect

Ignoring a returned primitive

A helper that returns an increased mark does not change the original variable by itself. Assign its result if the caller should retain it. A clear return-based design often makes primitive calculations easier to follow.

Trying to replace the caller array

Reassigning an array parameter cannot redirect the caller reference. Return the new array when replacement is intended. Mutating elements and replacing the caller variable require different interfaces.

Missing progress in recursion

A base case is useless if calls never approach it. For a digit sum, dividing a nonnegative number by ten removes one digit. Check zero as well as a multi-digit value when tracing termination.

Stable method foundations

Static helpers, overloads and recursion are established Java features. Nothing on this page needs a feature newer than Java 17. Later object methods use the same argument-copying rule, even when their receivers have mutable state.
