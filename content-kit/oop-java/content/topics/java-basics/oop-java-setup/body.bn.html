সোর্স থেকে প্রোগ্রাম চালানো পর্যন্ত যে টুলগুলো লাগে

Java সোর্সকে মানুষের পড়ার উপযোগী করে লেখা ইনস্ট্রাকশন ভাবতে পারো। কম্পিউটারকে সেটা চালাতে হলে আগে আরেক রূপে নিতে হয়। JDK, অর্থাৎ Java Development Kit, সোর্স অনুবাদ আর ফলাফল চালানোর টুল দেয়। গ্রাফিক্যাল এডিটর ব্যবহার করলেও তোমার JDK লাগবে।

প্রধান দুটি টুল হলো javac আর java। প্রথমটি সোর্স কম্পাইল করে বাইটকোড বানায়। দ্বিতীয়টি Java রানটাইম দিয়ে একটি ক্লাস চালু করে। কাজ দুটি আলাদা করে বুঝলে ভুলটা কম্পাইলের সময় হচ্ছে, নাকি চালানোর সময়, সেটা ধরতে সুবিধা হয়।

C জানা থাকলে আগে কম্পাইল, তারপর চালানোর ধাপ পরিচিত লাগবে। পার্থক্যটা মাঝের ফলাফলে। সাধারণভাবে javac কোনো নির্দিষ্ট অপারেটিং সিস্টেমের সরাসরি চালানোর ফাইল বানায় না। ভার্চুয়াল মেশিনে চলার জন্য ক্লাস ফাইল তৈরি করে।

চালু করার জন্য ন্যূনতম কাঠামো

JVM, অর্থাৎ Java Virtual Machine, বাইটকোড চালায়। JRE বলতে JVM আর দরকারি লাইব্রেরিসহ রানটাইম এনভায়রনমেন্ট বোঝায়। আধুনিক ডিস্ট্রিবিউশনে আলাদা JRE ইনস্টলারের বদলে পুরো JDK বা প্রয়োজনমতো তৈরি রানটাইম থাকতে পারে।

class Main {
    public static void main(String[] args) {
        // Put the first statements here.
    }
}

এই কাঠামো Main.java নামে সেভ করো। ক্লাসের মধ্যে Java-র মেম্বারগুলো থাকে। এখানে main মেথড থেকেই প্রোগ্রাম চালু হবে। public static void থাকার কারণে লঞ্চার আগে অবজেক্ট তৈরি না করেই মেথডটি কল করতে পারে। String[] args-এ কমান্ড লাইনে দেওয়া টেক্সট আসে। আপাতত এটা ব্যবহার না করলেও চলবে।

কোন টুলের কী কাজ
টুলকাজদ্রুত যাচাই
JDKডেভেলপমেন্টের টুল আর রানটাইম দেওয়াদুটি কমান্ডই পাওয়া উচিত
javacসোর্স কম্পাইল করাjavac -version
javaরানটাইম চালু করাjava -version

ইনস্টল করো, কম্পাইল করো, তারপর চালাও

তোমার অপারেটিং সিস্টেমের জন্য JDK 17 বা JDK 21 ডিস্ট্রিবিউশন বেছে নাও। সেটার ইনস্টলার বা সিস্টেমের প্যাকেজ ম্যানেজার ব্যবহার করো। ডাউনলোডের উৎস আর প্রসেসরের আর্কিটেকচার মিলিয়ে নাও। ইনস্টলের ধাপ আলাদা হতে পারে, তবে ভার্সন দেখার কমান্ড দুটি দিয়ে টুল পাওয়া যাচ্ছে কি না বোঝা যায়।

ইনস্টলের পর নতুন টার্মিনাল খোলো। javac -version আর java -version চালাও। কমান্ড না পেলে JDK-র bin ফোল্ডার PATH-এ আছে কি না দেখো। PATH হলো কমান্ড খুঁজতে টার্মিনাল যেসব ফোল্ডারে দেখে, সেগুলোর তালিকা। শুধু রানটাইম ইনস্টল থাকলে java পাওয়া গেলেও javac নাও পেতে পারো।

কাজের জন্য একটি ফোল্ডার বানিয়ে সেখানে Main.java সেভ করো। টার্মিনালের বর্তমান ফোল্ডার সেখানে নিয়ে যাও। javac --release 17 Main.java দিয়ে কম্পাইল করো। সফল হলে সাধারণত কোনো বার্তা আসে না, আর Main.class তৈরি হয়। ব্যর্থ হলে এরর মেসেজে প্রথম যে জায়গা দেখায়, সেখান থেকে পড়ো।

একই ফোল্ডার থেকে java Main চালাও। ক্লাসের নামের পরে .class লিখবে না। লঞ্চার classpath-এ ক্লাস খোঁজে। এই সাধারণ ক্ষেত্রে বর্তমান ফোল্ডারও সেখানে থাকে। Main.class পেলে JVM-কে তার main মেথড চালাতে বলে।

--release 17 দিয়ে Java 17-এর ভাষার নিয়ম, API আর ক্লাস ফরম্যাট লক্ষ্য করে কম্পাইল করো। ইনস্টল করা কম্পাইলার নতুন হলেও পুরোনো রানটাইম সমর্থন করতে চাইলে এটা কাজে লাগে। অপশনটি পুরোনো রানটাইম ইনস্টল করে না। কোন সমর্থিত প্ল্যাটফর্মের জন্য ফলাফল বানাতে হবে, কম্পাইলারকে তা বলে।

চোখে দেখা যায় এমন আউটপুট দিয়ে শুরু করো

প্রথম শুভেচ্ছার প্রোগ্রাম দিয়ে সোর্স থেকে চালানো পর্যন্ত পুরো পথ যাচাই করো। এরপর আলাদা লাইনে লেখা আর একই লাইনে টুকরো টুকরো লেখা তুলনা করো। সোর্সে কোটেশন দিয়ে টেক্সটের সীমানা বোঝানো হয়। সেই কোটেশন আউটপুটে আসে না।

প্রথম শুভেচ্ছা

শুরুর মেথডটি এক লাইন প্রিন্ট করে। সেমিকোলন দিয়ে প্রিন্ট স্টেটমেন্ট শেষ হয়েছে।

দুটি স্টেটমেন্ট পরপর চলে

প্রথম স্টেটমেন্ট কোর্সের কোড প্রিন্ট করে। দ্বিতীয়টি ল্যাবের জন্য আলাদা লাইন দেয়।

প্রিন্ট করা অংশ জোড়া লাগানো

print-এর পরে কার্সর একই লাইনে থাকে। println দিয়ে 17 লেখার পর লাইন শেষ হয়।

এডিটর বেছে নাও, টার্মিনালের ধাপও বোঝো

IntelliJ IDEA, VS Code আর NetBeans দিয়ে Java কোড লেখা ও চালানো যায়। দরকার হলে Java প্রজেক্ট বেছে নাও বা এডিটরের Java সাপোর্ট ইনস্টল করো। প্রজেক্টে তোমার JDK আর language level 17 ঠিক করো। রান বাটনের নিচেও Java-র টুলগুলোই কাজ করে।

IDE নিজে থেকে আউটপুট ফোল্ডার, package ঘোষণা আর প্রজেক্ট সেটিং তৈরি করতে পারে। কোন সোর্স ফাইল বদলাচ্ছ আর কোন entry point থেকে চালাচ্ছ, দেখে নাও। প্রজেক্ট না চললে আগে দেখো IDE কোন JDK আর সোর্স ফাইল ব্যবহার করছে। আগে খোলা পুরোনো প্রজেক্টে আলাদা সেটিং থেকে যেতে পারে।

ইনপুটের অনুশীলনে Scanner ব্যবহার করবে। এটি লাইব্রেরির একটি সহায়ক ক্লাস, যা তোমার টাইপ করা ইনপুট পড়ে। Scanner input-এর মতো ঘোষণা দিয়ে রিডার ভেরিয়েবল ঘোষণা করা হয়। nextInt দিয়ে একটি পূর্ণসংখ্যার টোকেন পড়া যায়। ইনপুট ও আউটপুটের পাঠে পুরো আচরণ শিখবে। এখন দেওয়া কাঠামো কম্পাইল করে চালাতে মন দাও।

সোর্সের ভুল আর টুলের সমস্যা আলাদা করো

কমান্ড খুঁজে পাওয়া যাচ্ছে না

javac কমান্ড না পাওয়া মানে ইনস্টল বা PATH-এর সমস্যা। println-এর কোড বদলে এটা ঠিক হবে না। JDK ইনস্টল আছে কি না নিশ্চিত হও। তারপর টার্মিনাল আবার খুলে ভার্সন দেখো।

ক্লাস খুঁজে পাওয়া যাচ্ছে না

বর্তমান ফোল্ডার আর java-কে দেওয়া ক্লাসের নাম মিলিয়ে দেখো। সোর্স ফাইলের নাম, ক্লাসের নাম আর ফাইলের পথ আলাদা জিনিস। সোর্স সেভ করে আবার কম্পাইল করো। তারপর classpath-এর মূল ফোল্ডার থেকে সঠিক ক্লাস চালাও।

public ক্লাসের নাম আর ফাইলের নাম মেলেনি

সরাসরি ফাইলে থাকা ক্লাস public হলে তার নামের সঙ্গে সোর্স ফাইলের নাম মিলতে হবে। public class Main হলে Main.java ব্যবহার করো। বড় ও ছোট হাতের অক্ষরও মিলবে। Java-তে Main আর main আলাদা আইডেন্টিফায়ার।

পুরোনো রানটাইম ফলাফল লোড করতে পারছে না

Java 21 দরকার এমন ক্লাস সাধারণভাবে Java 17 রানটাইমে লোড হয় না। মানানসই রানটাইম নাও বা উপযুক্ত release target দিয়ে কম্পাইল করো। নেটিভ লাইব্রেরি আর নির্দিষ্ট প্ল্যাটফর্মের ফাইলপথও অন্য সিস্টেমে চালানোর সুবিধা কমাতে পারে।

কোন রিলিজের জন্য কম্পাইল করছ, স্পষ্ট রাখো

Java 17-তে উপরের প্রচলিত main সিগনেচার ব্যবহার করতে preview feature লাগে না। পরের কিছু রিলিজে চালু করার বাড়তি কাঠামো আছে। শুরুর এই পথে সেগুলো দরকার নেই। বাইটকোড যেখানে নেবে, সেখানে মানানসই JVM রাখো।

Java-তে কাজ করার একই ধাপ বারবার অনুসরণ করো

JDK ইনস্টল করো, সোর্স সেভ করো, কম্পাইল করো, তারপর ক্লাস চালাও। বাইটকোড অন্য কম্পিউটারে নেওয়া গেলেও সেখানে মানানসই JVM লাগবে। এবার ভেরিয়েবল আর টাইপ শিখে শুরুর মেথডে দরকারি মান রাখো।
