The tools between source and execution

Think of Java source as a set of instructions written for people. A machine needs another form before it can follow them. A JDK, or Java Development Kit, provides the tools that translate your source and run the result. You need a JDK even if you prefer a graphical editor.

The main tools are javac and java. The first compiles source into bytecode. The second launches a class using a Java runtime. Keeping these jobs separate helps you diagnose whether a problem happens during compilation or during execution.

If you know C, the compile-then-run rhythm will feel familiar. The important difference is the intermediate result. Ordinary javac compilation produces class files for a virtual machine rather than a native executable for one operating system.

The minimum launch shape

A JVM, or Java Virtual Machine, executes bytecode. A JRE means a runtime environment containing a JVM and needed libraries. Modern distributions may provide a full JDK or a custom runtime instead of a separate JRE installer.

class Main {
    public static void main(String[] args) {
        // Put the first statements here.
    }
}

Save this shape in Main.java. The class groups Java members. The main method is the traditional entry point used here. Its public static void form lets the launcher call it without first creating an object. String[] args holds command-line text; you can leave it unused for now.

Install, compile and launch

Choose a JDK 17 or JDK 21 distribution for your operating system. Use its installer or your system's package manager. Check the download source and select the correct processor architecture. Installation steps vary, but the two version commands provide the same useful confirmation.

Open a fresh terminal after installation. Run javac -version and java -version. If a command is missing, check whether the JDK bin folder is on PATH. PATH is the list of folders your terminal searches for commands. A runtime-only installation may provide java without javac.

Create a working folder and save Main.java there. Change the terminal's current folder to that location. Compile with javac --release 17 Main.java. A successful compile usually prints no message and creates Main.class. Read an error message from its first reported location when compilation fails.

Launch with java Main from the same folder. Do not append .class to the class name. The launcher searches its classpath, which includes the current folder by default in this simple case. It finds Main.class and asks the JVM to execute the main method.

The --release 17 option targets Java 17 language rules, APIs and class format. It is useful when your installed compiler is newer than the runtime you plan to support. It does not install an older runtime. It tells the compiler which supported platform level to target.

Choose an editor without losing the terminal picture

IntelliJ IDEA, VS Code and NetBeans can all help you edit and launch Java. Select a Java project or install the editor's Java support when needed. Configure the project to use your installed JDK and language level 17. A run button still relies on Java tools beneath the interface.

An IDE may create output folders, package declarations and project settings automatically. Inspect the source file you are editing and the entry point selected for running. When a project fails, first confirm which JDK and source file the IDE uses. An older open project can keep its own configuration.

Separate source errors from tool errors

The command cannot be found

A missing javac command is a tool installation or PATH problem. Editing a println statement cannot fix it. Confirm that a JDK is installed, then reopen the terminal and repeat the version check.

The class cannot be found

Check your current folder and the class name given to java. A source filename, a class name and a filesystem path are different things. Recompile after saving the source and launch the intended class from its classpath root.

The public name does not match the filename

If a top-level class is declared public, its name must match the source filename. For public class Main, use Main.java with matching case. Java identifiers are case-sensitive, including Main and main.

An older runtime rejects the result

A Java 17 runtime cannot generally load classes requiring Java 21. Use a compatible runtime or compile with an appropriate release target. Native libraries and platform-specific paths can also reduce portability.

Keep the release target explicit

Java 17 uses the traditional main signature shown above without preview features. Some later releases offer additional launch forms, but they are outside this starting path. Keep a compatible runtime available wherever you copy the bytecode.

A repeatable Java work cycle

Install a JDK, save source, compile it, then launch its class. Portable bytecode still needs a compatible JVM on the destination machine. Continue with variables and types to put useful values inside the launch method.
