কী ঢুকবে আর কী বের হবে, আগে ঠিক করো

নম্বরের শিটে মানগুলো কীভাবে সাজানো আছে না বললে প্রোগ্রাম তা বুঝতে পারে না। আসা টেক্সট থেকে ব্যবহারযোগ্য মান বের করাই ইনপুট পার্সিং। আউটপুট ফরম্যাটিংয়ে মানকে পড়ার উপযোগী টেক্সটে সাজাও। ইনপুট আর আউটপুটের নিয়ম পরিষ্কার থাকলে দুটো কাজই সহজ হয়।

পূর্ণসংখ্যা, দশমিক বা শব্দের টোকেন পড়তে Scanner সুবিধাজনক। পুরো লাইন নিজের মতো সামলাতে আর দ্রুত পার্স করতে BufferedReader কাজে লাগে। কোনো টুলই নম্বর বা রোলের অর্থ জানে না। সেই নিয়ম তোমার প্রোগ্রাম দেবে।

C-এর scanf জানা থাকলে খেয়াল করো, Java-র রিডার মান ফেরত দেয়। &mark-এর মতো অ্যাড্রেস লাগে না। তবে অবৈধ টেক্সট, কম ইনপুট আর পড়া বাকি থাকা লাইনের শেষ নিয়ে ভাবতে হবে। API বদলালেও ইনপুটের নিয়ম ঠিক করার দরকার যায় না।

টোকেন আর লাইন আলাদা একক

পার্স করার নিয়মে আলাদা হওয়া ইনপুটের একটি অংশ হলো টোকেন। Scanner সাধারণত স্পেস, ট্যাব বা লাইনের শেষ দিয়ে টোকেন আলাদা করে। next একটি টোকেন পড়ে, nextInt টোকেনকে পূর্ণসংখ্যা করে, nextDouble দশমিক করে। nextLine বর্তমান লাইনের বাকি অংশ পড়ে।

Scanner input = new Scanner(System.in);
int roll = input.nextInt();
input.nextLine();
String name = input.nextLine();

System.in ইনপুট স্ট্রিম দেয়। System.out সাধারণ টেক্সট আউটপুটের স্ট্রিম। Scanner আছে java.util-এ, তাই স্পষ্ট করে ইমপোর্ট করো। উদাহরণে try-with-resources ব্যবহার করা হয়েছে। এই ব্লক শেষ হলে রিডার বন্ধ হয়। এখানে System.in-ও বন্ধ হয়, যা একবার চলা ছোট প্রোগ্রামে ঠিক আছে।

একটি ইনপুট স্ট্রিম পড়ার কাজ একটি রিডার দিয়ে সমন্বয় করো। System.in-এ আলাদা আলাদা রিডার বসালে বাফার করা ডেটা অপ্রত্যাশিত জায়গায় আটকে থাকতে পারে। বড় অ্যাপ্লিকেশনে ইনপুট স্ট্রিম শেয়ার করলে কোন অংশ সেটা বন্ধ করবে, ঠিক করো।

কোন অক্ষরগুলো পড়া বাকি, অনুসরণ করো

nextInt অঙ্ক পড়ার পরে পরের লাইন শেষের চিহ্ন পড়া বাকি থাকতে পারে। তখন nextLine ওই চিহ্নের আগের বাকি টেক্সট ফেরত দেয়। সেটা প্রায়ই খালি String হয়। তোমার নাম হঠাৎ বাদ যায়নি; সংখ্যার লাইনের বাকি অংশই পড়েছে।

ইনপুটের নিয়মে নাম পরের লাইনে থাকলে আগে বর্তমান লাইনের বাকি অংশ পড়ে শেষ করো। তারপর আবার nextLine দিয়ে নাম পড়ো। সংখ্যার একই লাইনে নাম থাকলে আলাদা পার্সিং পরিকল্পনা লাগবে। কীভাবে ঠিক করবে, সেটা নির্ভর করে ইনপুট কীভাবে সাজানো আছে তার ওপর।

কয়টি পূর্ণসংখ্যা আসবে জানা না থাকলে nextInt-এর আগে hasNextInt নাও। ইনপুট শেষে চেকটি false হয়। তবে পরের টোকেন বৈধ int না হলেও false হয়। তাই অবৈধ ইনপুটের সব ভুল জানানোর জন্য এই চেক যথেষ্ট নয়। এই যোগফলের অনুশীলনে প্রতিটি টোকেন পূর্ণসংখ্যা হওয়ার নিশ্চয়তা আছে।

EOF মানে ইনপুট শেষ। টার্মিনালে এটি জানানোর কী অপারেটিং সিস্টেমভেদে বদলায়। ফাইল বা পাইপ থেকে পড়লে সব বাইট পড়া শেষে EOF আসে। আগে সংখ্যা দিয়ে কতটি মান আসবে বলা আর EOF পর্যন্ত পড়া আলাদা নিয়ম। সমস্যায় যেটা বলা আছে, সেটা মানো।

ছোট রেকর্ড পড়ো আর সাজিয়ে দেখাও

মানের সঙ্গে ইনপুট চাওয়ার বার্তাও দেখো। সংখ্যা আর নামের উদাহরণে টোকেন পড়া আর লাইন পড়া আলাদা করা আছে। শেষ দুটি উদাহরণেই যোগফল হয়। একটিতে টোকেন পড়ে, অন্যটিতে প্রতি লাইনে একটি পূর্ণসংখ্যা পড়ে।

দুটি নম্বর পড়া

দুটি টোকেন int মান হয়। বার্তায় print থাকায় মোটের পাশে একই লাইনে বার্তাটি থাকে।

সংখ্যার পরে একটি পুরো লাইন

বাড়তি nextLine রোলের পরের বাকি newline পড়ে নেয়। তার পরের কল পুরো নাম পড়ে।

দশমিকের নির্দিষ্ট ফরম্যাট

%.2f দশমিকের পরে দুটি অঙ্ক দেখায়। Locale.ROOT দিয়ে দশমিকের বিভাজক নির্দিষ্ট থাকে।

ইনপুট শেষ পর্যন্ত পূর্ণসংখ্যা যোগ

লুপ তিনটি পূর্ণসংখ্যার টোকেন পড়ে শেষে থামে। যোগফল হয় 15।

বাফার দিয়ে লাইন পড়া

readLine লাইনের শেষ চিহ্ন বাদ দিয়ে টেক্সট দেয়। প্রতিটি ফাঁকা নয় এমন লাইন থেকে একটি পূর্ণসংখ্যা পার্স করে মোট 12 হয়।

মান না বদলে দেখানোর ধরন ঠিক করো

System.out.printf ফরম্যাট প্যাটার্ন অনুযায়ী টেক্সট লেখে। %d পূর্ণসংখ্যা, %s টেক্সট, আর %.2f ভগ্নাংশের দুটি অঙ্কসহ floating-point মান দেখায়। %n প্ল্যাটফর্মের উপযুক্ত লাইন শেষের চিহ্ন দেয়। ফরম্যাটের সঙ্গে আর্গুমেন্টের টাইপ মেলাতে হবে।

String.format একই ধরনের প্যাটার্ন ব্যবহার করে, তবে String ফেরত দেয়। আরেক মেথডকে তৈরি করা লেবেল দিতে হলে এটা সুবিধাজনক। ফরম্যাট করা অঙ্ক সেভ করলে আসল সংখ্যার মান বদলায় না। ফরম্যাটিং শুধু দেখানোর ব্যবস্থা; টাকার নিখুঁত হিসাব রাখার বিকল্প নয়।

ডিফল্ট locale অনুযায়ী দশমিক আর সংখ্যার গ্রুপ আলাদা করার নিয়ম বদলাতে পারে। অনুশীলনে ডট চাইলে Locale.ROOT নাও। একই নিয়মে দশমিক পড়তে Scanner-এর locale-ও সেট করো। তা না হলে প্রোগ্রাম এক নিয়মে পড়ে আরেক নিয়মে প্রিন্ট করতে পারে।

লাইন ধরে কাজের জন্য BufferedReader

BufferedReader অক্ষরগুলো একসঙ্গে বাফারে এনে পড়ে। readLine লাইনের শেষ বাদ দিয়ে টেক্সট ফেরত দেয়। আর কোনো লাইন না থাকলে null দেয়। খালি লাইনও একটি লাইন, শুধু টেক্সট খালি। তাই এটা EOF নয়।

Integer.parseInt একটি String থেকে int বানায়। বাফার দিয়ে পড়ার উদাহরণে লাইনের দুই পাশের স্পেস বাদ দেওয়া হয়। লাইন ফাঁকা না হলেই পার্স করে। তাই ফাঁকা নয় এমন প্রতি লাইনে একটি পূর্ণসংখ্যা গ্রহণ করে। এক লাইনে কয়েকটি সংখ্যা থাকলে ইনপুটের নিয়ম অনুযায়ী লাইন ভাগ বা টোকেন আলাদা করতে হবে।

পড়ার সময় IOException হতে পারে। উদাহরণের main-এ throws IOException আছে, যাতে পড়ার ব্যর্থতা চুপ করে বাদ না যায়। এক্সেপশনের পাঠে ভুল সামলানো আর কাজ চালিয়ে যাওয়া শিখবে। বাফার দিয়ে পড়া প্রায়ই দ্রুত হয়। তবে ফল ঠিক হবে কি না, সেটা পার্স করার সিদ্ধান্তের ওপরও নির্ভর করে।

একটি লাইন আর একটি মান গুলিয়ে ফেলো না

পুরো নাম খালি আসছে

আগের টোকেন পড়ার পরে কী বাকি আছে দেখো। ইনপুটের নিয়ম অনুযায়ী পরের পুরো লাইন পড়ার আগে বর্তমান লাইনের বাকি অংশ পড়ে নাও। কোনো লাইনে আসল ডেটা থাকতে পারে, না বুঝে সেটা ফেলে দেবে না।

খালি লাইনেই লুপ থেমে যাচ্ছে

BufferedReader-এ EOF ধরতে null-এর সঙ্গে তুলনা করো। সমস্যা অনুযায়ী ফাঁকা লাইন বাদ দিতে, রাখতে বা প্রত্যাখ্যান করতে পারো। নিজে থেকে ইনপুট নেই ধরে না নিয়ে এর অর্থ স্পষ্ট করো।

প্রিন্টের দশমিক বিভাজক বদলে যাচ্ছে

সিস্টেমের locale-এ কমা থাকতে পারে। নির্দিষ্ট ফরম্যাটে ডট চাইলে স্থির locale দাও। %.2f-এ চাওয়া অঙ্ক শুধু দেখানোর ব্যাপার; এতে double-এর হিসাব নিখুঁত হয় না।

লাইব্রেরির জন্য কোন ভার্সন লাগে

Scanner আর ফরম্যাট করে আউটপুট Java 5 থেকে আছে। String.isBlank-এর জন্য Java 11 লাগে। তাই বাফার দিয়ে পড়ার উদাহরণগুলো Java 17-এর মধ্যেই পড়ে। এখানকার সব ইনপুট কনসোলের টেক্সট, GUI দিয়ে নেওয়া নয়।

ইনপুটের নিয়মের সঙ্গে পার্সার মেলাও

আলাদা মানের জন্য টোকেন নাও। একটি মানের ভেতর স্পেস দরকার হলে লাইন নাও। দরকারমতো দশমিক দেখানোর নিয়ম নির্দিষ্ট করো। এবার সম্পর্কিত ডেটা আর কাজ একসঙ্গে রাখতে ক্লাস আর অবজেক্ট শেখো।
