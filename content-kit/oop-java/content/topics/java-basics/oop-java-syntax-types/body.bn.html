কাজ অনুযায়ী মানের টাইপ বেছে নাও

নম্বর, CGPA আর পাস করেছে কি না—এই তিনটি আলাদা ধরনের তথ্য। ভেরিয়েবলের টাইপকে ডেটা রাখার বাক্সের লেবেল ভাবো। লেবেল দেখে Java বুঝবে কোন মান রাখা যাবে আর কী অপারেশন করা যাবে। ঠিক টাইপ বেছে নিলে প্রোগ্রাম চালানোর আগেই অনেক ভুল আটকায়।

প্রিমিটিভ টাইপ পূর্ণসংখ্যা বা boolean-এর মতো মৌলিক মান ধরে। Java-তে আটটি প্রিমিটিভ টাইপ আছে। অবজেক্ট রেফারেন্স আরেক ধরনের টাইপ; স্ট্রিং আর অ্যারের সঙ্গে সেগুলো দেখবে। তাই Java-র প্রতিটি মানকে অবজেক্ট ভাববে না।

C জানা থাকলে ব্রেস আর সেমিকোলন পরিচিত লাগবে। তবে কয়েকটি টাইপের ব্যাপারে Java, C-এর চেয়ে বেশি নির্দিষ্ট নিশ্চয়তা দেয়। সত্য-মিথ্যার boolean মানকেও সংখ্যা থেকে আলাদা রাখে। বানানের ছোট পার্থক্যের চেয়ে এই নিয়মগুলো বেশি জরুরি।

ভেরিয়েবল, কনস্ট্যান্ট আর মান দেখে টাইপ বোঝা

লোকাল ভেরিয়েবল ঘোষণায় টাইপ, নাম আর প্রায়ই শুরুর মান থাকে। লোকাল ভেরিয়েবল পড়ার আগে অবশ্যই মান অ্যাসাইন করা থাকতে হবে। অবজেক্টের ফিল্ডে ডিফল্ট মান থাকে। কিন্তু কোনো লোকাল int-এ মান না দিয়ে সেটা পড়া যাবে না।

int mark = 80;
double cgpa = 3.75;
boolean passed = mark >= 40;
final int CREDIT = 3;
var count = 4;

Type inference মানে শুরুর মান দেখে কম্পাইলার ঘোষিত টাইপ ঠিক করে। Java 10 থেকে লোকাল ভেরিয়েবলে var ব্যবহার করা যায়। এখানে count-এর টাইপ int-ই থাকবে। পরে তাতে টেক্সট অ্যাসাইন করলে টাইপের ভুল হবে। var দিয়ে ভেরিয়েবলের টাইপ চলার সময় বদলায় না।

অ্যাসাইন করার আগে হিসাবটা কোন টাইপে হচ্ছে দেখো

গাণিতিক এক্সপ্রেশনের হিসাব হয় তার অপারেন্ডগুলোর টাইপ অনুযায়ী। দুটি অপারেন্ডই int হলে ভাগও পূর্ণসংখ্যার নিয়মে হয়। ভগ্নাংশ শূন্যের দিকে বাদ যায়। তাই 7 / 2 হলো 3, আর -7 / 2 হলো -3। একটি অপারেন্ড double হলে floating-point ভাগ হয়।

কাস্ট দিয়ে তুমি স্পষ্টভাবে টাইপ বদলাতে বলো; বন্ধনীর মধ্যে টাইপ লিখতে হয়। int থেকে long করলে মান অক্ষুণ্ন থাকে। double থেকে int করলে ভগ্নাংশ বাদ যেতে পারে। বড় পূর্ণসংখ্যাকে byte করলে ওপরের বিট বাদ যেতে পারে। শুধু ফলাফল রাখার ভেরিয়েবলের টাইপ বদলালে আগের হিসাব বদলায় না।

ধরো, দুটি গণনার মানই 50000। int হিসেবে গুণ করলে ফল int-এর সীমা ছাড়িয়ে যায়। Java-র integer overflow নির্দিষ্ট নিয়মে ঘুরে অন্য মান দেয়। C-এর signed overflow নিয়ে যা জানো, এখানে সেই ধারণা বসাবে না। ভুল হয়ে যাওয়া ফল long-এ রাখলেও আসল গুণফল ফেরত আসে না।

গুণের আগে একটি অপারেন্ড long করো। সেই অপারেশনের জন্য অন্যটিও long-এ প্রমোট হবে, আর সঠিক গুণফল রাখা যাবে। শুধু শেষ ভেরিয়েবল নয়, মাঝের সবচেয়ে বড় ফলটাও ভাবতে হবে। মোট যোগ করা আর ফি হিসাবেও এই অভ্যাস কাজে লাগে।

floating-point-এ অনেক দশমিক ভগ্নাংশ আনুমানিকভাবে রাখা হয়। গড় বা মাপজোকের জন্য এটি উপযোগী, তবে দশমিক টাকার নিখুঁত হিসাব রাখার ব্যবস্থা নয়। ছোট ফরম্যাটিং উদাহরণ শুধু ফল দেখানো শেখায়, পুরো আর্থিক হিসাবের নীতি নয়। নিখুঁত অঙ্কের জন্য পরে উপযুক্ত উপস্থাপন বেছে নিতে পারবে।

হিসাবের ফল তুলনা করো

প্রতিটি লাইনের ফল বলার আগে অপারেন্ডের টাইপ পড়ো। উদাহরণগুলোতে পূর্ণসংখ্যার ভাগ, ছোট টাইপে কাস্ট, টাইপ অনুমান আর বড় টাইপে যাওয়া আলাদা করা আছে। কোন নিয়ম থেকে ফল আসছে, সেটা ধরো।

পূর্ণসংখ্যা আর দশমিকের ভাগ

155 / 2 পূর্ণসংখ্যার ভাগ, তাই 77 প্রিন্ট হয়। double অপারেন্ড থাকলে অর্ধেক নম্বরও থাকে; ফল 77.5।

স্পষ্টভাবে ছোট টাইপে কাস্ট

3.89-কে int করলে 3 পাও। 130-কে byte করলে নিচের আটটি বিট থাকে, ফলে মান হয় -126।

একটি কনস্ট্যান্ট আর মান থেকে টাইপ পাওয়া লোকাল

4 দেখে var, int টাইপ ঠিক করে। গুণে 12 পাও, আর তুলনা থেকে boolean মান true আসে।

গুণের আগে বড় টাইপে নাও

কাস্টের কারণে প্রথম অপারেন্ড গুণের আগেই long হয়। তাই 2500000000 রাখা যায়।

C-এর মতো দেখতে অপারেটর

Java-তে পরিচিত গাণিতিক, তুলনা আর লজিক্যাল অপারেটর আছে। ভাগশেষের জন্য %, অ্যাসাইন করতে =, আর প্রিমিটিভ মান সমান কি না দেখতে == ব্যবহার করো। && আর || হলো short-circuit অপারেটর। বাম পাশেই ফল ঠিক হয়ে গেলে ডান পাশের হিসাব বাদ দিতে পারে।

Java-র if-এর শর্ত অবশ্যই boolean হবে। সংখ্যাকে সরাসরি সত্য-মিথ্যা ধরতে if (mark) লেখা যাবে না। mark != 0-এর মতো স্পষ্ট তুলনা লেখো। boolean আর পূর্ণসংখ্যার মধ্যে C-এর মতো কাস্টও করা যায় না।

final থাকলে অনুমোদিত প্রাথমিক অ্যাসাইনমেন্টের পরে ভেরিয়েবলে নতুন মান অ্যাসাইন করা যায় না। final প্রিমিটিভের মান স্থির থাকে। তবে final রেফারেন্সের ক্ষেত্রে সাবধান: যে অবজেক্টকে দেখায়, তার ভেতরের মান বদলাতে পারে। রেফারেন্স অ্যাসাইন করা আটকানো আর পুরো অবজেক্ট অপরিবর্তনীয় করা আলাদা ব্যাপার।

লোকাল var-এর শুরুর মান থেকে ব্যবহারযোগ্য টাইপ বুঝতে হতে হবে। var value = null লিখলে তুমি কোন রেফারেন্স টাইপ চাও, বোঝা যায় না। এখানে শেখা সাধারণ ঘোষণায় ফিল্ড বা মেথড প্যারামিটারের টাইপ হিসেবেও var চলবে না। টাইপ লিখলে একক বা অর্থ পরিষ্কার হয় এমন জায়গায় টাইপ স্পষ্ট করেই লেখো।

টাইপের ভুল আগেই ধরো

পূর্ণসংখ্যার ভাগ হয়ে যাওয়ার পরে কাস্ট করা

(double) (total / count) লিখলে ভগ্নাংশ বাদ যাওয়া ফলটাই double হয়। ভাগের আগে total বদলাও, বা double অপারেন্ড ব্যবহার করো। count শূন্য হলে কী করবে, ভাগের আগেই সেটাও ঠিক করো।

পূর্ণসংখ্যার লিটারাল অতিরিক্ত বড় লেখা

long-এর জন্য বড় দশমিক পূর্ণসংখ্যা লিখলে শেষে L লাগতে পারে। বড় হাতের L লেখো; ছোট হাতের l দেখতে একের মতো। শুধু যে ভেরিয়েবলে রাখবে তা নয়, লিটারালটাও ঠিক আছে কি না দেখো।

char মানেই এক বাইট ভাবা

Java-র char একটি UTF-16 code unit রাখে। কিছু Unicode অক্ষরের জন্য এমন দুটি ইউনিট লাগে। সাধারণ টেক্সটের জন্য String নাও। কী গুনতে চাও, সেই অনুযায়ী টেক্সট প্রসেস করার অপারেশন বেছে নাও।

লোকাল টাইপ অনুমানের জন্য কোন ভার্সন লাগে

লোকাল var-এর জন্য Java 10 বা নতুন ভার্সন দরকার। এই পাতার ঘোষণা আর টাইপ বদলানো Java 17-তে বৈধ। নির্দিষ্ট release target রাখলে ভিত্তিগুলো শেখার সময় ভুল করে পরের রিলিজের সুবিধা ব্যবহার হয়ে যায় না।

প্রতিটি হিসাবেই টাইপের ভূমিকা আছে

সীমার মধ্যে পূর্ণসংখ্যার কাজে int নাও। মাঝের ফলের জন্য বেশি সীমা দরকার হলে long নাও। আনুমানিক ভগ্নাংশ গ্রহণযোগ্য হলে double ব্যবহার করো। boolean-কে সংখ্যা থেকে আলাদা রাখো। এরপর এই মান দিয়ে সিদ্ধান্ত আর লুপ চালাতে Java-র কন্ট্রোল ফ্লো শেখো।
