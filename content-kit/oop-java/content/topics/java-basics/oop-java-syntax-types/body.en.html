Choose the right kind of value

A mark, a CGPA and a pass decision carry different kinds of information. Think of a variable type as a label on a storage box. The label tells Java which values belong there and which operations make sense. Choosing the type carefully prevents many mistakes before execution.

A primitive type holds a basic value such as an integer or a boolean. Java has eight primitive types. Object references form a separate family, which you meet with strings and arrays. You cannot assume that every Java value is an object.

If you know C, braces and semicolons will look familiar. Java gives several types stronger fixed guarantees than C does. It also separates boolean truth values from numbers. These differences matter more than the small changes in spelling.

Declarations, constants and inferred locals

A local declaration gives a type, name and often an initial value. A local variable must be definitely assigned before reading. Object fields have default values, but an uninitialised local int is not automatically safe to read.

int mark = 80;
double cgpa = 3.75;
boolean passed = mark >= 40;
final int CREDIT = 3;
var count = 4;

Type inference means the compiler works out a declared type from an initializer. Local var became available in Java 10. Here count is an int permanently; assigning text to it later is still a type error. var is not dynamic typing.

Follow the operation before the assignment

An arithmetic expression is evaluated using its operand types. With two int operands, division uses integer arithmetic. It discards the fractional part towards zero. Thus 7 / 2 is 3 and -7 / 2 is -3. A double operand changes the division to floating-point arithmetic.

A cast explicitly requests a conversion, written with a type in parentheses. Widening an int to long preserves its value. Narrowing double to int can discard a fraction. Narrowing a larger integer to byte can discard high bits. The destination type alone does not change earlier arithmetic.

Consider two counts equal to 50000. Multiplying them as int exceeds the int range. Java integer overflow wraps according to its defined arithmetic rules, unlike C signed-overflow assumptions. Storing that already overflowed result in long does not recover the intended product.

Convert one operand to long before multiplication. The other operand is promoted for that operation, and the exact product fits. You should reason about the largest intermediate result, not only the final variable. This habit also helps with totals and fee calculations.

Floating-point values approximate many decimal fractions. They are useful for averages and measurements, but they are not exact decimal money storage. The small formatting examples show presentation, not a complete financial arithmetic policy. Later designs can choose a representation suited to exact amounts.

Operators that resemble C

Java uses familiar arithmetic, relational and logical operators. The remainder operator is %, assignment is =, and equality comparison is == for primitive values. The short-circuit operators && and || can skip evaluating their right operand when the left already decides the answer.

A Java if condition must have type boolean. You cannot write if (mark) as a numeric truth test. Write an explicit comparison such as mark != 0 instead. Java also does not allow C-style casts between boolean and integer types.

The final modifier prevents assigning a new value to a variable after its allowed initialization. A final primitive is stable in value. A final reference later has a different caution: the referenced object's contents may still be mutable. Do not confuse assignment control with deep immutability.

Local var needs an initializer that identifies a usable type. var value = null cannot infer which reference type you intended. It also cannot serve as a field type or method parameter type in the ordinary declarations covered here. Use explicit types when they make units or meaning easier to see.

Catch type mistakes early

Casting after integer division

Writing (double) (total / count) converts the already truncated quotient. Convert total before the division, or use a double operand. Also decide how a zero count should be handled before dividing.

Making an integer literal too large

A large decimal literal intended for long may need an L suffix. Use uppercase L because lowercase l resembles the digit one. Check the literal itself as well as the variable receiving it.

Assuming char means a byte

Java char stores one UTF-16 code unit. Some Unicode characters require two such units. For general text, use String and choose text-processing operations according to what you need to count.

Local inference has a version boundary

Local var requires Java 10 or newer. The declarations and conversions on this page are valid under Java 17. The release target prevents accidentally relying on later language additions while you practise these foundations.

Types guide every calculation

Use int for bounded whole-number work, long when intermediate integer results need more range, and double when a fractional approximation is appropriate. Keep boolean separate from numbers. Next, direct these values through Java control flow.
