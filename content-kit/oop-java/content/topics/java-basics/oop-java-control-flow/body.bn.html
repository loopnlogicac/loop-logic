প্রোগ্রাম কোন পথে চলবে ঠিক করো

ক্যাম্পাসের নোটিশে কিছু কথা নির্দিষ্ট শিক্ষার্থীদের জন্য, আবার কিছু কাজ সবাইকে বারবার করতে হয়। প্রোগ্রামের কাজেও এমন বাছাই আর পুনরাবৃত্তি থাকে। স্টেটমেন্টগুলো কোন ক্রমে চলবে, সেটাই কন্ট্রোল ফ্লো। ব্রাঞ্চ পথ বেছে নেয়। লুপ একটি পথ বারবার চলে, যতক্ষণ না থামার শর্ত আসে।

C-তে শেখা if, switch আর লুপের অনেক কাঠামো Java-তেও আছে। শুরুতেই জরুরি নিয়ম: শর্ত boolean হতে হবে। যেকোনো পূর্ণসংখ্যাকে Java নিজে থেকে সত্য বা মিথ্যা ধরবে না। তুলনা স্পষ্ট লিখলে সিদ্ধান্তের অর্থও পরিষ্কার হয়।

এই পাঠে অ্যারের মান একে একে দেখা আর switch দিয়ে ফল বেছে নেওয়ার সুবিধা দেখবে। অ্যারে হলো ক্রমে সাজানো একদল মান। Java-র অ্যারে পাঠে বিস্তারিত শিখবে। এখন অ্যারের initializer-কে ছোট তালিকা আর length-কে এলিমেন্টের সংখ্যা হিসেবে পড়ো।

কাজ বাছবে, নাকি একটি মান বের করবে?

boolean এক্সপ্রেশন দেখে সিদ্ধান্ত নিতে if নাও। একটি মান অনুযায়ী একাধিক case থেকে কাজ বাছতে প্রচলিত switch স্টেটমেন্ট সুবিধাজনক। অ্যারো switch-এ ভুল করে পরের case-এ কাজ গড়ায় না। switch expression দিয়ে আরও এক ধাপ এগিয়ে সরাসরি অ্যাসাইন করার মান পাওয়া যায়।

if (mark >= 40) {
    // Handle a passing mark.
} else {
    // Handle a lower mark.
}
String label = switch (day) {
    case 5, 6 -> "Weekend";
    default -> "Class day";
};

এক্সপ্রেশনের শাখাগুলো মিলে সম্ভাব্য সব ইনপুট সামলাতে হবে। এখানে তালিকার বাইরের মান default সামলায়। কোনো শাখায় ব্লক থাকলে কয়েকটি স্টেটমেন্ট লিখে yield দিয়ে ফল দিতে পারো। অ্যারো শাখায় পরের case-এ চলে যাওয়া আটকাতে break লাগে না।

চেক, লুপের কাজ আর আপডেট ধরে এগোও

সাধারণ for লুপে initialization একবার হয়। প্রতিবার বডি চালানোর আগে শর্ত চেক হয়, তারপর বডি শেষে আপডেট হয়। continue বডির বাকি কাজ বাদ দেয়, তবে for-এর আপডেট ঠিকই চলে। while বডিতে ঢোকার আগে শর্ত দেখে। do-while বডি চালানোর পরে দেখে।

enhanced for লুপে ইনডেক্স না লিখেও এলিমেন্টগুলো ক্রমে পড়তে পারো। এর কাঠামোতে এলিমেন্টের টাইপ, লোকাল ভেরিয়েবল, কোলন আর অ্যারে থাকে। int অ্যারের ক্ষেত্রে প্রতিটি int মানের কপি ভেরিয়েবলে আসে। ওই লোকালে নতুন মান দিলেই অ্যারের এলিমেন্ট বদলায় না।

লেবেলসহ break দিয়ে বাইরের কোনো স্টেটমেন্ট থেকে বের হওয়া যায়। যে বাইরের লুপ ছাড়তে চাও, তার ঠিক আগে অর্থপূর্ণ লেবেল দাও। লেবেল ছাড়া break শুধু কাছের লুপ বা switch ছাড়বে। লেবেলকে যেকোনো জায়গায় লাফ দেওয়ার উপায় না ভেবে নির্দিষ্ট nested search শেষ করতে ব্যবহার করো।

সারি ধরে খোঁজার সময় আগে ঠিক করো, প্রথম মিল বলতে কী বোঝাচ্ছ। সারির ক্রমে খুঁজলে শূন্য নম্বর সারির সব কলাম দেখে তারপর এক নম্বর সারিতে যাবে। মিল পেলে স্থানাঙ্ক সেভ করে দুটি লুপ থেকেই বের হও। মিল না পেলে শুরুর অনুপস্থিতি বোঝানো স্থানাঙ্ক রেখে দাও।

চালানোর আগে পথটা অনুমান করো

উদাহরণগুলোতে গ্রেডের সীমা থেকে শুরু করে এক লুপের ভেতর আরেক লুপে খোঁজা দেখবে। কোন শর্তে ব্রাঞ্চ বাছা হচ্ছে বা লুপ থামছে, প্রতিটিতে সেটা ধরো। এরপর তোমার হিসাব আউটপুটের সঙ্গে মেলাও।

গ্রেডের সীমা

তুলনায় 80-ও ধরা হয়। তাই প্রথম ব্রাঞ্চ A+ প্রিন্ট করে।

লুপ আর enhanced for দিয়ে যোগফল

অ্যারের প্রতিটি মান score-এ আসে। 12, 8 আর 10 যোগ করে 30 পাও।

একটি switch expression

মিলে যাওয়া অ্যারো শাখা Weekend দেয়। এক্সপ্রেশনসহ অ্যাসাইনমেন্টটি সেমিকোলনে শেষ হয়।

খোঁজার দুটি লুপ থেকে বের হওয়া

মিল পাওয়া যায় 1 নম্বর সারির 0 নম্বর কলামে। break search বাইরের লেবেল দেওয়া লুপটাও শেষ করে।

শর্ত দেখার আগেই একবার চলা

শর্ত false কি না দেখার আগে do-এর বডি একবার চলে। তাই count হয় 1।

খালি কাজ, সীমা আর ভেতরের লুপ থেকে বের হওয়া

শুরুর শর্ত false হলে লুপের বডি একবারও চলে না। খালি তালিকা বা শূন্যবার কাজের ক্ষেত্রে এটাই দরকার। সমস্যা না চাইলে জোর করে একবার চালানোর ব্যবস্থা কোরো না। do-while আলাদা, কারণ প্রথমবার কাজের আগে কোনো শর্ত চেক হয় না।

সীমার তুলনা সমস্যার কথার সঙ্গে মিলতে হবে। অন্তত 40 মানে 40-ও চলবে, তাই >= নাও। 40-এর নিচে মানে 40 চলবে না, তাই < নাও। শূন্য থেকে ইনডেক্স গুনলে সাধারণত index < length হয়। <= দিলে অ্যারের শেষের পরের অবস্থান ব্যবহার করার চেষ্টা হবে।

পুরোনো কোলন দিয়ে লেখা switch case-এ নিয়ন্ত্রণ বের না হলে পরের case-এও কাজ চলতে পারে। একে fall-through বলে। অ্যারো case-এ তা হয় না। পুরোনো Java কোড পড়লে আগে case-এর কাঠামো দেখো। দুটি ধরন গুলিয়ে ফেললে প্রিন্ট করা টেক্সট আর যোগফল দুটোই বদলে যেতে পারে।

enhanced for-এর ভেরিয়েবলে অবজেক্ট রেফারেন্সও থাকতে পারে। সেই ভেরিয়েবলে নতুন রেফারেন্স অ্যাসাইন করলেও অ্যারের এলিমেন্ট বদলায় না। তবে তার মাধ্যমে মেথড কল করলে শেয়ার করা অবজেক্ট বদলাতে পারে। মেথডের পাঠে রেফারেন্সের মান নিয়ে একই নিয়ম শিখবে।

লেবেলসহ break লেবেল দেওয়া লুপ শেষ করে, পুরো মেথড নয়। লুপের পরের স্টেটমেন্টগুলো চলবে। তাই খোঁজার পরে একবার ফল দেখাতে এটি সুবিধাজনক। অস্পষ্ট অক্ষরের বদলে search-এর মতো অর্থপূর্ণ লেবেল নাও।

কোন পথে চলতে চাও পরিষ্কার রাখো

পূর্ণসংখ্যাকে শর্ত বানানো

count যদি int হয়, while (count) কম্পাইল হবে না। count > 0-এর মতো শর্ত লেখো। তুলনা দেখে পাঠকও বুঝবে লুপ কোন দিকে এগোবে।

কপি হওয়া লুপ ভেরিয়েবল দিয়ে এলিমেন্ট বদলানো

for (int mark : marks)-এ mark বদলালে শুধু লোকাল ভেরিয়েবল বদলায়। marks[index]-এ লিখতে হলে ইনডেক্সসহ লুপ নাও। শুধু মান দেখা বা যোগফলের জন্য enhanced for বেশি পরিষ্কার।

শুধু ভেতরের খোঁজা বন্ধ করা

সাধারণ break বর্তমান ভেতরের লুপ থামায়। বাইরের লুপ আবার চললে খোঁজা চালিয়ে যেতে বা সেভ করা উত্তর মুছে দিতে পারে। প্রথম মিলেই পুরো nested search ছাড়তে লেবেলসহ break কাজে লাগে।

নতুন switch-এর ধরন চিনে রাখো

enhanced for এসেছে Java 5-এ। switch expression Java 14-তে স্থায়ী ফিচার হয়েছে। Java 17-তে preview flag ছাড়াই এগুলো চলে। ফল হিসাব করার বদলে কাজ চালাতে চাইলে পুরোনো স্টেটমেন্টের ধরনও উপযোগী।

কাজের জন্য সবচেয়ে পরিষ্কার পথ নাও

স্পষ্ট boolean শর্ত লেখো। ইনডেক্স ধরে বদলাতে সাধারণ লুপ, আর মান দেখতে enhanced for নাও। switch expression দিয়ে সরাসরি ফল পাও, লেবেলসহ break দিয়ে একসঙ্গে কয়েক স্তরের খোঁজা শেষ করো। এবার বারবার করা কাজ মেথডে সাজাও।
