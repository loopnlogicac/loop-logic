টেক্সটও একটি অবজেক্ট, তারও নিয়ম আছে

কোর্সের কোড দেখতে অক্ষরের ছোট একটি লাইন। তবে Java-র টেক্সটে মানের পাশাপাশি বিহেভিয়ারও আছে। String হলো UTF-16 code unit-এর অপরিবর্তনীয় ক্রম। তুমি সেটা পড়তে পারো বা আরেকটি টেক্সটের মান চাইতে পারো। কিন্তু একই অবজেক্টের অক্ষর সরাসরি বদলাতে পারো না।

ছাপানো কোর্সের নোটিশ ভাবো। সংশোধিত আরেক কপি বানাতে পারো, কিন্তু আগের ছাপানো কপি বদলায় না। String ভেরিয়েবলে সংশোধিত String-এর রেফারেন্স বসানো যায়। তাতে পুরোনো অবজেক্ট বদলায় না। অন্য রেফারেন্স তখনও আগের টেক্সটই দেখে।

C জানা থাকলে String-কে null অক্ষরে শেষ হওয়া, লেখা যায় এমন char অ্যারে ভাববে না। Java স্ট্রিং নিজের দৈর্ঘ্য জানে, আর পরিচিত কাজগুলোর জন্য মেথড দেয়। শেষ চিহ্নের জন্য বাড়তি বাইট রাখতে বা টেক্সটের জন্য free কল করতে হয় না।

মেথড দিয়ে টেক্সট পড়ো

String লিটারালে ডাবল কোটেশন থাকে। char লিটারালে সিঙ্গেল কোটেশন থাকে, আর একটি UTF-16 code unit ধরে। String-এর কাজগুলো রেফারেন্সের মাধ্যমে মেথড কল করে করো। অ্যারের মতো ফিল্ড নয়; String-এর length() একটি মেথড।

String course = "CSE 212";
int units = course.length();
char first = course.charAt(0);
String number = course.substring(4);
boolean matches = course.equals("CSE 212");
String-এর দরকারি অপারেশন
মেথডকী জানা যায় বা কী পাও
length()UTF-16 code unit-এর সংখ্যা
charAt(index)নির্দিষ্ট ইনডেক্সের একটি code unit
substring(begin, end)begin থেকে end-এর আগ পর্যন্ত টেক্সট
indexOf(text)প্রথম মিলের অবস্থান, না পেলে -1
startsWith(prefix)শুরুর অংশ মেলে কি না
equals(other)টেক্সটের মান মেলে কি না

charAt-এর বৈধ ইনডেক্স length()-এর নিচে থাকবে। substring-এ end সমান length() হতে পারে, কারণ শেষ অবস্থানটি নেওয়া হয় না। উল্টো সীমা বা সীমার বাইরের অংশ অবৈধ। দুই প্রান্ত বাছার আগে কোন অংশ চাই, কাগজে লিখে দেখো।

টেক্সটের মান আর অবজেক্টের পরিচয় আলাদা করো

রেফারেন্সে == দেখে দুটো রেফারেন্স একই অবজেক্টকে দেখায় কি না। String.equals দেখে ভেতরের অক্ষরগুলো মেলে কি না। তাই আলাদা করে বানানো দুটি স্ট্রিংয়ে == থেকে false, আর equals থেকে true আসতে পারে। তুমি কোন প্রশ্নের উত্তর চাও, সেই তুলনা নাও।

String লিটারাল intern করা হয়। মানে, একই লিটারালের জন্য Java একটি নির্দিষ্ট অবজেক্ট শেয়ার করতে পারে। ছোট পরীক্ষায় তাই == দিয়ে টেক্সট তুলনা ঠিক হচ্ছে মনে হতে পারে। তাতে অপারেটরের অর্থ বদলায় না। ইনপুটের টেক্সটও অবজেক্টের পরিচয়ের বদলে ভেতরের মান দিয়ে তুলনা করো।

String অপরিবর্তনীয় বলে একই টেক্সট শেয়ার করলে অন্য কেউ তার অক্ষর বদলে দিতে পারে না। first আর second দুটিই CSE দেখালে first.toUpperCase কল করে কারও অবজেক্ট বদলাবে না। দরকার হলে ফেরত আসা ফল first-এ সেভ করলে first ফলের রেফারেন্স পাবে। second আগের টেক্সটই দেখবে।

পরিবর্তন দরকার না হলে কিছু মেথড একই অবজেক্ট ফেরত দিতে পারে। এই সম্ভাবনাকে টেক্সটের মান তুলনা করার নিয়ম বানাবে না। মেথডের টেক্সটের ফলের ওপর নির্ভর করো। নির্দিষ্ট বাস্তবায়নে নতুন অবজেক্ট তৈরি হয়েছে কি না, তার ওপর নয়।

ফেরত আসা টেক্সট আর বদলানো যায় এমন বিল্ডার দেখো

প্রথম উদাহরণে ফল সেভ না করলে কী হয় দেখবে। দ্বিতীয়টিতে পরিচয় আর ভেতরের মান সরাসরি তুলনা করা আছে। পরেরগুলোতে কোর্স কোড থেকে অংশ নেওয়া আর বিভাজক দিয়ে রোলের তালিকা তৈরি দেখবে।

মেথডের ফল সেভ করতে হয়

বড় হাতের টেক্সটের ফল সেভ না করলে code-এ cse-ই থাকে। ফল অ্যাসাইন করলে রেফারেন্স CSE দেখায়।

পরিচয় আর ভেতরের মান

new আলাদা String অবজেক্ট তৈরি করে। রেফারেন্স আলাদা, তবে ভেতরের অক্ষর মেলে।

কোর্সের নম্বর আলাদা করা

স্পেসসহ সাতটি UTF-16 ইউনিট আছে। substring শুরু হয় 4 নম্বর ইনডেক্সে, আর charAt(0) দেয় C।

রোলের তালিকা বানানো

বিল্ডারে একবারে একটি অংশ যোগ হয়। শুধু রোলগুলোর মাঝখানে কমা বসে।

বারবার টেক্সট যোগ করতে বিল্ডার নাও

StringBuilder হলো টেক্সট জড়ো করার এমন বাফার, যার ভেতরের মান বদলানো যায়। append দিয়ে অংশ যোগ করো, আর toString দিয়ে String ফল পাও। টেক্সটের সঙ্গে সংখ্যাও যোগ করা যায়। বিল্ডার সংখ্যাকে টেক্সটের রূপে নিতে পারে।

লুপে বারবার String জোড়া দিলে টেক্সট বাড়ার সঙ্গে মাঝের ফল বারবার তৈরি লাগতে পারে। বিল্ডারে বোঝা যায় তুমি এক জায়গায় টেক্সট জমাচ্ছ। অনেক ছোট অংশ যোগ করলে বা চলার সময় বিভাজক ঠিক করলে এটি বিশেষ কাজে লাগে। ছোট নির্দিষ্ট বার্তায় সাধারণ + দিয়ে জোড়া লাগানো বেশি পরিষ্কার হতে পারে।

কমা দিয়ে তালিকা বানাতে প্রথমটির পর প্রতিটি আইটেমের আগে কমা আর স্পেস যোগ করো। তাতে শেষে বাড়তি কমা থাকে না, মুছতেও হয় না। তালিকা খালি হলে ব্যবহারকারী কী দেখবে ঠিক করো। খালি String আর Empty বার্তা একই অর্থ দেয় না।

টেক্সটের ইনডেক্সে Unicode-এর ব্যাপারেও সাবধান। একটি char সব সময় ব্যবহারকারীর চোখে একটি পুরো অক্ষর নয়। কিছু Unicode code point-এর জন্য দুটি UTF-16 ইউনিট লাগে। একটি দৃশ্যমান অক্ষরে combining mark-ও থাকতে পারে। তাই char ধরে উল্টো করার অনুশীলনে ASCII ইনপুট বলা আছে। সব ভাষার টেক্সট ঠিকভাবে উল্টাবে এমন দাবি করা হয় না।

বড়-ছোট হাতের অক্ষর বদলানো locale-এর ওপর নির্ভর করতে পারে। মেশিনে পড়ার কোড স্বাভাবিক রূপে নিতে Locale.ROOT একটি স্থির, ভাষা নিরপেক্ষ নিয়ম দেয়। তার মানে সব ব্যবহারকারীর নামেও একই নিয়ম চলবে না। টেক্সটের উদ্দেশ্য অনুযায়ী নিয়ম বেছে নাও।

টেক্সটের কাজের নিয়ম পরিষ্কার রাখো

ফেরত আসা String সেভ না করা

substring বা অক্ষরের কেস বদলানোর মেথড কল করলে মূল অবজেক্ট বদলায় না। ভেরিয়েবলে বদলানো টেক্সট চাইলে ফল সেভ করো। কলের পরে কোন রেফারেন্স প্রিন্ট করছ, দেখো।

পাসওয়ার্ড বা কোর্স কোডে == নেওয়া

সমান দুটি ইনপুট আলাদা অবজেক্টে থাকতে পারে। অক্ষরের কেস মিলিয়ে ভেতরের মান তুলনা করতে equals নাও। রেফারেন্স null হতে পারলে তার মাধ্যমে ইনস্ট্যান্স মেথড কলের আগে সেটা সামলাও।

String-এ অ্যারের মতো ইনডেক্স লেখা

text[0] Java-র String ব্যবহারের কাঠামো নয়। একটি UTF-16 code unit দরকার হলে charAt(0) নাও। বড় অংশ চাইলে শেষ প্রান্ত বাদ দেওয়া substring মেথড ব্যবহার করো। টেক্সটকে C-এর পয়েন্টার ভাববে না।

StringBuilder অনেক দিনের টুল

Java 5 থেকে StringBuilder আছে। এই পাতার String অপারেশন Java 17 সমর্থন করে। এখানে নতুন টেক্সট ফিচার লাগছে না। মনোযোগ থাকুক মান, পরিচয় আর নিয়ম মেনে টেক্সট তৈরিতে।

স্থির টেক্সট আর টেক্সট বানানোর বাফার বেছে নাও

String স্থির টেক্সটের মান দেয়। equals দিয়ে তার ভেতরের মান তুলনা করো। ফল গুছিয়ে পরে String বানাতে StringBuilder সাহায্য করে। এরপর কিবোর্ড থেকে টেক্সট পড়তে ইনপুট ও আউটপুট শেখো।
