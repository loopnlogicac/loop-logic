Text is an object with rules

A course code looks like a short row of characters, but Java text has behaviour as well as contents. A String represents an immutable sequence of UTF-16 code units. You can inspect it or request another text value, but you cannot edit its characters in place.

Think of a printed course notice. You can make a revised copy, yet the original printed notice stays the same. A String variable can point to a revised String, but that reassignment does not alter the old object. Other references still see the original contents.

If you know C, do not treat String as a writable char array ending at a null character. Java strings track their length and offer methods for common operations. You do not allocate a spare byte for a terminator or call free on the text.

Read text through methods

String literals use double quotes. A char literal uses single quotes and holds one UTF-16 code unit. String operations are method calls through a reference. Unlike an array, a String provides length() as a method.

String course = "CSE 212";
int units = course.length();
char first = course.charAt(0);
String number = course.substring(4);
boolean matches = course.equals("CSE 212");

For charAt, a valid index is below length(). For substring, the end can equal length() because it is excluded. A reversed or out-of-range interval is invalid. Write the intended range on paper before selecting its endpoints.

Separate content from reference identity

Reference equality with == asks whether two references identify the same object. String.equals asks whether their character contents match. Two separately constructed strings can therefore produce false with == and true with equals. Choose the comparison that answers your actual question.

String literals are interned, meaning Java can share one canonical literal object. This can make == appear to compare text correctly in a small experiment. That observation does not change the operator's meaning. Text read from input should also be compared by content rather than identity.

Immutability makes sharing a String safe from character edits. If first and second both refer to CSE, requesting first.toUpperCase does not edit either reference's object. Saving the returned result changes first to a new result reference when needed. second continues to see its original text.

Some methods may return the same object when no change is needed. Never use that possibility as a content-comparison rule. You should depend on the method's text result rather than whether a particular implementation allocated another object.

Use a builder for repeated appends

A StringBuilder is a mutable buffer for assembling text. append adds another piece to that buffer, and toString gives you a String result. You can append numbers as well as text, because the builder can produce their textual representations.

Repeated String concatenation in a loop can require repeated intermediate results as the text grows. A builder makes the intended accumulation explicit. It is especially useful when you add many small pieces or decide separators dynamically. For a short fixed message, ordinary + concatenation is often clearer.

To create a comma-separated list, append comma-space before each item after the first. That policy avoids a trailing comma and needs no removal afterwards. For an empty list, decide what the user should see. An empty String and a message such as Empty communicate different things.

Text indexing also has a Unicode caution. A char is not guaranteed to hold a whole user-perceived character. Some Unicode code points use two UTF-16 units, and a visible character can include combining marks. A reverse-by-char exercise therefore states ASCII input rather than claiming to reverse every language correctly.

Case conversion can depend on locale. Locale.ROOT provides a fixed language-neutral convention when you normalise a machine-readable code. This does not mean every user name should be converted with the same rule. Choose the text policy according to its purpose.

Keep the text contract clear

Ignoring a returned String

Calling substring or a case-conversion method does not rewrite the receiver. Save the returned value when the variable should represent the changed text. Check which reference you print after the call.

Using == for a password or course code

Two equal inputs may occupy different objects. Use equals for a case-sensitive content match. If a reference might be null, handle that possibility before calling an instance method through it.

Indexing a String like an array

text[0] is not Java String syntax. Use charAt(0) when one UTF-16 code unit is appropriate. For a full substring, use the half-open interval methods rather than treating text as a C pointer.

StringBuilder is an established tool

StringBuilder has been available since Java 5. The String operations on this page are supported by Java 17. Newer text features are unnecessary for these examples, which focus on content, identity and controlled text construction.
