Answer with a rule, an example and a boundary

A strong interview answer is short enough to follow and precise enough to defend. Start with the central rule, give one concrete example, then name a limitation when it matters. These fifty questions cover the four pillars, Java-specific behavior and design choices.

Try saying each answer aloud before reading it. When a follow-up asks why, draw a small object diagram or write a two-line trace. Avoid broad claims such as every final object is immutable or every stream runs in parallel. A qualified answer is clearer than a confident overstatement.

The output quiz adds five small executable checks. Use those to distinguish a definition you remember from a behavior you can predict. The written bank also keeps the fifty short answers together for revision.

Objects and design foundations

  1. What is encapsulation?

    It keeps representation behind operations that maintain a contract. Private fields help, but validation and controlled access preserve the object’s rules.

  2. What is abstraction?

    It exposes the operations a caller needs while hiding irrelevant implementation choices. An interface can describe a fee calculation without exposing its formula.

  3. What does inheritance promise beyond code reuse?

    A subtype should satisfy the behavioural expectations of its supertype. Reusing code through extends is a poor choice when that substitution promise is false.

  4. What is runtime polymorphism?

    An overridden instance method is chosen from the receiver’s runtime class after a compatible signature is selected at compile time.

  5. How does a class differ from an object?

    A class defines a type and its implementation. An object is one runtime instance with identity and state.

  6. How do identity and equality differ?

    Reference == checks whether two references designate the same object. equals follows the class’s equality contract, which may compare values.

  7. How does Java pass object arguments?

    Java copies the reference value into the parameter. The callee can mutate a shared target, but reassigning its parameter does not replace the caller’s variable.

  8. What does null represent?

    It is a reference value designating no object. Dereferencing it usually throws NullPointerException; it is not an empty instance.

  9. When is composition preferable to inheritance?

    Use composition when an object has a collaborator whose behaviour may vary independently. Delegation exposes that relationship without promising a false is-a contract.

  10. Why does Java allow multiple interfaces but one class superclass?

    Interfaces can express several capabilities without inheriting several independent class-state implementations. Conflicting default methods still need explicit resolution.

Construction, methods and access

  1. Are constructors inherited or overridden?

    No. A constructor initializes a new instance of its declaring class. Subclass construction invokes a superclass constructor rather than overriding it.

  2. When does the compiler provide a default constructor?

    Only when the class declares no constructor. Its implicit superclass call must still be legal and accessible.

  3. What does this(...) do?

    It delegates to another constructor of the same class. In Java 17 it must be the first constructor statement and cannot create a constructor cycle.

  4. What does super.method() select?

    It invokes the accessible superclass implementation for that operation, bypassing the current class override for that explicit call.

  5. How do overloading and overriding differ?

    Overloading offers different parameter lists selected at compile time. Overriding supplies a subtype implementation for an inherited instance-method signature.

  6. Can an override reduce access?

    No. It must remain at least as accessible as the overridden method, so a public interface method needs a public implementation.

  7. What is a covariant return?

    An override may return a narrower reference type than the parent method. This does not allow unrelated or arbitrarily changed primitive return types.

  8. Can static methods be overridden?

    No. A same-signature subclass static method hides an inherited static method. Selection uses compile-time information rather than receiver dispatch.

  9. What does final mean on a variable?

    That binding can be assigned only once. If it holds a mutable object reference, operations may still change the object.

  10. What does final mean on methods and classes?

    A final method cannot be overridden. A final class cannot be extended. Neither declaration alone makes every field immutable.

  11. What is an effectively final local?

    It is a local variable that is not reassigned after its permitted initialization. Lambdas and local classes can capture such bindings.

  12. What is the main abstract-class versus interface choice?

    An abstract class can share instance state and construction. An interface defines a capability that unrelated classes can implement, with default and static helpers where useful.

  13. What does protected mean across packages?

    Subclass access is allowed under protected receiver restrictions. A subclass cannot use that permission to access the member through an arbitrary superclass instance.

  14. Does importing a package import its subpackages?

    No. Imports resolve type names; subpackages are separate packages. Imports do not copy code into the program.

Equality, wrappers and failures

  1. What are equals requirements?

    Reflexivity, symmetry, transitivity and consistency, with false for null. The chosen equality fields must also support a matching hashCode implementation.

  2. Does equal hashCode prove equals?

    No. Different values may collide. Equal objects require equal hashes, but equal hashes do not require equal objects.

  3. Why are mutable hash keys risky?

    Changing fields used by hashing or equality after insertion can make later lookup use a different bucket or equality relation. Prefer stable keys.

  4. Why compare String content with equals?

    String == checks reference identity, which interning can make misleading. equals checks the character sequence; handle null according to the caller’s contract.

  5. What is autoboxing’s null pitfall?

    Unboxing a null wrapper throws NullPointerException. A nullable Integer is not interchangeable with an always-present int.

  6. Are all equal Integer objects identical?

    No. Some small boxed constants share required cached objects, but general value equality does not imply identity. Use equals for wrapper values.

  7. What is a checked exception?

    It is an exception subject to the catch-or-declare rule. RuntimeException and Error families are unchecked; IOException is a common checked example.

  8. How do throw and throws differ?

    throw transfers control by raising a Throwable value. A throws clause declares possible propagated failures on a method or constructor.

  9. Why prefer try-with-resources for readers?

    It closes AutoCloseable resources even on normal exceptional exits, in reverse acquisition order, and preserves cleanup failures as suppressed exceptions when needed.

Generics, collections and functions

  1. What does a generic type parameter buy you?

    It expresses relationships between types across fields, parameters and results so incompatible uses can be rejected before execution.

  2. Why is List<Integer> not a List<Number>?

    A writable Number list can accept a Double, which would violate an Integer list’s element promise. Use an extends wildcard when reading numbers.

  3. What does producer extends, consumer super mean?

    Read T values from a source declared with ? extends T. Write T values into a destination declared with ? super T. Choose the direction per parameter.

  4. What is type erasure?

    Generic source types are checked then translated using bounds and casts for JVM compatibility. A separate runtime class is not created for every type argument.

  5. How do List, Set and Map differ?

    A List models positions and permits duplicates. A Set models uniqueness. A Map associates a value with each unique key; Map is not a subtype of Collection.

  6. When choose a tree collection over a hash collection?

    Choose TreeSet or TreeMap when sorted iteration or navigational queries matter. Hash variants usually provide expected constant-time basic lookup without sorted order.

  7. What does Comparable define?

    The implementing type’s natural order through compareTo. A Comparator supplies a separate ordering, useful for alternative reports and tie-breaking.

  8. What is a functional interface?

    It has one abstract operation after excluding Object-equivalent methods. Default and static methods may coexist without adding abstract operations.

  9. How does a lambda differ from an anonymous class?

    A lambda targets a functional interface and keeps the enclosing this. An anonymous class introduces a new class body and its own this and state.

  10. When does a stream pipeline execute?

    Intermediate operations such as map and filter describe work lazily. A terminal operation triggers traversal; the stream cannot then be reused.

  11. Why must a reduction use a suitable identity?

    The identity must leave values unchanged under the combiner, which must be associative. Parallel regrouping can expose an invalid identity or order-dependent operation.

Values, threads, interfaces and design

  1. What does a record generate?

    Component fields, accessors, a canonical constructor and value-oriented equals, hashCode and toString. Mutable referenced components still need a copying policy.

  2. Why store enum names or codes instead of ordinals?

    Ordinal values change when declaration order changes. Durable storage needs a stable code policy and a plan for unknown future values.

  3. Why is count++ unsafe across unsynchronized workers?

    It reads, adds and writes in separate steps. Interleaving can lose updates. Use a shared lock or an appropriate atomic operation.

  4. Does sleep replace join?

    No. sleep delays the current thread without proving another task has finished. join waits for a particular thread’s termination.

  5. Which Swing code belongs on the event thread?

    Ordinary component creation, reads and updates belong there unless an API explicitly permits otherwise. Long work should use a worker and return results to the event thread.

  6. How do SOLID and patterns help design discussions?

    They name pressures and solution roles, such as substitutability, injected policies and event subscribers. Explain the concrete problem and cost instead of adding abstractions by habit.

Make the explanation survive a changed example

After an inheritance answer, change the declared reference type and ask whether overload selection changes. After an equality answer, change one identity field and check both equals and hashCode. After a collection answer, add empty input, a duplicate or an ordering requirement.

For a design discussion, name the change pressure before proposing a pattern. An injected strategy addresses varying algorithms. A factory addresses construction choices. Observer introduces subscription lifetimes. Explain the cost as well as the benefit, including retained listeners or hidden global state.

If a question depends on a version, say so. Records are permanent from Java 16, and the code here targets Java 17. Executor cleanup examples from a newer release may rely on an interface contract that Java 17 does not have.

Keep your answer testable

A useful answer predicts what a caller can do and what happens at a boundary. Return to the exam questions for longer reasoning or explain the library project using the same contracts. That completes the Java OOP track.
