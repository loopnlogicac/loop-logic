Practise a complete reasoning chain

A good OOP exam answer connects a rule to a concrete result. Naming polymorphism is only a start. Identify the declared reference type, the runtime object and the selected method. Then give the exact printed lines and explain why another tempting method does not run.

Use this question bank as a timed rehearsal. First answer without running the code. Draw a small object picture and mark the state after each operation. Then compare your reasoning with the worked explanations. If the result differs, find the first incorrect assumption rather than memorizing the final string.

Use two passes for inheritance output

On the first pass, resolve names and signatures from declared types. Fields, static methods and overload selection belong to this pass. On the second pass, follow overridden instance methods through the runtime receiver. A parent reference can reach a child implementation without changing the type used for overload selection.

For construction traces, draw the superclass chain before following bodies. In Java 17 the superclass constructor call precedes the child constructor body. Field initializers and instance blocks run in their specified order after the parent constructor. Avoid assuming that child fields are already initialized if a parent constructor calls an overridable method.

For aliasing, draw one box per object and one arrow per reference. A method parameter receives a copy of a reference value. Mutating the shared object can be visible to the caller, but reassigning the parameter does not replace the caller's reference. This distinction often explains more than a long verbal definition of pass-by-value.

Build written and code answers from contracts

For a design question, name the invariant first. A library cannot lend an already borrowed book. Put the state behind operations that enforce that rule, then choose interfaces for required capabilities. Use a diagram to show actual is-a and has-a relationships. Explain why each relation is useful rather than adding inheritance everywhere.

For a code-writing question, state the input bounds and output format. Choose a suitable collection and keep display order deterministic. Validate before changing model state. A program that catches every exception and prints success does not meet the operation's contract even if it compiles.

Allocate time according to marks. A short definition needs one precise distinction and an example. A long answer needs a small model, a worked trace or code, and consequences. When a question asks for differences, compare the same dimensions on both sides: purpose, syntax, runtime selection and a typical use case.

Check the rule behind every line

Before submitting, inspect access levels, constructor order, comparison signs, null paths and empty inputs. Explain any output that depends on a contract rather than on an accident of implementation. Continue to the library project for one connected application of these exam skills.
