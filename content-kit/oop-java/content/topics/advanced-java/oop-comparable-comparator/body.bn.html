কোনটি আগে আসবে ঠিক করো

ফলাফলে বেশি নম্বর আগে, রোল রেজিস্টারে ছোট রোল আগে চাই। শিক্ষার্থী একই, সাজানোর নিয়ম আলাদা। Comparable টাইপের একটি natural ordering দেয়। Comparator নির্দিষ্ট কাজের আলাদা ordering দেয়।

সাজানোর অ্যালগরিদম নম্বর বা রোলের মানে জানে না। তুলনার অপারেশনকে জিজ্ঞেস করে কোন অবজেক্ট আগে। প্রতিটি গ্রহণযোগ্য জোড়ায় একই নিয়ম মানতে হবে। কখনও নিজের সঙ্গে বিরোধ করলে sorting বা sorted collection-এর কাজ ভাঙতে পারে।

কোডের আগে বলো নম্বর ছোট থেকে বড়, না উল্টো; সমান হলে কী হবে; অনুপস্থিত ডেটা চলবে কি না। এগুলো না বললে দুটি আপাত সঠিক রিপোর্টের ক্রম আলাদা হতে পারে।

দুটি চুক্তি চেনো

class Student implements Comparable<Student> {
    private final int roll;
    Student(int roll) { this.roll = roll; }
    @Override
    public int compareTo(Student other) {
        return Integer.compare(roll, other.roll);
    }
}
Comparator<Student> byRoll = (left, right) -> left.compareTo(right);

Comparable নিজের অবজেক্টের সঙ্গে একটি মান তুলনা করে। Comparator দুটি দেওয়া মান তুলনা করে। ফল ঋণাত্মক মানে বামটি আগে, শূন্য মানে এই ordering-এ সমান, ধনাত্মক মানে বামটি পরে। ঠিক -1 বা 1 ফেরানো বাধ্যতামূলক নয়।

Comparator.compare দুটি আর্গুমেন্ট নেয় বলে lambda-তে দুই প্যারামিটার। arrow-এর পরে বডি। Result::mark-এর মতো method reference মেলা কাঠামোর আগে থাকা মেথড বোঝায়। lambda পাঠে আরও দেখবে।

একবারে একটি key তুলনা করো

বেশি নম্বর আগে চাইলে বড় নম্বর আগে বসাও। নম্বর আলাদা হলেই থামো। সমান হলে ছোট রোল আগে। একে lexicographic ordering বলে: প্রথম আলাদা key সিদ্ধান্ত দেয়, শব্দে অক্ষর মেলানোর মতো।

জোড়ানম্বরের সিদ্ধান্তরোলের সিদ্ধান্তআগে
(4,80), (1,90)80-এর আগে 90লাগে নারোল 1
(4,80), (2,80)সমান4-এর আগে 2রোল 2
(2,80), (2,80)সমানসমানএকই অবস্থান

Comparator.comparingInt int key পড়ে অপ্রয়োজনীয় boxing ছাড়া তুলনা করে। reversed দিক উল্টায়। thenComparingInt শুধু সমান হলে পরের key নেয়। reversed কোথায় দাও তা জরুরি।

নম্বরের comparator আগে reverse করে পরে রোল দিলে নম্বর বড় থেকে ছোট, রোল ছোট থেকে বড়। পুরো চেইন reverse করলে দুটোই উল্টায়। বাম থেকে ডানে পড়ো, সমান নম্বরের জোড়ায় পরীক্ষা করো।

সবার কাজে মানায় এমন default, যেমন রোলের ছোট থেকে বড় ক্রম, natural ordering হতে পারে। সব রিপোর্টে তা চাপিয়ো না। একই অবজেক্ট আজ নম্বরে, কাল নামের বর্ণানুক্রমে সাজাতে Comparator নাও।

default, বিকল্প আর সীমার মান দেখো

রোল দিয়ে natural order

Student record ছোট data holder; roll accessor নিজে থেকে পায়। enum আর record পাঠে বিস্তারিত আছে। compareTo ছোট রোল আগে রাখে। List.sort-এ comparator null দিলে natural ordering চলে; 7-এর আগে 2 আসে।

সমান হলে আলাদা key-তে ranking

90 আগে আসে। দুইজনের 80 হলে রোল 2, রোল 4-এর আগে। Comparator, Result-এর বাইরে থাকে। record-কে সব কাজেই এই ranking মানতে হয় না।

বিয়োগের overflow এড়াও

Integer.MIN_VALUE একের চেয়ে ছোট। সেখান থেকে এক বিয়োগে overflow হয়ে ধনাত্মক ফল আসতে পারে। Integer.compare নিরাপদে সম্পর্ক দেখে। সমান মানে শূন্যও ফেরে।

ordering-এর নিয়ম এক রাখো

Sign antisymmetry-তে compare(a,b) আর compare(b,a)-এর sign উল্টো, অথবা দুটোই শূন্য। Transitivity-তে a আগে b, b আগে c হলে a আগে c। ছোট ছোট তুলনা দিয়ে বড় তালিকা সাজাতে এই নিয়ম লাগে।

a আর b শূন্য হিসেবে মিললে তৃতীয় মানের সঙ্গে তুলনায় দুটোর sign এক হতে হবে। নইলে এক দলে রাখা মান নিজের অবস্থান নিয়ে একমত নয়। বদলানো counter, বর্তমান সময় বা random ফল দিয়ে তুলনা কোরো না।

equals-এর সঙ্গে consistent হলে compare(a,b)==0 ঠিক তখনই হয় যখন a.equals(b)। Comparable তা জোরালোভাবে পরামর্শ দেয়, যদিও কিছু লাইব্রেরি টাইপ আলাদা নিয়ম নথিবদ্ধ করে। আলাদা হলে sorted set আর map-এ প্রভাব বলো। সেখানে অনন্যতা comparison দিয়ে ঠিক হয়।

List sorting stable: তুলনায় শূন্য হলে আগের আপেক্ষিক ক্রম থাকে। tie-breaker আলাদা নির্দিষ্ট ক্রম দেয়। stable হলেই নিজে থেকে ছোট রোল আগে আসে না; ইনপুটে সেই ক্রম থাকতে হবে।

না থাকা আর সমান key-এর নিয়ম দাও

Comparator null নাও নিতে পারে। দরকার হলে nullsFirst বা nullsLast দিয়ে মোড়াও। এটি পুরো null এলিমেন্টের নিয়ম। পড়া ফিল্ড null হতে পারলে তার comparator-এও আলাদা নিয়ম লাগতে পারে।

String-এর natural order UTF-16 ধরে lexicographic তুলনা। মানুষের ভাষার অভিধানের ক্রম নিজে থেকে নয়। ASCII অনুশীলনে নিয়ম স্পষ্ট। বহুভাষার অ্যাপে Collator আর নথিবদ্ধ locale লাগতে পারে।

TreeSet বা TreeMap-এ থাকা অবস্থায় তুলনার key বদলিয়ো না। পুরোনো তুলনা দিয়ে tree সাজানো। নম্বর বা রোল বদলালে খোঁজার ধারণা ভাঙে। immutable entry বা সরিয়ে বদলে আবার রাখার নীতি নাও।

সীমা আর সমান key দিয়ে চেইন দেখো

রোল 7, 2, 1, 4-এর নম্বর যথাক্রমে 60, 80, 80, 100। নম্বর বড় থেকে ছোটে রোল 4 প্রথম, 7 শেষ। 80-এর দুজনকে ছোট রোলে সাজালে পুরো ক্রম 4, 1, 2, 7।

পুরো চেইন reverse করলে 7 প্রথম, 4 শেষ; সমান নম্বরেও 2 আগে 1। এই বদল দেখলে বোঝো আগের চাহিদায় reversed বেশি পরে বসেছে।

শব্দের অনুশীলনে দৈর্ঘ্য ছোট থেকে বড়, তারপর natural String order। List বলে একই শব্দ বারবার থাকলেও থাকে। sort-এ তুলনা শূন্য মানে বাদ নয়। অনন্যতা কালেকশনের নিয়ম।

সমান key-এর সিদ্ধান্ত বুঝে নাও

সমান অবজেক্টেও এক ফেরানো

বাম ছোট না হলেই এক দিলে শূন্য কখনও আসে না; compare(a,a)-ও ধনাত্মক হয়। চুক্তি ভাঙে। helper দিয়ে সমতাও স্বাভাবিকভাবে সামলাও।

অনন্য শিক্ষার্থীর tree-তে শুধু নম্বর দেখা

নম্বরের comparator-এ TreeSet সমান নম্বরকে একই এলিমেন্ট ধরে। দুজন রাখতে অনন্য roll tie-breaker দাও। সমান key-সহ ranking-এ List প্রায়ই পরিষ্কার।

উল্টো তুলনায় বিয়োগ করা

right-left-এও overflow হয়। reversed বা নিরাপদ helper-এর আর্গুমেন্ট উল্টাও। দশমিকে Double.compare বা comparingDouble নাও; NaN সম্ভব হলে তার নীতি বলো।

বেছে নেওয়া জোড়ায় তুলনা যাচাই করো

  • মূল key আলাদা আর সমান, দুটো জোড়া দেখো।
  • ডোমেইনে চললে সমান মান আর int-এর চরম মান নাও।
  • reversed কোথায় লাগছে দেখো।
  • comparison-এর সমতা আর equals মেলে কি না বলো।

Java 17-এ ordering helper

Comparator factory আর chaining Java 8 থেকে। ছোট record-গুলো Java 16 বা পরে চলে। Java 17-এ preview লাগে না। accessor-সহ সাধারণ ক্লাস নিলেও ordering একই থাকবে।

ordering-ও একটি চুক্তি

Comparable natural order দেয়, Comparator কাজমতো বিকল্প দেয়। তুলনার চুক্তি মানো, সমান key-এর সিদ্ধান্ত স্পষ্ট করো। এবার nested ক্লাসে scope আর স্টেটের দরকার অনুযায়ী helper সাজাও।
