Pass an operation as a value

One result report adds bonus marks, another keeps passing marks, and a third totals them. You can describe each operation without writing a new named class. A lambda is a function-shaped expression that implements the operation of a functional interface.

A stream describes a traversal pipeline over values. You can filter unwanted values, map each remaining value to another form, then collect or reduce the result. Think of a report passing through several workstations, each with one clear task.

Lambdas and streams are related but separate. A lambda can be used in a button listener or comparator without any stream. A stream can use existing method references instead of inline lambdas. Learn the operation’s type and contract before trying to make a chain shorter.

The examples use bounded exam data. They preserve the input collections and build results through transformations. That makes the relationship between source values and final output easier to trace than updating an external accumulator from several callbacks.

Let the target interface define the shape

IntUnaryOperator bonus = mark -> mark + 2;
Predicate<Integer> passing = mark -> mark >= 40;
Function<String, Integer> length = String::length;
Consumer<String> display = System.out::println;

A functional interface has one abstract operation, ignoring declarations equivalent to public Object methods. It can still contain default and static methods. The target type tells the compiler how many parameters the lambda accepts and what it returns.

IntUnaryOperator accepts one primitive int and returns int. Predicate<T> accepts T and returns boolean. Function<T,R> converts T to R. Consumer<T> accepts T without returning a value. Supplier<T> produces T without an argument. Primitive-specialized interfaces avoid boxing when that matters.

A one-expression lambda returns that expression’s value when the contract needs a result. A block lambda uses braces and explicit return statements. Parameters can be inferred; parentheses are required for multiple parameters or explicit types. Keep the body short enough that its purpose remains visible.

stream creates a source traversal. filter and map are intermediate operations: they describe work but normally do not traverse until a terminal operation needs results. collect, reduce, count and forEach are terminal operations. A short-circuiting terminal operation may not visit every source element.

A pipeline can process one element through several stages before moving to the next. Do not imagine that every intermediate stage necessarily builds a separate list. Some operations, such as sorted, must retain values before they can produce the ordered result.

A collection is reusable storage. A stream is a single-use traversal description. After a terminal operation, create a new stream from the source for another independent calculation. Reusing the consumed stream can raise IllegalStateException.

Use functions for adjustment, selection and aggregation

Capture a stable bonus

The adjustment lambda adds four and caps the result at 100. It produces 74 and 100 from 70 and 99. The local bonus is effectively final. The lambda may read it, but the enclosing code cannot reassign that binding after initialization.

Filter before transforming

The marks pipeline removes 35 before adding two to accepted marks. The result is [42, 77]. Reversing those stages would be a different rule: a mark of 39 could become passing after adjustment. Stage order is part of the business contract.

Reduce with an identity

Addition uses zero as an identity. An empty stream therefore totals zero, while 3, 5 and 7 total 15. Integer::sum names the static addition method without writing a two-parameter lambda. This is safe for the small bounded values shown.

Reuse existing instance methods

String::toUpperCase invokes the method on each encountered string. System.out::println invokes a method on a particular existing receiver. The uppercase result is a separate unmodifiable list; printing the source afterward confirms that its original strings remain unchanged.

Recognize four reference forms

A static reference such as Integer::sum points to a class method. A bound instance reference such as System.out::println carries a specific receiver. An unbound instance reference such as String::length uses an incoming argument as the receiver. A constructor reference such as ArrayList::new creates an object when invoked.

The target interface checks compatibility, including parameter and result types. The same written method name can be overloaded, so surrounding type information still matters. A method reference does not mean that the method runs immediately when the reference is created.

Use a reference when the existing method’s name explains the action. Use a lambda when you need extra conditions or combine operations. Avoid replacing a readable lambda with a cryptic reference merely to remove characters.

Lambdas preserve the enclosing this rather than creating the anonymous-class this. Captured local bindings must be final or effectively final. Captured objects may still be mutable, so this restriction alone does not make callbacks thread-safe.

Choose a result contract

reduce combines values into one result using an associative operator. Associative means regrouping does not change the result. Integer addition is suitable within the stated bounds. Subtraction is not: grouping 10-3-2 differently can change the answer.

The identity must leave a value unchanged when combined with it. Zero works for addition; ten does not. A sequential sum starting at ten may look useful, but parallel partitions can each receive that invalid identity. Sum from zero, then add a one-time adjustment afterward.

An identity-free reduce returns Optional because an empty stream has no element to return. Optional is a container representing a present or absent value. Handle absence with an explicit fallback or branch rather than assuming every source has a first result.

collect builds a container using a collection protocol. Collectors.toList does not promise a particular concrete list class or mutability contract. Stream.toList explicitly returns an unmodifiable list. If later mutation is required, request a container with Collectors.toCollection(ArrayList::new).

mapToInt converts boxed numeric elements into an IntStream. Its sum operation naturally returns zero on empty input. For larger domains, use mapToLong before multiplication or accumulation so intermediate arithmetic does not overflow int first.

Keep pipelines independent of changing external state

A stream function should normally be stateless and not interfere with its source. Removing elements from the source list inside filter can invalidate traversal. Updating an external counter makes the result depend on callback execution details rather than a visible reduction.

Parallel streams introduce additional requirements. Updating one ordinary ArrayList from parallel forEach can race. A suitable collector coordinates partial results through its protocol. Parallel execution is not automatically faster; splitting, synchronization and merging have costs.

Encounter order comes from the source when the source defines one. A list stream has sequence order. HashSet does not supply a sorted report order. Use sorted for a deterministic ordering, and remember that parallel forEach may invoke actions in a different order; forEachOrdered has an explicit encounter-order contract.

Streams created from I/O resources, such as Files.lines, need closing even though many collection streams do not. Put resource-backed streams in try-with-resources. A tidy pipeline does not eliminate resource ownership or checked-failure decisions.

Inspect an empty report and a threshold value

The passing-total exercise accepts an empty list. filter then sees no elements, mapToInt sees no elements and sum returns zero. The same result occurs when all marks are below 40, but the reasoning is different: those elements were visited and rejected.

A mark of exactly 40 must survive the filter. Writing greater than 40 would silently exclude it. A mark of 39 must not survive merely because a later adjustment could raise it. Check these boundary values whenever you change pipeline order or a predicate.

For distinct room labels, repeated lab becomes one value before sorting. The sorted terminal print gives gate, hall and lab in order for the demonstrated labels. Equality decides duplicates; ordering decides presentation. Those are separate stages with separate purposes.

Avoid chains that hide a different rule

Expecting a discarded pipeline to do work

Calling map without a terminal operation normally performs no traversal. Do not put required business side effects inside a lazy transformation. Return or consume a meaningful result.

Reusing a stream

count consumes its stream. A later collect on the same object is invalid. Keep the source list or create a supplier that makes a fresh stream when several independent reports are required.

Mutating an unmodifiable result

Calling add on a toList result throws UnsupportedOperationException. Choose an explicit mutable destination at collection time when editing is part of the next operation.

Make the data flow easy to read

  • Name complex predicates instead of nesting several conditions inline.
  • Check stage order with a value close to the acceptance boundary.
  • Use an identity that matches the combining operation.
  • Prefer loops when early exits or stateful workflows are clearer.
  • Define locale rules for text transformations in real multilingual data.

Lambdas and modern stream results

Lambdas, method references and streams arrived in Java 8. Stream.toList arrived in Java 16. This lesson targets Java 17 and distinguishes that unmodifiable result from the weaker guarantees of Collectors.toList. No parallel execution is needed for the examples.
