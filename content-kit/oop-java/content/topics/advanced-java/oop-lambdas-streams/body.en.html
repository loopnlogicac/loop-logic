Describe a transformation as a small operation

A marks report may keep passing marks, add moderation, then compute a total. A lambda supplies a short implementation of one operation. A stream describes a pipeline that takes elements through operations such as filtering and mapping before producing a result. Neither feature requires creating a new named class for each step.

You already used comparators to describe an ordering policy. Comparator is a functional interface: it has one abstract operation after the interface rules are applied. A lambda receives arguments and provides that operation's result. The compiler needs a target type to know what those arguments and the result mean.

Streams are useful when a data transformation reads naturally from left to right. They do not replace every loop. A loop may express early exit, indexed updates or a stateful workflow more clearly. Choose the form that makes the operation and its effects easiest to explain.

Match a lambda to its target contract

A lambda has parameters, an arrow, and either an expression or a block body. For an expression body, Java returns the expression value when the target requires a result. A block body needs explicit return statements for result paths. A void operation can use a compatible statement expression or a block with no returned value.

Predicate<T> tests a value and returns boolean. Function<T,R> transforms T into R. Consumer<T> accepts a value without returning a result. Supplier<T> provides a value without receiving an argument. Primitive specializations such as IntUnaryOperator avoid boxing for common numeric operations.

The annotation @FunctionalInterface asks the compiler to verify the intended single abstract operation. Default and static methods do not add abstract operations. Redeclarations of public Object methods are treated specially and do not create an additional functional requirement. Do not count every method name mechanically when checking an interface.

Predicate<Integer> passing = mark -> mark >= 40;
Function<String, Integer> length = text -> text.length();
IntUnaryOperator bonus = mark -> Math.min(100, mark + 5);
// Block form:
IntUnaryOperator twice = value -> {
    return value * 2;
};

Separate pipeline construction from execution

A stream starts from a source such as a collection. Intermediate operations return another stream description. filter keeps elements matching a predicate; map changes each retained element. A terminal operation such as reduce, collect, count or toList requests the final result and triggers traversal.

Building a pipeline does not normally process its elements yet. This is called lazy evaluation. A terminal operation may also short-circuit when it has enough information. For example, anyMatch can stop after a matching element. Avoid using incidental side effects as evidence that every intermediate lambda must run.

A stream can be consumed only once. After a terminal operation, create a new stream from the source for another calculation. The collection may still exist unchanged, but the stream traversal has been used. Saving one Stream variable and calling count twice is not equivalent to iterating a collection twice.

filter does not remove elements from the source collection. map does not automatically replace source entries either. In a well-behaved pipeline, you compute a new result from existing values. Mutating the source during traversal breaks the non-interference expectation and can produce failures or unpredictable behaviour.

marks [35, 40, 70]
    filter >= 40  -> [40, 70]
    map + 5       -> [45, 75]
    reduce sum    -> 120
source remains [35, 40, 70]

Use an existing method as the operation

A method reference is a compact way to refer to a method matching the target contract. Integer::parseInt refers to a static method. text::startsWith refers to an instance method on one existing text object. String::length refers to an instance method where the stream element supplies the receiver.

Constructor references such as ArrayList::new can provide objects through a Supplier or another compatible factory contract. The target interface determines which constructor arguments are expected. Method references do not call every method immediately when written; they describe an operation that runs when invoked through the target.

Use a reference when it clarifies a familiar single method call. Keep a lambda when you need a condition, a combined expression or a useful parameter name. mark -> mark + bonus is often clearer than creating a helper method solely to obtain a reference. Readability matters more than making every lambda shorter.

Like local classes, lambdas capture final or effectively final local variables. They do not introduce their own this. A captured collection can still be mutable, so capture is not an immutability guarantee. When operations may run on several threads, shared mutable state needs an explicit concurrency policy.

Pick an identity and a result container carefully

reduce combines values into a result. For summation, zero is an identity because adding zero changes nothing. The combiner must be associative for splitting and regrouping to preserve the result. Subtraction is not associative, so a reduction using subtraction is not a safe substitute for a left-to-right loop across parallel execution.

A reduce without an identity returns Optional because an empty stream has no first value to combine. Optional represents presence or absence; choose orElse when a default has a real meaning. Do not call get without considering emptiness. For an empty total, an identity-based sum naturally yields zero.

collect performs a mutable reduction into a result container. Collectors.toCollection(ArrayList::new) gives an ArrayList when you need a mutable list explicitly. Stream.toList, introduced in Java 16, returns an unmodifiable list. Collectors.toList does not promise a particular implementation or mutability contract, so avoid claiming it always creates ArrayList.

Primitive streams such as IntStream support sum and average without boxing each element. mapToInt(String::length) extracts primitive lengths. average returns OptionalDouble because an empty set of values has no average. A zero total and an absent average are different facts and should lead to different output decisions.

Keep side effects and parallel work deliberate

A sequential stream over a list normally follows encounter order. Filtering preserves that order among retained elements, and a list collection can preserve it in the result. Sorting establishes another order. A source such as HashSet does not provide the same ordered-list promise, so choose or establish order before deterministic display.

Calling parallel is not an automatic speed improvement. Splitting work, combining results and coordinating resources all have costs. Operations that block, mutate shared state or depend on sequence can be especially unsuitable. Start with sequential pipelines for these small datasets, then measure a real workload before introducing parallel execution.

Do not add to a shared ArrayList from parallel forEach. The unsynchronized writes can conflict. Use a proper collector that manages accumulation and combination. Even when synchronization prevents corruption, arbitrary side effects can obscure the pipeline's meaning and make tests dependent on scheduling.

forEach expresses an action rather than a transformation. When order matters in a parallel pipeline, forEachOrdered provides an encounter-order guarantee if the source has one. It can constrain parallel benefits. These examples avoid parallel execution entirely so that their teaching output follows a simple, explicit sequence.

Distinguish filtering values from mutating records

Filtering a list of mutable Student objects creates another sequence of references, not independent student copies. If you later change one retained student's mark, both lists can observe that same object. A pure pipeline avoids mutation while it runs, but the resulting references may still point to mutable state afterward.

When a report must represent a historical snapshot, map each object to an immutable value with the required fields. A record of primitive marks and immutable names can serve that purpose. Choose the ownership boundary deliberately rather than treating stream collection as automatic deep copying.

Avoid hiding control flow in a pipeline

An empty filter result is normal. Decide whether the terminal result should be zero, an empty list, false or an Optional. The answer depends on the operation, not on a universal empty-stream rule. Test the no-passing-marks case separately from a mixed class.

A lambda that increments an external holder to compute a total hides reduction state. Use sum or reduce instead. A stateful operation may appear to work sequentially but become incorrect under parallel execution. Make the combination rule visible so another reader can reason about empty input and regrouping.

Checked exceptions cannot be thrown from a lambda unless the target method declares a compatible throws clause. Most standard Function contracts do not. Perform file loading before a pure transformation, or translate failure through a deliberate boundary. Do not bury IOException in an empty catch simply to make a lambda compile.

Use the correct list-result contract

Lambdas, method references and streams arrived in Java 8. Stream.toList needs Java 16, so it is available under Java 17. It returns an unmodifiable list. The examples use explicit collectors where a mutable destination is part of the lesson. Newer stream conveniences are outside this baseline.

Make each stage tell one part of the story

Use a functional interface to define an operation, then choose a lambda or method reference to implement it. Separate filtering, transformation and reduction. Check laziness, empty results and mutation rules before predicting output. Enums and records provide clearer value types for these pipelines.
