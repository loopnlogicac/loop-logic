তৈরি কাজ শেয়ার করো, বাকি ধাপ চাইল্ডকে দাও

সব ফলাফলের রিপোর্টে একই হেডিং আর বন্ধনী লাগতে পারে, কিন্তু ভেতরের তথ্য আলাদা। প্রতিটি চাইল্ডে পুরো প্রক্রিয়া লিখলে অমিল হওয়ার সুযোগ বাড়ে। অ্যাবস্ট্রাক্ট ক্লাস তৈরি কাজ রেখে বেছে নেওয়া কিছু অপারেশন সাবক্লাসকে পূরণ করতে বলে।

অ্যাবস্ট্রাক্ট ক্লাসের ভেরিয়েবল বা প্যারামিটার লেখা যায়, সরাসরি new দিয়ে অবজেক্ট বানানো যায় না। concrete সাবক্লাস বাকি কাজ পূরণ করে। তাই new Plot() না চললেও Plot ভেরিয়েবলে Rectangle রাখা যায়।

এতে শুধু খালি মেথড থাকে না। private ফিল্ড, কনস্ট্রাক্টর, তৈরি অপারেশন আর helper মেথডও থাকে। সম্পর্কিত ক্লাসগুলো স্টেট বা অ্যালগরিদম শেয়ার করলে কাজে আসে। প্রতিটি চাইল্ডকে প্যারেন্টের চুক্তিও মানতে হবে।

অসম্পূর্ণ ক্লাস আর অপারেশন চিহ্নিত করো

abstract class Plot {
    abstract int area();
}
class Rectangle extends Plot {
    @Override
    int area() {
        return 24;
    }
}

abstract মেথডে বডির বদলে সেমিকোলন থাকে। কলের ধরন আর রিটার্ন টাইপ বলে দাও। ক্লাসটিও abstract হতে হবে। concrete সাবক্লাস সঠিক signature আর ওভাররাইডের নিয়ম মেনে বডি দেয়।

সাবক্লাস কিছু কাজ পূরণ করে নিজেও abstract থাকতে পারে। পরের concrete চাইল্ডকে সব বাকি abstract মেথড পূরণ করতে হবে। Java নিজে শূন্য, null বা খালি কাজ বসায় না। অসম্পূর্ণ concrete ক্লাস কম্পাইল হয় না।

abstract ক্লাসে একটিও abstract মেথড না থাকতে পারে। শুধু নির্দিষ্ট ধরনের অবজেক্ট বানাতে দিতেও এটি ব্যবহার হয়। একই ক্লাস abstract আর final হতে পারে না। একটি এক্সটেন্ড করে পূরণের সুযোগ চায়, অন্যটি এক্সটেন্ড করাই আটকায়।

তৈরি মেথড থেকে abstract hook কল হয়

Hook হলো বড় অ্যালগরিদমের এমন অপারেশন, যার আলাদা কাজ সাবক্লাস দেয়। Template method বড় ধাপগুলোর ক্রম রাখে, কিছু ধাপ hook-কে দেয়। এখানে render() রিপোর্ট সাজায়, detail() বদলানো তথ্য দেয়।

Report.render() {final}
       |
       +-- opening bracket
       +-- heading()       shared implementation
       +-- detail()        subclass hook
       +-- closing bracket

MarkReport --|> Report

MarkReport-এ render() কল করলে Report-এর তৈরি মেথড চলে। সেটি detail() কল করলে রানটাইম dispatch-এ MarkReport.detail() চলে। অ্যালগরিদম এক জায়গায় থাকে। render final হলে সাবক্লাস ক্রম বদলাতে পারে না।

এই pattern-এ final বাধ্যতামূলক নয়। পুরো প্রক্রিয়া বদলানো যুক্তিযুক্ত হলে ওভাররাইড করতে দিতে পারো। ক্রমটি জরুরি নিয়ম রক্ষা করলে final দিয়ে স্থির রাখো।

Hook-এর চুক্তি স্পষ্ট করো। যেমন grade hook শুধু ০ থেকে ১০০ নম্বর নেবে, খালি নয় এমন grade দেবে। সব সাবক্লাসকে তা মানতে হবে। abstract ঘোষণা বডি থাকার নিশ্চয়তা দেয়, বডির অর্থ যাচাই করে না।

concrete চাইল্ড দিয়ে তৈরি অ্যালগরিদম চালাও

জ্যামিতির অপারেশন চাও

Rectangle প্রস্থ আর উচ্চতা দিয়ে area() দেয়। Plot অর্থহীন ডিফল্ট ক্ষেত্রফল না দিয়ে একই কলের চুক্তি দেয়।

রিপোর্টের বাইরের কাঠামো ঠিক রাখো

Report.render() হেডিং, সেপারেটর আর বন্ধনী রাখে। MarkReport শুধু ভেতরের detail বদলায়।

প্যারেন্টের শেয়ার করা স্টেট বসাও

Grant কনস্ট্রাক্টরে ডিপার্টমেন্ট রাখে। MeritGrant পরিমাণ দেয় আর প্যারেন্টের লেবেল বানানোর কাজ ব্যবহার করে।

abstract প্যারেন্টের কনস্ট্রাক্টরও চলে

কনস্ট্রাক্টর abstract হয় না। সাবক্লাসের অবজেক্ট তৈরিতে শুরুর স্টেট বসাতে হয়। MeritGrant পরিমাণ রাখার আগে Grant ডিপার্টমেন্ট পায়। abstract হওয়ায় সরাসরি new Grant বন্ধ থাকে, প্যারেন্টের initialization বন্ধ হয় না।

private শেয়ার করা ফিল্ড দিয়ে প্যারেন্ট নিজের নিয়ম ধরে রাখে। সাবক্লাস উপযুক্ত protected বা public মেথড ব্যবহার করুক। সব ফিল্ড protected করলে ভেতরের স্টোরেজের ওপর নির্ভরতা বাড়ে। অল্প, স্থির অপারেশন রাখো।

কনস্ট্রাক্টর থেকে ওভাররাইডযোগ্য hook কল কোরো না। Java তখনও চাইল্ডের ইমপ্লিমেন্টেশন বেছে নেয়। চাইল্ডের ফিল্ডে চাওয়া মান তখনও বসেনি। আগে অবজেক্ট তৈরি করো, পরে আলাদা অপারেশনে কাজ চালাও।

বেস কনস্ট্রাক্টর detail() ডাকলে চাইল্ডের mark অ্যাসাইনের আগেই মেথড চলতে পারে। চাওয়া নম্বরের বদলে ডিফল্ট শূন্য দেখবে। অবজেক্ট তৈরির পরে render() কল করলে এই সমস্যা থাকে না।

abstract মেথড private হতে পারে না; আলাদা সাবক্লাসকে সেটি পূরণ করতে হয়। final-ও হয় না, কারণ ওভাররাইড দরকার। static-ও হয় না; static কাজ টাইপের, রানটাইম অবজেক্টের অসম্পূর্ণ অপারেশন নয়।

ছোট, স্পষ্ট দায়িত্বের extension point রাখো

রিপোর্টে ইনপুট যাচাই, হিসাব, তারপর ফরম্যাট করা লাগতে পারে। সীমা সবার এক হলে যাচাইয়ের কাজ তৈরি রাখো। নীতি আলাদা হলে হিসাব abstract করো। আউটপুটের গঠন সবার এক হলে ফরম্যাটও তৈরি রাখো।

বেশি hook হলে সাবক্লাসকে ভেতরের ক্রম আর গোপন নির্ভরতা বুঝতে হয়। step3-এর বদলে calculateGrade বা buildDetail নাম দাও। কোন ডেটা পড়বে, কী ফেরাবে লিখে দাও।

Hook স্টেট বদলালে বারবার কলে ফল বদলায়। Counter কুইজে result(), step() দুবার ডাকে। একবার হিসাব লাগলে একবার কল করে ফল রাখো। কাজটি স্টেট বদলায় না এমন ধরে নিও না।

সম্পর্কহীন ক্লাসে একই ক্ষমতা চাইলে, শেয়ার করা ইনস্ট্যান্স স্টেট না লাগলে, ইন্টারফেস ভালো হতে পারে। অ্যাবস্ট্রাক্ট ক্লাস সরাসরি ক্লাস প্যারেন্টের একমাত্র জায়গাটি নেয়। পরের পাঠে একাধিক ইন্টারফেসের চুক্তি দেখবে।

C জানা থাকলে: abstract ঘোষণা নিজে বসানোর মতো function pointer ফিল্ড তৈরি করে না। concrete ক্লাস সব কাজ পূরণ করেছে কি না কম্পাইলার দেখে। তারপর সাধারণ ইনস্ট্যান্স কলে রানটাইম সঠিক মেথড বেছে নেয়।

সবার দরকার এমন স্টেটই প্যারেন্টে রাখো

সব চাইল্ডের দরকার না হলে ফিল্ড প্যারেন্টে তুলো না। তাতে অন্য চাইল্ডে অর্থহীন ডিফল্ট আর জটিল যাচাই লাগে। সব গ্রান্টে ডিপার্টমেন্ট থাকলে Grant-এ রাখো। শুধু বৃত্তির ranking সংশ্লিষ্ট চাইল্ডে থাকুক। প্যারেন্ট ভবিষ্যতের সব ফিল্ড জমাবার জায়গা নয়।

অসম্পূর্ণতা বুঝে রাখো

abstract টাইপ সরাসরি বানানো

কনস্ট্রাক্টর থাকলেও new Plot() চলে না। concrete shape বানিয়ে Plot ভেরিয়েবলে রেফারেন্স রাখো। ঘোষিত টাইপ আর তৈরি ক্লাস এক হতে হয় না।

ইনহেরিট করা একটি কাজ ভুলে যাওয়া

start() পূরণ করলে stop() পূরণ হয় না। বাকি কাজ লেখো বা মাঝের ক্লাস abstract রাখো। আগের প্যারেন্ট আর ইন্টারফেসের চুক্তিও দেখো।

চাইল্ডের স্টেট বসার আগে hook কল

প্যারেন্ট কনস্ট্রাক্টর চাইল্ড তৈরি হওয়া পর্যন্ত dispatch আটকে রাখে না। সেখানে তৈরি প্যারেন্ট স্টেটের ওপর নির্ভর করা private বা final helper ব্যবহার করো।

বিশেষ রানটাইম মোড লাগে না

Java 17-এ সাধারণ কম্পাইলেই অ্যাবস্ট্রাক্ট ক্লাস, কনস্ট্রাক্টর চেইন আর template method চলে। preview syntax নেই। এখানে template মানে অ্যালগরিদমের কাঠামো; C++ template বা Java জেনেরিক টাইপ প্যারামিটার নয়।

কোথায় কাজ বদলাবে ভেবে ঠিক করো

অ্যাবস্ট্রাক্ট ক্লাস স্টেট আর সাধারণ কাজ রাখে, দরকারি কিছু অপারেশন অসম্পূর্ণ রাখে। concrete চাইল্ড hook পূরণ করে; template method সাধারণ ক্রম ধরে রাখে। এবার এই মডেলের সঙ্গে ইন্টারফেসের ক্ষমতাভিত্তিক মডেল তুলনা করো।
