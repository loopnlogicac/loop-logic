কাজের যতটুকু access লাগে ততটুকু দাও

Results clerk নাম-নম্বর পড়তে চাইতে পারেন, grade বদলাতে নয়। Shop app অর্ডার বানাবে, সার্ভার অ্যাকাউন্ট চালাবে না। আলাদা অ্যাকাউন্ট ভিন্ন কাজের ক্ষমতা বলে এবং এক জায়গার ভুলের ক্ষতি কমায়।

Authentication কে connect করছে দেখে; authorization কী করতে পারবে দেখে। Login সফল মানেই সব টেবিল read নয়। আলাদা রাখলে অকারণে admin right না দিয়েই access-denied বোঝা যায়।

Least privilege মানে কাজের দরকারি action ও ডেটা-ই grant। Operation,scope,কলাম,delegation,অ্যাকাউন্ট lifetime সবই ধরো। প্রথম কোয়েরি চালাতে রিপোর্ট reader-কে global admin দেবে না।

Exercise isolated teaching সার্ভার-এ admin হিসেবে চলে। Named temporary অ্যাকাউন্ট বানায়, narrow grant দেখে, শেষে সরায়। Sample পাসওয়ার্ড শুধু local অনুশীলনের। আসল credential protected runtime secret-এ, rotation process-সহ রাখো।

অ্যাকাউন্ট পরিচয়-তে host-ও আছে

MySQL অ্যাকাউন্ট user ও host জোড়া, যেমন 'report_reader'@'localhost'। অন্য host-এ আলাদা credential-privilege অ্যাকাউন্ট হতে পারে। শুধু দৃশ্যমান username-কে সম্পূর্ণ পরিচয় ভাববে না।

CREATE USER অ্যাকাউন্ট ও authentication সেটিং বানায়, selected ডেটাবেস-এ টেবিল access দেয় না। GRANT নির্দিষ্ট পারমিশন, যেমন এক ভিউ-তে SELECT বা কলাম-এ UPDATE। REVOKE নির্দিষ্ট grant, DROP USER অ্যাকাউন্ট সরায়।

Global,ডেটাবেস,টেবিল,কলাম scope আছে। সব ডেটাবেস-এর grant এক schema-র students থেকে অনেক বড়। UPDATE(hometown)-এ edit সীমিত হয়; কিন্তু actual predicate-expression পড়তে কী SELECT লাগে তাও দেখো।

Exercise ডেটাবেস নাম generated। DATABASE() ও prepared SQL দিয়ে trusted নাম GRANT/REVOKE-এ বসে। Ordinary value placeholder identifier নয়, তাই identifier quoting লাগে। শুধু exercise-এর trusted schema নাম নেওয়া হয়েছে।

Untrusted ইনপুট জুড়ে privilege স্টেটমেন্ট বানাবে না। Value ও identifier আলাদা handling চায়; administrative SQL-এ narrow interface দরকার। অ্যাকাউন্ট management সাধারণ user ফিচার নয়, admin-এর কাজ।

CREATE USER '<user>'@'<host>' IDENTIFIED BY '<local_secret>';
GRANT <needed_privileges> ON <schema>.<object> TO '<user>'@'<host>';
REVOKE <removed_privileges> ON <schema>.<object> FROM '<user>'@'<host>';
DROP USER '<user>'@'<host>';

তৈরি থেকে সরানো পর্যন্ত grant দেখো

CREATE USER-এর পর current schema-তে টেবিল grant নেই। প্রথম উদাহরণ metadata রো গুনে দেখায়। অ্যাকাউন্ট বানানো ও কাজের reporting login বানানো আলাদা; ডেটা পারমিশন ভেবে দিতে হবে।

Students-এ SELECT দিলে টেবিল-level authorization হয়। information_schema.table_privileges current schema-র SELECT দেখায়। একই scope-এ REVOKE-এর পরে খালি। DROP USER পর্যন্ত অ্যাকাউন্ট থাকে।

Practice-এ SELECT,UPDATE দিয়ে UPDATE revoke; SELECT থাকে। REVOKE নির্দিষ্ট grant সরায়, সব reset নয়। একটি টেবিল grant সরানো broad grant-এর ওপর deny rule-ও নয়।

প্রযোজ্য scope ও active role-এর privilege যোগ হয়। টেবিল SELECT সরালেও ডেটাবেস SELECT পড়তে দিতে পারে; role-ও পারে। Narrow revoke ক্ষমতা সরিয়েছে বলার আগে পুরো effective design দেখো।

নাম-only ভিউ approved interface দিতে পারে। SQL SECURITY DEFINER-এ underlying access owner context নেয়। Reader ভিউ SELECT পেলেই চলে, students direct SELECT লাগে না। বাস্তবে কম privilege-এর owner নাও, শক্ত admin নয়।

Fresh schema-তে চালানোর সুবিধায় exercise admin definition বানায়। Production owner হিসেবে সুপারিশ নয়। শিক্ষা হলো caller-এর ভিউ grant ও definer-এর underlying ক্ষমতা আলাদা রাখা এবং বিকল্প base access বন্ধ করা।

UPDATE(hometown) আরও narrow edit। Metadata column_privileges-এ, complete টেবিল UPDATE নয়। Real স্টেটমেন্ট target অ্যাকাউন্ট-এ পরীক্ষা করো, WHERE-এ পড়া কলাম-সহ। এক grant listing compatibility প্রমাণ নয়।

সঠিক operation ও scope যাচাই করো

প্রথম অ্যাকাউন্ট টেবিল access পায় না; পরেরটি এক পারমিশন পেয়ে হারায়। ভিউ example restricted interface দেয়। Temporary reader-কে ALL,global বা GRANT OPTION কোনোটিই দেওয়া হয় না।

Metadata admin কানেকশন-এ দেখা হয়। Target user দিয়ে login ও allowed-denied operation test-এর বিকল্প নয়। Deployment review-তে ওই user দিয়ে approved read ও rejected write দুটোই যাচাই করো।

টেবিল access ছাড়া অ্যাকাউন্ট

নতুন অ্যাকাউন্ট-এর টেবিল grant নেই। দেখে teaching অ্যাকাউন্ট সরানো হয়।

Student read grant,পরে revoke

প্রথম রিপোর্ট SELECT, দ্বিতীয় খালি। Dynamic SQL fixed schema নয়, current exercise ডেটাবেস চেনে।

Narrow ভিউতে নাম

শুধু public_students-এ SELECT। Exercise admin owner হলেও deployed ভিউ-তে narrow owner চাই।

Narrow revoke-এর পরেও broad access থাকতে পারে

সব authority source দেখো

টেবিল SELECT revoke-এর পরেও ডেটাবেস/global grant বা role দিয়ে students পড়া যেতে পারে। SHOW GRANTS ও role সেটিং দেখে নীতি অনুযায়ী আসল broad source সরাও। MySQL সাধারণ টেবিল-level deny system নয়।

Access এরর-এ ALL ON *.* দেবে না। এতে এক রিপোর্ট-এর বাইরেও অ্যাকাউন্ট-management ও write ক্ষমতা আসে। আগে operation,object,effective অ্যাকাউন্ট চেনো। কাজের অধিকার থাকলেই narrow missing grant দাও।

Context দেখে reconnect

USER() ও CURRENT_USER() কানেকশন পরিচয় ও authenticated context আলাদা দেখাতে পারে। Host matching ও সেটিং-এ local কানেকশন-এর অনুমান ভুল হয়। Definer object-এ context আরও আলাদা; relevant call-এ দেখো, এক মানকে universal পরিচয় ধরবে না।

Scope ও active session অনুযায়ী grant change-এর effect timing বদলায়। পরিষ্কার পরীক্ষায় target অ্যাকাউন্ট reconnect করো। Mysql system grant টেবিল সরাসরি edit সাধারণ workflow নয়। CREATE USER,GRANT,REVOKE-এ routine FLUSH PRIVILEGES লাগে না।

অনুমোদিত ও নিষিদ্ধ দুই কাজ পরীক্ষা করো

App ও admin অ্যাকাউন্ট আলাদা রাখো। রিপোর্ট reader-এর প্রয়োজন না হলে write নয়। Controlled delegation না থাকলে GRANT OPTION নয়। Object grant-এর সঙ্গে host,পাসওয়ার্ড,অ্যাকাউন্ট removal review করো।

Fresh target কানেকশন-এ আসল রিপোর্ট চালাও। Approved ভিউ read সফল, sensitive direct read/write নীতি অনুযায়ী ব্যর্থ কি না দেখো। Broad grant ও active role-ও দেখো। Narrow example সফল মানেই বিকল্প authority নেই নয়।

MySQL 8-এ অ্যাকাউন্ট আলাদা করে বানাও

MySQL 8.0/8.4-এ GRANT-এর আগে explicit CREATE USER; GRANT অ্যাকাউন্ট-creation shortcut নয়। Authentication ডিফল্ট ভার্সন-এ বদলায়; পুরোনো plugin instruction অন্ধভাবে নেবে না। Dataset baseline 8.0.16, অ্যাকাউন্ট action-এ উপযুক্ত admin privilege চাই।

এক grant নয়, কার্যকর ক্ষমতা দেখো

অ্যাকাউন্ট-এ পরিচয়,authentication ও additive পারমিশন source থাকে। সবচেয়ে ছোট কাজের interface দাও, অপ্রয়োজনীয় ক্ষমতা সরিয়ে target কানেকশন-এ যাচাই করো। এরপর functional dependency-তে টেবিল design-এর নিয়ম বোঝো।
