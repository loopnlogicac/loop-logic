Stored procedure CALL-এ চলে,multi-statement,result set,parameter-এ মান ফেরায়। Stored function এক declared scalar ফেরায়,expression-এ চলে। ছোট syntax নয়,interface দেখে বাছো।

Database-এ রাখলেই faster-safer নয়। Privilege,transaction boundary,error handling চাই। App function-এর মতো routine-ও expensive query লুকাতে পারে।

Client দিয়ে পুরো definition পাঠাও

BEGIN-END-এ কয়েক semicolon statement। mysql client সাধারণত semicolon-এ submission শেষ। DELIMITER client terminator বদলে পুরো routine একসঙ্গে পাঠায়।

DELIMITER server SQL নয়। // দিলে client তা পর্যন্ত অপেক্ষা,ভেতরের semicolon SQL separator। END//-এর পরে DELIMITER ; স্বাভাবিক করে। Driver প্রায়ই complete definition পাঠায়,DELIMITER বোঝে না।

Routine আর transaction boundary আলাদা

CALL atomicity ঠিক করে না

Ordinary procedure-এর সব statement CALL নিজে এক transaction করে না। Autocommit-এ explicit transaction ছাড়া update আলাদা commit। এক unit চাইলে caller-procedure contract বলো।

Caller-owned transaction procedure হঠাৎ COMMIT করবে না। আবার caller জানে ধরে start-end নয়। Owner document। Function-trigger-এর বাড়তি restriction,procedure-এর মতো transaction control নয়।

Progress আর declaration promise

Condition variable না বদলালে infinite। Condition,body,update আলাদা আঁকো। প্রতিটি পথে progress বা deliberate exit। Bound-validation missing increment সারায় না।

DETERMINISTIC একই input-এ একই ফলের দাবি,MySQL সব execution পরীক্ষা করে প্রমাণ নয়। Pass-label শুধু parameter-নির্ভর,table না পড়ায় NO SQL সত্য। Changing row পড়া function-এ একই declaration copy নয়।

Binary log-এ function creation-এ extra privilege/config লাগতে পারে। Failure admin policy,মিথ্যা behavior declaration-এর যুক্তি নয়। Actual data access-determinism বলো,DBA-র সঙ্গে authority মেটাও।

সব app code server-এ নয়,অল্প purposeful routine। Table-permission বদলালে dependency review। Routine stored থাকলেও assumption ভুল হতে পারে,versioned schema-তে dependent routine-ও ধরো।
