বড় প্রশ্নের ভেতর ছোট প্রশ্ন

Class গড়-এর ওপর ফল চাইলে আগে গড়, পরে বেশি mark। Subquery ছোট প্রশ্ন বড় রিপোর্ট-এর মধ্যে বলে। কত indent নয়, প্রশ্নের সম্পর্কটাই মূল।

Subquery অন্য স্টেটমেন্ট-এর ভেতর SELECT। এক value,রো,set বা temporary relation দেয়। এক গড়-এর তুলনা আর কোনো registration আছে কি না আলাদা, উপযুক্ত রূপ নাও।

জয়েন matching pair দেয় জানো। Membership outer রো-পিছু হ্যাঁ-না চায়। তাই জয়েন rewrite-এ মানুষ repeat হতে পারে। কোনোটিই সবসময় ভালো নয়, কাজের shape আলাদা।

উদাহরণ university ফল আর shop price নেয়। No enrollment,no mark,no category-পণ্য আলাদা empty case। কোনটি সামলাও আর কী ফল বাছো বলো।

Comparison-এর সঙ্গে subquery shape

Scalar subquery সর্বোচ্চ এক রো-এর এক কলাম। এক value চাইলে বন্ধনীতে। GROUP BY ছাড়া AVG এক aggregate রো দেয়, ইনপুট না থাকলে তাতে NULL।

Scalar-এ no রো-ও NULL, দুই রো-এ একই মান হলেও এরর। LIMIT 1 ভুল লুকিয়ে arbitrary রো নিতে পারে। সত্যিই এক রো চাইলে unique predicate বা অর্থপূর্ণ ordered selection।

Row subquery tuple comparison-এ কয়েক কলাম। Enrollment পরিচয় student_id-section_id। Left tuple আর ফল-এর সংখ্যা-position মিলবে। আলাদা IN list-এ আলাদা enrollment-এর ভুয়ো combination হতে পারে।

Table subquery FROM-এ, MySQL-এ alias চাই। Surrounding কোয়েরি-তে temporary relation। Grouped পেমেন্ট এক মোট/অর্ডার দিয়ে original পেমেন্ট multiply ছাড়া জয়েন করে।

SELECT <outer_columns>
FROM <outer_table> AS o
WHERE EXISTS (
    SELECT 1 FROM <inner_table> AS i WHERE <correlation>
)
ORDER BY <outer_keys>;

Membership, witness আর universal test

Value/tuple ফল set-এ আছে চাইলে IN। ভেতরে duplicate outer রো বাড়ায় না। Enrollment-এ Ayesha কয়েকবার হলেও students membership একবার দেয়।

যেকোনো qualifying রো যথেষ্ট হলে EXISTS। Selected expression অর্থহীন; SELECT 1 readable convention, one গুনতে নয়। NULL-সহ রো-ও true, empty false।

Correlated subquery outer value পড়ে। Missing-enrollment-এ inner WHERE current শিক্ষার্থী-এর সঙ্গে enrollment.student_id মেলায়। Student-পিছু প্রশ্ন ভাবো; optimizer বদলাতে পারে, execution strategy promise নয়।

Correlated গড় নিজের সেকশন গড়-এ তুলনা। 31-এ 85 আর 65, গড় 75, শুধু 85। Overall গড় অন্য প্রশ্ন, অন্য শিক্ষার্থী আসতে পারে।

ANY-তে অন্তত এক true। Study price-এর ANY-এর বড় হতে সস্তাটির বড় হলেই চলে। ALL-তে সব true, সবচেয়ে দামিরও বড় চাই। Strict greater-এ equal যথেষ্ট নয়।

Empty-তে ANY false, success দেখানোর candidate নেই। ALL true, ভাঙার candidate নেই। এটি vacuous truth। Business প্রশ্নে মানায় কি না আগে বোঝো।

NULL-এর পাশে অর্থ রক্ষা

Nullable exclusion-এ policy

NOT IN সহজ লাগে, কিন্তু nullable-এ বিপদ। 101 NOT IN (102, NULL)-এ প্রথম inequality true, NULL comparison unknown। মিলিয়ে unknown বলে WHERE বাদ, confirmed non-member নয়।

Missing-related-রো-তে NOT EXISTS পরিষ্কার। ভেতরে পরিচয় মেলিয়ে existence উল্টাও। Outer NULL কী-তেও policy চাই; equality match পায় না। NULL-NULL মিলবে চাইলে null-safe comparison বুঝে।

চাওয়া কলাম-এই correlation

ANY-ALL candidate-এ NULL থাকলেও সতর্ক। এক true ANY প্রতিষ্ঠা, এক false ALL ভাঙে; নইলে unknown থাকতে পারে। Empty rule সত্যিকারের empty-তে, এক NULL রো-তে নয়।

Unqualified correlation এড়াও। student_id = student_id inner-কে নিজের সঙ্গে মেলাতে পারে। Alias দিয়ে দুই owner লেখো। সিনট্যাক্স ঠিক self-comparison এক inner রো থাকলেই সবার EXISTS true করে।

Tuning-এর আগে readable equivalent

জয়েন rewrite-এ uniqueness দেখো। Unique বিভাগ কী-তে এক match/শিক্ষার্থী, enrollment-এ বহু। শুধু existence হলে EXISTS রাখো বা dedup requirement বলো। প্ল্যান-এর আগে semantics।

ছোট গ্রুপ হাতে দেখো, missing আর repeated match-সহ, তারপর empty inner। Ordinary ডেটা-তে এক লাগা কোয়েরি আলাদা হয়। পরে ইনডেক্স আর EXPLAIN-এ পারফরম্যান্স দেখো, প্রশ্ন না বদলে।

ফল shape portable

Scalar,রো,derived,quantified comparison MySQL 8.0/8.4-তে। Shared CHECK-এ 8.0.16+। Optimizer চলার পদ্ধতি বদলায়, cardinality আর NULL rule অর্থের অংশই থাকে।

Inner প্রশ্ন নির্দিষ্ট করো

এক value,membership set নাকি existence চাই ঠিক করো। Complete কী-তে correlate, empty আর NULL আলাদা ভাবো। পরের set operation-এ outer রো-প্রতি পরীক্ষা নয়, পুরো compatible ফল মেলাবে।
