বড় প্রশ্নের ভেতর ছোট প্রশ্ন

শিক্ষক class গড়-এর বেশি নম্বর চান। আগে গড়, তারপর সেটি ছাড়ানো নম্বর চাই। বড় রিপোর্ট-এর মধ্যে ছোট প্রশ্নটি subquery বলে। SQL কতটা ভেতরে লিখলে তার চেয়ে প্রশ্ন দুটির সম্পর্ক জরুরি।

Subquery অন্য SQL স্টেটমেন্ট-এর ভেতরের SELECT। একটি মান, value রো, candidate set বা temporary relation দিতে পারে। প্রশ্ন অনুযায়ী নাও। একটি গড়ের সঙ্গে তুলনা ও কোনো registration আছে কি না আলাদা কাজ।

জয়েন matching pair ফেরায়। Membership-এ outer রো-প্রতি শুধু yes/no লাগে। তাই subquery-র বদলে জয়েন-এ হঠাৎ মানুষ repeat হতে পারে। কোনোটি সবসময় ভালো নয়; কাজের shape আলাদা।

University ফল ও shop price আবার নেব। খালি case ইচ্ছাকৃত: enrollment নেই, recorded mark নেই, category-তে পণ্য নেই—ভিন্ন অবস্থা। কোয়েরি কোনটি সামলায় ও কী উত্তর দেয় বোঝাও।

Comparison-এর সঙ্গে subquery shape

Scalar subquery সর্বোচ্চ এক রো-এর একটি কলাম দেয়। একটি মানের জায়গায় parentheses-এ বসাও। GROUP BY ছাড়া AVG ঠিক একটি aggregate রো দেয়, তাই সুবিধা। ইনপুট mark না থাকলে মান NULL।

Scalar কোয়েরি-তে রো না এলেও NULL। দুই রো এলে একই মান হলেও এরর। LIMIT 1 ভুল লুকিয়ে arbitrary রো নিতে পারে। সত্যিই এক রো চাইলে unique predicate বা অর্থপূর্ণ ordered choice নাও।

Row subquery tuple comparison-এর জন্য একাধিক কলাম দেয়। Enrollment পরিচয় student_id,section_id pair। Left tuple ও ফল-এর কলাম সংখ্যা-অবস্থান মিলবে। আলাদা IN list দিলে ভিন্ন enrollment-এর ভুল combination চলতে পারে।

Table subquery FROM-এ থাকে; MySQL-এ alias চাই। বাইরের স্টেটমেন্ট-এর কাছে temporary relation-এর মতো। Grouped পেমেন্ট কোয়েরি অর্ডার-প্রতি মোট দিলে মূল পেমেন্ট multiply না করে জয়েন করা যায়।

SELECT <outer_columns>
FROM <outer_table> AS o
WHERE EXISTS (
    SELECT 1 FROM <inner_table> AS i WHERE <correlation>
)
ORDER BY <outer_keys>;

Membership, witness আর universal test

Value বা tuple ভেতরের ফল-এর member হলে IN নাও। ভেতরের repetition outer রো বাড়ায় না। Ayesha-র ID অনেক enrollment-এ থাকলেও students membership-এ একবার আসে।

যেকোনো qualifying inner রো যথেষ্ট হলে EXISTS। Selected expression গুরুত্বপূর্ণ নয়। SELECT 1 পাঠযোগ্য convention, এক গোনার অনুরোধ নয়। NULL-সহ রো-ও EXISTS true; খালি ফল false।

Correlated subquery outer কোয়েরির মান নেয়। Missing enrollment-এ inner WHERE বর্তমান শিক্ষার্থী ID-এর সঙ্গে মিলায়। Student-প্রতি প্রশ্নটি ভাবো। Optimizer ভেতরে বদলাতে পারে; এই mental model নির্দিষ্ট execution strategy-এর প্রতিশ্রুতি নয়।

Correlated গড় প্রতি ফল নিজের সেকশন গড়-এর সঙ্গে মেলায়। Section 31-এ 85,65-এর গড় 75, তাই শুধু 85। Overall গড় নিলে অন্য প্রশ্ন, অন্য শিক্ষার্থী-ও আসতে পারে।

ANY-তে অন্তত একটি comparison true চাই; study item-এর সস্তাটিকে ছাড়ালেই above ANY। ALL-এ সব true চাই, তাই সবচেয়ে দামিটিও ছাড়াতে হবে। Strict greater-than-এ maximum-এর সমান যথেষ্ট নয়।

খালি set-এ greater-than ANY false: সফলতার witness নেই। Greater-than ALL true: ভাঙার candidate নেই। এই universal empty-set rule vacuous truth। ব্যবসার প্রশ্নে মানায় কি না আগে ঠিক করো।

পেমেন্ট সারাংশ-তে inner কোয়েরি actual পেমেন্ট গ্রুপ করে। Outer LEFT JOIN পেমেন্ট-হীন অর্ডার রাখে। COALESCE missing মোট zero দেখায়; zero-valued পেমেন্ট রেকর্ড ইনসার্ট করা নয়।

NULL-এর পাশে অর্থ রক্ষা

Nullable exclusion-এ policy

বাদ দিতে NOT IN সহজ মনে হয়, NULL-এ ঝুঁকি। 101 NOT IN (102, NULL)-এ প্রথম inequality true, NULL তুলনা unknown। সম্মিলিত শর্ত unknown, তাই WHERE রো সরায়; confirmed non-member ধরে না।

Missing-related-রো-তে NOT EXISTS প্রায়ই পরিষ্কার। Inner কোয়েরি-তে পরিচয় মিলিয়ে existence negate করো। Outer NULL কী-তেও policy চাই: ordinary equality match পায় না। NULL-NULL match চাইলে ইচ্ছা করে null-safe comparison নাও।

চাওয়া কলাম-এই correlation

ANY-ALL candidate-এ NULL থাকলেও সতর্ক হও। একটি true ANY প্রমাণ করে; একটি false ALL ভাঙে। নইলে unknown ফল unknown রাখতে পারে। খালি-set নিয়ম আসল খালি ফল-এর; NULL-সহ এক-রো ফল নয়।

Unqualified correlation এড়াও। student_id = student_id inner কলাম নিজের সঙ্গে মেলাতে পারে। দুই মালিক alias-সহ লেখো। এমন বৈধ self-comparison-এ একটি inner রো থাকলেই সবার EXISTS true হতে পারে।

Tuning-এর আগে readable equivalent

জয়েন rewrite-এ uniqueness দেখো। Unique বিভাগ কী-তে শিক্ষার্থী-প্রতি একটি match, enrollment-এ অনেক। শুধু existence চাইলে EXISTS রাখো বা deduplication স্পষ্ট করো। প্ল্যান-এর আগে semantics তুলনা করো।

ছোট গ্রুপ হাতে দেখো: missing match, repeated match, তারপর খালি inner ফল। সাধারণ ডেটায় সমান দেখানো কোয়েরি-ও তখন আলাদা হবে। প্রশ্ন না বদলে পারফরম্যান্স দেখতে পরে ইনডেক্স ও EXPLAIN নাও।
