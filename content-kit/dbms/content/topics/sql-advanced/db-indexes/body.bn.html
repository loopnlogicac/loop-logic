মোটা register-এ প্রতিটি page পড়ে student পাওয়া যায়, name directory থাকলে কাছে যাওয়া যায়। Index এমনই আরেক পথ, সব lookup দ্রুত হবে তার promise নয়।

Index table data-র পাশে রাখা সহায়ক structure। B-tree key ক্রমে রেখে equality বা range পেতে দেয়। বাঁচা search কাজ traversal,storage,row-fetch খরচের বেশি হতে হবে।

Shared dataset ছোট, হাতে দেখা যায়; production speedup মাপা যায় না। Declaration-plan শব্দ শেখো, performance representative size,query,write,concurrency-তে দেখো।

Correctness আর access আলাদা। Normal secondary index যোগ-সরালে membership একই। ORDER BY নেই বলে print order বদলালে query-র ordering ত্রুটি, index predicate-এর অর্থ বদলায়নি।

দরকারি ক্রমে key

CREATE INDEX নাম আর column order বলে। Composite index-এ কয়েক key part। (department_id, student_name)-এ আগে department, ভেতরে name। উল্টো দিলে অন্য path।

B-tree সাধারণত leftmost prefix-এ শুরু। Department equality first part, সঙ্গে name equality দুটো। Name-only-তে leading interval নেই, তবে MySQL scan,প্রযোজ্য skip-scan বা অন্য index ভাবতে পারে।

Range-এর পরে key use বদলায়। (department_id, admitted_on, student_id)-এ department equality আর date range clear interval। পরের column filter,cover,order-এ কাজে লাগে, কিন্তু আরেক leading equality-র মতো interval সংকুচিত করে না-ও পারে।

DROP INDEX secondary structure সরায়, row নয়। Primary,unique,FK-support index-এর বাড়তি দায়। এক SELECT ব্যবহার করছে না বলেই key মুছো না।

Plan choice পড়ো, stopwatch নয়

InnoDB clustered primary-key structure-এ row রাখে। Secondary entry-তে row পেতে primary key-ও। তাই secondary tree পরে clustered fetch লাগতে পারে। Requested সব মান index-এ থাকলে extra fetch বাঁচে।

Covering index ওই query-র দরকারি মান রাখে। এটি query-index সম্পর্ক, universal property নয়। আরেক unindexed column select-এ সুবিধা যায়। Wide index-এ storage-maintenance বাড়ে।

EXPLAIN proposed plan। Traditional-এ type,possible_keys,key,key_len,ref,rows,filtered,Extra। Fixed primary-ID উদাহরণে const। পরের SELECT actual row, EXPLAIN planning তথ্য।

type-এ const,ref,range,index,ALL ইত্যাদি access। ALL table scan, index full index scan-ও হতে পারে। Label একা bad plan নয়। ছয়-product table scan secondary lookup-এর চেয়ে সস্তা হতে পারে।

possible_keys lookup candidate, key বাছা index। rows examined estimate, exact output count নয়। filtered condition-এর পরে শতাংশের estimate। Statistics-version-এ বদলায়।

Extra-তে Using where,index,filesort সূত্র। Using index সাধারণত covering। Filesort sort method, disk file লেখা proof নয়। Predicate,projection,order-এর সঙ্গে label মেলাও।

Expression আর display order

Indexed column ঘিরে function সাধারণ lookup আটকাতে পারে। YEAR(admitted_on) = 2026-এর বদলে 2026-01-01 থেকে 2027-01-01-এর আগের half-open range contiguous date interval। Functional index আলাদা option-rule।

Index scan থেকে sort ধরে নিও না, কাল অন্য path হতে পারে। Sequence চাইলে ORDER BY। Report-এর tie rule দাও, incidental primary suffix নয়।

Workload দেখে design, তারপর মাপো

জরুরি predicate-join থেকে শুরু। Equality,range,order,projection একসঙ্গে ভাবো। প্রতিটি column-এ আলাদা index নয়। Overlap খরচ বাড়িয়েও উপযোগী composite order মিস করতে পারে।

Representative data-তে before-after plan, read লাভ-write খরচ রাখো। EXPLAIN ANALYZE actual তথ্য দেয় কিন্তু query চালায়, তাই সচেতন ব্যবহার। Query-distribution বদলালে index আবার দেখো।
