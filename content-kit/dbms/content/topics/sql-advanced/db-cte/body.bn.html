রিপোর্টের প্রতিটি ধাপের নাম দাও

Shop balance রিপোর্ট-এ billed ও paid তুলনার আগে item মোট ও পেমেন্ট মোট চাই। সব nested expression-এ রাখলে পড়া কঠিন। CTE দিয়ে প্রতিটি মাঝের প্রশ্নের নাম দাও।

Common টেবিল expression বা CTE হলো WITH-এ নাম দেওয়া কোয়েরি ফল। Main কোয়েরি relation হিসেবে নেয়। Temporary মানে শুধু একটি SQL স্টেটমেন্ট-এর scope, পুরো কানেকশন নয়।

Nonrecursive CTE কাজের stage পড়তে সহজ করে। Recursive CTE mentor-এর team-এর মতো সম্পর্ক বারবার ধরে। WITH মিললেও যুক্তি আলাদা: recursion-এ শুরুর population, এগোনোর rule ও থামার পথ চাই।

University dataset-এ শিক্ষক আছে, mentoring hierarchy নেই। তাই local teacher_links relation existing শিক্ষক reference করে। নতুন সম্পর্ক স্পষ্টভাবে যোগ করা হয়েছে; বিভাগ membership-কে parent-child বলা হয়নি।

সাধারণ CTE ও recursive reference বোঝো

Nonrecursive WITH-এ নাম,AS,parenthesized SELECT, তারপর main SELECT। এক WITH-এ comma দিয়ে অনেক definition। পরে আগেরটি নেওয়া যায়; লেখার ক্রম নয়, stage বোঝানো নাম দাও।

Item_totals order_items, payment_totals payments স্বাধীনভাবে order_id-তে গ্রুপ করে। Final কোয়েরি orders-এ সারাংশ জয়েন করে। প্রতি সারাংশ-তে অর্ডার-প্রতি সর্বোচ্চ এক রো, তাই item-পেমেন্ট multiplication নেই। নাম দিলে cardinality দেখা সহজ।

WITH RECURSIVE-এর anchor নিজেকে না নিয়ে শুরুর রো দেয়। Recursive member CTE নিয়ে আগের round বাড়ায়। এখানে UNION ALL সব round মেলায়।

Anchor ও recursive কলামের সংখ্যা,অবস্থান,type মিলবে। নাম ও গুরুত্বপূর্ণ width nonrecursive অংশ থেকে। Growing path-এ anchor-কে যথেষ্ট wide CAST করো। শুরু ছোট স্ট্রিং মানে পরে সীমাহীন বাড়তে পারবে নয়।

MySQL recursive member-এ aggregate,window,GROUP BY,ORDER BY,DISTINCT এবং recursive reference placement সীমিত করে। Expansion-এ মন দাও; completed ফল বাইরে সর্ট,aggregate বা rank করো।

WITH RECURSIVE <walk_name> AS (
    <anchor_query>
    UNION ALL
    <recursive_query_with_stop_condition>
)
SELECT <columns> FROM <walk_name> ORDER BY <display_order>;

এক round করে hierarchy দেখো

শিক্ষক 11 Nusrat-এর mentor নেই। 12 Arif ও 14 Sajid 11-এর অধীনে, 13 Farhana 12-এর। mentor_id IS NULL root দেয়। Anchor depth zero, কারণ এখনও কোনো edge পার হয়নি।

প্রথম round-এ child teacher_links current parent-এ জয়েন। 12 ও 14 parent 11 পেয়ে depth one। পরের round-এ 13 parent 12 পেয়ে depth two। 14-এর child নেই, আর কিছু দেয় না।

13-এর নিচে পরের round খালি, তাই থামে। Final ফল anchor ও সব round রাখে। ORDER BY depth,teacher_id level-ভিত্তিক print করে, সার্ভার-এর internal traversal schedule বলে না।

এক named শিক্ষক থেকে শুরু ও সব root থেকে শুরু আলাদা প্রশ্ন। 12 থেকে 12,13; leaf 14 থেকে শুধু 14। Root-only anchor disconnected rootless cycle পায় না। Anchor রিপোর্ট-এর অর্থের অংশ।

Depth নির্বাচিত start থেকে edge গোনে। Anchor zero, প্রতি expansion এক যোগ। parent.depth < 10-এ child depth ten আসে, আর বাড়ে না। “Ten levels”-এ start-কে one ধরা হচ্ছে কি না বুঝে boundary দেখো।

Mentor foreign কী referenced শিক্ষক আছে মানায়, cycle আটকায় না। দুজন পরস্পর বা লম্বা chain আগের শিক্ষক-এ ফিরতে পারে। UNION ALL-এ guard না থাকলে রো তৈরি চলতে পারে।

Cyclic উদাহরণ comma-delimited visited path রাখে। Child যোগের আগে complete ID token খোঁজে। Delimiter না থাকলে 1-কে 11-এ পাওয়া যায়। একই path-এ repeated ID প্রত্যাখ্যান করে cycle আর বাড়তে দেয় না।

Depth limit path guard-এর সঙ্গে কাজ বাঁধে। Unexpected ডেটা বা encoding ভুলেও সীমা থাকে। এটি deliberate truncation, পুরো hierarchy দেখা প্রমাণ নয়। বৈধ path বেশি গভীর হলে রিপোর্ট আগে থামে; সীমা বলতে হবে।

Recursion-এর আগে সাধারণ stage বোঝো

প্রথম রিপোর্ট শিক্ষার্থী সারাংশ-র নাম দেয়। Shop-এ দুটি স্বাধীন aggregate নাম দিয়ে জয়েন। কোনোটির self-reference নেই, তাই recursion লাগে না।

Hierarchy-তে self-reference আসে। Cycle case-এ 11-এর mentor 13 দিয়ে child traversal-এ 11→12→13→11 হয়। Explicit 11 anchor root না থাকলেও শুরু দেয়।

Path traversal দেখায় ও visited check দেয়। ছোট উদাহরণে CAST 200 character রাখে। বড় ID বা depth-এ অন্য capacity/representation চাই। Intended path না ধরলে guard নির্ভরযোগ্য নয়।

Dedup পুরো recursive state দেখে

UNION DISTINCT complete রো deduplicate করে, entity নিজে চেনে না। Depth থাকলে (11,0),(11,3) আলাদা। Cycle নতুন depth দিতে পারে, তাই শুধু DISTINCT যথেষ্ট নয়।

State সত্যিই শুধু পরিচয় হলে পরিচয়-only recursion DISTINCT-এ revisit থামতে পারে। Path,cost,depth যোগে state ও dedup rule বদলায়। অপারেটর-এর আগে কোন state progress ঠিক করে বোঝাও। Accidental suppression-এর ওপর cycle policy রেখো না।

Scope আর physical execution আলাদা

পরের স্টেটমেন্ট-এ CTE নাম নেওয়া ভুল; semicolon scope শেষ করে। আবার একই stage চাইলে WITH লেখো বা মানালে ভিউতের মতো persistent object নাও। CTE কানেকশন-wide temporary টেবিল নয়।

CTE সবসময় derived টেবিলের চেয়ে দ্রুত নয়। Optimizer nonrecursive CTE merge বা materialize করতে পারে। Named stage readability বাড়ায়; physical স্টোরেজ/execution আলাদা সিদ্ধান্ত। পারফরম্যান্স-এ প্ল্যান দেখো।

Tree-এর বদলে graph-এ expansion দ্রুত বাড়ে। Cycle ছাড়াও বহু path-এ এক person বারবার আসতে পারে। সব path নাকি person একবার চাই ঠিক করো। Per-path guard cycle আটকায়, একই শিক্ষক-এর অনেক বৈধ route রাখে।

Traversal-এর চুক্তি আগে বলো

Anchor মুখের ভাষায় লেখো: সব root, নির্বাচিত mentor নাকি অন্য population। এক step কী ও depth কী গোনে বলো। আলাদা path-এ repeated person থাকবে কি না ঠিক করো। এগুলো SQL shape নির্ধারণ করে।

ছোট trace-এ শিক্ষক,mentor,depth ও দরকারে path রাখো। Root,interior,leaf,cycle পরীক্ষা করো। এক লম্বা acyclic chain-এর চেয়ে এগুলো anchor ও stopping ভুল বেশি দেখায়।

সার্ভার limit শেষ রক্ষাকবচ

MySQL 8.0 recursive CTE দেয়। cte_max_recursion_depth ডিফল্ট 1000 level; ছুঁলে এরর, অনুমোদিত partial hierarchy নয়। Cycle না সারিয়ে limit বাড়াবে না। Shared CHECK 8.0.16 চায়।

ধাপের নাম দাও, recursion-এর অগ্রগতি বোঝাও

Ordinary CTE স্টেটমেন্ট গুছায়; recursive CTE নির্দিষ্ট state বাড়ায় যতক্ষণ রো মেলে। Root,depth,path capacity ও cycle স্পষ্ট করো। এরপর stored procedure ও ফাংশন-এ parameter ও control flow-সহ reusable আচরণ রাখো।
