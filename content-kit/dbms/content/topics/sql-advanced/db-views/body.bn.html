Librarian বারবার member ID-name চায়, email নয়। একই projection না লিখে নাম দিয়ে table-এর মতো query করো। View interface দেয়, আসল member record নিজের table-এ থাকে।

View stored query definition। সাধারণ MySQL view আলাদা result snapshot রাখে না। Query করলে definition দিয়ে data আসে। Base-এ নাম বদলালে পরের view query-তেও দেখা যায়।

View report সহজ, public-sensitive column আলাদা, controlled update route-ও হতে পারে। Readable মানেই updatable নয়; view-এ column লুকালেই অন্য access revoke হয় না। আলাদা পরীক্ষা চাই।

একই রেকর্ড দেখার named window ভাবো। জানালায় কী দেখাবে বদলালে নতুন student copy হয় না। Visible column,population,operation আর security context বলো।

Interface স্পষ্ট define

CREATE VIEW নাম আর SELECT definition দেয়। Explicit column আর meaningful alias। student_directory-তে ID-name-department, email বাদ। Consumer সব student field নয়, intended shape জানে।

Controlled security interface-এর উদাহরণ ছাড়া SQL SECURITY INVOKER। Underlying access caller privilege-এ। DEFINER-এ view owner privilege-এ। কোনোটিই view-এ access-এর grant বাদ দেয় না।

Simple filtered view-এ WITH CHECK OPTION। View দিয়ে write করলে predicate-এর মধ্যে থাকতে হবে। CSE-only-তে department 1 থেকে 2 করলে বাইরে যায়, তাই reject।

CASCADED default, underlying view-এর প্রাসঙ্গিক condition-ও দেখে। LOCAL current condition দেখে, সঙ্গে underlying-এর নিজস্ব check option মানে। Stacked view-এ সব definition দেখো, এক filter সব write পথ রক্ষা ধরে নয়।

CREATE SQL SECURITY INVOKER VIEW <view_name> AS
SELECT <visible_columns> FROM <base_table>
WHERE <visible_population>
WITH CASCADED CHECK OPTION;

Live result আর update mapping আলাদা

Simple projection প্রতি visible row-কে এক base row-তে মেলায়। View-এ student_name update একই base column বদলায়। Primary key দেখালে target সহজ, কিন্তু শুধু key থাকলেই সব view writable নয়।

Aggregate-এ mapping ভাঙে। Enrollment total row তিন registration বোঝাতে পারে; count চার করলে কোন নতুন enrollment চাই জানা যায় না। তাই GROUP BY-aggregate view non-updatable; DISTINCTসহ অন্য restriction-ও আছে।

কিছু joined view MySQL rule-এ সীমিত update দেয়, সব join writable নয়। Permitted base-এ mapping ঠিক চাই। শুরুতে single-table maintenance interface review সহজ।

Updatable হলেই সবভাবে insertable নয়। Required base column default ছাড়া বাদ থাকলে row সম্পূর্ণ হয় না। Insert promise-এর আগে NOT NULL,default,generated column,constraint দেখো।

Stock zero-তে product 1 view থেকে যায়, rollback-এ ফেরে। REFRESH লাগে না; stored definition, আলাদা maintained result table নয়।

CHECK OPTION সব base change বাঁধে না। Authorized direct students update CSE থেকে সরাতে পারে। Workflow boundary চাইলে privilege-এ অনুপযুক্ত direct write সরাও।

Direct-table route বন্ধ

Name-only view-এর সঙ্গে students SELECT-ও দিলে email এখনও পড়ে। View convenience exposure কমালেও broad grant boundary ভাঙে। Table,view,database,active role মিলিয়ে effective permission দেখো।

Definer view caller-কে base grant ছাড়া approved data দিতে পারে। Owner-এ শুধু দরকারি privilege। সর্বক্ষম owner খারাপ definition বা unsafe change-এর ফল বাড়ায়। Owner সরালে interface ভাঙতে পারে, plan রাখো।

Query-কে history ভেবো না

View-এর ভেতর ORDER BY দিলেই সব consumer same order নয়। Outer query-optimizer বদলায়। Final SELECT-এ order দাও। View relation, printed layout নয়।

View old semester freeze করে না। Date filter বর্তমান qualifying row, আগের মান copy নয়। History চাইলে snapshot/history storage design। Current query old_results নাম দিলেই history নয়।

Definition interface contract

Public view-এ stable name আর explicit column, SELECT * নয়। Creation-এ star expand হয়, পরে table change-এ expectation অদ্ভুত হতে পারে। Explicit projection exposure-migration review সহজ।

Maintenance-এ IS_UPDATABLE metadata দেখো, actual intended operation test-ও। Insertability base-required আর constraint-এও নির্ভর। DROP VIEW definition সরায়, base row নয়; DELETE থেকে আলাদা।
