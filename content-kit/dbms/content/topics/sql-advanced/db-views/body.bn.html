দরকারি কোয়েরির স্থির নাম

Librarian বারবার member ID-নাম চায়, email নয়। একই projection না লিখে নাম দিয়ে টেবিলের মতো কোয়েরি করো। ভিউ interface দেয়, আসল member রেকর্ড নিজের টেবিলে থাকে।

ভিউ stored কোয়েরি definition। সাধারণ MySQL ভিউ আলাদা ফল snapshot রাখে না। কোয়েরি করলে definition দিয়ে ডেটা আসে। Base-এ নাম বদলালে পরের ভিউ কোয়েরি-তেও দেখা যায়।

ভিউ রিপোর্ট সহজ, public-sensitive কলাম আলাদা, controlled আপডেট route-ও হতে পারে। Readable মানেই updatable নয়; ভিউতে কলাম লুকালেই অন্য access revoke হয় না। আলাদা পরীক্ষা চাই।

একই রেকর্ড দেখার named window ভাবো। জানালায় কী দেখাবে বদলালে নতুন শিক্ষার্থী copy হয় না। Visible কলাম,population,operation আর security context বলো।

Interface স্পষ্ট define

CREATE VIEW নাম আর SELECT definition দেয়। Explicit কলাম আর meaningful alias। student_directory-তে ID-নাম-বিভাগ, email বাদ। Consumer সব শিক্ষার্থী ফিল্ড নয়, intended shape জানে।

Controlled security interface-এর উদাহরণ ছাড়া SQL SECURITY INVOKER। Underlying access caller privilege-এ। DEFINER-এ ভিউ owner privilege-এ। কোনোটিই ভিউতে access-এর grant বাদ দেয় না।

Simple filtered ভিউতে WITH CHECK OPTION। ভিউ দিয়ে write করলে predicate-এর মধ্যে থাকতে হবে। CSE-only-তে বিভাগ 1 থেকে 2 করলে বাইরে যায়, তাই reject।

CASCADED ডিফল্ট, underlying ভিউতের প্রাসঙ্গিক শর্ত-ও দেখে। LOCAL current শর্ত দেখে, সঙ্গে underlying-এর নিজস্ব check option মানে। Stacked ভিউতে সব definition দেখো, এক ফিল্টার সব write পথ রক্ষা ধরে নয়।

CREATE SQL SECURITY INVOKER VIEW <view_name> AS
SELECT <visible_columns> FROM <base_table>
WHERE <visible_population>
WITH CASCADED CHECK OPTION;

Live ফল আর আপডেট mapping আলাদা

Simple projection প্রতি visible রো-কে এক base রো-তে মেলায়। ভিউতে student_name আপডেট একই base কলাম বদলায়। Primary কী দেখালে target সহজ, কিন্তু শুধু কী থাকলেই সব ভিউ writable নয়।

Aggregate-এ mapping ভাঙে। Enrollment মোট রো তিন registration বোঝাতে পারে; সংখ্যা চার করলে কোন নতুন enrollment চাই জানা যায় না। তাই GROUP BY-aggregate ভিউ non-updatable; DISTINCTসহ অন্য restriction-ও আছে।

কিছু joined ভিউ MySQL rule-এ সীমিত আপডেট দেয়, সব জয়েন writable নয়। Permitted base-এ mapping ঠিক চাই। শুরুতে single-টেবিল maintenance interface review সহজ।

Updatable হলেই সবভাবে insertable নয়। Required base কলাম ডিফল্ট ছাড়া বাদ থাকলে রো সম্পূর্ণ হয় না। ইনসার্ট promise-এর আগে NOT NULL,ডিফল্ট,generated কলাম,কনস্ট্রেইন্ট দেখো।

Stock zero-তে পণ্য 1 ভিউ থেকে যায়, rollback-এ ফেরে। REFRESH লাগে না; stored definition, আলাদা maintained ফল টেবিল নয়।

CHECK OPTION সব base change বাঁধে না। Authorized direct students আপডেট CSE থেকে সরাতে পারে। Workflow boundary চাইলে privilege-এ অনুপযুক্ত direct write সরাও।

Direct-টেবিল route বন্ধ

নাম-only ভিউতের সঙ্গে students SELECT-ও দিলে email এখনও পড়ে। ভিউ convenience exposure কমালেও broad grant boundary ভাঙে। টেবিল,ভিউ,ডেটাবেস,active role মিলিয়ে effective পারমিশন দেখো।

Definer ভিউ caller-কে base grant ছাড়া approved ডেটা দিতে পারে। Owner-এ শুধু দরকারি privilege। সর্বক্ষম owner খারাপ definition বা unsafe change-এর ফল বাড়ায়। Owner সরালে interface ভাঙতে পারে, প্ল্যান রাখো।

কোয়েরি-কে history ভেবো না

ভিউতের ভেতর ORDER BY দিলেই সব consumer same অর্ডার নয়। Outer কোয়েরি-optimizer বদলায়। Final SELECT-এ অর্ডার দাও। ভিউ relation, printed layout নয়।

ভিউ old semester freeze করে না। তারিখ ফিল্টার বর্তমান qualifying রো, আগের মান copy নয়। History চাইলে snapshot/history স্টোরেজ design। Current কোয়েরি old_results নাম দিলেই history নয়।

Definition interface contract

Public ভিউতে stable নাম আর explicit কলাম, SELECT * নয়। Creation-এ star expand হয়, পরে টেবিল change-এ expectation অদ্ভুত হতে পারে। Explicit projection exposure-migration review সহজ।

Maintenance-এ IS_UPDATABLE metadata দেখো, actual intended operation test-ও। Insertability base-required আর কনস্ট্রেইন্ট-এও নির্ভর। DROP VIEW definition সরায়, base রো নয়; DELETE থেকে আলাদা।

MySQL security-আপডেট rule

8.0/8.4-তে ফিচার আছে, CHECK-এ 8.0.16+। Ordinary ভিউ native materialized নয়। Stored কোয়েরি,ট্রানজ্যাকশন visibility,write পারমিশন,definer ownership আলাদা, দেখতে টেবিল হলেও।

কোয়েরির নাম আর authority দেখো

ভালো ভিউতে projection,population,আপডেট policy স্পষ্ট। SQL SECURITY-র সঙ্গে boundary-মেলা grant। পরের ইনডেক্স logical ফল না বদলে access path দ্রুত করে।
