সম্পর্কিত change একসঙ্গে

Shop অর্ডার বানিয়ে item যোগ করে। অর্ডার থেকে item হারালে অসম্পূর্ণ। ট্রানজ্যাকশন compatible change এক unit করে,সম্পূর্ণ কাজ রাখবে নাকি failure-এ ফেরাবে বাছতে দেয়।

ট্রানজ্যাকশন commit-rollback boundary-র ডেটাবেস work। COMMIT স্থায়ী,ROLLBACK এখনও pending transactional change ফেরায়। কোন স্টেটমেন্ট-engine অংশ তা জানলেই কাজে লাগে।

Shared InnoDB transactional রো,lock,FK দেয়। একই SQL চলে বলেই nontransactional টেবিল rollback মেলে না। Engine কী ফেরাতে পারে ঠিক করে।

এখানে এক কানেকশন-এর control। Concurrency,isolation,deadlock পরে concurrency control-এ। Boundary unit রক্ষা করে,অন্য কানেকশন কী দেখবে সব মেটায় না।

শুরু,শেষ আর partial progress

START TRANSACTION,related DML,required outcome যাচাই,সফলে COMMIT failure-এ ROLLBACK। মানুষ screen পড়া বা unrelated ইনপুট দিতে থাকা পর্যন্ত lock রেখো না,short রাখো।

Savepoint active ট্রানজ্যাকশন-এর named marker। SAVEPOINT first_item,পরে ROLLBACK TO-তে তার পরের কাজ ফেরে,আগের pending। ট্রানজ্যাকশন শেষ নয়,শেষে full rollback বা commit চাই।

RELEASE শুধু marker সরায়,undo-commit নয়। Full boundary savepoint ফেলে। আরেক ট্রানজ্যাকশন শুরু nested independent করে না;এক unit-এ partial undo-তে savepoint।

Autocommit1 আর explicit ট্রানজ্যাকশন না থাকলে সফল standalone transactional স্টেটমেন্ট সাধারণত commit। START TRANSACTION session variable স্থায়ী না বদলিয়ে গ্রুপ করে,শেষে configured আচরণ ফেরে।

Failure explicit সামলাও

অর্ডার ইনসার্ট সফল,item CHECK fail হলে অনেক MySQL এরর শুধু failing স্টেটমেন্ট ফেরায়,আগের pending। Ignore করে commit-এ incomplete অর্ডার থাকে। এরর ধরে intended unit rollback।

InnoDB deadlock victim-এর মতো failure পুরো ট্রানজ্যাকশন ফেরাতে পারে। Whole operation retry আর external effect duplicate এড়ানো জানতে হবে। Message বা অন্য সার্ভিস charge DB rollback ফেরায় না।

DDL আর savepoint আলাদা boundary

CREATE/ALTER TABLE,CREATE INDEX implicit commit করতে পারে। Stock আপডেট-এর মাঝে দিলে later rollback-এও stock permanent। Atomic DDL internal crash-safe,নিজের DML rollback গ্রুপের অংশ নয়।

Savepoint independent commit নয়। ROLLBACK TO-এর আগের pending,পরে full rollback-এও যাবে। Marker-এর পরের সব lock ছেড়েছে ধরো না,engine detail আছে। ডেটা position,পুরো resource reset নয়।

ট্রানজ্যাকশন owner স্পষ্ট

এক layer boundary own করুক,document। Procedure unexpected commit caller-এর বড় unit ভাঙে। CALL নিজে atomic ধরে caller-ও ভুল করতে পারে। Routine-trigger workflow-তে review।

Schema migration business ট্রানজ্যাকশন-এর বাইরে। সম্ভব হলে lock-এর আগে validation,ভেতরে affected-রো,সব failure path। Pool-এ ফেরার আগে সেটিং restore,পরের user ভুল mode না পাক।
