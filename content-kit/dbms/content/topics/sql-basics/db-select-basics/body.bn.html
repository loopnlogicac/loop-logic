প্রশ্নের উত্তর দেয় এমন তথ্য পড়ো

Student office-এর CSE roll আর নাম দরকার, পুরো ডেটাবেস নয়। SELECT-এ কলাম বেছে, মেলা রো রেখে, দরকারি ক্রমে উত্তর দেখাও।

কোয়েরি ডেটাবেসকে তথ্যের অনুরোধ। ফল set-এ ফেরত রো আর কলাম। পড়লে stored value বদলায় না। Alias দেখানো heading বদলায়, টেবিল definition নয়।

নির্দিষ্ট প্রশ্ন দিয়ে শুরু। “Student দেখাও”-এ অনেক পছন্দ বলা নেই। “Department 1-এর ID আর নাম, ID-র ক্রমে” বললে source,কলাম,শর্ত,অর্ডার জানা যায়। পরিষ্কার প্রশ্নে SQL-ও পরিষ্কার।

SELECT-এর অংশ ধরে পড়ো

SELECT selected_columns
FROM source_table
WHERE row_condition
ORDER BY first_sort_key, tie_breaker
LIMIT row_count;

লেখায় SELECT আগে হলেও logical পড়া FROM-WHERE দিয়ে সুবিধা। Candidate রো নিয়ে যোগ্যগুলো রাখো, displayed মান হিসাব, তারপর সাজাও। সার্ভার আলাদা physical প্ল্যান নিলেও অর্থ রাখবে।

কলাম, রো আর দেখানোর ক্রম

কলাম আর alias

SELECT *-এ নির্ভর না করে দরকারি নাম লেখো। নতুন ফিল্ড এলেও রিপোর্ট বোঝা যায়, বাড়তি ডেটা-ও আসে না। Reader-এর সুবিধায় student_id-কে roll alias দিতে পারো।

Alias কোয়েরি ফল-এর, stored কলাম rename নয়। একই কোয়েরির WHERE সাধারণত SELECT alias পায় না, ফিল্টারিং logically আগে। ORDER BY ফল alias দিয়ে displayed expression সাজাতে পারে।

শর্ত আর তিন-মূল্যের logic

WHERE শুধু TRUE রাখে। তুলনায় FALSE বা UNKNOWN-ও হয়। NULL missing/unknown, তাই hometown-কে equals NULL দিলে TRUE হয় না। Marker আছে কি না-তে IS NULL।

IS NOT NULL known মান পায়। 'NULL' চার অক্ষরের known স্ট্রিং, marker নয়; empty স্ট্রিং-ও known। Unknown বোঝাতে zero বা বানানো town দিও না, অর্থ গুলিয়ে যায়।

AND-OR মেলাতে বন্ধনী উদ্দেশ্য দেখায়। AND আগে চলে। “Dhaka বা Cumilla-র CSE শিক্ষার্থী” চাইলে town বিকল্প ঘিরে বিভাগ rule-এর সঙ্গে মেলাও।

সর্ট আর limit

ORDER BY-তে DESC না দিলে ascending। টেক্সট collation মানে। Highest mark-এ descending, tie-তে student_id আর section_id দাও। Complete অর্ডার-এ repeated top-N একই ফল।

LIMIT অংশ রাখে। ORDER BY ছাড়া “প্রথম তিন” স্থির নয়। শুধু marks অর্ডার-এ boundary tie থাকলে ভিন্ন শিক্ষার্থী আসতে পারে। কী tie-breaker ঠিক করে কারা ওই জায়গা নেবে।

MySQL ascending-এ NULL known-এর আগে, descending-এ পরে। বিশেষ placement চাইলে স্পষ্ট লেখো। সর্টিং membership ঠিক করে না; WHERE-র যোগ্যতা আলাদা।

Distinct combination

DISTINCT সব selected expression-এর একই combination সরায়। Hometown একা নিলে দুই Dhaka এক; সঙ্গে student_id নিলে pair আলাদা, দুটো থাকে। পুরো আউটপুট রো ভাবো।

ইনপুট-এ repeated NULL থাকলে DISTINCT-এ এক displayed গ্রুপ। IS NOT NULL আগে সেগুলো বাদ দেয়। পরে COUNT(DISTINCT hometown) NULL argument বাদ দেয়, সম্পর্কিত হলেও আলাদা aggregate rule।

hometown নিজে NULL হলেও hometown = NULL UNKNOWN। WHERE কিছু রাখে না। Missing hometown-এর প্রশ্নে IS NULL।

অজানা duplicate ঢাকতে DISTINCT

Repeat কেন আগে বোঝো। জয়েন সঠিকভাবে ফল-পিছু রো দিলে শিক্ষার্থী কয়েকবার আসে। Membership প্রশ্নে DISTINCT ভালো, unrelated রেকর্ড জোড়া ভুল সারায় না।

স্টোরেজ অর্ডার-ই রিপোর্ট অর্ডার

এক পরীক্ষায় ID অর্ডার দেখালেও অন্য প্ল্যান বা maintenance-এ বদলাতে পারে। Predictable রিপোর্ট-এ ORDER BY। প্রশ্নের অর্থে সাজিয়ে বাকি tie মেটাও।

স্থির MySQL কোয়েরি ভিত্তি

SELECT,DISTINCT,alias,ORDER BY,LIMIT MySQL 8.0.16 আর 8.4-তে চলে। অন্য পণ্য-এ LIMIT আলাদা হতে পারে। টেক্সট তুলনা-সর্ট collation-এও নির্ভর।

দেখানোর আগে membership ঠিক করো

SELECT মান, WHERE যোগ্য রো, ORDER BY ক্রম বাছে। DISTINCT সমান combination সরায়, LIMIT নির্দিষ্ট অংশ। NULL স্পষ্ট ধরো। পরের অপারেটর আর built-in ফাংশন-এ কোয়েরি বাড়াও।
