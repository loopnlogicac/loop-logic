প্রশ্নের উত্তর দেয় এমন তথ্য পড়ো

Student office-এর CSE roll number ও নাম দরকার, পুরো ডেটাবেসের সব ফিল্ড নয়। SELECT-এ কলাম বাছতে, matching রো রাখতে ও কাজের ক্রমে ফল দেখাতে পারো।

কোয়েরি ডেটাবেসের কাছে তথ্য চায়। ফল set-এ ফেরত আসা রো-কলাম থাকে। পড়লে stored মান বদলায় না। Alias টেবিল definition না বদলে display heading বদলায়।

প্রশ্ন নির্দিষ্ট করো। “Student দেখাও”-এ অনেক কিছু অস্পষ্ট। “Department 1-এর identifier ও নাম identifier ক্রমে দাও”—এ source, আউটপুট, শর্ত ও অর্ডার পরিষ্কার। স্পষ্ট প্রশ্ন থেকে স্পষ্ট SQL হয়।

SELECT-এর অংশ ধরে পড়ো

SELECT selected_columns
FROM source_table
WHERE row_condition
ORDER BY first_sort_key, tie_breaker
LIMIT row_count;

লেখায় SELECT আগে, তবে logical পড়া FROM ও WHERE থেকে শুরু করলে সুবিধা। Candidate রো চেনো, শর্তমেলা রো রাখো, display মান হিসাব করে সাজাও। সার্ভার অন্য physical প্ল্যান নিয়েও অর্থ একই রাখে।

কলাম, রো আর দেখানোর ক্রম

কলাম আর alias

SELECT *-এর বদলে দরকারি কলাম লেখো। টেবিলে ফিল্ড বাড়লেও রিপোর্ট বোঝা যায়; অপ্রয়োজনীয় ডেটা আনা কমে। Reader-এর সুবিধা হলে student_id-তে roll alias দাও।

Alias কোয়েরি ফল-এর; stored কলামের নাম বদলায় না। রো ফিল্টার আগে হওয়ায় একই কোয়েরির WHERE-এ SELECT alias সাধারণত পাওয়া যায় না। ORDER BY ফল alias নিতে পারে।

শর্ত আর তিন-মূল্যের logic

WHERE শুধু TRUE রো রাখে। Comparison FALSE বা UNKNOWN-ও হতে পারে। NULL missing/unknown তথ্য, তাই hometown = NULL TRUE দেয় না। Missing marker খুঁজতে IS NULL নাও।

IS NOT NULL জানা মান খোঁজে। 'NULL' চার অক্ষরের জানা টেক্সট, missing marker নয়। Empty স্ট্রিং-ও জানা মান। Unknown বোঝাতে zero বা বানানো town দেবে না; অর্থ গুলিয়ে যায়।

AND ও OR মেশালে parentheses-এ গ্রুপিং দেখাও। AND-এর precedence বেশি। “Dhaka বা Cumilla-র CSE শিক্ষার্থী” চাইলে আগে town বিকল্প এক করে বিভাগ শর্তের সঙ্গে মেলাও।

সর্ট আর limit

ORDER BY ডিফল্ট ascending; DESC-এ উল্টো। টেক্সট সর্ট collation মানে। বেশি নম্বর আগে চাইলে marks DESC। Tie-তে student_id,section_id যোগ করো। Complete অর্ডার বারবার একই top-N দেয়।

LIMIT ফলের চাওয়া অংশ রাখে। ORDER BY ছাড়া “প্রথম তিন” স্থির নয়। শুধু marks-এ অর্ডার দিলেও boundary tie-তে অন্য শিক্ষার্থী আসতে পারে। কী tie-breaker ওই জায়গা নির্ধারণ করে।

MySQL-এ ascending-এ NULL আগে, descending-এ পরে। অন্য placement চাইলে স্পষ্ট expression দাও। অর্ডার ও membership আলাদা; সর্ট WHERE-এর শর্ত ঠিক করে না।

Distinct combination

DISTINCT নির্বাচিত সব expression-এর সমান combination সরায়। শুধু hometown নিলে দুই Dhaka এক হয়। student_id-সহ নিলে pair আলাদা বলে দুজনই থাকে। এক কলাম নয়, পুরো আউটপুট রো ভাবো।

DISTINCT-এ ইনপুটে থাকা একাধিক NULL এক displayed গ্রুপ হয়। IS NOT NULL আগে সরায়। পরে COUNT(DISTINCT hometown) NULL argument বাদ দেয়; সম্পর্কিত হলেও আলাদা aggregate rule।

পরিষ্কার heading-এ CSE শিক্ষার্থী

Department 1-এ চার শিক্ষার্থী। কোয়েরি শুধু identifier ও নাম নেয়; identifier heading roll।

সর্বোচ্চ তিন recorded mark

Descending marks ranking ঠিক করে। LIMIT প্রথম তিন নেওয়ার আগে শিক্ষার্থী ও সেকশন identifier tie মেটায়।

Hometown জানা নেই যাদের

শেষ কোয়েরি সরাসরি IS NULL নেয়। Imran ও Fahim-কে blank বা zero hometown বানানো ছাড়াই পায়।

ছোট সিনট্যাক্স-এ প্রশ্ন বদলায়

Equals দিয়ে NULL তুলনা

Hometown নিজে NULL হলেও hometown = NULL UNKNOWN। WHERE তাই এই তুলনায় কোনো রো রাখে না। Missing hometown চাইলে IS NULL করো।

অজানা duplicate ঢাকতে DISTINCT

Duplicate সরানোর আগে কেন এসেছে ভাবো। পরে জয়েন-এ ফল-প্রতি রো হলে শিক্ষার্থী একাধিকবার আসাই সঠিক। DISTINCT শিক্ষার্থী membership বলতে পারে; unrelated রেকর্ড মেলানো ভুল জয়েন সারায় না।

স্টোরেজ অর্ডার-ই রিপোর্ট অর্ডার

একবার টেবিল identifier ক্রমে দেখা যেতে পারে; অন্য প্ল্যান বা maintenance-এ বদলায়। Predictable রিপোর্ট-এ ORDER BY দাও। প্রশ্নের অর্থে সাজিয়ে বাকি tie মেটাও।

স্থির MySQL কোয়েরি ভিত্তি

এখানকার SELECT, DISTINCT, alias, ORDER BY, LIMIT MySQL 8.0.16 ও 8.4-এ চলে। অন্য পণ্য-এ LIMIT সিনট্যাক্স বদলায়। টেক্সট comparison ও সর্টিং collation-এর ওপরও নির্ভর করে।

দেখানোর আগে membership ঠিক করো

SELECT মান, WHERE যোগ্য রো, ORDER BY ক্রম বাছে। DISTINCT সমান আউটপুট combination সরায়; LIMIT নির্ধারিত অংশ নেয়। NULL স্পষ্টভাবে সামলাও। এরপর অপারেটর ও built-in ফাংশন যোগ করো।
