প্রশ্নের উত্তর দেয় এমন তথ্য পড়ো

Student office-এর CSE roll আর নাম দরকার, পুরো ডেটাবেস নয়। SELECT-এ column বেছে, মেলা row রেখে, দরকারি ক্রমে উত্তর দেখাও।

Query ডেটাবেসকে তথ্যের অনুরোধ। Result set-এ ফেরত row আর column। পড়লে stored value বদলায় না। Alias দেখানো heading বদলায়, table definition নয়।

নির্দিষ্ট প্রশ্ন দিয়ে শুরু। “Student দেখাও”-এ অনেক পছন্দ বলা নেই। “Department 1-এর ID আর নাম, ID-র ক্রমে” বললে source,column,condition,order জানা যায়। পরিষ্কার প্রশ্নে SQL-ও পরিষ্কার।

SELECT-এর অংশ ধরে পড়ো

SELECT selected_columns
FROM source_table
WHERE row_condition
ORDER BY first_sort_key, tie_breaker
LIMIT row_count;

FROMকোন table row দেবে?

লেখায় SELECT আগে হলেও logical পড়া FROM-WHERE দিয়ে সুবিধা। Candidate row নিয়ে যোগ্যগুলো রাখো, displayed মান হিসাব, তারপর সাজাও। Server আলাদা physical plan নিলেও অর্থ রাখবে।

Column, row আর দেখানোর ক্রম

Column আর alias

SELECT *-এ নির্ভর না করে দরকারি নাম লেখো। নতুন field এলেও report বোঝা যায়, বাড়তি data-ও আসে না। Reader-এর সুবিধায় student_id-কে roll alias দিতে পারো।

Alias query result-এর, stored column rename নয়। একই query-র WHERE সাধারণত SELECT alias পায় না, filtering logically আগে। ORDER BY result alias দিয়ে displayed expression সাজাতে পারে।

Condition আর তিন-মূল্যের logic

WHERE শুধু TRUE রাখে। তুলনায় FALSE বা UNKNOWN-ও হয়। NULL missing/unknown, তাই hometown-কে equals NULL দিলে TRUE হয় না। Marker আছে কি না-তে IS NULL।

IS NOT NULL known মান পায়। 'NULL' চার অক্ষরের known string, marker নয়; empty string-ও known। Unknown বোঝাতে zero বা বানানো town দিও না, অর্থ গুলিয়ে যায়।

AND-OR মেলাতে বন্ধনী উদ্দেশ্য দেখায়। AND আগে চলে। “Dhaka বা Cumilla-র CSE student” চাইলে town বিকল্প ঘিরে department rule-এর সঙ্গে মেলাও।

Sort আর limit

ORDER BY-তে DESC না দিলে ascending। Text collation মানে। Highest mark-এ descending, tie-তে student_id আর section_id দাও। Complete order-এ repeated top-N একই ফল।

LIMIT অংশ রাখে। ORDER BY ছাড়া “প্রথম তিন” স্থির নয়। শুধু marks order-এ boundary tie থাকলে ভিন্ন student আসতে পারে। Key tie-breaker ঠিক করে কারা ওই জায়গা নেবে।

MySQL ascending-এ NULL known-এর আগে, descending-এ পরে। বিশেষ placement চাইলে স্পষ্ট লেখো। Sorting membership ঠিক করে না; WHERE-র যোগ্যতা আলাদা।

Distinct combination

DISTINCT সব selected expression-এর একই combination সরায়। Hometown একা নিলে দুই Dhaka এক; সঙ্গে student_id নিলে pair আলাদা, দুটো থাকে। পুরো output row ভাবো।

Input-এ repeated NULL থাকলে DISTINCT-এ এক displayed group। IS NOT NULL আগে সেগুলো বাদ দেয়। পরে COUNT(DISTINCT hometown) NULL argument বাদ দেয়, সম্পর্কিত হলেও আলাদা aggregate rule।

Result-এর গঠন আগে ভাবো

পরিষ্কার heading-এ CSE student

Department 1-এ চারজন। শুধু ID-নাম, ID heading roll।

সর্বোচ্চ তিন recorded mark

Descending mark ranking দেয়। Student-section ID tie মেটানোর পরে LIMIT প্রথম তিন নেয়।

Repeat ছাড়া known town

Unknown আর duplicate Dhaka বাদ। কোন town আছে বলে, প্রতি town-এ কত student নয়।

Hometown জানা নেই যাদের

শেষ query সরাসরি IS NULL। Imran-Fahim পায়, blank বা zero town কল্পনা করে না।

ছোট syntax-এ প্রশ্ন বদলায়

Equals দিয়ে NULL তুলনা

hometown নিজে NULL হলেও hometown = NULL UNKNOWN। WHERE কিছু রাখে না। Missing hometown-এর প্রশ্নে IS NULL।

অজানা duplicate ঢাকতে DISTINCT

Repeat কেন আগে বোঝো। Join সঠিকভাবে result-পিছু row দিলে student কয়েকবার আসে। Membership প্রশ্নে DISTINCT ভালো, unrelated record জোড়া ভুল সারায় না।

Storage order-ই report order

এক পরীক্ষায় ID order দেখালেও অন্য plan বা maintenance-এ বদলাতে পারে। Predictable report-এ ORDER BY। প্রশ্নের অর্থে সাজিয়ে বাকি tie মেটাও।

স্থির MySQL query ভিত্তি

SELECT,DISTINCT,alias,ORDER BY,LIMIT MySQL 8.0.16 আর 8.4-তে চলে। অন্য product-এ LIMIT আলাদা হতে পারে। Text তুলনা-sort collation-এও নির্ভর।

দেখানোর আগে membership ঠিক করো

SELECT মান, WHERE যোগ্য row, ORDER BY ক্রম বাছে। DISTINCT সমান combination সরায়, LIMIT নির্দিষ্ট অংশ। NULL স্পষ্ট ধরো। পরের operator আর built-in function-এ query বাড়াও।
