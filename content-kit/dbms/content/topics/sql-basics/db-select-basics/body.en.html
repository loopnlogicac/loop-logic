Read the facts that answer your question

A student office needs CSE roll numbers and names, not every field in the university database. SELECT lets you choose the columns, keep matching rows and present the answer in a useful order.

A query asks the database for information. A result set contains the rows and columns returned by that request. Reading rows does not change their stored values. An alias can change a displayed heading without altering the table definition.

Start with a precise question. “Show students” leaves many choices unstated. “Return identifiers and names for department 1, ordered by identifier” tells you the source, output columns, condition and order. Clear questions lead to clearer SQL.

Read a SELECT statement in parts

SELECT selected_columns
FROM source_table
WHERE row_condition
ORDER BY first_sort_key, tie_breaker
LIMIT row_count;
The parts answer different questions
ClauseQuestion
SELECTWhich values should appear?
FROMWhich table supplies the rows?
WHEREWhich source rows qualify?
ORDER BYHow should the answer be arranged?
LIMITHow much of the ordered answer is needed?

SELECT appears first in writing, but a useful logical reading starts with FROM and WHERE. Identify candidate rows, keep the qualifying ones, compute displayed values and arrange the result. The server may use a different physical plan while preserving the requested meaning.

Choose columns, rows and presentation

Columns and aliases

Name the columns you need rather than relying on SELECT *. Explicit columns keep reports understandable when a table gains new fields. They can also avoid retrieving unnecessary data. Use an alias such as roll for student_id when that heading helps the reader.

An alias belongs to the query result. It does not rename a stored column. A SELECT alias is generally not available in the same query’s WHERE because row filtering logically happens earlier. ORDER BY can use a result alias to arrange the displayed expression.

Conditions and three-valued logic

WHERE keeps rows only when the condition is TRUE. Ordinary comparisons can yield FALSE or UNKNOWN as well. NULL represents missing or unknown information, so comparing a hometown to NULL with equals does not produce TRUE. Use IS NULL to ask whether the marker is present.

IS NOT NULL finds known values. The text 'NULL' is a known four-letter string, not the missing-value marker. An empty string is another known value. Avoid using zero or invented town names to stand for unknown information; those replacements blur the meaning of the data.

When combining AND and OR, parentheses make the intended grouping visible. AND has higher precedence than OR. If your question means “CSE students from either Dhaka or Cumilla,” group the town alternatives before combining them with the department rule.

Ordering and limiting

ORDER BY is ascending unless you specify DESC. Text sorting follows the chosen collation. For highest marks, sort marks descending. When several results tie, add student_id and section_id to settle their order. A complete ordering makes repeated top-N queries reproducible.

LIMIT keeps a requested portion of the result. Without ORDER BY, the phrase “first three” has no stable meaning. Even with ORDER BY marks alone, a tie at the boundary can select different students. A key-based tie breaker defines which rows occupy those places.

MySQL sorts NULL before known values in ascending order and after known values in descending order. If missing values need a special placement, express it deliberately. Presentation order is separate from membership: sorting a result does not decide which rows satisfy WHERE.

Distinct combinations

DISTINCT removes duplicate combinations of all selected expressions. Selecting distinct hometowns collapses the two Dhaka values to one. Selecting student_id with hometown keeps both students because the pairs differ. Think about the entire output row rather than one column in isolation.

For DISTINCT, repeated NULL values form one displayed duplicate group if they remain in the input. Filtering with IS NOT NULL removes them before distinct towns are displayed. Later, COUNT(DISTINCT hometown) ignores NULL arguments, which is a related but different aggregate rule.

Small syntax changes can change the question

Comparing a value with NULL using equals

The result of hometown = NULL is UNKNOWN, even when hometown itself is NULL. WHERE therefore keeps no rows for that comparison. Replace it with IS NULL when the question concerns missing hometowns.

Using DISTINCT to hide an unexplained duplicate

Before removing repeated rows, ask why they exist. A later join may correctly produce one row per result, so a student appears several times. DISTINCT can answer a student-membership question, but it cannot repair a join that connects unrelated records.

Assuming storage order is report order

A table may appear in identifier order during one experiment. Another plan or maintenance operation can change that appearance. State ORDER BY for every report that needs predictable rows. Order by the question’s meaning and then settle remaining ties.

A stable MySQL query foundation

The SELECT, DISTINCT, alias, ORDER BY and LIMIT forms here work on the MySQL 8.0.16 baseline and MySQL 8.4. LIMIT syntax differs in some other database products. Text comparison and sorting also depend on collation settings.
