জমা তথ্য না বদলে আরও প্রশ্ন করো

লাইব্রেরির due তারিখ পেরিয়ে এখনও ফেরত না-আসা বই চাই। Student office-এর অজানা hometown-এর পাঠযোগ্য লেবেল চাই। অপারেটর ও ফাংশন দিয়ে stored রেকর্ড না বদলেই দুটো অনুরোধ বলা যায়।

অপারেটর মান মেলায় বা তুলনা করে, যেমন যোগ বা equality। ফাংশন argument থেকে মান বের করে, যেমন দুই তারিখের দিনের ফারাক। SELECT expression-এ মূল কলাম না বদলেই লেবেল ও মাপ হিসাব হয়।

ফিল্টারিং ও presentation আলাদা করো। শর্ত বলে রো ফলের অংশ হবে কি না। Display expression বলে নির্বাচিত রো-তে কী দেখাবে। রিপোর্ট-এ NULL-এর বদলে Unknown লিখলে hometown জানা হয়ে যায় না।

প্রচলিত expression চেনো

value BETWEEN lower_bound AND upper_bound
value IN (choice_a, choice_b)
text_value LIKE 'prefix%'
COALESCE(first_choice, fallback)
CASE
    WHEN condition_a THEN label_a
    WHEN condition_b THEN label_b
    ELSE other_label
END

Expression SELECT ও উপযুক্ত শর্তে থাকে। CASE মান ফেরায়, আলাদা রো-change কমান্ড নয়। টেক্সট literal quote-এ রাখো। বিশেষ করে AND-OR মেশালে parentheses দিয়ে compound শর্ত পড়া সহজ করো।

রেঞ্জ, pattern, স্ট্রিং ও তারিখ বোঝো

সীমা আর তালিকার বিকল্প

BETWEEN দুই প্রান্তই রাখে: 75 থেকে 80-তে 75 ও 80 দুটোই চলে। প্রান্ত উল্টো দিলে MySQL নিজে বদলে নেয় না। Type ঠিক নাও, যেন numeric/তারিখ তুলনা অনিচ্ছাকৃত টেক্সট অর্ডার না হয়।

IN list membership দেখে। Department (1,3)-এ মানে যেকোনো একটি, মাঝের সব মান নয়। NULL-সহ list-এ বিশেষ করে NOT IN সাবধানে নাও; unknown comparison শর্ত TRUE হতে বাধা দেয়। Absence কোয়েরি-তে পরিষ্কার NULL নীতি চাই।

টেক্সট pattern মেলাও

LIKE-এ percent শূন্য বা বেশি অক্ষর, underscore ঠিক একটি। Active collation-এ A% শুরুতে A মেলায়; _a%-এ দ্বিতীয় অক্ষর a। কোনো wildcard নিজে digit বা গোটা word বোঝায় না।

Literal percent বা underscore মেলাতে escaping বা অন্য নির্দিষ্ট matching পদ্ধতি চাই। Backslash SQL mode-নির্ভর; অন্য ভাষায় স্ট্রিং দেখে আন্দাজ করবে না। Case ও accent collation ঠিক করে; LIKE নিজে বাধ্যতামূলক case-sensitive নয়।

রিপোর্ট-এর টেক্সট বদলে দেখাও

UPPER ও LOWER display-র letter case বদলায়। CONCAT roll লেবেল-এর মতো টেক্সট জোড়ে। CHAR_LENGTH character, LENGTH byte গোনে। English-এ প্রায়ই সমান হলেও utf8mb4 Bangla-তে আলাদা হতে পারে।

Unicode character সংখ্যা সবসময় চোখে দেখা grapheme cluster-এর সংখ্যা নয়। Combining mark আলাদা character হিসেবে গোনা হতে পারে। SQL character সংখ্যা-এ CHAR_LENGTH নাও; হাতের লেখা অক্ষর বা display width নিখুঁত গোনে বলবে না।

CONCAT-এর কোনো argument NULL হলে ফল NULL। পড়ার মতো fallback চাইলে ভেবে replacement দাও। TRIM পাশের space সরাতে, SUBSTRING অংশ নিতে পারে। সবার নামে একই সংখ্যক word ধরে নয়, আসল requirement অনুযায়ী যাচাই করো।

Fixed রিপোর্ট তারিখ-এ হিসাব

DATEDIFF(first_date, second_date) দিনের ফারাক দেয়। Argument উল্টো করলে sign বদলায়। DATE_ADD interval যোগ করে; YEAR, MONTH calendar অংশ নেয়। Local format আন্দাজ না করে DATE ও স্পষ্ট year-month-day literal নাও।

Overdue রিপোর্ট-এ নির্দিষ্ট reporting তারিখ ও open-loan শর্ত চাই। returned_on IS NULL outstanding loan রাখে। due_on reporting তারিখ-এর আগে হলে overdue। আজ due হলে zero days late; এই সংজ্ঞায় strictly overdue নয়।

Missing মান আর category

IFNULL দুই argument নেয়; প্রথমটি NULL হলে দ্বিতীয়টি দেয়। COALESCE একাধিক বিকল্পের প্রথম non-NULL নেয়। Zero ও empty স্ট্রিং জানা মান, তাই নিজেরা পরের fallback চালু করে না।

Searched CASE ক্রমে শর্ত দেখে প্রথম TRUE branch দেয়। Excellent ও Pass দিতে আগে অন্তত 80, তারপর অন্তত 40 দেখো; উল্টোতে বেশি নম্বরও আগে Pass হয়। বাকি অবস্থার জন্য ELSE দাও।

Prefix বা দুই hometown-এর একটি

প্রথম কোয়েরি LIKE ও IN-কে OR-এ মেলায়। নাম বা town যেকোনো শর্তে রো আসতে পারে।

সীমায় আর ভেতরের marks

রেঞ্জ-এ 75,78,80 আছে। Grading rule তুলনায় আনার সময় দুই প্রান্তই গুরুত্বপূর্ণ।

নাম, character সংখ্যা আর roll লেবেল

স্ট্রিং ফাংশন নতুন display কলাম হিসাব করে। মূল শিক্ষার্থী নাম ও identifier আগের মতোই stored থাকে।

1 March-এ overdue open loan

নির্দিষ্ট দিনে loan 402 দশ দিন overdue। পুরোনো due তারিখ পেরোলেও ফেরত দেওয়া loan বাদ।

Fallback আর grade band

দুটি ফল set missing-town লেবেল ও CASE-এর ক্রম দেখায়। লেবেল রিপোর্ট-এর পছন্দ, stored fact-এর বদলি নয়।

সীমা ও missing value দেখো

BETWEEN-কে exclusive ভাবা

Strictly above 75 ও below 80 চাইলে BETWEEN বেশি রাখে, কারণ প্রান্ত নেয়। Strict comparison দাও। অপারেটর বাছার আগে প্রশ্নের সীমার শব্দ পড়ো।

Unknown-কে আসল category করা

COALESCE রিপোর্ট পড়তে সাহায্য করে, কিন্তু একই stored লেবেল-এর সঙ্গে fallback গ্রুপ করলে ভিন্ন অর্থ মিশতে পারে। দরকার হলে missingness দৃশ্যমান রাখো। সুন্দর display দিয়ে ডেটা quality ঢেকো না।

ঐতিহাসিক প্রশ্নে আজকের clock

1 March-এর রিপোর্ট পরে চালালেও 1 March নেবে। Current তারিখ বদলালে অন্য প্রশ্ন হয়। As-of তারিখ বলো; due-today, overdue ও returned আলাদা রাখো।

ফাংশন ও সেটিং দুটোই জরুরি

এগুলো MySQL 8.0.16 বা নতুনে চলে। utf8mb4 Bangla রাখে; collation matching-সর্ট ঠিক করে। SQL mode escaping বদলাতে পারে, তাই literal wildcard escape নেওয়ার আগে সেটিং দেখো।

অর্থ থেকে expression বাছো

রেঞ্জ-pattern রো ছাঁকে, ফাংশন মান বের করে, CASE category দেয়। NULL, Unicode সংখ্যা ও reporting তারিখ সাবধানে নাও। এরপর aggregate ফাংশন ও GROUP BY-এ রো মিলিয়ে সারাংশ করো।
