Invalid record রাখা কঠিন করো

100-এর scale-এ 101 নীরবে নয়। Result nonexistent enrollment-এর নয়। Table definition row বদলালে MySQL-কে promise check করতে দেয়।

CREATE TABLE column,type,constraint বলে। Constraint stored data-তে enforced rule। Requirement বোঝার বদলি নয়, তবে accidental invalid state অনেক ঠেকায়।

কোন তথ্য রাখবে তার স্পষ্ট নাম। Attendance row এক student এক date, identity-reference-presence লাগে। এই policy-তে একই student-day দুই record চলবে না।

সংজ্ঞা promise হিসেবে পড়ো

CREATE TABLE table_name (
    id INT AUTO_INCREMENT PRIMARY KEY,
    required_value INT NOT NULL,
    status_code INT NOT NULL DEFAULT 1,
    UNIQUE (required_value),
    CHECK (status_code IN (0, 1))
);

প্রতি line design-এর অংশ। ID বাদ দিলে generated, required value NULL নয়, omitted status default। UNIQUE known value repeat ঠেকায়, CHECK row condition। Pattern থেকে actual fact-এর নাম-reference বাছো।

Constraint সম্পর্কিত, বিনিময়যোগ্য নয়
Ruleকী নিশ্চিতকী নিশ্চিত নয়
NOT NULLমান চাইText nonblank বা সত্যি
UNIQUEKnown key repeat নয়Nullable-এ NULL নেই

অর্থপূর্ণ domain-এ rule মেলাও

Required আর valid value

NOT NULL unknown mark ঠেকায়। 0..100 CHECK invalid known ঠেকায়। Real mark চাইলে দুটোই। CHECK TRUE বা UNKNOWN নেয়, FALSE বাদ; range একা NULL বাদ নয়।

NOT NULL name empty string হতে পারে। Blank নিষিদ্ধ হলে rule আর input validation। Whitespace-only অর্থপূর্ণ কি না-সহ policy মানো। Type একা সব business rule নয়।

Key,reference,default

Primary key এক/কয়েক column। student_id-attended_on unique pair একদিন এক attendance, component আলাদা repeat পারে। FK existing Students row নিশ্চিত।

Column বাদ বা explicit DEFAULT-এ default। Supplied value check-এর বদলি নয়। উপস্থিত ধরে entry হলে default 1 ভালো, অন্য workflow explicit চাইতে পারে।

AUTO_INCREMENT omitted ID দেয়, gapless নয়। Failure,delete,rollback gap রাখতে পারে। Highest ID row count বা legal receipt count নয়।

Structure বুঝে বদলাও

ALTER column/constraint যোগের মতো change। NOT NULL/UNIQUE-এর আগে old row দেখো; NULL বা duplicate ভাঙতে পারে। বানানো placeholder নয়, verified তথ্য দিয়ে ঠিক করো।

DROP definition-row সরায়। TRUNCATE definition রেখে empty, সাধারণত AUTO_INCREMENT reset। DELETE DML, WHERE থাকতে পারে। Transaction-reference আচরণ আলাদা।

অনেক structural command implicit commit। TRUNCATE-এর পরে ROLLBACK table ফেরায় না। Referenced table truncate-এ InnoDB restriction-ও। Destructive explore-এ private scratch table।

Definition তৈরি, alter, test

Constrained attendance

Generated ID,student FK,unique day,default,range একসঙ্গে। Insert-এ MySQL কোন মান দেয় দেখো।

ALTER-এ capacity

Study-group table capacity পায়। Inserted group নতুন default ten seat নেয়।

Empty, তারপর definition সরাও

Private label table-এ TRUNCATE-DROP আলাদা। Metadata count-এ DROP-এর পরে নেই।

Range-এর বাইরে mark reject

ইচ্ছা করে 101 update। CHECK violation reject করে আগের valid result রাখে।

দেখতে বেশি শক্ত constraint

UNIQUE মানেই required

Nullable unique-এ MySQL বহু NULL নেয়। Optional email-এ ভালো, required candidate ID নয়। Known unique চাইলে NOT NULL।

অসংগত নাম

Lowercase table, descriptive student_id/enrolled_on। কারণ ছাড়া একই অর্থে StudentID,sid,student_number বদল নয়। OS-এ table-name case আলাদা হতে পারে, lowercase consistency ভালো।

Rejection না বুঝে rule off

FK error ভুল parent বা operation order জানায়। আগে row-সম্পর্ক দেখো। Check off-এ orphan থাকে। Rejection data-design তদন্তের evidence।

CHECK enforcement-এর version

MySQL 8.0.16 থেকে CHECK enforced। আগে কিছু syntax নিলেও condition মানাত না। এখানে 8.0.16+ আর FK-transactional row change-এ InnoDB।

পুরো rule বলো

Type,required,key,default,check আলাদা সমস্যা মেটায়। বুঝে মেলাও, row আর structural change আলাদা। পরের INSERT, UPDATE আর DELETE-এ এগুলো ব্যবহার।
