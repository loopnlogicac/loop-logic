অনেক row থেকে দরকারি summary

Office জানতে চায় department-পিছু কত student। সব student list করলে অন্য প্রশ্নের উত্তর। Aggregate row মিলে count,total আর অন্য summary করে।

Aggregate function কয়েক input row থেকে মান হিসাব করে। COUNT গোনে, SUM যোগ, AVG গড়, MIN-MAX সবচেয়ে ছোট-বড় known মান। GROUP BY ভাগ করে, প্রতিটি group নিজের summary পায়।

আগে বলো এক output row কী বোঝায়: পুরো university,department নাকি section? কোন record হিসাবেও আসে বলো। Passing result-এর average আর সব completed result-এর average আলাদা।

Row,group আর result order আলাদা

SELECT grouping_column, COUNT(*) AS row_count
FROM source_table
WHERE row_condition
GROUP BY grouping_column
HAVING COUNT(*) >= required_count
ORDER BY grouping_column;

WHERE grouping-এর আগে পৃথক row দেখে। GROUP BY expression-এ group, aggregate summary। HAVING সম্পূর্ণ group দেখে, ORDER BY বাকি group সাজায়। Server physical পদ্ধতি আলাদা নিলেও logical ফল রাখে।

মূল aggregate-এর অর্থ
Expressionঅর্থEmpty ungrouped input
COUNT(*)Row count0
COUNT(column)Non-NULL argument count0
SUM(column)Non-NULL totalNULL
AVG(column)Non-NULL গড়NULL
MIN or MAXসবচেয়ে ছোট-বড় non-NULLNULL

সঠিক জিনিস গুনো

Row আর known মান এক নয়

Students-এ আট row, COUNT(*) আট। দুই hometown unknown, COUNT(hometown) ছয়। এতে repeated Dhaka আলাদা গোনা, COUNT(DISTINCT hometown) পাঁচ ভিন্ন known town।

বেশিরভাগ aggregate NULL argument বাদ দেয়। Unknown mark নিজে zero করবে না। Zero real মান, numerator-denominator বদলায়। Average দেখাতে missing-result policy স্পষ্ট।

Empty input-এ ungrouped aggregate তবুও এক summary row: COUNT zero, SUM-AVG NULL। Grouped empty input-এ group নেই, সাধারণত row-ও নেই। তাই payment-only grouped report-এ unpaid order হারাতে পারে।

সংজ্ঞায়িত অর্থে group

Students department_id-তে group করলে তিন group, size চার,দুই,দুই। প্রতি row Students-এ represented department। নতুন department-এ student না থাকলে group বানানোর row নেই, আসে না।

Empty department-ও চাইলে Departments থেকে Students-এ outer join। তখন non-NULL student ID গুনবে, COUNT(*) preserved parent row-ও গুনত। Join পাঠে দেখবে। পার্থক্য joined row-এর অর্থ থেকে।

কয়েক column-এ পুরো combination group। Department-hometown একসঙ্গে, শুধু department থেকে আলাদা। SQL grouping-এ দুই NULL hometown এক group, যদিও সাধারণ NULL equality TRUE নয়।

WHERE আর HAVING আলাদা ধাপ

অন্তত দুই passing result-এর section চাই। আগে WHERE marks অন্তত 40, তারপর section_id group, শেষে HAVING count অন্তত দুই। Average শুধু pass-এর।

সব result group করে average অন্তত 40 চাইলে failure-ও গড়ে আসে। Condition এদিক-ওদিক নিলে প্রশ্ন বদলায়। Failure বাদ দিলে mean_pass নাম দাও, unrestricted mean নয়।

ONLY_FULL_GROUP_BY মানো

সাধারণত mode চালু। Grouped SELECT-এ arbitrary nonaggregate নেবে না। Department group-এ বহু student_name, পুরো group বোঝায় এমন একটিমাত্র নাম নেই।

Grouping key আর aggregate দাও, বা selected fact অর্থপূর্ণ হয় এমন grouping। MySQL grouped primary key থেকে determined column-এর মতো কিছু functional dependency-ও বোঝে। বহু student-এর department থেকে যেকোনো নাম নেওয়ার যুক্তি নয়।

Mode বন্ধে misleading query চললেও কোন নাম উত্তর জানা যায় না। এক row-এর অর্থ পরিষ্কার করাই সমাধান। প্রশ্ন নির্দিষ্ট representative না চাইলে সুবিধার জন্য MIN(name) নেবে না।

Credit আলাদা হলে weight

Grade point documented 4.00 scale-এ এক course result। CGPA completed result-কে credit weight-এ মেলায়। Point গুণ credit যোগ করে একই completed credit-এর মোট দিয়ে ভাগ।

SQL result থেকে Section হয়ে Course-এ join করে credit পায়। Join related table-এর matching row মেলায়; পরের module বিস্তারিত। Section offering চেনায়, Course credit দেয়। Grouping recorded-result থাকা student-পিছু weighted মান করে।

Pending বাদ, repeated-course replacement ধরা হয়নি। University retake বা grade replacement rule আলাদা দিতে পারে। Official CGPA বলার আগে policy বলো। অদরকারি intermediate rounding নয়, final display round।

Payment total না থাকলে zero দেখাও

Order 203-এ payment নেই। Raw NULL sum আর সচেতন 0.00 fallback দুটোই দেখায়।

দেখতে ঠিক সংখ্যাও ভুল প্রশ্ন

আগের average আবার average

দুই section-এ result count আলাদা। Mean-এর average section-এ equal weight, প্রতিটি result-এ নয়। Overall student-result mean চাইলে underlying row থেকে বা contributing count-সহ মেলাও।

Join multiplicity না দেখে SUM

Order-এ বহু item আর payment। দুটো সরাসরি join করলে প্রতি item-এ payment repeat, SUM receipts বাড়ায়। এক row কী মানে দেখো, আগে প্রত্যেক সম্পর্ক intended level-এ summary করে মেলাও।

GROUP BY sort-ও করে ভাবা

Grouping বলে কারা summary ভাগ করে, ক্রম নয়। Department-section display-তে ORDER BY। Accidental implementation-এ report নয়।

Grouping mode চালু রাখো

MySQL 8.0.16 আর 8.4-তে aggregate চলে, ONLY_FULL_GROUP_BY সাধারণত চালু। Dependency recognition কিছু expression নিতে পারে, তবু selected প্রতিটি মান group-এর জন্য স্পষ্ট অর্থ চাই।

Summary-র পেছনের population বলো

Input row-ই summary, তাই count,NULL,filter,weight অর্থ ঠিক করে। WHERE row, HAVING group বাছে। Grouping স্পষ্ট, order explicit। পরের Join-এ related table মিলে সাবধান summary।
