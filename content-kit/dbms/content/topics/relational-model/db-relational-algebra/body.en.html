Build a question from smaller operations

“Find CSE students from Dhaka” contains two tasks: keep matching students and choose the columns you want. Relational algebra gives those tasks names and symbols. Larger queries grow by combining small, well-defined operations.

Relational algebra is a language of operations on relations. Each operation receives relations and produces another relation. This closure lets you nest expressions. An intermediate answer can become the input to the next step without changing the basic kind of object.

Classical algebra uses sets: duplicate tuples disappear and tuple order has no meaning. SQL usually keeps duplicate result rows unless you request DISTINCT. SQL also includes NULL, which classical algebra does not. Keep those differences visible when comparing a mathematical expression with a MySQL query.

Subscripts name attributes or conditions. Read πstudent_id(σdepartment_id=1(Students)) from inside outward. First keep department 1 students, then return their identifiers. Neither operation asks the server to use a particular index or physical scan.

Selection, projection and rename

Selection keeps entire tuples whose predicate is true. σmarks ≥ 80(Results) keeps three result tuples in the university data. Projection keeps named attributes. Projecting student_id from those tuples returns the identities of qualifying students rather than their marks and sections.

Several qualifying results may belong to the same student. Set projection returns that student only once. SQL needs DISTINCT when duplicates are possible. Projection does not mean selecting the first few rows; that is a different operation involving order and a limit.

Rename gives a relation or its attributes new names within an expression. Use ρ to distinguish two roles of the same relation or to make headings clear. SQL aliases such as s for Students serve this purpose. Aliases do not change the stored schema.

Set operations need compatible shapes

Union, intersection and difference require union-compatible inputs. Corresponding attributes must have compatible domains and the inputs must have the same degree. A set of student identifiers can combine with another set of student identifiers. It should not be unioned meaningfully with unrelated payment amounts merely because both happen to use integers.

Let A be students enrolled in section 31: {101,102}. Let B be students enrolled in section 33: {101,102,103}. Their union is {101,102,103}; their intersection is {101,102}. B − A is {103}, while A − B is empty. Difference is directional.

Products and joins combine tuple pairs

A Cartesian product pairs every tuple on the left with every tuple on the right. Eight students and five courses produce forty pairs. These are possible combinations, not proof of actual registration. To represent actual enrollment, follow the recorded relationship rather than assuming every pair exists.

A theta join keeps product pairs satisfying a condition θ. An equality join uses equality as its condition. Natural join matches every same-named attribute automatically and merges matching columns. That convenience can become a trap if a later schema change adds another shared name.

A left outer join preserves unmatched left tuples and adds missing right-side values. In the enrollment-result example, Sadia’s enrollment survives with NULL marks. Outer joins extend the classical set-based operators with missing-value behaviour. State this difference when discussing a mathematical answer.

Division means every required value

Suppose the required sections are 31 and 33. A student qualifies only when neither requirement is missing from their enrollments. Ayesha and Tanvir have both sections. Nabila has section 33 but not section 31, so having one qualifying witness is insufficient.

Using E(student_id, section_id) and R(section_id), division E ÷ R returns the student IDs from E that cover every R section. The SQL example instead uses Students as the candidate range, then checks that no required section lacks an enrollment. For a nonempty required set, the intended qualifying IDs agree here.

An empty required set exposes the candidate-range choice. Every student satisfies “no requirement is missing,” including Fahim with no enrollments. Classical division’s projected E candidate range would omit an ID absent from E. Define the business question’s candidates before choosing an expression.

Check a relational expression’s intermediate schema

Write down the attributes after every operation when solving an exam problem. Selection preserves the input attributes. Projection changes them to the requested list. A product combines both schemas, requiring renaming when names conflict. A join combines matching values according to its condition. This habit exposes comparisons against attributes that were already removed and prevents ambiguous names from hiding a wrong connection.

Check the meaning after every operation

Projecting a needed condition away too early

If you discard department_id before testing department membership, the remaining relation may no longer contain the attribute needed for selection. Build the expression from the inside and note each intermediate schema. Keep join attributes until their connections have been applied.

Treating a join as one row per student

A join produces matching pairs. Ayesha has several results, so joining her student row to Results repeats her identity across those pairs. Use set projection or DISTINCT when the question asks only which students, rather than which results.

Replacing every with any

One EXISTS proves one witness. It does not prove that all requirements are covered. Division needs absence of a missing requirement, or another correctly counted equivalent. Try a student with only one of two required sections to expose an incomplete condition.

Keep SQL version differences explicit

MySQL added INTERSECT and EXCEPT in 8.0.31. The set examples use EXISTS and NOT EXISTS so they also work on the stated 8.0.16 baseline. UNION already removes duplicates; UNION ALL preserves them. ORDER BY defines display order separately from set membership.
