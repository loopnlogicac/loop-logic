ভাঙার পরেও তথ্য থাকে প্রমাণ করো

Registration টেবিল ছোট করেও জয়েন-এ ভুল উত্তর আসতে পারে। দুটি পরীক্ষা আলাদা প্রতিশ্রুতি রক্ষা করে। Losslessness বৈধ রো-এর তথ্য রাখে। Dependency preservation আলাদা component-এর ভেতরে মূল নিয়ম মানানোর ক্ষমতা রাখে।

D = {R1,…,Rn}-এ lossless মানে R-এর প্রতিটি বৈধ r project করে জয়েন করলে ঠিক r ফেরে। Relational theory-তে projection duplicate tuple সরায়। প্রতিটি মূল tuple সব projection-এ অংশ দেয় বলে জয়েন-এ মূল tuple থাকেই। ঝুঁকি হলো ভিন্ন মূল tuple-এর অংশ মিলে বাড়তি spurious tuple হওয়া।

DISTINCT ছাড়া SQL SELECT bag semantics নেয়। Mathematical split-এর সঙ্গে SQL তুলনায় duplicate ও কী-এর হিসাব রাখো। আজ রো সংখ্যা মেলা সব বৈধ অবস্থার প্রমাণ নয়। প্রতি গণনার পাশে FD set, heading ও অনুমান লেখো।

আলাদা দুটি পরীক্ষা বোঝো

R1 ∪ R2 = R এমন binary split-এ FD-ভিত্তিক lossless criterion: F+-এ (R1 ∩ R2) → R1 অথবা → R2। F-এ common attribute-এর closure করে পুরো একটি component আসে কি না দেখো। FD-এর ক্ষেত্রে এই শর্ত necessary এবং sufficient দুটোই।

Preservation-এ F+ প্রতিটি Ri-তে project করো। Projected FD-গুলোর union G ধরো। G থেকে মূল প্রতিটি FD এলে F preserved। Projected rule F থেকেই আসে, তাই উল্টো implication স্বয়ংক্রিয়। F-এর প্রতি X → Y-এর জন্য G-তে X+ করো। Y না এলে local enforcement যথেষ্ট নয়।

Projection-এ derived rule-ও আসে। F = {A → B, B → C}, component AC ধরো। লেখা FD-তে শুধু A,C নেই, কিন্তু implied A → C projection-এ থাকবে। কেবল মূল arrow খুঁজলে ভুল করে preservation হারিয়েছে বলতে পারো।

পুনর্গঠন, counterexample ও chase দেখো

দুই ভাগে lossless decomposition

R(A,B,C,D), F = {A → B, B → C, C → D}-কে AB ও BCD করো। Common B। B+ শুরু B; B → C-তে C, C → D-তে D আসে। পুরো BCD আছে বলে lossless। B থেকে A না এলেও চলে; এক পাশ পাওয়াই যথেষ্ট।

AB-তে A → B; BCD-তে B → C ও C → D থাকে। Union-এ সব মূল rule আছে, তাই preserving-ও। A+ = ABCD বলে A candidate কী। বৈধ মূল relation-এ B-প্রতি এক C,D combination, তাই B-তে জয়েন নিরাপদ।

Lossy split-এর witness

এবার R(A,B,C), F = {A → B}-কে AB ও BC করো। Common B; B+ শুধু B, পুরো AB বা BC কোনোটিই নেই। Test ব্যর্থ। এর অর্থ দেখতে দুটি tuple-এর বৈধ r নাও।

ABC
a1b1c1
a2b1c2

AB = {(a1,b1),(a2,b1)}, BC = {(b1,c1),(b1,c2)}। B-তে জয়েন-এ মূল দুটির সঙ্গে (a1,b1,c2),(a2,b1,c1), মোট চার tuple। মূল ও নতুন ফলে A → B এখনও ঠিক। ওই FD কোন A-এর সঙ্গে কোন C বলে না; split ঠিক সেই association হারায়।

Business rule B → C-ও সত্য হলে দুই-রো witness অবৈধ হতো এবং closure test সফল হতো। তাই lossless সিদ্ধান্ত সবসময় বলা dependency set অনুযায়ী। খারাপ জয়েন দেখে সুবিধামতো নতুন FD যোগ করবে না।

Lossless কিন্তু enforcement হারায়

SCI, F = {SC → I, I → C}-কে SI ও IC করো। Common I IC নির্ধারণ করে, তাই lossless। Projection-এ I → C আছে, SC থেকে I-এর rule নেই। Union-এর অধীনে SC+ শুধু SC থাকে। তাই SC → I preserved নয়।

Enforcement witness: SI = {(101,Nusrat),(101,Arif)}, IC = {(Nusrat,DBMS),(Arif,DBMS)}। Component স্থানীয় FD মানে, জয়েন SC → I ভাঙে। এগুলো বৈধ মূল relation-এর projection হওয়া লাগে না; split-এর পরে স্বাধীন আপডেট-এর ঝুঁকি দেখায়।

তিন component-এর chase

ABCD ও A → B, B → C, C → D chain-এর AB, BC, CD নাও। Chase tableau-তে component-প্রতি একটি রো। Component-এ A থাকলে ওই কলাম-এ distinguished aA, না থাকলে cell-টির নিজস্ব নতুন symbol। অন্য কলাম-এও একই নিয়ম।

রোABCD
ABaAaBb13b14
BCb21aBaCb24
CDb31b32aCaD

AB ও BC রো-এর B = aB মেলে। B → C দিয়ে C symbol মিলিয়ে b13-কে aC করো; distinguished symbol অগ্রাধিকার পায়। এখন তিন রো-এর C = aC। C → D দিয়ে b14,b24-কে aD করো। AB রো পুরো (aA,aB,aC,aD) হয়; তাই chase lossless প্রমাণ করে।

শুরুর দুই রো-এর A মেলে না বলে A → B এখানে দরকারি merge দেয় না। সব FD চালু হওয়া লাগে না। একটি all-distinguished রো হলেই সফল। আর merge না হলে এবং এমন রো না থাকলে এই standard FD chase lossiness-এর witness দেয়।

Safe binary ধাপেও প্রমাণ করা যায়। আগে C → D-তে ABCD থেকে ABC,CD; পরে B → C-তে ABC থেকে AB,BC। দুই common set-ই আলাদা করা পাশ নির্ধারণ করে। পুরো chase-এর চেয়ে সহজ হতে পারে, তবে সত্যিই দেওয়া component তৈরি করতে হবে। ইচ্ছেমতো কিছু pair check সাধারণ multiway test নয়।

Dependency-preserving 3NF synthesis

Singleton minimal cover G দিয়ে শুরু করো। প্রতি determinant X ও তার right-side attribute নিয়ে relation বানাও। অন্যটির মধ্যে থাকা relation বাদ দাও। কোনো component-এ মূল R-এর candidate কী না থাকলে কী-সহ relation যোগ করো। এটি standard 3NF synthesis; minimal-cover শর্ত তার guarantee-এর অংশ।

R(A,B,C,D,E), G = {A → B, B → C, C → A, D → E}-তে প্রথমে AB,BC,CA,DE। কোনোটিতে সব পাঁচ attribute-এর কী নেই। D mandatory, A/B/C যেকোনোটি তিন-cycle নির্ধারণ করে। কী AD,BD,CD। AD যোগ করো। প্রতিটি FD component-এ আছে; কী relation lossless guarantee দেয়।

প্রথম চার component lossless নয়: জয়েন প্রতিটি ABC গ্রুপ-কে প্রতিটি DE গ্রুপের সঙ্গে মেলায়, মূল A-D association ভুলে যায়। AD তা ফেরায়। সব dependency কোথাও আছে বলেই কী ধাপ বাদ দেবে না। এটি instructor উদাহরণের উল্টো দিকে preservation ও losslessness আলাদা করে।

পরীক্ষার উত্তরে দুটি আলাদা সিদ্ধান্ত ও প্রমাণ দাও। “I থেকে IC হয় বলে lossless; projected rule-এ SC+ থেকে I আসে না বলে preserving নয়”—সম্পূর্ণ যুক্তি। শুধু “BCNF decomposition” বললে reconstruction-এর কারণ ও enforcement খরচ লুকায়।

A-based আর preserving split আলাদা

R(A,B,C), F = {A → B, B → C}-এর AB,AC ধরো। Common A-এর closure ABC, তাই lossless। AC projection-এ derived A → C আছে। A → B-এর সঙ্গে মিলিয়েও B → C আসে না; স্থানীয় rule-এ B+ শুধু B। দুই component-এ কী থাকলেও preservation হারায়।

Witness হিসেবে AB = {(a1,b),(a2,b)}, AC = {(a1,c1),(a2,c2)} নাও। প্রতিটি A-ভিত্তিক FD মানে। জয়েন একই b-কে c1,c2 দেয়, তাই B → C ভাঙে। কিন্তু AB,BC-তে dependency স্থানীয় এবং B BC নির্ধারণ করে বলে lossless-ও। বাস্তব design বাছার আগে projected closure তুলনা করো।

Closure-এর আগে উভয় split-এর heading লেখো। একই attribute set component-এর কী হয়েও মূল relation-এর রো না-চিনতে পারে।

প্রতি ধাপে সঠিক heading রাখো

Intersection পুরোR-এর কী চাই ভাবা

Binary criterion-এ intersection পুরো মূল heading নয়, একটি component নির্ধারণ করলেই চলে। AB,BCD-তে B থেকে A না এলেও B যথেষ্ট।

FK থেকে preservation ধরা

Foreign কী reference বৈধ রাখে; SI ও IC পেরিয়ে SC → I নিজে বের করে না। Referential integrity ও local FD preservation আলাদা invariant রক্ষা করে। Schema বানানোর সময় দুটোই লেখো।

Chase-এ fresh symbol reuse

প্রতিটি missing cell নতুন b symbol দিয়ে শুরু হবে। একইটি আবার দিলে dependency ছাড়া মিথ্যা agreement হয়। বলা FD অনুমতি দিলেই merge করো এবং tableau-জুড়ে consistent replacement দাও।

দুটি স্পষ্ট সিদ্ধান্তে শেষ করো

Binary split-এ intersection closure, preservation-এ projected-rule closure, বহু component-এ chase বা বৈধ ধাপ নাও। একই design একটি pass করে অন্যটিতে fail করতে পারে। SQL কী ও foreign কী-এর সঙ্গে যুক্তি মেলাতে normalization-এ ফিরে যাও।
