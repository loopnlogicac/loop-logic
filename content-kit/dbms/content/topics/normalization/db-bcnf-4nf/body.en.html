When 3NF still repeats a fact

Two instructors may teach the same course, while each instructor teaches only one course. A registration can then repeat the instructor’s course again and again. A relation may pass 3NF and still have this redundancy. Boyce–Codd normal form, or BCNF, applies a stricter rule to determinants.

For every nontrivial FD X → Y in the closure of the dependency set, BCNF requires X to be a superkey. Nontrivial means Y is not contained in X. Unlike 3NF, BCNF has no exception because a right-side attribute belongs to a candidate key. This difference matters most when candidate keys overlap.

A later problem has several values that vary independently, such as a student’s languages and hobbies. FDs alone cannot describe that independence. Fourth normal form, or 4NF, uses multivalued dependencies. Learn the different promise before applying another split: multiple rows alone never prove an MVD.

Test determinants and independence

A BCNF decomposition starts with a violating FD X → Y. Split R into R1 = X ∪ Y and R2 = R − (Y − X). The common attributes are X, and X determines R1. Therefore the binary split is lossless. Project the original FD closure onto each component and repeat until neither component has a violating dependency.

Projection means keeping every dependency implied by the original rules whose attributes lie within that component. It is more than copying only the FDs printed in the original list. For instance, A → B and B → C imply A → C even if a component contains only A and C. Recompute keys after each split because the relation heading has changed.

A multivalued dependency X ↠ Y says that, for a fixed X, the allowed Y values combine independently with Z = R − X − Y. If two legal tuples share X, the tuples formed by swapping their Y and Z parts must also be present. The whole set of combinations is required. An MVD is trivial when Y ⊆ X or X ∪ Y = R.

4NF requires every nontrivial MVD determinant to be a superkey. Every FD implies an MVD, so 4NF implies BCNF. The reverse does not hold. For a violating X ↠ Y, split into XY and XZ. This decomposition is lossless precisely because the MVD promises that the original relation already contains every reconstructed combination.

Work through two different kinds of redundancy

Find every key in the instructor relation

Let R(S,C,I) describe a student S, course C and instructor I. The rules are SC → I and I → C. The first rule says each student has one instructor for a given course. The second says each instructor teaches one course in this exercise. These assumptions are deliberately narrower than a full university timetable.

S is mandatory because it never appears on a right side. SC and SI each determine the whole heading, and neither loses an attribute without failing. They are the only candidate keys. Consequently S, C and I are all prime. The relation is in 3NF: SC is a superkey, and I → C has a prime right side. However, I is not a superkey, so that same FD violates BCNF.

Split, reconstruct and examine enforcement

Decompose on I → C into InstructorCourse(I,C) and StudentInstructor(S,I). InstructorCourse has key I. StudentInstructor has key SI and no nontrivial projected FD. Both components are in BCNF. Their common attribute I determines InstructorCourse, so the decomposition is lossless for every relation satisfying the original FDs.

Yet SC → I is not preserved locally. The projected union contains I → C, but SC+ under that union is only SC. You cannot derive I. To see the practical danger, store (Nusrat,DBMS) and (Arif,DBMS), then give student 101 both instructor links. Each component satisfies its own local rules, but the join gives student 101 two instructors for DBMS. A transactionally safe cross-table rule or a different design is required to prevent that state.

Losslessness and dependency preservation answer different questions. The lossless proof assumes the source relation obeys the original FDs and asks whether projection loses information. Preservation asks whether independently maintained components can enforce all original FDs locally. Losing preservation does not contradict the lossless proof. A 3NF synthesis may be preferable when local enforcement is essential.

Independent languages and hobbies

Let Interest(S,L,H) record student, language and hobby. For student 101, the languages are Bangla and English; the hobbies are chess and cricket. Assume the requirement says every known language combines with every hobby. This is an independence rule, not a claim that a language is used for a particular hobby.

The four rows satisfy S ↠ L and, by complementation, S ↠ H. There is no nontrivial FD: one student has several languages and hobbies, and a language-hobby pair need not identify one student. Under these assumptions the candidate key is SLH. The relation is BCNF because there is no violating nontrivial FD, but it violates 4NF because S is not a superkey for the nontrivial MVD.

Split into StudentLanguage(S,L), with key SL, and StudentHobby(S,H), with key SH. The first contains (101,Bangla) and (101,English); the second contains (101,chess) and (101,cricket). Their join on S returns all four combinations. Each component has only trivial MVDs on its two-column heading under the stated rules, so each is in 4NF.

Originally m languages and n hobbies require m × n rows for one student. The decomposition stores m + n rows. Adding Arabic needs one language row instead of two combination rows in this case. Deleting the last hobby no longer deletes every known language. These are concrete benefits of representing two independent collections separately.

Reject an invalid independence assumption

Suppose Interest actually means “student uses this language while doing this hobby.” The only recorded pairs may be (Bangla,cricket) and (English,chess). Joining separate collections would add (Bangla,chess) and (English,cricket), which were never asserted. S ↠ L does not hold in that meaning. Keep the three-way association, or introduce a better event model. A smaller representation is incorrect if it changes the question being answered.

Similarly, a teacher-course-semester relation may require the semester in its determinant. An instructor teaching one course in Spring and another in Summer does not satisfy I → C globally. Add the missing time scope, restate the dependencies and recalculate the keys. Normal-form names cannot replace a precise statement about what each row means.

Recheck a recursive BCNF decomposition

Consider another relation R(A,B,C,D) with A → B, B → C and C → D. A is the only candidate key: A+ reaches all four attributes, and A never appears on a right side. C → D violates BCNF because C+ contains only C and D. Split R into CD and ABC. Their intersection C determines CD, establishing a lossless first step.

In ABC, the projected rules include A → B, B → C and A → C. A remains its key, but B is not a superkey. Split ABC into BC and AB on B → C. The common B determines BC, so this second step is lossless too. The final components AB, BC and CD have determinants A, B and C respectively; each determinant is a key for its component.

This particular BCNF decomposition preserves the original dependencies because every arrow has a local relation. Compare it with the instructor example, where SC → I disappears from the local union. BCNF may lose preservation, but it does not always lose it. Recompute both properties for the specific relation rather than repeating a general slogan.

If you instead split using another violating dependency, the resulting components may differ. A valid result needs projected-rule reasoning and normal-form checks for each component. The number of tables alone is not evidence that one decomposition is correct or preferable.

Keep the two dependency languages distinct

Calling every many-to-many relation a 4NF violation

A two-column student-course bridge has a composite key and only trivial MVDs on that heading. Several registrations do not by themselves violate 4NF. You need independent value sets in a relation with enough attributes for a nontrivial MVD.

Assuming 3NF and BCNF always differ

Many everyday relations satisfy both. Look for a nonkey determinant whose right side is prime to find the classical 3NF exception. Do not declare a relation BCNF without checking all implied FDs and alternative candidate keys.

Promising every original constraint remains local

The instructor example is a counterexample to that promise. Show the projected closure of SC explicitly. An application that checks after an unsafe concurrent insert can still race, so any cross-table enforcement must be designed with transaction isolation and locking in mind.

Choose stronger forms with a proof

BCNF removes nonkey FD determinants; 4NF also separates independent multivalued facts. Each decomposition needs a reconstruction argument and an enforcement review. Next, practise the formal tests in lossless and dependency-preserving decomposition.
