Schedule প্রত্যেক ট্রানজ্যাকশন-এর নিজস্ব অর্ডার রেখে mixed operation। Serial-এ একটির পরে অন্য। Serializable interleave হলেও নির্দিষ্ট equivalence-এ serial-এর মতো। Disk-lock অপেক্ষায় অন্য কাজ চলে বলে overlap দরকারি।

Locking-এর দুই phase

Shared compatible reader দেয়,exclusive writer রক্ষা। Basic 2PL-এ আগে acquire করে grow,কোনো release-এর পরে shrink-এ আর acquire নয়। Lock model-এ conflict serializable নিশ্চিত,deadlock হতে পারে।

Strict2PL exclusive boundary পর্যন্ত,dirty read-overwrite ঠেকায়। Rigorous shared-ও রাখে। বইয়ে নাম আলাদা হতে পারে,কোন lock বলো। InnoDB lock+MVCC,ordinary consistent SELECT textbook shared-lock2PL নয়।

Same ID অর্ডার-এ lock এই cycle কমায়। Short ট্রানজ্যাকশন,selective ইনডেক্স,user-ইনপুট wait নয়। Timeout1205 ডিফল্ট-এ সাধারণত waiting স্টেটমেন্ট rollback,deadlock victim whole। Timeout retry-এর আগে business unit explicit rollback।

Consistent আর locking read

Ordinary SELECT সাধারণত MVCC-তে selected রো lock নয়। FOR UPDATE current ডেটা আর exclusive lock। Observed-এ A account1 lock,B UPDATE অপেক্ষা করে short timeout-এ1205। A commit release।

একই RR-এ locking read আগের snapshot থেকে ভিন্ন ভার্সন পেতে পারে। Invariant-এ casually mix নয়। Explicit ট্রানজ্যাকশন চাই,autocommit-এ স্টেটমেন্ট শেষে protection যায়। একই boundary-তে validate-change রো lock।

RR রেঞ্জ-এ next-কী রেকর্ড+gap। Existing unique equality সাধারণত রেকর্ড only। RC-তে অধিকাংশ search gap কমে,FK-duplicate check exception। Access path কোন রেকর্ড-gap দেখা-lock হবে বদলায়।

Recoverability-তে commit অর্ডার-ও

w1(X),r2(X),c2,a1-এT2 dirty পড়ে commit,T1 abort। Graph শুধুT1→T2,acyclic,তবু reader আগে commit বলে nonrecoverable।

T1 commit-এর পরে T2 commit হলে dependency recoverable হতে পারে। Dirty read না হলে cascading abort এড়ায়। Serial test পুরো recovery proof নয়;conflict অর্ডার আর commit dependency আলাদা property।
