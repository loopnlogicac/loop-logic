Debit-credit-এর মাঝেই সার্ভার থামতে পারে। কিছু changed page disk-এ,কিছু committed page মেমরি-তে। Recovery শেষ মেমরি বিশ্বাস না করে persistent তথ্য থেকে valid state বানায়।

কনস্ট্রেইন্ট failure স্টেটমেন্ট/ট্রানজ্যাকশন-এর,process crash volatile মেমরি হারায় কিন্তু স্টোরেজ থাকতে পারে,media failure ফাইল-device হারায়। Committed ভুল DELETE logical এরর,engine intended না হওয়া কাজও ঠিক রেখেছে। এক mechanism চারটি সারায় না।

Engine log আর app audit আলাদা। Mark কে বদলাল log বলতে পারে,redo-undo-র বদলি নয়। Commit-ও configured persistence-স্টোরেজ guarantee-র মধ্যেই অর্থপূর্ণ।

Buffer,undo,redo বোঝো

Buffer pool frequent page রাখে। Changed page ডেটা ফাইল-এ লেখা না হওয়া পর্যন্ত dirty। Commit-এ সব final page write লাগে না,random write বাঁচে;তাই committed reconstruction-এর durable উপায় চাই।

Redo log page change আবার করার তথ্য,undo log uncommitted ফেরানো আর older ভার্সন। InnoDB দুটোই। Undo MVCC-তেও লাগে,স্টেটমেন্ট শেষে শুধু ফেলে দেওয়া temporary নয়।

WAL-এ dependent ডেটা page flush-এর আগে দরকারি log durable। Durable commit acknowledgment-এর আগে required redo-ও configuration অনুযায়ী persist। নইলে page-এ change থাকবে,recovery তথ্য crash-এ যাবে।

Steal-এ uncommitted dirty disk-এ যেতে পারে,তাইundo। No-force-এ commit সবpage flush নয়,তাইredo। এগুলো conceptual;engine page latch,LSN,detailed protocol-এ করে।

Checkpoint progress marker

Checkpoint safe recovery position। Dirty flush-এ তার আগের redo আর crash reconstruct-এ লাগে না। Fuzzy-তে normal ট্রানজ্যাকশন চলতে পারে,সব active একসঙ্গে শেষ নয়।

Oldest needed page change LSN200 হলে latest500 মানেই200..499 বাদ নয়। Page-log শর্ত-এ advancement। Checkpoint-এর আগের ট্রানজ্যাকশন পরেও active,rollback need শুধু timeline নয়।

Restart work কমায়,redo capacity reuse দেয়। Backup নয়,commit নয়,আগের checkpoint বেছে deleted টেবিল restore নয়। Lost ডেটা-র সঙ্গে lost marker আলাদা recovery material নয়। Undo-binlog retention-ও অন্য।

Media loss-এর পরে restore

Device গেলে ছোট circular redo-তে missing base ফেরে না। Valid backup replacement-এ,configured retained binlog-এ point-in-time। Encryption কী-metadata-ও রক্ষা,চাবি ছাড়া encrypted backup অকেজো হতে পারে।

InnoDB logical backup snapshot নিতে পারে,tool rule আর concurrent DDL restriction-সহ। Physical tool-এর preparation আলাদা। Live ফাইল সাধারণ copy automatic consistent নয়। Supported পদ্ধতি আর আলাদা environment-এ পুরো restore practice।

RPO গ্রহণযোগ্য recent ডেটা loss,RTO ফেরার সময়। Nightly backup-এ retained change না থাকলে প্রায় একদিন loss। Log retention gap কমায়,restore time-complexity তবু মাপো।

Committed human mistake

WHERE ছাড়া results DELETE commit করলে restart তা রাখবে। Isolated backup restore,verified ডিলিট-এর আগের log boundary পর্যন্ত replay,lost রো extract,later valid change reconcile এক উপায়। Format-position-requirement-এ exact process নির্ভর।

Timestamp আন্দাজ করে current overwrite নয়। Affected ট্রানজ্যাকশন চেনো,current material রাখো,recovered রো যাচাই। Facts-কনস্ট্রেইন্ট জানা থাকলে compensating INSERT explicit repair,পুরোনো commit-এর automatic rollback নয়।

Redo engine crash,binlog backup-সহ replication/PITR। Replica ভুল ডিলিট-ও ঠিকমতো repeat করে,তাই historical backup নয়। Retention-separation design,শুধু দ্বিতীয় সার্ভার নাম দিলেই হয় না।
