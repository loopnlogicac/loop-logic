Transfer-কে এক সিদ্ধান্ত ধরো

Ayesha Tanvir-কে100 BDT পাঠায়। একপাশে বিয়োগ,অন্যপাশে যোগ দুই স্টেটমেন্ট হলেও এক transfer। ট্রানজ্যাকশন এগুলো গুছায়। শুধু প্রথমটি টিকলে model থেকে টাকা হারায়।

ACID-এ atomicity all-or-nothing,consistency valid-state rule,isolation concurrent কাজ,durability failure-এর পরে committed effect। দায় আলাদা,COMMIT একা চারটি proof নয়।

দুই শিক্ষার্থী-এর InnoDB অ্যাকাউন্ট-এ শুরু1000 আর500। Invariant total1500,কোনোটিই negative নয়। Fixed ID,DECIMAL money,fee/external system নেই—এই assumption-এ expected state নির্দিষ্ট।

Partially committed conceptual recovery boundary,SELECT-এ দেখা MySQL status নয়। শেষ UPDATE-এর পরেও persistence-এর আগে failure পারে। Configured durability policy-তে successful acknowledgment ক্লায়েন্ট boundary।

Atomicity crash/rollback-এ অর্ধেক unit committed রাখে না,InnoDB undo সাহায্য করে। তবে বহু স্টেটমেন্ট এরর শুধু failing স্টেটমেন্ট ফেরায়। Debit-এর পরে credit fail হলে app whole transfer rollback করবে,কানেকশন আছে বলেই commit নয়।

Consistency valid শুরু থেকে valid শেষ। CHECK negative ঠেকায়,দুই রো মোট নিজে মানায় না। Same amount debit-credit,missing অ্যাকাউন্ট ধরতে কোড চাই। কনস্ট্রেইন্ট সব business invariant আন্দাজ করে না।

Isolation chosen level-access pattern অনুযায়ী interference আটকায়। Plain read পরে unconditional write concurrent change হারায়। Conditional আপডেট/locking read,affected-রো আর consistent lock অর্ডার নাও। Stronger isolation concurrency কমিয়ে proof সহজ করতে পারে।

Durability system promise-এর failure-এ commit রাখে। Redo-তে dirty page final জায়গায় না গেলেও চলে,log যথাযথ persist চাই। সাধারণ durable সেটিং innodb_flush_log_at_trx_commit=1,binary log-এ sync_binlog-ও। Device flush মানবে, disk loss-এ backup তবু চাই।

ACID consistency app invariant,CAP consistency distributed replica-র single-copy ভিউ। শব্দ মেলে,দাবি একে অন্যের বদলি নয়।

Retry-র আগে business request-এর নাম

COMMIT পাঠিয়ে response-এর আগে কানেকশন গেলে সার্ভার committed-response lost অথবা commit unfinished দুই সম্ভাবনা। Unlabelled replay-এ double debit,সরাসরি fail বললেও সফল transfer লুকায়।

Unique request ID আর completed outcome balance change-এর একই ট্রানজ্যাকশন-এ রাখো। Reconnect-এ lookup করে reconcile। Unique rule একই request-এর দুই committed রেকর্ড আটকায়। Amount-অ্যাকাউন্ট-ও মেলাও,এক ID অন্য payload-এ অন্য transfer না হয়।

Idempotent handling-এ same logical request established ফল দেয়,দ্বিতীয় পেমেন্ট নয়। Concurrency-safe implementation আর প্রথম ট্রানজ্যাকশন active থাকলে policy চাই। Timeout মানে সার্ভার কাজ করেনি proof নয়। Durable commit আর reliable business response related,আলাদা design।

কোন promise ভাঙল দেখো

Valid SQL মানেই consistency

দুই UPDATE ভিন্ন amount-এও রো CHECK মানতে পারে। Before-after invariant দেখো। Arithmetic আর affected-রো ট্রানজ্যাকশন design-এর।

স্টেটমেন্ট এরর আগের সব abort

CHECK fail-এ অনেকসময় আগের pending-সহ active থাকে। Business শেষ না হলে full rollback। Deadlock whole abort করতে পারে,এরর classify করে retry।

Rollback সব disaster recovery

Uncommitted change ফেরায়,গতকালের committed ভুল ডিলিট বা নষ্ট disk নয়। Log আর tested backup অন্য failure সামলায়।

Logic,isolation,persistence মেলাও

Safe transfer-এ invariant,অ্যাকাউন্ট match check,এক boundary,এরর path। App logic-engine মিলে ACID। পরের concurrency control-এ overlap দেখো।
