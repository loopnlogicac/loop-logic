শুধু comparison নয়,page visit

প্রতি বইয়ে সব shelf খোলা ধীর। স্টোরেজ relevant page-এর route দেয়। Page রেকর্ড একসঙ্গে read-write করে,তাই এক useful visit বহু মেমরি comparison-এর চেয়ে জরুরি হতে পারে।

ফাইল organization রেকর্ড placement,ইনডেক্স extra search স্ট্রাকচার;কিছুengine রো-ও ইনডেক্স-এ রাখে। Related choice-এর cost আলাদা। Page read,comparison,মেমরি নাকি maintenance মাপছ বলো।

General concept InnoDB-তে map:clustered B-tree family,ordered access-এ সাধারণ B+ আচরণ। Textbook heap comparison model,shared InnoDB টেবিল heap দাবি নয়।

Heap free-space map-এ খালি page-তে রাখে। Cold model-এb ডেটা-page scan প্রায়b read। Sequential throughput,prefetch,cache elapsed বদলায়,b reasoning tool।

Sorted ফাইল রেঞ্জ start খুঁজে consecutive scan। Ideal b-page binary প্রায়log2(b) probe। Frequent ইনসার্ট অর্ডার রাখতে move,overflow,reorganization;tree ছোট local maintenance ভাগ করে।

Textbook Primary ইনডেক্স primary-কী ordered ফাইল-এ কখনো block-পিছু sparse। Secondary অন্য কী,সাধারণতdense/reference list। Clustered placement ঠিক করে। System-ভেদে নাম আলাদা,physical অর্থ বলো।

Tree আর reference হাঁটো

ছোট B+ tree

                 root: [30 | 60]
                 /      |      \
leaves:     [10,20] -> [30,40,50] -> [60,70,80]
               ordered leaf link

Separator route দেয়:30-এর নিচেleft,30..60-এর আগেমাঝে,60+right।40-এroot-মাঝেরleaf।35..70-তেfirst possible leaf,তারপর link রেঞ্জ শেষ পর্যন্ত।

B+-তে রেকর্ড/reference leaf-এ,internal routing। Leaf same depth,point level সংখ্যা predictable। Page-এ বহু entry-তে high fanout child pointer,বড় relation-ও shallow।

ইনসার্ট leaf-এ ordered,full-এsplit,parent separator,overflow ওপরে,root split level বাড়ায়। ডিলিট redistribute/merge implementation-মতো। Local হলেওlog,lock/latch,page write লাগে।

InnoDB clustered mapping

Students PRIMARY KEY(student_id) clustered। Leaf-এ রো কলাম,আলাদাheap pointer শুধু নয়। এক টেবিলে একclustering। Display-এ তবু ORDER BY,physical organization SQL promise নয়।

Explicit PK নেই হলে first suitable UNIQUE all-NOT-NULL;তাও নেই হলে hidden clustered ID। Deliberate stable PK-এ design-app পরিচয় পায়। Hidden ID অঘোষিত business unique মানায় না।

Hometown secondary-তে hometown+PK। Full শিক্ষার্থী পেতে secondary পরে match-পিছু clustered।শুধু hometown-ID চাইলে cover,extra lookup নয়।

Long PK সব secondary বড় করে,entry/page কম,page বাড়ে। Compact stable কী বহু ইনডেক্স কমায়। Surrogate হলেও প্রয়োজনের business unique মানাও।

Hash bucket

Equality কী bucket-এ। h(id)=id mod4-এ101,105 bucket1। Collision,equality proof নয়। Original কী তুলনা,overflow/chaining/অন্য strategy চাই।

ভালো distribution-load-এ অল্প expected access,skew-এlong overflow।101..110 রেঞ্জ bucket-এcontiguous নয়,বহু bucket দেখতে হয়,hash অর্ডার হারায়।

Static fixed,dynamic extendible/linear ধীরে বাড়ে। Rehash-split maintenance লাগে। General ধারণা,shared InnoDB-তে ordinary HASH user B-tree-র মতো বাছে না।

Adaptive hash frequent B-tree page-এর internal optimization। Declared ইনডেক্সের বদলি নয়,ভার্সন-config-এavailability/ডিফল্ট। MEMORY explicit hash দেয়,কিন্তু persistence-ট্রানজ্যাকশন আলাদা। এক lookup দাবি নয়,whole workload-এengine।

Read লাভ বনাম write

ইনসার্ট-ডিলিট-কী আপডেট ইনডেক্স page-ও বদলায়। বেশিইনডেক্স space,buffer,log নেয়। PK আপডেট secondary পরিচয়-ও। Rare ইনডেক্স write-heavy workload ধীর করে,কোয়েরি না নিলেও।

ছোট টেবিল বা অধিকাংশ রো চাইলে scan ভালো হতে পারে। Secondary-তে scattered clustered fetch,scan leaf efficient। Selectivity,width,coverage,cache,cost model-মতো best। Optimization route বাছে।

Collision-skew overflow বাড়ায়। Expected cost-এর load-distribution বলো,worst অনেক বেশি।
