Answer briefly, then defend the boundary

These fifty questions practise clear spoken explanations. Give the core answer first, then add the condition that makes it correct. If an interviewer challenges a broad claim, respond with a small example rather than another memorised definition.

The numbered answers cover design, SQL, dependencies, transactions and practical storage choices. Pause after each question and say your own answer aloud. Use the linked longer lessons when you cannot explain why a statement holds.

Design and identity

1. What does a DBMS add beyond unrelated data files?

It coordinates queries, shared updates, integrity, authority and recovery. Those facilities reduce repeated application work, but the schema and business rules still need design.

2. How do logical and physical data independence differ?

Logical independence concerns changes in the conceptual structure without unnecessary external-view changes. Physical independence concerns storage and access changes without changing the logical interface.

3. Is a relation the same thing as any SQL table?

A mathematical relation is a set of tuples over defined domains. An unconstrained SQL table may permit duplicates and NULL, so the mapping needs explicit assumptions.

4. How does a candidate key differ from a superkey?

A candidate key has no removable attribute while still identifying tuples. A superkey can include additional attributes that do not contribute to identification.

5. Why can a foreign key contain repeated values?

Several child rows can reference the same parent. The foreign key protects valid references; it does not make every child reference unique.

6. What makes an entity weak?

Its identification depends on an owner’s key together with a partial key. A room number that repeats across buildings is a typical example.

7. What is total participation in an ER relationship?

Every entity instance on that side must participate. This is a minimum requirement and differs from the maximum number of allowed partners.

8. How is an M:N relationship mapped?

Introduce a bridge relation with references to both participants and a key matching the relationship’s event identity. Store relationship attributes on that bridge.

9. Why might an enrollment need a section rather than only a course?

A course can have repeated offerings. The section distinguishes the specific event in which the student registers and receives a result.

10. Does adding a surrogate identifier remove redundancy?

No. The original determinants still describe business facts. Preserve necessary uniqueness and analyse those dependencies rather than treating a new id as normalisation.

SQL meaning and result shape

11. Why does NULL = NULL not behave like ordinary equality?

SQL NULL represents missing or unknown information. Equality yields UNKNOWN in that comparison, so use IS NULL for a missing-value test.

12. How do COUNT(*) and COUNT(column) differ?

The first counts input rows. The second counts rows where the expression is non-NULL. This distinction is essential after an outer join.

13. What is the difference between WHERE and HAVING?

WHERE filters input rows before grouping. HAVING filters the resulting groups. Their placement can change both counts and which groups remain.

14. Why can a LEFT JOIN lose its unmatched parents?

A later WHERE condition can reject the NULL-extended child values. Put a child-matching restriction in ON when the parent must survive without a match.

15. When is EXISTS preferable to joining raw children?

When the question asks whether at least one child exists, EXISTS expresses membership without multiplying the parent by every matching child.

16. Why is NOT IN risky with a nullable subquery result?

A NULL in the comparison set can make the predicate UNKNOWN for otherwise unmatched values. NOT EXISTS often expresses the intended absence more directly.

17. What does UNION ALL preserve that UNION removes?

UNION ALL keeps duplicate occurrences from both inputs. UNION performs distinct set-style combination. Choose according to whether repeated events have meaning.

18. Why does a window aggregate differ from GROUP BY?

A window can attach a group-related value to each input row without collapsing those rows. GROUP BY produces one output row per group.

19. How do RANK and DENSE_RANK treat ties?

Both assign equal positions to equal ordering values. RANK leaves gaps after ties, while DENSE_RANK numbers distinct levels consecutively.

20. Why does LIMIT need a complete ordering for repeatable choices?

Equal ordering values leave the selected tied rows ambiguous. Add a unique tie-breaker when a particular limited subset must be reproducible.

Dependencies and decomposition

21. Can a few distinct sample rows prove a functional dependency?

No. A dependency is a rule for every permitted state. Sample rows may refute it, but requirements must justify its universal promise.

22. What is the purpose of attribute closure?

It collects every attribute determined by a starting set under the given FDs. You can use it to test implication and superkey status.

23. What causes a 2NF violation?

A nonprime attribute depends on a proper subset of a candidate key. Check all candidate keys rather than only the selected primary key.

24. What is the formal 3NF condition for X → A?

For a nontrivial dependency, X must be a superkey or A must be prime. The prime-right-side exception matters when candidate keys overlap.

25. What stronger demand does BCNF make?

Every nontrivial functional determinant must be a superkey. BCNF removes the 3NF exception for a prime right-side attribute.

26. What information does an MVD express?

For a fixed determinant, one attribute set varies independently of the remaining attributes, requiring the corresponding cross combinations of tuples.

27. How can a decomposition be lossless but fail preservation?

Its projections may reconstruct every valid original relation, while independently maintained components cannot enforce one original FD locally. Reconstruction and enforcement are separate tests.

28. What is a spurious tuple?

It is an extra row created when projected components join parts that did not belong together in the original relation.

29. Why does 3NF synthesis sometimes add a key relation?

FD-based components may enforce every rule yet lose associations between groups. Including a candidate key completes the synthesis construction’s lossless guarantee.

30. Does denormalisation always mean a design mistake?

No. A deliberate read optimisation or historical snapshot can duplicate facts. It needs a clear update, staleness and reconstruction policy.

Transaction boundaries and concurrency

31. What is the unit protected by atomicity?

The intended transaction boundary. If a business action spans two transactions or an external service, one local transaction cannot make all effects atomic automatically.

32. Can an atomic transaction violate consistency?

Yes. Committing an incorrect debit and credit together preserves all-or-nothing behaviour while breaking the total-balance rule.

33. What is a dirty read?

A transaction observes another transaction’s uncommitted change. If the writer later aborts, the reader used a value that never became committed history.

34. What is a nonrepeatable read?

A transaction reads a row again and sees another committed value. READ COMMITTED can allow this because consistent reads use fresh snapshots.

35. What is a phantom?

Repeating a predicate query sees a changed matching row set, such as an additional row. Its occurrence depends on isolation and access behaviour.

36. How do precedence and wait-for graphs differ?

Precedence edges describe ordering of conflicting data operations for serialisability. Wait-for edges describe blocked transactions depending on lock holders for deadlock analysis.

37. Does basic 2PL eliminate deadlocks?

No. Transactions can acquire locks in opposite orders and wait in a cycle. Common acquisition order reduces that pattern.

38. What should a deadlock retry repeat?

The complete aborted transaction, using current data and bounded retry logic. Preserve request identity so an uncertain previous outcome does not duplicate the business action.

39. Why is a savepoint not a nested transaction?

It marks an undo position within one transaction. Releasing it does not commit independently, and a full rollback removes the surrounding work.

40. Can ordinary DDL be rolled back with earlier DML in MySQL?

Many DDL statements cause implicit commits. Atomic DDL protects the DDL operation itself; it does not make it part of an ordinary user rollback group.

Recovery, storage and security

41. What does redo contribute after a crash?

It can reconstruct logged page changes that are not yet safely present in final data pages. Uncommitted logical effects still require rollback handling.

42. What does undo contribute besides rollback?

Undo records support older row versions for consistent reads. Retention therefore depends on active snapshot needs as well as transaction completion.

43. Why is a checkpoint not a backup?

It tracks recovery progress inside the running storage system. It does not provide an independent historical copy after media loss or committed mistakes.

44. What does an InnoDB secondary index use to find the full row?

The clustered primary-key value stored with its entry. A noncovering lookup can therefore involve both secondary and clustered trees.

45. Why do B+ tree leaves help range queries?

Their key order and neighbour links support scanning adjacent values after locating the starting leaf. A hash layout lacks that natural interval order.

46. What does EXPLAIN rows describe?

An estimate of examined input rows for a plan operation, not necessarily the exact final result count or an observed runtime measurement.

47. Why do prepared statements not replace authorisation?

They protect how values enter SQL syntax. The application must still decide whether this caller may access the particular valid identifier being requested.

48. Can a stored procedure contain an injection flaw?

Yes. Dynamic SQL assembled from untrusted text can remain unsafe inside a procedure. Bind values and restrict unavoidable structural choices.

49. Does NoSQL mean there is no schema?

No. Application code still expects field names, types and relationships. Those expectations need validation, versioning and migration even without a rigid table definition.

50. What does CAP require deciding during a network partition?

Whether to sacrifice linearizable responses or availability for affected operations. It is not a permanent instruction to choose any two unrelated product features.
