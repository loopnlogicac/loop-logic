সমাধান পড়ার আগে পঞ্চাশটি query চেষ্টা করো

আলাদা keyword নয়, university ডেটাসেট দিয়ে সম্পূর্ণ প্রশ্ন অনুশীলন করো। সহজ projection থেকে কয়েক ধাপের কঠিন report—এভাবে পঞ্চাশটি কাজ সাজানো। আগে query লেখো, কোন student বা section পরিচয় আসবে অনুমান করো, তারপর সমাধানের SQL ও ফল মেলাও।

পাঁচটি উত্তর-দলে প্রশ্নের ক্রমেই দশটি করে নম্বর দেওয়া query আছে। প্রতিটি দল অপরিবর্তিত university ডেটা দিয়ে শুরু হয়। পরপর result table ওই দলের পরের query-টির ফল। সোর্সের comment-এ প্রশ্নটি আবার আছে, তাই একবারে একটি query পড়েও উদ্দেশ্য বোঝা যাবে।

কঠিনতার মান easy, medium বা hard। এটি যুক্তির জটিলতা বোঝায়, চলতে কত সময় লাগবে তা নয়। কিছু প্রশ্নে খালি ফলই ঠিক। Query ভুল ধরার আগে ডেটা দেখে প্রয়োজনীয় সব সম্পর্ক আছে কি না ভাবো।

প্রতিটি ফলের চুক্তি স্পষ্ট করো

প্রতি কাজে কলাম, একটি row-এর অর্থ, duplicate নীতি, NULL-এর নিয়ম ও শেষ ordering লিখে রাখো। Row registration বোঝালে student_id ও section_id দুটোই পরিচয়ের অংশ। একটি কোর্সের একাধিক offering থাকায় course-level প্রশ্নে DISTINCT লাগতে পারে। সব শিক্ষার্থীসহ count চাইলে outer join বা সমতুল্য স্বাধীন count লাগবে।

SELECT requested_columns
FROM relevant_relations
WHERE row_conditions
GROUP BY grouping_identity
HAVING group_conditions
ORDER BY complete_display_order;

এই template একটি checklist; সব clause ব্যবহার বাধ্যতামূলক নয়। Scalar COUNT-এর display sort লাগে না। Window function-এর ordering তার গণনা নিয়ন্ত্রণ করে; row কীভাবে দেখাবে তা এখনও শেষ ORDER BY ঠিক করে।

Seed data দিয়ে অর্থ পরীক্ষা করো

তিনটি সীমার ঘটনা মনে রাখো। Student 108-এর enrollment নেই। Student 107 ভর্তি হয়েছে, ফল নেই। Section 36-এ কোনো enrollment নেই। ভালো report সব অনুপস্থিত সম্পর্ককে শূন্য নম্বর না বানিয়ে তিনটি আলাদা করে। অনুপস্থিত ফল অপেক্ষমাণ তথ্য, রেকর্ড করা ফেল নয়।

দেওয়া স্কেলে ৪০-এর নিচে F। Weighted report-এ grade_point ও course credit-এর গুণফল যোগ করে ফল থাকা credit দিয়ে ভাগ হয়। এখানে repeated-course replacement নেই ধরা হয়েছে। বাস্তব CGPA-তে এই formula নেওয়ার আগে retake, withdrawal ও incomplete grade-এর নীতি ঠিক করতে হবে।

Query 38-এর required course set আসে student 102 থেকে। Query 50 সব catalogued CSE course নেয়। CSE 121-এ registration না থাকায় শেষটির উত্তর বদলায়। দুটি division তুলনা করো: কাছাকাছি SQL দিয়েও প্রয়োজনের আলাদা জগতের উত্তর হয়।

প্রশ্ন, সমাধানের SQL ও চালিয়ে পাওয়া ফল

কাজ ১–১০: projection ও row filter

১. Identifier ক্রমে শিক্ষার্থীর identifier ও নাম দেখাও। সহজ। শুধু চাওয়া দুই কলাম নাও এবং display order স্পষ্ট করো।

২. Department identifier 1 দিয়ে CSE শিক্ষার্থীদের দেখাও। সহজ। Ordering-এর আগে filter করো; বিভাগের পরিচয় সংখ্যা, নামের অংশ নয়।

৩. যাদের hometown নেই খুঁজে বের করো। সহজ। অনুপস্থিত মানে IS NULL লাগে; NULL-এর সঙ্গে equality নয়।

৪. জানা hometown একবার করে দেখাও। সহজ। অনুপস্থিত মান ও duplicate আলাদাভাবে সরাও।

৫. A দিয়ে শুরু হওয়া শিক্ষার্থীর নাম খোঁজো। সহজ। Percent wildcard নামের বাকি অংশ মেলায়।

৬. অন্তত তিন credit-এর কোর্স দেখাও। সহজ। সংখ্যার credit তুলনা করো এবং unique code দিয়ে সাজাও।

৭. 60 থেকে 79 নম্বরের ফল দেখাও, দুই প্রান্তসহ। সহজ। BETWEEN নিচের ও ওপরের মান দুটোই রাখে।

৮. প্রথম ভর্তি হওয়া তিন শিক্ষার্থী দেখাও; তারিখ সমান হলে identifier নাও। সহজ। দ্বিতীয় ordering column limited subset নির্দিষ্ট করে।

৯. Hometown না থাকলে Unknown দেখাও। সহজ। COALESCE stored মান না বদলে display label দেয়।

১০. Half-open interval দিয়ে 2026 সালে ভর্তি শিক্ষার্থী দেখাও। সহজ। এতে দিনের শেষ সময় নিয়ে অনুমান লাগে না।

সমাধান ১–১০

ওপরের একই নম্বরের প্রশ্নের সঙ্গে query মেলাও। Query-র ক্রমে result table পড়ো। শুধু count মেলায় সন্তুষ্ট না হয়ে পরিচয়, অনুপস্থিত সম্পর্ক ও tie যাচাই করো।

কাজ ১১–২০: aggregate নিয়ে যুক্তি

১১. সব শিক্ষার্থী এবং জানা hometown আলাদা করে গোনো। মাঝারি। COUNT(column) NULL বাদ দেয়; COUNT(*) row গোনে।

১২. প্রতি department identifier-এ শিক্ষার্থী গোনো। মাঝারি। প্রতি grouped department একটি count দেয়।

১৩. রেকর্ড করা নম্বরের সর্বনিম্ন, সর্বোচ্চ ও দুই দশমিকের গড় বের করো। মাঝারি। শুধু থাকা ফল ধরবে; অপেক্ষমাণ ফল শূন্য নয়।

১৪. অন্তত তিন enrollment-এর section দেখাও। মাঝারি। HAVING তৈরি হওয়া enrollment group ছাঁকে।

১৫. 40 নম্বরের সীমা ধরে রেকর্ড করা ফলে pass ও fail গোনো। মাঝারি। Conditional aggregation বলা pass rule অনুযায়ী নম্বর ভাগ করে।

১৬. Generated grade অনুযায়ী result row গোনো। মাঝারি। Grade column shared scale থেকে তৈরি হয়।

১৭. প্রতি বিভাগের catalogued credit যোগ করো। মাঝারি। কোর্স catalogue-এর credit গুনবে, শিক্ষার্থীর অর্জিত credit নয়।

১৮. শিক্ষার্থীর গড় রেকর্ড করা নম্বর দেখাও; 70-এর নিচের গড় বাদ দাও। মাঝারি। Round করার আগের গড়ে filter দাও, শুধু display-তে round করো।

১৯. ফল আছে এমন আলাদা শিক্ষার্থীর সংখ্যা বের করো। মাঝারি। একই শিক্ষার্থীর একাধিক result row একবার ধরবে।

২০. প্রতি section-এর সর্বশেষ enrollment date বের করো। মাঝারি। এখানে তারিখ চাওয়া হয়েছে, group থেকে যেকোনো শিক্ষার্থী নয়।

সমাধান ১১–২০

ওপরের একই নম্বরের প্রশ্নের সঙ্গে query মেলাও। Query-র ক্রমে result table পড়ো। শুধু count মেলায় সন্তুষ্ট না হয়ে পরিচয়, অনুপস্থিত সম্পর্ক ও tie যাচাই করো।

কাজ ২১–৩০: সম্পর্ক ও অনুপস্থিত child

২১. প্রতিটি শিক্ষার্থীর পাশে department code দেখাও। মাঝারি। Foreign key-তে প্রতি student-এর একটি department match থাকে।

২২. প্রতি section-এর course code ও teacher name দেখাও। মাঝারি। দুটি parent join offering-এর পরিচয় না বাড়িয়ে তথ্য যোগ করে।

২৩. শূন্যসহ প্রতিটি শিক্ষার্থীর enrollment গোনো। মাঝারি। Non-NULL child column গুনলে Fahim-এর NULL-সহ row শূন্য যোগ করবে।

২৪. ফলের অপেক্ষায় থাকা enrollment দেখাও। মাঝারি। Join-এ result key-এর দুই কলামই চাই; child না থাকলে অপেক্ষমাণ কাজ বোঝায়।

২৫. প্রতিটি section-এর খালি আসন বের করো। মাঝারি। খালি section রাখো এবং প্রকৃত child count বিয়োগ করো।

২৬. Student 101-এর নেওয়া unique course code দেখাও। মাঝারি। DISTINCT course membership বোঝায়, offering কতবার এসেছে তা নয়।

২৭. কোনো enrollment নেই এমন teacher-সহ সবার enrollment গোনো। মাঝারি। এটি enrollment event-এর count; teacher-এর সব section মিলিয়ে distinct student নয়।

২৮. শিক্ষার্থীর নাম ও course code-এর পাশে রেকর্ড করা নম্বর দেখাও। মাঝারি। Report-এ composite result identity দৃশ্যমান রাখো।

২৯. কোনো section-এই enrollment নেই এমন course দেখাও। মাঝারি। সব offering-এ অনুপস্থিতি ও একটি খালি offering আলাদা।

৩০. একই জানা hometown-এর আলাদা student pair একবার করে দেখাও। মাঝারি। Identifier-এর less-than শর্ত নিজের সঙ্গে জোড়া ও উল্টো duplicate বাদ দেয়।

সমাধান ২১–৩০

ওপরের একই নম্বরের প্রশ্নের সঙ্গে query মেলাও। Query-র ক্রমে result table পড়ো। শুধু count মেলায় সন্তুষ্ট না হয়ে পরিচয়, অনুপস্থিত সম্পর্ক ও tie যাচাই করো।

কাজ ৩১–৪০: subquery ও সবার জন্য শর্ত

৩১. সব ফলের গড়ের চেয়ে বেশি নম্বরের ফল খোঁজো। কঠিন। Scalar aggregate সব result-এর জন্য একটি threshold দেয়।

৩২. নিজের section-এর গড়ের বেশি নম্বরের ফল খোঁজো। কঠিন। Correlation প্রতি তুলনায় সংশ্লিষ্ট section-এর গড় দেয়।

৩৩. NOT EXISTS দিয়ে enrollment নেই এমন student দেখাও। কঠিন। অন্য জায়গায় nullable মান থাকলেও NOT EXISTS নিরাপদ থাকে।

৩৪. অন্তত একটি 80 বা বেশি নম্বর আছে এমন course দেখাও। কঠিন। EXISTS duplicate course row ছাড়া membership বোঝায়।

৩৫. প্রতি section-এর সর্বোচ্চ নম্বরের সব tie ফেরত দাও। কঠিন। Section maximum-এর সমান শর্ত একটি বেছে না নিয়ে সব tie রাখে।

৩৬. Raw child join না করে teacher-এর চেয়ে student বেশি এমন department দেখাও। কঠিন। স্বাধীন count নিলে দুই child collection একে অন্যকে গুণ করে না।

৩৭. দুটি EXISTS দিয়ে course 21 ও 22 দুটোই নেওয়া student খোঁজো। কঠিন। প্রতিটি membership শর্ত নিজের course-এর যেকোনো offering মেলাতে পারে।

৩৮. Student 102-এর নেওয়া প্রতিটি course নিচ্ছে এমন student খোঁজো। কঠিন। Double NOT EXISTS course-level division করে; এখানে target set খালি নয়।

৩৯. অন্তত একটি enrollment আছে এবং প্রতিটি enrollment-এ passing result আছে এমন student খোঁজো। কঠিন। বাইরের EXISTS খালি history বাদ দেয়; অনুপস্থিত ফল অসম্পূর্ণ গণ্য হবে।

৪০. Department 1-এ আছে অথবা অন্তত 80 নম্বর পেয়েছে এমন student identifier একবার করে দাও। কঠিন। UNION দুই source-এর duplicate membership সরায়।

সমাধান ৩১–৪০

ওপরের একই নম্বরের প্রশ্নের সঙ্গে query মেলাও। Query-র ক্রমে result table পড়ো। শুধু count মেলায় সন্তুষ্ট না হয়ে পরিচয়, অনুপস্থিত সম্পর্ক ও tie যাচাই করো।

কাজ ৪১–৫০: window ও কয়েক ধাপের report

৪১. প্রতি section-এ নম্বরের rank করো; সমান নম্বরে rank সমান রাখো। কঠিন। শুধু নম্বর tie ঠিক করলে RANK-এর ordering-এ student_id দেবে না।

৪২. প্রতি student-এর ফল বেশি নম্বর আগে রেখে সাজাও; tie-তে section-id নাও। কঠিন। নির্দিষ্ট individual order পেতে ROW_NUMBER-এ unique tie-breaker লাগে।

৪৩. প্রতিটি ফল ও section mean থেকে তার পার্থক্য দুই দশমিকে দেখাও। কঠিন। Window result row রেখে section aggregate যোগ করে।

৪৪. CTE দিয়ে অন্তত তিন enrollment-এর section count দেখাও। কঠিন। বাইরের query নাম দেওয়া count stage ছাঁকে।

৪৫. প্রতি ভর্তি student-এর সর্বশেষ registration দেখাও; তারিখ tie হলে বড় section id নাও। কঠিন। Window হিসাব করা query-র বাইরে তার মান filter করো।

৪৬. প্রতি section-এর সর্বোচ্চ দুই distinct নম্বর দেখাও, dense rank দুইয়ের tie-সহ। কঠিন। DENSE_RANK আলাদা mark level গোনে; দুইয়ের বেশি student আসতে পারে।

৪৭. Date ও id ক্রমে ভর্তি শিক্ষার্থীর running count দেখাও। কঠিন। স্পষ্ট ROWS frame একই admission date-এর row-ও একে একে গোনে।

৪৮. খালি section-সহ প্রতিটির enrollment count সব section-এর গড় count-এর সঙ্গে তুলনা করো। কঠিন। আগে section অনুযায়ী aggregate করো, তারপর ছয়টি count-এর ওপর window নাও।

৪৯. রেকর্ড করা ফল আছে এমন student-এর credit-weighted grade point বের করো। কঠিন। Grade point-কে credit দিয়ে weight দাও; অপেক্ষমাণ ফল বাদ। Retake replacement এই ডেটাসেটের বাইরে।

৫০. Enrollment নেই এমন CSE course-সহ catalogue-এর সব CSE course নেওয়া student দেখাও। কঠিন। CSE 121-এ কেউ ভর্তি নয়, তাই ঠিক উত্তর খালি। Required course set-ই খালি হলে division vacuously true হতো।

সমাধান ৪১–৫০

ওপরের একই নম্বরের প্রশ্নের সঙ্গে query মেলাও। Query-র ক্রমে result table পড়ো। শুধু count মেলায় সন্তুষ্ট না হয়ে পরিচয়, অনুপস্থিত সম্পর্ক ও tie যাচাই করো।

Syntax বদলানোর আগে প্রশ্নের অর্থ পরীক্ষা করো

NULL-দিয়ে বাড়ানো row গোনা

LEFT JOIN-এর পরে COUNT(*) child-হীন student-এর জন্যও এক গুনতে পারে। COUNT(e.section_id) প্রকৃত enrollment match গোনে। শূন্যসহ enrollment count চাইলে child key নাও।

Result join-এ key-এর একটি কলাম নেওয়া

এক শিক্ষার্থীর একাধিক section-এ নম্বর থাকতে পারে। Enrollment-এর সঙ্গে result দুই identifier দিয়েই join করো, নইলে অন্য ফল ভুল registration-এ জুড়বে। Report-এর সব ধাপে composite identity রাখতে হবে।

একই WHERE-এ rank ছাঁকা

নিজের query block-এর window value তৈরি হওয়ার আগেই WHERE চলে। CTE বা derived table-এ rank বের করে বাইরে filter করো। Tie-এর নীতি অনুযায়ী RANK, DENSE_RANK বা ROW_NUMBER নাও।

Shared MySQL baseline ব্যবহার করো

উত্তরগুলো MySQL 8-এর window ও CTE নেয়; native INTERSECT বা EXCEPT লাগে না। স্কিমার CHECK constraint-এর জন্য MySQL 8.0.16 বা নতুন লাগে। Query shared row বদলায় না, তাই বারবার চেষ্টার ফল তুলনা করা যায়।

প্রতি row কেন রইল বোঝাও

সমাধানের পর একটি ফেরত আসা ও একটি বাদ পড়া row-এর membership rule বোঝাও। খালি উত্তরে কোন requirement মেলেনি বলো। SQL-এর সঙ্গে ডিজাইন ও transaction-এর প্রমাণ মেলাতে সমাধানসহ DBMS পরীক্ষার প্রশ্ন পড়ো।
