Attempt fifty queries before reading their answers

Use the university dataset to practise complete questions rather than isolated keywords. The fifty tasks below progress from easy projections to harder reports with several reasoning steps. Write a query first, predict which student or section identities should appear, then compare your answer with the worked SQL and its result.

The five answer groups each contain ten numbered queries in the same order as their questions. Every group starts from the unchanged university data. A result table belongs to the next numbered query in that group. The source comments repeat each question so you can study one query at a time without losing its purpose.

Difficulty is marked easy, medium or hard. The rating describes the reasoning load, not the required execution time. Empty answers are valid for some questions. Before assuming that a query is broken, inspect the data and ask whether every required relationship exists.

State the contract for each result

For every task, write down the requested columns, one-row meaning, duplicate policy, NULL rule and final ordering. When a result row represents a registration, its identity includes student_id and section_id. A course-level question may need DISTINCT because one course can have several offerings. A student-preserving count needs an outer join or an equivalent independent count.

SELECT requested_columns
FROM relevant_relations
WHERE row_conditions
GROUP BY grouping_identity
HAVING group_conditions
ORDER BY complete_display_order;

This template is a checklist, not a requirement to use every clause. A scalar COUNT does not need a display sort. A window function’s ordering controls its calculation; the final ORDER BY still controls how rows are shown.

Use the seed data to test the meaning

Keep three boundary cases in view. Student 108 has no enrollment. Student 107 has an enrollment but no result. Section 36 has no enrollments. A good report distinguishes all three instead of turning each missing relationship into a zero mark. The absent result is pending information, not a recorded failure.

The recorded grade scale treats marks below 40 as F. Weighted grade reports sum grade_point times course credits and divide by the credits with recorded results. This practice assumes no repeated-course replacement. A production CGPA policy must define how retakes, withdrawals and incomplete grades are treated before copying the formula.

For query 38, the required course set comes from student 102. Query 50 uses every catalogued CSE course instead. The empty registration history of CSE 121 changes the latter answer. Compare these two divisions carefully: similar SQL can answer different universes of requirements.

Debug the question before changing syntax

Counting the null-extended row

COUNT(*) after a LEFT JOIN can count one row for a student with no child. COUNT(e.section_id) counts actual enrollment matches. Use the child key when the question asks for zero-inclusive enrollment counts.

Joining results on only one key column

A student can have marks in several sections. Join results to enrollments on both identifiers, or unrelated results can attach to the wrong registration. Composite identity must survive every report stage.

Filtering a rank in the same WHERE

WHERE is evaluated before the window values of its query block exist. Use a CTE or derived table to compute the rank, then filter it outside. Choose RANK, DENSE_RANK or ROW_NUMBER according to the intended tie policy.

Use the shared MySQL baseline

These answers use MySQL 8 windows and CTEs but do not require native INTERSECT or EXCEPT. The schema’s CHECK constraints require MySQL 8.0.16 or newer. Queries avoid changing shared rows, making their answers comparable across attempts.
