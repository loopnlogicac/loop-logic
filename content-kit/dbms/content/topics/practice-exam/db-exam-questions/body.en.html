Design and relational queries

1. Design a Chen ER model for students, sections and repeated offerings of courses; map enrollment and results to tables.

Marks: 10.

[Student] M --- <Enrolls> --- N [Section]
                   |               | N
             (enrolled_on)      <Offers>
                                   | 1
                                [Course]

Student has underlined student_id, Course has underlined course_id, and Section has underlined section_id. Each section offers exactly one course; a course can have several sections. Enrollment is optional for both a student and a section. Attach enrolled_on to the Enrolls relationship. In a full Chen drawing, entities use rectangles, relationships diamonds and attributes ovals.

Map Student and Course to their own tables. Section stores course_id as a non-NULL foreign key. Map the M:N relationship to Enrollment(student_id,section_id,enrolled_on), with the two identifiers as its key and foreign keys to their parents. Map Result(student_id,section_id,marks) with the same primary key and a composite foreign key to Enrollment. A result is optional for an enrollment. This permits another offering of the same course without confusing its registration identity.

3. Write relational algebra and SQL for names of students enrolled in section 31, and show the actual answer.

Marks: 8.

Select the relevant registrations, join them to students by student_id, then project names. The relational expression is πstudent_name(Students ⋈Students.student_id=Enrollment.student_id σsection_id=31(Enrollment)). The SQL below also displays student identity so distinct people with equal names remain distinguishable. A literal name-only set projection would use SELECT DISTINCT student_name.

SELECT s.student_id, s.student_name FROM students AS s
JOIN enrollments AS e ON e.student_id=s.student_id
WHERE e.section_id=31 ORDER BY s.student_id;

4. Report enrollment counts for every section, including empty sections. Explain the COUNT choice.

Marks: 8.

Start from sections and preserve them with LEFT JOIN. Group by the section key. COUNT(e.student_id) counts actual matching registrations because that child key cannot be NULL in a real enrollment. For section 36 the outer join produces a null-extended row, so the child count is zero. COUNT(*) would instead count that row as one.

SELECT se.section_id, COUNT(e.student_id) AS registrations
FROM sections AS se LEFT JOIN enrollments AS e ON e.section_id=se.section_id
GROUP BY se.section_id ORDER BY se.section_id;

Dependencies and normal forms

5. For R(S,C,N,T,M), F={S → N,C → T,SC → M}, find all candidate keys and decompose from 1NF to 3NF.

Marks: 10.

Neither S nor C appears on an FD right side, so every key contains both. SC+ starts SC, adds N through S → N, T through C → T and M through SC → M. Thus SC is the only candidate key. N, T and M are nonprime. Assume one scalar value per cell, so the starting relation is 1NF.

S → N and C → T depend on proper subsets of SC, violating 2NF. Decompose into Student(S,N), Course(C,T) and Registration(S,C,M). Their keys are S, C and SC respectively. Every nontrivial projected determinant is a key, so all three are BCNF and therefore 3NF. The Student split shares S, which determines SN; the Course split shares C, which determines CT. Both steps are lossless. Each original FD is local to one component, so the design also preserves dependencies.

6. R(A,B,C) has only A → B. Test the split AB,BC and exhibit a counterexample if it is lossy.

Marks: 8.

The common heading is B. Its closure is just B, so it determines neither AB nor BC. Therefore the binary lossless criterion fails. Choose r={(a1,b,c1),(a2,b,c2)}. It obeys A → B. Its AB projection has (a1,b),(a2,b), and its BC projection has (b,c1),(b,c2). Joining gives the two original rows plus (a1,b,c2),(a2,b,c1). The added tuples prove that the split loses the association between A and C.

7. For R(S,C,I) and SC → I,I → C, compare 3NF and BCNF and discuss the IC,SI split.

Marks: 10.

S is required in every key, and either C or I completes it. The keys are SC and SI, making all three attributes prime. SC → I has a superkey left side; I → C has a prime right side. Both pass 3NF. I+ is IC, which misses S, so I → C violates BCNF.

Split on I → C into IC and SI. Common I determines the IC component, proving losslessness. The projected nontrivial FD union contributes I → C only. SC+ under that union cannot obtain I, so SC → I is not preserved locally. A valid implementation must address that missing enforcement or choose a preserving 3NF design.

Schedules, recovery and secure access

8. Determine conflict serialisability of r1(X),r2(Y),w1(X),r2(X),w2(Y), and draw the graph.

Marks: 6.

T1 ----> T2

The X pairs r1(X) before r2(X) are read-read and add no edge. The pair w1(X) before r2(X) adds T1 → T2. T1 never touches Y, so no reverse edge comes from Y. The graph is acyclic; T1,T2 is a topological ordering and an equivalent serial order. The interleaving itself need not be serial to be conflict-serialisable.

9. A locks account 1, B locks account 2, then each requests the other account. Explain detection, retry and prevention.

Marks: 8.

A --waits for--> B
A <--waits for-- B

The circular wait is a deadlock. With InnoDB detection enabled, the engine selects a transaction victim, rolls it back and returns error 1213. The application retries the complete business unit with bounded attempts and an idempotent request identity. The victim is not guaranteed to be the most recent requester. Requesting both account locks in a common identifier order reduces this cycle. A lock timeout has a different rollback boundary and must also be handled explicitly.

10. A committed transfer changes wallets from 1000/500 to 900/600. A later uncommitted edit changes the first wallet to 1 before a crash. Explain recovery and the final state.

Marks: 8.

The transfer is committed and must survive within the configured durability guarantees. The later edit is uncommitted and must not survive as committed data. Recovery can replay required logged page changes, then undo uncommitted effects according to the engine protocol. The final logical state is 900/600. A checkpoint can reduce redo work but does not commit the second transaction. Separate backups are still needed for lost files or media.

11. A student search concatenates a quoted input into SQL. Explain the flaw and show a bound-value alternative.

Marks: 8.

A crafted value can end the intended literal and introduce an operator or comment, changing which rows the predicate accepts. Prepare a fixed statement with a value placeholder, bind the name, execute it and deallocate the statement. The text then remains a value. In an application use the connector’s parameter API, retain least privilege and separately authorise which student records the caller may view.

PREPARE search FROM 'SELECT COUNT(*) AS matches FROM students WHERE student_name=?';
SET @name='Ayesha Rahman';
EXECUTE search USING @name;
DEALLOCATE PREPARE search;

12. Explain why InnoDB REPEATABLE READ is not a general proof that every multi-row invariant is serialised.

Marks: 8.

Consistent reads use an established snapshot, while writes and locking reads use current versions and locks. Two transactions can read the same invariant condition but update disjoint rows, allowing write skew unless the condition is protected. A stable snapshot therefore does not prove equivalence to a serial order for every workload. Identify the invariant, use appropriate shared locking or constraints, or choose serialisable execution, and test competing transactions.
