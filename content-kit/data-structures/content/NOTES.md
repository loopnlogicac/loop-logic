## Reviewer attention

- Address numericals state their element widths; C does not guarantee four-byte int. Runtime examples avoid unstable pointer addresses and platform-specific byte-size output.
- The vector deliberately supports at most 1024 reserved slots. Its arithmetic is safe under that bound; it is not presented as an unrestricted production vector. Optional shrink failure preserves a valid smaller sequence in the existing allocation.
- The dynamic-array lab illustrates a moving realloc and counts the corresponding copies. A real allocator may extend in place; the lesson explains this distinction.
- Array lab spare cells are rendered as null. C deletion only changes the logical size; it need not erase the old final cell. Comparisons use the live sequence, not spare bytes.
- List labs show endpoint markers for orientation. A visual tail does not imply that the head-only C helpers gain constant-time tail access. The doubly linked round trip inserts 64 after head and then removes that same node, including the empty/singleton cases.
- Floyd's out-of-length entry selector leaves the chain acyclic in both the lab and C example. The player variable uses numeric 0/1, matching C's result. Distinct equal-valued nodes are not mistaken for a cycle.
- Middle selection intentionally chooses the later middle for even lengths. Positions from the end are one-based. Merge inputs are disjoint and transfer ownership; polynomial addition instead creates independent result nodes.
- Polynomial input limits are eight raw terms, coefficient magnitude at most nine and exponents 0..9. Multiplication collects equal exponents through sorted insertion, so its stated complexity includes result-list scans.
