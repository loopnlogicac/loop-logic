Introduction

A circular linked list joins its final node back to its first node. Think of students taking turns around a table. After the final seat, the next turn belongs to the first seat again. There is no natural NULL at the end of a nonempty round.

This shape supports repeated turns, rotating schedules and elimination problems. It also changes traversal and release rules. A loop that waits for NULL will never complete on an intact circle. You need a remembered starting node or an explicit count to stop after one lap.

This lesson stores only tail for the circular operations. Since tail->next is head, that one pointer gives direct access to both ends of the logical sequence. You will build a circle, insert at its front, rotate its starting point and solve a small Josephus elimination.

Representation and rules

In a singly circular list, each node still has one next field. The tail’s next points at head. Empty storage uses tail=NULL. A singleton points its next to itself, because its successor after one turn is the same participant.

With tail retained, head is derived as tail->next. To insert at head, set node->next=tail->next, then tail->next=node. The stored tail stays the same for a nonempty circle. To append at tail, make those same links and then set tail=node. Both updates take a fixed amount of link work.

Nonempty singly circular:
head = tail.next
  +--------------------------------+
  v                                |
A[12] --> B[24] --> C[36] --> tail.next
                    tail=C

Singleton: tail --> A[7]
                    A.next=A

A doubly circular list adds prev and wraps in both directions. head.prev=tail and tail.next=head. A singleton has next and prev both pointing to itself. The ordinary doubly linked endpoint checks from the previous lesson must be adapted because boundary neighbors now exist through wrap links.

One-lap printing first guards tail!=NULL. Save head=tail->next, set cur=head, print and advance in a do-while loop, then stop when cur==head. Comparing addresses is essential: duplicate values do not tell you whether a complete lap has occurred.

Follow the memory

The examples first build a linear chain, find its final node and connect tail->next=head. This preparation makes the change from an ordinary list visible. Empty input returns no tail and performs no link update.

Before closing:
head --> A[12] --> B[24] --> C[36] --> NULL

After closing:
A --> B --> C --> A
head=A       tail=C

For head insertion of 64 into a circle starting at 72, prepare the new node’s next as the old head. Redirect tail->next to the new node. The first visible value changes, but the old tail remains the endpoint that identifies the first node through its next.

Before: tail=C; C.next=A
A[72] --> B[85] --> C[91] --> A

Prepare N[64].next=A
Publish C.next=N
After: N[64] --> A[72] --> B[85] --> C[91] --> N

An empty insertion needs a separate case. Set node->next=node and tail=node. There is no old first node to preserve. This self-link makes the same one-lap printing routine visit the singleton exactly once.

Rotating the logical starting point can be cheaper than moving values. Advancing tail one link also advances the derived head one link. The node relationships stay circular and unchanged. Repeating that step changes which participant is considered first without allocating or freeing anything.

Josephus repeatedly counts a fixed number of participants and removes the selected one. Here the current node counts as one. Keep cur and its predecessor prev. Advance both step-1 times, save next=cur->next, bypass cur with prev->next=next, free cur and restart at next.

Labels 1,2,3,4,5; step=2
1 --> 2 --> 3 --> 4 --> 5 --> 1
Remove 2: 1 --> 3 --> 4 --> 5 --> 1
Remove 4: 1 --> 3 --> 5 --> 1
Remove 1: 3 --> 5 --> 3
Remove 5: 3 --> 3
Survivor: 3

The elimination routine owns the circle while it runs. It releases every removed node and finally releases the survivor after saving its label. The caller must not destroy or traverse the old head or tail afterward. Those former pointers may identify nodes whose lifetimes already ended.

Doubly circular before inserting N between tail C and head A:
C.next=A; A.prev=C

After: C.next=N; N.prev=C; N.next=A; A.prev=N
New head=N; tail=C

Delete N: C.next=A; A.prev=C; free N
The original two-way wrap is restored.

Each completed circular doubly linked update must preserve both wrap links. This is the circular counterpart of the ordinary doubly linked neighbor rule.

Examples

Traverse exactly one lap

The do-while visits head once before checking whether it has returned. An empty circle needs a separate guard.

Insert at the front using only tail

tail->next identifies head, so inserting after tail makes a new head. For an empty list the first node points to itself.

Josephus: count two, remove one

Counting starts at head and includes the current node. After each removal, counting restarts at its successor; five labels leave label 3.

Costs and boundary cases

One full circular traversal takes Theta(n) time and O(1) auxiliary pointers. Head or tail insertion with tail retained takes O(1) link work and adds one node. Constructing a circle from an existing linear chain takes O(n) to find its tail unless that endpoint is already known.

Deleting head with tail retained takes O(1), including the singleton case. Deleting tail in a singly circular list generally needs its predecessor, which takes O(n) to locate. A doubly circular list can obtain that predecessor through prev when the node is known, making its local deletion O(1).

For Josephus, this direct implementation advances up to step-1 links before each of n-1 removals. Its time is O(n*step), and its auxiliary space is O(1) beyond the existing nodes. With fixed step two, the elimination work is linear. A separate mathematical recurrence can find only the survivor more efficiently for large steps, but does not show the removal sequence.

Empty printing produces no labels. Empty Josephus returns -1 as this program’s chosen marker. A singleton survives immediately and is then freed. For ordinary whole-circle destruction, save head and break tail->next=NULL before using the linear destroy helper.

Common mistakes

Waiting for NULL in an intact circle

A valid circular link never reaches NULL. Save the starting address and stop when you return to it. A do-while gives a singleton its one required visit.

Stopping at a repeated value

Two participants can share a stored value. Their addresses still identify different nodes. Compare node identity when deciding whether the lap is complete.

Using linear destruction without breaking the circle

The walk can reach storage it already freed. Cut one wrap link first, or remove nodes with a carefully maintained circular invariant.

Changing Josephus counting conventions halfway

Counting the successor as one gives a different elimination order. State that cur counts as one and restart at the saved successor after each removal.

A circular doubly linked deletion makes the wrap rule concrete. Given a known node cur in a circle with at least two nodes, connect cur->prev->next to cur->next and cur->next->prev to cur->prev. If cur is the retained tail, move tail to cur->prev before freeing it. For a singleton, clear tail instead, because its predecessor and successor are the victim itself. Forward and backward laps should then visit the same surviving identities in opposite orders.

Working habits

Draw the wrap edge even when it makes the picture less tidy. A chain drawing with no visible final edge can hide the difference between a circle and a linear list. For a doubly circular drawing, include both wrap relationships.

Keep ownership of an elimination routine explicit. Once it consumes and frees the participants, old endpoint variables are no longer usable. Returning the survivor label rather than its freed pointer makes that interface clear.

Try step one, a singleton and an empty circle before longer Josephus traces. Step one removes the current participant immediately, exercising a different movement pattern from step two. Distinct node identities also let you test circles with equal stored labels without confusing termination.

C version notes

These circle routines use C17 allocation and pointer semantics. A self-link is valid when it refers to a live node of the same type. It does not make free follow links automatically; allocation release remains an explicit responsibility of the program.

Summary

A circular structure replaces a missing end with a wrap relationship. Use node identity to finish a lap and preserve the predecessor during elimination. Next, combine pointer techniques in Classic Linked List Problems.
