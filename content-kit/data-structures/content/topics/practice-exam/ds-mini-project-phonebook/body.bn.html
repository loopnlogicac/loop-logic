Structure মিলিয়ে সম্পূর্ণ প্রোগ্রাম

Phone book list operation-কে ছোট app বানায়। Contact যোগ, নামে খোঁজা, মুছে ফেলা, sort আর পরের session-এর জন্য save করবে। Menu কাজগুলো জুড়বে, প্রতিটি command নিজের মতো মেমরি rule বানাবে না।

প্রতি contact node নিজের name অ্যারে, phone অ্যারে আর next পয়েন্টার রাখে। Head পুরো chain-এর মালিক। নাম unique, case-sensitive তুলনা: ContactA আর contacta আলাদা key। সব উদাহরণ কাল্পনিক লেবেল, ব্যক্তিগত record নয়।

Phone number text। 01700000001 integer করলে শুরুর zero হারায়; optional plus-ও পরিচয়ের অংশ। এখানে এক থেকে ষোলো phone character: digit, শুরুতে optional plus। নামে এক থেকে চব্বিশ ASCII letter, digit বা underscore। সর্বোচ্চ বত্রিশ contact উদাহরণ সীমিত রাখে।

Menu-র আগে command contract

Menu একবারে পুরো line পড়ে। A name-phone যোগ, F নামে খোঁজে, D মুছে, S sort, L list, W contacts.txt লেখে, R সেই ফাইল reload, Q quit। EOF-ও session শেষ করে সব contact ছাড়ে। Command letter uppercase।

ইনপুটঅর্থResponse
A ContactA 0017Unique contact যোগadded, rejected বা no মেমরি
F ContactAExact name lookupName আর phone, বা not found
D ContactAExact match সরানোdeleted বা not found
Sstrcmp-তে নাম sortsorted
Lবর্তমান ক্রম প্রিন্টcontacts: তারপর শূন্য বা বেশি row
W or RSave বা loadsaved/loaded বা failure message
QRun শেষবাড়তি row নেই

Field limit দেখার আগে গ্রহণযোগ্য পুরো line ধরার মতো buffer-এ parser পড়ে। কাটা name নীরবে অন্য বৈধ contact হবে না। Extra টোকেন command invalid করে। Buffer-এর বড় line drain করে invalid line জানায়, যাতে বাকি byte দ্বিতীয় command না হয়।

Working directory-র local contacts.txt ব্যবহার হয়। Scratch folder-এ চালাও, কারণ W write mode-এ আগের content বদলে দেয়। ফাইলে space দিয়ে আলাদা name-phone pair, প্রতি line-এ এক contact। এই format-এ নামে space নেই; quoted বহু-শব্দের নাম চাইলে অন্য parser লাগবে।

Edit আর sort-এ ownership রাখো

Add আগে field rule, distinct name আর contact limit দেখে, তারপর allocate। সফল হলে bounded text node-এ copy করে head-এ ঢোকায়। Allocation failure-এ list বদলায় না। Search strcmp equality বা chain-এর শেষ পর্যন্ত next ধরে।

Deletion incoming link-এর পয়েন্টার ধরে হাঁটে। Link head বা আগের node-এর next field হতে পারে। Matched node-এর successor দিয়ে বদলে owning chain থেকে record সরায়, তারপর free। নাম না পেলে কিছু বদলায় না।

ContactA যোগের আগে:
head -> [ContactB | 01700000002 | NULL]
যোগের পরে:
head -> [ContactA | +8801700000001 | next] -> [ContactB | ... | NULL]
ContactA মুছলে:
head -----------------------------------> [ContactB | ... | NULL]
সরানো ContactA allocation ছাড়া হয়।

Sort বারবার মূল chain থেকে পরের node নিয়ে আলাদা sorted chain-এ বসায়। নাম তুলনা করে জায়গা খুঁজে দুই link ঠিক করে। Contact text বিনিময় বা নতুন node allocation হয় না। মূল chain ফাঁকা হলে head sorted chain পায়।

Insertion-sort নকশা O(n squared) সময় আর বাড়তি O(1) পয়েন্টার নেয়। Search, delete আর duplicate-checking add worst case O(n)। List আর save-এ O(n) record visit, সঙ্গে লেখা text-এর পরিমাণ। প্রতি record-এ fixed অ্যারে-সহ মোট owned storage O(n)।

Edit আর ফাইল round-trip চালাও

পুরো contact menu চালাও

নাম unique, case-sensitive। Sort link বদলায়, phone-এ zero আর optional plus থাকে।

List save, বদল আর reload

বর্তমান folder-এর contacts.txt-এ sorted row save হয়। Load ক্রম বানিয়ে deleted contact ফেরায়। W ফাইল বদলায় বলে scratch folder নাও।

Temporary list-এ load

Save বর্তমান list order-এ contact লেখে। প্রতিটি fprintf আর শেষ fclose দেখে, কারণ buffered আউটপুট close-এ ব্যর্থ হতে পারে। সফল W saved বলে। Empty list empty ফাইল বানায়, সেটি বৈধ saved phone book।

Save-এর চেয়ে load-এর rollback শক্ত। R ফাইল খুলে bounded পুরো row parse করে validated record temporary list-এ যোগ করে। ভুল field, duplicate name, বেশি record, read error বা allocation failure load reject করে। Temporary list ছাড়া হয়, edited in-মেমরি list অক্ষত।

Front insertion temporary তৈরিতে ফাইল order উল্টায়। সব row আর ফাইল close সফল হলে loader সেটি আবার উল্টায়। তারপর আগের list free করে restored head প্রকাশ করে। এতে disk-এ saved order থাকে, ফাইল আগে থেকেই sorted বলা হয় না।

W ইচ্ছা করে portable basic save, atomic storage transaction নয়। w-তে খোলাই পরের write শেষের আগে পুরোনো ফাইল truncate করে। Failed write-এ partial content থাকতে পারে, মেমরি contact তবু আছে। শক্ত app temporary ফাইল লিখে completion দেখে সফল হলে original বদলায়; power-loss durability-তে platform support-ও লাগে।

দ্বিতীয় উদাহরণ read-এর আগে write করে, তাই আগের contacts.txt-এ নির্ভর নয়। Sorted record save, মেমরি থেকে একটিকে delete, reload আর restored row list করে। Practice-ও read-এর আগে ফাইল বানায়। Malformed-load পরীক্ষা করতে মেমরি-তে contact রেখে ফাইলে খারাপ row দাও, R আর L দিয়ে rollback দেখো।

Menu-র সীমা পরীক্ষা

Empty list-এ search, delete, sort, list আর save চলে। Search-delete not found, sort empty head, list শুধু heading। শেষ contact মুছলে head NULL। Duplicate add নীরবে phone overwrite না করে reject।

strcpy-র আগে length দেখা হয় বলে valid name node অ্যারে overflow করে না। Phone-এ শুধু plus, মাঝের punctuation আর ষোলোর বেশি character বাদ। 001-এর মতো সংখ্যার শুরুর zero থাকে। উদাহরণ byte-oriented ASCII validation, Unicode name policy নয়।

Rejected add বা malformed command-এর পরে menu চলে, কারণ partial contact link হয়নি। ফাইল load-এও বত্রিশ record সীমা। Q না থাকলেও EOF exit, final cleanup প্রতিটি বাকি node দেখে। সফল আর rejected দুই load-এই handle close।

Linked list edit আর শেখায় সহজ, exact-name search linear। বড় phone book hash index বা balanced ট্রি যোগ করতে পারে, তবে প্রতিটি contact-এর owner একজন স্পষ্ট থাকবে। একাধিক index update-এ consistent success-or-rollback policy, বিশেষ করে allocation failure-এ দরকার।

প্রতি temporary add আগের নাম scan করে duplicate দেখে বলে n contact load O(n squared)। Edited আর new list একসঙ্গে own করে, তাই peak storage দুই set ধরে। Sort node-এর বাইরে শুধু link ভেরিয়েবল নেয়। বড় app-এ temporary name index repeated duplicate search কমাতে পারে।

Sort-এর আগে:
head -> [ContactC] -> [ContactA] -> [ContactB] -> NULL
Relink করে sort-এর পরে:
head -> [ContactA] -> [ContactB] -> [ContactC] -> NULL
সফল load-এর আগে:
live head -> edited record    temporary head -> parsed record
Commit-এর পরে:
live head -> restored parsed record; পুরোনো edited record ছাড়া
Rejected load-এ:
live head -> আগের edited record; temporary record ছাড়া

Interface বদলানোর আগে ডেটা রক্ষা

সরাসরি live head-এ load

পরের খারাপ row অর্ধেক phone book রেখে দেবে। আলাদা বানিয়ে পুরো load সফল হলেই live list বদলাও।

সীমাহীন string ইনপুট

লম্বা টোকেন node field overwrite করতে পারে। Bounded line পড়ে পুরো টোকেন length যাচাই, contract মিললেই copy।

Save failure পুরোনো disk ফাইল রাখে ভাবা

Basic writer error জানায়, truncation ফেরাতে পারে না। নিরাপদ replacement নকশায় সীমাটা মনে রাখো।

ছোট app দিয়ে ownership পরীক্ষা

Phone book এক menu-তে list edit, sort, ইনপুট validation আর ফাইল lifetime মেলায়। প্রতিটি command বৈধ list রাখে বা সম্পূর্ণ নতুনটি প্রকাশ করে। শেষে interview question দিয়ে পছন্দগুলো মুখে বোঝাও।
