Practice explaining before reading answers

Treat an exam answer as a small explanation that someone else can follow. Begin with the representation, show the requested state changes, and finish with the result and its cost. A correct final array without its movement steps may not answer a tracing question.

The chapters below cover arrays and addresses, linked lists, stacks, queues, trees, hashing and graphs. Each question includes a full answer. Try a question on paper before reading its solution, then compare intermediate states rather than only the final numbers. All address calculations specify element width explicitly; they do not assume every machine gives int the same size.

For a timed practice session, choose one array question, one pointer question, one tree trace and one graph question. Allow time to label diagrams and check empty or missing-element cases. For complexity answers, state whether the bound is worst case, expected or amortized. Explain the representation that makes the bound true.

Arrays

1. Arrays (5 marks): A[3][4] is row-major, base address 1000, width four bytes, zero-based. Find A[2][1].

The element offset is 2*4+1=9. The byte offset is 9*4=36. Therefore the address is 1036. The array contains twelve elements, so the index is valid. A column-major interpretation would instead use 1*3+2=5 elements and address 1020.

2. Arrays and complexity (5 marks): insert at position 1 in [4,8,12,16], with spare capacity. Show movement and cost.

Move 16 from index 3 to 4, 12 from 2 to 3, and 8 from 1 to 2. Write the new value, say 6, at index 1. The result is [4,6,8,12,16]. Right-to-left movement avoids overwriting unread values. Three shifts are required here; general worst-case insertion is O(n) time with O(1) auxiliary space.

Lists

3. Linked lists (6 marks): head points to 5 -&gt; 9 -&gt; 12. Delete 9. Write the essential pointer actions.

Locate prev at node 5 and cur at node 9. Save cur next, set prev next to node 12, then free cur. The result is 5 -> 12 -> NULL. If cur were the head, update head instead; a pointer-to-pointer loop can handle both cases. Searching is O(n); unlinking a known incoming link is O(1).

Stacks

4. Stacks (5 marks): push 3, push 7, pop, push 2, peek. Give all states and returned values.

Starting at [], push 3 gives [3], push 7 gives [3,7], pop returns 7 and leaves [3], push 2 gives [3,2], and peek returns 2 without changing it. The right end is top. Each array operation is O(1) with enough capacity; a pop on the initial empty stack would be underflow.

Queues

5. Queues (6 marks): capacity four, count zero, front zero. Enqueue 10,20,30; dequeue twice; enqueue 40,50,60. Give final physical cells and logical order.

Cells evolve to [50,60,30,40]. Front is 2 and count is 4. The active logical order is [30,40,50,60], wrapping through indices 2,3,0,1. A count field distinguishes full from empty even when a next-insertion index meets front. The two dequeues return 10 and 20.

Trees

6. Trees (6 marks): insert 8,3,10,1,6,9,14 into a BST, then delete 8 using its successor. Give the new tree and traversals.

The successor is 9, the minimum of the right subtree. Copy 9 to the root and remove the old leaf 9 under node 10. Root 9 has left 3 with children 1 and 6, and right 10 with right child 14. Inorder is 1,3,6,9,10,14. Preorder is 9,3,1,6,10,14.

Heaps

7. Heaps (5 marks): insert 12 into max-heap [10,7,8,3,5]. Show swaps.

Append 12 at index 5, whose parent is index 2 holding 8. Swap to obtain [10,7,12,3,5,8]. The new parent is index 0 holding 10; swap again to obtain [12,7,10,3,5,8]. The complete shape remains valid, and every parent is at least its children. Sift-up takes O(log n) time.

Hashing

8. Hashing (6 marks): modulus seven, front-insert 1,8,15 in a chained table. Delete 8. Contrast linear probing.

Chaining puts bucket 1 at 15 -> 8 -> 1. Deleting 8 links 15 directly to 1 and frees 8. Linear probing instead puts the keys in slots 1,2,3. Deleting 8 must leave a tombstone at slot 2 so searching for 15 can pass it. Both schemes have O(n) worst-case searches.

Graphs

9. Graphs (6 marks): undirected edges 0-1,0-2,1-3,1-4,2-4,3-5,4-5 and isolated vertex 6. Give BFS from 0 with ascending neighbors.

Queue expansion yields order 0,1,2,3,4,5. Distances are [0,1,1,2,2,3,-1]. Parents are [-1,0,0,1,1,3,-1]. The parent path to 5 is 0,1,3,5. Vertex 6 remains outside the BFS tree. Listing neighbors once gives O(V+E) traversal time.

10. Graphs (5 marks): compare BFS and DFS when finding a minimum-hop route and detecting all components.

BFS is appropriate for minimum-hop routes in an unweighted graph because its queue processes layers. DFS does not guarantee minimum hops. Either traversal can count undirected components by starting a new search at every unseen vertex. With adjacency lists both take O(V+E) time; the queue or DFS stack can need O(V) extra space.

Union-Find

11. Union-find (5 marks): union(0,1), union(2,3), union(0,2), find(3), using size and first-root ties.

Parents become [0,0,2,2], then [0,0,0,2]. The final find follows 3 to 2 to 0 and compresses parent[3] to zero. Final parents are [0,0,0,0], with root size four. A repeated union(1,3) changes neither size nor the number of components.

Design

12. Design (8 marks): store sparse city connections, check connectivity repeatedly as roads are added, and sometimes recover a shortest-hop route.

Use adjacency lists to retain actual road neighbors, costing O(V+E) records. Add each undirected road to both lists. Maintain union-find for repeated same-component queries as roads arrive. For a route, run BFS with parent links on the adjacency lists. Union-find alone lacks the edge history needed for route reconstruction. Deletions require a different strategy or rebuilding connectivity.

Check assumptions before quoting a result

A complexity label needs a representation and an operation. Matrix traversal scans absent connections too; adjacency-list traversal does not. A BST can be a chain, and a hash function can place many keys into one bucket. State the conditions that allow a faster average or amortized claim.

For pointer traces, distinguish an allocated record from the link that owns it. Repair incoming links before release, and never use a freed node as the next traversal step. For graph traces, specify source and neighbor order; use a separate unreachable marker instead of inventing a route.

Turn a memorized fact into a reason

After each answer, change one assumption and predict the effect. Try a full queue, a duplicate key, a missing contact or a disconnected vertex. Revisit complexity basics whenever two answers appear to use the same cost word for different guarantees.
