উত্তর পড়ার আগে বোঝানোর চর্চা

Interview-তে operation-এর সঙ্গে মেমরি layout আর শর্ত মেলাও। আগে key search লাগলে শুধু list deletion constant time বলা অসম্পূর্ণ। কী তথ্য পায়, কী বদলায়, খরচ কোথা থেকে আসে বোঝাও।

পঞ্চাশ ছোট প্রশ্ন structure ধরে সাজানো: অ্যারে, list, স্ট্যাক, কিউ, ট্রি, hashing আর গ্রাফ। প্রতিটি উত্তর মুখে বলে অতিরিক্ত বড় দাবির ছোট counterexample আঁকো। Skewed BST, matching key-র আগে tombstone আর isolated vertex কাজে লাগে।

Design তুলনায় locality, ownership, failure behavior আর সবচেয়ে দরকারি operation বলো। এক workload-এর ভালো structure অন্যটিতে খারাপ হতে পারে। উত্তরে C-style অ্যারে আর পয়েন্টার থাকলেও invariant আর operation contract-এর যুক্তি অন্য language-এও চলে।

অ্যারে

1. অ্যারে: পাশাপাশি storage কী সুবিধা দেয়?

Indexing-এ base যোগ index গুণ element width, তাই access O(1)। কাছের element সাধারণত cache line ভাগ করে। সামনের দিকে insert-এ তবু shift লাগে।

2. অ্যারে: শুধু length ভেরিয়েবল বদলে C অ্যারে কি জায়গাতেই বাড়ে?

না। Length active element বলে, allocated capacity নয়। বেশি জায়গা allocate বা checked realloc করো; success পর্যন্ত old পয়েন্টার রাখো।

3. অ্যারে: unsorted search কেন linear?

যেকোনো অবস্থানে target থাকতে পারে, তাই failed search সব n active element দেখে। আগে মিললে তাড়াতাড়ি শেষ, worst case O(n)।

4. অ্যারে: কোন বাড়তি শর্তে binary search চলে?

একই comparison rule-এ sorted হতে হবে। Binary search index interval অর্ধেক করে, অ্যারে-তে O(log n) comparison।

5. অ্যারে: dynamic-অ্যারে append কখন খরচ বেশি?

Storage বাড়লে সব n element copy আর পুরোনো element পয়েন্টার invalid হতে পারে। Geometric growth-এ O(1) amortized append, ওই একটি append O(n)।

6. অ্যারে: delete কি সবসময় order রাখে?

না। পরের element shift-এ O(n) সময়ে order থাকে। Order দরকার না হলে last active value দিয়ে বদল O(1)।

7. অ্যারে: row-major আর column-major আলাদা কীভাবে?

Row-major এক পুরো row-এর পরে পরের row রাখে। Column-major এক পুরো column-এর পরে পরেরটি, তাই address multiplier বদলায়।

লিস্ট

8. লিস্ট: linked list-এ constant-time indexing হয় না কেন?

নোডে পরের প্রতিটি element-এর address নয়, link থাকে। Head থেকে index i পেতে i link ধরতে হয়, random indexing O(n)।

9. লিস্ট: node free-এর আগে কী লাগবে?

দরকারে head-tail-সহ সব owning incoming link মেরামত। তারপর ঠিক একবার ছাড়ো, পরে field পড়বে না।

10. লিস্ট: singly linked list deletion সবসময় constant time?

শুধু জানা incoming link-এ unlink O(1)। Key বা predecessor খোঁজা O(n)। সাধারণত শুধু tail-এর নিজের পয়েন্টার দিয়ে tail সরানো যায় না।

11. লিস্ট: doubly linked list জানা node দ্রুত মুছে কেন?

Node predecessor আর successor রাখে। দুই neighbor link আর boundary header ঠিক করে free, সময় O(1); তবে প্রতি node-এ বাড়তি পয়েন্টার।

12. লিস্ট: ইটারেটিভ reversal কীভাবে suffix বাঁচায়?

Current next-কে previous করার আগে রেখে দাও। Previous current-এ, current রাখা successor-এ নাও। শেষে previous নতুন head।

13. লিস্ট: slow-fast পয়েন্টার cycle পায় কীভাবে?

দুই step থাকা পর্যন্ত slow এক, fast দুই link এগোয়। Cycle-এ relative gap একসময় zero। Acyclic list-এ fast NULL পায়।

14. লিস্ট: circular আর corrupt list আলাদা কী?

Circular list ইচ্ছা করে last node head বা sentinel-এ জোড়ে। Traversal NULL নয়, ওই boundary-তে থামে।

15. লিস্ট: link করার আগে allocate কেন?

Allocation ব্যর্থ হতে পারে। Incoming link-এ প্রকাশের আগে node তৈরি failure-এ old list অক্ষত রাখে, caller স্পষ্ট ownership পায়।

স্ট্যাক

16. স্ট্যাক: last-in first-out হয় কেন?

একই top প্রান্তে insert-remove। মাঝে অন্য operation না হলে সর্বশেষ push হওয়া item-ই পরের pop।

17. স্ট্যাক: empty pop-এর অর্থ কী?

Underflow। বৈধ ডেটা-ও হতে পারে এমন এলোমেলো মান না দিয়ে storage access-এর আগেই failure জানাও।

18. স্ট্যাক: এক অ্যারে-তে দুই স্ট্যাক কীভাবে?

এক top বাম boundary, অন্যটি ডান থেকে শুরু। একে অন্যের দিকে বাড়াও, ফাঁক শেষ হলে full।

19. স্ট্যাক: bracket matching-এ কেন দরকার?

Closing bracket সর্বশেষ unmatched opening-এর সঙ্গে মিলবে। Opening push, closing top-এর সঙ্গে তুলনা, শেষে স্ট্যাক empty চাই।

20. স্ট্যাক: postfix-এর কোন operand আগে pop?

আগে right, তারপর left। বিয়োগ বা ভাগে উল্টো করলে উত্তর বদলায়।

21. স্ট্যাক: রিকার্শন argument ছাড়া কী রাখে?

Call frame parameter, local state আর return location রাখে। Explicit স্ট্যাক-এ থামানো কাজ চালানোর যথেষ্ট state থাকতে হবে।

কিউ

22. কিউ: first-in first-out কেন?

Enqueue rear-এ যোগ, dequeue front থেকে সরায়। আলাদা scheduling policy না এলে অপেক্ষার item arrival order রাখে।

23. কিউ: circular কিউ আগের cell ফিরে পায় কেন?

Index capacity-র modulo-তে ঘোরে। Dequeue-তে front এগোলে পরের enqueue released physical cell নেয়, বাকি মান shift লাগে না।

24. কিউ: circular কিউ full-empty আলাদা করে কীভাবে?

Count রাখো, অথবা এক unused cell রাখো, অথবা আলাদা flag। Front-rear সমান index বোঝার আগে বাছা নিয়ম বলো।

25. কিউ: deque কী?

দুই প্রান্তে insertion-removal দেয়। Bounded circular অ্যারে-তে চার end operation-ই O(1)।

26. কিউ: priority কিউ arrival time-এ সাজানো?

মূল নিয়ম priority। সমান priority-তে arrival order শুধু explicit stable tie rule থাকলেই নিশ্চিত।

27. কিউ: linked কিউ-তে tail পয়েন্টার কেন?

Rear insertion O(1) হয়। Last node সরালে dangling tail এড়াতে head আর tail দুটো reset।

ট্রি

28. ট্রি: nonempty ট্রি-তে কত edge?

n vertex-এ n-1 edge। একে একে leaf সরালে বোঝা যায়; এক-vertex ট্রি-তে zero edge।

29. ট্রি: height-depth আলাদা কী?

Depth root থেকে node-এর পথ। Height node থেকে leaf-এর longest downward path। Edge নাকি node গুনছ বলো।

30. ট্রি: binary ট্রি মানেই BST?

না। Binary সর্বোচ্চ দুই child position বলে। BST পুরো left-right subtree-তে ordering rule যোগ করে।

31. ট্রি: BST inorder sorted কেন?

আগে ছোট left-subtree key, তারপর root, পরে বড় right-subtree key। রিকার্সিভ ordering পুরো sequence সাজায়।

32. ট্রি: BST search linear হতে পারে?

হ্যাঁ। সাধারণ BST-তে increasing insertion chain বানায়। নাম binary search ট্রি হলেও search সব n node দেখতে পারে।

33. ট্রি: দুই child-সহ BST node মুছলে কী বদলি হয়?

সাধারণ পছন্দ inorder successor, right subtree-র minimum। Key copy করে successor-কে পুরোনো অবস্থান থেকে সরাও।

34. ট্রি: AVL rotation কী রাখে?

স্থানীয় height বদলেও inorder sequence আর সব subtree key bound রাখে। Middle subtree link মেরামত আর cached height update করো।

35. ট্রি: complete আর full binary ট্রি আলাদা কী?

Complete level বাম থেকে ডানে ভরে। Full-এর প্রতিটি internal node-এ ঠিক দুই child, leaf ভিন্ন depth-এ হতে পারে।

36. ট্রি: হিপ পুরো sorted?

না। Max-হিপ প্রতিটি parent-কে child-এর সমান বা বড় রাখে। Sibling বা আলাদা branch sorted হতে হবে না।

37. ট্রি: bottom-up হিপ build linear কেন?

অধিকাংশ node leaf-এর কাছে, অল্প দূর sift করে। Subtree height ধরে যোগে convergent geometric sum গুণ n হয়।

38. ট্রি: trie prefix আর stored word আলাদা কী?

বড় শব্দ prefix ভাগ করায় path থাকতে পারে। Child থাকলেও terminal marker exact stored word চেনায়।

39. ট্রি: B+ leaf linked কেন?

প্রথম মেলা leaf পেয়ে range query key order-এ পাশের leaf ধরে। Internal separator search চালায়, record leaf-এ থাকে।

হ্যাশিং

40. হ্যাশিং: ভিন্ন key-র hash সমান হয়?

হ্যাঁ। সীমিত bucket অ্যারে সাধারণত বড় key space বোঝায়। Hash-কে identity না ভেবে collision-এ আসল key তুলনা করো।

41. হ্যাশিং: load factor কী মাপে?

Stored key count ভাগ bucket বা slot capacity। Chaining-এ এক ছাড়াতে পারে; দক্ষ probing-এ open addressing-এর unused slot চাই।

42. হ্যাশিং: open-address deletion tombstone রাখে কেন?

পরে থাকা key insertion-এ ওই slot পেরোতে পারে। Tombstone search চলতে দেয়, আবার future insertion-এ reusable space-ও দেয়।

43. হ্যাশিং: primary clustering কী?

Linear probing পাশাপাশি occupied run বানায়। নতুন collision সেগুলো বাড়ায়, আলাদা home bucket-এও probe বাড়ে।

44. হ্যাশিং: growth-এর পরে rehash কেন?

Bucket formula capacity-র ওপর। নতুন formula-তে সব live key reinsertion lookup rule ফেরায়; পুরোনো অবস্থান copy নয়।

গ্রাফ

45. গ্রাফ: undirected edge adjacency list-এ কী রাখে?

প্রতি endpoint-এ এক neighbor record। তাই E edge-এ 2E neighbor record, সঙ্গে vertex header।

46. গ্রাফ: BFS enqueue-তে mark কেন?

দুই frontier vertex একই neighbor পেতে পারে। Enqueue-এর আগে mark duplicate entry ঠেকায়, প্রথম shortest-hop distance স্থির করে।

47. গ্রাফ: BFS যেকোনো weighted shortest path পারে?

না। সমান cost-এ BFS edge count কমায়। Unequal weight-এ weight মেনে চলা অ্যালগরিদম লাগে।

48. গ্রাফ: DFS finish time কী রাখে?

Active call-এ vertex-এর unexplored neighbor আর নেই কখন, তা। Ancestor ফেরার আগে descendant শেষ হয়।

49. গ্রাফ: সব disconnected component traversal কীভাবে?

সব ID scan করে প্রতিটি unseen-এ নতুন search। Search-গুলো forest হয়, isolated vertex এক-node ট্রি।

50. গ্রাফ: union-find path compression কী বদলায়?

Visited parent link আগের root-এর দিকে ঘোরায়। Forest shape বদলায়, set partition আর representative root রাখে।

ফল বলার আগে শর্ত দেখো

Complexity লেবেল-এ representation আর operation চাই। Matrix absent connection-ও scan করে, adjacency list নয়। BST chain হতে পারে, hash অনেক key এক bucket-এ দিতে পারে। দ্রুত average বা amortized দাবির শর্ত বলো।

পয়েন্টার trace-এ allocated record আর owner link আলাদা। Release-এর আগে incoming link মেরামত, freed node পরের traversal step নয়। গ্রাফ trace-এ source আর neighbor order বলো; route বানিয়ে না দিয়ে unreachable marker রাখো।

মুখস্থ তথ্যের কারণ বোঝাও

প্রতি উত্তরে এক শর্ত বদলে ফল ভাবো। Full কিউ, duplicate key, missing contact বা disconnected vertex নাও। একই cost word-এ ভিন্ন নিশ্চয়তা বোঝালে complexity basics আবার দেখো।
