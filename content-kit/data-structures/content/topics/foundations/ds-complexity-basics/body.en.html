Introduction

A stopwatch can tell you how long one run took. It cannot tell you how much slower the program will become when a class grows from 60 students to 6,000. To answer that question, count the work as a function of input size. This is the starting point for comparing data structures.

Imagine searching roll-number marks written on cards. If the required card is first, you stop immediately. If it is absent, you examine every card. The number of cards is the same in both situations. The position of the answer changes the work.

An operation count measures a chosen action, such as comparing one stored value with a target. You must say what you count. A comparison count is easier to explain than wall-clock seconds and is less dependent on the computer running your program.

Representation and rules

Let n be the number of live values. Reading an indexed array cell needs a fixed amount of work, independent of n. Traversing all cells needs work proportional to n. Comparing every pair needs work proportional to n squared. Repeatedly halving a remaining range takes about log base two of n rounds.

Big-O is an upper growth bound. Saying a cost is O(n) means that, beyond some size, a constant times n bounds it above. The constant and the starting threshold are not the focus. An exact count of 3n+7 is therefore O(n). O(n squared) is also an upper bound for that function, but the tighter linear bound tells you more.

Big-Omega supplies a lower growth bound. Big-Theta gives matching upper and lower bounds. A complete traversal taking one action per element is Theta(n). Big-O does not automatically mean worst case, and Big-Omega does not automatically mean best case. First choose a cost function; then describe its growth.

Best case chooses the cheapest input of a fixed size. Worst case chooses the most expensive. Average case needs an explicit probability model. For a present target equally likely at each of n positions, linear search averages (n+1)/2 comparisons.

The pair example uses j=i+1. For n=4, the outer iterations contribute three, two, one and zero pairs. Their total is six. In general the sum is n(n-1)/2. Removing the lower-order term and constant factor leaves quadratic growth. Doubling n approaches four times the work for large n.

The growth-copy example introduces amortized cost. Some appends copy many elements, but most append into a spare slot. With doubling, the copy counts are 1+2+4+8 and so on. A sequence of n appends copies fewer than 2n old elements. Add the n new writes and the total remains O(n), yielding O(1) amortized work per append.

Costs and boundary cases

Time and space answer different questions. Linear search stores the original n values but uses only a few extra variables. Its auxiliary space is O(1). If you make a separate copied array, that new storage is O(n). State whether a space claim includes input storage, output storage or only temporary work.

For common operations, remember the conditions behind each entry. Array indexing is O(1). Unsorted search is O(n) worst case. Front insertion into a fixed array is O(n) because values shift. Head insertion into a linked list is O(1) after allocation. Finding its last node without tail is O(n). Tree search depends on height, so a very skewed tree can also take O(n).

Common mistakes

Counting loops by appearance

Two nested loops do not always mean exactly n squared steps. Count the actual ranges. A triangular inner range still gives Theta(n squared), while an inner loop with a fixed three repetitions gives Theta(n).

Calling amortized cost a guarantee for one operation

The ninth doubling append may copy eight old values. Its individual cost is linear in the current size. The constant amortized claim applies to a whole sequence, including those expensive calls.

Averaging without assumptions

Do not say a target is usually near the middle unless the input model supports that claim. A frequently requested first item changes the average, while the worst-case bound stays linear.

Working habits

Choose a visible basic action, write a small trace and derive the sum before using notation. Record whether n counts live elements or reserved capacity. If two implementations have equal growth rates, memory locality and constant factors can still matter for real workloads.

Use exact counts for small exam inputs and asymptotic bounds for growing sizes. An answer such as four comparisons explains one search. Theta(n) explains a family of searches when the target is absent.

C version notes

The counting arguments do not depend on a new C language feature. C17 does not promise a particular speed for malloc, memory access or integer division. The examples count explicit actions; they do not claim to measure processor instructions.
