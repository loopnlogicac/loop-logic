Introduction

A data structure is a way to arrange values so your program can use them. Think about a class marks register. You may need the mark for roll 17, the class total, or a list of students who passed. The same marks can be arranged in different ways. Your choice changes how much work each request takes.

A register with numbered rows gives you a useful picture of an array. Each roll has a known place. A chain of cards gives you a picture of a linked list. Each card tells you where to find the next card. Neither picture is a complete program yet. Both help you ask which relationships your program must preserve.

You already know C variables, loops and functions. This course adds a question before writing those functions: how should the data live in memory? You will learn to explain that choice using operations, memory limits and boundary cases.

Representation and rules

An abstract data type, usually shortened to ADT, describes what a collection means and what you can do with it. A sequence ADT has an order. Its interface might let you read a position, insert a value, remove a position and ask for the size. The interface should also explain what happens when a request is invalid.

An implementation supplies the actual fields and code behind that promise. You can implement a sequence using adjacent array cells or separately allocated linked nodes. A caller can use the same operation names while the internal work differs. This separation lets you change storage without rewriting every caller.

A linear structure arranges elements in one logical sequence. Arrays, lists, stacks and queues are familiar examples. A non-linear structure branches or connects values in more general ways. Trees represent parent-child relationships. Graphs represent connections such as roads between places. Linear does not mean that allocated bytes must form one straight physical block.

Static capacity means the reserved maximum is fixed. Dynamic storage can request or release memory while the program runs. These labels concern storage policy, not whether stored marks can change. A fixed array may hold changing marks. A dynamic list may still enforce an application limit.

Follow the memory

Start with four marks: 72, 85, 64 and 91. In the array picture, the third mark occupies index two. An index counts from zero because the first element has zero displacement from the beginning. Reading index two finds 64 without walking past the earlier marks.

Array: [72][85][64][91]
Index:   0   1   2   3

Linked sequence:
head --> [72|next] --> [85|next] --> [64|next] --> [91|NULL]

A linked traversal begins at head and follows next. Each arrow stores a relationship between two nodes. The boxes may be far apart in actual memory. The final NULL says there is no successor. An empty linked sequence has head equal to NULL and needs no node box.

Now insert a new first mark. An array shifts the old values right if it has room. A list allocates one new node, points that node at the old head, and replaces head. The final logical order can match even though the memory updates differ. Watch the difference between moving values and changing relationships.

Before: head --> [85|NULL]
Prepare: new --> [72|next] --> [85|NULL]
After:  head --> [72|next] --> [85|NULL]

The linked example is a first picture of nodes rather than a new storage rule to memorize. malloc requests a node and can return NULL; destroy releases the nodes after use. Follow those details in the pointer and allocation review before adapting that example.

Costs and boundary cases

Choose storage from the workload. A fixed set of 60 roll numbers favors indexed access. A collection with frequent front insertions may favor links. Printing every mark requires visiting every live value in either representation. A structure does not become suitable because one operation sounds fast.

Include memory in your decision. An array reserves space for its capacity, including spare cells. A linked node needs its value plus a pointer and possibly padding. A dynamic allocation can fail even when your logical collection has no fixed limit. A full fixed array must reject insertion before writing outside its bounds.

Check the empty, singleton and full states explicitly. Empty traversal should print no values. A singleton is both first and last. Full capacity affects insertion, but it does not prevent reading an existing mark.

Common mistakes

Confusing size with capacity

A bag with capacity eight may contain only three marks. Loop to size when reading live values. Treating all eight slots as marks can read uninitialized storage or display unrelated leftovers.

Choosing by name alone

A linked list does not make every update constant time. Reaching a numbered position still requires a walk. Describe how the requested node is found before stating the cost of changing its links.

Forgetting failure behavior

The bounded bag example reports success or failure. Ignoring that result can make a caller believe a mark was saved when storage was full. Check the result before reporting that an update succeeded.

Working habits

Write a short operation list before declaring fields. Include the most common read, the most common update and the largest expected collection. Decide whether order matters and whether duplicate values are allowed. These questions make the storage choice concrete.

Use this course map as a route: foundations explain cost and C memory; arrays teach indexed storage; lists teach links. Stacks and queues restrict which ends you use. Trees add hierarchy, hashing targets fast lookup, and graphs describe general connections. Later practice combines these ideas rather than replacing them.

C version notes

These examples use C17. C arrays have adjacent elements, while separate malloc calls have no promised relative location. The C standard does not guarantee a particular byte size for int or for a pointer. Diagrams show logical boxes rather than machine addresses.

Summary

A useful structure supports the operations your application needs at a reasonable cost. Keep its logical interface separate from its memory layout. Next, learn to count that cost in Measuring Operations.
