প্রতি bucket-এর নিজের list রাখো

নম্বর দেওয়া ডেস্কের tray-তে কয়েকটি ID card রাখা ভাবো। Tray বাছলে কাছে আসো, তবু ভেতরের ID পড়তে হয়। Separate chaining-ও তাই: প্রতিটি hash bucket একই bucket ভাগ করা record-এর linked list দেখায়।

Singly linked list দিয়ে record জোড়া তুমি জানো। Hashing শুরু করার pointer-এর ছোট array যোগ করে, তাই সাধারণত এক ছোট list দেখলেই হয়। টেবিলে সাত bucket header, শুরুতে NULL। নোডে integer key আর next pointer। Key একবার থাকে; সমান key insert করলে set বদলায় না।

Record header array-র বাইরে থাকে বলে bucket-এর চেয়ে বেশি key chaining-এ চলে। Bucket লম্বা হতে পারে, তাই insertion-এর মেমরি থাকলেও speed-এর জন্য capacity গুরুত্বপূর্ণ। Load factor bucket-প্রতি গড় key বলে, actual distribution দৈর্ঘ্যের অসমতা বলে।

Ownership আর duplicate নিয়ম বলো

Insert helper bucket head array আর key পেয়ে bucket(key,7) হিসাব করে, পুরো key মিলিয়ে list ধরে। সমান থাকলে শূন্য ফেরায়। না হলে এক নোড allocate করে শেষ NULL link-এ append করে। এক মানে যোগ হয়েছে, minus one মানে allocation failure।

Link-এর pointer append আর deletion ছোট করে। শুরুতে link bucket header দেখায়, প্রতি অগ্রগতিতে existing node-এর next field দেখায়। তাই link দিয়ে assignment ঠিক দরকারি incoming pointer বদলায়। Local variable pointer; node-এর owner টেবিল।

Expected খরচ ভালো distribution ধরে। এখানে alpha=n/m, n distinct রাখা key আর m bucket। জানা link-এ node জোড়া constant time হলেও equality দেখার জন্য unique insertion বাছা chain-এর দৈর্ঘ্য অনুযায়ী linear। Header আর record-সহ table-এর জায়গা O(m+n)।

একবারে এক incoming link ঠিক করো

ফাঁকা সাত-bucket table-এ 1,8,15 ঢোকাও। সবার remainder এক। প্রথমটি header, দ্বিতীয়টি node 1-এর next, তৃতীয়টি node 8-এর next বদলায়। Append list-এর ভেতর insertion order রাখে; সামনে insert করলে membership না বদলে ক্রম উল্টো হতো।

15 insert-এর আগে:
bucket[1] -> [1|next] -> [8|NULL]
15 insert-এর পরে:
bucket[1] -> [1|next] -> [8|next] -> [15|NULL]
8 delete-এর আগে:
link -> node 1 next -> [8|next] -> [15|NULL]
8 delete-এর পরে:
bucket[1] -> [1|next] ----------------> [15|NULL]
Incoming link বদলানোর পরেই node 8 ছাড়া হয়।

15 search আগে bucket এক বাছে, তারপর 1 আর 15 তুলনা করে। দ্বিতীয় নোডে success। 22 search একই list-এ NULL পেয়ে absence প্রমাণ করে। Index সমান বলে search থামবে না, একই bucket-এ ভিন্ন key থাকে।

Deletion link matching node না দেখানো বা pointed link NULL না হওয়া পর্যন্ত হাঁটে। মিললে node pointer রেখে incoming link-এ old next বসায়, তারপর old free করে। Free-এর আগে next রাখায় dead memory পড়ে না। পরে old ব্যবহার হয় না, তাই released record ভুল করে traversal step হয় না।

Animation প্রথম উদাহরণের append order আর duplicate rule মানে। [1,8,15] থেকে 8 সরিয়ে 15 খোঁজো। তারপর 1 সরিয়ে header case দেখো। Table player bucket value list হিসেবে আঁকে; box diagram C-তে মেরামত হওয়া owner link দেখায়।

সাধারণ আর ভিড় করা bucket পরীক্ষা

সাত bucket-এ insert, remove আর find

Insertion list-এর শেষে যোগ করে। 8 সরালে মাঝের link মেরামত হয়, duplicate 1 নতুন record বানায় না।

Bucket head আর শেষ record মুছো

একই link-based deletion bucket header বদলায়। পরের search ফাঁকা bucket পায়।

Load-এর সঙ্গে জমা হওয়াও মাপো

মাঝারি গড় load পাঁচ-node chain লুকিয়ে রাখে। সবচেয়ে লম্বা bucket এই ভিড় দেখায়।

Load factor বুঝে পড়ো

নব্বই key আর ত্রিশ bucket-এ alpha তিন। Uniform-distribution model-এ failed search bucket বেছে প্রায় তিন record দেখে। Successful search মাঝেই থামতে পারে; expected comparison placement আর query-র শর্তে নির্ভর করে। দুটিই O(1+alpha), সর্বজনীন constant নয়।

Bucket count allocated record-এর সীমা নয় বলে alpha এক ছাড়াতে পারে। Open addressing-এ কিন্তু প্রতি slot-এ সর্বোচ্চ এক live key। বেশি node মানে বেশি allocation, pointer chase আর key comparison। Chained table বড় করলে নতুন modulus-এ node ছড়ায়, bucket-প্রতি list-এর ধারণা বদলায় না।

ছোট গড় এক খারাপ bucket লুকাতে পারে। তৃতীয় উদাহরণ ইচ্ছা করে পাঁচ key এক chain-এ দেয়। Alpha একের কম হলেও longest পাঁচ। Alpha-র সঙ্গে সর্বোচ্চ length দিলে দুর্বল hash-এ regular key pattern না ছড়ানো ধরা পড়ে।

Uniqueness না দেখা front-insert dictionary O(1)-এ record জোড়ে। আমাদের নিয়ম আলাদা: সমান key duplicate হয় না। কোন প্রান্তে নতুন node বসুক, আগে বাছা chain দেখতেই হবে। পরীক্ষায় insertion খরচ বলার আগে contract বলো।

Missing node আর failed allocation

ফাঁকা table-এ search সরাসরি NULL, deletion শূন্য দেয়। এক-node bucket header NULL করে ফাঁকা হয়। Tail মুছলে আগের next NULL। Absent key link বা মেমরি বদলায় না, তাই repeated deletion নিরাপদ, দ্বিতীয়বার শূন্য।

Allocation failure আগের node নষ্ট করবে না। Insert incoming link লেখার আগে allocate করে। malloc NULL দিলে পুরোনো list অক্ষত। প্রথম উদাহরণের caller failure ফেরার আগে সব existing record ছাড়ে। আংশিক তৈরির পরে ভুল input-ও একই cleanup path নেয়।

মেমরি বা app limit ছাড়া chaining-এর fixed full নেই। Trace ছোট রাখতে প্রোগ্রামে সর্বোচ্চ বারো initial key, সেটি input bound, structure capacity নয়। Cleanup সব সাত bucket scan করে successor রেখে প্রতি node একবার free করে।

Negative integer-ও key range-এ। Normalized remainder -1-কে bucket ছয়ে পাঠায়। ফাঁকা list NULL বলে শূন্য সাধারণ stored key। Duplicate allocate করে না, key count বা alpha বাড়ায় না।

Free-এর পরে node-এর next পড়া অবৈধ। আগে successor রেখে owner link মেরামত করো, তারপর old ছাড়ো।

শুধু head মিললে তা চলে। মাঝের node মুছতে আগের next field বদলাবে। Pointer-to-pointer walk দুই case-এই সঠিক জায়গা খুঁজে দেয়।

চেষ্টার সংখ্যাকে distinct key ধরা

প্রথম উদাহরণের repeated 1 আগেই আছে। সফল allocation আর attachment-ই শুধু load factor-এর set size বাড়ায়।

C17 allocation আর node lifetime

Bucket list standard library-র malloc আর free ব্যবহার করে। C17-এ free-এর পরে record পড়া চলে না। Bucket pointer NULL দিয়ে initialize করে incoming link-এ বসানোর আগে node তৈরি করো।

Bucket linked-list search ছোট করে

Separate chaining collide করা প্রতিটি key পৌঁছানো যায় এমন record-এ রাখে। Hash list বাছে, key comparison record খোঁজে, deletion-এর link repair ownership রাখে। এরপর open addressing record array-র ভেতরেই রাখবে।
