Let a collision search for another cell

Imagine assigned seats in a small reading room. If your assigned seat is occupied, you follow a fixed rule to try another seat. Open addressing stores each key directly in the table array and uses a probe sequence to find its possible positions.

The rule must be reproducible. A search starts from the same home bucket and follows the same sequence as insertion. It compares keys until it finds a match, a never-used empty cell, or the attempt limit. Our eleven-slot table supports three methods, chosen by an input number: zero for linear, one for quadratic and two for double hashing.

Each slot has a key field and a state field. State zero means never used, one means occupied, and two means deleted. A deleted slot is a tombstone: available for later insertion, but unable to prove that a searched key is absent. Integer zero remains valid data because state, rather than key value, describes occupancy.

Write the complete probe formula

All methods use normalized h1(k)=k mod 11, with attempt i beginning at zero. Linear probing uses (h1+i)%11. Quadratic probing uses (h1+i*i)%11. Double hashing uses (h1+i*h2)%11, where h2=1+(k mod 10), again with normalized remainders. Every attempt uses the original home bucket, rather than the previous probe as a new home.

Linear probing visits every slot because its step is one. Its weakness is primary clustering: long adjacent occupied runs attract more arrivals. A key whose home is anywhere inside a run must continue toward its end. Even unrelated home buckets then share the same congested region.

Quadratic steps spread early attempts apart but need a coverage argument. Modulo eleven, i squared reaches only six distinct residues. Our code bounds attempts at eleven and reports exhaustion if no reachable free slot appears. A table can therefore reject an insertion while some slots remain empty. The standard prime-capacity guarantee for this simple quadratic rule requires the table to stay below half full.

Double hashing chooses a separate step for each key. A complete cycle needs gcd(step,capacity)=1. With prime eleven and step one through ten, that condition always holds. Keys with the same home can follow different routes, reducing shared clustering. They can still collide, so the normal comparison and stopping rules remain necessary.

Search past deletions without creating duplicates

Insert 1,12,23,34 using linear probing. All four begin at slot one, so they occupy slots one through four. Removing 12 must not turn slot two into a never-used empty cell. Otherwise a search for 34 would stop too early and incorrectly report absence.

state    empty  [1]  [12]  [23]  [34]  empty
After deleting 12:

Search 34: home 1 -> tombstone 2 -> 23 at 3 -> match at 4

Insertion remembers the first tombstone but continues searching for an equal key. When it reaches a never-used empty cell, equality is ruled out along that sequence. It can then place the new key into the remembered tombstone, or into that empty cell if no tombstone occurred. If every allowed probe is used, a remembered tombstone is still reusable.

The first example inserts all input keys, deletes one key and searches for another. The fourth example goes further: it deletes 12, tries duplicate 23, then inserts new key 34. The duplicate attempt leaves the tombstone available. The new key occupies it, while the older 23 stays reachable.

In the lab, choose the same four initial keys and switch methods. The final membership should agree unless the quadratic sequence exhausts its reachable positions. Slot layouts may differ because each method resolves collisions differently. The insertion status list distinguishes a duplicate from an exhausted attempt.

Load and probe coverage both matter

An expected constant-time claim needs a low load and a suitable distribution model. As live occupancy approaches capacity, finding a free slot becomes harder. Tombstones can also lengthen searches even though they no longer count as live keys. A useful implementation monitors both live count and used-or-deleted count, then rebuilds when necessary.

For a capacity-m table, one bounded operation can inspect O(m) slots in the worst case and uses O(1) working space. The array occupies O(m) total storage. An insertion adds no separately allocated node. This often improves locality compared with chasing a linked chain, but requires free capacity and careful deletion rules.

A never-used empty slot proves absence because insertion would have stopped there earlier in the same sequence. That argument assumes the capacity and hash rule have not changed without rebuilding. Tombstones preserve the argument by distinguishing deletion from a slot that was never crossed by stored keys.

Double hashing has a full-cycle guarantee under our capacity and step choices. Quadratic probing has a different limitation, explicitly shown by example two. Do not call both failures table full: one can mean all slots occupied, while the other means only the chosen sequence is exhausted.

Bound every attempt loop

An empty table gives an immediate empty probe. A single occupied home either matches or forces another probe. A full linear or double-hash table scans at most eleven attempts before failure. Searching an absent key in a table containing only occupied cells and tombstones also terminates at that bound.

Duplicate keys keep set semantics and return status zero. Negative keys use the same normalization for both h1 and h2. With -1, h1 is ten and h2 is ten, so the double-hash step remains nonzero. The key arithmetic after reduction stays small enough for the int expressions used here.

Capacity must never be zero; all remainder formulas depend on a positive divisor. Increasing capacity requires reinsertion because both home positions and steps can change. Merely adding unused cells at the end would leave searches following routes unrelated to the old placement.

The eleven-slot arrays are initialized with empty state and harmless key zero. State tests always happen before interpreting a stored key. Reusing a tombstone changes state back to occupied. An absent deletion leaves every state untouched, while a successful deletion records exactly one tombstone.

Do not erase the search history

Stopping at a tombstone

A collision may have pushed the target beyond that slot. Continue until a match, a never-used empty slot or the bounded attempt limit.

C17 slot states

The probing programs use explicit int state fields rather than reserving an integer key as an empty marker. Their bounded offsets fit int, and their negative-remainder adjustment follows C17 arithmetic rules.
