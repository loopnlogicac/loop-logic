Collision হলে আরেক ঘর খোঁজো

ছোট reading room-এ নির্দিষ্ট seat আছে ভাবো। তোমার seat ভরা হলে নির্দিষ্ট নিয়মে অন্যটি দেখো। Open addressing প্রতিটি key সরাসরি table array-তে রাখে, সম্ভাব্য অবস্থান খুঁজতে probe sequence ব্যবহার করে।

নিয়ম আবার একইভাবে চালানো যেতে হবে। Search insertion-এর একই home bucket আর sequence ধরে। মিল, কখনো ব্যবহার না হওয়া empty cell বা attempt limit পর্যন্ত key তুলনা করে। এগারো-slot table-এ input শূন্যে linear, একে quadratic আর দুইয়ে double hashing।

প্রতি slot-এ key আর state field। State শূন্য মানে কখনো ব্যবহৃত নয়, এক occupied, দুই deleted। Deleted slot tombstone: পরে insert করা যায়, কিন্তু খোঁজা key নেই তা প্রমাণ করে না। Occupancy key নয় state বলে integer শূন্য বৈধ data।

পুরো probe formula লেখো

সব পদ্ধতিতে normalized h1(k)=k mod 11, attempt i শূন্য থেকে। Linear (h1+i)%11, quadratic (h1+i*i)%11, double hashing (h1+i*h2)%11, যেখানে h2=1+(k mod 10), এখানেও remainder normalized। প্রতিবার আসল home bucket থেকে হিসাব; আগের probe নতুন home নয়।

Linear step এক বলে সব slot visit করে। দুর্বলতা primary clustering: পাশাপাশি লম্বা occupied run আরও key টানে। Run-এর ভেতর যেকোনো home-এর key-কে শেষ পর্যন্ত যেতে হয়। সম্পর্কহীন home-ও একই ভিড়ে পড়ে।

Quadratic শুরুতে attempt ছড়ায়, কিন্তু coverage প্রমাণ দরকার। Modulo এগারোতে i squared মাত্র ছয় distinct residue পায়। কোড সর্বোচ্চ এগারো attempt করে, reachable free slot না পেলে exhaustion। তাই কিছু slot ফাঁকা থাকলেও insert ব্যর্থ হতে পারে। এই সরল quadratic rule-এর standard prime-capacity নিশ্চয়তায় table অর্ধেকের কম ভরা চাই।

Double hashing প্রতি key-র জন্য আলাদা step বাছে। Full cycle পেতে gcd(step,capacity)=1 চাই। Prime এগারো আর এক থেকে দশ step-এ শর্ত সবসময় মেলে। একই home-এর key আলাদা route ধরতে পারে, shared clustering কমে। তবু collision হতে পারে, স্বাভাবিক comparison আর stopping rule লাগবে।

Deletion পেরিয়ে খোঁজো, duplicate বানিও না

Linear probing-এ 1,12,23,34 দাও। সবার home এক, তাই slot এক থেকে চার নেয়। 12 সরিয়ে slot দুই কখনো ব্যবহার না হওয়া empty করা যাবে না। করলে 34 search খুব আগে থেমে ভুল absent বলবে।

Deletion-এর আগে:
slot       0     1     2     3     4     5
state    empty  [1]  [12]  [23]  [34]  empty
12 মুছলে:
state    empty  [1]   [†]  [23]  [34]  empty
34 search: home 1 -> tombstone 2 -> slot 3-এ 23 -> slot 4-এ মিল

Insertion প্রথম tombstone মনে রেখেও সমান key খোঁজে। Never-used empty cell এলে ওই sequence-এ equality আর নেই। তখন মনে রাখা tombstone-এ, তা না থাকলে empty cell-এ key বসায়। সব allowed probe শেষ হলেও মনে রাখা tombstone ব্যবহার করা যায়।

প্রথম উদাহরণ সব input key insert করে, এক key মুছে অন্যটি খোঁজে। চতুর্থটি 12 মুছে duplicate 23 চেষ্টা করে, তারপর নতুন 34 ঢোকায়। Duplicate tombstone খালি রাখে। নতুন key পরে সেটি নেয়, আগের 23-ও পৌঁছানো যায়।

Lab-এ একই চার initial key নিয়ে পদ্ধতি বদলাও। Quadratic reachable position শেষ না হলে শেষ membership মেলার কথা। Collision আলাদাভাবে মেটায় বলে slot layout আলাদা হতে পারে। Insertion status list duplicate আর exhausted attempt আলাদা দেখায়।

অবস্থান আর tombstone-এর আচরণ তুলনা

Probe পদ্ধতি বেছে search বাঁচাও

Linear colliding key পরপর ঘরে রাখে। 12 মুছলে tombstone থাকে, তাই পরের search 34 পায়।

Quadratic-এর reachable cell শেষ হতে পারে

সাত colliding key modulo এগারোতে মাত্র ছয় distinct quadratic offset চায়। অন্য slot ফাঁকা থাকলেও শেষ insertion -1 দেয়।

Double-hash cycle দেখো

দ্বিতীয় hash step তিন দেয়। এগারো prime বলে শুরুতে ফেরার আগে sequence সব slot দেখে।

Duplicate দেখে tombstone আবার ব্যবহার

প্রথম চেষ্টা tombstone-এর পরে 23 পেয়ে কিছু যোগ করে না। পরে নতুন 34 একই tombstone নেয়, 23-কে আড়াল করে না।

Load আর probe coverage দুটোই জরুরি

Expected constant-time বলতে কম load আর উপযুক্ত distribution model চাই। Live occupancy capacity-র কাছে গেলে free slot খোঁজা কঠিন। Tombstone live key না হলেও search লম্বা করে। ভালো implementation live count আর used-or-deleted count দুটো দেখে দরকারে rebuild করে।

Capacity m হলে bounded operation worst case-এ O(m) slot দেখে, কাজের জায়গা O(1)। Array-র মোট storage O(m)। Insertion আলাদা allocated node যোগ করে না। Linked chain ধাওয়ার তুলনায় locality ভালো হতে পারে, তবে free capacity আর সাবধান deletion rule লাগে।

Never-used empty slot absence প্রমাণ করে, কারণ একই sequence-এ insertion আগে সেখানেই থামত। যুক্তি ধরে capacity বা hash rule rebuild ছাড়া বদলায়নি। Tombstone deletion-কে কখনো key না পেরোনো slot থেকে আলাদা করে যুক্তি রাখে।

আমাদের capacity আর step-এ double hashing full cycle নিশ্চিত। Quadratic-এর সীমা আলাদা, দ্বিতীয় উদাহরণে স্পষ্ট। দুই failure-কে table full বলো না: একটিতে সব slot ভরা, অন্যটিতে বাছা sequence শেষ।

প্রতিটি attempt loop সীমিত করো

ফাঁকা table-এ প্রথম probe-ই empty। Home occupied হলে মেলে বা আরেক probe লাগে। Full linear বা double-hash table সর্বোচ্চ এগারো attempt-এ failure। শুধু occupied আর tombstone থাকা table-এ absent key search-ও ওই সীমায় থামে।

Duplicate set-এর নিয়মে status শূন্য দেয়। Negative key-তে h1 আর h2 দুটো normalize। -1-এ h1 দশ, h2 দশ, তাই double-hash step nonzero। Reduction-এর পরে arithmetic এখানকার int expression-এর জন্য যথেষ্ট ছোট।

Capacity কখনো শূন্য নয়; remainder-এ positive divisor দরকার। Capacity বাড়ালে home আর step বদলাতে পারে, তাই reinsertion চাই। শুধু শেষে ফাঁকা cell যোগ করলে search-এর route পুরোনো placement-এর সঙ্গে মিলবে না।

এগারো-slot array empty state আর নিরীহ key শূন্য দিয়ে initialize। Stored key বোঝার আগে state পরীক্ষা। Tombstone reuse-এ state occupied হয়। Absent deletion state বদলায় না, সফল deletion ঠিক এক tombstone রাখে।

Search-এর ইতিহাস মুছো না

Tombstone-এ থামা

Collision target-কে ওই slot-এর পরে ঠেলতে পারে। মিল, never-used empty slot বা bounded attempt limit পর্যন্ত চলো।

প্রথম tombstone-এই সঙ্গে সঙ্গে insert

একই key পরে থাকতে পারে। Reusable অবস্থান রেখে duplicate check শেষ করে তবেই insert করো।

সব step পুরো table ঘোরে ধরা

Capacity বারোতে step চার মাত্র তিন distinct cell দেখে। Double hashing-এ coprimality, quadratic formula-তে load guarantee দেখো।

C17 slot state

Probing প্রোগ্রামে integer key-কে empty marker না বানিয়ে স্পষ্ট int state field আছে। সীমিত offset int-এ ধরে, negative-remainder adjustment C17 arithmetic মানে।

Lookup-এ placement rule-ও লাগে

Open addressing বাইরের list-এর বদলে আবার অনুসরণযোগ্য array sequence দেয়। Deletion-এর পরে slot state search-এর অর্থ রাখে। পরের পাঠে occupancy বাড়লে কখন আর কীভাবে rebuild করবে দেখাবে।
