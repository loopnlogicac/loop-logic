পাশের শাখার আগে এক শাখা শেষ

নতুন room না থাকা পর্যন্ত corridor ধরে গিয়ে সর্বশেষ junction-এ ফেরার কথা ভাবো। পরের কোন দরজা দেখবে মনে রাখো। Depth-first search বা DFS nested call বা নিজের stack frame দিয়ে এইভাবে graph দেখে।

প্রতিটি reached vertex-এ দুই ঘটনা: প্রথম ঢোকা discovery; সব neighbor দেখা আর recursive child ফেরার পরে finishing। দুই ক্রম আলাদা, কারণ সক্রিয় descendant-এর আগে parent শেষ হতে পারে না।

Visited array cycle-এ endless recursion ঠেকায়। Neighbor দেখার আগে entry-তেই mark করো। উদাহরণ BFS-এর graph choice মেনে ascending ID দেখে। একই source-এ BFS-এর একই component পায়, তবে route আর visit order সাধারণত আলাদা।

Frame-এ কোথা থেকে ফিরবে রাখো

Recursive DFS-এর প্রতিটি active call frame বর্তমান vertex আর loop-এর next neighbor position রাখে। উদাহরণ loop-এর আগে enter U, পরে leave U প্রিন্ট করে। Child ফিরলে parent প্রথম neighbor থেকে নয়, থামার জায়গা থেকে চলে।

Iterative উদাহরণ stack[top] আর next[top]-এ একই state রাখে। Top active frame। Neighbor বাকি থাকলে নামার সিদ্ধান্তের আগেই saved next index বাড়াও। Unseen neighbor-এ mark করে next শূন্যের নতুন frame push করো।

mark start; enter[start] = ++clock; push frame(start,0)
while frames remain
    u = top; advance its next neighbor index
    if neighbor v is unseen: mark v; enter[v] = ++clock
        push frame(v,0)
    if no neighbors remain: leave[u] = ++clock
        pop the exhausted frame and resume its parent
report discovery order, finish order and times

Clock শূন্যে শুরু, প্রতি entry-exit-এ বাড়ে। Enter আর leave শূন্য দিয়ে শুরু বলে unreached vertex আলাদা বোঝা যায়। সাত vertex-এ সর্বোচ্চ সাত active frame আর চৌদ্দ event time। Explicit stack suspended call রাখে, এলোমেলো future visit নয়।

Unseen component-এ নতুন DFS

প্রথম tree শূন্য থেকে পাঁচ পায়। দ্বিতীয় root ছয় isolated component ধরে।

DFS কী তথ্য দেয় পড়ো

DFS interval [enter[u],leave[u]]-এ সব descendant interval থাকে। Forest-এ completed vertex-এর interval হয় nested নয় disjoint। যেমন দুইয়ের 6..7 চারের 5..8-এর ভেতর। সম্পর্ক traversal tree-র, মূল graph-এ শুধু tree edge ছিল এমন দাবি নয়।

এক reached component-এ discovery edge tree বানায়। অন্য দেখা edge আগেই seen vertex জুড়তে পারে। Undirected cycle detect করতে reverse parent edge অন্য visited neighbor থেকে আলাদা চাই। Directed-এ cycle detect-এ শুধু visited boolean নয়, active আর finished state লাগে।

DFS connected component, topological ordering আর cycle analysis-এর ভিত্তি। DAG-এ সব vertex দেখে finish order উল্টালে topological order। Directed cycle থাকলে বৈধ topological order হয় না, তাই ওই ব্যবহারে cycle check-ও চাই।

DFS path সবচেয়ে কম edge নিশ্চিত করে না। Graph শূন্যে দুইকে 0,1,3,5,4,2 দিয়ে পায়, অথচ 0-2 edge আছে। BFS দুইকে distance একে পেত। Exploration structure আর finish তথ্যের জন্য DFS, unweighted minimum-hop route-এ BFS নাও।

সহজ iterative DFS reverse neighbor order-এ vertex push করে visited হলে skip করতে পারে। কাজের discovery order পেলেও recursive return event সরাসরি মেলে না। ঠিক একই entry/exit আর parent resume চাইলে frame পদ্ধতি দরকার।

Active call সীমিত করো, অন্য component-ও ধরো

পুরো forest-এ adjacency-list DFS O(V+E): প্রতি vertex একবার entry, প্রতি adjacency entry একবার দেখা। Visited, event array আর worst-case active stack বাড়তি O(V)। Path-এ একসঙ্গে V call লাগতে পারে, recursive depth সবসময় logarithmic নয়।

Fixed builder আগে matrix নেয়, construction O(V squared), storage rectangular। পরে traversal active neighbor count ধরে। বড় sparse graph-এ সরাসরি compact list বানাও; language call stack শেষ হতে পারলে explicit frame stack নাও।

এক source থেকে no-edge graph-এ এক entry-exit; singleton-ও একই। Complete graph অনেক seen neighbor দেখলেও প্রতি vertex একবার mark। শুধু unseen vertex নতুন frame করে বলে stack capacity যথেষ্ট।

Disconnected graph পেতে search-জুড়ে seen রেখে ID order-এ scan করো। প্রথম unseen নতুন forest root। তৃতীয় উদাহরণে graph শূন্যে দুই component, সাত-vertex no-edge graph-এ সাত। Root-এর মাঝে seen reset করলে পুরোনো component আবার গুনবে।

Child call এখনও হয়নি। Active frame-এর সব neighbor দেখা শেষেই finish লেখো।

Traversal forest-কে মূল graph বলা

Tree edge প্রথম discovery রাখে। মূল graph-এ forest-এ না থাকা cycle আর extra connection থাকতে পারে।

Timestamp implementation যাচাইয়ে কাজে লাগে। প্রতি reached vertex-এ enter ছোট হবে leave-এর চেয়ে। প্রতিটি event number একবার, descendant interval active ancestor-এর ভেতরে। Discovery order ঠিক দেখালেও ভুল early pop ধরা পড়ে।

নির্দিষ্ট recursive trace মেলাতে neighbor order আর marking time দুটোই মেলাও। সব unvisited neighbor একসঙ্গে push করলে বহু দিক থেকে পাওয়া vertex-এর parent আলাদা হতে পারে। এক active frame রেখে এক child করে নামলে iterative আচরণ recursive ব্যাখ্যার সঙ্গে মেলে।
