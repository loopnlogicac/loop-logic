দূরের আগে কাছের vertex দেখো

এক corridor, তারপর দুই, তারপর তিন corridor পেরিয়ে কোন room পাওয়া যায় ভাবো। পরের layer বাড়ানোর আগে কাছেরটি শেষ করবে। Breadth-first search বা BFS first-in first-out কিউ দিয়ে তা করে।

BFS এক source থেকে শুরু। সেখান থেকে পৌঁছানো সব vertex আবিষ্কার করে, সর্বনিম্ন edge count রাখে। Source-এর distance শূন্য। Unreachable vertex-এ minus one থাকে, বৈধ nonnegative hop count-এর সঙ্গে মেশে না।

উদাহরণে শূন্য থেকে ছয় সাত vertex। Neighbor ascending ID-তে দেখা হয়, তাই print order আর parent পুনরায় মেলে। একই দৈর্ঘ্যের অনেক route-এ অন্য neighbor order অন্য shortest route বাছতে পারে। Minimum distance একই থাকবে।

Distance দিয়েই discovery mark

Distance আর parent অ্যারে শুরুতে -1। Nonnegative distance মানে discovered। Source enqueue-এর আগে dist[start]=0 করো। u-এর নতুন neighbor v-তে dist[v]=dist[u]+1, parent[v]=u বসিয়ে কিউতে v যোগ করো।

সাত-cell কিউতে head পরের removal, tail পরের insertion position। প্রতি vertex সর্বোচ্চ একবার ঢোকে, তাই tail সাত ছাড়ায় না। একবারের traversal-এ circular reuse লাগে না। দীর্ঘমেয়াদি কিউ service-এ circular representation বা reset rule চাই।

dist = -1; parent = -1; dist[start] = 0
mark start; enqueue start
while queue not empty: u = dequeue
for each ascending neighbor v: check dist[v]
if undiscovered: dist[v] = dist[u]+1; parent[v] = u; mark v
enqueue v
finish u and append it to order
report distances and parents

শেষ পাঁচ line উপযুক্ত লুপ বা condition-এর ভেতর: neighbor check কিউ লুপ-এ, enqueue undiscovered branch-এ। C brace scope পরিষ্কার করে। Lab একই dist, parent, কিউ আর order নাম ব্যবহার করে, কিউ-তে ঢোকানোর আগেই discovery mark করে।

গ্রাফ শূন্যে source ছয় করো। Lab শুধু ছয়ে শূন্য লেবেল দেয়, এক-entry কিউ চালায়। তারপর গ্রাফ তিন নাও: source থেকেই বাকি সব vertex discovered। Reachable set আর layer আলাদা দেখালেও একই অ্যালগরিদম।

প্রথম discovery কেন shortest route

দরকারি invariant: কিউর সামনে থেকে পেছনে distance কমে না। Distance-d vertex expand করলে শুধু distance-(d+1) যোগ হতে পারে। আগের layer-এর queued vertex নতুনদের আগে থাকে। Source এক distance-zero entry দিয়ে শুরু করে।

v প্রথম u থেকে d+1 পেল, অথচ ছোট route আছে ধরি। সেই route-এ v-এর predecessor-এর distance d-এর কম। BFS আগে সেটি expand করে v পেত। এখন প্রথম discovery কথার বিরোধ, তাই d+1 minimum hop।

প্রতিটি সফল discovery এক parent রাখে। Reachable vertex-এ link-গুলো BFS ট্রি বানায়: source ছাড়া সবার distance এক কম এমন আগের parent। Path পেতে target থেকে -1 পর্যন্ত parent ধরে vertex জমাও। তারপর উল্টে source-to-target প্রিন্ট।

dist[target] -1 হলে source থেকে route নেই। তার -1 parent-কে অ্যারে index কোরো না। Target source হলে path-এ শুধু সেই vertex, edge শূন্য। একাধিক shortest route-এ ascending neighbor একটি consistent parent বাছে, সব route দেয় না।

সব edge-এর সমান cost-এ BFS hop কমায়। Unequal weight-এ অন্য অ্যালগরিদম চাই। BFS দ্রুত পেলেই প্রথম weighted route-এ থামা নিরাপদ নয়। Directed adjacency list-এ শুধু outgoing neighbor ধরা যাবে।

Traversal আর construction খরচ আলাদা

Adjacency list-এ প্রতিটি reachable vertex একবার কিউতে ঢোকে-বেরোয়। পৌঁছানো vertex-এর প্রতিটি adjacency entry একবার দেখা হয়; undirected-এ প্রতি reached edge দুইবার। অ্যারে initialization-সহ traversal O(V+E), distance, parent আর কিউ-তে বাড়তি O(V) জায়গা।

Builder ছোট matrix দিয়ে sorted অ্যারে-backed neighbor list বানায়। তৈরির সময় O(V squared), rectangular অ্যারের reserved cell O(V squared)। bfs helper শুধু active neighbor count ধরে। Helper-এর traversal খরচ আর পুরো bounded প্রোগ্রামের setup ও reserved storage আলাদা বলো।

Empty গ্রাফে আলাদা no-source policy লাগে; উদাহরণে সবসময় সাত vertex আর বৈধ source চাই। Edge না থাকলেও গ্রাফ বৈধ, শুধু source-এ পৌঁছায়। Complete গ্রাফ কিউতে একসঙ্গে V-1 neighbor তুলতে পারে, কিন্তু discovery-তে marking overflow ঠেকায়।

Undirected গ্রাফের সব component পেতে বাইরের ID লুপ-এ এখনও undiscovered vertex থেকে BFS শুরু করো। Run-জুড়ে visited অ্যারে একই রাখো। Search-গুলো forest হয়। এক source search ইচ্ছা করেই অন্য component অছোঁয়া রাখে, গ্রাফ শূন্যের ছয়-সহ।

প্রথম আগমনের অর্থ রাখো

শুধু dequeue-তে mark

দুই আগের vertex একই neighbor-কে কোনো copy সরার আগেই enqueue করতে পারে। প্রথম distance বসানোর সময় enqueue-এর আগে mark করো।

প্রতি দেখা হলে parent বদল

পরে edge পাওয়া নতুন discovery নয়। বাছা shortest-hop ট্রি স্থির রাখতে প্রথম parent রাখো।

Parent walk সামনের দিকে প্রিন্ট

Parent source-এর দিকে যায়। চাওয়া source-to-target দিক দেখাতে জমা sequence উল্টাও।

সমান shortest route অনেক হলে এক parent শুধু এক উত্তর রাখে। সব shortest predecessor চাইলে distance এক কম এমন incoming discovery-র list রাখো। শুধু route count চাইলে আলাদা count-এ equal-layer contribution যোগ করা যায়। বাড়তি state আর নিজস্ব numeric overflow limit লাগবে।

Stopping rule প্রশ্নের ওপর। এক target-এর distance প্রথম discovery-তেই স্থির। পুরো distance table বা component চাইলে কিউ ফাঁকা পর্যন্ত চলো। উদাহরণে unreachable vertex আর সব parent choice দেখাতে পুরো source search শেষ হয়।

C17 কিউ আর parent অ্যারে

সবসময় সাত vertex বলে fixed অ্যারে। C17-এ built-in কিউ type নেই। Head আর tail dynamic allocation ছাড়া traversal কিউ বানায়।

FIFO ক্রম distance-এর ক্রম হয়

BFS কিউ দিয়ে layer ধরে search করে, minimum hop আর parent path দেয়। Visited rule প্রতিটি vertex-এর কিউ entry unique রাখে। এর সঙ্গে depth-first search তুলনা করো, যা ফেরার আগে এক শাখা ধরে এগোয়।
