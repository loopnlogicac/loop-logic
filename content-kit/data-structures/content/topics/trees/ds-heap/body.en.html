Keep the next maximum at the front

A contest organizer repeatedly awards the highest remaining score. Sorting every score after every new arrival wastes work. A binary heap keeps the most extreme key at a known location while allowing efficient insertion and removal. You only order each parent against its children.

A max heap places the greatest key at its root. A min heap reverses every comparison to keep the smallest there. Both require a complete binary shape, so an array can store the active nodes without gaps. This lesson implements a max heap and keeps duplicate scores as separate entries.

The priority queue is the interface; the heap is one implementation. A heap does not provide the BST rule about all left keys being smaller. You should not choose left or right to search for an arbitrary key based on a single root comparison.

Two rules make an array heap

Rule one is shape: active positions occupy indices zero through n-1. Rule two is max ordering: every parent key is at least each child key. With zero-based numbering, parent(i)=(i-1)/2 for positive i. Left and right child positions are 2*i+1 and 2*i+2.

The C insertion line stores the key at heap[n], calls sift_up with that index, then increments n. Sift-up needs only the index and ancestors, so it does not require the new count. The lab array reducer increases its active length when it appends. Both perform the same comparisons and swaps.

Repair only the disturbed path

Appending preserves completeness but may break ordering between the new leaf and its parent. Compare those keys. If the parent is already at least as large, stop. Otherwise swap them and continue at the parent index.

Only the upward path can be wrong. Existing child subtrees were heaps before insertion. When a larger key rises, it still dominates those child roots. Sift-up therefore needs at most the tree height, O(log n), comparisons and O(1) working storage.

Removing the maximum starts by saving heap[0]. Move the last active key to that root position and shrink n. This preserves the complete shape, but the replacement may be smaller than either child. Compare existing children and choose the larger one.

Before remove: array=[12,10,8,7], n=4
Save 12; replace root with last 7; shrink
Temporary:     array=[7,10,8], n=3
Choose 10; swap root and index 1
After remove:  array=[10,7,8], removed=12

Swap only when the chosen child is greater than the current key. If the parent already dominates the greater child, it also dominates the other child, so stop. When child keys tie, the code chooses the left child. That tie rule helps the lab and C example produce the same array layout.

Sift-down visits one downward path and uses O(log n) time with O(1) auxiliary space. Peek reads the root in O(1), after checking that n is positive. Searching for an arbitrary non-root key may require O(n) inspection because heaps do not order sibling subtrees against each other.

To build a heap from an arbitrary array, begin at the last internal index n/2-1. Sift that node down, then process earlier indices backward. Every child subtree is already a heap when its parent is processed. Leaves need no work because they have no child comparisons to violate.

Linear construction and reversed comparisons

It is tempting to multiply n nodes by a log n height bound and call bottom-up construction O(n log n). That is an upper bound but misses the actual distribution of work. About half the nodes are leaves and move zero levels. About a quarter can move only one level.

At increasing heights, the number of eligible nodes falls geometrically. The total downward distance is bounded by n times the series 1/4+2/8+3/16 and further terms. That series has a constant sum. Including leaf and comparison overhead gives O(n) construction time.

Repeated insertion is a separate construction method. It has O(n log n) worst-case time because later inserted leaves may rise through many levels. It is useful for a stream, where values arrive gradually. Bottom-up construction is preferable when the whole initial array is already available.

For a min heap, choose the smaller child during sift-down and swap upward when a key is smaller than its parent. The shape and index formulas stay the same. The root then supplies delete-min rather than delete-max. Do not reverse only one routine and leave the rest using max comparisons.

A priority queue may attach an arrival sequence to each entry to break equal-priority ties. This integer heap does not promise FIFO ties. Equal values remain valid entries but carry no separate identity. Use a compound comparator if your application needs stable service among equal priorities.

Empty, singleton and full storage

An empty heap has no root to inspect or remove. A singleton removal saves its only key and makes n zero; no downward comparison follows. If the input array has fixed capacity and n equals that capacity, insertion must report full before writing heap[n]. That boundary belongs to storage, not to the abstract priority rule.

These examples reserve sixteen cells, read at most twelve initial keys and append at most one key. That proves capacity before insertion. The zero-length input still accepts the one inserted key. Removing it immediately produces an empty active array.

The final inactive cell may still contain an old value in C. Only indices below n belong to the heap. The lab removes that displayed slot entirely, so its active values match the C prefix. No logic uses a spare cell's contents as an emptiness marker.

Preserve both shape and ordering

Taking a BST-style deletion path

A heap cannot replace its root with an inorder successor and leave an arbitrary hole. Move the last active value and shrink the end. This keeps complete-tree indexing valid.

Always swapping with the left child

The right child may be larger. Swapping with the smaller child can leave the new parent below its sibling immediately. Select the greater existing child before testing the current key.

Using an unsigned backward build loop

An unsigned index can wrap after zero. The example counts i down while positive and repairs i-1. That handles n zero or one without computing a negative active index.

C17 array bounds

The heap routines use portable C17 integer indices. Their small fixed bounds keep child arithmetic safe. In a much larger heap, ensure that computing 2*i+1 cannot overflow the index type before you compare it with n.

A partial order is enough for extremes

Complete shape packs a heap into an array, while parent dominance keeps its maximum at the root. Sift operations repair one path, and bottom-up construction shares work across levels. Next, expression trees use children to represent evaluation dependencies.
