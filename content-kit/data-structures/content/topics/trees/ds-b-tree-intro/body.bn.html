Search-এ কম page পড়ো

Disk index-এ লাখ লাখ roll-number record থাকতে পারে। আগে মেমরিতে থাকা কয়েকটি key তুলনার চেয়ে storage থেকে page আনার খরচ অনেক বেশি। B-ট্রি প্রতিটি চওড়া নোডে বেশ কয়েক key আর child link রেখে search path-এর page সংখ্যা কমায়।

কয়েকটি interval লেখা directory page ভাবো। এক page-ই বলে দিতে পারে অনেক ছোট directory-র কোনটি খুলবে। Binary ট্রি প্রতি নোডে শুধু দুই child interval বাছে। বড় storage page-এ শুধু এক key রাখলে height কমানোর সুযোগ নষ্ট হয়।

B-ট্রি সব leaf একই depth-এ রাখে আর নোড কতটা ফাঁকা হতে পারে সীমা দেয়। এতে কাজে লাগার মতো fan-out নিশ্চিত। B+ ট্রি record রাখার জায়গা বদলে range scan-এর জন্য leaf জোড়ে। দুটোই চওড়া নোড ব্যবহার করে, তবে separator-এর আচরণ আলাদা।

এই পরিচয়ে দুই নকশা ব্যাখ্যা আর ছোট সম্পূর্ণ B-ট্রি insertion প্রোগ্রাম আছে। Production disk pager বা B+ insertion বানানো হয়নি। শেষ উদাহরণে range scan আলাদা বোঝাতে fixed B+ leaf layout। তুলনার সময় এই পরিসর মনে রাখো।

সূত্রের আগে order-এর অর্থ বলো

বইয়ে order-এর অর্থ আলাদা হতে পারে। এখানে order m মানে এক নোডের সর্বোচ্চ child সংখ্যা। Internal node-এ k sorted key থাকলে k+1 child interval। তাই সর্বোচ্চ key m-1।

প্রচলিত order-m সংজ্ঞায় non-root internal node-এ অন্তত ceil(m/2) child। তাই non-root page-এ অন্তত ceil(m/2)-1 key। Root-এ কম key চলবে, তবে non-leaf root-এ অন্তত দুই child চাই। সব leaf একই depth-এ।

চালানো উদাহরণ minimum-degree নিয়ম t=2 মানে। Non-root node-এ t-1 থেকে 2t-1 key, internal node-এ t থেকে 2t child। সর্বোচ্চ fan-out চার, এখানে order চার-এর সমান। অর্থ না বদলে সূত্রে m-এর জায়গায় t বসিও না।

এক internal page: [10 | 20]
Child 0: keys < 10
Child 1: 10 < keys < 20
Child 2: keys > 20
           [10 | 20]
          /    |     \
       [5,6] [12,17] [25,30]
তিন child leaf-এর depth একই।

C-র BNode-এ count, leaf flag, তিন key আর চার child index-এর জায়গা। Fixed arena-তে বত্রিশ এমন record। সর্বোচ্চ বারো distinct insertion বলে এই ছোট উদাহরণের চেয়ে arena-তে বেশি জায়গা আছে। Page index-এর আড়ালে dynamic allocation নেই।

Interval খোঁজো আর ভরা page ভাগ করো

Page search-এ sorted key scan করো যতক্ষণ query পরের key-র বড়। সমান হলে ওই page-এ B-ট্রি key পাওয়া যায়। সমান না হলে থামার অবস্থান child interval বলে। Leaf-এ সমান না পেলে key absent।

10 আর 20 key-র page query 17-কে child interval একে, 25-কে দুইয়ে পাঠায়। শেখানোর কোড ছোট page-এর key linear scan করে। বড় page-এ CPU comparison কমাতে ভেতরে binary search করা যায়।

Insertion page-এর সাজানো key আর সমান leaf depth রাখবে। t=2 implementation ভরা তিন-key node-এ নামার আগেই split করে। [5,10,20] হয় left [5], ওপরে ওঠা key 10 আর right [20]। Promoted key parent-এ দুই নতুন child link-এর মাঝে যায়।

Root split-এর আগে: root ---> [5 | 10 | 20]

Root split নতুন root-এ এক key আর দুই child বানায়। আগের সব leaf একসঙ্গে এক level নামে। Non-root child split তার parent-এর শুধু এক page interval বদলায়। ট্রি কখনো শুধু এক leaf path লম্বা করে না।

Internal full page-এ key-র সঙ্গে child link-ও ভাগ করো। পুরোনো page নিচের দুই interval রাখে, sibling ওপরের দুইটি পায়। Middle key ওপরে ওঠা range-গুলো আলাদা করে। Child না সরালে প্রিন্টের root key ঠিক দেখালেও পুরো subtree হারাতে পারে।

split_child আগে sibling তৈরি করে, middle key রাখে, পুরোনো count কমায়। জায়গা করতে parent-এর পরের child index আর key ডানে সরায়। তারপর নতুন sibling link আর promoted key ঢোকায়। শুরুতেই parent-এ spare capacity থাকতে হবে।

Insertion-এর শুরুতে key আগেই আছে দেখে। সমান key set বদলায় না, split-ও করে না। নতুন key-তে full root split করে non-full শুরুর page পাওয়া যায়। পরে নামার প্রতিবার full child ঢোকার আগেই split, তাই insert_nonfull সবসময় spare room পায়।

Leaf-এ বড় key এক অবস্থান ডানে সরিয়ে ফাঁকে নতুন key রাখো। Internal page-এ child interval বেছে নাও। Split-এ ওপরে ওঠা key নতুন key-র ছোট হলে নতুন right sibling-এ, না হলে পুরোনো left half-এ নামো।

ছোট page index চালাও

প্রথম উদাহরণে সম্পূর্ণ t=2 insertion, split আর ordered traversal। দ্বিতীয়টি ওই page-এ membership search করে। তৃতীয়টি আগে তৈরি leaf chain-এ B+ range scan দেখায়; insertion দিয়ে chain বানানোর দাবি করে না।

নামার আগে full node split করো

Minimum degree দুইয়ে প্রতি নোডে তিন key চলে। Full root split-এ middle key ওপরে ওঠে, height বাড়ে।

প্রতি page-এর কয়েক key-তে search

17-এর child interval বাছার আগে search page-এর প্রতিটি sorted key-র সঙ্গে তুলনা করে।

ছোট B+ layout-এ leaf-chain range scan

Separator 10 আর 20 শুরুর leaf বাছে। তারপর root-এ না ফিরে next link ধরে 7, 10, 12, 17 আর 20 দেয়।

B-ট্রি record আর B+ leaf record

এখানকার B-ট্রি-তে leaf-এর মতো internal page-এর key-ও record বোঝাতে পারে। Internal page-এ সমান পেলেই search শেষ হতে পারে। তাই পুরো ordered traversal-এ child traversal-এর মাঝে internal key প্রিন্ট করতে হবে। শুধু leaf দেখলে promoted record বাদ যাবে।

এখানকার B+ নিয়মে পুরো ডেটা record leaf-এ থাকে। Internal key routing separator, সাধারণত নিচের boundary key-র copy। Internal separator সমান হলেও lookup leaf পর্যন্ত যায়। Exact separator rule বদলাতে পারে, তাই বাস্তব implementation-এ equality কোন interval-এ যায় বলতে হবে।

আগে বানানো B+ routing page: [10 | 20]
        /                    |                    \
[5,6,7] --next--> [10,12,17] --next--> [20,30] --next--> NULL
Range [7,20]-এর আগে: separator দিয়ে প্রথম leaf বাছো
Scan-এর পরে: output=[7,10,12,17,20], key 30-এর আগে থামো
কোনো page key বা leaf link বদলায়নি।

B+ scan উদাহরণে separator পরের leaf-এর minimum key। 10-এর ছোট query প্রথম leaf-এ, 10 থেকে 20-এর নিচে দ্বিতীয়তে, অন্তত 20 হলে তৃতীয়তে শুরু করে।

দুই সীমা-সহ inclusive range scan-এ আগে lower-bound leaf খোঁজো। নিচের সীমার ছোট key বাদ দিয়ে মেলা record দাও, তারপর next ধরো। ওপরের সীমা ছাড়ালেই থামো। পরপর প্রতিটি record-এর জন্য root-এ ফিরতে হয় না।

B+ leaf split সাধারণত record key leaf-এ রেখে separator ওপরে copy করে। আগের B-ট্রি split middle key child page থেকে সরিয়ে parent-এ নেয়। দুই কাজ মেশালে record হারাতে বা duplicate হতে পারে। Page-এর ছবি কাছাকাছি হলেও এই পার্থক্য বেশি জরুরি।

Height, কতটা ভরা আর resource সীমা

Minimum fan-out t অন্তত দুই হলে height O(logt n)। Search-এ তত page level লাগে। CPU কাজ page-এর ভেতরের search পদ্ধতিতেও নির্ভর করে। Linear scan-এ O(t logt n); fixed page capacity constant ধরলে n-এর হিসাবে logarithmic।

Insertion এক নিচের পথ ধরে, পথে page split হতে পারে। Split-এ O(t) key আর link সরে, তাই CPU খরচে একই capacity factor। রিকার্সিভ call space ট্রি height-এর সমানুপাতে। Fixed minimum degree আর occupancy নিশ্চয়তায় রাখা page-এর মোট key capacity O(n)।

ফাঁকা উদাহরণে count শূন্যের এক leaf root। প্রথম key তাতে ঢোকে, child page বানায় না। Insertion-এর আগে full root বৈধ; পরের distinct key এলে split হয়। Root-এর occupancy ব্যতিক্রম ছোট বৈধ ট্রিকে non-root নিয়ম ভাঙা থেকে বাঁচায়।

Production page allocator-এ storage ভরলে failure policy লাগে। Fixed arena উদাহরণ বারো insertion থেকে ছোট capacity bound প্রমাণ করে, ফাইল I/O করে না। Key range বড় হলে page count বদলায় না; insertion সীমা বড় করলে arena bound আবার দেখতে হবে। Demonstration capacity-কে সাধারণ B-ট্রি সীমা বলবে না।

Deletion minimum occupancy ফেরাতে sibling থেকে key ধার বা page merge করতে পারে। সেগুলো এই insertion পরিচয়ের বাইরে। সাধারণ BST deletion wide-page occupancy রাখে না। একইভাবে leaf split বা merge হলে B+ leaf chain মেরামত লাগে।

B+ range query-তে শুরুর নামার পরে qটি leaf page scan হলে page read O(h+q)। Result stream করলে cursor storage O(1)। CPU খরচে দেখা আর দেওয়া key-ও ধরতে হবে। B-ট্রি range practice বরং সব page ক্রমে হাঁটে: O(n) সময় আর O(h+1) রিকার্সিভ space, B+ leaf link ব্যবহার করে না।

Page-এর নিয়ম পরিষ্কার রাখো

Order আর minimum degree একইভাবে ব্যবহার

এখানে order চার আর minimum degree দুই একই সর্বোচ্চ capacity বোঝালেও সংখ্যার অর্থ আলাদা। সংজ্ঞার পাশে max children আর max keys লেখো। অন্য বইয়ে শব্দ আলাদা হলেও পরীক্ষার উত্তর বোঝা যাবে।

B+ record leaf থেকে সরানো

বেছে নেওয়া B+ নিয়মে সব record leaf layer-এ চাই। Internal separator routing copy। B-ট্রির middle-key move অপরিবর্তিত B+ leaf split-এ চলে না।

আগেই full parent-এ split করা

split_child parent-এ এক key আর এক child link ঢোকায়। Top-down অ্যালগরিদম parent non-full রাখে। এই invariant না থাকলে shift-এ page capacity ছাড়িয়ে লেখা হবে।

C17 page index

B-ট্রি মডেল C17 অ্যারে আর integer child index ব্যবহার করে। Index মেমরি page-এর সম্পর্কের অনুকরণ, আসল disk address নয়। Fixed arena-র lifetime process-এর সঙ্গে; free লাগে এমন হিপ record নেই, filesystem page size ধরেও নেয় না।

চওড়া নোড storage-level depth কমায়

B-ট্রি page occupancy আর split দিয়ে সব leaf একই depth-এ রাখে। B+ ট্রি linked leaf-এ record রেখে range-কে পরপর এগোতে দেয়। পরের trie সংখ্যার key তুলনার বদলে character দিয়ে search path সাজায়।
