Prevent an ordered tree from becoming a chain

Insert increasing roll numbers into an ordinary BST and every new number extends the right branch. Searches gradually resemble a linked-list walk. An AVL tree keeps the BST ordering rule while repairing large height differences near the insertion path.

Picture a shelf that becomes heavy on one side. Instead of sorting every item again, you move a few supporting links. In an AVL tree those local moves are rotations. They change roots and depths while preserving the left-to-right key order.

This lesson implements insertion with rebalancing. It builds on BST insertion and the owner-link ideas from deletion. AVL deletion needs additional rebalancing rules and is outside this insertion lesson. Ordinary BST deletion must not be applied unchanged while expecting AVL balance to survive.

The cache here measures height in nodes: a missing subtree has height zero and a leaf has height one. This differs from the edge-height measurements introduced earlier. Adding one to every nonempty subtree height does not change the balance difference, provided both children use the same convention.

Cache height and define balance

int left_height = height(root->left);
int right_height = height(root->right);
root->height = 1 + (left_height > right_height ? left_height : right_height);
int balance = left_height - right_height;

The balance factor is left height minus right height. Values -1, zero and 1 are allowed at every node. A positive value means the left side is taller. The Node record adds a cached height field to its key and two child pointers.

Cached height lets an update inspect two child fields in O(1) time. Recomputing each subtree height from scratch would repeatedly visit many records. Correct caching therefore belongs to the algorithm, rather than being a cosmetic optimization. Every changed subtree must report an updated height to its parent.

insert(root, key):
    perform distinct-key BST insertion
    update root.height after its child returns
    balance = height(left) - height(right)
    if left-heavy: straighten LR if needed, then rotate right
    if right-heavy: straighten RL if needed, then rotate left
    return the repaired local root

Four cases, two rotation directions

Follow the insertion path upward after creating a leaf. A node may become left-heavy with balance 2 or right-heavy with balance -2. The next turn toward the inserted key identifies a straight path or a bent path. These become LL, RR, LR and RL.

Save x and its right subtree B before changing links. Move B to y.left first, then link y as x.right. All A keys remain below x; B keys stay between x and y; C keys remain above y. This interval argument proves that inorder stays unchanged.

After rewiring, update y before x. Node y is now lower, and x's new height depends on y's new height. Reversing those updates can preserve a stale height even when the visible shape looks correct. Return x because it is the local subtree's new root.

Left rotation for RR

Before:        x=10               After:          y=20
              /    \                            /    \
             A     y=20                       x=10    C
                   /  \                      /  \
                  B    C                     A    B
Pointer moves: middle=y.left; x.right=middle; y.left=x
Return y, then reconnect its incoming owner link.

A left rotation is the mirror operation. The right child rises and the old root moves left. Its middle subtree B transfers to the old root's right link. Again update the old root first, then the new root.

Double rotations for bent paths

LR before: 30.left=10; 10.right=20
First:     rotate_left(10) -> 30.left=20; 20.left=10
Second:    rotate_right(30)
LR after:  root=20; 20.left=10; 20.right=30
RL before: 10.right=30; 30.left=20
First:     rotate_right(30) -> 10.right=20; 20.right=30
Second:    rotate_left(10)
RL after:  root=20; 20.left=10; 20.right=30

For LR, a single right rotation would leave the inner branch too tall. First rotate the left child left to turn the bend into a straight LL arrangement. Then rotate the original root right. RL performs the symmetric pair.

The three-key examples make every transferred middle subtree empty. In larger trees, those middle subtrees may contain many nodes. Save and reconnect them exactly as in the rotation functions. A rotation moves only a constant number of pointers regardless of the number of records below those pointers.

Why the height is logarithmic

Let N(h) be the fewest nodes in an AVL tree of node height h. To reach height h with as few nodes as possible, one child has height h-1. The other can be only one level shorter, so its height is h-2. Include the root to get N(h)=1+N(h-1)+N(h-2).

The base values are N(0)=0 and N(1)=1. The next values are 2, 4, 7, 12 and 20. This Fibonacci-like growth is exponential in h. Turning the relationship around makes h logarithmic in the number of stored nodes.

You do not need an exact logarithm constant to use the guarantee. A path has O(log n) nodes, so searching and inserting take O(log n) time. Recursive insertion uses O(log n) active calls. The tree itself uses O(n) records, each with one extra height field.

One insertion can make several ancestors look taller while the call stack unwinds. Rebalancing the lowest unbalanced ancestor restores that subtree's previous height. Therefore at most one rebalancing location needs rotation for a single AVL insertion, using one or two rotations. Higher ancestors still receive their returned child pointers and updated caches.

The code checks for imbalance while unwinding every ancestor rather than stopping through a separate flag. This keeps the recursive structure easy to follow. Its asymptotic time remains logarithmic because the path length is logarithmic. A single rotation costs O(1) local time and O(1) extra pointer storage.

Contrast that with repeatedly computing recursive heights from scratch during insertion. Even though the final tree may be balanced, those repeated scans can add much more work. Cached child heights make each ancestor update constant time. The guarantee assumes those cached values are correct after every operation.

Duplicates, allocation and ownership

Insertion into an empty tree creates a leaf with height one. Inserting the same key again returns that record without increasing the count. There is no fixed full boundary for linked AVL storage. If allocation fails, the ok flag prevents rebalancing incomplete work and the caller destroys the retained tree.

A failed allocation happens at an empty child link. Returning NULL there does not replace a populated subtree. Existing ancestor records remain reachable, so cleanup can release them. The example programs treat failure as an unsuccessful run rather than claiming a new key was inserted.

Rotations do not allocate or free records. A successful distinct insertion allocates one leaf, even when a double rotation follows. At program end, postorder cleanup frees each record once. Stored pointers to node records remain addresses of those records, although their parents and depths may change.

Balance alone does not prove the BST property. A malformed tree could have perfectly even heights and misplaced keys. Review both facts: inorder must match the distinct input set, and every node must have correct height and allowed balance. The valid routine checks the cache and balance; insertion's comparison rule preserves ordering.

Do not lose the middle subtree

Linking the old root below its child too early

If you overwrite x.right before saving it during a right rotation, the middle subtree can become unreachable. Save middle first. The diagram's three named subtrees show exactly which pointer must survive each assignment.

Choosing a rotation by the root comparison alone

Left-heavy does not distinguish LL from LR. Inspect the insertion direction relative to the left child. A bent path needs its child rotation before the final root rotation.

Keeping the former local root in its parent

A rotation's return value identifies the new subtree root. Assign it into the parent child field, or into the caller's root variable. Correct local links still form an incomplete repair if the owner keeps the former root.

Mixing zero-height and one-height leaf caches

The C helper treats NULL as height zero and leaves as height one. Initialize new records accordingly. Subtracting heights from inconsistent conventions can trigger a rotation when none is needed.

C17 height fields

The AVL implementation uses C17 structs, pointers and ordinary integer arithmetic. Heights are small under the bounded input. No compiler feature maintains a height cache automatically; every update and returned-root assignment is part of your algorithm.
