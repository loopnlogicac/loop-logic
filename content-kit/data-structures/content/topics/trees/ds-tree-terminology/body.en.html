Describe the shape before writing code

Think about a university folder containing departments, courses and individual class notes. You can reach each note by following one route downward. A tree describes that kind of hierarchy using nodes and connecting edges. You will use its vocabulary to explain memory pictures before choosing an implementation.

A tree does not require sorted numbers. The folder example has relationships, but no rule saying a smaller name belongs on the left. A binary search tree adds that ordering later. First learn to describe a shape without making assumptions about its stored values.

In this track, a rooted tree has a chosen starting node. Every other node has exactly one parent, and every node is reachable from the root. There are no cycles. Following child links must eventually reach a node with no children.

A node can have degree zero, one or two in a binary tree. The degree of the whole tree is the largest node degree. Do not count a node's parent as one of its children. That would measure a different quantity used for undirected graphs.

Levels, heights and binary shapes

A binary tree gives each node two named positions: left and right. A position may be empty. A node with only a right child differs from one with only a left child, even when both store the same keys.

Depth starts at zero for the root. Moving through one child link increases depth by one. Height works in the opposite direction: a leaf has height zero. An internal node has one plus the larger child height.

Our measurement examples give an empty subtree height -1. That makes a leaf calculation read one plus the maximum of -1 and -1. Some implementations count nodes on the longest path instead. Under that convention, empty height is zero and leaf height is one.

A full binary tree has either zero or two children at every node. A complete binary tree fills every earlier level and packs its final level from left to right. These describe different facts. A root with only a left child is complete but not full.

A perfect binary tree fills every level completely. All its leaves share one depth, and each internal node has two children. A skewed tree forms a chain. Its height can become nearly its total number of nodes.

At depth d, a binary tree has at most 2d nodes. Start with one root; every node can supply at most two children. Adding the level capacities through edge height h gives at most 2h+1-1 nodes. A perfect tree reaches that bound.

A nonempty tree with n nodes has n-1 edges. Count one incoming edge for every node except the root. In a full binary tree with I internal nodes, those same edges number 2I. Therefore n=2I+1 and the leaf count is I+1.

For a binary tree with n positive nodes, the minimum possible edge height is ceil(log2(n+1))-1. Its maximum is n-1, achieved by a chain. These limits explain why shape affects search time. The same node count can occupy a short broad tree or a long narrow one.

Empty and single-node trees

The empty tree has zero nodes and no root record. Its leaf count is zero. A single-node tree has one leaf, degree zero and edge height zero. It is full, complete and perfect under the usual empty-child definitions.

Counting nodes, leaves or height visits every existing node, so each takes O(n) time. Recursive measurement uses O(h+1) active calls. On a chain, that can be O(n) extra space. A fixed maximum of twelve nodes keeps the instructional programs small; general applications need deeper-input safeguards.

Avoid ambiguous descriptions

Calling every leaf a bottom-level node

A leaf has no children, even if another branch extends farther down. In the full, noncomplete picture, B is a leaf above D and E. Test its links instead of comparing its depth with the tree height.

Mixing height conventions

Writing height two without a convention can lose a mark in a tracing answer. State whether you count edges or nodes. This lesson uses edges; the later AVL cache and lab player use node height.

Applying the perfect formula to every shape

Six nodes can have height two, but a perfect tree of that height needs seven. Use the formula as an upper bound unless perfection is given. For a full tree, use the internal-node relationship instead.

C17 arithmetic and measurements

These examples use C17 without compiler extensions. Small bounded heights keep repeated doubling within the chosen unsigned type. Do not translate 2 raised to h into 2 ^ h: C uses that operator for bitwise XOR.
