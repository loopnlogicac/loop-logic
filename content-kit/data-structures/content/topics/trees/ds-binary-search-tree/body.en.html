Turn comparisons into directions

Suppose you keep roll numbers in a tree and want to find one quickly. At each box, a smaller target sends you left and a larger target sends you right. A binary search tree, or BST, makes that decision safe by keeping every subtree within known key bounds.

The rule applies to whole subtrees. Every key below a node's left link must be smaller than that node's key. Every key below its right link must be larger. This lesson stores unique integer keys, so inserting an equal key leaves the tree unchanged.

A BST is a binary tree with an extra ordering rule. It does not promise a complete shape or a small height. You should already know inorder traversal and linked child pointers. Here you will connect those ideas to search, insertion and neighboring-key queries.

State the key policy and ownership

search(root, key):
    while root exists and root.key differs from key:
        root = root.left if key is smaller, otherwise root.right
    return root
insert(root link, key):
    follow the same comparisons
    equal: keep the existing node
    empty link: allocate and initialize a leaf, then publish it

The root link belongs to the caller. Recursive insertion receives its address, so it can fill an empty root as well as a child link. Iterative insertion uses a pointer to the current owner link. Moving that pointer does not move tree nodes; it chooses which link may receive a new leaf.

Before inserting 6:         After inserting 6:
        [8]                         [8]
       /   \                       /   \
     [3]   [10]                   [3]   [10]
       \                            \
       NULL                         [6]
Path bounds at new leaf: 3 < key < 8
New record: [key=6 | left=NULL | right=NULL]

The new key 6 must be greater than 3 and smaller than 8. Checking only its immediate parent would miss the upper bound. Following comparisons from the root preserves both constraints automatically. A later arbitrary key change could break them, so ordinary BST insertion never rewrites unrelated keys.

Search and insert along one path

Start a search at the root and compare the target with its key. Equality finishes successfully. For a smaller target, discard the entire right subtree because all of its keys are larger than the root. A larger target similarly discards the left subtree.

In the example tree, searching for 6 visits 8, then 3, then 6. Searching for 7 shares that path, then reaches 6's empty right link. The missing link proves absence within the surviving interval. It does not mean the whole tree was empty.

Recursive search expresses those same cases as function calls. Its base case handles NULL or equality. The recursive case passes exactly one child, so it never scans both subtrees. Iterative search avoids recursive call storage and keeps only a current pointer.

Insertion follows a search for the new key. An existing match requires no allocation because this tree represents a set. At an empty link, allocate a Node and initialize both child pointers to NULL. Publish that pointer only after initialization succeeds.

If allocation fails, insertion reports failure and preserves every previously stored key. The program then destroys its existing tree before returning. A failed attempt does not justify overwriting the owner link with a partly initialized record. The C examples check each insertion result.

The lab inserts input.values in the supplied order and then searches input.key. Its comparison path matches example one's recursive insertion and iterative search. The found value is one for a match and zero for absence. The comparison count includes the matching node when a search succeeds.

For edge height h, search and insertion visit at most h+1 stored nodes. Their time is O(h+1). Recursive versions require O(h+1) call space; iterative versions use O(1) extra space. A successful insertion adds one record, while a duplicate adds no storage.

Building n keys through repeated insertion can take O(n squared) time on increasing unique input. With a reasonably balanced shape it takes O(n log n). Do not claim the second bound for every ordinary BST. The structure itself has no rotation rule to guarantee balance.

Minimum, maximum and strict successor

The minimum stored key lies at the farthest reachable left link. If a node has a left child, that entire subtree contains smaller keys. Continue until the left link is NULL. A maximum query follows right links by the symmetric argument.

An empty tree has neither minimum nor maximum. Return NULL and let the caller print a clear empty result. Do not use zero or -1 as a missing key because either may be valid data. The examples inspect returned pointers before reading their keys.

A successor is the smallest stored key strictly greater than a query. The query need not already be present. Whenever the current key is larger, save it as a candidate and continue left. When the current key is not larger, move right without replacing the candidate.

Successor of 8:
        [8] --right--> [10] --left--> [9]
Before descent: candidate=NULL
At 10: candidate=10, move left
At 9:  candidate=9, move left to NULL
After descent: result=9; no links changed

For a stored node with a right subtree, its successor is that subtree's minimum. Without a right subtree, a larger ancestor may supply the answer. The candidate method handles both situations using the root path. If the query is at least the maximum key, the candidate remains NULL.

Minimum, maximum and successor each take O(h+1) time and O(1) extra space in these loops. Range counting can visit many nodes because it may need both children. Pruning helps when an entire subtree falls outside the interval, but worst-case work is still O(n).

Shape is part of the performance answer

An empty search performs zero stored-node comparisons. A singleton matches in one comparison or follows one missing link. There is no fixed full state for the linked BST; available memory limits growth. The twelve-key input bound belongs to these programs, rather than to the BST definition.

Try inserting 1,2,3,4,5. Each new key follows every previous key to the right, producing edge height four. Inserting 3,1,5,2,4 gives a shorter shape with the same set. Inorder prints 1 through 5 in both cases, so sorted output alone cannot reveal performance.

A search result pointer refers to an owned tree record. It stays usable while that record remains alive. Later deletion can invalidate it. This is one reason a key-returning interface may be easier for callers that do not need direct access to node fields.

Do not weaken the subtree rule

Placing duplicates without a declared policy

Some BSTs count equal keys in a record; others consistently put them on one side. This lesson instead ignores duplicates. Mixing policies makes search and deletion disagree, so keep set semantics in every routine here.

Allocating before detecting equality

A duplicate should not leave an unused allocated record. Search first and allocate at the empty endpoint. If you choose early allocation in another design, every no-insert path must release the spare node.

Assuming one comparison halves the remaining nodes

A chain can discard an empty subtree at every step. Halving depends on shape, not merely on the word binary. State the height before converting O(h+1) into a bound in n.

C17 pointer updates

The recursive and iterative routines are portable C17. Passing a pointer by value cannot change the caller's root variable. Use a returned root or a pointer to the actual owner link when an operation can replace it.

Ordering narrows the work

A BST turns ancestor bounds into safe search directions. Insertions preserve those bounds, while shape determines the path length. Continue with BST deletion to remove records without losing their surviving subtrees.
