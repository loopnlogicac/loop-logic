Make grouping visible as child links

The expressions (8-2)*3 and 8-(2*3) contain the same digits and operators, but produce different answers. Their grouping determines which work must happen first. An expression tree stores that grouping directly: operands become leaves, and operators become parents of the values they combine.

Instead of memorizing precedence while evaluating, follow the links. Each binary operator has a left operand subtree and a right operand subtree. Those positions matter for subtraction. A multiplication node may combine two whole expressions rather than only two digit leaves.

This lesson starts with postfix input, which you saw in postfix evaluation. A stack now holds subtree roots instead of computed integers. You also use postorder reasoning to evaluate children before parents.

Define a small expression language

The examples accept one line with at most fifteen symbols, including any spaces. Operands are single digits zero through nine. Operators are binary plus, minus and multiplication. There are no variables, multi-digit literals, unary minus or division in this particular parser.

    binary operator: require two roots

The Expr record contains a token and two child pointers. A digit record has two NULL links. An operator record receives both children before it is pushed. Because the accepted operators are binary, every valid internal node has exactly two children.

Build first, then compute

Read postfix from left to right. A digit creates an independent one-node tree. An operator combines the two most recently completed trees into one larger tree. Its right tree is on top of the stack, so pop right before left.

For 82-, the stack contains root 8 below root 2. The minus node must point left to 8 and right to 2. Reversing those assignments computes 2-8 instead of 8-2. Addition and multiplication examples can hide this bug because swapping their operands leaves the value unchanged.

The stack invariant is that every entry owns one complete expression tree for an already read fragment. Entries own disjoint records. When an operator pops two entries, ownership moves into its two child links. Pushing the new parent gives the stack one combined owner for those same records.

Before allocating an operator, check that two roots exist. If allocation fails, the two operand roots must still be owned somewhere. The example allocates before popping, so failure leaves the stack ownership unchanged. Cleanup can then dispose of every partial tree still on the stack.

Evaluation recursively obtains the left value and right value, then applies the stored operator. A digit returns token minus the character zero. C guarantees consecutive codes for decimal digits, so this conversion is portable. An operator cannot run until both operand values are available.

The first tree evaluates its left minus to six and its right digit to three. The root multiplication therefore returns eighteen. For 823*-, multiplication produces six inside the right subtree, and the root returns two. The different links, rather than token frequency, explain the changed result.

The parser takes O(m) time for m input symbols and stores one record per non-space token. Its root stack needs O(m) space. Evaluation visits each record once, taking O(m) time and O(h+1) recursive space. Printing and final disposal have the same traversal-time bound.

Observe grouping and invalid input

The first two programs print different parenthesized forms for expressions with identical digits. The third deliberately supplies too few operands. It reports invalid and releases the already built digit tree, rather than trying to use a nonexistent second operand.

Parentheses preserve the shape

The tree groups 2*3 before subtraction. Infix prints (8-(2*3)), while preorder produces -8*23.

The plus sign finds only one subtree. The parser frees that subtree and reports invalid rather than popping past the stack.

Print infix, prefix and postfix

An inorder walk can print the left expression, operator and right expression. Without parentheses, that sequence loses some grouping information. To preserve the exact binary tree, print an opening parenthesis before each operator's left subtree and a closing parenthesis after its right subtree. Digit leaves need no parentheses.

Preorder prints the operator before its operands and gives prefix notation. Postorder prints operands before their operator and recovers postfix notation. Our one-character token grammar needs no separators for those forms. A multi-digit or named-variable grammar would need explicit token boundaries.

Full parentheses may look longer than ordinary handwritten arithmetic, but they are unambiguous. Removing only unnecessary parentheses requires precedence and associativity rules. For subtraction, even equal-precedence child expressions need care on the right. The introductory printer keeps all grouping instead of guessing.

Because every operator has two children, a valid tree with I operators has I+1 operands. The fifteen-symbol bound permits at most eight digits in a complete expression. With digits at most nine and these three operators, intermediate magnitudes remain within signed long's required range. A larger language should check arithmetic overflow explicitly.

A zero leaf is ordinary data. It does not mark an absent expression, because absence is represented by a NULL pointer. The valid one-token input 0 therefore evaluates to zero and still owns one allocated record. Distinguishing those two cases prevents an empty expression from being mistaken for a successful zero result.

Reject malformed forests

An empty line is not a complete expression, so this parser reports invalid. One digit is a valid leaf tree and evaluates to that digit. An operator arriving before two roots is invalid. Two leftover operand roots, such as input 82, are also invalid even though neither individual root is malformed.

A full stack cannot occur within the accepted line bound: twenty-four root slots exceed the maximum fifteen non-space tokens. The parser still relies on that stated input limit. Do not enlarge the input line without reconsidering its stack capacity and arithmetic bound.

Spaces are ignored after the total line-length check. Unknown characters trigger cleanup. Allocation failure follows the same partial-tree release path. Since stack entries own disjoint trees, disposing each one releases every allocated record once.

The mirror practice problem swaps both child links at every node. Its output can change subtraction results because left and right roles are semantic. That exercise tests structure, not a valid algebraic simplification. Compare its fully parenthesized output before evaluating the new tree.

Respect operand order and ownership

Popping left first

The top subtree belongs on the right of a binary operator. Name the local variables right and left to make that decision visible. Test subtraction before trusting an implementation that works only for addition.

Accepting any nonempty final stack

More than one root describes several expressions with no operator joining them. Require exactly one root. Dispose of every root when rejecting the leftover forest.

Printing raw inorder as equivalent arithmetic

A tree for (8-2)*3 would become 8-2*3 without parentheses. That text follows a different grouping. Surround internal expressions with parentheses to preserve the stored dependencies.

C17 tokens and long arithmetic

The expression code uses C17 character operations and signed long values. Its fixed grammar and fifteen-symbol limit bound arithmetic. C does not define a universal safe result for overflowing signed arithmetic, so larger operands require checked operations or a larger-number library.

A tree records what must happen first

Postfix builds complete subtrees on a stack, evaluation combines child results, and parentheses preserve grouping when printing. Those same ownership rules make invalid-input cleanup safe. Continue to B-trees and B+ trees to see why storage devices favor wider nodes.
