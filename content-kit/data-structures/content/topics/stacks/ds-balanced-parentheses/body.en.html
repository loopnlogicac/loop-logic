Introduction

When you open a small box inside a larger box, you must close the small one first. Brackets follow the same nesting rule. In {[()]}, the round pair closes before the square pair, and the square pair closes before the braces. A stack remembers that order.

Balanced brackets have both the correct partners and the correct nesting. Counting opening and closing symbols is not enough. The expression ([)] has equal counts, yet its pairs cross. The next closer must match the most recent opener still waiting.

You will check three families: round parentheses, square brackets and braces. Other characters are ignored. This is a bracket test, not a complete C parser. A line can have balanced brackets and still contain invalid operators, declarations or types.

Representation and rules

The array named items holds pending opening characters from bottom to top. A parallel positions array stores their locations in the input. The same top index selects both the character and its position. Keeping these arrays aligned lets the program explain an unfinished opening bracket.

The helper match returns true only for one of the three allowed pairs. It does not compare bracket characters numerically. Character codes do not form a portable pairing formula for this purpose.

The function check returns zero for balanced input. A positive result identifies a 1-based character position. When a closer has no valid partner, report that closer immediately. If scanning ends with pending openers, report the oldest remaining opener. This end-of-input policy is explicit; another application could choose the newest instead.

The line reader accepts at most twenty-four characters and removes the newline before checking. Spaces count toward character positions even though they do not affect nesting. ASCII bracket symbols occupy one byte each in these examples; byte positions are not general Unicode character positions.

Follow the operations

For an opening symbol, increment top and save both token and position. It represents unfinished work. For a closing symbol, first check whether the stack is empty. Reading items[top] before that check could access index minus one.

If the stack is nonempty, compare its top opener with the closer. A match allows one pop. A mismatch ends the scan immediately, because later text cannot repair an incorrectly closed inner group. Do not search deeper in the stack for a convenient partner.

After the last character, an empty stack proves that every opener found a correctly ordered closer. A nonempty stack proves that something remains unfinished. Use positions[0] for the oldest unmatched opener under this lesson’s reporting policy.

read } : [{]      -> []        top=-1

read ) : [(,[]    -> [(,[]     error; top expects ]

Consider a{b[c]. The brace enters at position two and the square opener at position four. The square closer at position six removes only the square opener. At the end the brace remains, so the answer points to position two.

For ()), the first round pair empties the stack. The third character is a closer with no opener. Report three without attempting a pop. For an empty line, the stack starts and ends empty, giving success.

The lab follows the same check order and position convention. Its pending opener boxes appear in opening order. At a mismatch, they remain visible, so you can inspect which partner was expected and why the current closer fails.

A closer trace

The central invariant is about the accepted prefix, meaning the part of the line processed without an error. The stack contains exactly its unmatched opening brackets, in their original opening order. Initially both prefix and stack are empty. An opener extends that list. A valid closer removes its last entry. An ordinary character changes neither list nor stack.

This invariant explains the mismatch rule. If the top is square and the next closer is round, the innermost unfinished group is being closed with the wrong family. Finding a round opener deeper down does not help; the square group would remain crossed. Stopping immediately points to the first prefix that can no longer be valid.

Maximum nesting depth can be measured during the same scan. After every successful opener push, compare top+1 with the largest previous depth. For ()() the maximum is one. For (()) it is two. Both have two pairs, so total pair count and maximum pending depth describe different properties.

Suppose a source-code line contains bracket characters inside quoted strings. This bracket-only function still treats them as brackets. A full language tool must first recognize quoted strings, escapes and comments, then decide which characters count as syntax. Ignoring non-brackets is deliberately narrower than recognizing all source-language contexts.

Try inserting a letter before a known mismatch. The stack decisions remain the same, but its reported character position increases by one. That small experiment checks that diagnostics refer to the complete input line rather than to a filtered list of bracket tokens.

Operation plan

top = -1; error = 0
for each token at position i + 1
    if opener: push token and save its position
    if closer: require matching items[top], then pop
if openers remain: error = oldest saved position
return error

Costs and boundary cases

Scanning n characters takes O(n) time. Each opener is pushed once and, if matched, popped once. The nested structure does not create repeated rescanning. The worst space requirement is O(n), reached when every character opens another group.

Flat pairs such as ()()() need little simultaneous stack space even though the whole line still takes linear time. The useful measure is maximum nesting depth. The fixed twenty-four-character input bound makes a twenty-five-cell local array sufficient for this implementation.

The earliest invalid closer is discovered during scanning. An unfinished opener can only be confirmed after reaching the end. These are different diagnostic situations. The return policy should explain both, rather than treating every failure as the final character’s fault.

A single opening bracket, a single closer, an empty line and crossed families exercise different branches. A line of letters exercises the ignored-character branch. None should cause a stack operation on invalid storage.

Common mistakes

Using only a counter

A depth counter can detect excess closing parentheses for one family, but it cannot remember bracket families. Use characters on the stack when round, square and brace groups can nest.

Popping before matching

Popping immediately loses the opener that explains a mismatch. Test the top first. Only a valid family match removes it.

Reporting the wrong position base

C array indices begin at zero; the diagnostic positions here begin at one. Add one when storing an input index, then return the saved position unchanged.

Working habits

When tracing by hand, make one column for the character, one for the pending stack and one for the reason. A non-bracket character should leave the pending stack exactly as it was.

Keep the diagnostic policy consistent between the algorithm and its caller. Zero means success, not character zero. A positive value refers to the original line, including spaces, rather than to the count of bracket symbols.

C17 notes

The bracket algorithm requires no newer C feature than ordinary arrays and loops. The programs use C17 and fgets for bounded line input. The strlen-family indices use size_t, while the bounded stack positions fit in int.

Summary

Correct nesting depends on the latest unmatched opener. Store its family and position, refuse invalid closers, and check for unfinished groups at the end. Next, use a stack to rearrange operators in expression conversion.
