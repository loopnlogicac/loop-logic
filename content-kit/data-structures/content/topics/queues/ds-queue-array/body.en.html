Introduction

At a service desk, people normally leave in the order they arrived. A queue follows that rule for data. New values join the rear, and the oldest waiting value leaves from the front. This is FIFO: first in, first out.

A queue differs from a stack because its insertion and removal happen at opposite ends. If roll numbers twelve, twenty-four and thirty-six arrive, twelve is served first. Numerical size does not matter; arrival order decides service.

An array can hold the waiting values without moving them after every service. Two cursors describe the live interval. This lesson begins with a linear queue so you can see both its simple updates and the storage problem that motivates circular indexing.

Representation and rules

The structure Queue owns four cells, a front cursor and a rear cursor. Front identifies the next live cell to remove. Rear identifies the next unused cell for insertion. Both start at zero, giving an empty interval.

The live entries occupy indices front through rear minus one. Its size is rear-front. Empty means front equals rear. The enqueue helper refuses a write when rear equals capacity, even if some prefix cells have become unused.

Rear is therefore a next-write index, not the index of the last live value. When the queue is nonempty, the last live index is rear-1. Keeping this distinction explicit prevents a common one-cell mistake in drawings and full tests.

The dequeue helper returns status and writes its output value only on success. It does not use a special integer as an empty marker. Every stored int remains distinguishable from an unsuccessful request, because the status is separate.

Follow the operations

Enqueue first checks the rear boundary. On success, it writes into items[rear] and advances rear. Existing values stay in their cells. Dequeue checks the empty condition, reads items[front], then advances front. It never shifts the suffix.

After inserting twelve and twenty-four, front is zero and rear is two. Removing twelve advances front to one. Twenty-four remains physically at index one. Inserting thirty-six writes index two and advances rear to three.

enqueue 24:
before: [12][  ][  ][  ] front=0 rear=1
after:  [12][24][  ][  ] front=0 rear=2
dequeue:
before: [12][24][  ][  ] front=0 rear=2
after:  [--][24][  ][  ] front=1 rear=2, returned=12
peek front/rear:
        [--][24][  ][  ] front value=24, rear live value=24

The old twelve may remain in memory after removal, but it lies before front and is no longer queued. The program prints only the live interval. A picture can mark unused cells with dashes without requiring the C helper to erase their payloads.

Fill all four cells, then remove the first two. Front becomes two and rear stays four. A new enqueue is refused because index four is outside the array. This is sometimes called false overflow: the queue has spare physical cells, but the linear cursor scheme cannot reach them for writing.

A simple repair after complete draining is to reset front and rear to zero. The practice problem explores that policy. It does not solve the partial-drain case, where some values still occupy the suffix. Circular queues solve that case without shifting.

Operation plan

front = 0; rear = 0; capacity = 4
for each command
    if zero and front < rear: dequeue; front++
    else if zero: report empty
    else if rear < capacity: enqueue; rear++
    else: report no rear space
return items and cursors

Costs and boundary cases

One successful linear enqueue or dequeue takes O(1) time and O(1) auxiliary space. A full live traversal takes O(n), where n is the number waiting. The allocated array has O(C) storage for capacity C even when its live size is smaller.

Compacting the suffix to the beginning reclaims prefix cells, but moving n live values costs O(n). If you compact after every removal, dequeue becomes linear. Delaying compaction changes when that cost is paid but does not make the copies free.

An empty removal must preserve both cursors and avoid reading a cell. A singleton removal advances front until it equals rear. If rear has already reached capacity, the queue can become empty while both cursors equal four. Equality, rather than zero, defines this empty state.

You can inspect the front payload only when front is less than rear. You can inspect the last queued payload at rear-1 under the same condition. Merely printing rear’s numeric cursor does not inspect a value. Index four is a legal boundary number but not a legal cell index.

Common mistakes

Mixing two rear conventions

Some queue designs store the last occupied rear index. This lesson stores the next write index. Taking a full or empty formula from the other design without translating it changes which cells are considered live.

Resetting while entries remain

Setting both cursors to zero after every dequeue discards the remaining live interval. Reset only when the queue is empty, or deliberately move the live values before changing their boundaries.

Sorting a FIFO queue

Smaller roll numbers do not get served earlier unless they arrived earlier. Sorting changes the service policy into a different structure. Keep arrival order when tracing queue operations.

Working habits

Draw front and rear even when they coincide. Show rear just beyond the final live cell. For a supplied byte width w and base B, the next removal address is B+front*w while the queue is nonempty.

Compare logical size with the remaining linear write range. They answer different questions. Size counts waiting values; capacity-rear counts cells this implementation can still fill before a reset or compaction.

C17 notes

The queue code uses C17 with ordinary fixed arrays. C permits computing a one-past boundary for an array, but you must not dereference it. Here rear can equal capacity as a number; enqueue checks that boundary before accessing items.

Summary

A linear queue maintains FIFO using separate front and next-write cursors. It avoids shifting but can strand freed prefix cells. See circular queues to reuse those cells through wrapping.
