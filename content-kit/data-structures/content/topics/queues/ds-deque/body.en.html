Introduction

An ordinary queue lets new values enter at one end and old values leave at the other. Sometimes you need more freedom. A recent arrival may cancel from the back, or an urgent item may enter at the front. A deque, pronounced deck, permits insertion and removal at both ends.

The four operations are front insertion, rear insertion, front removal and rear removal. Their names describe positions, not priorities. A deque does not automatically sort values or choose the most urgent key.

You can implement a deque using a circular array or a doubly linked list. The array needs careful wrap arithmetic. The linked version needs careful neighbor repairs. Both can provide constant endpoint work when their representation rules are maintained.

Representation and rules

The array Deque stores items, front and count. It derives other indices rather than storing a separate rear cursor. The next rear insertion cell is (front+count)%capacity. The last live cell is (front+count-1)%capacity when count is positive.

Front insertion moves front backward before writing. Use (front+capacity-1)%capacity. Adding capacity keeps the bounded arithmetic nonnegative. In C, a negative left operand can produce a negative remainder, so (front-1)%capacity is unsafe at front zero.

Front removal reads items[front] and advances front. Rear removal reads the last live index and leaves front unchanged. Either successful removal decreases count. Empty and full use count zero and count capacity, respectively.

The linked Deque stores front and rear pointers. Each Node has prev and next. A nonempty front has prev NULL; a nonempty rear has next NULL. When the structure is empty, both endpoints are NULL.

Follow the operations

The array insert helper takes at_front to choose its end. It refuses fullness before changing a cursor. Front insertion updates front and writes there. Rear insertion uses the derived next rear index. Both then increase count.

The erase helper similarly refuses an empty structure. It chooses front or the derived last live index, copies the payload, and advances front only for front removal. Lowering count removes the selected entry from the live range.

A removed array integer need not be erased. Subsequent membership depends on front and count. The final print loop traverses logical order, so stale cells outside that range never appear as deque entries.

For linked insertion, initialize the new node’s neighbors before publishing it. Front insertion connects the old front’s prev back to the new node. Rear insertion connects the old rear’s next forward to it. In the empty case, also set the opposite endpoint.

For linked removal, save the selected node, repair each existing neighbor, and update any endpoint that referred to it. A singleton has no neighbors, so both endpoints become NULL. Free only after extracting the value and completing link repairs.

The alternating example inserts even-positioned input at front and odd-positioned input at rear. With one, two, three, four, five, the logical order becomes five, three, one, two, four. Removing from rear reverses that final deque order.

A closer trace

The singleton ring case is a good formula check. With front three and count one in capacity four, the last live index is (3+1-1)%4, which is three. Either front or rear removal reads that same cell. Rear removal leaves front three and count zero; front removal wraps front to zero and count zero. Both states are empty and valid.

For linked nodes, write the reverse picture as carefully as the forward picture. If a node x precedes y, then x->next must identify y and y->prev must identify x. Removing x at the front requires y->prev=NULL. Removing y at the rear requires x->next=NULL. A successful traversal in only one direction does not prove both repairs happened.

A deque can act as a stack by inserting and removing at the same end. It can act as an ordinary queue by inserting rear and removing front. Those are uses of the more general interface; they do not require changing the internal data layout.

Restrictions can match an application’s rules. If only the newest cancellation and oldest service are allowed, permit removal at both ends but accept arrivals at rear only. That is input restricted. If urgent arrivals may join front but all service leaves front, insertion is unrestricted while removal is output restricted.

Do not confuse this endpoint flexibility with arbitrary middle access. A deque’s constant-time promise concerns its ends. Searching for an interior value can still require linear work, and removing a linked interior node requires locating it or receiving a valid node pointer first.

ring rear insertion: [4] -> [4,8]
ring front removal: [4,8] -> [8]
linked rear insertion:
NULL <- [4] -> NULL  becomes  NULL <- [4] <-> [8] -> NULL
linked front removal:
NULL <- [4] <-> [8] -> NULL  becomes  NULL <- [8] -> NULL; [4] freed

Costs and boundary cases

Both ring and doubly linked endpoint operations take O(1) local work and O(1) auxiliary space. A ring reserves O(C) cells. A linked deque occupies O(n) nodes, each with two links. Node allocation and release add real costs beyond the pointer-operation model.

A singly linked chain can append with a saved tail, but removing that tail still needs its predecessor. Without prev links or another predecessor mechanism, rear removal becomes O(n). This explains why a linked deque commonly uses doubly linked nodes.

An input-restricted deque permits insertion at one end but removal at both. An output-restricted deque permits removal at one end but insertion at both. These are interface restrictions. The same general deque implementation can support either by exposing fewer operations.

Full ring insertions and empty removals must preserve all state. One-element removal must make the deque empty regardless of the chosen end. Linked allocation failure must leave both endpoint chains unchanged. Repeated alternation across the wrap point is especially useful for finding index mistakes.

Common mistakes

Confusing last-live and next-write rear

For a nonempty deque these indices differ by one logical step. Use count for insertion and count minus one for removal. Derive the formula from a two-value drawing before coding it.

Repairing only one link direction

A forward traversal may appear correct while prev still points to a removed node. Repair both neighbor directions. A valid doubly linked chain must support the reverse walk too.

Leaving one endpoint after singleton removal

If the only node leaves, neither endpoint can identify a live object. Clear both. The general neighbor repair in the example handles this case without retaining the freed address.

Working habits

Name the end explicitly in your operation trace. Writing only insert or delete hides the behavior that makes a deque different from a queue or stack.

When choosing storage, compare capacity needs and reverse links. Ring arrays are compact and avoid per-node allocation. Doubly linked nodes grow independently, but each value pays for two pointers and careful lifetime management.

C17 notes

The deque programs target C17. The remainder rule matters for backward wrapping, so the code avoids a negative numerator. Struct padding and pointer widths are implementation dependent; no example assumes a fixed node byte size.

Summary

A deque exposes both endpoints while preserving an ordered sequence. Ring formulas or two-way links make each endpoint update local. Compare positional choice with key-based choice in priority queues.
