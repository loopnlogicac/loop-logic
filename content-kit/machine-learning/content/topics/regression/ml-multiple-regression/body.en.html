Two flats with the same area

Mina finds two flat cards with equal floor area. One flat is near a bus stop; the other is much farther away. Tuktuk gives both the same rent because it reads only area. Nana asks whether the robot can keep more than one useful detail in mind.

Multiple regression predicts one quantity from several features. Each feature contributes through its own learned weight. An intercept supplies a shared starting height. The result is still one numeric prediction for each input row.

Extra inputs can explain differences a one-feature model misses. They can also duplicate each other, leak future information or make coefficients difficult to interpret. More columns do not automatically mean more useful knowledge.

You will build a tiny two-feature design matrix, fit its weights, and interpret one coefficient while holding the other input fixed. Then you will inspect what correlated features do to the meaning of individual weights.

A design matrix is the numeric table supplied to a fitting calculation, including any constructed columns. A dot product multiplies matching entries and adds the products. Collinearity means one input column is closely related to a combination of other columns.

Imagine three labelled cups feeding a bowl: a shared starting amount, an hours contribution and an attendance contribution. Each row changes the cup contents according to its inputs. The bowl's total is the prediction. The learned weights decide how strongly each feature contributes.

The attendance flag here is a teaching input equal to zero or one, not the percentage used in the larger study dataset. Naming its meaning prevents a coefficient of three from being misread as three marks per percentage point.

Add a ones column and multiply

The table follows marks=10+2*hours+3*flag. The first row contributes 10+2*1+3*0=12. The fourth contributes 10+2*4+3*1=21. We created these exact targets so you can verify whether a solver recovers the intended weights.

A row:       [1, hours, attendance_flag]
weights:     [intercept, hours_weight, flag_weight]
prediction:  their dot product

The leading one is multiplied by the intercept. Without it, a direct matrix calculation would force the fitted surface through the origin of its feature coordinates. LinearRegression adds an intercept internally by default, so its input table needs only the two feature columns.

To predict the query hours=3,flag=1, use [1,3,1] dot [10,2,3]=19. Keep the same column order at training and prediction. Swapping hours and flag would make the arithmetic produce a different and meaningless answer.

To interpret the hours weight, compare two hypothetical rows with the same flag. Increasing hours from 2 to 4 changes the prediction by 2*(4-2)=4 marks. That is a conditional model comparison. It does not assert that a real intervention will cause the same change.

For noisy observations, the solver finds the weights minimising squared residuals. With several features, the fitted trend is a plane or a higher-dimensional flat surface. You can calculate predictions even when you cannot draw all input dimensions at once.

Hold one card detail fixed

Write six cards containing hours and the attendance flag from the table. Build a second card differing in only one feature. Calculate both predictions and describe the change in a sentence. Your explanation must name the feature held fixed and the unit of the changed feature.

Now replace hours with minutes by multiplying that column by sixty. To preserve every prediction, divide its coefficient by sixty. The hours contribution has not become less useful, even though its coefficient is numerically smaller. This is why unscaled coefficient size is not a universal importance ranking.

Create a duplicate hours column and distribute its weight as 1+1 instead of 2+0. Predictions remain identical. You have found two different coefficient vectors with the same fitted values. A good score alone cannot tell which duplicate feature deserves the credit.

Read weights with their context

  • Forgetting the leading ones in a direct solve: the intercept is then missing. Add it explicitly or use a regressor that fits it.
  • Changing feature order for a query: a model cannot know that one numeric column was accidentally swapped. Preserve names and order.
  • Inverting a singular matrix: duplicate columns can destroy the inverse. Use least squares or a pseudoinverse and inspect rank.
  • Calling the largest raw coefficient most important: units and correlation alter its size. Explain a meaningful input change instead.
  • Reading association as causation: holding model columns fixed is not the same as controlling real-world confounders.

Optional: normal equations and identifiable predictions

Let A contain n rows and d+1 columns, including the intercept. For parameter vector theta, predictions are A theta. Minimising the squared norm of y-A theta gives the normal equation A transpose A theta=A transpose y.

With independent columns, the symbolic solution is theta=(A transpose A) inverse A transpose y. This formula is useful for derivation. In numerical code, forming the cross-product and explicitly inverting it can worsen conditioning. A one-line NumPy solution is np.linalg.lstsq(A,y,rcond=None)[0]; np.linalg.pinv(A) @ y also handles rank deficiency.

The pseudoinverse selects a minimum-Euclidean-norm coefficient vector among equivalent least-squares solutions. In the exact duplicate-column example, several weight allocations give the same predictions. The chosen allocation is a numerical convention, not proof of separate feature effects.

Highly correlated columns need not be exact duplicates to cause trouble. Small changes to rows can make individual coefficients swing while predictions on familiar combinations remain stable. Report uncertainty and consider regularisation when coefficient interpretation matters.

A dense least-squares solve with n at least d typically needs O(nd²+d³) work, depending on the decomposition. One new prediction takes O(d). These costs concern arithmetic; collecting trustworthy measurements may be far more expensive.

Residual sums are orthogonal to each design column at an unconstrained least-squares optimum, up to numerical precision. With an intercept, their signed sum is zero on training rows. That fact does not require test residuals to sum to zero.

Several contributions, one prediction

  • Each feature contributes through a learned multiplier.
  • The intercept can be represented by a ones column.
  • A dot product adds all feature contributions.
  • Preserve column meanings and order for future rows.
  • Coefficient interpretation depends on units and correlation.
  • Stable solvers handle matrices better than explicit inverses.
