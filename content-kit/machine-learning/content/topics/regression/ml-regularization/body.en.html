A ribbon that pulls too hard

Nana asks Tuktuk to draw a smooth price trend for tomorrow's baskets. The robot's latest ribbon has sharp turns around every pencil smudge. Mina attaches gentle elastic bands that resist extreme pulls. The ribbon no longer follows every smudge, but its broad shape becomes more useful.

Regularisation adds a cost for certain parameter choices. Ridge discourages large squared weights. Lasso penalises absolute weights and can set some to exactly zero. Both change the fitting goal, so a little training error can buy a less sensitive model.

The penalty has a strength setting, usually called alpha in scikit-learn. A tiny penalty may do little; a huge one can flatten useful structure. Choose that setting with validation data rather than treating smoothness as a score by itself.

You will solve a small ridge problem, compare its objective with the library convention, and inspect how feature scaling affects the penalty. You will also see one case where lasso removes an irrelevant feature.

A penalty is an extra cost attached to parameter choices. Ridge uses the sum of squared feature weights, also called an L2 penalty. Lasso uses the sum of absolute feature weights, called an L1 penalty.

Both care about magnitude rather than sign. A large negative coefficient is not automatically cheap. They can reduce how sharply a model reacts to the peculiarities of one training sample. That benefit depends on the data, feature representation and chosen strength.

Balance residuals against coefficient size

Start with the centred inputs x=-2,-1,0,1,2 and targets y=-4,-2,0,2,4. There is no intercept offset to estimate in this hand example. The cross-product sum is 20 and the feature-square sum is 10. Ordinary least squares gives slope 20/10=2.

Ridge with alpha=10 changes the denominator to 10+10. The fitted slope becomes 20/20=1. At the two extreme inputs it predicts -2 and 2 instead of -4 and 4. Those extra residuals are accepted because a smaller coefficient reduces the penalty.

The objective used by sklearn Ridge is SSE+alpha*sum(weights²). SSE means the sum of squared residuals, without division by observation count. The intercept is not included in that weight penalty. For multiple features, solve the penalised system on the centred feature columns.

This makes the intercept equal to the original target mean in centred coordinates, while weights describe standardised power contributions.

Increasing alpha shrinks the combined L2 norm on these fixed features. Individual correlated coefficients may move in less regular ways as they trade contributions. The chart therefore labels the vector norm rather than claiming every component must decrease at every step.

Lasso's absolute-value penalty has corners at zero. Its optimum can land exactly on those corners, producing zero coefficients. Ridge generally reduces weights without making them exactly zero, although symmetric or irrelevant features can already have zero solutions.

Find an exactly zero feature

The last example gives a target that depends only on the first of two orthogonal inputs. Lasso at alpha 1 shrinks that useful weight and sets the irrelevant weight to zero. Feature selection and coefficient bias happen together.

Keep penalties comparable

  • Penalising the intercept accidentally: centring separates the shared offset. Exclude it from the penalty when matching these models.
  • Comparing alpha across unmatched objectives: SSE and MSE differ by observation count. Translate the strength before comparing formulas.
  • Skipping feature scaling: large and small input units receive different effective treatment. Scale inside the training pipeline.
  • Expecting ridge to delete every weak feature: ridge is a shrinkage method. Lasso can create exact zeros.
  • Choosing alpha from final test scores: those choices leak evaluation information. Use validation or cross-validation within development data.

Optional: ridge equations and L1 geometry

Let Z be the centred, scaled design without an intercept and let yc be centred targets. Differentiating ||yc-Zw||²+alpha||w||² gives (Z transpose Z+alpha I)w=Z transpose yc. With positive alpha, the added diagonal makes the system positive definite even when columns are dependent.

If your written objective is mean squared error plus lambda||w||², multiplying by n gives SSE+n*lambda||w||². Matching sklearn Ridge therefore requires alpha=n*lambda. This conversion applies to Ridge's convention; sklearn Lasso uses a different normalisation, namely SSE/(2n)+alpha||w||1.

In the one-dimensional centred ridge example, the derivative equation is (sum(x²)+alpha)w=sum(x*y). Lasso instead uses a soft-thresholding relation in an orthogonal design. Its flat central interval can produce exactly zero, explaining sparse solutions without requiring a zero raw correlation.

Zero coefficients do not prove that a feature is causally irrelevant. Correlated alternatives can substitute for each other, and the selected subset can change with small data changes. Strong interpretive claims need additional evidence beyond one regularised fit.

The lab uses a dense solve with pivoted elimination for each positive alpha. With d=8 power columns, work is O(nd²+d³) per fit. It uses the population spread and divisor one for a constant feature. This convention prevents division by zero without pretending that a constant column carries predictive variation.

Control coefficients with a stated objective

  • Regularisation changes the goal by charging for weight size.
  • Ridge uses squared sizes and lasso uses absolute sizes.
  • Lasso can set some coefficients exactly to zero.
  • Scale features before comparing penalty strengths.
  • Keep the intercept outside the penalty in these models.
  • Choose alpha through held-out development performance.
