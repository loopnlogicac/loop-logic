Tuktuk takes steps on a foggy hill

During a school game, Tuktuk must find the bottom of a cardboard valley while wearing a paper blindfold. Mina lets it feel the tilt under its feet. Tiny steps take too long. Huge jumps carry it up the opposite wall. Rafi suggests choosing each step from the local tilt.

Gradient descent improves parameters by repeatedly moving against the direction in which cost increases. You do not need to try every ruler before making progress. You need the current error and a rule for measuring its local direction.

Line fitting has two knobs: slope and intercept. This lesson updates both, using the same old predictions to calculate their changes. You will see the line move and its cost recorded for each update.

The method matters beyond regression. Many models have too many parameters for an exhaustive search. Understanding learning rate and scaling here will help you recognise training problems later.

The gradient collects the cost's local rates of increase for the parameters. The learning rate controls how strongly an update follows those rates. An epoch is one pass through the training observations, though the number of updates per epoch depends on the training method.

On a hill, the downhill direction is opposite the uphill direction. In parameter space the same idea applies. The gradient points uphill, so subtract a positive multiple of it. Recalculate after moving because the new location can have a different tilt.

The lab uses exact full-batch derivatives on your points. Each iteration draws its new line and immediately appends that iteration's MSE in a paired operation. No extra training happens between those two display operations. Use the iteration number and displayed MSE to connect them.

Calculate both changes before moving

Take five centred inputs -2,-1,0,1,2. Their targets are -3,-1,1,3,5. The exact rule is y=2x+1, but start with w=0 and b=0. Define error for differentiation as prediction minus target. This is the negative of the earlier observed-minus-predicted residual; squared cost is unchanged.

The five initial errors are 3,1,-1,-3,-5. Their average is -1. Their products with x average -4. For MSE, the slope derivative is twice the average of error times x, giving -8. The intercept derivative is twice the average error, giving -2.

With learning rate 0.1, set w_new=0-0.1*(-8)=0.8 and b_new=0-0.1*(-2)=0.2. The new MSE is 3.52 instead of 9. Both changes used the zero line, so they form one simultaneous gradient update.

start w = 0, b = 0
repeat for the requested updates:
    error = w*x + b - y for every training row
    grad_w = 2 * mean(error*x)
    grad_b = 2 * mean(error)
    w, b = w - lr*grad_w, b - lr*grad_b
    draw this line and record its MSE

At the next iteration, recompute errors from w=0.8,b=0.2. The slope derivative becomes -4.8 and the intercept derivative becomes -1.6. The next parameters are 1.28 and 0.36. Reusing the original derivatives forever would move in a straight path through parameter space and miss the bowl's changing tilt.

After forty updates at rate 0.1, the printed slope and intercept round to 2.000 and 1.000. The printed MSE rounds to 0.000. The internal intercept still differs slightly from one, so rounded zero is not a proof of exact convergence.

A learning rate of 0.01 also reduces error on these points, but more slowly. A rate of 0.6 makes the slope overshoot repeatedly with increasing magnitude. A rate safe on centred inputs may fail when raw feature values are hundreds or thousands.

SGDRegressor updates from individual training observations rather than averaging all rows first. The example imputes missing values and standardises features inside the pipeline. Its seeded order and decaying learning rate make the demonstration reproducible.

Full-batch descent uses the entire training collection before each update. Stochastic descent uses one observation. Mini-batch descent uses a small group, often combining more stable directions with cheaper updates. An epoch can therefore contain one, many or an intermediate number of updates.

Inspect the path before changing the model

  • Adding the gradient: that follows local increase. Subtract learning rate times gradient when minimising cost.
  • Updating w before calculating grad_b: coupled parameters would then use different old predictions. Calculate every component first.
  • Blaming divergence on too few updates: more unstable steps can make the error much larger. Reduce the rate and inspect scaling.
  • Rounding parameters during training: rounding can stop small improvements artificially. Round only displayed numbers.
  • Equating one epoch with one update everywhere: count the observations used per update and the batches used per pass.

Optional: derivatives, stability and work

For J(w,b)=mean((w*x+b-y)²), the chain rule gives grad_w=2*mean((w*x+b-y)*x) and grad_b=2*mean(w*x+b-y). Both are evaluated at the same parameter pair. Writing J=MSE/2 instead removes the leading twos and changes what a given numeric learning rate means.

For the centred preset, mean(x)=0 and mean(x²)=2. The slope error therefore multiplies by 1-4*lr each update. Stable reduction requires its magnitude below one, so 0<lr<0.5. The intercept error multiplies by 1-2*lr. The stricter slope bound controls this particular problem.

More generally, a convex quadratic with largest positive Hessian eigenvalue L converges in its identifiable directions for a fixed rate between zero and 2/L. This is a statement about that objective, not a universal rate recommendation. Feature scaling changes L and the relative curvature of different directions.

One full-batch update costs O(nd) for n rows and d features. T updates cost O(Tnd). Stochastic updates cost O(d) each, but noisy directions usually require many updates and a rate schedule. Common stopping criteria combine gradient size, relative cost improvement and a maximum work budget.

Keep an evaluation score separate from this training path. The gradient uses training answers, while validation can help choose update settings. If training error falls but validation error worsens, investigate generalisation rather than assuming that more descent must help.

A step is a calculated change

  • The gradient describes local cost increase.
  • Subtract its scaled components to move downhill.
  • Use common old predictions for simultaneous updates.
  • Small rates can be slow and large rates can diverge.
  • Input scales affect the cost bowl and stable rates.
  • Distinguish examples per update from passes through data.
