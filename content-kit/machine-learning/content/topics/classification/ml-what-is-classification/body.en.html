Name the group before choosing a tool

Mina labels six fruit cards for Tuktuk. Three say apple and three say mango. Tomorrow she will bring a card without its name. Tuktuk must choose a fruit group, rather than guess its price. Mina asks what kind of question she has given the robot.

Classification means predicting a category. A category is a named group, such as apple, mango, spam or normal message. Its name can be stored as a number, but that does not turn it into an amount. Class one is not necessarily twice class zero.

You will recognise binary and multiclass tasks, read a border between groups and distinguish a probability from a label. Then you will fit a classifier and measure its result on reserved examples. Understand the question before choosing a complicated model.

A classifier is a model that chooses categories. A decision boundary is a border where its chosen category changes. A probability describes its estimated chance for a category. A fence gives a label, while a probability can show uncertainty near a difficult choice.

These invented classroom scores do not claim that real fruit species always separate by size. A useful feature must be available when prediction is needed. The hidden answer on the back of a card is a label, not an honest input feature.

Turn a task into a measured prediction

First define the allowed labels. Apple versus mango is binary because there are two. Adding lychee makes the task multiclass. Predicting weight in grams is regression, even if a notebook contains only a few observed weights. The target's meaning matters more than the number of recorded values.

Next collect features and known labels for training. The explicit rule predicts mango when size exceeds three. It labels all six cards correctly and predicts mango for size 3.3. That hand trace is useful, but a perfect score on cards used to choose the fence can be optimistic.

A library classifier follows a common pattern: fit learns from training features and labels, predict returns categories and score measures a documented result. For the classifiers here, score is accuracy. Keep held-out rows away from fit so the later measurement tests unseen examples rather than repeats the lesson answers.

Probability output answers a richer question. If apple receives 0.6 and mango 0.4, choosing the larger number gives apple, but the model was not certain. For a binary class-one probability, an inclusive threshold of 0.5 chooses one at or above that value. Moving the threshold changes decisions without changing the scores.

Accuracy counts exact matches, then divides by the number evaluated. Six correct predictions out of eight give 0.75. Always name the evaluated population: training cards, reserved cards or a later real-world collection. A percentage without that context hides what was actually measured.

Hide one answer before choosing a border

Draw six labelled cards with two scores each. Let a partner choose a border using five cards while you hide the sixth label. Ask for a prediction, then reveal the answer. Repeat with another hidden card and notice that the result can change.

Keep the question and the evidence clear

Confusing encoded labels with amounts

Labels zero and one are names here. Averaging their numeric spelling is not the same as predicting a fruit measurement. Interpret an output according to the target definition.

Reporting training accuracy as a future guarantee

A model can memorise or exploit a small sample. Reserve representative examples and state how they were selected. One split provides evidence with uncertainty, not a permanent promise.

Treating a high probability as certainty

A model can be confidently wrong. New conditions, missing features and poor calibration can matter. Decide what a mistake costs before turning probabilities into automatic actions.

Optional: decisions and their costs

Accuracy treats every error equally. That can be unsuitable when rare positive cases matter. Evaluation lessons will distinguish false positives and false negatives and compare their consequences. A model that predicts the common class every time can score highly while missing every rare case.

A threshold represents a decision policy. The best value depends on the application, rather than a rule that every system must use 0.5. Check calibration before interpreting scores as reliable long-run frequencies, and use validation data when choosing a policy. Keep the final test set for the resulting fixed decision.

Categories, uncertainty and evidence

  • Classification predicts a category rather than a continuous amount.
  • Binary and multiclass describe the number of target categories.
  • A probability retains uncertainty that a hard label hides.
  • A decision boundary separates different predicted labels.
  • Measure generalisation on held-out examples.
