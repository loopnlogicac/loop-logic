A useful question tree should know when to stop

Mina adds a question for every unusual fruit card. Tuktuk soon remembers the entire pile, including one card whose score was copied wrongly. Nana brings fresh fruit and the complicated tree makes mistakes. Rafi asks whether every remembered exception deserved its own branch.

Growing a decision tree means repeatedly finding a useful question inside each current group. Stopping and pruning control how detailed that model becomes. A perfect training score may describe memorisation rather than useful future decisions.

You will build a small CART tree recursively, compare depth and sample limits, and inspect pruning on a library model. The examples keep model choice inside development data so the final test remains a separate check.

Children solve smaller versions of the same job

A recursive procedure solves a problem by applying itself to smaller parts. A tree's child receives only the cards that followed its branch. It asks the same kind of question-selection problem, but inside a smaller region.

Maximum depth limits how many question levels a path can use. Pruning simplifies an overly detailed tree by removing structure according to a stated rule. These controls change the model while keeping the original valid training records.

The first setting fits all eight training labels with five nodes. The other settings keep three nodes and miss one training card. That difference alone cannot tell you which setting will work best on a new population.

Grow a node, then hand off its two subsets

At a node, count labels and record a majority prediction. Check whether the group is pure, the depth budget is exhausted or too few examples arrived. If any stopping rule applies, keep the majority leaf. The root starts at depth zero in this implementation.

Otherwise evaluate each possible feature midpoint with the chosen impurity criterion. Keep the best strictly positive gain under the stated numerical tolerance. Partition the rows and recursively grow two children using only their respective subsets. A constant-feature or non-improving group stops instead of inventing a question.

fit_node(rows, depth):
    prepare a majority leaf
    if pure, depth limit or too few rows: return leaf
    find the best positive-gain question on these rows
    if none exists: return leaf
    fit left child using the yes subset and depth + 1
    fit right child using the no subset and depth + 1
    return question with those two children

The lab uses a deterministic binary, two-feature CART solver for at most twenty cards. Every selected question appears both as a tree node and as a cut within its parent rectangle. Leaf rectangles show the final decisions. Feature-order and smaller-midpoint ties are explicit; this is not a globally optimal search over every possible tree.

For query (2,5), depth two gives the root size test and a left-side sweetness test, predicting one. Depth one stops at the mixed left majority, predicting zero. Raising minimum split count to five also stops that four-card child, even when the depth budget would allow it.

Grow, validate and simplify actual fitted models

Recursively split only the rows reaching each node

Each recursive call receives only its own subset. A pure node, depth limit, too few rows or absent positive gain produces a majority leaf. Feature-order and threshold-order ties make this educational solver deterministic.

Inspect cost-complexity pruning on a training-only path

The pruning path is derived from training data, while reserved validation rows compare candidate models. Larger alpha penalises extra leaves more strongly. These rows are validation evidence, not a final test repeatedly used for selection.

Reduce structure rather than rewriting evidence

Depth and sample limits stop growth early, often called pre-pruning. Cost-complexity pruning instead compares simpler subtrees of a fitted tree. It trades training impurity against a penalty for additional leaves. A larger nonnegative alpha makes extra leaves more expensive.

The library example derives its pruning path from training data and compares fixed alpha choices on validation. It does not use the final test to choose repeatedly. Pruning can improve generalisation by removing noise-sensitive branches, but it can also remove a real small pattern. Validation evidence decides which trade is useful for the intended task.

Minimum split size and minimum leaf size are different controls. A parent with eight rows can satisfy a minimum split count five and still create a four-row child. If every leaf must contain a specified minimum, use that separate rule. Names that sound similar should not substitute for reading the actual contract.

Keep every claim attached to its evidence

Passing all original rows to each recursive child

The child would forget its path and repeat the parent problem. Pass only the yes or no subset, keeping the region bounds consistent with it.

Choosing depth from training accuracy

Additional branches often improve training fit, including fit to noise. Compare candidate complexity on suitable validation rows and keep the final test separate.

Calling pruning data cleaning

Removing branches changes the model. Deleting valid inconvenient examples changes the evidence and can erase a minority group. Investigate actual recording errors through a separate documented data-quality process.

Assuming arbitrary feature units matter exactly as in KNN

Axis-aligned trees depend on feature ordering for their possible training partitions. Simple positive unit rescaling usually preserves those partitions while changing numeric thresholds. This differs from raw distance voting, but it does not excuse inconsistent preprocessing or missing-value handling.

Optional: greedy CART and a complexity penalty

At each node, CART greedily chooses an immediate impurity reduction and repeats within children. The educational implementation scans all midpoints directly, costing O(depth times n squared) in its small two-feature setting. More efficient implementations maintain sorted information rather than rebuilding every subset repeatedly.

Cost-complexity pruning adds alpha times the number of leaves to a weighted training-impurity objective. It asks whether the extra fit earned by more leaves justifies their complexity. Optimising that training criterion still needs a separate statistical evaluation; a numerically valid pruning path is not evidence that every future class group benefits.

Controlled growth with separate evaluation

  • Each recursive node works only on its own arriving examples.
  • Depth and minimum-sample controls stop different kinds of growth.
  • A deeper training fit can capture noise rather than general patterns.
  • Pruning simplifies the model while retaining the original data.
  • Choose complexity on validation and reserve the final test.
