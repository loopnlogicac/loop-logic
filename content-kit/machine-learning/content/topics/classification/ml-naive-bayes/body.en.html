Let counted words provide evidence

Mina sorts six pretend messages for Tuktuk. Some offer free things; others discuss class. One message mixes Bangla and English. Nana asks whether the robot needs to understand every sentence before it can make a useful first guess. Rafi suggests counting a few clearly stated word features.

Naive Bayes combines class frequency with evidence from features. In text classification, those features can be word counts. The model is small enough to calculate by hand, making it a useful baseline before trying more complex representations.

This lesson uses a deliberately tiny two-word vocabulary. You will count it, smooth missing class counts and add log evidence for a query. A later example learns a broader vocabulary from the invented course SMS dataset, while keeping the final test outside fitting.

A vocabulary is the list of word features the model recognises. A prior is the starting class frequency before reading the query's words. Smoothing adds a small count so an in-vocabulary word unseen in one class does not receive zero likelihood.

There are three messages per class, so both priors are one-half. Each class has four occurrences in the selected vocabulary, although some messages contain other words. The English free and Bangla ক্লাস are exact tokens. ফ্রি is a different word and is deliberately excluded from this teaching vocabulary.

That limited vocabulary is a visible modelling choice, not a claim that two words can solve real spam detection. Unknown words contribute nothing to this model. A known word with a zero count in one class is different: it still has a smoothed likelihood there.

Count, smooth and compare the same query

For each class, add alpha to every vocabulary count. With alpha one, the total denominator gains two because there are two word features. Ham likelihoods become one-sixth for free and five-sixths for ক্লাস. Spam has the reverse counts and likelihoods.

For query free free, begin each class score with its prior. Multiply by that class's free likelihood twice because the query contains two occurrences. The spam joint score is one-half times five-sixths squared, about 0.347222. Ham gives one-half times one-sixth squared, about 0.013889.

Choose the larger score, here spam. The common probability of observing the query cancels when comparing classes. If you want posterior probabilities, normalise the two joint scores afterwards. The spam posterior is 25/26, about 0.962, not the unnormalised joint score 0.347222.

The lab fills counts before likelihoods, making the smoothing visible. It uses sums of natural logarithms rather than multiplying many tiny factors. This preserves which score is larger and avoids underflow for long messages. A less negative log score is the larger score.

Totals count recognised vocabulary occurrences rather than every raw word in a message. Both class rows here begin with four selected occurrences, even though the original messages also contain ignored words. Keep that representation rule fixed when calculating the smoothing denominator.

Learn a broader vocabulary from invented course SMS

The vectorizer learns its vocabulary only from training messages. These course messages are invented; a random-row score does not establish performance on future real messages or new campaigns. Whitespace tokenisation is an explicit simple policy, not full Bangla linguistic analysis.

What naive means and what tokenisation loses

The naive assumption treats feature evidence as conditionally independent given the class. Real words often arrive in related phrases. Multiplying their evidence can exaggerate confidence because several words may repeat one underlying clue. A useful decision boundary does not automatically imply well-calibrated probabilities.

Multinomial word counts also discard order. Reordering the same recognised tokens leaves the score unchanged. Whitespace tokenisation preserves the displayed Bangla token, but punctuation and spelling variants can produce different tokens. A full text system needs a representation chosen for its languages and use case, with the same transformation during training and prediction. Lowercasing merges English case variants but does not solve spelling variation or punctuation. Inspect the actual tokens on both languages before interpreting an apparently useful word count as linguistic understanding.

The broader example uses CountVectorizer inside a pipeline. Its vocabulary is learned only from training messages, then fixed for test transformation. The invented dataset provides reproducible arithmetic, not evidence that a deployed filter will handle new campaigns, slang or changing message distributions.

Keep smoothing and evaluation honest

Adding one without changing the denominator

Every vocabulary entry receives the added count. Update the total by alpha times vocabulary size. Otherwise the row no longer represents the stated likelihood distribution.

Confusing unknown words with zero class counts

An out-of-vocabulary token has no feature in this fixed model. A known token unseen in one class receives smoothing. Do not silently expand the vocabulary for each query without refitting the model definition.

Reading joint scores as posterior probabilities

Log scores include prior and likelihood evidence but are not normalised. Compare them for a label or normalise correctly when probabilities are needed.

Leaking message templates across evaluation

Near-duplicate templates in training and test can inflate a random-row score. Consider grouping or time when those better match future use, and state that the course messages are invented.

Optional: Bayes comparison in log space

For class c, Bayes' rule makes the posterior proportional to its prior times the query likelihood. The multinomial model multiplies word likelihoods raised to query counts. Taking logs turns this product into log prior plus a sum of count times log likelihood.

Laplace alpha one is a special additive-smoothing choice. A larger alpha pulls class word distributions toward a more uniform row, reducing the influence of small count differences. Choose representation and alpha using suitable validation rather than repeatedly inspecting final-test answers.

A small baseline with visible assumptions

  • Count documents for class priors and token occurrences for word likelihoods.
  • The naive assumption treats feature evidence as conditionally independent.
  • Smoothing adjusts both a word count and the class total denominator.
  • Out-of-vocabulary words differ from known words unseen in one class.
  • Joint log scores are not normalised posterior probabilities.
