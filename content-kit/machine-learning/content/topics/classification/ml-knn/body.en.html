Ask the nearby cards before naming a new fruit

Nana mixes six labelled fruit cards on the table. Tuktuk receives a seventh card with size and sweetness scores but no name. Mina suggests asking the closest cards to vote. Nana asks how close is close, and how many cards should be heard.

k-nearest neighbours, or KNN, answers both questions explicitly. It measures distance, selects k nearby examples and predicts from their labels. It does not need to learn one fixed fence before every prediction. The stored examples help decide the answer when a query arrives.

You will follow one query through distance measurement, ranking and voting. Then change k and move the query in the lab. Keep the selection rule visible, especially when distances or votes tie.

A query is the new example needing a label. A neighbour is a stored example selected for being close to that query. A vote is one selected example's support for its known category. Farther examples do not vote in this uniform-k prediction.

The query's label is not an input. If you needed that answer to compute the distances, the method would not solve the prediction problem. Coordinates determine closeness; stored labels determine what the selected neighbours vote for.

Measure first, select second, count third

For each stored point, subtract the query's size and sweetness scores. Square the two differences, add them and take the square root. This Euclidean distance is the length of the straight segment between the points. A three-four offset gives distance five, not seven or twenty-five.

Sort by distance and retain the first k examples. If fewer examples exist, use that smaller effective count. This lesson breaks exact distance ties by input order. Count one vote per selected label, then choose the largest count. A tied class count chooses the smaller label zero.

The mango at (4,4) is about 0.990 from (3.3,3.3). The mangoes at (4,5) and (5,4) are about 1.838 away. The nearest apples are farther, so the three selected votes all name mango. The lab exposes each measurement before publishing the prediction.

Do not confuse the neighbourhood with the whole dataset

Counting every stored label

KNN counts only selected neighbours. A large global apple majority can still lose near a small mango group. Rank before voting.

Assuming odd k solves every tie

Odd k avoids a binary equal uniform vote only when that many neighbours actually vote. Distance ties, multiclass ties and a clamped effective count still need policies. Different libraries may select different equal-distance candidates.

Ignoring feature units

A feature measured in thousands can dominate another measured from zero to five. Choose meaningful scaling and learn its parameters on training data only. A pipeline keeps that transformation attached to the classifier.

Calling memory the absence of learning

Basic KNN stores examples rather than fitting a small parameter vector. It still depends on training data, feature choices and a distance rule. Prediction can be costly because the simple implementation compares every stored point.

Optional: distance, voting and prediction cost

For two features, distance is sqrt((x1−q1)²+(x2−q2)²). Each symbol names one point or query coordinate. Ranking can use squared distance because square root preserves nonnegative order, while displayed distances remain in the original units.

The sort-based implementation takes O(n log n) work per query after O(n) distance calculations. It needs the stored examples and a ranking list. Search trees or partial selection can improve some workloads, but high-dimensional distances can become less informative. Feature design and representative data remain essential.

A prediction built from selected examples

  • KNN predicts from nearby stored examples.
  • Measure all candidate distances before selecting neighbours.
  • Distance ties and vote ties need separate stated rules.
  • Odd k does not remove every multiclass or distance tie.
  • Feature scaling changes which points count as close.
