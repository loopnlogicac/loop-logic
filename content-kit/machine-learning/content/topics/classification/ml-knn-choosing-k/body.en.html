The value k controls how local a KNN decision is. One neighbour follows small details, including possible noise. More neighbours average over a larger area. Neither choice is automatically best, so you need evidence from examples held out of training.

You will compare four requested k values, inspect their decision maps and try distance weighting. The same data can produce a different border when you change the voting rule. Keep the final test separate from the cards used to choose that rule.

Give exact matches an explicit rule

Inverse-distance weighting gives a selected neighbour weight one divided by its distance. At distances 0.2, one and two, the weights are five, one and one-half. A nearby minority point can therefore defeat two farther majority points. This is a chosen model policy, not a discovery that the farther labels became wrong.

Distance zero needs special handling. This implementation lets only selected exact matches vote equally when any exist. It does not divide by zero or silently replace zero with an arbitrary tiny number. Duplicate locations with different labels can still tie, so the smaller-label class rule remains relevant.

Raw numeric units influence both selection and weighting. Scaling millimetres to another unit changes distances unless the transformation is handled consistently. Fit scaling on the candidate training portion, then apply that same transform to validation. Do not use held-out feature statistics merely because no labels were read.

Keep model choice separate from final evidence

Choosing from final-test answers

Repeatedly inspecting test performance turns those rows into selection data. Use validation or cross-validation within development data, then assess the fixed result on a separate final test.

Assuming larger means better

Large k can suppress noise but also hide a genuine small class region. When k reaches the whole training set, prediction becomes a global vote. Compare the errors that matter instead of ranking models by smoothness.

Forgetting prediction cost

Storing a large dataset can make each query expensive in a full-sort implementation. Consider query volume, dimension and possible search indexes or partial selection. Measure actual workload costs before assuming a neighbour index always helps.

Optional: validation uncertainty and weighted decisions

A weighted class score sums the chosen weights for neighbours carrying that label. The predictor takes the largest score, with an explicit class tie. Uniform voting is the special case where every selected weight equals one. Neither version produces automatically calibrated probabilities merely by normalising its votes.

Four validation examples provide a coarse measurement: one changed answer moves accuracy by 0.25. Comparing many candidates can also overfit the validation set. Cross-validation and an untouched final test improve the evaluation design, while representative sampling remains essential for the intended population.

Choose the neighbourhood with evidence

  • Choose k using validation evidence rather than final test answers.
  • A smoother boundary can reduce noise sensitivity or hide a real local group.
  • Distance weighting gives closer selected neighbours stronger votes.
  • Exact-match handling prevents inverse-distance division by zero.
  • Fit preprocessing only inside the training portion of each comparison.
