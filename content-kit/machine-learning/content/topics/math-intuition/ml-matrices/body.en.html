A matrix is a rectangular table of numbers. In machine learning, rows commonly represent examples and columns represent features. Multiplying that table by a matching weight vector produces one combined score per example.

You will do each row calculation by hand, read its dimensions, use NumPy's matrix operator and understand a transpose. The arithmetic is familiar multiplication and addition; the new challenge is keeping positions and meanings aligned.

Rows meet the same weight card

A matrix is a rectangular numeric table. Its shape gives row count and column count in that order. A dot product multiplies matching entries of two equal-length vectors and adds their products.

One dot product per example

Name the table X and weights w. X has shape (5,2), meaning five rows and two columns. w has two entries. The matrix-vector product Xw takes one dot product between each row and w.

For row one, multiply 1×2 and 2×1, then add: four. Row two gives 3×2+1×1=7. Row three gives 2×2+4×1=8. Row four gives 0×2+2×1=2. Row five gives 4×2+0×1=8. The output vector is (4,7,8,2,8), with total twenty-nine.

X = rows of feature pairs; w = two weights
for each row i:
    output[i] = 0
    for each column j: output[i] += X[i,j] * w[j]
sum the output entries

The number of feature columns must equal the number of weights. With two feature columns and three weights, the matching rule is incomplete: which feature should multiply the extra weight? NumPy raises a dimension error rather than inventing a pairing.

A transpose swaps rows and columns. For the first three rows, the original table is [[1,2],[3,1],[2,4]]. Its transpose is [[1,3,2],[2,1,4]]. The shape changes from (3,2) to (2,3). The entries are not sorted or otherwise changed; their two index roles are exchanged.

NumPy writes a transpose as X.T and a matrix product as X @ w. In contrast, X * w broadcasts the two weights across columns and leaves a (5,2) array of products. Summing those products across columns would recover the five dot products.

A numeric shape cannot tell you whether a column is size or sweetness. A weight vector in reversed feature order still has length two and passes the dimension check, yet generally gives different scores. Carry the column specification alongside your arrays.

A valid shape is necessary, not sufficient

  • Using * when you mean @: decide whether you need individual products or a dot product with a sum.
  • Transposing a one-dimensional vector to create a column: w.T keeps shape (2,). Add an axis with w[:, None] when you need shape (2,1).
  • Reading shape backwards: the first dimension counts rows and the second counts columns for this matrix.
  • Swapping feature columns alone: reorder their weights consistently or restore the documented feature order.
  • Interpreting toy weights as trained knowledge: these weights were chosen to show arithmetic, not fitted to evidence.

Optional: indices explain the compact operator

For n rows and d features, X is n×d and w is a d-entry vector. Output z has n entries. Its ith entry is zi=ΣXijwj, where j runs over the d feature columns. This is exactly the inner loop in the pseudocode.

Computing all row products takes O(nd) multiplications and additions. Storing the input needs O(nd) space; weights and output need O(d+n). Extra working storage can be constant per row if you emit results one at a time.

In two-dimensional matrix notation, use w with shape d×1 to obtain an n×1 output. NumPy's one-dimensional w instead yields shape (n,). Both can represent the same list of row scores, but later broadcasting operations treat their shapes differently.

Transpose obeys (AB)ᵀ=BᵀAᵀ for compatible matrices. If A is m×n and B is n×p, AB is m×p. Reversing the transposed factors gives p×n times n×m, hence p×m, which matches the required transpose shape. The reversed order matters because matrix multiplication is not generally commutative.

A dot product can represent a linear score. Adding one shared intercept b gives z=Xw+b, where scalar b is added to every output. This generalises the earlier single-input line to many features. It still needs a later fitting procedure to choose useful weights.

When columns have physical units, each weight needs compatible units for the summed terms to make sense. Software can multiply two numeric arrays successfully while producing a meaningless quantity. Document the intended score before assigning interpretation to its output.

For a concrete order check, take A=[[1,1],[0,1]] and B=[[2,0],[0,1]]. Multiplication gives AB=[[2,1],[0,1]] but BA=[[2,2],[0,1]]. Both products have the same shape, yet their upper-right entries differ. Shape compatibility permits an operation; it does not make changing the order harmless.
