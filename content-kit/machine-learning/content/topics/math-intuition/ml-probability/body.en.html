Five tails at the cricket toss

Mina and her friends practise a coin toss before cricket. Five tails appear in a row. Tuktuk declares that heads must come next to repair the record. Nana asks whether the coin remembers the earlier tosses. Mina starts a tally chart. The next result will test Tuktuk's claim, but one result cannot tell them everything about chance.

Probability describes how likely an event is under a stated model. Frequency records what happened in an actual or simulated collection of trials. Their numbers can differ in a short run.

You will count simple outcomes, follow a running head share and simulate coins and dice with fixed seeds. The goal is to understand a long-run tendency without turning it into a guarantee about the next toss.

A model of chance beside a tally

An outcome is one possible result of a trial. An event is a set of outcomes you care about. A probability is a number from zero to one describing an event's chance under the model.

Count the relevant outcomes

For equally likely elementary outcomes, probability is favourable count divided by total count. The even event on a fair die contains 2,4,6, giving 3/6=0.5. Above four contains 5,6, giving 2/6=1/3. Even and above four contains only six, giving 1/6.

For a coin model, let p be the chosen head probability. A simulation produces a number u from zero inclusive to one exclusive. Count a head when u<p. With p=0 no draw qualifies; with p=1 every draw qualifies. A fair coin uses p=0.5.

After t tosses, running frequency is heads/t. The lab starts with integer seed seven and uses an explicit pseudorandom recurrence. That recurrence makes this illustration reproducible. It does not claim to be a cryptographic generator or a physical source of independent randomness.

state = seed
for t from 1 to trials:
    state = (1664525*state + 1013904223) mod 2^32
    u = state / 2^32
    heads += 1 if u < probability else 0
    plot heads/t against the probability

In the first preset, one hundred tosses give fifty-two heads and frequency 0.52. The model probability stays 0.5. Do not change the reference line to the observed share and call that proof of the true probability.

The law of large numbers says that independent repeated trials with the same probability have a sample share that approaches that probability in the long run. It does not say every next trial reduces the current gap.

Keep a paper tally

Run the lab with probability zero and then one. Predict both entire paths. Return to one half and change the seed while preserving the trial count. The target is unchanged, although the observed sequence changes.

Toss a classroom coin twenty times and record every result. Update the head share after each toss using a tally. Combine several classmates' records and compare the combined share with each short record. Discuss whether tossing style or the surface might challenge the fair-independent-coin assumption.

Try a biased probability of 0.8. A long run should tend towards that value, not towards one half. Fairness is an assumption about a particular model, not a requirement imposed on every coin simulation.

Chance does not repay a debt

  • Expecting a compensating head after tails: independent trials keep the same next-toss probability.
  • Equating frequency with truth: a finite observed share is an estimate or illustration, not the underlying model parameter.
  • Counting unequal outcomes as equal: favourable-count ratios require equal elementary chances.
  • Resetting a seed inside the loop: that repeats the start instead of producing successive draws. Initialise once.
  • Demanding a smooth path: inspect the long-run tendency and allow short-run fluctuations.

Optional: indicators and sample-share variation

Let Hi be one for heads and zero for tails on trial i. The observed share is p̂=(1/n)ΣHi. Under independent identical Bernoulli trials, its expectation is p and its variance is p(1-p)/n.

The standard deviation of that share therefore shrinks like 1/sqrt(n). Multiplying the trial count by four halves this typical fluctuation scale; it does not force one particular run to have exactly half its earlier error.

A finite deterministic generator mimics randomness for teaching and numerical work. The probability theorem refers to the ideal trial assumptions. Reproducible code helps you inspect an example of those ideas, while empirical checks still matter for actual coins and data collection.

Separate the model from the observed run

  • Events contain outcomes.
  • Probabilities range from zero to one.
  • Counting ratios need equally likely elementary outcomes.
  • Frequency is an observed proportion.
  • Long-run convergence can include short-run reversals.
  • Seeds reproduce a specified generator's sequence.
