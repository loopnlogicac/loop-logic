Three districts do not make a ranking

Rafi asks Mina to turn three district names into numbers for Tuktuk. Mina writes Badda as zero, Mirpur as one and Uttara as two. Tuktuk says Uttara is twice Mirpur. Nana laughs at the robot's imaginary geography. The names need a numeric representation that does not pretend to measure distance.

Many models calculate sums, products or distances, so raw names need preparation. The conversion must preserve what the category actually means.

You will build indicator columns, recognise when ordered codes are appropriate, and decide how a fitted encoder should handle an unfamiliar name.

Give each name its own switch

One-hot encoding creates one on/off column per category. Ordinal encoding assigns numbers that represent an intended order. A vocabulary is the set of category names an encoder learned during training.

Read across the Mirpur row. Only its own switch is on. All three names receive equal treatment as nominal categories. The columns do not claim that one district is larger, better or farther away.

Ordered service levels are different. Low, medium and high have an intended sequence. Codes 0, 1 and 2 preserve that sequence, but a distance-based model may also assume equal spacing. Check whether that extra assumption is justified.

Six known rows create six ones across eighteen cells. The first row becomes [1,0,0]. The code letters B, M and U stand for the three names. In the lab, the training vocabulary is already fixed; the input string supplies rows to transform.

Enter a question mark for an unseen name. Under ignore, its row is all zeros. Under error, the row is marked ERROR to explain rejection. A real OneHotEncoder using the error policy raises an exception instead of returning numeric cells for that row.

Keeping the entire vocabulary makes an all-zero vector distinguishable from each known category. If you drop one indicator column, all zeros can also mean the dropped baseline. Document that ambiguity when handling unknowns.

Discuss a spelling variation such as an extra space. Decide whether the source means a different district or merely inconsistent text. Apply a fixed, documented spelling rule before fitting categories; do not merge names because their targets happen to look similar.

Pandas get_dummies is useful for exploration. Calling it separately on training and test tables can produce different columns or column orders. Reindex test columns to the training columns with fill_value=0, or use one fitted encoder throughout.

Names do not justify arithmetic

  • Feeding arbitrary district integers into KNN invents distances. Use nominal indicators or a justified representation.
  • Using LabelEncoder on unordered input columns hides a modelling assumption. It is primarily for target labels; use OneHotEncoder for nominal inputs.
  • Learning categories from the combined train and test table uses held-out information. Fit the vocabulary on training data.
  • Silently treating every unknown as a familiar district invents membership. Choose an unknown policy and monitor how often it occurs.

Optional: geometry and many categories

For k categories, a complete one-hot vector has length k with one entry equal to one. Two different known categories have squared Euclidean distance two: one switch turns off and another turns on. Arbitrary integer codes cannot preserve that equal treatment for three or more names.

Thousands of unique names can create thousands of columns. Consider grouping rare categories using training counts, supported encoder frequency options, or a domain-defined grouping. Never group by test outcomes. Sparse storage reduces memory, but it does not remove the statistical difficulty of rare groups.

With an intercept, all k indicators are linearly dependent because their sum is one. Some unregularised linear models drop a baseline column to avoid redundant coefficients. This is a modelling choice, not a universal rule for trees or distance methods.

Keep a stable vocabulary

  • Use nominal indicators when category order has no meaning.
  • Use ordinal codes only with an explicit order and spacing caveat.
  • Fit category names and column order on training data.
  • Transform future rows with those same columns.
  • Declare how missing and unseen names are represented.
  • Watch memory use and rare categories as vocabularies grow.
