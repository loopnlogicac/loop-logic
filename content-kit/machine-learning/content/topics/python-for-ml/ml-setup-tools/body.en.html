A toolbox that opens tomorrow

Mina brings a notebook of mango sizes to Rafi’s room. His first program works. The next morning, the computer says a tool is missing. “Did the mangoes change?” Mina asks. Rafi finds two Python installations. Yesterday’s tools went into one; today’s editor opened the other.

A useful ML toolbox starts with a known Python and a small set of libraries. Before asking a computer to learn, make sure it can open the same tools each time. That saves time when a lesson fails because of setup rather than an idea.

You will prepare a separate environment, import four libraries and check their versions. You will also choose between a script and a notebook. Neither choice learns anything by itself. They are places where you write and run instructions.

Draw a box around the project

Imagine a labelled tray holding the tools for one classroom activity. A virtual environment is a project’s separate collection of Python packages. A package is reusable code that someone has organised for other programs. A kernel is the running Python process behind a notebook.

The tray does not contain the fruit cards themselves. Your scripts and CSV files remain ordinary files in your project directory. You can replace the environment without deleting those files. The environment also is not a security boundary or a separate operating system.

Prepare and verify the interpreter

Install Python 3.12 using the method for your operating system. The lesson’s syntax also works on Python 3.10 and newer, with compatible package releases. First open a terminal in your project folder. On Linux or macOS, create and activate an environment:

python3 --version
python3 -m venv .venv
source .venv/bin/activate
python -m pip install "numpy>=2.0" "pandas>=2.2" "scikit-learn>=1.5" "matplotlib>=3.8"

On Windows, a Python 3.12 installation can create the environment with py -3.12 -m venv .venv. In Command Prompt activate it with .venv\Scripts\activate.bat. PowerShell uses .venv\Scripts\Activate.ps1; school policy may control whether activation scripts can run. Activation only changes which Python command your shell finds first. You can also call the environment’s Python executable directly.

Use the same interpreter in your editor. A Python check such as import sys; print(sys.executable) shows its location. Compare that location in the terminal and the editor when one succeeds and the other fails. Do not name your own file numpy.py or pandas.py; such names can hide the real libraries during ordinary local imports.

Now trace a small task before running it. Five size cards show 2, 3, 4, 5 and 6 cm. Count five cards. Add the sizes to get 20 cm, then divide by five to get a mean of 4 cm. The first script uses a different three-card check, [2,4,6], with that same mean. Counting and averaging verify that imports lead to usable numeric operations.

A script is a saved .py file, run from start to finish with python first.py. Jupyter notebooks divide work into cells, which can show a table or plot near its explanation. Use Jupyter if your computer or classroom already provides it, and select the intended environment as its kernel. A notebook interface is optional; these lessons need only scripts and the four libraries.

Google Colab provides hosted notebooks in a browser. It can help when local installation is unavailable, but it requires a connection. Its library versions may differ, and session files can disappear. Copy the course CSVs into the session before reading them, preserve your work outside temporary session storage, and check imports there too. Do not upload private records to practise these lessons.

Test a fresh start

Run the import example, close Python, then run it again. Check that both runs report three rows and mean size 4.0. In a notebook, restart the kernel and run all cells in order. A saved screen full of results does not show whether the current cell order is sufficient.

Make five paper tool cards using the table above. Put Python beside a blank instruction sheet. Add NumPy only when a calculation needs an array, and pandas when the task needs column names. Tell a partner which card scikit-learn represents and why no learning has happened yet.

Three setup checks

The first program imports every required tool and performs a known calculation. A successful import is useful evidence, but the numeric result also confirms that the tools can do work.

The second program reads installed version numbers and checks minimums. Full version strings vary across installations. Inspect the local strings when reporting a problem, including the Python executable used.

The third program separates a numeric function from its starting instructions. The guard runs the demonstration when the file is executed. Keeping its input visible makes the calculation independent of yesterday’s notebook state.

When a tool seems missing

Installing into a different Python

If pip says a package exists but the script cannot import it, compare interpreter paths. Run installation through that interpreter with python -m pip. Repeatedly installing into another environment will not help.

Confusing cells with a complete program

A notebook can remember variables from cells you deleted or ran earlier. Restarting clears them. Keep data loading before calculations and rerun the whole notebook after editing.

Relying on an open cloud session

A hosted runtime may reset. Keep the original data and saved notebook in durable storage. Recreating the environment should be possible from your recorded steps.

Optional: what reproduction needs

Rafi distinguishes a minimum requirement from an exact environment record. A minimum allows newer compatible releases; it does not promise identical numerical behaviour forever. Record Python, library versions, code, inputs and any seeds when preserving an experiment. A virtual environment isolates installations but does not freeze versions automatically. Hardware and numerical libraries can matter for some later calculations too.
