Check validity before predicting a value

These thirty-two programs are grouped by the rule that makes their output interesting. Read the complete program, write a small state table and predict the result before running it. Every numeric question here has defined behavior under its selected C17 rules; undefined expressions are not puzzles with a secret compiler-dependent number.

Track changes at full-expression boundaries. Keep a pointer's position separate from the value it names, and keep a string's visible length separate from its array capacity. For a macro, expand the tokens before applying precedence. For a static local, carry its state from one call to the next.

After comparing your answer, explain the first step where your reasoning differed. A correct guess without the rule is less useful than a wrong prediction followed by a repaired trace. The worked explanations identify both the intermediate state and the operation that produces the final output.

Operators

Integer division before conversion

a/b is integer three before the first cast. Casting a before division makes the second quotient 3.5.

Short-circuit AND skips an update

The first condition is false, so ++n is not evaluated. Both result and n remain zero.

Short-circuit OR skips an update

The first condition is true, so the second operand is skipped. A logical result is one rather than the original four.

Bitwise selection differs from logical truth

Binary 110 AND 011 selects bit one, giving two. Both operands are nonzero, so logical AND gives one.

Conditional operator chooses one update

Only the false branch runs because two is not above eight. y becomes nine and the chosen value is nine.

Comma operator sequences two steps

The comma operator completes x += 2 first. Its right expression then computes nine from x equal to three.

Loops

Loop counter after the final failed condition

The body adds one, two and three. The last increment leaves i at four, where the condition fails.

Continue still reaches the for increment

Even values skip addition but still reach the increment. The sum is one plus three plus five.

Break preserves the current counter

The break exits immediately at two. The for increment does not run after that break.

A do loop executes before testing

The body runs once before the false condition is tested. n therefore becomes one despite starting at zero.

Nested triangular iteration count

The inner loop runs one, two and three times. Adding those row lengths gives six.

A post-decrement condition changes the final state

The body runs for old values three, two and one. The final comparison uses old zero but still decrements n to minus one.

Pointers

Post-incrementing the pointer rather than its element

The old pointer is dereferenced for ten. The pointer then advances to the element containing twenty.

Incrementing an element through a pointer

The pointed-to int becomes eleven. The pointer itself remains at the first element.

Pointer subtraction counts elements

Both pointers belong to the same array. Their difference counts two int elements, not a byte distance.

A pointer-to-pointer replaces the selected pointer

Assigning through link changes p to name b. It does not change the separate int object a.

One-past is a boundary rather than an element

The one-past pointer may be formed and subtracted within this array. Moving back one reaches the final element nine.

Strings

The array has room for three letters and a terminator. The string length excludes the terminator.

The three source letters abc are copied safely into indices one through three. The original terminator at four remains, producing aabc.

The differing characters are eight and nine; decimal digit order is guaranteed. The comparison is negative; only its sign is used.

Macros

Parenthesise a complete macro replacement

The grouped addition is evaluated before multiplication. A macro replacement used as an expression needs equivalent grouping.

Observe a deliberately ungrouped replacement

SUM_BAD expands to 2 + 1 without enclosing parentheses. The expression becomes 3 * 2 + 1, so multiplication happens first.

A grouped square macro handles an expression operand

Parenthesised parameter occurrences and the complete replacement preserve the intended square. The operand has no side effects.

Conditional compilation chooses a branch before execution

FEATURE_VALUE is defined as seven in the selected preprocessor branch. The unselected source branch is not a runtime alternative.

A function avoids repeating an argument side effect

The function argument is evaluated once, supplying three, and i becomes four. twice computes six from its local parameter.

Static state

A static local is initialised once

The static local starts at zero once and persists. Separate calls return one and then two.

An automatic local starts fresh on each call

Each call creates and initialises a new local count. Both calls increment their own zero to one.

Block shadowing does not replace a static object

The inner automatic count shadows the static name only within its block. The static object is then incremented separately across calls.

Zero-initialised static arrays retain assignments

Static storage is zero-initialised before execution. Only the middle element changes to four.

A static accumulator keeps earlier contributions

The first call stores three in the persistent total. The second adds five to that total and returns eight.
