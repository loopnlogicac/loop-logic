Replace unexplained status numbers with names

A lab submission may be new, running, done, or failed. Storing only the numbers two, three, eight, and nine makes the code difficult to remember. An enumeration gives names to a related set of integer constants. STATUS_DONE tells a reader what the value means without a nearby decoding comment.

Think of an enum as a small vocabulary for choices. It does not store several values at once like a record. An enum variable holds one value used to describe a current state. A switch can then branch using readable constant names rather than repeated numeric literals.

Names help people maintain the code, but C17 enums do not validate every input automatically. A number read from a file or typed by a user may not match any named choice. Validate that external number before treating it as an accepted state. Keep an unknown-value branch where the interface permits arbitrary codes.

Read the C notation

The enum keyword starts a list of enumerators. You may assign a value explicitly or let C choose the next integer. Without an explicit first value, counting starts at zero. After an explicit value, the next unassigned enumerator is one larger. Different gaps are allowed when external codes require them.

The tag Status names the enum type. Like a struct tag, it normally appears with its keyword in C: enum Status status. Enumerator names themselves are ordinary identifiers in their scope. A prefix such as STATUS_ avoids collisions with names from other enum definitions.

enum Status { STATUS_NEW = 2, STATUS_RUNNING, STATUS_DONE = 8, STATUS_FAILED };

Follow named values into a switch

The first example prints the enumerator values as integers. STATUS_NEW starts at two, STATUS_RUNNING follows at three, STATUS_DONE restarts at eight, and STATUS_FAILED follows at nine. These are compile-time constant choices. There is no loop assigning them during program execution.

The second example stores STATUS_DONE in status. The switch selects the matching case and prints done. A break prevents control from continuing into the following case. Enum names improve the labels, but ordinary switch control-flow rules remain unchanged.

The third example uses a zero-based Stage sequence. DRAFT is zero, REVIEW is one, and PUBLISHED is two. Assigning STAGE_REVIEW changes the current state. Comparing that state with STAGE_REVIEW produces true, represented by integer one. The published constant remains two regardless of the variable's current state.

An enum variable's underlying compatible integer type is implementation-defined in C17. Do not assume sizeof(enum Status) equals sizeof(int). Enumerator constants in C17 have type int and must have int-representable values. Cast an enum variable to int for these known small values when passing it to an integer printf conversion.

Enum names and macro constants

A #define can give a number a name too, but it does token replacement before C parsing. An enum groups related integer constants in the language and often gives debuggers better symbolic information. A macro can represent more kinds of replacement text, including strings or expressions. Choose based on purpose rather than using one mechanism for every name.

Enum constants are not preprocessor macros. An #ifdef STATUS_DONE tests whether a macro with that name exists, not whether an enum constant was declared. A preprocessor #if cannot inspect ordinary C enum declarations. Keep compile-time source selection separate from runtime state choices.

An enum can also be used as a union tag, as shown in Unions. The names identify which payload member is meaningful. The enum alone does not enforce the agreement. Construction and reading code must consistently use the same named alternatives.

Mistakes and repairs

Assuming a cast validates input

Casting a number to enum Stage does not check whether it equals DRAFT, REVIEW, or PUBLISHED. Check the accepted numeric codes first. If the values are sparse, use explicit cases rather than only a minimum and maximum. Values between the extremes may still be unnamed.

Writing duplicate case values

C allows different enumerator names to share the same value, but a switch cannot contain two case labels with the same value. Treat aliases as one branch or choose a different state representation. Names do not make numerically duplicate cases distinct.

Habits to use in your programs

Use prefixed enumerator names that explain the state in a wider source file. Assign explicit values when an external protocol requires stable codes. Otherwise a simple zero-based sequence is easier to extend and inspect. Avoid assuming that declaration order defines every future transition rule.

Separate state transitions from raw numeric arithmetic when the state graph becomes more complex. Adding one works for the small consecutive Stage exercise, but sparse Status values need explicit transitions. Write tests for the final state, no-change actions, and unknown codes. Enum readability helps reveal those rules; it does not implement them.

C versions and portability

Enums are part of C89 and later. All examples target C17 and use small int-representable enumerators. C23 extends enum facilities, including fixed underlying types, but those forms are not used here. Do not apply C23 assumptions about enumerator types or declarations to these C17 programs.
