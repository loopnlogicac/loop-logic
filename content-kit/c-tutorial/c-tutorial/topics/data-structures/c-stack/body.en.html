The latest unfinished job stays on top

When you place books in a pile, the last book added is the first one you can remove without disturbing the rest. A stack gives that same order to program data. Push adds at the top, pop removes from the top and peek observes the top without removing anything. Numeric size has no role in deciding which value comes next.

A stack is an abstract set of operations, not one particular memory layout. You can store its elements in a fixed array or in linked nodes. Both must agree on the visible order and on what happens when an operation cannot succeed. Separating that behavior from the storage choice helps you choose a representation for the workload.

Stacks appear in nested-expression processing, undo histories and depth-first exploration. This lesson uses bracket matching because you can trace its entire state with a small drawing. A closing bracket must finish the most recent unfinished opening bracket, exactly the order a stack provides.

Use count as the next free array position

The array representation contains eight int slots and a size_t count initially zero. Live values occupy indices zero through count minus one. The top exists only when count is positive. No stored value is reserved as an empty marker, so zero and negative values remain valid data.

array_push returns a status. When count equals capacity, it returns failure before writing. Otherwise it stores at values[count] and increments count. array_pop first rejects an empty stack, then decrements count and copies that element to the caller's output. array_peek reads the same element without changing count.

The functions require valid stack and output pointers and a stack whose invariant already holds. An output parameter is changed only on success. This prevents callers from confusing a legitimate zero with an empty-stack result. Never read an uninitialised output merely because a failed pop left it untouched.

Keep the same operations with linked nodes

A linked stack owns a head pointer named top. A null top means empty. Push allocates a node, stores the value, points its next at the old top and publishes the new node as top. The old chain remains reachable. If allocation fails, return without changing any link.

Pop saves the node at top and its value, advances top to the saved successor, then frees the removed node. Peek reads the value without changing a link or lifetime. Cleanup repeatedly pops until no nodes remain. A borrowed pointer to a popped node becomes dangling, even if the owning top now points somewhere valid.

The linked representation has no fixed eight-element capacity, but that does not make it unlimited. Allocation can fail, and each node needs a pointer and allocator overhead in addition to its value. The array representation has predictable fixed storage and avoids per-push allocation. Choose based on bounds and allocation requirements rather than assuming linked means better.

Compare the abstraction across storage choices

Keep peek non-destructive while pop removes the latest value

The count names the next free index, so the top element is at count minus one only when count is positive. Peek preserves count. Pop returns twenty before ten, demonstrating last-in, first-out order.

Use linked nodes without imposing an array capacity

Each push allocates one node at the head; pop unlinks and frees that node. The linked version can still fail allocation, so it is not an unlimited stack. Cleanup handles an already-empty owner safely.

Match nested brackets by comparing the most recent opener

Correct counts alone are insufficient: ([)] crosses nesting order. Each closing bracket must match the most recent unmatched opener. The matching function ignores non-bracket characters; it is not a C lexer and does not interpret quotes or comments.

Reject array overflow and preserve an output on underflow

The ninth push fails before writing outside the eight slots. A failed pop does not invent a value or modify the output. Status and data stay separate, so zero would remain a valid stored value.

Use the top to enforce nesting order

Read the text from left to right. Push each opening bracket. On a closing bracket, first reject an empty stack, then pop the most recent opener and compare its type. A mismatch fails immediately. When scanning ends, success requires an empty stack: an unmatched opener is still an unfinished job.

The string (() has no mismatched closer, yet fails the final empty check. The string )( fails immediately because no opener exists for its first character.

The implementation ignores non-bracket characters and accepts at most eighty unmatched openers. For the line exercise, the whole input length is bounded at eighty, so this storage is sufficient. It does not recognise quoted strings, escaped characters or comments in C source. Calling it a full programming-language parser would overstate its contract.

Understand constant-time operations and bounded memory

Push, pop and peek perform constant structural work in the array design. Linked operations also change only a constant number of links, apart from the allocator's own behavior. Printing or clearing all n elements takes linear work. Bracket matching visits each character once, so its scanning time is linear in text length.

Auxiliary stack space is proportional to the largest unmatched nesting depth. A flat sequence such as ()() uses little stack space; many opening brackets before their closers use more. A fixed maximum can make an array attractive. If the maximum is unknown, choose dynamic growth or a linked design and state how allocation failure is reported.

An undo feature needs more policy than raw stack operations. Decide what constitutes one action, whether rejected actions are recorded and whether a new action clears redo history. The data structure supplies ordering; the application supplies meaning. Keeping those responsibilities separate prevents a correct stack from being mistaken for a complete workflow.

Test the empty and full transitions explicitly

Start by popping and peeking an empty stack with a known output value, then verify that failure preserves that output. Push one value, peek twice and confirm that both observations agree and count remains one. Pop it and confirm that the stack returns to empty. These cases expose underflow and accidental destructive peeks.

For the array, fill every slot, reject one extra push and then pop all original values in reverse order. A failed extra push must not replace the previous top. For linked storage, review the allocation-failure branch and clear a partially built stack before returning. A normal successful run does not exercise every possible allocation failure.

For brackets, include a blank line, one matched pair, nested mixed types, adjacent groups, a wrong-type closer, an early closer and an unfinished opener. These inputs test independent conditions. Adding many balanced examples cannot replace one crossing-order case that actually challenges the algorithm.

Preserve the abstraction at the boundaries

Using count as a live top index

count identifies the next free slot. Reading values[count] as the top reads outside the live range and can reach outside the buffer when full. Check nonempty, then use count minus one.

Returning zero as both data and failure

Store the value through an output pointer and return status separately. A stack containing zero must still be distinguishable from an empty stack. Callers use the output only after a successful result.

Freeing the remaining chain on pop

One pop removes one node. Advance top before freeing that node and leave the remaining chain owned by top. Whole-stack cleanup is a separate operation that repeats the single-node removal safely.

Matching only bracket totals

Totals cannot represent nesting order. Compare each closer with the actual top opener and require no unfinished opener at the end. Preserve the full state needed by the question rather than a smaller summary that loses essential information.

Trace state as well as returned values

For push 4, push 7, pop and push 9, write the stored sequence after every step: [4], [4,7], [4] and [4,9]. The returned pop value is seven, but it is no longer part of the stored sequence. Keeping these two records separate prevents a common trace error in which removed values remain drawn inside the stack.

Now peek twice. Both calls observe nine and preserve [4,9]. The next two pops return nine and four, leaving empty storage. A final failed pop changes neither the empty state nor the caller's previous output. This trace checks order, observation and failure behavior in one short sequence.

C17 implementations with explicit ownership

Both storage implementations use standard C17 and single-threaded ownership. They are not concurrent stacks. The examples compile their module locally, while the standalone bracket example needs only the standard library. A bounded array failure and a linked allocation failure are both ordinary results that callers must handle.

One end, one ordering rule

A stack keeps the latest remaining value at the top. Maintain the array count or linked owner, report boundary failures explicitly and use nesting order when matching brackets. Next, a queue separates the insertion and removal ends to preserve arrival order.
