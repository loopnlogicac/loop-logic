Introduction

A lab entry rule may require both a valid roll and enough attendance. Another rule may allow either of two room numbers. Logical operators let you combine questions. Logical AND, written &&, requires both sides.

Logical OR, written ||, requires at least one side. Logical NOT, written !, reverses a truth value.

C treats scalar zero as false and a nonzero scalar as true. The logical result is still exactly int zero or one. Thus combining two numbers does not preserve their magnitudes. Logical operators answer yes-or-no questions; arithmetic operators calculate quantities.

Syntax and reading guide

valid = mark >= 0 && mark <= 100;
choice = room == 201 || room == 202;
missing = !present;

Follow the values and decisions

Start by evaluating the left operand. For AND, a false left operand already makes the whole answer false. C skips the right operand. For OR, a true left operand already makes the whole answer true, so C skips the right operand.

This behavior is short-circuit evaluation. The left evaluation is sequenced before the right evaluation when the right side is needed.

Use that order to guard a dangerous operation. In divisor != 0 && total / divisor > 2, the first question prevents division by zero. Reversing the operands loses the protection. A guard must come before the operation it protects, not afterward on the same line.

NOT binds more tightly than comparisons and AND. The expression !marks == 40 compares the normalized result of NOT with forty. To negate a comparison, write !(marks == 40), or use marks != 40. AND groups more tightly than OR; parentheses make a mixed attendance rule easier to read.

You can trace short-circuiting with a separate counter increment on the right. If the left side decides the answer, the counter never changes. This is useful for understanding execution, but avoid burying important work in conditions. A condition is easiest to review when it mostly asks questions.

Examples

Check a marks interval

Both comparisons are true, so AND produces one. A mark below zero or above one hundred would fail one side. The expression describes a closed interval without using a mathematical chained comparison.

Skip an unnecessary update

The left zero decides the false result. C never evaluates the prefix increment on the right. Both printed fields are zero. This demonstrates skipped execution rather than an increment whose result was discarded.

Guard a division

Count is zero, so the first comparison fails. The division is skipped completely, leaving a safe result of zero. Switching the two operands would attempt the division before its guard.

Boundaries and alternatives

Logical AND is different from bitwise AND. One ampersand combines integer bits and evaluates both operands; two ampersands combine truth values and may skip one operand. Likewise, one vertical bar is bitwise OR and two are logical OR. Their precedence groups also differ.

For a range, join the lower and upper comparisons with AND. For alternatives, repeat the entire comparison on each side of OR. Writing room == 201 || 202 is always true because the literal 202 is nonzero. The computer does not fill in the missing comparison from English context.

Common mistakes

Forgetting to repeat the comparison

Write room == 201 || room == 202. A bare second room number is treated as true, so it admits every room.

Putting the safety check second

Division happens too early in total / count > 2 && count != 0. Check count first. Parentheses around the existing operands do not change that order.

Questions to ask while reading

QuestionRule and reason
When does logical AND skip its right operand?When the left operand is false. A false left side already fixes the result at zero.
When does logical OR skip its right operand?When the left operand is true. A true left side already makes the result one.
Which value does !(-5) produce?0. Negative five is nonzero and therefore true; NOT reverses it.
Which binds more tightly: ! or &&?!. NOT is unary and has higher precedence.
Which expression safely guards division by count?count != 0 && total / count > 2. AND checks the guard first and can skip division.
Why is room == 201 || 202 always true?The bare nonzero 202 is true. Each side must contain the full intended question.
What distinguishes & from &&?& works on bits and does not short-circuit. The bitwise and logical operations have different meanings.

The order can protect more than arithmetic. Later array lessons use a bounds check before accessing an element. The same reasoning applies: the left condition must establish that the right operation is valid. If a required action must always happen, do not hide it in an operand that short-circuiting may skip.

Perform it in a separate statement and name its result before combining the truth questions.

For a room alternative, test an allowed first room, an allowed second room, and a room in neither category. For an AND rule, test each requirement failing independently. These cases distinguish a correct combination from an expression that happens to accept one ordinary example.

Version notes

Logical operators and their short-circuit rules apply throughout C89 to C23. C17 needs no Boolean header for integer truth expressions. stdbool.h can provide more readable flag declarations.
