Introduction

Imagine a row of small switches, each recording whether one lab device is ready. Instead of storing a separate integer for every switch, you can store several flags in the bits of one unsigned integer. Bitwise operators combine or move those individual binary digits. A bit is one binary digit, either zero or one.

Use unsigned operands while learning these operations. They make the representation and shift rules easier to reason about. The examples display ordinary decimal results alongside small binary diagrams. The diagram shows only the low four bits; an unsigned int normally has more bits.

Follow the values and decisions

AND puts a one in a result position only when both input bits are one. OR uses one when either bit is one. XOR, exclusive OR, uses one when the input bits differ. Work through the diagram one column at a time from the low bit.

The decimal output then confirms the binary calculation.

A mask is an integer whose selected bits identify positions of interest. For bit position two, counting from zero, 1U << 2 makes a mask with value four. OR with that mask sets the bit. AND with the complemented mask clears the bit.

XOR with the mask toggles it. AND with the original mask checks whether it is present; compare the result with zero for a normalized truth value.

Complement flips every bit of the promoted operand type, not only the four bits drawn on paper. To display a four-bit complement, mask the result with 15U. Without that mask, complementing a small unsigned int produces a much larger value. The number of meaningful bits in your task is separate from the width of the C type.

Unsigned left shift moves bits toward higher positions and fills low positions with zero. Unsigned right shift moves toward lower positions and fills high positions with zero. The shift count must be nonnegative and smaller than the width of the promoted left operand. A count equal to that width is invalid, even if you expect the result to be zero.

Examples

Combine two bit patterns

The low-bit diagram predicts eight for AND, fourteen for OR and six for XOR. Check each output by lining up the two binary operands. The operators act on matching positions; they do not combine the decimal digits twelve and ten.

Set, clear, toggle and test

Starting from two, setting bit two gives six. Clearing the bit represented by two leaves four. Toggling bit two turns it off and leaves zero. The final check is false.

Following each stored update explains why the flag disappears.

Limit complement to four bits

Ten has low bits 1010. Complementing and retaining four positions gives 0101, or five. A left shift gives twenty and a right shift gives five. All shift counts are one, safely below the unsigned int width.

Parity and a distinct-object XOR swap

The low bit of five is one, indicating odd parity. Three separate XOR assignments exchange a and b. The objects are distinct, and each update completes before the next begins. This demonstrates the identity; a temporary variable would communicate the swap more directly.

Boundaries and alternatives

Do not shift negative signed values as a shortcut for multiplication or division. In C17, left shifting a negative signed value is undefined, and right shifting a negative signed value is implementation-defined. Signed left shifts of nonnegative values also have representability restrictions. Use unsigned values and bounds that suit the intended bit operation.

The low bit identifies parity for a nonnegative unsigned number: n & 1U is zero for even values and one for odd values. Parenthesize a bitwise test before comparing it, because equality has higher precedence than bitwise AND. The intended test is (flags & mask) != 0U.

XOR can swap two distinct integer objects using three statements. The identity works because XORing a value with the same mask twice restores it. However, using the same object for both names would destroy the value. A temporary-variable swap is easier to read and is usually the better choice in ordinary code.

Reason about unchanged positions

A useful check for setting a bit is that every other position stays unchanged. OR with a one-bit mask has zeroes elsewhere, so each unrelated input bit OR zero keeps its old value. Clearing uses ones elsewhere in the complemented mask, so those positions survive AND. Toggling uses zeroes elsewhere, which also preserve the old bits under XOR.

These statements are stronger than checking one decimal result. Draw the before and after rows for zero, an already-set bit, and all low bits set. The same position rule explains all three. If two unrelated positions change, inspect the mask rather than the decimal output format.

Common mistakes

Using logical AND for a mask

Logical AND asks whether both whole operands are nonzero. It produces only zero or one and cannot preserve the selected bit pattern. Use a single ampersand for bit intersection.

Forgetting integer promotion

An unsigned char operand can promote to int before complement or shift. Do not assume every operation stays eight bits wide. Choose an unsigned calculation type and mask the intended low bits explicitly.

Questions to ask while reading

QuestionRule and reason
Which operation sets selected bits?OR with the mask. A one in the mask forces an OR result bit to one.
Which operation clears a selected bit?AND with the complemented mask. Complement puts a zero at the selected position.
What does XOR with a one-bit mask do?Toggle that bit. A differing mask bit reverses the input bit.
Which type is preferable for beginner bit shifts?unsigned int. Unsigned shifts have clearer bit-filling and arithmetic rules.
Is shifting by the full operand width valid?No. The count must be strictly less than the promoted type width.
What does ~ flip?Every bit of the promoted operand type. An explicit low-bit mask limits the displayed result.
Why is XOR swapping the same object twice unsafe?The first self-XOR clears it. The identity requires two distinct objects with their values preserved through the sequence.

Name a position before making its mask

Number the least significant bit as position zero. Its value is one. Position one has value two, position two has value four, and position three has value eight. A mask for position three is therefore eight, rather than the number three.

Confusing a position with its mask often changes several unintended bits.

For a value with low bits 1010, checking position one gives a nonzero intersection of value two. That result says the bit is present, but it is not normalized to one. Comparing the intersection with zero produces an int flag of one. Keep the raw mask result when you need bits; normalize it when you need a yes-or-no answer.

The two forms serve different purposes even though both can act as a true condition.

When serializing a flag field, define its bit positions as part of the data format. Do not assume a C object's byte layout is automatically a portable external format.

Version notes

All six bitwise operators exist in C89. These examples use C17 and hexadecimal or decimal masks; binary 0b literals become standard in C23. C17 negative signed right shifts remain implementation-defined.

Summary

Bitwise operators combine integer bit positions. OR sets, AND with complement clears, and XOR toggles. Continue with Assignment Operators.
