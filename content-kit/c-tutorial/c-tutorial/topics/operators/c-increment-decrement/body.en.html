Introduction

Imagine numbering students as they enter a lab. After giving one student a number, you advance the counter for the next student. Increment adds one to a modifiable value; decrement subtracts one. C writes them as ++ and --.

Placement matters when the expression's value is also used. Prefix updates first and supplies the new value. Postfix supplies the old value while still scheduling the update as part of that expression. Both leave a standalone counter one step higher or lower.

Use a separate statement when you only need to change the counter.

Syntax and reading guide

++count;  /* prefix */
count++;  /* postfix */
--count;
count--;

The operand must identify a modifiable object of a permitted type. You cannot increment a numeric literal or a const-qualified counter. These examples use integers with values safely away from their limits.

Follow the values and decisions

Trace int used = count++; with count initially four. The expression supplies four to initialize used. By the next statement, count is five. For int used = ++count;, the expression instead supplies five, and count is also five afterward.

The prefix/postfix difference concerns the supplied value, not whether the counter eventually changes.

A side effect is a change to program state. Both forms modify the operand. A full expression, such as a standalone assignment statement, completes before the next full expression begins. Older explanations call certain boundaries sequence points.

Modern C also describes one evaluation as sequenced before another. You need not memorize every formal rule to use a safe habit: perform one counter update per statement.

Writing i = i++; is undefined behavior in C17. The assignment and postfix side effect modify i without the required sequencing between them. There is no portable final value to predict. Parentheses do not introduce the missing sequencing.

Likewise, avoid reading and updating the same counter in different printf arguments. C does not specify their evaluation order in a way that makes that pattern safe.

Examples

Use the current ticket first

Postfix supplies the current ticket, four, to issued. The update leaves ticket at five before printf runs. This matches giving out a number and preparing its successor. Two different variables make the old and new values visible.

Advance before assigning

Prefix adds one before supplying the expression value. Both fields are five because issued receives the updated value. Compare this with the previous example: the counter ends the same way, while the assigned value differs.

Compare two decrements

Postfix decrement supplies eight and leaves a at seven. Prefix decrement leaves b at seven and supplies seven. The four printed fields separate each expression value from its operand after the full statement. None of the updates are combined unsafely.

Boundaries and alternatives

For a standalone count++;, prefix and postfix have the same final effect for an integer counter. Choose the form that makes your intention clear. When assigning a ticket number, deliberately choose whether the current ticket or the following ticket should be used.

Decrement follows the same old-value/new-value distinction. If an unsigned counter is zero, decrement wraps it to the maximum value. That is defined unsigned arithmetic, but rarely the intended seat count. A signed counter at its minimum must not be decremented because that would overflow.

Check the task's boundaries rather than treating the short operator as automatically safe.

Common mistakes

Predicting a result for i = i++

The expression has undefined behavior in C17. Split the intended actions into separate statements and decide which value each statement should use. A compiler warning is useful evidence, but silence would not make the expression valid.

Assuming postfix waits until the next statement

In used = count++;, count has already changed by the next statement. The old value is supplied to used, not kept in count. Trace the two variables in separate columns.

Questions to ask while reading

QuestionRule and reason
For int n = 4; int x = ++n;, which value initializes x?5. Prefix supplies the value after incrementing.
What does postfix n++ supply to its surrounding expression?The value before increment. The operand changes, but the expression supplies its earlier value.
When is n changed after x = n++; finishes?Before the next statement. The side effect completes within that full expression.
Which operand can be incremented here?A modifiable int variable. Increment needs an appropriate modifiable operand.
Why is i = i++ invalid to predict in C17?Its modifications lack required sequencing. Undefined behavior means no portable final value exists.
How should you pass old and new counter values to printf safely?Save and update in earlier separate statements. Separate full expressions establish the needed order.
What does decrementing unsigned zero do?Wrap to the maximum unsigned value. Unsigned arithmetic wraps; the task may still consider that a mistake.

Keep two columns for a consumed value

Statement with count initially 4Saved valueCount afterward
saved = count++;45
saved = ++count;55
saved = count--;43
saved = --count;33

Reset count to four before comparing these rows. They are separate experiments, not four consecutive statements. When they become consecutive, each row must instead begin from the previous row's final count. This small bookkeeping difference explains many incorrect counter traces.

The saved ticket and the next ticket have separate purposes. Keep both names when the current value must be reported after the counter has advanced.

Version notes

Prefix and postfix integer updates have long existed in C. C11 introduced the modern sequencing terminology used here. Under the C17 baseline, i = i++ remains undefined; do not transfer rules from a different programming language.
