Introduction

Suppose a student needs at least forty marks to pass. Your program must ask whether the stored mark reaches that boundary. A comparison checks a relationship between values and produces a truth result. In C, the relational and equality operators produce integer zero for false or one for true.

This makes a comparison useful even before you learn branching. You can store its result in an int, print it, or combine it with another question. Read the comparison aloud: marks greater than or equal to forty. The words help you notice whether the boundary belongs on the passing side.

Syntax and reading guide

a < b
 a > b
 a <= b
 a >= b
 a == b
 a != b

The first four are relational operators in the formal terminology. Equality and inequality form a separate precedence group. They are often taught together because all six answer comparison questions.

Follow the values and decisions

With a mark of forty, marks > 40 is false while marks >= 40 is true. Test the exact threshold, then one value on each side. This three-value check is a quick way to catch a wrong boundary operator.

Equality uses two equals signs. A single equals sign performs assignment and supplies the assigned value. If a program asks a question by assigning forty to marks, it changes the mark and produces nonzero forty instead of checking anything. Warning-enabled compilers catch many suspicious cases, but you should still read each equals sign according to its role.

Do not write a mathematical chain such as 0 < marks <= 100. C groups it as (0 < marks) <= 100. The first comparison becomes zero or one, so the second test is always true for those results. Use two comparisons joined by logical AND, as taught in logical operators.

Comparison operands also undergo type conversions. Avoid casually mixing negative signed numbers with unsigned counts. The conversion rules can change a negative value into a large unsigned value before the comparison. Use compatible types for quantities you intend to compare.

Examples

Check the passing boundary

Forty does not exceed forty, but it reaches the inclusive threshold and equals it. The results are zero, one and one. Looking at all three questions together makes the meaning of the equals bar visible at the passing boundary.

Compare two scores

Theory is larger than lab, so the less-than test is false and the greater-than test is true. The values are also unequal. Each result is an int truth value rather than a copy of either score.

Use a measurement tolerance

The permitted absolute error is one millionth in the chosen units. The difference between these small finite values is below that limit, so the result is one. The tolerance is written explicitly so a reader can judge whether it suits the measurement.

Boundaries and alternatives

Floating arithmetic often approximates decimal fractions. An exact equality test can therefore fail even when two calculations represent the same measured quantity. One possible absolute test is fabs(a - b) <= tolerance. fabs, from math.h, gives the absolute magnitude of a double.

Choose tolerance from the task's units and permitted error. A tolerance of 0.01 may suit a coarse measurement but be much too large for another task. For widely varying magnitudes, combine absolute and relative tolerances, for example by comparing the difference with an allowed scale-dependent error. The examples use small finite values and an explicit absolute tolerance.

NaN values compare unequal even to themselves; unrestricted measurements need a separate policy for such values.

Common mistakes

Confusing = with ==

The single equals sign replaces the left value. Double equals compares two values and leaves them unchanged. Name the task as either storing or asking before choosing the symbol.

Using exact equality for every measured result

Decide whether exact identity is the real requirement. For approximate measurements, state an error budget and compare the difference against it. Do not choose a tolerance merely because one failed example starts passing.

Questions to ask while reading

QuestionRule and reason
What type does a C relational expression produce?int. Its value is zero or one.
Which operator asks whether marks equals 40?==. Equality needs the doubled symbol.
Which comparison includes the upper boundary 100?marks <= 100. Less than or equal includes equality.
How should a closed range be expressed in C?x >= low && x <= high. Each comparison is complete and AND requires both.
Why may 0.1 + 0.2 fail an exact equality check with 0.3?Binary floating arithmetic can approximate the values. A small representation difference may remain.
Who determines a useful comparison tolerance?The task units and error requirement. A tolerance suitable for one measurement can be unsuitable for another.
Does a comparison modify its operands?No. Ordinary comparisons compute a result without assignment.

Choose a tolerance in the correct units

Suppose a measurement is reported in metres and allows an error of one centimetre. An absolute tolerance of 0.01 metres has a concrete meaning. If you convert both readings to centimetres, the matching tolerance becomes one, not 0.01. Keep the tolerance in the same units as the difference.

For exact integer identifiers such as roll numbers, use equality instead; accepting a nearby roll would change the task rather than make its comparison safer.

Version notes

The comparison result is int zero or one in C17, as in earlier editions. The numeric conversion rules still apply. A change of output format does not change those operand conversions or repair an unsuitable floating comparison.
