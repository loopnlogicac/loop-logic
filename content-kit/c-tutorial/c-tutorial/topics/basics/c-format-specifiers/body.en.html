Introduction

Think of a format specifier as an instruction attached to a particular kind of value. %d asks printf to show an int as decimal text. For scanf, it instead describes the integer box to fill. A format specifier must match both the function and the argument type.

Similar-looking letters do not always mean identical rules.

Suppose a marks system stores a double CGPA and a long long event count. Their visible values might look like short numbers, but their types still determine the required formats. A format mismatch is a correctness problem rather than an appearance preference.

This page groups the common conversions by type, explains length modifiers and includes less common pointer rules. Use the table while writing code, then retain compiler diagnostics as a second check.

Syntax and vocabulary

An output conversion describes a value passed after default argument promotions. An input conversion describes the object that will receive a converted value through a pointer. Those are different contracts, so do not copy a format blindly between the two functions.

How it works

The integer example uses d and i on the same signed value and gets the same decimal output. It also uses u, x and o on one unsigned value, showing that output base changes without changing the stored number. Length modifiers select the larger integer families.

For input, %i recognizes a leading zero as octal and a hexadecimal prefix as base sixteen. %d reads decimal regardless of a leading zero. The input example receives 032 twice and stores twenty-six in the first int and thirty-two in the second.

The floating example shows fixed, exponent and compact forms. %e places an exponent in the output; %g chooses a compact form based on value and precision. Precision means significant digits for %g, unlike fractional digits for %f.

size_t is an unsigned type used by sizeof and many library sizes. %zu remains correct without knowing whether size_t aliases unsigned int, unsigned long or another permitted unsigned type. The count example uses a fixed value so its output is stable.

Examples

Signed and unsigned integer families

%d and %i are equivalent for output. Unsigned 26 appears as 1a in hex and 32 in octal.

Floating, character and string families

For printf, %f and %lf both consume double; %e uses an exponent and %g chooses a compact representation.

A size value

%zu matches the unsigned size_t type rather than assuming it is int or long.

Input base detection

%i recognizes 032 as octal 26, while %d reads 032 as decimal 32.

Object pointer formatting

%p receives a void * obtained from an object pointer. The address text is implementation-defined and varies between runs. The displayed output is one real run, not a fixed address guarantee.

A scanset matches a specified group of characters during input. See String Input and Output. These advanced forms are listed for recognition rather than required in the first exercises. Each family has detailed constraints beyond its short table entry.

Pointers require deliberate treatment

A pointer holds a reference to an object or other permitted target. See Introduction to Pointers. To display an object pointer with %p, explicitly convert it to void *. The printed representation is implementation-defined and may vary from run to run, so you cannot predict one fixed printed address.

For input %p, provide the address of a void * object, which has type void **. The textual input form and useful round-trip guarantees are implementation-dependent, so do not use it as a general parser for arbitrary integer addresses. Address values are not portable identifiers for students, records or files.

Widths and stars have different meanings

In printf, a star width obtains the width from an int argument. In scanf, a star suppresses assignment for that conversion, so it does not contribute to the assignment count. Input width limits consumed characters, while output width normally supplies minimum padding.

A scanf %s width must leave room for an added null terminator. For %c with a width greater than one, the function reads that many characters without appending a terminator. These details matter when deciding whether later output may safely use %s.

Try a small change

The mixed-format record is easiest to read one field at a time. Write the declared type above each conversion, then follow the order of the arguments. For input, include the pointer star when naming a destination type: double * is not float *. For output, remember that a float argument becomes double.

Use the input lesson when a leftover newline affects a character field. Widths also have different meanings in the two functions. An input width limits characters read. An output width normally pads a short result.

Checking these choices separately prevents a plausible-looking format from hiding a type error.

Common mistakes

Selecting a format from the numeric value

A size_t holding twelve is still not necessarily int. Use its type's conversion, even for small values. A cast can be appropriate for a deliberate checked conversion, but weakening warnings does not make a mismatch valid.

Assuming identical input and output rules

printf receives values, while scanf usually receives pointers to objects. The float-to-double promotion in output does not change a float * destination into double *. Check both sides of the table before writing a read.

Mistake: a wrong size format

size_t is not int on this host; %zu expresses its type portably and avoids a format mismatch.

Best practices

  • Identify the function and argument type before choosing a conversion.
  • Use length modifiers for the actual integer family.
  • Keep pointer values out of fixed expected-output questions.
  • Bound string input and understand whether a terminator is appended.
  • Consult the full library reference for advanced conversion constraints.

Version notes

C99 standardized useful additions including ll, j, z, t and hexadecimal floating conversions. The tables describe C17 behavior. C23 adds further facilities, so an older compiler accepting a format extension should not be treated as proof that it belongs to C17.

Summary

Format strings are typed contracts with different input and output rules. Match value families, destination pointers and length modifiers before controlling appearance. Next, learn how source literals represent special characters in Escape Sequences.
