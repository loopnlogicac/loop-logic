Introduction

A count of thirty seats and a tally of billions of events need different ranges. Type modifiers help you choose an integer family and its signedness. You can inspect the real limits instead of guessing from your laptop's name. This also helps you prevent arithmetic that leaves the permitted range.

The words short, long, long long, signed and unsigned combine with suitable type specifiers. They do not set arbitrary widths by themselves. On a 64-bit system, long may still be thirty-two bits under one data model and sixty-four under another.

This lesson also separates defined unsigned wraparound from undefined signed overflow. The distinction is a language rule, not a prediction based on what the processor appears to do during one test. Choose a range that prevents unintended overflow before performing the operation.

Syntax and vocabulary

Signed integer types can represent negative and nonnegative values. Unsigned types represent nonnegative values and have a defined modulo arithmetic rule. An omitted int in forms such as unsigned long still denotes an integer type.

short seats = 30;
unsigned int count = 26U;
long distance = 1000000L;
long long events = 9000000000LL;

How it works

The first example matches each integer family with its output length modifier. A short argument normally promotes to int in the call, but %hd requests a short-style conversion. A long needs %ld, and a long long needs %lld. Choosing the wrong format is not repaired by the value happening to be small.

limits.h provides integer boundaries such as SHRT_MIN, SHRT_MAX, INT_MIN, INT_MAX, UINT_MAX, LONG_MAX and LLONG_MAX. Read them instead of embedding a machine assumption in a portable explanation. The limits example prints the host's int range and a floating precision characteristic.

float.h provides separate facts about floating types, including FLT_DIG, DBL_DIG, FLT_MAX, DBL_MAX and precision-related macros. DBL_DIG describes decimal precision, while DBL_MAX concerns magnitude. A type can have a huge range without preserving every integer in that range exactly.

Details and comparisons

Two different overflow rules

For unsigned arithmetic, results are reduced modulo one greater than the maximum representable value. Subtracting one from zero therefore yields the maximum. This is useful in some low-level algorithms but can be a serious bug for sizes or balances if wrapping was not intended.

Ordinary signed arithmetic whose mathematical result is outside the representable range has undefined behavior. Do not record a wrapped signed value as an expected answer. A compiler may optimize on the assumption that signed overflow does not occur, so behavior can change with options.

To calculate a large product, choose a type that can represent the whole result and ensure the operands participate in that type before multiplication. Assigning an already-overflowed int product into long long is too late. A later conversion cannot restore information lost or invalidated earlier.

A cast explicitly requests a conversion. See Type Conversion and Casting. A cast can change the calculation type when applied to an operand, but it is not a runtime proof that the result fits. Input bounds and arithmetic reasoning still matter.

Exact-width and minimum-width choices

stdint.h may provide exact-width types such as int32_t and uint8_t when the implementation supports suitable types. The number states the width. Unsigned uint8_t represents zero through 255 when present. Exact-width typedefs are optional rather than universal on every imaginable C target.

A typedef is another name for an existing type, not a new storage operation. See typedef. stdint.h uses such names to express representation requirements. It also provides least-width and fast-width families for tasks that need minimum ranges without insisting on exact layouts.

inttypes.h supplies portable format macros such as PRId32 for int32_t. A fixed-width typedef can alias a different underlying integer type on another system, so guessing %d from the width alone is less portable. Common mistakes

Assuming unsigned prevents every bug

Defined wraparound is still wrong when a task expects a growing count. Check capacity and input ranges before the operation. An unsigned type does not represent negative error values and can complicate comparisons with signed values.

Assuming long follows the OS label

Inspect LONG_MAX and sizeof(long) for the target. Use a suitable fixed-width type when exact width is truly required, checking availability. Do not silently change a data format based on a laptop's observed layout.

Mistake: a mismatched length modifier

%d requests int, not long long. Use %lld rather than running this mismatched call.

Best practices

  • Choose ranges before choosing a type name.
  • Consult limits.h and float.h rather than guessing.
  • Keep signed overflow out of normal examples and calculations.
  • Distinguish promoted arithmetic from conversion back to a narrow object.
  • Use inttypes.h formats for fixed-width typedefs when needed.

Version notes

C99 added long long, stdint.h and inttypes.h. C17 is the baseline for the demonstrated rules. C23 adds further integer facilities, but it does not make ordinary signed overflow a portable wrapping operation. Exact-width typedef availability remains a representation capability to check.

Summary

Modifiers describe integer families, headers reveal actual limits, and fixed-width typedefs express representation needs when supported. Unsigned wrap is defined while signed overflow must be avoided. Next, study written values and named constants in Constants and Literals.
