Introduction

A variable is a named object whose stored value can be used and, when permitted, changed. Its declaration tells the compiler the type and name. Initialization supplies an initial value so the first later read has a defined meaning.

A marks register is a useful picture: a column label identifies what is stored, and a number fills a particular student's entry. In C, the type also determines which values the object can represent. The name marks does not remove the need to choose an appropriate type.

This lesson distinguishes creating storage, announcing a name and changing an existing value. These jobs often occur together in a short program, but separating them makes larger programs easier to understand.

Syntax and vocabulary

A declaration introduces information about a name. An object definition supplies the object itself, while an initializer specifies its starting value when present. An assignment expression updates an object after it already exists.

int marks = 70;  /* definition with initialization */
marks = 80;      /* later assignment */
extern int total; /* declaration; definition is provided elsewhere */

Every definition is a declaration, but not every declaration is a definition. The extern example normally refers to an object defined elsewhere rather than creating a new local object. Multi-file definitions are developed in Multi-File Programs.

How it works

The first example initializes marks to 70 and then assigns 80. When printf reads marks, the earlier value has already been replaced. Printing a variable shows its value at that execution point, not a history of every value it has ever held.

The second example initializes theory and lab separately on one source line. Their sum is then used to initialize total. A comma between declarators does not copy an initializer from one object to another: int a = 0, b leaves b without an explicit initializer.

A storage duration describes how long an object exists. Ordinary local variables in these functions have automatic storage duration, while the third example's static local has static storage duration. The distinction controls initialization and lifetime, not merely how the source looks.

Verified examples

Initialize before reading

Initialization creates the first stored value; assignment later replaces it, so only 80 is printed.

Multiple declarations

Both variables are initialized separately; the total receives 85 after their values are available.

Static zero initialization

A static-duration object without an explicit initializer is zero-initialized; this does not apply to an uninitialized ordinary local int.

Details and comparisons

Uninitialized does not mean useful randomness

An uninitialized automatic int has an indeterminate value and must not be read as ordinary program data. The familiar phrase garbage value is an informal warning, not a promise that you can print a safe random number. Such a read can have undefined behavior, meaning C does not prescribe a result.

Initialize a local variable when a sensible initial value exists, or ensure a successful input read assigns it before use. Do not initialize to zero merely to hide a failed read and continue as though valid input arrived. The practice scaffold checks scanf so that conversion failure does not lead to a later read of an unassigned value.

Static-duration objects have different rules: without an explicit initializer, arithmetic objects begin at zero. This includes static locals and ordinary file-scope arithmetic objects. The Visits example intentionally demonstrates that rule rather than depending on leftover memory contents.

Stack and static storage are implementation pictures

Many implementations keep automatic locals in a stack frame associated with a function call, and reserve a separate static storage region for long-lived objects. These are useful mental pictures. The C language does not require every local to occupy a physical stack slot; a compiler may use registers or optimize an object away.

A stack frame is a common implementation area holding information for one active function call; lifetime rules are developed in Scope and Lifetime. Scope tells where a name is visible, while lifetime tells when its object exists. The two ideas are related but different.

Assignments have an order

Saving a balance before deducting a fare requires copying it first. If you overwrite balance before saving it, the old number is lost from that object. The swap practice uses a temporary variable for the same reason: each assignment replaces one value, so an intermediate copy preserves data needed later.

Declare a variable close to its first useful value when the language mode permits it. This reduces the distance between the declaration and the operation it supports. Split a declaration line when several names have different roles or initialization needs.

Common mistakes

The marked mistake example is supplied for compiler diagnostics. Repair the stated cause before running it; it has no expected stdout transcript.

Assuming one initializer covers every name

In int a = 0, b, only a receives that explicit initializer. Give b its own initializer or assign it successfully before reading it. Separate declaration lines can make the missing value easier to notice.

Assuming every local starts at zero

The zero-initialization rule for static duration does not apply to an ordinary uninitialized local int. An apparently stable output on one run is not a language guarantee. Repair the data flow instead of recording that accidental output.

Mistake: duplicate definition in one block

A second definition with the same name in the same block is invalid; assign to the existing object instead.

Best practices

  • Initialize each object or prove assignment succeeds before its first read.
  • Keep declarations near the work they support.
  • Use a saved copy when an old value is needed after an update.
  • Separate scope, storage duration and physical placement in your explanation.
  • Use one declaration per line when roles differ.

Version notes

C89 required declarations at the start of a block before its statements. C99 and later allow declarations mixed with statements. The static zero-initialization rule remains applicable in the C17 baseline; later language editions do not make uninitialized automatic int reads safe.

Summary

Declarations describe names, definitions provide objects and initialization gives starting values. Later assignments change what is stored, so order and lifetime matter. Next, choose the values an object can hold in Data Types.
