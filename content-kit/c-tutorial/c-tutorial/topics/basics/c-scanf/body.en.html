Introduction

scanf reads formatted input from standard input and stores converted values in supplied destination objects. It is useful for small lab tasks with a known input format. The key obligations are matching destination types, checking assignments and respecting buffer capacity.

A terminal shows your typed input as part of its interactive display, but the program does not necessarily print those characters back. The supplied output files capture stdout alone. That is why a prompt may be followed immediately by the result in a recorded run.

This lesson assumes numeric input is representable in the destination type. Checking the assignment count detects missing or nonmatching fields; it is not a complete defense against arbitrarily large numeric text. For robust general parsing, later lessons combine line input with checked conversion functions.

Syntax and vocabulary

The address operator & obtains the location of an object so scanf can store into it. An address identifies where an object is stored; pointer details are introduced in Introduction to Pointers. Supplying an integer's current value instead of its address is a serious type error.

int marks;
if (scanf("%d", &marks) != 1) {
    return 1;
}

The star in these type descriptions denotes a pointer type: a value that refers to an object. A string input destination is an array used through its first-element pointer. For that usual %s call, write label rather than &label, because &label has pointer-to-array type.

How it works

scanf tries each conversion in format order and reports the number of successful assignments. A two-mark calculation must see a return value of two before using both marks. Returning one means only the first field was assigned; the second destination cannot be treated as new valid input.

If the first numeric field does not match, scanf can return zero. If input ends before any conversion can complete, it returns EOF, a negative macro value whose exact number is not assumed here. Checking for the required assignment count handles both situations for these fixed-field reads.

  1. Print a short prompt naming the expected input.
  2. Provide correctly typed destination addresses.
  3. Compare the return value with the number of required assignments.
  4. Handle failure before reading destination values.
  5. Perform the task using only successfully assigned values.

The float-and-double example is especially important: input %f requires float *, while %lf requires double *. These objects need not have the same size or representation. The output call then uses %f for both because a float argument is promoted to double in printf.

Details and comparisons

Whitespace and the leftover newline

Most numeric conversions skip preceding whitespace automatically. %c does not: it reads the next character, which may be the newline left after a prior numeric token. A leading whitespace directive in " %c" skips any amount of whitespace before reading the character.

A whitespace character in a scanf format means skip a sequence of input whitespace, not match one exact source space. This lets the roll-and-grade example accept a line break between its fields. Do not add trailing whitespace to an interactive format without understanding that it may wait for the next non-whitespace input.

The grade is a non-whitespace character by the stated task. If you need to read a literal space or newline as data, do not use the leading-space form. The format should express the task rather than blindly applying a remembered template.

Reserve space for the terminator

An array is a sequence of elements; char label[12] provides twelve character slots, as developed in Arrays. %s reads a non-whitespace word and appends a null terminator. A width of eleven leaves the twelfth slot available for that terminator.

The width does not include the null character in its maximum consumed text length. It also does not reject a longer word as a whole: extra input characters remain for later reads. If the task needs a complete line or must detect overlong input, a line-based strategy is more suitable.

Failure handling and stream state

A nonmatching character generally remains unread after a failed numeric conversion. Repeating the same call without handling the bad input can fail forever on that character. This batch's simple failure paths stop or print Invalid rather than pretending recovery occurred.

Do not use fflush(stdin) as portable cleanup. ISO C does not define that input-stream use; some environments provide extensions, but those are not general language rules. Deliberate line reading and explicit parsing give you more controlled recovery when a larger application needs it.

The output quizzes use sscanf, the related stdio.h function that applies formatted-input rules to a supplied string instead of stdin. This makes their input self-contained for automatic grading. Their assignment counts, whitespace behavior and %i versus %d rules follow the same conversion principles.

Common mistakes

The marked mistake example is supplied for compiler diagnostics. Repair the stated cause before running it; it has no expected stdout transcript.

Using a value after an unchecked read

A failed conversion does not create the intended value. Check the return count before using the destination, even if you initialized it earlier. A fallback zero can hide failure when zero is also a valid task input.

Using %s without a width

An unbounded word can exceed the array and cause undefined behavior. Choose capacity first, then use a maximum text width one smaller. The field width does not allocate storage for you.

Mistake: wrong destination type

%f expects float *, not double *; the compiler warns and the call must be corrected to %lf before execution.

Best practices

  • Match conversions with destination pointer types.
  • Check the exact required assignment count.
  • Use a leading space before %c only when whitespace should be skipped.
  • Bound every %s word read to the available array capacity.
  • Keep the numeric input within the stated representable range.

Version notes

The demonstrated scanf family rules apply in C17 and have long-standing forms in earlier C editions. Input %f and %lf remain different because their destination pointer types differ. Compiler-specific input cleanup extensions are outside these portable examples.

Summary

scanf needs correctly typed destinations and successful conversions before values are used. Whitespace directives and string widths must match the actual input task. Next, compare the full input and output rules in Format Specifiers Reference.
