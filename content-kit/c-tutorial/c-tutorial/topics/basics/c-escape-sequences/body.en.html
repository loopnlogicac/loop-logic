Introduction

How can you put a quote inside a quoted message without ending it? C uses a backslash spelling called an escape sequence. The compiler turns that spelling into a character. You can represent quotes, backslashes, tabs and newlines while keeping the boundaries of your string clear.

For a two-line marks card, you need newline characters in the output stream. Breaking a source statement across editor lines does not automatically add output newlines. Conversely, one source string can request several output lines by including several newline escapes.

Some control characters have effects that depend on the viewer or terminal. A tab may look like several spaces, and an alert may make no sound at all. Read the recorded bytes and the language meaning separately from how one screen renders them.

Syntax and vocabulary

Place escapes within a character constant or a string literal. The compiler interprets a recognized escape as a character value. An ordinary unknown escape is not a portable way to print its second letter.

How it works

The marks-card example emits a tab between headings and values, with newlines between rows. The displayed result contains actual tab characters. A renderer may choose different tab stops, so a fixed-width report should use printf width conversions when precise columns are required.

The quote-and-path example protects the double quotes that belong to the message and doubles the source backslash in the path label. The output shows one backslash. No filesystem is accessed: the path is only text in the output.

A null terminator is a zero character marking the end of a C string. See Introduction to Strings. The literal "Lab\0Hidden" includes an embedded null before Hidden. %s stops at that first null, so it prints Lab rather than the full literal's visible source text.

Details and comparisons

Octal and hexadecimal escapes

An octal escape starts with a backslash followed by one to three octal digits. \101 represents the numeric value sixty-five. A hexadecimal escape begins with \x and consumes subsequent hexadecimal digits without an automatic two-digit limit.

On an ASCII-compatible implementation, both \101 and \x41 have the code used for A. That mapping is a character-encoding fact, not a universal language promise that every machine uses ASCII. For a readable letter, the character constant 'A' avoids depending on that numeric mapping.

/* Adjacent literals stop the hex escape before B. */
"\x41" "B"
/* In contrast, \x41B consumes three hex digits. */

Adjacent string literals are joined during translation. Splitting the source as shown makes the end of the hexadecimal escape unambiguous before the letter B. This is useful when a following character happens to be a valid hex digit.

Control characters are not screen commands

\a represents the alert character, but a terminal may ignore it or signal visually rather than sounding. \r represents carriage return and often moves a cursor to the start of the current line. A captured file stores the character even when no visible cursor exists.

Do not claim that \r clears a line or that \b always erases a printed character. Those effects depend on the terminal and later output. The language defines characters and stream operations. A display device interprets control characters according to its own behavior.

Text streams can also translate newline representations for the host environment. The logical C newline remains the correct way to end a text line even if the operating system stores line endings differently. A Linux terminal commonly represents each newline with one LF character.

Common mistakes

Using a forward slash for an escape

/n is ordinary slash-and-letter text, while \n requests a newline. The characters look similar in some fonts but serve different source roles. Inspect the actual source rather than changing printed results to match a typo.

Putting an unescaped physical newline in a string

An ordinary string literal cannot continue through a raw source newline in this way. Use a newline escape for the output, or separate adjacent string literals for source layout. A newline in the editor and a newline character represented in a literal are different.

Confusing null with zero text

'0' is a character representing a digit, while '\0' has numeric value zero. They do not end strings in the same way. Choose the character based on whether you need visible text or termination.

Mistake: an unknown escape

\q is not a standard escape. The compiler warns. Write \\ in the source for one literal backslash.

Best practices

  • Count emitted characters rather than source spelling characters.
  • Use character literals for letters when numeric encoding is irrelevant.
  • Double backslashes that must appear literally in output.
  • Separate hexadecimal escapes from following hex-digit text.
  • Use predictable visible examples instead of assuming terminal control effects.

Version notes

The common escapes in this lesson are available in the C17 baseline and long predate it. C99 added universal character-name facilities for wider character notation, which are separate from the octal and hex byte-value examples here. C23 does not turn terminal-dependent display effects into fixed output guarantees.
