Introduction

Compare a with lab_marks on a classmate's solution. Both may be legal names, but only one tells you what it stores. An identifier names a variable, function or another program element. You need a valid spelling for the compiler and a useful meaning for the reader.

For a marks calculation, theory_marks and lab_marks explain the data better than a and b. A short name may still work in a small mathematical formula, but a name should not force readers to reconstruct its purpose every time it appears.

C names are case-sensitive and share several reserved-name rules with the standard library. An identifier can be grammatically valid yet unsuitable because the implementation owns that spelling in a particular context. Following a conservative naming convention avoids most of these traps.

Syntax and vocabulary

For the portable ASCII naming subset used in this course, begin with a letter or underscore and continue with letters, digits or underscores. A digit may appear after the first character, as in group2. Spaces and hyphens do not belong inside this ordinary identifier spelling.

int student_count = 40;
int group2 = 18;

How it works

When the compiler sees an identifier, it relates the spelling to a declaration visible at that point. The lab_marks example uses the same name in its declaration and output argument. A change in spelling at the second location would refer to another name or produce an undeclared-name diagnostic.

Case is part of the spelling. The second example deliberately declares score and Score as separate objects, giving them 70 and 80. The output proves they are different, but the pair is a poor style choice because a reader can easily miss the capital letter.

The third example names two groups using trailing digits. group2 and group3 remain separate identifiers, and their values add to forty students. The numbers are part of the names rather than array indexes. An array is a sequence of elements, introduced later in Arrays.

  1. Pick a name describing the role or unit.
  2. Check the first character and remaining characters.
  3. Reject keyword spellings.
  4. Avoid implementation and library reserved patterns.
  5. Use the exact same case at every intended reference.

Details and comparisons

Reserved identifiers are more than keywords

Names beginning with an underscore followed by another underscore or an uppercase letter are reserved to the implementation for any use. Names beginning with a single underscore are also reserved at file scope in the ordinary and tag name spaces. File scope means a declaration outside every function.

A single underscore followed by lowercase may be allowed for a local name in some circumstances, but this course avoids leading underscores altogether. That simple convention is easier to apply than remembering each context. It still permits readable internal underscores such as remaining_balance.

Standard library names have additional reservation rules, including names associated with included headers and external linkage. Do not define your own replacement printf or reuse library type and macro names in normal exercises. A spelling being absent from the keyword table does not guarantee that it is free for every use.

Choose one readable convention

snake_case joins lowercase words with underscores. It works well for variables and helper functions in this tutorial. Constants expressed as macros are often uppercase by convention, but uppercase itself does not make an object constant.

Use nouns for stored values, such as student_count, and a task-oriented phrase for a helper, such as total_marks. Add a unit when ambiguity matters: duration_minutes is clearer than duration in a program that also stores seconds. Avoid embedding a physical type into a name unless that detail is central to the task.

Longer is not always clearer. total_theory_and_lab_marks_of_current_student may repeat context already obvious from a small function. Prefer the shortest name that preserves meaning, and do not shorten through unexplained abbreviations that make code harder for a classmate to review.

Names do not enforce assumptions. Naming a variable positive_count does not prevent negative input from being stored there. State and check required ranges separately when the program is responsible for validation.

Try a small change

The receipt exercise is a good naming test. Cover the problem statement and try to explain the calculation from its variable names. Use price_per_ticket when price could otherwise mean the whole bill. Use ticket_count for the other factor.

Values arrive through scanf, with & giving the destination address. An if checks whether the read succeeds. A name such as valid_count does not perform that validation for you. If two values differ only in capitalization, replace the names with their actual roles before continuing.

Meaningful spelling reduces the chance of updating the wrong object.

Common mistakes

Using a hyphen like an underscore

The source lab-marks is read as separate tokens involving subtraction. The compiler cannot guess that you intended one name. Replace the hyphen with an underscore consistently in the declaration and every use.

Depending on tiny case differences

score and Score compile as different names but can conceal a typo. Rename the values by their roles, such as theory_score and lab_score. A naming convention prevents this mistake more effectively than another comment.

Mistake: a digit at the beginning

A numeric start cannot form this identifier. Rename it group2.

Best practices

  • Use lowercase words joined by internal underscores for ordinary names.
  • Put digits after a leading letter when a group number helps.
  • Avoid leading underscores and standard library name collisions.
  • Include units when the program handles different measurement scales.
  • Rename confusing names throughout the source, then rebuild.

Version notes

The basic ASCII naming rules and case sensitivity apply across the course editions. Keyword sets and permitted non-ASCII identifier details evolve between editions. The examples use a conservative portable subset and follow the C17 naming rules.

Summary

A good identifier is legal, unreserved for its use and meaningful to a reader. Consistent case and snake_case reduce mistakes without changing execution. Next, use those names to create and update objects in Variables.
