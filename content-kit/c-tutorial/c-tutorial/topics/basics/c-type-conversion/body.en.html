Introduction

Suppose marks total eleven across two students. You want 5.5, but integer division gives five before the result reaches a double variable. A type conversion changes a value to another type. Some happen automatically.

A cast requests one. You need the right conversion before the operation that would lose information.

Suppose two students have marks five and six and you want their average. An integer quotient loses the fraction before a later assignment to double. To keep 5.5, make the division floating-point before calculating the quotient.

This lesson follows integer promotions, the usual arithmetic conversions and explicit casts. The goal is to predict each expression's type and value, then check whether the destination can represent the result. A cast is a request, not a general safety check.

Syntax and vocabulary

An implicit conversion follows from context, such as assigning an int to a double or combining operands of different arithmetic types. An explicit cast writes a type name in parentheses before an expression. The original object is not automatically changed by casting its value.

double average = (double)total / count;
double too_late = (double)(total / count);
int whole = (int)reading;

A rank is part of the ordering used by integer conversion rules. It generally follows the standard integer families from smaller ranks to larger ones, but rank and byte size are not identical concepts. Equal-size types can still have different ranks.

How it works

With two int operands, division computes an integer quotient. In C17 the quotient truncates toward zero, so 5 / 2 is 2 and -5 / 2 is -2. A double destination receives that integer result after the operation. It cannot recover the discarded fraction.

With 5.0 / 2, the first operand has type double, so the second converts to double before floating division. The result is 2.5. The first example puts these forms together to make the difference observable.

Integer promotions first lift types such as char, short and _Bool into int when int can represent all their values, otherwise into unsigned int where required. The unsigned-char example uses an eight-bit-byte implementation with a wide enough int, so 200 and 50 are added as ints to produce 250.

Default argument promotions also convert float to double in calls such as printf. This does not change scanf destination pointers: float * remains a pointer to float. A type rule for an argument value is not a rule that rewrites every related pointer type.

Details and comparisons

The usual arithmetic conversions

The usual arithmetic conversions select a common type for many binary arithmetic operations and comparisons. For ordinary real floating operands, a higher floating type determines the common type: long double takes priority over double, and double over float. Integral operands are converted as needed when combined with that floating type.

For two integer operands, apply integer promotions first. If both then have the same signedness, convert to the type with greater rank. If signedness differs, the decision depends on both rank and whether the signed type can represent every value of the unsigned type.

  1. If the unsigned type has rank at least the signed type's rank, convert the signed operand to that unsigned type.
  2. Otherwise, if the signed type can represent all values of the unsigned type, convert to the signed type.
  3. Otherwise, convert both to the unsigned type corresponding to the signed type.

On the usual equal-width int and unsigned int pair, comparing -1 with 1U converts -1 to unsigned int. That value becomes UINT_MAX, so an expectation based on ordinary signed ordering fails. Later Relational Operators develops comparisons. Here the key is that conversion happens before the comparison.

Do not reduce the rule to unsigned always wins. A wider signed type may represent the entire range of a lower-ranked unsigned type and therefore become the common type. Consult limits and ranks rather than relying on one memorized result from one data model.

Loss, truncation and representability

Converting a finite floating value to an integer discards its fraction toward zero when the resulting integer is representable. The final normal example converts 3.9 to 3 and -3.9 to -3. This is not rounding to the nearest integer and is not the same as taking the mathematical floor of a negative number.

If the truncated value is outside the destination integer's range, ordinary floating-to-integer conversion has undefined behavior. A cast does not make it saturate or wrap. Check the domain before conversion in a program that accepts uncontrolled measurements.

Converting an integer to an unsigned type reduces its value modulo one greater than that type's maximum. In C17, conversion to a signed integer type that cannot represent the value instead has an implementation-defined result or may raise an implementation-defined signal. Keep this separate from signed arithmetic overflow, which is undefined behavior.

Converting a large integer to floating-point may lose exact low-order information even when the magnitude is within range. Converting double to float can also round and reduce precision. State whether the task needs an exact count or an approximate measurement before choosing such conversions.

Design the calculation type first

For an average, cast an operand or use an appropriate floating literal before division. For a large integer product, promote an operand to a sufficiently wide integer type before multiplication. Assigning the final expression to a wider destination is insufficient if the intermediate operation already overflowed.

A denominator must also be nonzero. This lesson's quotient practice restricts it to one through ten, making that safety condition explicit in the task. Input bounds are part of the reasoning, not decorative notes after the code.

Try a small change

For the percentage exercise, compare two routes on paper. One route divides the integer mark by the maximum before multiplying by one hundred. The other uses a floating operand before the division. Try a mark smaller than the maximum: the first route can discard the whole fraction.

scanf must first read both numbers with matching destinations. An if can reject a zero maximum before division. Neither a cast nor a successful input read proves that a divisor is nonzero. Record the type at each arithmetic step, then decide where a conversion belongs.

Common mistakes

Casting only the final quotient

(double)(total / count) converts an integer quotient that has already lost its fraction. Move the cast to an operand. Predict the types at each operator before looking at the final assignment.

Using a cast to silence concern

An explicit conversion can lose range or precision even when the compiler accepts it. Explain why the value fits the new type and why discarded information is acceptable. Do not use arbitrary pointer casts to disguise unrelated type errors.

Mistake: incompatible pointer initialization

A floating value cannot initialize an int pointer. A cast is not a general repair for unrelated types.

Best practices

  • Trace operand types before tracing values.
  • Apply conversions before the operation that needs the wider range or precision.
  • Keep signed and unsigned interactions deliberate.
  • Check representability before floating-to-integer casts.
  • Choose exact integer arithmetic for exact count tasks where feasible.

Version notes

The examples follow C17. C99 fixed signed integer division to truncate toward zero. Earlier editions allowed more implementation variation for negative operands. C23 changes some conversion details and adds types, so the signed out-of-range conversion description here is explicitly the C17 rule.

Summary

Conversions occur at defined points and may change range, precision or signedness. Cast before division when a fractional result is needed, and never treat a cast as proof of safety. Next, organize the operations themselves in Operators Overview.
