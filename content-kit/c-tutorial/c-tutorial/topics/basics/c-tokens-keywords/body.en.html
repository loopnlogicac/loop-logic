Introduction

A token is a meaningful piece of source recognized during C translation. A declaration is not read as an English sentence: the compiler separates names, values and punctuation according to language rules. Recognizing those pieces makes unfamiliar source easier to read.

Consider a marks declaration followed by an output call. The keyword int identifies a type, marks supplies a name, and 80 supplies a value. Punctuation tells the compiler where each grammatical unit begins and ends.

A keyword is a spelling reserved for a language role. You may choose a name such as lab_marks, but you cannot redefine int as your variable name. Library functions such as printf are names with declarations, not keywords in the C grammar.

Syntax and vocabulary

Teaching descriptions commonly group C tokens into six categories. Operators are themselves punctuators in the standard's formal lexical classification; the six-group table separates their calculation role for easier study. Do not confuse this teaching grouping with six disjoint formal token categories.

int marks = 80;
/* int | marks | = | 80 | ; */

The semicolon is one token and marks the end of this declaration. Whitespace separates int and marks so they remain distinct names. Without the separating space, intmarks would be a single identifier rather than a type followed by a variable.

How it works

Token recognition happens before the compiler understands the full statement. For the first example, read the source in small pieces and classify each piece. Then reconnect the pieces: an int object called marks is initialized with 80, and the following call formats its stored value.

The complete string inside double quotes is a string-literal token even when it contains spaces, commas or escape sequences. A comma inside that string is printable data. A comma outside the string may separate function arguments, as shown by the punctuation example.

Comments act like whitespace during translation and do not become ordinary executable tokens. A preprocessor directive has its own translation role: include in #include is a directive name, not a C17 keyword. Header names are also handled in preprocessing, so they should not be forced into the simplified ordinary-token table.

  1. Find quoted strings and keep their contents together.
  2. Recognize identifiers and keyword spellings outside strings.
  3. Recognize numeric and character constants.
  4. Read operators and punctuation according to context.
  5. Use the resulting sequence to understand the declaration or statement.

Verified examples

Tokens in a declaration

int is a keyword, marks an identifier, 80 a constant, = an operator and ; a punctuator; the format is a string literal.

Keyword types, different names

int keeps its language meaning in both declarations; theory and lab are programmer-chosen identifiers.

Punctuation separates expressions

The comma inside the string is output; commas outside the string separate arguments and are not printed.

Details and comparisons

The complete C17 keyword list

The following 44 spellings are C17 keywords. Case matters: _Bool and _bool are different spellings, and only the former belongs to this list. The list is a reference, not a demand to use every feature in your first lab.

auto break case char const continue default do double else enum
extern float for goto if inline int long register restrict return
short signed sizeof static struct switch typedef union unsigned
void volatile while
_Alignas _Alignof _Atomic _Bool _Complex _Generic _Imaginary
_Noreturn _Static_assert _Thread_local

Several keywords name features whose complete use comes much later, such as structures and pointers. A type describes the values and operations associated with an object or expression. For now, recognizing a reserved spelling prevents you from trying to use it as your own name.

New C23 keyword spellings

C23 adds the spellings shown below alongside the existing language vocabulary. Some provide preferred forms of older underscore spellings; others support new facilities. A compiler accepting a spelling as an extension in C17 mode does not make it part of standard C17.

alignas alignof bool constexpr false nullptr static_assert
thread_local true typeof typeof_unqual _BitInt _Decimal32
_Decimal64 _Decimal128

The decimal floating type keywords have conditional feature availability, so recognition of the language vocabulary does not imply every compiler implements decimal arithmetic. This course does not depend on those types. Later standard-version lessons discuss which features your toolchain actually supports.

In C17, including stdbool.h normally supplies bool, true and false as macros; _Bool is the keyword. In C23, bool, true and false are language keywords. The spelling used in source may look familiar while its status changes between editions.

A declared name is still a name

main and printf are identifiers, even though they are important standard names. A reserved identifier can be protected for library or implementation use without being a keyword. The next lesson explains why a non-keyword is not automatically a safe name for every purpose.

Common mistakes

The marked mistake example is supplied for compiler diagnostics. Repair the stated cause before running it; it has no expected stdout transcript.

Choosing a keyword as a variable name

The parser already assigns return and for grammatical meanings. They cannot become ordinary variable names in a declaration. Choose result or loop_count instead of trying to change spacing around the keyword.

Treating text inside quotes as code

The text int in an output message is data, while int outside the string may introduce a declaration. Keep the quote boundaries visible when counting tokens. Editing a message does not create a new variable.

Mistake: a keyword used as a name

return has a reserved grammatical role; choose a meaningful non-keyword such as result.

Best practices

  • Classify source pieces before tracing a long statement.
  • Use the keyword list as a reference rather than inventing reserved names.
  • Distinguish directive names, library names and keywords.
  • Keep spaces where adjacent names would otherwise merge.
  • Check the selected C edition when learning a new spelling.

Version notes

The list of 44 keywords is for C17. C99 and C11 added several of the underscore-prefixed and other modern spellings compared with C90. C23 introduces the additional list above, so code using those additions needs appropriate language mode and implementation support.

Summary

Tokens connect raw source characters to C grammar, and keywords carry fixed language meanings. String contents and library names must be read in their own roles. Next, choose legal and clear names in Identifiers and Naming Rules.
