string.h Functions

A room-label program often needs to copy text, add a suffix, compare names or find a separator. The string.h library supplies these operations. Its functions save loop-writing work, but you still supply the storage and its limits.

Think of string functions as tools with different jobs. A measuring tape does not enlarge a box, and strlen does not create space. Before a copy or append, calculate the required capacity. Before using a search result, check that a match exists.

Declarations and call rules

Include string.h for the declarations. Pass valid terminated strings to functions that scan strings. A destination must also be writable and large enough for every byte the operation will write.

strlen(text) returns size_t, so print it with %zu. strcmp(a,b) returns an int whose sign describes byte ordering. strchr(text,ch) and strstr(text,part) return pointers selecting matching positions, or NULL when absent.

The reference table below separates each function's result from its main obligation. The word bounded needs care: a numeric argument does not always mean the function guarantees a terminated result.

A pointer stores an address selecting existing storage. Here, search results select characters inside the searched string. The detailed address model is taught in Introduction to Pointers; a search result is not a newly allocated string.

size_t length = strlen(source);
if (length < capacity) {
    strcpy(destination, source);
}

Follow the storage and operations

For strcpy(destination, source), measure the source plus one for its zero. The condition strlen(source) < capacity proves the copy fits when the operands are valid and non-overlapping. The routine copies the terminating zero as well as visible text.

For strcat(destination, source), destination must already be a valid string. Its existing length consumes capacity. You need room for the old visible text, the new visible text and one final zero. The append replaces the old terminator with the first new character, then writes a later terminator.

strncpy(destination, source, n) writes exactly n bytes. A shorter source causes zero padding through the rest of those bytes. A source with at least n visible bytes leaves no null terminator in the copied part. The prefix example therefore copies capacity minus one and explicitly writes the last zero.

strcmp stops at the first differing byte or the shared end. It compares bytes as unsigned char values. Different lengths matter only after an equal prefix: Lab precedes Lab1 because the shorter string reaches zero first. Test less than zero, equal to zero, or greater than zero; never assume an exact result of minus one.

strchr finds one character, including the terminator if you search for '\0'. strstr finds a contiguous substring; an empty search string matches at the beginning. Neither routine creates a new copy. The returned position shares the original storage.

Programs to inspect and trace

Copy and append within capacity

The combined seven visible bytes need eight slots with the terminator; capacity sixteen is enough.

Compare by sign

Only the sign of the first result is tested. Equal byte strings compare as zero.

Find a character and a substring

Both results point inside text. Printing from the dash produces -204; printing from the substring produces 204.

Terminate a bounded strncpy result

The explicit zero makes the three-character prefix Cam a valid string. strncpy alone would not terminate this truncated prefix.

Choose the right behavior

Searching Room-204 for the dash returns a pointer at that dash. Printing from there yields -204 because the suffix still ends at the original zero. Searching for 204 returns a later position that prints only the digits.

For a missing separator, NULL is a status value rather than an empty string. puts(NULL) is invalid even if a particular library displays a helpful message. Branch on the result first, then choose your missing-value response.

Copy and append operations here do not allow overlapping source and destination regions. Moving a suffix one character within the same array needs a different tool, such as memmove with a checked byte count including termination. A cast or larger destination bound does not remove the overlap restriction.

These functions operate on bytes and stop at zero. A binary buffer containing embedded zeros needs explicit lengths and byte-memory operations instead. UTF-8 byte lengths also differ from visible-letter counts; strcmp does not promise dictionary order for Bangla names.

Mistakes and repairs

A destination sized to strlen(source) is one byte too short. The zero is easy to overlook because it does not appear in output. Include it in every capacity proof.

Do not use strncpy as a drop-in safe spelling of strcpy. Its padding and termination rules serve a different contract. Check whether you want rejection, truncation or a full copy, then implement that policy explicitly.

Pointer equality compares addresses, not string content. Two separate arrays containing Lab can have different addresses while strcmp reports equal text. Use the operation matching the question you mean to ask.

Copying past a destination

The result is undefined because the copy needs four positions. Use an array of at least four chars.

Working habits

Write capacity checks before mutation. Keep source and destination roles clear. Normalize comparison signs when displaying order. Test missing searches, equal strings and exactly full destinations, rather than only comfortable short labels.

Standard and portability notes

The listed string.h functions are available in C89 through C23. The examples use C17. Annex K checked functions are optional and are not required here; their existence is no reason to omit the ordinary functions' storage checks.
