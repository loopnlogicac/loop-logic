Array of Strings

One room label fits in one character array. A timetable needs several labels, and their lengths may differ. You can store them in fixed-width character rows or in a table of pointers to separate strings.

Picture fixed rows as equal-sized drawer compartments. Every row reserves the same number of char positions, even if one holds A and another holds Office. A pointer table instead resembles an index of addresses: the table holds routes to text stored elsewhere.

Both representations support names[i] as a selected string, but their storage and update rules differ. Choose the representation before choosing how to read, edit or sort its entries.

Declarations and call rules

The declaration char rooms[3][12] creates three adjacent rows, each containing twelve chars. rooms[1] selects the second row. rooms[1][0] selects that row's first character. Each row needs its own terminator when used as a string.

Initialize rows with {"Lab2", "Lab1", "Office"}. The remaining elements of each row are zero-initialized. Each row can later hold up to eleven visible bytes. The capacity comes from twelve char positions, not from the current string's length.

The declaration const char *names[] = {"A", "Campus", "Lab"} creates an array of pointers. Each entry selects a literal. const prevents writes through those character pointers, while the pointer entries themselves remain reassignable. Their targets do not share an equal fixed row width.

A pointer stores the address of another object. In this table, that object is a character in existing string storage. If addresses are unfamiliar, use the diagrams in Introduction to Pointers as a preview before tracing the pointer-table example.

Follow the storage and operations

In the fixed matrix, moving from rooms[0] to rooms[1] skips twelve chars. The compiler knows that physical row stride. A string length of four does not reduce the stride to five; unused capacity remains part of the row.

For bounded token input, scanf("%11s", rooms[i]) writes into one twelve-element row. Read each row separately and check every conversion result. Names containing spaces require a line-reading policy instead; using a matrix does not change scanf's token behavior.

A pointer table has two layers: pointer entries first, target characters second. Selecting names[i] reads the stored address; selecting names[i][j] then reaches a character in that target. Reassigning names[i] changes which text the entry selects without moving any characters.

A literal target must not be modified. You may instead build a table of pointers to writable arrays if editing is needed. Those arrays must remain alive for every use of the table. Keeping their addresses does not extend their lifetimes.

These representations also differ under sizeof. An actual fixed row reports its twelve-char capacity. A pointer-table entry reports pointer-object size, not target string capacity. Use strlen only to measure an already valid string; it cannot reveal unused writable space.

Programs to inspect and trace

Fixed rows with spare capacity

Each row can hold eleven visible characters and a zero. Changing the first row does not touch the others.

Sort writable rows

The temporary row has the same capacity. The resulting order is Asha, Bela, Toma; these are invented labels.

Sort a table of literal pointers

Only addresses move. The character data in the literals is never written.

Choose the right behavior

To sort fixed rows, compare their text with strcmp. If two rows are out of order, copy the first to a temporary row, copy the second over the first, and copy the temporary into the second. The temporary must fit the complete strings, including their zeros.

The row-sort example repeatedly compares the selected row against later rows. It is a small O(n squared) comparison sort for n rows. Character comparison adds a cost depending on common-prefix length. Row swaps also copy characters, so fixed-width storage has a different cost from swapping addresses.

For a pointer table, comparison still uses strcmp on the selected strings. A swap exchanges pointer values using a pointer temporary. The target characters remain where they were. This is useful for read-only literal lists or several views over the same names.

Do not sort names with names[i] > names[j]. That asks about address ordering, which does not express text order and may not be valid between unrelated objects. The address with a larger numeric-looking representation does not mean its string comes later alphabetically.

The invented labels in the sorting example appear as Asha, Bela and Toma after sorting. Equal names compare as zero. This particular swap-based algorithm is not promised stable for records with additional associated data. If you later attach marks or roll numbers to names, move the whole related record together.

A two-dimensional char matrix does not convert to char **. The matrix stores characters in consecutive fixed-width rows, while char ** expects pointer objects at the intermediate level. A cast changes the expression type without rebuilding the storage and can lead to undefined behavior.

When rows contain names with spaces, reserve the same per-row terminator space but use fgets with that row's capacity. Remove its stored newline only after success. If one name is too long, handle its remaining input before reading the next row; otherwise the suffix becomes a different student's name.

An outer count can represent a partially filled matrix. With capacity for ten rows and used count three, only the first three initialized rows belong to the logical list. Sorting all ten would inspect entries outside that list. Track row capacity, used rows and each row's character capacity as three different quantities.

A fixed-row copy is safe only if the source is already terminated within a known bound. Equal row capacities support the swap proof because every valid source row fits the temporary and the destination rows. They do not repair an earlier unbounded input that already destroyed termination.

Mistakes and repairs

A row cannot be assigned with rooms[0] = rooms[1] after declaration. An array row is not a pointer variable. Use a checked character copy when the destination row has enough space, or swap pointer entries only in a real pointer table.

Do not apply the total matrix capacity as a %s width for one row. The write target is a single twelve-char row even if the complete matrix occupies thirty-six bytes. Crossing into a later row is still an out-of-bounds operation for that row.

If a table selects local temporary arrays, returning the table does not preserve those targets. Choose caller-owned arrays, documented static data or allocated storage with clear ownership. The next pointer lessons explain these lifetime rules in detail.

Avoid using strlen to infer how many rows exist. strlen scans characters in one terminated string. Keep a separate row count, or calculate it from the actual array in the scope where its full type is known.

A row is not assignable

An array row cannot be assigned after declaration. Copy a checked string with strcpy instead.

Working habits

Use fixed rows for a small editable list with a known maximum name length. Use a pointer table for independent targets or address-only reordering. Validate each row's input limit and keep a clear distinction between row count and per-row capacity.

Standard and portability notes

Arrays of arrays and arrays of pointers follow the same layout rules from C89 through C23. These C17 examples use C99 loop declarations. Literal mutability does not change when a later standard is selected.
