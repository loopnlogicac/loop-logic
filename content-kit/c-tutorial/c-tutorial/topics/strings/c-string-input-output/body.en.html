String Input and Output

A course code is one word, but a room description can contain spaces. Before reading text, decide which kind you need. C offers token-based input through scanf and line-based input through fgets. Their stopping rules differ.

Imagine giving someone a small box for a written note. You must also tell them how much fits. A destination array alone does not stop an input function from writing too much. Use a field width or buffer-size argument, then check whether the input operation succeeded.

Declarations and call rules

For char code[8], the conversion scanf("%7s", code) accepts at most seven non-whitespace characters and appends a zero. The width excludes the terminator, so it is one smaller than capacity. code already supplies the first-element address; do not add an ampersand for this call.

The expression fgets(line, sizeof line, stdin) reads at most one less than capacity into an actual local array. It appends a null on success. stdin means the standard input stream, usually what you type in the terminal.

Use puts(text) for a string followed by newline. Use printf("%s", text) when you want explicit formatting. User text belongs in the argument position, with a constant format describing how to print it.

char code[8];
/* Check that scanf returns 1 before reading code. */
int assigned = scanf("%7s", code);
/* For a line, check the returned pointer before reading line. */
char line[82];
char *result = fgets(line, sizeof line, stdin);

Follow the storage and operations

A %s conversion skips leading whitespace, then reads a token until whitespace or its field width. A successful single conversion returns one. If the input begins with only whitespace and ends, no token was assigned; do not examine an uninitialized array afterward.

A width prevents a buffer overflow, but it does not necessarily consume the whole token. Reading a long code with width seven leaves the remaining characters unread. A later conversion can then read that suffix as another token. Decide whether truncation is acceptable or whether the whole line should be rejected.

fgets keeps spaces and includes a newline if one is encountered before the buffer fills. Its return value is the destination pointer on success, or NULL when no usable string was read. Check that result before searching the buffer.

After success, line[strcspn(line, "\n")] = '\0'; removes a stored newline. strcspn reports the number of initial characters before a newline. When none exists, it reports the current string length, so the assignment rewrites the existing terminator safely.

A missing newline can mean the line was too long, or the final line ended at EOF without a newline. It is not automatically an error. The bounded example allows at most six characters and reads enough to detect a seventh. That extra character proves overflow of the chosen input policy.

char line[8], fgets size = 8
input: A B C \n
buffer: ['A'][' ']['B'][' ']['C']['\n']['\0'][spare]
                                  |
after newline removal:            '\0'
remaining capacity does not imply more input was read

Programs to inspect and trace

Read a bounded word

The conversion stores CSE212 and its zero terminator. Width seven is one less than the eight-element buffer.

Preserve spaces in a line

fgets keeps both words. strcspn finds the first newline, which is replaced by a zero.

Compare puts and printf

puts appends a newline. The percent sign in the data is harmless because printf receives a fixed format.

Reject and drain a long line

The seventh stored character proves the six-character limit was exceeded. The remaining input is discarded through newline or EOF.

Choose the right behavior

If you reject a long line, consume its unread suffix before asking for another line. The draining loop reads into an int, stopping at newline or EOF. Storing getchar in int preserves the distinct EOF value. The output says Too long instead of silently accepting a shortened label.

Numeric scanf usually leaves the next delimiter unread. If you read an integer and immediately call fgets, the newline after the integer may be the entire next line read. Consume the rest of that numeric line deliberately, or use line-based input consistently. A trailing space in the scanf format can instead make the program keep waiting for more input.

puts adds one newline even when text already ends with one. Printing an untrimmed fgets buffer with puts can therefore produce a blank line. Either keep the input newline and use a suitable printf call, or remove it and let puts add the output newline.

The percent character in a room description is ordinary data. printf(text) is dangerous because it treats percent sequences as conversions. printf("%s", text) keeps the description in the data role, with no accidental format interpretation.

Mistakes and repairs

An unbounded %s has no knowledge of the destination capacity. A larger array reduces the chance of trouble without fixing the cause. Always set the correct width for that particular buffer.

The old gets function accepted no destination size. No caller could enforce its write limit through the interface. It was deprecated in C99's later amendment and removed from C11. It has no place in new programs; replace the design with bounded fgets input.

Do not remove the last character blindly with line[strlen(line)-1]='\0'. The line might be empty in a reusable helper or might have no newline. Search for the newline rather than assuming its position.

Working habits

Pick a token or line policy before writing the call. Check the return result, define how oversized input is handled, and preserve text spaces unless your task explicitly removes them.

Standard and portability notes

fgets is standard from C89 onward. C11 removed gets; C17 and C23 do not restore it. The shown programs target C17 and keep fixed capacities so their line policies are visible.

What to carry forward
