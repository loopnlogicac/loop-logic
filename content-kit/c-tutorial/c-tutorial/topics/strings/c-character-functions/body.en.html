Character Functions (ctype.h)

A registration code mixes letters, digits and separators. Instead of writing a long chain of character comparisons, ask ctype.h what kind of character you have. Its small functions classify bytes and convert letter case.

Think of a sorting desk with separate trays for letters, digits and whitespace. isalpha, isdigit and isspace answer which tray fits. isupper asks a narrower question about letter case. The answers are true or false, represented by nonzero or zero integer results.

Declarations and call rules

Include ctype.h before calling these functions. The expression isdigit(ch) tests whether ch is a decimal digit. toupper(ch) returns an uppercase equivalent when one exists, while tolower(ch) returns a lowercase equivalent.

A classification result is not necessarily exactly one. When adding successful tests to a count, use isdigit(ch) != 0. The comparison converts any successful result to one. In an if condition, the raw nonzero result is already suitable.

For bytes stored in a plain char array, use (unsigned char)text[i] as the argument. The valid domain is EOF or a value representable as unsigned char. A negative plain char value outside that domain causes undefined behavior.

unsigned char ch = (unsigned char)text[i];
int digit = isdigit(ch) != 0;
int upper = toupper(ch);

Follow the storage and operations

The token CSE212! has three letters, three digits and one punctuation byte. The loop tests each byte before the string terminator. The exclamation mark increases neither selected count, so the two printed counts are three and three.

isspace handles more than the ordinary blank character. In the initial C locale, it recognizes space, form feed, newline, carriage return, horizontal tab and vertical tab. This helps word counters treat a tab and several spaces as separators under the same rule.

isupper('A') succeeds in the C locale, while isdigit('A') fails. The demonstration prints normalized results so they remain portable. A particular library might return a large positive bit mask for a successful raw predicate; that magnitude has no teaching meaning.

Case conversion does not remove digits or punctuation. Converting Lab-204 produces LAB-204 with toupper and lab-204 with tolower. Nonmatching characters are returned unchanged. The functions return int, so storing their byte result in a char array uses an explicit char conversion.

The unsigned-char conversion preserves the byte's value when plain char is signed. Do not cast a pointer to unsigned char instead of converting the selected character. The function expects a character value, not an address.

Choose the right behavior

A locale is a set of language and regional rules used by parts of the library. A C program starts in the C locale until it explicitly changes that setting. These examples do not call setlocale, which keeps their ASCII classification rules predictable.

Some character properties can differ after a locale change. Do not infer that every byte above the ASCII range is a letter in every environment. These byte functions also do not decode a UTF-8 character spanning several bytes. Bangla text needs an encoding-aware approach for character-level processing.

For direct input with getchar, keep the result in an int until EOF has been checked. A char might not preserve EOF distinctly from every possible input byte. Once a real byte is known, classification can use its valid unsigned-char value.

Whitespace normalization needs more than calling isspace once. Remember whether a separator is pending, and write one ordinary space only when a later nonspace byte arrives. That policy removes leading and trailing whitespace while collapsing internal runs. The hard practice task applies this state-based design.

A character-category report should state whether categories overlap. isalpha and isupper can both succeed for A. If you want disjoint totals, choose an if/else-if chain that assigns each byte to exactly one category. If you want independent properties, separate tests may correctly count the same byte more than once.

Whitespace normalization has its own output bound. Replacing a nonempty separator run with one space never increases its length, and discarding leading or trailing separators shortens it. Therefore an output array with the original line's maximum visible length plus one can hold the normalized result, including termination.

Mistakes and repairs

Do not compare isalpha(ch) == 1. Success is nonzero, and its exact value is unspecified by the interface. Test truth or normalize it with a comparison to zero.

Calling toupper on a possibly negative stored char is not a portable shortcut. Add the unsigned-char conversion at the call boundary so every byte read from the array is in range.

A null terminator is a byte value too, but it marks the end of these text loops. Stop before classifying it. Counting past it would include storage outside the logical string and could eventually exceed the array.

Working habits

Choose categories that match the task. State whether whitespace counts include tabs. Normalize predicate results before arithmetic, preserve EOF during input, and use case conversion rather than guessing ASCII numeric differences.

Standard and portability notes

The listed ctype.h operations are available in C89 and later. Their argument-domain restrictions still apply in C17 and C23. A newer compiler does not convert these byte routines into a general Unicode text library.
