Introduction

Different number problems often reuse the same small loop ideas. A product grows through factors, a pair of values advances through a sequence, and a working number loses one digit at a time. The challenge is to choose a state that explains what has already been completed.

A loop invariant is a fact that remains true at a chosen point on every iteration. It helps you argue that the result is correct, rather than only recognizing a familiar program. For each problem below, connect the initialized state, the update and the stopping rule. Then test the smallest allowed input before trying a larger demonstration.

Syntax and reading guide

/* Product pattern */
result = 1;
for (int factor = 2; factor <= n; factor++) {
    result *= factor;
}
/* Digit pattern */
while (working > 0) {
    digit = working % 10;
    working /= 10;
}

These fragments describe recurring patterns. The complete examples supply declarations, bounded inputs, output calls and the correct types for their own tasks.

Follow the values and decisions

For factorial, before multiplying by factor, result holds the product of all earlier positive factors. Starting from one represents the empty product. This proves zero factorial is one without a special multiplication by zero. Unsigned long long can hold twenty factorial on every implementation with its required minimum range, but twenty-one factorial exceeds a common 64-bit range.

The lesson bounds n at twenty.

For Fibonacci, keep a as the next term to print and b as the following term. The update shifts the pair to b and a+b. Start from zero and one. Save the sum before replacing either operand, or the second update will use the wrong old values.

A prime number is an integer at least two with no divisor other than one and itself. If n has a nontrivial divisor, one member of its factor pair is at most its square root. Test d only while d <= n / d. This avoids overflow in d*d while expressing the same bound for positive n.

A prime-range loop repeats that test for each candidate.

Euclid's GCD loop replaces (a,b) with (b,a%b). Their common divisors stay the same, and the nonnegative remainder decreases below the old second value. When the second value becomes zero, the first is the GCD. For nonzero GCD, LCM is (a/GCD)*b.

Divide before multiplying and widen the product. This lesson defines GCD(0,0) and LCM involving zero as zero.

Examples

Factorial with its zero case

Starting from one, the product becomes two, six, twenty-four and one hundred twenty. No multiplication is needed for n zero or one, so the same initialization gives the correct empty product. The input bound twenty prevents unsigned long long overflow.

A Fibonacci pair

The pair starts at zero and one. Each printed a is followed by a simultaneous-style pair advance using a saved next value. The eight terms end at thirteen. The bound used in the exercises keeps even the extra computed next term inside unsigned long long.

Prime check with a division bound

Twenty-nine survives candidate divisors two through five. Six would exceed the positive square-root bound expressed by n/d, so no further divisor is needed. Starting prime from n >= 2 rejects zero and one before the loop can wrongly accept them.

Primes in a small range

The outer loop tests each candidate from one through fifteen. The inner loop rejects composite values, while one is excluded by definition. The resulting primes are separated by one space. A found flag also lets the program name an empty result explicitly.

Euclid GCD and a safe LCM product

The pair changes from forty-eight/eighteen to eighteen/twelve, twelve/six and six/zero. The GCD is six. Dividing forty-eight by six before multiplying by eighteen gives LCM one hundred forty-four. The widened product avoids an unnecessary int intermediate.

A palindrome keeps its original

The reversal takes the digits from the right and builds another integer. The saved original stays 1221 while n becomes zero. Comparing the reversed result with that original gives one. The do-while also handles zero as a valid one-digit case.

Armstrong uses the actual digit count

The first digit pass counts four positions. Each digit is then multiplied into an integer power four times. The fourth-power sum equals 1634, so the output is one. A fixed cube would give the wrong answer for this four-digit candidate.

A perfect-number divisor sum

The loop checks divisors through three and adds one, two and three. Their sum equals six, so the predicate is true. The extra n > 1 guard excludes one, whose empty proper-divisor sum cannot make it perfect.

Boundaries and alternatives

A palindrome number equals its reversed digits. Preserve the original before division consumes a working copy. Numeric reversal ignores leading zero formatting. Zero is a palindrome under this lesson's definition.

An Armstrong number equals the sum of each decimal digit raised to the number of digits. The exponent is the digit count, not always three. For 153, the sum is one cubed plus five cubed plus three cubed, which is 153. For 1634, use fourth powers.

Count zero as one digit, and compute powers with bounded integer multiplication rather than floating pow.

A perfect number equals the sum of its positive proper divisors, excluding itself. For six those divisors are one, two and three. One is not perfect because its proper-divisor sum is zero. The straightforward example checks through n/2; a factor-pair method can reduce work for larger bounds.

Explain the work before increasing bounds

Factorial and a list of n Fibonacci terms use a number of updates proportional to n. The straightforward prime check uses at most about the square root of the candidate divisor tests. Checking a whole interval repeats that cost for every candidate, so a later sieve is better when many primes are needed. The array lessons provide storage tools for such improvements.

Digit extraction uses one iteration per decimal digit. Armstrong checking also performs one short power loop per digit. For the six-digit bound, each digit power is at most nine to the sixth, and the sum is at most six times that value. That bound fits the stated GCC host int.

Raising the input range would require a new bound argument and possibly a wider type.

Euclid uses only a pair of working integers and repeatedly reduces the second value. The LCM result can be much larger than either input, which is why its product uses long long. Extra storage remains constant for these small number algorithms. Outputting a Fibonacci sequence does not require storing every term when only the current pair is needed.

Common mistakes

Starting every accumulator at zero

A sum starts at zero, while a product starts at one. Multiplying a zero factorial accumulator would keep it zero forever. State the meaning of the initial state before the first iteration.

Using a cube for every Armstrong candidate

The required power is the number of decimal digits. Include a four-digit candidate to reveal the shortcut. Keep each intermediate power and the complete sum within a proven bound.

Questions to ask while reading

QuestionRule and reason
What initial product makes zero factorial correct?1. The product of no factors is one.
Why save the next Fibonacci value before replacing a?Both old pair values are needed. Overwriting one too early loses part of the sum.
Why can primality testing stop at the square root?A nontrivial factor pair has a member at most that bound. If neither factor were small, their product would exceed n.
What quantity stays the same in Euclid replacement?The set of common divisors. Replacing a by its remainder preserves common divisibility.
Why divide before multiplying in LCM?It reduces the intermediate product size. The equivalent formula is safer when the GCD is nonzero.
Which power belongs in an Armstrong test?The number of decimal digits. Four-digit candidates require fourth powers.
Which divisors belong in a perfect-number sum?Positive divisors smaller than the number. Proper divisors exclude the number being tested.

Version notes

The algorithms use C17 and long long from C99. No example depends on integer overflow or a floating approximation to an exact digit power. The chosen input bounds are part of the correctness argument.
