Introduction

Imagine printing roll numbers for forty students. Writing forty almost identical printf calls would be slow and easy to mistype. A loop repeats a statement or block while a rule allows another repetition. You describe the work once and let a changing counter or input control how often it runs.

A repetition is also called an iteration. The useful questions are where the loop starts, what state changes, and when it stops. C provides while, do-while and for. They can express many of the same calculations, but each makes a different kind of stopping rule easier to read.

Syntax and reading guide

while (condition) {
    /* work, then update */
}
do {
    /* work, then update */
} while (condition);
for (initialization; condition; update) {
    /* work */
}

These are syntax sketches, not three blocks to paste together unchanged. The names condition, initialization and update stand for expressions you choose for the task.

Follow the values and decisions

A while loop checks its condition before each iteration. If the starting condition is false, the body runs zero times. This is an entry-controlled loop. A for loop also checks before its body.

Its initialization, condition and update sit together in the header, which suits counted repetition.

A do-while loop performs the body before checking whether to repeat. It is an exit-controlled loop, so the body runs at least once when control reaches it normally. A menu that must display before reading the first choice often fits this shape. Its trailing semicolon belongs to the syntax.

For a count of three, you can begin at one, repeat while the counter is at most three, and add one after each output. The body sees one, two and three. The final condition sees four and fails. Notice that a pre-test loop normally performs one more condition check than completed iterations.

A sentinel is a special input value that means stop. It is not ordinary data. For example, negative one can end a stream of nonnegative marks. You cannot know the number of iterations in advance, so while often reads more naturally than a fixed-count loop.

Input failure and end-of-input also need a stopping policy.

Examples

Repeat a counted action

The counter begins at one and reaches three inside the body. Increment then makes it four, so the next condition fails. Three labeled lines appear, each produced by the same source statement with a different counter value.

Skip a pre-test body

The starting condition is false because no seats remain. The body never runs, and Done is printed afterward. This zero-iteration behavior is often exactly what an empty workload requires.

Compare a post-test body

The body prints Menu before checking remaining. The false condition then stops repetition. Compared with the previous example, moving the test changes whether the initial body runs, even though the starting value is identical.

Boundaries and alternatives

Choose for when the count progression is central to the task. Choose while when a condition or read controls repetition. Choose do-while when the first action must happen before its first repeat decision. These are readability choices, not separate categories of problems a compiler can solve.

Every terminating loop needs a reason to make progress toward exit. A counter can move toward a bound; an input loop can consume new input or stop at a sentinel. If the condition remains true and nothing leaves the loop, repetition continues. An intentional infinite service loop needs a clear exit or external lifetime policy; an accidental infinite loop usually means a missing update or failed input recovery.

Begin with a small trace table containing the counter before the test, the condition result, and the body action. Include the final failed test. A trace that stops immediately after the last printed value can hide the actual stopping reason.

Common mistakes

Assuming every loop runs at least once

Only the do-while shape places its ordinary repeat test after the first body. A while or for with a false initial condition skips the body. Check zero-work cases before choosing a loop.

Changing the wrong variable

A condition based on count will not become false merely because another variable changes. Trace the exact value used by the condition. Tie each update to a measurable step toward completion.

Questions to ask while reading

QuestionRule and reason
Which loops check before their body?while and for. Both pre-test forms may run zero iterations.
Which loop naturally guarantees an initial menu display?do-while. Its body comes before its repeat test.
What is one loop iteration?One repetition of the body. The body is the work repeated under the loop rule.
What is a sentinel?A special input value signaling stop. It is excluded from ordinary data processing.
Which loop is usually clearest for a simple known count?for. Its header collects the counter progression.
What should a loop trace include after the last body?The final condition that stops repetition. The failed test explains why the body does not run again.
What often causes accidental infinite repetition?A missing update or missing input progress. The state never moves toward a false condition.

Name one iteration's work

For roll printing, one iteration handles one roll. For a menu, one iteration handles one displayed menu and one choice. Naming that unit helps you place initialization outside the loop and the repeated actions inside it. It also reveals whether an empty input should require zero iterations or one initial attempt.

Version notes

All three loop forms exist in C89. C99 permits a variable declaration inside a for header. The C17 examples use that convenient form and consistently brace the loop bodies.
