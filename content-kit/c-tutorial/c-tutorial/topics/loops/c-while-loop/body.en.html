Introduction

Suppose you keep reading marks until a stop value arrives. You cannot write the exact number of reads in advance. A while loop repeats while its condition remains nonzero. The condition is tested before each body, including the first one.

Picture a gate you revisit after every piece of work. Passing through once does not promise another turn. The loop must update its state or consume input before returning to the gate. You will use this structure for counting, reading until a sentinel, summing digits and reversing a number.

Follow the values and decisions

A counter loop might start at one and run while the counter is at most three. Print the current counter, add one, then test again. After the third body the counter becomes four. The false test leaves the loop.

Starting above three would skip all bodies, which is the correct behavior for an empty range.

A sentinel loop gets its progress from reading new input. First try to read a value, then decide whether it is the sentinel. Process only ordinary data. You can combine a successful scanf assignment with a non-sentinel test using logical AND.

If reading fails, short-circuiting prevents the stale destination from being treated as new data.

For decimal digit work, percent ten extracts the last digit of a nonnegative integer. Integer division by ten removes that digit. Starting with 5070, the extracted digits are zero, seven, zero and five. Their sum is twelve.

Each division makes a positive value smaller, so the loop eventually reaches zero.

To reverse the digits, keep a separate result initialized to zero. Repeatedly multiply it by ten and add the next extracted digit. For 120, the result evolves through zero, two and twenty-one. Numeric reversal drops leading zeroes in the reversed representation because an integer does not preserve formatting width.

Bound the input so the intermediate reversed value fits.

Boundaries and alternatives

The number zero needs special thought in digit algorithms. A while condition based on positive n skips its body for zero. That is fine for a digit sum initialized to zero. A digit-count task, however, should count zero as one decimal digit.

Handle it separately or use a do-while shape.

An intentional while (1) repeats until a break, return or another permitted transfer leaves it. Use it only with a clear termination mechanism. A failed scanf that consumes nothing can otherwise leave a loop stuck on the same nonmatching character. Stopping on failure is safer than retrying the identical read forever in these early examples.

Keep an original copy when the task needs the input later. Digit extraction destroys the working copy by repeated division. A palindrome comparison, for example, must compare the reversed result against the preserved original number.

Common mistakes

Forgetting the counter or digit update

If n stays positive forever, the condition never changes. Put the progress operation where every repeating path reaches it. Trace the smallest nonzero input to locate missing progress.

Using an unchecked read in the repeat condition

The destination may keep an old value after failure. Check scanf for the required assignment count, then inspect the sentinel. Do not process a stale mark as though a new mark arrived.

Questions to ask while reading

QuestionRule and reason
When is a while condition tested?Before every body execution. A false test skips the next body.
What progress does n /= 10 provide for positive digit work?It removes the last decimal digit. A positive integer eventually reaches zero.
Which operator extracts the last nonnegative decimal digit?% 10. Remainder after division by ten is the low digit.
Should a sentinel be added to a marks total?No. Its role is termination rather than data.
Why preserve original before reversing n?The working n is consumed by division. The original is needed for a later comparison.
How many body executions occur when a while starts false?Zero. It is an entry-controlled loop.
What is dangerous about retrying a failed numeric scanf unchanged?The same bad character may remain unread. Without consumption or exit, failure can repeat forever.

Choose a name for destructive work

A variable called remaining_digits makes repeated division easier to recognize than changing the original input silently. Preserve the input when the final report needs to name it. The loop's progress and the report's identity are separate roles.

Version notes

While is part of C89 and remains unchanged in C17. The digit programs use C99-or-later division rules, though their nonnegative values avoid negative-remainder differences. C17 is the build baseline.
