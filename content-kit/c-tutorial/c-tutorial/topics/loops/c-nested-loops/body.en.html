Introduction

A classroom has several rows of seats. To label every seat, you visit each row and then each column in that row. A nested loop puts one loop inside another. The outer counter often identifies a row; the inner counter identifies a position within it.

Think of reading a table from left to right, then moving down to the next row. The inner loop completes its own run before the outer loop advances. You can use this structure for multiplication grids, coordinate pairs and patterns. Start with tiny dimensions so the order stays visible.

Syntax and reading guide

for (int row = 1; row <= rows; row++) {
    for (int column = 1; column <= columns; column++) {
        /* one cell */
    }
    /* one completed row */
}
row 1: column 1, column 2, column 3
row 2: column 1, column 2, column 3

Follow the values and decisions

With two rows and three columns, the outer loop first sets row to one. The inner declaration starts column at one. Its three iterations visit the first row's cells. Only after the inner test fails does the outer update set row to two.

The inner declaration then starts a fresh column counter at one again.

There are two useful places for output. A print inside the inner body happens once per cell. A newline after the inner loop happens once per row. Putting the newline inside the inner body would produce a column of values instead of a grid.

Putting it after both loops would join all rows into one line.

For a rectangular grid with n rows and m columns, the inner body runs n times m times. If both dimensions double, the number of cells becomes four times larger. This gives an early time-cost intuition: a straightforward rectangular traversal is proportional to n*m. The counters themselves need only a small fixed amount of extra storage.

Not every nested loop has a rectangular count. If the inner bound equals row, the number of visits is one plus two through n. This triangular total is n*(n+1)/2. The outer loop still resets the inner counter every time, but each later row permits more inner iterations.

Derive the count from the actual bounds rather than multiplying two unrelated maximum values blindly.

Examples

Visit coordinate pairs

The first row prints three pairs with row one, then the second row starts column again at one. The newline is outside the inner loop, producing exactly two output lines. Six cells confirm the product two times three.

A multiplication grid

Each cell multiplies its row number by its column number. Width three aligns the small products. The final row contains three, six and nine. The nine body executions fill a three-by-three grid.

A growing inner range

The inner loop runs one, two, three and four times on successive rows. Their total is ten. Treating every row as four visits would overcount; the row-dependent bound is the key difference from a rectangle.

Boundaries and alternatives

If either rectangular dimension is zero, the inner body runs zero times. The outer loop may still perform row-level work when columns is zero. Decide whether empty rows should produce blank lines for your particular output format. These examples specify small positive grid dimensions except where zero is an explicit practice edge case.

Use different counter names. Updating row inside the column loop can skip rows or break the outer stopping rule. Declare the column counter in its own for header so its reset is obvious and it cannot be used after the inner loop by mistake.

A break inside the inner loop leaves only that inner loop. The outer loop can then begin another row. Exiting both requires an outer condition, a flag, or a carefully named exit, explained in break and continue. Indentation alone cannot change which loop owns a break.

Common mistakes

Failing to reset the inner counter

A counter declared and initialized before both loops may already be beyond its bound after the first row. Put the inner initialization inside the outer body so each row begins at column one.

Printing a row newline per cell

Follow the unit of work. A value belongs to one cell; a newline belongs to one completed row. Place each output at the loop level that matches that unit.

Questions to ask while reading

QuestionRule and reason
When does the inner for initialization run?Each time the outer body reaches that loop. A new row starts the inner progression again.
How many cell visits occur for 3 rows and 4 columns?12. Each of three rows has four visits.
Where should a row-ending newline go?After the inner loop inside the outer body. It must happen once per completed row.
What changes when the inner bound is row?Different rows have different visit counts. The total becomes a sum of row lengths.
How does doubling both rectangle dimensions affect cell count?It multiplies the count by four. The count is the product of both dimensions.
Which loop does an inner break leave?Only the nearest enclosing loop. A separate outer exit condition is needed to stop both.
Why use separate row and column names?To keep each progression and role clear. Mixing updates can corrupt the traversal.

Trace a tiny rectangle before a large one

A two-by-two grid has four cell visits but only two row completions. Mark the cell action and row action in different columns on paper. Their counts explain where output statements belong more clearly than staring at indentation alone.

Version notes

Nested loops are ordinary loops used inside a body. C99 permits the header-local counters shown here. C17 adds no special reset rule: the inner initialization runs again because control reaches its declaration again.

Summary

The inner loop finishes for each outer value. Reset the inner counter for every new row. Continue with break and continue.
