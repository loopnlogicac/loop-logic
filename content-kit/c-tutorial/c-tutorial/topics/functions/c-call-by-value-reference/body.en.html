A copied address can still reach the original

Imagine writing a room number on a second piece of paper. You now have two pieces of paper, but both identify the same room. Changing the copied paper does not change the original paper. Entering the room can still change what both room numbers lead to.

This picture helps explain C arguments. C always uses pass-by-value: an argument value is copied into a parameter. For an int argument, the copied value is an integer. For a pointer argument, the copied value identifies an object or is a null pointer.

The title call by reference appears often in exam questions. In C, it usually means simulating updates to caller objects through pointer parameters. C has no built-in reference parameter mechanism. The address itself is still passed by value.

Read the address and the object separately

void swap(int *a, int *b)
{
    int temporary = *a;
    *a = *b;
    *b = temporary;
}

A pointer stores an address-like value identifying an object. In the parameter declaration, int *a says that a points to int. In an expression, *a accesses the int selected by that pointer. This operation is called dereferencing.

At the call, swap(&left, &right) passes addresses of the caller's two variables. The address operator & does not copy the entire variable into the helper. It produces a pointer value, which is then copied into a or b.

Dereferencing requires a valid target. The target must still exist, have a suitable type and permit the intended read or write. An arbitrary integer is not a safe replacement for an object address. More pointer rules appear in Introduction to Pointers.

Compare the two swaps one assignment at a time

The value-copy swap receives two independent int parameters. Swapping those parameters changes the helper's own objects. Nothing in that function identifies the caller's original objects for writing. Printing inside the helper can therefore look correct while main remains unchanged.

Before value swap: main a=12, main b=30
Inside helper:      copy a=12, copy b=30
After local swap:   copy a=30, copy b=12
After return:       main a=12, main b=30

Pointer swap: a points to main a; b points to main b
*a = *b writes into main a
*b = temporary writes into main b

For the pointer swap, first save the value reached through a. Next, copy the value reached through b into a's target. Finally, write the saved value into b's target. The temporary is necessary because the first write otherwise destroys a value still needed later.

A caller may use completely different names, such as score and bonus. Parameter names a and b do not match objects by spelling. The argument expressions establish the connection. This matters when several functions each use local variables called value.

Passing the same address twice is also worth tracing. With the temporary-based swap, both reads initially get the same value. Both writes store that value back, so the object stays unchanged. An XOR-based swap does not have this useful property when both pointers select one object.

In the retarget example, changing chosen modifies the local pointer parameter. It does not redirect main's chosen pointer. The following starred assignment uses the new local target, so other becomes 25. This separates changing a pointer from changing the object it selects.

The optional-output example gives null a deliberate meaning. NULL is a macro for a null pointer constant, and a null pointer identifies no object. The helper checks for null before dereferencing. Its return flag tells the caller whether an increment occurred.

State the pointer contract

Not every function must accept null. A swap helper can require two valid writable int pointers as part of its interface. A function that promises optional output should instead check whether that output pointer is null. Pick a rule and document it where callers can see it.

A non-null pointer is not automatically valid. A pointer can refer to an object whose lifetime has ended, or hold an unrelated value. Testing against NULL cannot prove that storage is alive or correctly typed. The caller and helper must preserve these conditions together.

Two parameters may select the same object. This is called aliasing. Decide whether an algorithm allows it before accepting shared targets. The transfer practice uses distinct source and destination variables. If a transfer interface allowed the same object for both, its promised meaning would need careful explanation.

An input pointer may be declared const int *value when the helper should only read that int. The const qualification limits writes through this access path. It does not promise that every other part of the program is unable to change the object.

To change a caller's pointer variable itself, a helper normally needs its address, producing a pointer-to-pointer parameter. That is a different interface from the int-pointer swap. See Pointer to Pointer when you need to replace which object a caller pointer selects.

Match each operation to the intended object

Passing values where addresses are required

A call to swap(a, b) is wrong when the prototype expects int pointers and a and b are ints. Use the address operator on each live variable. Do not try to silence the type diagnostic with a cast.

Assigning the pointer instead of its target

Inside a pointer helper, a = b; changes which object local a selects. *a = *b; copies one target value to another. Read the stars before deciding what a line changes.

Returning an address of a short-lived local

A local int disappears when its automatic lifetime ends. Returning its address does not extend that lifetime. Place result storage in the caller or choose storage with an appropriate longer duration.

Overwriting before saving

Writing the first target from the second and then the second from the first copies the same value twice. Save the original first value before either write. A three-line trace makes the lost-value bug visible.

Make updates visible at the call

Use pointer parameters when a helper must update caller-owned storage or work with a larger object. For a small calculation with one result, returning that result is often easier to follow. An address at the call helps readers notice an intended update.

Check a helper with different values, equal values and shared targets when its contract allows them. A rotation needs three distinct variables in its practice task. A swap can be checked with one address used twice. Choose boundary checks from the actual update rules.

Keep reads and writes in separate statements while learning. A complicated expression containing several modifications hides which value was saved first. Straightforward assignments make a pointer trace easier to verify and maintain.

Reference terminology does not change the language rule

C89 through C23 pass arguments by value. Pointer parameters provide indirect access to objects; they do not create a separate language-level pass-by-reference mode. The programs here follow C17 pointer rules without compiler extensions.

Follow values and storage separately

An int parameter is a copied integer; an int-pointer parameter is a copied pointer. Dereferencing a valid copied pointer can update the original target. Continue with Scope and Lifetime to understand where names work and how long their objects remain valid.
