A name for a useful job

A function is a named group of statements that performs one job. Think of a lab assistant who knows how to calculate a photocopy bill. You give the page count, receive the price, and continue your own work. You do not explain the multiplication rule at every request.

Functions give the same benefit in C. A program may need the same price rule at several points. Writing that rule once makes it easier to understand and change. A later price change belongs in one place. Every call then uses the revised rule.

You have already called functions such as printf and scanf. Those are library functions supplied by the C implementation. A user-defined function is one you write for your own problem. Both kinds are called using a name followed by parentheses.

Read the parts of a function

int copy_cost(int pages)
{
    return pages * 3;
}

The first int describes the result type. The name copy_cost describes the job. Inside the parentheses, int pages declares an input parameter. The braces contain the function body. The return statement calculates a result and finishes this call.

A parameter is a local variable that receives an input value. In copy_cost(12), the expression 12 is an argument. The argument value initializes pages when the call begins. Here the returned value is 36, and the caller may print it or store it.

A function with return type void does not supply a result value. A greeting function is a good example. It still performs work, but there is no number to assign. Writing void inside the parameter parentheses states that a function takes no arguments.

Pause, call and resume

A call transfers control to the named function. The caller waits while the called function runs. When the called function returns, control resumes at the waiting call. Execution does not restart at the beginning of main.

A call stack is a useful picture of active calls. Each active call has a record of its local work and where to return. The most recent call finishes first. This picture explains nested calls even though C does not require a particular physical stack design.

main starts report
    main waits | report starts line
    main waits | report waits | line prints
    main waits | report resumes and finishes
main resumes after report()

The nested report example follows this order in its messages. main cannot print its final message while report is still active. report itself cannot finish before line returns. A function definition may appear earlier in the file without running earlier; a call starts execution.

Two calls to the same helper normally create separate automatic parameters and local variables. The page count of one bill does not become the next bill's count. Later lessons introduce static objects, which deliberately retain values between calls.

Use the greeting to separate repetition from definition. Find the single body that describes the greeting, then count its two calls. For the photocopy program, identify the two argument values before calculating either price. The arithmetic is familiar; the new part is where it happens.

The distance helper combines code you own with a library service. Including stdlib.h makes the declaration of abs available. The function returns an integer magnitude. Avoid passing the most negative int to abs when its positive counterpart cannot fit in int.

Decide what the helper promises

A useful function has a small, clear contract. For copy_cost, this could mean accepting a nonnegative page count small enough for multiplication by three. The return value then means the total price in taka. A negative page count would violate that classroom contract.

Decide which layer checks input. main can reject unsuitable user input before calling a mathematical helper. That keeps the calculation focused. A widely reused helper may also need its own checks. The important point is to make the responsibility clear rather than hoping every caller guesses correctly.

Functions can call other functions, including library functions. They cannot be defined inside another function in standard C. Place helper definitions outside main, with their own braces. Indentation helps you see that the helpers are separate pieces of the program.

Distinguish a definition from a call

Writing a name without calling it

The parentheses in welcome() matter. The name alone does not run the greeting. Call the function as a statement when only its action matters. Use a result-producing call inside an expression when you need its returned value.

Expecting every helper to print

A price helper can return 36 without displaying anything. Printing belongs to the caller in that design. Keeping calculation separate from display lets another caller use the same number in a larger total.

Making one function do unrelated jobs

A helper named copy_cost should not also read marks and choose a grade. Unrelated actions make the name misleading. Split those jobs so each name tells the reader what to expect.

Choose a small boundary

Name functions with verbs or clear result descriptions, such as show_report or copy_cost. Read a call as a short sentence. If the meaning remains unclear, improve the name or reduce the number of responsibilities.

Try a helper with a small input, a typical input and a boundary input. For the price rule, zero pages should cost zero. Compare the returned number with a calculation you can do by hand. You can then trust that part while reading a larger report.

Functions across C editions

Named functions, explicit return types and prototypes are available in C89. The programs here use C17 and some C99 declaration style. No special extension is needed for one function to call another.
