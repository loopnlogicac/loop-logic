Storage class is more than a location label

A lab may keep a daily visitor sheet and a permanent total. Both records can sit inside the same room, yet their persistence differs. C storage-class specifiers help describe comparable choices for variables and names. They do not merely choose a physical place in memory.

The four traditional specifiers in this lesson are auto, register, static and extern. Their effects depend on where the declaration appears. In particular, static inside a function changes duration, while static at file scope also changes linkage.

Review Scope and Lifetime if visibility and existence still seem interchangeable. Here a third idea matters: linkage tells whether different declarations can identify the same object or function. External linkage can connect declarations across translation units.

Compare declarations by context

auto int subtotal = 0;
register int index = 0;
static int visits;
extern int lab_capacity;

The first two lines belong inside a function or another block. auto explicitly names the usual automatic storage class of a block variable. It is normally omitted. register suggests frequent access, but a compiler may ignore that hint when choosing machine instructions.

A block-scope static object lasts for the entire program. Its name still belongs to the block. An extern declaration can refer to an object defined elsewhere. Without an initializer, it does not by itself supply the object's storage.

A static initializer is not a repeated reset

Consider a helper containing static int visits; followed by an increment. Before normal execution begins, visits is initialized to zero. The first call increases it to one. Returning hides the local name from callers, but the object continues to exist.

The second call reaches the same object, whose value is already one. Its declaration does not reset it. The next increment produces two. An ordinary int visits = 0; would instead create and initialize a new automatic object for each call.

Static-duration objects without explicit initializers receive zero initialization. For arithmetic objects this gives zero; pointer objects receive null pointers. Ordinary automatic objects without initializers do not receive the same useful guarantee. Initialize a subtotal before reading it.

A static local initializer must be a permitted constant expression in C. It cannot call a function to initialize itself on first entry as some other languages allow. If a value depends on runtime input, arrange an explicit assignment and define when that assignment should occur.

The private-total example uses static on both an object and a function at file scope. Other translation units cannot link to those names as external interfaces. The helper can still read and change the total normally inside this source file.

The extern example places its definition later in the same file so you can run the idea in one program. The source-file boundary adds a separate compilation and linking step.

Use extern across source files

Suppose a small program has two source files and one header. A header named capacity.h contains extern int lab_capacity;. One file, capacity.c, includes that header and defines int lab_capacity = 60;. A second file includes the header and prints the value from main.

Compile and link both sources together with gcc -std=c17 main.c capacity.c -o capacity. The declaration gives main the type information. The definition in capacity.c provides the object. Linking only main.c leaves the external reference without its definition.

The following are the exact declarations needed in those two places. The runnable extern example above puts their relationship in a single translation unit. The multi-file form changes where the definition is compiled, not whether two separate capacity objects should exist.

extern int lab_capacity;
int lab_capacity = 60;

Do not put the initialized definition in a header included by several source files. Each inclusion would define another externally linked object. A header should share the extern declaration; one implementation file should own the definition.

In C17, register also imposes a language restriction. You cannot apply the address operator to an object declared register. This remains true even if the compiler stores it in ordinary memory. Avoid register for objects whose addresses you need to pass to another helper.

File-scope objects already have static storage duration without the word static. Adding static there mainly changes their linkage to internal. Saying that static always means a global variable is therefore misleading: a static local has block scope, and a non-static global already persists.

Separate declaration from definition

Assuming extern always creates a new object

An ordinary extern int rate; declares a reference to an existing definition. Adding an initializer makes an object declaration a definition, including when extern is written. Keep the single storage-owning definition easy to locate.

Using a static local as a fresh subtotal

A static subtotal accumulates across calls unless explicitly reset. That can silently combine unrelated calculations. Use an automatic subtotal when each request should start from zero.

Promising speed with register

Modern compilers choose register allocation from the whole function. The keyword does not guarantee faster code or a hardware register. Clear algorithms and measured performance matter more than this hint.

Giving a private object an external declaration elsewhere

A file-scope static object is not an external object available to another source file. Expose an intentional helper interface if another module needs controlled access. Do not try to connect incompatible linkage expectations by matching spellings alone.

Keep persistent state deliberate

Prefer automatic variables for temporary calculation. Use file-scope static for implementation state that belongs privately to one source file. Avoid exposing writable global state unless there is a clear reason and an ownership rule.

For a static counter, decide its starting value, increment moment and reset behavior. Also consider repeated use in one program. An interface that remembers calls can be harder to test or reuse than a function whose result depends only on its arguments.

When reviewing an extern declaration, find the matching definition and compare types. Include the same header in its implementation file. This lets the compiler catch a mismatch before a separately compiled caller relies on it.

Traditional rules and newer additions

auto, register, static and extern are traditional C keywords. C11 also adds thread storage duration through _Thread_local. C23 extends auto to support type inference in certain declarations; these examples deliberately use the explicit C17 spelling auto int.
