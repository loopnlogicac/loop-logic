Visibility and existence answer different questions

A classroom notice may be visible only inside one room, while the room itself stays there overnight. A C variable also has two separate properties. Its name may be usable only within a small region. Its storage can exist for a shorter or longer period.

Scope means the region where a name can be used. Lifetime means the part of execution during which an object exists. C also uses storage duration to describe broad categories of object lifetime. Keeping these ideas separate helps explain nested blocks and persistent counters.

A variable declared inside a function usually has block scope and automatic storage duration. A local static variable also has block scope, but its object survives between calls. These two declarations can look similar while behaving differently during repeated execution.

Locate the declaration and its braces

int seats = 40;

void count_visitors(void)
{
    int today = 0;
    static int all_days;
    today++;
    all_days++;
}

The name seats has file scope from its declaration onward. today and all_days have scope within the helper's block. today is automatic and is newly initialized on each call. all_days has static storage duration and retains its previous value.

A name's scope generally starts just after its declarator. It does not reach backward to earlier statements. File scope likewise does not mean a name is visible before its declaration. An earlier declaration can make a later-defined object known where needed.

The helper above is a reading fragment. The complete visit example prints both counters so you can observe their different lifetimes. A block can also be nested inside main without defining a new function.

Name lookup chooses the closest visible declaration

Shadowing happens when an inner declaration hides an outer declaration with the same name. The inner object is separate storage. Hiding the outer name neither changes its value nor destroys it. After leaving the inner scope, the outer declaration becomes visible again.

The inner print therefore uses 92. The final print uses the unchanged 70. If the inner block assigned to mark without declaring another mark, it would update the outer object instead. The declaration is what creates the separate object.

Function calls have their own blocks and parameters. A helper parameter called value does not shadow a caller's value through the call relationship. Each function is a separate lexical region. Scope follows source-code nesting, not the chain of active calls.

Local and file-scope names

A label can be used within its function

The label is visible throughout main. The jump does not carry a block-local object beyond its lifetime.

The capacity program distinguishes a local name from a file-scope object. main prints its own seats variable, representing occupied seats. show_capacity reads the file-scope seats, representing total capacity. Choosing different names would be clearer in everyday code, but the shared spelling makes lookup visible here.

The label example revisits goto. Labels have function scope, so a jump can name a label elsewhere in the same function. Ordinary variable names do not gain function scope just because they appear in a function.

Four scopes and two common durations

A prototype parameter name is only a description for that declaration. It does not create a reusable variable for main. A for-loop counter declared in its header has a limited scope covering that loop, including its body. Code after the loop needs a different declaration if it needs a counter.

An ordinary non-VLA automatic object exists during execution of its associated block. Re-entering that block creates a new instance. Recursive calls therefore get separate automatic locals. A local initializer runs again for each execution that reaches it.

A static-duration object exists for the whole program execution. Its constant initializer is established once before normal program work. If no initializer is written, such an object is zero-initialized. Its name may still be hidden outside one small block, as with the persistent visit counter.

A pointer can outlive the automatic object it once selected. After the object's lifetime ends, dereferencing that pointer is invalid. The address does not preserve the former object. Returning the value of a local integer is safe; returning its address for later access is not.

Scope also differs from linkage, which concerns whether declarations denote the same entity across scopes or translation units. File-scope static names have internal linkage. The next lesson explores that third property without treating it as another word for visibility.

Do not infer lifetime from indentation

Expecting a local counter to remember a call

An automatic int initialized to zero starts again on the next call. Incrementing it once and returning does not save it. Use a deliberately persistent object when previous calls matter, and consider how that state affects reuse.

Reading a name after its block ends

An inner variable cannot be named after its closing brace. Move a result into an outer variable before leaving if it is needed afterward. Do not widen every local scope merely to avoid planning where a result belongs.

Assuming a hidden object was overwritten

A shadowing declaration creates a new object. The outer object remains alive unless its own lifetime ends. To modify the outer variable, avoid introducing a same-named inner variable.

Mixing labels with ordinary identifiers

A label is a jump destination, not a data object. It has function scope and belongs to a separate name category. Its visibility does not permit jumping into forbidden VLA scopes or accessing expired local storage.

Keep local meaning local

Prefer different names for different concepts, such as capacity and occupied. This removes the need to remember which declaration hides another. Enable an optional compiler warning such as GCC's -Wshadow when checking a larger program.

Declare a temporary near the work that needs it. Narrow scopes reduce accidental reuse, especially for loop counters and subtotals. Use a static local only when retained state is part of the function's intended behavior.

Trace repeated calls with two columns: the new automatic values and the persistent static values. This catches the common mistake of treating every initializer as an action repeated on entry. It also shows why resetting a static counter requires an explicit design.

Loop declarations and storage duration

C99 introduced declarations in for headers and mixed declarations with statements. The distinction between block visibility and static storage duration remains in C17. VLAs have additional lifetime rules tied to reaching their declaration.
