A runtime bound changes the storage decision

Sometimes an array length becomes known only after reading input. A variable-length array, or VLA, has a bound that is not an integer constant expression. Its extent is determined during execution when control reaches the declaration.

This can make a small mathematical routine convenient. A helper can work with a matrix whose row width is supplied at runtime. However, convenience does not remove size limits or portability concerns. A length taken directly from untrusted input is not automatically a safe allocation size.

Think of reserving seats only after counting visitors. You must finish the count and confirm a reasonable limit before arranging the seats. Similarly, validate a VLA bound before declaring the array, and choose another storage strategy when the possible size is large.

The examples use very small caps and provide a fixed-capacity branch for implementations that advertise no VLA support. They also show an allocated alternative. The goal is to make the storage choice explicit rather than assuming every compiler and machine has identical limits.

Declare only after validating the bound

int n;
if (scanf("%d", &n) != 1 || n < 1 || n > 16) {
    return 1;
}
int values[n];

At the declaration, n supplies the extent. Every evaluated array bound must be greater than zero. Reading n later is too late; the declaration has already needed its value. A negative or zero evaluated bound does not create a portable empty VLA.

A local const int is not an integer constant expression in C17 merely because it cannot be assigned again. Therefore const int n = 4; followed by values[n] can still declare a VLA. Use an enum constant, a macro constant or a literal for a fixed array bound.

An ordinary VLA object has automatic storage duration and block scope. It cannot be a file-scope array with a runtime extent. It also cannot be made into a static-duration object by adding static to that variable-length declaration.

An extent is fixed for that array instance

When execution reaches a VLA declaration, its evaluated bounds determine that instance's size. Changing the variable later does not resize the object. The size example begins with n equal to three, declares the array, and then assigns five to n.

sizeof values still describes three elements. The variable now holds a different number, while the existing object retains the original extent. To create a new VLA instance with another extent, execution must reach an appropriate declaration again under the language's scope rules.

For a VLA type, sizeof can require runtime evaluation. For an ordinary fixed array, sizeof is normally an integer constant expression. Avoid side effects in dimension expressions, because they make these evaluation distinctions difficult to reason about.

C17 does not permit an initializer on a VLA object. Declare it, then assign or read each element in a loop. The fixed fallback may use an initializer, but the VLA branch needs explicit element initialization before reading.

The fixed fallback uses a four-column row type on both sides of its call. It may use only three columns logically, but its physical row width is four. Matching that width is necessary for correct row stepping. The VLA branch instead has physical width equal to the runtime columns value.

Understand the lifetime and storage risk

A VLA's lifetime begins at its declaration and ends when execution leaves its scope. A pointer into it becomes unusable after that lifetime ends. Returning such a pointer cannot extend the storage, just as returning a pointer to an ordinary automatic array cannot.

Many implementations place automatic VLAs on a call stack. C does not require that physical arrangement, but execution storage is limited either way. An excessive bound can exhaust the available storage. Unlike malloc, the declaration does not return a null pointer that the program can check.

A fixed small upper bound makes classroom use easier to audit. For real workloads, consider the total byte requirement, other automatic objects and recursion depth together. Several individually moderate arrays can still exceed a thread's available execution storage.

You cannot jump into the scope of a variably modified identifier from outside that scope with goto. A switch case can create related problems if control would bypass a VLA declaration. Introduce a nested block after selecting a branch, then declare and use the bounded array within that block.

A zero logical count needs a different design. Reserve a positive fixed capacity and use zero elements, or skip allocation for an empty input. The allocated practice explicitly handles zero before requesting any storage, so no zero-size allocation behavior is needed.

malloc returns a pointer to allocated storage, or a null pointer on failure. Include stdlib.h for its declaration. In C, its void-pointer result converts to the required object-pointer type without a cast. Release the successful allocation using free when it is no longer needed.

The allocated example checks whether n times the element size would exceed SIZE_MAX before multiplying. SIZE_MAX, provided here through stdint.h, is the maximum value of size_t. A wrapped byte count could request less storage than the following element loop expects.

The practice allocation has a cap of twenty ints, so its multiplication is already safely bounded. It still checks malloc's result. On an input failure after successful allocation, it frees the memory before returning an error. Cleanup belongs to every path that owns the allocation.

Allocated storage is not automatically resized either. A later reallocation can request another size, but that operation has its own ownership and failure rules. Continue to malloc and calloc and realloc and free before building a growing collection.

A runtime row type preserves matrix structure

A parameter such as int matrix[rows][columns] adjusts to a pointer to a row with columns ints. It lets matrix[r][c] use the supplied physical row width. The function must receive a compatible actual object with enough rows and columns.

This is not the same as int double pointer. A pointer-to-pointer interface usually describes a different representation, often a collection of separately managed row pointers. Mixing these representations without a correct conversion design leads to invalid accesses.

An array parameter's row count is still a contract. Writing it in the brackets does not add automatic bounds checks. The helper uses the explicit rows argument as its traversal limit. The caller must ensure that the storage actually covers that range.

A library that supports many compilers can offer a fixed-width interface, a flat buffer with explicit stride, or allocated row storage instead. Which design is clearest depends on required portability, shapes and ownership. Do not choose a VLA interface solely to shorten one declaration.

Do not confuse validation with recovery

Checking n after declaring values[n]

The size has already been evaluated. Move every bound check before the declaration. A later if statement cannot repair an invalid object declaration or an exhausted execution stack.

Expecting a changed n to enlarge storage

The array retains its established extent. Keep the original size if later code changes the input variable. A loop using the new larger value can run beyond the original object.

Assuming const makes a fixed C17 bound

C's integer constant expression rules differ from some other languages. Use an enum or another actual constant expression when fixed storage is intended. Do not classify a declaration solely by whether its value looks predictable to a human.

Forgetting cleanup in an allocation fallback

Replacing a VLA with malloc changes ownership rules. Every successful allocation needs a release when its work ends. Input-error exits are easy paths to miss, so inspect them alongside the normal return.

Make the portability decision visible

Use a small documented size cap before automatic storage is requested. Prefer a fixed-capacity array when the cap is already tiny and unused capacity is acceptable. Keep VLA declarations in a narrow block whose exit clearly ends all uses.

Compile and run the fixed fallback as well as the VLA branch when claiming both paths work. Review row widths on each branch independently. A shared logical shape does not mean their physical fixed and variable row types are interchangeable.

C99, C11, C17 and C23 differ

C99 introduced VLAs as a required feature. C11 and C17 permit an implementation to define __STDC_NO_VLA__ as 1 and omit VLA and variably modified type support. In C23, that opt-out concerns automatic-duration VLA objects; support for variably modified types and allocated-storage use is required. These programs select a C17-compatible fixed fallback when the macro advertises no support.

Runtime extents require bounded decisions

A VLA uses validated positive runtime bounds and retains its extent for its lifetime. Portability and execution-storage limits can favor fixed or allocated alternatives. The next module begins with Introduction to Strings, where character arrays need room for a terminating zero.
