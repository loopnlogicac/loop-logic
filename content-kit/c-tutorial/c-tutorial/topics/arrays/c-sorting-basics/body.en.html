Build order through a repeated small step

A sorted mark list makes rankings and later binary searches easier. A sorting algorithm rearranges elements according to an ordering rule while preserving their occurrences. Ascending integer order means each value is no greater than the next.

Bubble, selection and insertion sort use different small steps. Bubble exchanges adjacent mistakes. Selection chooses the next smallest value. Insertion places a new key into an already sorted prefix. Each method is easier to understand when you trace its outer passes.

The same final list does not mean the methods do the same work. They move different elements and behave differently on nearly sorted data. Their treatment of equal keys also matters when each key belongs to a larger record.

Use the same array interface for three algorithms

void bubble(int values[], int count);
void selection(int values[], int count);
void insertion(int values[], int count);

Each helper changes the caller's elements in place. The count is the used length, not the reserved capacity. A length of zero or one already needs no sorting. All three helpers leave every occurrence present, including repeated values.

In-place here means O(1) extra working storage beyond the input array. Each implementation uses counters and a temporary or saved key. It does not allocate another list as large as the input.

Trace bubble, selection and insertion separately

Bubble sort scans neighboring pairs from left to right. When a pair is out of order, it swaps them. The largest value in the unsorted region reaches its right edge. The next pass can therefore stop one position earlier.

The changed flag records whether a pass made a swap. If none occurred, all adjacent pairs in the remaining region were already ordered. Combined with the fixed suffix, the complete list is sorted. This gives the optimized version a fast best case.

Selection sort scans the unsorted suffix to find its minimum. It swaps that selected value into the suffix's first position. The sorted prefix grows by one entry. The scan must finish before the swap so it truly selects the minimum of the entire remaining region.

Insertion sort begins with a one-element sorted prefix. Save the next key, shift larger prefix elements right, and place the key into the gap. The prefix remains sorted and grows by one. Saving the key is necessary because shifting can overwrite its original slot.

Each algorithm has an invariant. Bubble preserves a sorted final suffix of largest values. Selection preserves a sorted prefix of smallest values. Insertion preserves a sorted prefix containing the elements already processed. State the appropriate invariant when explaining a pass.

Stable means that equal keys retain their original relative order. Imagine two students with the same mark but different roll numbers. A stable mark sort preserves their previous roll order. Equal plain ints look identical, so labeled records make stability visible.

The shown bubble and insertion sorts move values only for a strict greater-than comparison. They do not move an equal earlier value past an equal later value. The selection swap can do so: sorting 2A, 2B, 1 swaps 1 with 2A and leaves 1, 2B, 2A.

Selection makes n times n-minus-one divided by two key comparisons in its full scans. Bubble and insertion have similar quadratic worst-case growth. Insertion is often useful for a short or nearly sorted range because it shifts only entries that need to move past the current key.

For general larger arrays, consider the standard qsort interface rather than choosing a quadratic elementary sort by habit. C does not require qsort to implement quicksort, promise stability or provide a specific complexity bound. Evaluate the library implementation and requirements when those properties matter.

A comparator must define a consistent order

A qsort comparator returns a negative value when the first element should precede the second, zero when equivalent, and a positive value otherwise. The magnitude is irrelevant. The comparison must remain consistent throughout the sort.

For ints, returning left minus right can overflow for extreme values. The example instead subtracts two boolean comparison results, each zero or one. Its result is safely minus one, zero or one. It also avoids assuming that only small classroom input will ever reach that comparator.

The insertion loop tests position greater than zero before reading position minus one. Short-circuit evaluation protects that access. The final key write must happen after shifting finishes. If it remains inside the loop, some no-shift inputs never receive their intended insertion step.

A duplicate-removal task changes the number of reported occurrences after sorting. Sorting itself must not discard duplicates. Keep those two operations separate so a missing occurrence cannot be mistaken for a successful sort.

Preserve the value being moved

Forgetting the saved insertion key

Right shifts overwrite slots, including the key's original location. Store the key first and write it into the final gap. A trace should distinguish that saved variable from the temporarily duplicated array entries.

Resetting the selection minimum incorrectly

At each outer start, set smallest to that start index. Reusing the previous pass's index can select an element outside the unsorted suffix. Compare values through the saved index, not the index numbers themselves.

Failing to reset the bubble flag

changed describes one pass. Set it to zero at the beginning of each pass, then set it when a swap happens. A stale true flag loses the early-exit benefit.

Check order and preserved occurrences

After sorting, check that adjacent entries are nondecreasing. Also verify that every original value occurs the same number of times. A program that replaces all elements with zero may pass an order check but is not a sort.

Include empty, one-element, sorted, reverse-sorted and repeated-value cases. Count shifts or comparisons only when the task defines exactly which operations count. A swap consists of several assignments and should not be confused with one insertion shift.

Standard library and algorithm choices

qsort is available in the C standard library through stdlib.h. The shown comparator and elementary loops follow C17. Stability and time guarantees belong to the chosen algorithm or implementation, not to the existence of an array type.
