Keep related values under one name

Suppose you need the marks of forty students. Forty separately named variables would make input, totals and updates difficult to write. An array stores several values of one element type under a single name. An index selects which element you want.

Think of numbered lockers arranged in a row. Each locker has its own position, and every locker stores the same kind of item. In C, the numbering starts at zero. A four-element array therefore has positions zero, one, two and three.

Arrays combine naturally with loops. A counter selects an element during each repetition. You can change one element directly or visit every element in order. The type and declared size describe the available storage; the loop decides which elements to use.

Choose a size and initializer

int marks[4] = {65, 72, 81, 59};
int rolls[] = {11, 15, 23};
int totals[4] = {0};
int selected[4] = {[2] = 7};

The first declaration reserves four int elements and gives every element a value. In the second, the initializer determines a size of three. The third initializes every element to zero, not only the first. The fourth uses a designated initializer to place seven specifically at index two.

An initializer that supplies fewer values than the array size initializes the remaining elements to zero. This rule also applies to an automatic local array when it has an initializer. An automatic array declared without any initializer instead has indeterminate element values, which must not be read as useful numbers.

The expression marks[1] accesses the second element. It can be read in a calculation or written with an assignment. Changing marks[1] does not shift other elements or change the array's size.

Match positions to consecutive elements

index       0       1       2       3
marks    [ 65 ]  [ 72 ]  [ 81 ]  [ 59 ]
                   |
marks[1] = 75      v
marks    [ 65 ]  [ 75 ]  [ 81 ]  [ 59 ]

Elements are stored consecutively, with no gaps between complete elements. The address of element i is the array's start plus i element widths. The width is sizeof the element type. It is not always four bytes merely because the type is int.

A loop that visits this array uses i less than four. The last valid index is three. Using i less than or equal to four would attempt a fifth access. The size counts elements, while the last index is one less than that count.

For an actual array in the current scope, sizeof marks / sizeof marks[0] gives its element count. Both sizes use the same byte unit, so the quotient is independent of the host's int width. The result type of sizeof is size_t, printed with %zu.

C does not check each index for you

An index outside the array is a programming error. C does not automatically reject it with a neat bounds message. Reading or writing outside the valid element range has undefined behavior. The program may crash, corrupt another object or appear to work during one run.

An index equal to the count is already outside the elements. A negative index is also invalid for the simple whole-array accesses here. Validate user-supplied indices before using them, and keep loop bounds tied to the known length.

A fixed-size array has a positive element count in standard C. A zero logical input count is still useful: reserve positive capacity, keep n equal to zero and skip all element accesses. This is different from declaring a standard zero-length array.

A one-element array has both first and last element at index zero. The endpoint practice uses that case to test the last-index rule. An empty range, however, has no first element; do not read values[0] before checking whether the range is nonempty.

Ordinary arrays cannot be assigned wholesale with a = b;. Use a loop to copy corresponding elements. Their size also does not grow automatically when you write beyond the end. Later topics introduce allocated arrays when runtime growth is needed.

Separate an element count from an index

Starting a full traversal at one

A loop starting at one skips the first element. If it also visits the declared size, it reads past the end. Start at zero and stop before the element count for a complete traversal.

Assuming every local array starts at zero

Only the relevant initialization rules supply zero values. Write an initializer or assign each automatic element before reading it. A previous successful run does not establish an initial value for another execution.

Using a value as though it were a valid position

An array element might contain 80, but that does not make index 80 valid. Position and content are separate. Frequency tables use contents as indices only after limiting their value domain.

Keep capacity and used length visible

Use a clear positive capacity and validate the number of elements before input. The practice tasks reserve at most twenty elements, then visit only the first n. Input errors should stop before any uninitialized element is used.

Choose names for the data meaning, such as marks, rolls or readings. Use size calculations while the actual array is visible. Pass an explicit length when giving its elements to a helper, rather than expecting a helper to discover it.

Initializers across standards

Fixed arrays and partial initialization are available in C89. C99 adds designated initializers and the %zu conversion for size_t. The examples use C17. An empty initializer for an ordinary array is a newer C23 feature, so {0} is used here.

Use an index within a known range

An array groups same-type elements in consecutive storage, with indices beginning at zero. Initialization, logical length and bounds determine which reads are safe. Continue with Array Operations to calculate totals and move values within that storage.
