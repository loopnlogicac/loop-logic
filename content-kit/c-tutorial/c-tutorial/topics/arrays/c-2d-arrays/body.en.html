Use two coordinates for a table

A class result sheet has rows for students and columns for assessments. One position needs both a row number and a column number. A two-dimensional array stores this rectangular arrangement as an array whose elements are themselves row arrays.

In int matrix[2][3], there are two rows and three columns. The expression matrix[1][2] selects the second row and third column. Both coordinates start at zero. Neither coordinate is a count of all earlier entries by itself.

Matrices are useful for images, grids, attendance tables and mathematical calculations. Their shape determines which operations make sense. Addition needs equal shapes; multiplication has a different compatibility rule. Writing the dimensions before the loops helps prevent confusing these operations.

Declare rows outside, columns inside

int matrix[2][3] = {
    {1, 2, 3},
    {4, 5, 6}
};
int value = matrix[1][2];

The first bound counts rows and the second counts entries per row. The nested braces show that structure. The selected value above is six. An omitted element in an aggregate initializer becomes zero, following the same rule as a one-dimensional array.

A row loop normally surrounds a column loop. For each row, the column counter starts again at zero. This structure also makes printing easy: print entries inside the inner loop and one newline after that loop finishes.

Read the row-major layout

Row-major order means that one complete row precedes the next complete row in memory. For a two-by-three matrix, the conceptual element sequence is 1, 2, 3, 4, 5, 6. Advancing one column moves one int; advancing one row moves three ints.

coordinates: [0][0] [0][1] [0][2] | [1][0] [1][1] [1][2]
values:         1      2      3  |    4      5      6
element offset = row * column_count + column

The offset formula counts elements, not bytes. Multiply by sizeof the element type only when calculating a byte offset. It also explains why helpers need a physical row width when accepting a two-dimensional array.

Each subscript must respect its own row or column bound. Writing matrix[0][3] is outside row zero, even if another row follows in storage. Use matrix[1][0] for the first element of the next row. Contiguous layout does not legalize an out-of-range row subscript.

The diagonal example reports separate sums and their union. Each separate diagonal includes the center. If the requested total means entries belonging to either diagonal, subtract the center once for an odd-sized square.

Addition and multiplication use different rules

Addition pairs corresponding coordinates. For every row r and column c, the result is a[r][c] plus b[r][c]. Both input matrices must have exactly the same dimensions. The work is O(rows times columns).

For multiplication, suppose A has r rows and k columns. B must have k rows, and it may have c columns. The product then has r rows and c columns. Each output entry combines one row of A with one column of B.

For the first product cell in the example, the calculation is 1 times 7 plus 2 times 9 plus 3 times 11. That gives 58. The inner k loop advances across the left row and down the right column. Reset the output accumulator before starting a different cell.

The multiplication work is O(r*k*c). Multiplying the corresponding coordinates is an elementwise operation, not matrix multiplication. A square example can hide this shape difference, so first trace the rectangular example where the inner dimension is three and the output width is two.

Transpose and diagonals have their own bounds

Transposition exchanges row and column coordinates. Its output shape is columns by rows. A loop that prints the transpose therefore has the original column count as its outer bound. Reusing the original row bound can omit entries or read invalid positions.

A primary diagonal uses [i][i]. A secondary diagonal in an n-by-n square uses [i][n-1-i]. The secondary column decreases while the row increases. For n equal to one, both diagonals select the same single entry.

The practice matrices limit dimensions to four and values to minus ten through ten. A product cell then adds at most four products with magnitudes at most one hundred. These bounds keep int arithmetic safe. Larger dimensions and values need a separate range analysis.

An identity matrix has ones on its primary diagonal and zeros elsewhere. Multiplying a matrix by a compatible identity should preserve its entries. This gives a useful independent check for the multiplication task, alongside one-cell and all-zero inputs.

Name every loop coordinate

Swapping row and column input limits

A two-by-three array needs row less than two and column less than three. Square matrices can conceal a swapped bound. Include a rectangular input when checking a traversal.

Leaving a product accumulator uninitialized

Adding products to an indeterminate local produces an invalid result. Initialize each output cell to zero, or declare a fresh zero sum inside the column loop. Do not carry the preceding cell's total into the next one.

Counting the shared center twice

Two diagonal sums are individually correct even when they share a center. The error occurs only when their sum is treated as a union total. Read whether the problem wants two sums or one set of diagonal entries.

Write shapes beside an operation

Before matrix multiplication, write A as r by k, B as k by c, and the result as r by c. Each loop then has a natural bound. For transposition, explicitly reverse the destination dimensions.

Use row and column names rather than unrelated counters while learning. Keep a clear newline boundary in matrix output. Validate input shape before using it as a logical range within fixed-capacity storage.

Nested arrays have a stable layout

Fixed rectangular arrays and row-major nested-array layout are longstanding C features. These examples use C17 and C99 loop declarations. Runtime-dependent row widths involve VLA-related rules, covered separately in the final arrays lesson.
