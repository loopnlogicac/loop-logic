Choose access before touching existing records

You want to add today’s attendance to yesterday’s log. Opening that log with the wrong mode can erase yesterday before you write anything. A file mode tells fopen whether you need reading, replacement, appending or a combination. Choose it from the task, not from a memorised example.

A mode is a short string, but its effects are substantial. Reading an absent file should normally fail. Creating a fresh report may deliberately replace an old report. Extending a journal should retain earlier entries. Those three jobs should not share one careless opening line.

Decide whether a missing file is acceptable. Then decide whether existing bytes must survive. Finally decide whether new output belongs at a selected position or always at the end. These questions lead directly to the mode table.

Truncate means discard the old contents. A successful w or w+ open performs that action even if the next statement returns without writing. The plus sign adds the other transfer direction. It does not mean preserve, append, or automatically synchronise every operation.

Add b for binary stream handling, as in rb, wb or r+b. The plus and b markers can appear in either order, such as rb+ or r+b. Keep ordinary mode strings clear and conventional. Extra letters are not a portable way to invent permissions or locking.

Separate mode effects from stream position

Replacement and overwriting are different

Replacement mode removes the previous content at open time. An update write at an existing position instead replaces the characters it covers. If an existing line is ABC and you write X at its beginning through r+, the later BC remains. This is not insertion: later characters do not automatically move right.

The third example reads A, returns to the beginning, writes X, and returns again before reading. Its result XBC demonstrates the preserved suffix. A longer replacement could overwrite more characters or extend the file. Designing variable-length record edits needs more than choosing r+.

Append describes every output operation

In append mode, writes are forced to the current end of file. That remains true after a positioning operation. fseek requests a stream position; in the second example it requests the beginning. The following output still appends 34 after 12. The append promise overrides that attempted overwrite location.

For a+ reading, explicitly select the place you intend to read. Do not depend on an assumed initial read position across implementations. The fourth example seeks to the beginning after its output, then reads the first line. Full positioning rules appear in file positioning.

Text and binary describe transfer rules

A text stream can translate between the program’s characters and the external text representation. Newline handling is a familiar example. A binary stream avoids those text translations under the implementation’s binary I/O model. On some systems the visible difference is small; on others it matters immediately.

Binary mode does not reverse bytes, compress records or select a fixed integer width. It also does not make structure dumps universally portable. The mode chooses stream handling. A portable file format must separately define what its bytes mean.

Closing ends the resource lifetime

After a successful open, fclose flushes pending output as needed and closes the stream. Zero reports success; EOF reports failure. Check that result when successful delivery matters. Do not retry fclose on the same invalidated pointer, even when its first close reports an error.

Save both the transfer result and the close result. If you combine them carelessly with short-circuit evaluation, a failed write may skip cleanup. The examples compute written or ok first, then call fclose separately. This ensures the close attempt happens after a valid open.

Respect update-stream direction changes

An update stream permits both input and output. It does not allow arbitrary alternation with no intervening action. The library may still have buffered data or position state associated with the previous direction. C therefore states a rule for each transition.

After output, perform fflush or a positioning operation before input. After input, perform a positioning operation before output, unless that input encountered end-of-file. Notice the asymmetry: a flush alone is not the general input-to-output solution.

The positioned patch example uses fseek between both transitions. Each request chooses offset zero from the beginning and checks whether it succeeded. That both establishes the intended edit location and supplies the required sequencing. A seek is useful only when the stream supports the requested positioning.

Do not call fflush(stdin) to discard unread keyboard input. That is not a portable input-cleaning operation in ISO C. If you need to consume remaining input, read and handle it deliberately. Stream direction rules and input validation are separate concerns.

Protect old data and valid handles

Using w because it opened successfully before

A previous experiment with a scratch file says nothing about the intended policy for an attendance log. Write the preservation requirement beside the open. Inspect the table before running a new write experiment. Use expendable teaching names until replacement and append effects are clear.

Using a NULL or already closed stream

Failure to open does not supply a usable FILE object. After closing, the old pointer is not valid for more stream operations. Reopening returns a new handle that must be checked again. Assigning NULL to a local variable can help prevent accidental reuse, but it does not fix aliases elsewhere.

Assuming plus means automatic insertion

r+ does not shift the suffix to make room for new text. Editing a longer name over a shorter field can overwrite the following record. For variable-length text records, rewriting a validated new file is often clearer than patching arbitrary character positions. Keep the original safe until the replacement has succeeded.

Ignoring a late output failure

An earlier fputs can report success while output remains buffered. fclose may discover delivery failure. Return a failure result to the caller instead of claiming that a log entry was saved. Also preserve the first useful error information when later cleanup could change library error state.

Keep portable modes separate from extensions

The six modes, binary marker and update sequencing rules used here are supported by C17. C11 added an exclusive-create x option for appropriate w modes. Platform-specific mode letters and sharing flags need their own documentation. An append stream alone is not a portable multi-process transaction protocol.

Match preservation, position and direction to the task

r inspects, w replaces, and a appends. Plus permits both directions while keeping the base mode’s creation and truncation effects. Check open and close, sequence update operations, and select binary handling deliberately. Next, move actual records with text reading and writing.
