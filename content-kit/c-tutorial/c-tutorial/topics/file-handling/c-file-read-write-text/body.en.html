Choose what one read should mean

A club file might contain one mark pair per record, a sentence with spaces, or a short message to copy. These are all text, but they do not ask for the same reading operation. Choose between formatted fields, complete line fragments and individual characters according to what the data means.

Imagine reading a notice aloud. Sometimes you want the whole sentence. Sometimes you want only a number written inside it. Sometimes you want to inspect every punctuation mark. C’s text I/O functions offer corresponding levels of control.

Writing has similar choices. fprintf formats values, fputs writes an existing string, and fputc writes one character. Pair the chosen operation with its success test. A loop should use data only after the operation that produced it succeeded.

char line[64];

    if (fputs(line, output) == EOF) {
        break;
    }
}

The streams must already be valid. The character functions use EOF to report failure or completion. fgets instead returns NULL when it produces no line fragment. These different return conventions are a reason to read the function’s interface rather than treating every result as a Boolean.

Read only values that were actually obtained

Formatted fields describe conversions

fprintf uses the familiar printf format with an explicit destination. fscanf similarly uses a scanf-style format on a selected input stream. For two integer fields, process a record only after two assignments succeed. A return of one does not make the untouched second variable a valid new mark.

Whitespace in a scanning format can consume newlines as well as spaces. That is useful for token sequences, but it does not enforce physical records. A roll on one line and a mark on the next may still satisfy two conversions. Read a line first when line identity matters to the task.

A matching failure can leave the offending input waiting. Repeating the same conversion without consuming anything may repeat the same failure forever. Stop, reject the record, or use a deliberate recovery rule. Checking feof before the read cannot predict that kind of matching failure.

Line fragments preserve useful structure

fgets reads at most one less than the supplied buffer size and adds a terminating null character. If it reads a newline, that newline stays in the string. fputs writes the string but adds no newline. This pairing can preserve spaces and existing line endings without inventing blank lines.

A full buffer is not proof that a complete line arrived. If the newline did not fit, later reads may contain more of the same record. Establish a line-length contract or implement a reject-and-drain or bounded growth policy. The small import example explicitly uses short lines.

Characters make copy decisions visible

Keep fgetc’s result in int. First compare it with EOF; only a successful character belongs in the copy. Passing that character to fputc preserves its place in the sequence. Count a copied character only after the output operation succeeds.

The copy example owns two resources. Failure to open the destination still requires closing the source. A failure inside the loop requires both close attempts. Save their outcomes separately so one failed close does not skip the other through short-circuit evaluation.

Define words and lines before counting them

A word counter needs a precise definition. Here a word is a maximal run of nonwhitespace characters. Punctuation remains part of that run. The word robot’s, for example, is not split merely because it contains an apostrophe. Different language-processing tasks may choose another rule.

Track whether you are inside a word. Whitespace puts you outside. A nonwhitespace character increments the count only when you were outside, then puts you inside. Several spaces or tabs therefore separate words without producing empty words. End-of-file requires no extra increment because starts, not endings, are counted.

Use isspace from ctype.h for the chosen whitespace classification. Its argument must be EOF or a value representable as unsigned char. The loop has already excluded EOF, so converting the returned character to unsigned char is safe. Do not pass an arbitrary negative signed-char value.

Counting newline characters is not the only possible line policy. A final fragment without a newline may count as a logical line. Remember whether any character was seen and whether the last one was a newline. Add one unfinished line only when some text exists and its final character is not a newline.

Under this policy, empty input has zero lines. A followed by a newline has one. A alone also has one logical line, but zero completed newlines. State which quantity your report presents instead of making the reader infer it from an example.

Do not accept partial records or duplicate separators

Printing a line with puts after fgets

If fgets retained the newline, puts adds another one. Use fputs for copying the existing string unchanged. If your task deliberately wants a modified line, remove or replace its ending explicitly rather than relying on two functions to cancel one another.

Counting every space as a word

A sequence with leading spaces, a tab and repeated separators can have fewer words than spaces. Count outside-to-inside transitions instead. Test empty text, whitespace-only text, a single word and a last word without a newline. These cases expose the state logic.

Using stale values after a short conversion

Initialising a mark to zero does not make a failed conversion acceptable. It only replaces one possible bug with a misleading default. Accept the record after every required field succeeds and its domain is valid. The bounded line importer also checks for a trailing token, so a correct prefix cannot hide extra data.

Treating bounded integer conversion as unlimited validation

The simple fscanf and sscanf examples use numeric tokens known to fit int. A field width limits consumed characters but does not generally prove a numeric range. For arbitrary external text, use a conversion design that detects range errors, such as checked strtol, then validate the application range. See argument conversion for that technique.

Replacing the source while copying it

Opening the destination with w can truncate existing data. If it names the same file as the source, you can destroy the input before the loop begins. The example uses distinct teaching names. Real path identity can be more complicated than comparing two strings, so design replacement workflows carefully.

Text operations do not define a universal encoding

These C17 interfaces operate on character sequences according to their stream and locale rules. A byte-oriented word counter is not a complete Unicode word segmenter. Text-mode copying can involve platform newline translations. Use a defined binary transfer when exact external bytes, rather than text characters, are the requirement.

Let successful reads drive the work

Read fields for token data, bounded lines for physical records, and characters for precise scanning. Preserve EOF in int, check output and cleanup, and define word and final-line policies. Next, use binary files to transfer blocks and examine the limits of raw structure storage.
