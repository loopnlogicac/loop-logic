Introduction

C is a general-purpose programming language used to describe work that a computer can carry out. A C program can calculate marks, read a sensor or help an operating system manage hardware. You write a text file, translate it with a compiler, and run the resulting program.

Think of a lab attendance machine: a small device receives a roll number, checks data and signals a result. C is useful when software must work with limited memory or communicate closely with hardware. The same language can also support a small terminal program on your laptop.

This course begins with small hosted programs, which run with operating-system services and a standard library. An embedded system may use a freestanding environment with different startup rules. You do not need a hardware board to learn the language rules used here.

Syntax and vocabulary

A source file contains program text, commonly with a .c suffix. A compiler translates that text into lower-level code. An executable is the finished program file that your operating system can start.

gcc -std=c17 -Wall -Wextra lab.c -o lab
./lab

A function is a named unit of work; a call asks it to run. The printf call prints the quoted message, and inside that message requests a newline. You will study this structure line by line in Your First C Program.

How it works

C separates writing a program from running it. First save the source, then compile and link it, then run the executable. A build failure means you must fix the source before a new executable is ready. An older executable may still exist, so seeing output alone does not prove your latest edit was built.

source text --> compiler toolchain --> executable --> output

The first verified example prints a message without needing input. The marks example stores two integer values, adds them and prints their total. A variable is a named object that holds a value, so names such as theory and lab help you connect the calculation to the task.

The sensor example represents a reading with an integer. This is a model of the data, not a program that reads real hardware. Keeping the data source fixed lets you predict the output while learning what compilation and execution mean.

Details and comparisons

How C developed

Dennis Ritchie developed C at Bell Labs in the early 1970s during work connected with UNIX. Rewriting much of UNIX in C helped show that an operating system could be written mostly in a higher-level language while retaining access to machine-level facilities. C followed earlier work on B and related languages.

The book commonly called K&R described an early form of C and strongly influenced practice before international standardization. K&R C and modern standard C are not interchangeable labels. Old examples may use declarations or library functions that a current course should replace.

Why C still matters

Operating-system kernels use C for much of their core code. Embedded firmware uses C for controllers with small resources, and compiler implementations use it to process other programs. C is also useful at library boundaries because many languages can call functions through a C interface.

C gives you a concrete way to learn how values, objects and memory relate. Its syntax helps when you later meet C++ or Java, but each language has its own rules. Learning C first can be valuable; it is not a requirement for understanding every other language.

C implementations can produce efficient machine code with little runtime support. Speed still depends on the algorithm, data and compiler choices. The language does not automatically check every array access, and dynamically allocated memory must be released according to ownership rules. Those responsibilities can lead to crashes or security faults if ignored.

Common mistakes

The marked mistake example is supplied for compiler diagnostics. Repair the stated cause before running it; it has no expected stdout transcript.

Expecting identical machines

A portable program follows language rules instead of assuming every machine has identical integer sizes or text encoding. Check actual limits when a task needs them. A result observed once is evidence about that run, not proof that every C implementation behaves the same way.

Treating compilation as proof

A program can compile and still use the wrong formula. Predict the marks total yourself, then compare it with the recorded run. A small edge case such as zero marks is often easier to reason about than a large random input.

Mistake: C is case-sensitive

Printf is not the declared library function printf; use the exact lowercase spelling.

Best practices

  • Learn with short, saved source files and warning-enabled builds.
  • State the task and allowed input range before choosing a formula.
  • Use meaningful names and compare predicted output with real output.
  • Treat memory safety as part of correctness from the beginning.

Version notes

The examples use C17 unless marked otherwise. Standards describe the language; compiler releases implement them over time. C23 is the edition name even though its final ISO publication followed in 2024. A compiler version number and a selected language standard are different facts.

Dynamic memory is storage a program requests while it runs. C gives the programmer responsibility for releasing such storage when its ownership ends; see Dynamic Memory Allocation.

Summary

C combines a small language core with a standard library and close control over memory. That control is useful in systems work and brings responsibilities you will learn gradually. Next, prepare a compiler and editor in Setting Up a C Environment.
