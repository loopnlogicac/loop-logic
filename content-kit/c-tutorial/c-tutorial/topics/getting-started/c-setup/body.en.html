Introduction

Think of a C workspace as a desk with three tools. An editor lets you write, a compiler builds your program, and a terminal lets you run it. Together they form your C environment. Start with a small program so you can check each tool before tackling a lab problem.

Imagine submitting a lab task from a shared computer. Your code should build from a saved file with a clear command, even if the next machine uses a different editor. A repeatable terminal build gives you that starting point.

This lesson uses C17 and warning flags. GCC is used to verify the programs below. On macOS the command named gcc often runs Apple Clang instead. Read the version output rather than assuming a command name identifies the implementation.

Syntax and vocabulary

The -o option names the generated executable, while -std=c17 selects the language dialect. The source filename and output filename serve different jobs. Keep the source as lab.c. Do not overwrite it with the executable.

gcc --version
gcc -std=c17 -Wall -Wextra -Wpedantic -Werror -O2 lab.c -o lab
./lab
Build command parts
PartPurpose
gccInvoke the compiler driver
-std=c17Select this course baseline
-Wall -Wextra -WpedanticRequest useful diagnostics
-WerrorMake enabled warnings fail the build
-O2Enable a standard optimization level
-o labName the output file

A terminal accepts commands in a current working directory. Use pwd on a Unix-like shell or Get-Location in PowerShell to see that directory. List its files and confirm that the source you edited is actually there.

How it works

On Windows, install a current MinGW-w64 GCC toolchain, for example through an MSYS2 UCRT64 environment. Use its package manager to install the matching UCRT64 GCC package, then use that environment's terminal or add its compiler bin directory to PATH. PATH is the list of directories the shell searches for executable commands.

pacman -S --needed mingw-w64-ucrt-x86_64-gcc
gcc --version

The package command belongs in the MSYS2 UCRT64 terminal, not an ordinary Ubuntu shell. In PowerShell build with the same GCC options but name the output lab.exe, then run .\lab.exe. Avoid mixing several unrelated MinGW installations, because your editor and terminal could select different compilers.

On Ubuntu, install the distribution build tools from a terminal. On macOS, request the Xcode Command Line Tools and finish the operating-system installer before testing the compiler. These installation commands configure your computer. They are not C source and do not belong in a .c file.

sudo apt update
sudo apt install build-essential
xcode-select --install

Use the two apt commands on Ubuntu and the xcode-select command on macOS. After installation, run the compiler version command and compile the first example. A successful run should show the exact message recorded beside its source.

A macro substitutes source tokens before ordinary compilation. The language-mode example uses a predefined macro to inspect the selected standard. See Predefined Macros.

Details and comparisons

Choose and configure an editor

Code::Blocks is an integrated development environment: an editor with project and build controls. Select a GCC toolchain in its compiler settings and check the detected executable path. Some Windows distributions bundle a compiler and others do not, so inspect the installed tools instead of relying on the editor name.

For VS Code, install C/C++ language support and separately install a compiler. Set the compiler path used for language analysis, and configure a build task that invokes the same command you tested in the terminal. Language highlighting and completion do not prove that a compiler is installed or that a build task is correct.

Build the unchanged smoke-test program first. Then change Build works to Build 2, save, rebuild and run again. This small controlled edit proves that your build task uses the expected file and that you are launching the new executable.

Online compilers as a temporary workspace

Programiz and OnlineGDB can help you try a single-file program without installing tools. Select C, inspect available standard settings, paste the complete source and put input in the provided stdin field. A browser text box for input is different from typing into a live terminal.

Online services may restrict running time, files, compiler options or interactive input. Their compiler versions may differ from your laptop, and a saved browser session is not a reliable backup of coursework. Download or copy your source into your own files after experimenting.

The language-mode example prints the standard-version macro, a predefined number supplied by the compiler. A macro substitutes text before ordinary compilation. The full mechanism is covered in The C Preprocessor. In C17 mode this number is 201710L, regardless of whether GCC itself is version 13 or 14.

Try a small change

For a useful setup check, choose an input you will recognize immediately, such as roll 42. scanf reads that roll; &roll tells it where the variable is. An if block handles a failed read. Try the terminal build first, then the editor button.

Change the printed label and repeat both runs. If only one run shows your change, the two tools are using different source or executable paths. Copy the build command from the editor log and compare those paths. Reinstalling the editor is rarely the first useful step.

Common mistakes

Building from the wrong folder

A cannot-open-source message often means the terminal cannot find the file, rather than a C syntax failure. Check the current directory, filename suffix and spelling. An editor may silently save a file as lab.c.txt if extensions are hidden.

Running an old executable

A failed build may leave the previous executable untouched. Read the build status before running, and verify a deliberate message change. Do not repair this by editing an printed result. Fix and rebuild the source.

Mistake: a missing closing quote

The source does not contain a closed string literal. Fix the quote before trying to run.

Best practices

  • Record the compiler version used for your lab work.
  • Keep one tested terminal build command alongside your editor workflow.
  • Use a separate folder for each exercise and save before building.
  • Investigate warnings rather than hiding them with weaker flags.

Version notes

Selecting -std=c17 makes these examples follow the same baseline across current GCC installations. C23-only examples use -std=c2x in GCC. Toolchain support varies, so a newer language edition may need a newer compiler even when the editor works normally.

Summary

A working environment turns a saved source file into a fresh executable through an explicit build command. Confirm the version, source path and output path before adding editor shortcuts. Next, understand each source line in Your First C Program.
