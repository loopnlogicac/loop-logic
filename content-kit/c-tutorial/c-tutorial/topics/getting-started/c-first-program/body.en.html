Introduction

A Hello World program is a small complete program that prints a known message. Its purpose is to prove that editing, compilation and execution work together. Because the required output is short, you can focus on the job of each line.

Use the first verified example as a whole source file. Copying only the printf statement into an empty file is not enough: a hosted C program also needs an entry function. Save the file before building, then compare its output with the displayed result.

A program is precise instructions expressed through grammar. Case, quotes, parentheses and semicolons all have roles. Treating punctuation as meaningful makes first-day errors easier to repair than trying random edits until compilation succeeds.

A header provides declarations shared with your source. A declaration tells the compiler about a name and its type. Including stdio.h is how this program learns the correct printf interface; you do not need to write the library implementation yourself.

How it works

The Hello World program begins execution at main in the hosted environment. The printf call writes the string to standard output, normally the terminal. The return statement then ends main and provides a status to the environment that launched the program.

The word int describes the return type of main. The word void between the parentheses means this form of main takes no parameters. A parameter is an input declared by a function; later lessons explain how your own functions receive values.

The quoted text is a string literal, a sequence of characters represented in the source. Inside it, the two source characters backslash and n form an escape sequence that requests one newline character. They do not print as the visible letters backslash and n.

Before any of those runtime steps, the compiler checks the saved source and the linker connects the required library code. The include directive is processed during the build; it is not a statement executed every time the program starts. This distinction helps explain why a missing header causes a build problem rather than extra output.

Details and comparisons

Calls and output lines are different things

One output line does not have to come from one printf call. The second example writes Lab with a following space, then writes ready and a newline. The terminal shows a single line because only the second call ends it.

One printf call can also produce several output lines. The marks-card example includes two newline escapes within a single string. Count the escapes and locate them before predicting the result, rather than counting source lines.

Source whitespace and output whitespace have different roles. An empty source line between statements improves readability and does not appear in the result. A space inside the quoted string becomes output, so moving that space outside the quotes changes the message.

A return value is not printed text

Returning zero from main reports success to the host. To see a digit zero in the output, you would need an output call containing it. This is why the real Hello World transcript contains the message but no extra zero at the end.

The operating system's shell can inspect a completed program's status. That status is separate from stdout, the byte stream captured in each output file. Later programs can use nonzero status to report an input failure without confusing it with a normal numeric result.

Every example here includes return 0 explicitly, even though reaching the end of main has a success-return rule in C99 and later. Writing the statement makes the intended end visible while you are learning. The same rule must not be assumed for every other non-void function.

Common mistakes

The marked mistake example is supplied for compiler diagnostics. Repair the stated cause before running it; it has no expected stdout transcript.

Using the wrong quotes

Use straight double quotes for a string. Curved quotes pasted from a document are different source characters, and single quotes describe character constants rather than an ordinary text string. Replace the delimiters directly in the source editor.

Changing the case of a name

printf, Printf and PRINTF are different identifiers. The standard header declares the lowercase name. Fix the call spelling instead of adding a second declaration to hide the symptom.

Reading the next line as the cause

A missing semicolon can make the compiler complain at the following statement. Inspect the previous line as well as the reported location, then rebuild after one correction. Extra braces rarely fix a missing statement terminator.

Mistake: a missing semicolon

The call is an expression statement and needs a semicolon after the closing parenthesis.

Best practices

  • Start from a complete verified file, then change one message at a time.
  • Read the first compiler diagnostic before later follow-on messages.
  • Keep braces on clear lines and indent statements by four spaces.
  • End a finished output line with a newline.
  • Compare both spelling and punctuation in the result.

Version notes

The hosted main form int main(void) works in all the course's language modes. C99 and later define reaching the end of main as returning zero. C17 remains the build baseline here; do not replace main's int return type with void based on old compiler-specific examples.

Summary

Hello World connects a header declaration, an entry function, an output call and a success return. Each part has a separate role, and output lines depend on characters inside the string. Next, place these pieces in a larger file in Structure of a C Program.
