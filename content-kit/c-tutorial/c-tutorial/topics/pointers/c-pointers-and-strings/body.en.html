Pointers and Strings

A string pointer can select a complete label or begin partway through one. That makes it useful for parsing course codes and room descriptions. The pointer supplies a starting address; the string's zero terminator supplies the stopping point.

There is a crucial storage choice behind this convenience. A writable character array owns characters you may edit. A pointer to a string literal selects text you must leave unchanged. Similar-looking declarations can therefore have very different write permissions.

Think of an editable notebook page and a printed reference card. Both can be read, but changing the notebook does not imply you may write on the reference card. Choose storage according to whether your operation reads or modifies text.

Declarations and call rules

The declaration char text[] = "Lab" creates a four-element array containing a copy of the characters and zero. Its elements are writable. The declaration const char *view = "Lab" creates a pointer selecting a literal with static storage duration.

C17 also accepts char *view = "Lab", but writing the literal through that pointer is undefined. The non-const declaration does not grant permission to modify literal storage. Prefer const char * so accidental writes receive a compiler diagnostic.

A character pointer can be redirected to another compatible target. An array cannot be redirected by assignment. view = "Office" selects another literal; text = "Office" is invalid for an array. Copying new text into an array requires enough capacity.

Pointer arithmetic creates suffix views. If text holds CSE212, then text+3 selects the first digit. The substring remains terminated by the original final zero. No allocation or copying happens when that suffix pointer is formed.

const char *view = "Lab";
char *suffix = editable + 1;

Follow the storage and operations

The first example changes the first element of editable from L to M. Its output becomes Mab while view still selects Lab. These are separate storage objects; their matching initial text does not create an automatic shared editable buffer.

The room example searches Lab-204 for a hyphen using strchr. If found, the returned pointer selects the dash inside the writable room array. Incrementing that pointer selects the following digit. Changing its first character changes room itself because both access paths share those bytes.

Printing the full room and the suffix afterward shows Lab-304 and 304. The suffix has no independent lifetime or capacity. It remains usable only while the containing array is alive and its required zero remains within bounds.

A pointer walk tests *p != '\0', reads the current character, then advances. The final test reads the terminator, which is a real array element. It stops before stepping farther. A string without a valid terminator cannot support this walk safely.

The pointer does not retain the array capacity. sizeof p is a pointer size even if p began at a large buffer. For a suffix, the usable remaining capacity also depends on the offset. A writing helper needs that remaining bound, not the full original capacity.

The length of text+3 for CSE212 is three. strlen starts from the address it receives and stops at the next zero. It has no knowledge of preceding characters, the original name text, or unused writable storage after the terminator.

Choose the right behavior

Library string functions work with pointer arguments because strings are accessed through their first characters. strcpy receives a writable destination pointer and a readable source pointer. The caller must still prove that the destination range fits the complete copy and does not overlap the source.

A pointer returned by strchr or strstr often borrows storage from the searched string. It does not own a new allocation. Do not free that pointer merely because a search returned it. Free is for a valid allocated-block owner, introduced fully in the dynamic-memory module.

A failed search returns NULL. Before advancing or printing a result, check that it is non-null. For a final hyphen, result+1 selects the existing terminator and represents a valid empty suffix. That case differs from a missing hyphen.

The expression *p++ reads the current character and then advances p, because postfix increment binds before unary star. (*p)++ instead increments the character value. Spell the operations on separate lines until their roles are clear; compactness can hide whether text or selection changes.

A literal has static storage duration, so its characters remain available for the program's lifetime. That duration does not make it writable. A local array is writable but expires when its block ends. Mutability and lifetime are independent questions.

Two identical literals may share storage, or they may occupy different storage. Comparing their pointers is not a reliable way to compare their text. Use strcmp when the desired question is whether character sequences match. The implementation's literal-sharing choices should not affect the algorithm.

These examples select ASCII byte offsets. An offset into the middle of a UTF-8 sequence may no longer start a valid encoded character. For user-facing Bangla text, a byte suffix operation needs an encoding-aware boundary policy rather than a guessed letter index.

Removing a prefix illustrates another ownership distinction. Advancing a pointer past the first three characters leaves the original array unchanged. Moving the remaining characters to index zero changes the array contents and may require overlap-aware copying. Both can display the same suffix while doing different work.

For read-only parsing, a borrowed suffix is often enough and avoids a copy. For storing an independent field, a separate destination is safer when the source buffer will be reused for the next input line. A saved pointer into that reused buffer would observe its new contents.

A search within a const string should preserve read-only intent in your own result variable. Even where a C library declaration returns char *, the original storage may still be a literal. Access permissions follow the actual target, not the apparent mutability of a returned pointer type.

Mistakes and repairs

Writing a literal is undefined even if a test appears to work on one compiler. A cast that removes const does not change the underlying storage permissions. Allocate or declare a writable copy before editing.

Changing a terminator can expose bytes that earlier string operations ignored. Ensure another zero exists within capacity before treating the result as a string. Replacing a zero with a letter does not automatically extend the buffer safely.

A suffix view does not copy characters. If you need an independent result that survives later edits to the original, copy into separately owned storage with a capacity check. State which result kind your helper returns.

Do not call strlen on a possibly null search result as a way to check whether it is empty. Test for NULL first; then a zero-length string is a distinct valid result.

Working habits

Use const character pointers for borrowed read-only text. Keep writable capacity beside editing pointers. Label suffix results as borrowed views, and test the missing, final-separator and ordinary-suffix cases separately.

Standard and portability notes

C string literals must not be modified in C89 through C23, even though their array element type in C is char. These examples target C17 and use const on pointer access paths to express the intended read-only role.
