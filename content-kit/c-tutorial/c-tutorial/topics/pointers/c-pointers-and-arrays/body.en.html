Pointers and Arrays

Array indexing and pointer traversal are two ways to reach the same elements. Understanding their relationship explains why a function can change an array without receiving a complete array copy. It also prevents a common mistake: treating an array object as though it were a pointer variable.

Picture a row of marks on a desk and a movable bookmark selecting one mark. The row owns the values; the bookmark owns a location. Moving the bookmark changes the selected element while leaving the row itself where it was.

C connects these ideas through an automatic conversion in many expressions. That conversion supplies an address, while the original array retains its own type, extent and lifetime.

Declarations and call rules

For an actual array a, a[i] has the same element-access meaning as *(a+i) when the position is valid. Addition chooses a position, and the star accesses its element. The array bound still applies to either spelling.

In most ordinary expressions, an array expression converts to a pointer to its first element. This is often called array decay. Initializing int *p = a uses that conversion. No elements are copied, and no new array is allocated.

Important exceptions include an array operand of sizeof and unary address-of. sizeof a measures the whole actual array in its declaring scope. &a takes the address of the array object itself, giving a pointer-to-array type rather than a first-element pointer type.

A parameter written int values[] is adjusted to int *values. This parameter rule explains why sizeof inside that helper does not report the caller's complete array size. Send the used length separately.

int values[] = {12, 24, 36};
int *p = values;
size_t count = sizeof values / sizeof values[0];

Follow the storage and operations

For marks containing 12, 24 and 36, marks[1] and *(marks+1) both read twenty-four. The expression marks+1 selects the second int. Parentheses matter: *marks+1 instead reads the first int and adds one to its value.

A separate pointer p can advance within marks because p is a modifiable pointer object. The expression marks++ is invalid: the array name does not denote an assignable pointer variable. The conversion result is useful for arithmetic, but it does not turn the array object into mutable address storage.

Aliases still share the elements. If p equals marks and p[1]=50, then marks[1] reads fifty afterward. The index notation works with pointer operands because it is defined using pointer arithmetic and indirection. It does not prove how many elements p can access.

The full array count can be calculated as sizeof a / sizeof a[0] where a really is the array object. The numerator includes every element, and the denominator is one element's size. The result is a size_t value independent of whether int happens to occupy two, four or another number of bytes.

With int *p, sizeof p measures only the pointer object. Dividing that by sizeof p[0] produces a ratio of unrelated object sizes, not an array length. Sometimes that ratio accidentally matches a small example's count; accidental agreement does not validate the method.

A pointer parameter cannot recover an arbitrary caller extent. Two callers may pass arrays of different lengths through the same pointer type. The helper therefore needs a count or a deliberate stopping convention, such as a string terminator. Ordinary integer arrays do not automatically carry a sentinel.

Choose the right behavior

The sum helper accepts a read-only pointer and a count. The caller computes four from its actual array and passes both arguments. The helper walks precisely four elements. A count of zero can describe no work, provided the interface avoids invalid arithmetic or dereferences for that case.

A useful loop keeps begin and end pointers for a live array. Stop at end before reading, and advance one element per iteration. The array and pointer version have the same O(n) traversal cost. Choose whichever spelling makes the range clearest for the task.

For int a[5], a after conversion has type int *. The expression &a has type int (*)[5], a pointer to a complete five-int array. They begin at the same underlying array location but carry different target types. Adding one therefore means one int for the first and one entire array for the second.

A two-dimensional matrix decays to a pointer to its first row, preserving the row's width. It does not decay to int ** because its intermediate objects are arrays, not stored pointer values. Later lessons compare real pointer tables with fixed-width row pointers.

The size-inspection example intentionally prints implementation-dependent values. On the recorded compiler platform those values describe the actual array, pointer and int element. The teaching rule is their role, not a claimed universal size. The deterministic element-count example remains portable.

When passing a slice, its starting address alone does not prove that a later index is within the original object. Track the slice's usable count. Pointer notation removes neither bounds obligations nor lifetime obligations. A helper must finish using a caller array while that array remains alive.

A pointer can select an interior element, so index zero is relative to that selected position. If p equals a+1, p[0] is a[1] and p[1] is a[2]. The original array's lifetime and remaining extent still control those accesses. The local zero-based view does not create an independent smaller array object.

For a caller-owned result array, a helper can fill elements through a pointer without returning their storage. The caller later reads the same elements under its own array name. This is often a clearer interface than returning a pointer that merely repeats the input address.

The address-of exception also explains why a and &a should not be substituted blindly in calls. A helper expecting int * needs an element pointer, while a helper expecting int (*)[N] needs a whole-row pointer of matching width. Similar printed starting addresses do not erase that type distinction.

Mistakes and repairs

Do not describe an array as a const pointer. That phrase blurs two different objects and does not explain sizeof or address-of correctly. An array owns elements; a const pointer is still a pointer object holding an address.

Adding an index to the pointed-to value instead of the pointer selects a different calculation. Read parentheses aloud: *(a+2) means select then read, while *a+2 means read then add. The output quiz distinguishes those roles.

A fixed matrix cannot be made into a pointer table by casting. Such a cast does not manufacture pointer entries between rows. Keep the declaration that matches the real storage.

The count formula belongs in the array-owning scope. Repeating it inside a pointer-taking helper is a frequent source of partially processed arrays. Receive the caller's actual used count and state it in the interface.

Incrementing an array name

An array name is not a modifiable pointer variable. Introduce int *p = a and increment p within bounds.

Working habits

Use array syntax for straightforward indexed work and pointer syntax for explicit ranges. Retain a separate count at function boundaries. Verify the complete type of each sizeof operand before using the result as a storage or element count.

Standard and portability notes

Array-to-pointer conversion and array-parameter adjustment are established C rules and remain present in C17 and C23. These examples use C99 loop declarations and size_t formatting. Newer standards do not attach array-length metadata to an ordinary pointer.
