void and NULL Pointers

Sometimes a routine needs to carry an object's address without knowing its type yet. A generic container or sorting function is a typical example. The type void * provides a generic object-pointer value, while a separate contract explains how the target may be used.

Another common situation is absence: a search finds no element or a menu has no selection. A null pointer represents that missing target. Generic type and absence are different questions; a void pointer can select a real object, and a typed int pointer can be null.

Think of an unlabelled storage location versus an empty selection. The first needs type information before use. The second has no object to use at all. Keeping those meanings separate avoids several pointer mistakes.

Declarations and call rules

An int address may be stored with void *generic = &score. In C, assignment back to a compatible object pointer is allowed without a cast: int *typed = generic. If the target is still the original live int, the converted pointer can access it.

You cannot read an int value through *generic while generic has type void *. void does not describe an object value or size. Recover an appropriate target type first. Casting to an arbitrary type does not prove that type matches the real object.

Initialize an absent typed target with int *found = NULL. Standard headers such as stddef.h and stdio.h provide NULL. Test found == NULL or use the pointer as a condition before a dereference when null is an allowed state.

C's object-pointer conversions differ from C++ rules. A C++ example might require an explicit cast from void *, but these C17 programs do not. Follow the selected language rather than adding casts merely because another language uses them.

Follow the storage and operations

The round-trip example starts with score at seventy-two. generic stores its address while hiding the target type in the pointer expression. typed restores int * access, and assigning through typed changes score to eighty. No separate score copy was created.

The generic printer accepts const void * but documents that the target is an int. Converting to const int * lets it read that int without writing through the parameter. Calling it with an unrelated double address would violate the contract even though the initial object-pointer conversion is accepted.

A generic interface often carries a tag, a callback or an element-size value alongside the address. The hard practice task uses a tag to choose between an int and a char target. The tag must describe the actual selected object. Inconsistent metadata is a program error, not something void * can repair.

The missing-search example initializes found to NULL and scans a known three-element array. No value equals five, so the pointer stays null. The final branch prints Missing without attempting to read a nonexistent element.

Null pointer values compare equal to a null pointer constant after the appropriate conversion. A zero integer constant can serve as such a constant in C. This does not mean address zero is an ordinary object selected by the pointer or that a null pointer's bytes must all be zero.

An implementation may spell NULL as a zero constant or a void-pointer form, subject to its language requirements. Do not treat NULL as an arbitrary integer for variadic printing. When printing an object pointer, provide a suitable void * argument to %p.

Choose the right behavior

A non-null pointer is not automatically valid. It might be uninitialized, point beyond an array, select incompatible storage or outlive its former target. Null checks handle an agreed absence state; they do not replace type, lifetime or range reasoning.

An uninitialized automatic pointer must not be read even to compare it against NULL. Initialize it before any branch uses its value. Similarly, after an object's lifetime ends, do not inspect stale aliases as a general validity test. Track the owner and borrowing lifetime instead.

Portable C17 does not define arithmetic on void pointers. There is no void element size to scale a step. GCC may accept byte-like stepping as an extension, but code using that extension is outside the ordinary C rules in these lessons.

For access to an object's bytes, an unsigned char pointer is the appropriate special tool, with an explicit valid byte range. For reading an int value, use an int pointer that actually selects an int object with the required alignment. A cast alone cannot create such an object.

The conversion guarantee discussed here concerns object pointers. Function pointers have their own compatibility rules and cannot be assumed to round-trip through void * portably. Keep callback fields typed as function pointers rather than placing them in generic object-address slots.

C23 adds nullptr, a dedicated null pointer constant with type nullptr_t, declared by stddef.h for the type name. It expresses the missing-pointer intention without using an ordinary integer-zero spelling. Strict C17 does not provide that keyword, so the runnable examples use NULL.

Even with nullptr, dereferencing a null pointer is undefined. A newer null constant improves expression of the state; it does not create a target or add runtime validation. Keep the same branch-before-access logic.

A nullable parameter should document what absence means. For an optional result, NULL may mean skip that output. For a required input, it may mean reject the call. The same pointer state can support different interfaces, but each interface must choose a clear behavior.

Mistakes and repairs

Do not dereference void * as though it implied int. The compiler needs the target type for meaningful object access. Convert according to known metadata, not according to whichever cast makes an error disappear.

Do not assume calloc's zeroed bytes initialize every pointer object to a null pointer representation. Explicit pointer assignment establishes a null pointer value. This subtle representation distinction matters when designing portable pointer tables.

A null string pointer differs from a pointer to an empty string. The latter selects a real zero character that puts and strlen can read. The former selects no character storage at all, so those calls are invalid.

Checking only non-null after free cannot validate an old alias. The allocation is gone even if the numerical-looking address remains unchanged. The following topic develops this lifetime problem with explicit examples.

Dereference an untyped pointer

void does not describe an object value that can be read. Convert data to a compatible int pointer first.

Working habits

Keep type metadata with every generic object address. Prefer typed interfaces when generic storage is unnecessary. Define whether NULL means absence or invalid input, and check that state before selecting any target value.

Standard and portability notes

void * conversions and NULL are established C features. The executable examples use C17. C23 nullptr is a forward-looking note here; it should be compiled only with suitable C23 support and does not alter the dereference rules.
