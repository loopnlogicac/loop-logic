Introduction to Pointers

Imagine a library desk that keeps the location of a book rather than another copy of the book. A pointer plays a similar role. It stores an address that lets your program reach an object already in memory.

An object is a region of storage used to hold a value, such as the int variable marks. Its address identifies that storage location within the running program. A pointer is itself a separate object: it has a stored value and an address of its own.

You have already passed &marks to scanf. That expression gives the input function a route to the caller's variable. Now you will use the same idea directly to read and change values without depending on their variable names.

Declarations and call rules

The declaration int *p = &marks; creates a pointer to int. The unary & operator takes the address of marks. The star in the declaration belongs to p's type: it says p stores an int pointer value.

In an expression, *p means follow p to its target. This operation is called dereferencing or indirection. Reading *p reads the selected int, while assigning to *p writes that int. The expression p = &other instead changes the address stored in p.

Declare one pointer per line while learning. In int *p, q;, only p is a pointer; q is an ordinary int. Repeating a star for each pointer declarator is necessary, which is one reason separate declarations are clearer.

Initialize a pointer immediately. int *selected = NULL; records that no target has been selected. NULL is a macro available through standard headers such as stdio.h and stddef.h. A null pointer is a useful absence marker, but it is never a valid target for reading or writing.

Follow the storage and operations

Read the memory picture as two boxes and one arrow. The marks box holds seventy. The p box holds the address of marks. The illustrative addresses are teaching labels, not values your computer is required to use.

After *p = 85, the marks box contains eighty-five. The arrow does not move. Printing marks and *p therefore reads the same stored int twice. No synchronization between separate int copies is needed because there is only one target object.

After p = &other, the arrow moves to another live int. That assignment does not change marks and does not copy the value of other into marks. Separate address assignment from target assignment whenever you trace a pointer program.

Copying p into q creates a second pointer object with the same target address. These pointers are aliases: two access paths to the same object. A write through either path changes what the other reads. Redirecting p afterward changes only p; q keeps its own stored address.

The address of p is &p, whose type is int **. You do not need double-pointer operations yet, but notice that &p and p describe different objects. The former identifies the pointer box, while the latter selects the int box.

A valid dereference needs more than a non-null bit pattern. The target must exist, have a compatible type and alignment, and be within the permitted range. Assigning an arbitrary integer as an address cannot prove those facts. Use addresses derived from real live objects.

Choose the right behavior

To inspect an object pointer, use printf("%p", (void *)p). The %p conversion expects void *, a generic object-pointer type. The explicit conversion supplies the proper argument type to this variadic printing function. %d and %zu are integer formats and do not replace %p.

The address example prints both p and &p. Their text form is implementation-defined, and their values may change between runs. Read the example as a distinction between target location and pointer-variable location, without memorizing a particular hexadecimal number.

Pointer width need not equal int width. On many current systems they differ. Converting a pointer to an int merely to print it can lose information and is not the portable address-inspection method. Later lessons discuss sizeof without assuming a universal byte count.

The address operator does not allocate another target. &marks selects storage that already belongs to marks. Likewise, pointing at a local variable does not extend its lifetime. A pointer to that variable becomes unusable when the variable stops existing.

A null initialization lets you postpone choosing a target safely. You may compare the initialized pointer with NULL and handle the missing case. Only after assigning a valid target should the program dereference it. A zero check on an uninitialized pointer reads an indeterminate value and is not an initialization technique.

Use pointers when a function needs to modify caller storage, when traversing an array, or when representing relationships between objects. For a simple local calculation, an ordinary variable name is often clearer. The benefit of a pointer is a deliberate access path, not extra syntax around every value.

An address is meaningful within the execution and storage context that produced it. Printing an address does not create a persistent identifier for a later run. Do not save its text in a file and expect another process to use it as a direct location. For a stored record, keep an application identifier such as a roll number instead.

Pointer type also describes access size and interpretation. An int pointer lets the compiler access an int at a compatible target. It is not interchangeable with a double pointer merely because both expressions represent addresses. The selected object, alignment and type must support the requested read.

A useful paper trace records three columns: variable name, current stored value and selected target. For p, the stored value is an address; for marks, it is an integer. That distinction makes an alias write easy to follow without needing actual machine addresses.

Mistakes and repairs

Dereferencing NULL has undefined behavior. Some systems terminate the program, but C promises no particular failure message. The intentional mistake example explains the invalid access without assigning it a predictable output.

Do not write int *p = 70 to point at an int whose value is seventy. An address and an int value are different roles. Create the int object, then initialize p with its address.

An uninitialized automatic pointer has no valid selected target. Even comparing its value before assignment is a mistake. Initialize to NULL or a live address at declaration so the first read has a defined meaning.

Parentheses help when combining operations. (*p)++ increments the target value, while p++ moves the pointer within a suitable array. Those operations answer different questions and have different safety requirements.

Working habits

Draw the pointer box separately from the target box. For each assignment, ask whether the arrow moves or the target value changes. Keep the target alive, initialize every pointer and print addresses only when the location itself is relevant.

Standard and portability notes

Object addresses, address-of and indirection are central C features from C89 onward. The examples target C17. NULL is used here for that baseline; C23 also introduces nullptr, discussed in the dedicated void and null pointer lesson.
