Pointers and Functions

A function often needs to update something that belongs to its caller. Swapping two exam marks or producing both a minimum and maximum are familiar examples. Pointer parameters give the function addresses of caller-owned result slots.

C still passes every argument by value. For a pointer argument, the copied value is an address. The function can follow that copied address to shared storage, but changing the local pointer parameter itself does not change the caller's pointer variable.

Think of handing someone a copied room location. They can reach the room and change its contents. Writing a different location on their copy does not alter the note you kept. This distinction explains both successful target updates and failed attempts to redirect caller pointers.

Declarations and call rules

A function declared void swap(int *left, int *right) receives two int pointer values. Call it with swap(&a, &b). The caller takes the addresses of its live ints, and the helper dereferences those addresses to exchange their values.

For several results, use output parameters such as int *low and int *high. The caller declares the result variables and passes their addresses. The helper fills those slots before returning. Its contract must say whether targets may be null or alias each other.

A function can also return a pointer, written int *find(...). That returned address must select storage that remains alive after return. A position inside the caller's array can satisfy this rule. An address of the helper's automatic local int cannot.

Use a scalar return when the result is one ordinary value and no shared access is needed. Returning an address is appropriate when the result is a location in existing storage or an explicitly owned object, rather than a more complicated spelling for a simple number.

Follow the storage and operations

Trace swap using caller ints a=40 and b=90. left points at a and right points at b. The temporary first saves forty. The write through left stores ninety into a; the write through right stores the saved forty into b.

The pointer parameters occupy their own objects inside the call. Their target addresses are copied from the arguments. On return, those parameter objects disappear, but the caller ints remain alive and retain their new values. No address of the parameter object is needed.

A temporary-value swap also handles swap(&a,&a). Both paths select the same int, and every assignment preserves its original value. Arithmetic swaps are harder to reason about and can overflow or fail under aliasing.

The minmax helper starts from values[0], so its contract requires n>0 and a readable n-element range. It scans into local smallest and largest values, then writes outputs once. This prevents output writes from disrupting the scan if an interface permits some input overlap.

To retain two different results, low and high must select distinct writable ints. If both select one int, the final write replaces the first result. That call is not automatically undefined, but it cannot satisfy a promise to preserve both extrema simultaneously.

The search helper returns a+i when a match appears, or NULL when absent. Its returned position remains valid while the caller array stays alive and unchanged in ways that invalidate the requested position. Check NULL before editing the found element.

Choose the right behavior

Returning &local from a helper is a lifetime error. The local automatic object stops existing when the call finishes. The caller receives no live int target, regardless of whether the same stack bytes appear unchanged in a debugger. Reading through that expired address is undefined.

One safe alternative is to return the computed int value. Another is to let the caller supply an output address. A documented static result can also survive return, but it is shared across calls rather than freshly created for each call.

The static counter example saves one result value, calls the function again, then reads through the original pointer. The saved scalar remains one; the shared target becomes two. Lifetime safety does not guarantee that later calls leave a static result unchanged.

Allocated results provide another lifetime model: the callee can create storage whose lifetime continues until the responsible owner frees it. That model needs allocation-failure handling and an ownership contract. The dynamic-memory module develops it; prefer caller-owned output for these small exercises.

If a helper must redirect a caller pointer, an ordinary int * parameter is insufficient. Assignment to that parameter replaces only its local copied address. Pass an int ** selecting the caller pointer object instead, as the next topic explains.

A nullable output parameter needs deliberate behavior. You may reject NULL, skip an optional result, or return a status indicating failure. Do not add a null check that silently leaves required caller outputs uninitialized. State the success condition and which outputs were written.

For empty input, minmax has no minimum or maximum under this interface. A reusable version could return failure without touching outputs. The fixed nonempty examples keep that choice explicit rather than inventing a sentinel that might also be a legitimate mark.

Mistakes and repairs

Using swap(a,b) for an address-taking swap is a type mismatch. The function needs locations, not copies of the two numbers. Write the ampersands at the call site when passing ordinary int variables.

Returning a local array address has the same lifetime problem as returning a local int address. The array-to-pointer conversion does not preserve the array after the call. Copy into a caller-owned buffer or choose another documented lifetime.

Do not free a returned search pointer into a caller array. The helper returned a borrowed position, not an allocated-block owner. The right cleanup depends on where the target storage came from.

Output aliases deserve review even when each pointer is non-null. Two individually valid addresses can still refer to the same object, causing one logical result to overwrite another. Contracts describe relationships between arguments as well as each argument separately.

Return an expired automatic object

The result is undefined when used: local stops existing on return. Return a value or use caller-owned result storage.

Working habits

Name input and output roles in helper declarations. State nonempty-range and aliasing requirements. Prefer caller-owned result slots for small multi-result tasks, and follow every returned pointer back to storage with a known lifetime.

Standard and portability notes

C89 through C23 pass pointer arguments by value. These C17 examples use C99 loop declarations. No standard automatically extends automatic local lifetimes when a pointer is returned, and no pointer spelling creates language-level pass-by-reference.
