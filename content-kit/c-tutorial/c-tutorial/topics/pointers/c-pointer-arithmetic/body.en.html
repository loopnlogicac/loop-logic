Pointer Arithmetic

An array is a row of adjacent elements. A pointer selecting one element can move along that row without handling raw byte addresses. This is pointer arithmetic: addition and subtraction interpreted in units of the target type.

Imagine walking between classroom seats. Moving forward by two seats means two whole positions, regardless of each seat's physical width. An int pointer behaves similarly: adding two skips two int elements, not necessarily two bytes.

The row also has boundaries. C permits a special end position immediately after the final element, but that marker is not another seat. Keep the legal positions separate from positions that contain readable values.

Declarations and call rules

For a pointer p into an array, p + k selects a position k elements forward, and p - k selects one k elements backward. p++ and --p move by one element when the resulting position is valid. The target value is not changed by these address calculations.

The difference last - first counts elements between two positions in the same array. Store it in ptrdiff_t, a signed integer type declared by stddef.h. Print it using %td. A negative result means the first operand precedes the second.

An n-element array permits pointer positions from its beginning through one past its end. Reading and writing are limited to the actual n elements. Even forming a pointer two past the end or one before the beginning violates the arithmetic range rule.

This lesson orders pointers with < only when they identify positions in the same array. That is the useful portable rule for array traversal. Do not apply numeric-looking address order to unrelated local arrays.

int *end = values + count;

Follow the storage and operations

Take scores containing 40, 60, 80 and 90. A pointer initially selects scores[0]. Adding two selects scores[2], whose value is eighty. On a system with four-byte ints, the address spacing would be eight bytes, but the expression remains +2 on every implementation.

The scaling comes from the pointed-to type. A char pointer advances by one char; an int pointer advances by one int. Later, a pointer to an entire three-int row advances by a whole row. The compiler uses the target type rather than inferring a stride from the observed values.

A half-open range includes its starting element and excludes its ending position. For three values, begin is values and end is values+3. The loop tests p != end, reads *p, then advances p. The final advance reaches end and the next condition stops before any end dereference.

Half-open ranges describe empty work naturally. If begin equals end, the loop performs no reads and the sum remains zero. You do not need a fabricated last index of minus one. This matters for size_t lengths, where subtracting one from zero would wrap.

Reverse traversal also benefits from the end marker. Start p at end, check p != begin, decrement, then read. The decrement first reaches the final live element. After reading the first element, stop without forming begin-1.

Subtracting &seats[4] and &seats[1] yields three because three element steps separate them. It does not report a byte distance. Reversing the operands yields minus three. The mathematical result must fit ptrdiff_t; an unrepresentable pointer difference is not a usable value.

Choose the right behavior

Within one array, relational comparison reflects element position. A pointer to an earlier element compares less than a pointer to a later element, and the one-past position follows the last. This supports two-ended traversals and range reasoning.

Equality comparison asks whether compatible pointer values select the same position, with special rules for null pointers and array boundaries. For the straightforward cases here, a copied pointer compares equal to its source and an end pointer equals begin+n. Do not infer string equality or target-value equality from pointer equality.

Pointers into two separately declared arrays cannot be subtracted, even if a debugger happens to show adjacent addresses. Physical adjacency in one run does not turn them into one array object. Their separate origins determine which arithmetic operations are valid.

A single standalone object is treated like a one-element array for these arithmetic rules. You can form a pointer one past it, but not read through that pointer or step farther. This narrow allowance does not create neighboring int objects.

Void-pointer arithmetic is not portable C17 because void has no object element size. GCC may accept it as an extension. Choose a correctly typed pointer, or use an unsigned char pointer when inspecting an object's byte representation with an explicit byte range.

For an input offset, check its domain before forming the pointer. Forming a wild position and then deciding not to dereference it is too late to satisfy the arithmetic rule. The selection exercise validates its index first, then adds it to the array beginning.

A range contract must keep count consistent with the actual object. A helper receiving begin and count cannot validate that count from the pointer alone. If a caller passes count ten for a three-element array, the helper's well-written traversal still receives an invalid range. Bounds are shared responsibilities across the interface.

Pointer arithmetic changes a selected position without extending storage. Forming end does not allocate an extra sentinel element. If you want to store an explicit sentinel value, reserve a real element for it and include that storage in the array definition.

The difference between two adjacent pointers can equal one even when their printed addresses differ by several numeric units. That is expected type scaling. Use ptrdiff_t for element distance, and use a separately designed valid byte view only when byte distance is the actual question.

Mistakes and repairs

The one-past position is a boundary marker, not an element with a hidden zero value. The mistake example dereferences that marker and has undefined behavior. Replace the read with a condition that stops before the marker.

Do not add sizeof(int) to an int pointer to move one int forward. The language already scales by the type size, so that expression moves several elements on common platforms. Use p+1 for one element.

Using size_t to store a negative pointer difference loses its signed meaning. Use ptrdiff_t and the matching printf format. A cast does not make subtraction between unrelated arrays valid.

Avoid a reverse condition that decrements p below begin before testing it. A non-dereferenced invalid pointer is still a problem. Organize the loop around the permitted one-past end instead.

Reading the end marker

The result is undefined: end is one past the array and has no element to read. Stop before dereferencing it.

Working habits

Label beginning, final element and end marker separately in every range diagram. Validate offsets before arithmetic. Measure differences only within the same array, and choose traversal conditions that also explain the empty range.

Standard and portability notes

The type-scaled arithmetic and one-past rules apply throughout the C standards used in this course. C99 adds the %td printing length modifier used here. These programs target C17 without compiler-specific void-pointer arithmetic.
