Introduction

A student either passes a threshold or needs another attempt. Both outcomes deserve a message. An if-else statement chooses exactly one of two controlled statements. When its condition is true, C runs the if branch.

Otherwise it runs the else branch. The paths meet again afterward.

This is like choosing one of two doors and arriving at the same corridor. The condition does not run both rooms in sequence. Each branch can contain several actions inside braces. Put work shared by both outcomes after the whole decision so you do not repeat it.

Syntax and reading guide

if (marks >= 40) {
    puts("Pass");
} else {
    puts("Try again");
}
puts("Report complete");

An else has no condition of its own. Its meaning is that the paired if condition failed. Use an else-if chain when you need another distinct question.

Follow the values and decisions

Take the passing threshold forty. A mark of forty or more enters the first block; a lower mark enters the second. After the chosen block ends, execution continues with the report-complete message. You can verify the decision using thirty-nine, forty and forty-one.

These values show both branches and the inclusive boundary.

Parity provides another two-way choice. An integer is even when its remainder after division by two is zero. Negative even numbers also have zero remainder. Test number % 2 == 0 rather than assuming every odd remainder must equal positive one.

A negative odd dividend can leave negative one in C17.

The dangling else problem appears when nested if statements omit braces. An else pairs with the nearest preceding unmatched if allowed by the grammar. Indentation cannot force it to match a more distant outer if. You can accidentally make a rejection message depend on the wrong condition.

The safe repair is to brace both branches of both decisions. Then trace which condition owns each else. You do not need a clever indentation convention to resolve the ambiguity; the source structure itself makes the pairing explicit. In a code review, name the question answered by each else before checking its actions.

A pass or retry report

The inclusive comparison accepts forty, so Pass appears and Retry does not. Done follows either branch. A value of thirty-nine would switch only the selected first message; the common final line would remain.

Parity for a negative input

Negative seven has a nonzero remainder on division by two, so the else branch prints Odd. The test asks for zero remainder, which works for positive and negative integers. It does not require the odd remainder to be positive one.

Boundaries and alternatives

An if-else chooses one branch even if the branch statements modify the variable used by the condition. The condition was already evaluated for that decision. A later modification does not send execution backward into the other branch.

Two independent if statements can look similar to an if-else, but their behavior differs when the first changes a value. The second independent if evaluates again and may run too. Use the form that matches the requirement: exactly one outcome or several potentially independent actions.

For a bill discount, calculate the adjusted amount inside the chosen branch and print it after the branches merge. This keeps the output format in one place. It also makes it easier to check that every path initializes the result before it is read.

Common mistakes

Putting a condition after else

An else does not accept a parenthesized condition directly. Write else if when another question is needed, or put a new if statement inside an explicitly braced else block.

Relying on indentation to match else

The compiler uses grammatical nesting. Add braces around the intended outer branches, then indent to show that structure. Reformatting alone cannot change an existing pairing.

Initialize a result on every selected path

A shared print after if-else is convenient only when both branches provide the value it prints. Draw two arrows into that print and ask what result arrives along each. If one branch forgets to assign the result, that path may read an uninitialized local. Initializing a default can be appropriate, but choose a default with a clear meaning rather than hiding a missing branch calculation.

Version notes

if-else and nearest-unmatched-if pairing apply throughout the C editions used here. C17 introduces no special indentation rule. Braces remain the portable way to show explicit branch grouping.
