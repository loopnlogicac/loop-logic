Introduction

A lab assistant gives an extra reminder only when a student arrives late. Most arrivals need no extra action. An if statement expresses that optional work in C. It checks a condition and runs one statement when the condition is nonzero.

When the condition is zero, execution skips that statement and continues afterward.

Think of the condition as a gate along one path. The gate decides whether you visit the enclosed block. It does not stop the whole program when it closes. A statement after the if belongs to the ordinary path and runs unless something else ends execution.

Syntax and reading guide

if (marks < 40) {
    puts("Review the topic");
}
puts("Check complete");

The condition belongs inside parentheses. The braces form one compound statement, or block, containing all the actions controlled by the decision. Indentation helps a reader but does not replace those braces.

Follow the values and decisions

C evaluates the condition once each time control reaches the if. If a mark is thirty-nine, the comparison with forty produces one and the reminder runs. If the mark is forty, the comparison produces zero and the reminder is skipped. Both paths reach Check complete.

Trace the boundary rather than assuming that an if always prints something.

Any nonzero scalar condition is true. Positive five and negative five both enter an if block. Zero does not. A comparison is useful because it expresses a readable question, but the language does not require the condition to equal exactly one.

A double condition also uses zero/nonzero truth, although a named comparison is usually easier to understand.

An if controls exactly one statement. Without braces, only the immediately following statement is controlled, even when several lines share the same indentation. With braces, the entire block is that one statement. Always use braces while learning so adding a second action cannot accidentally move it outside the decision.

A single if has no alternative branch. If you need a message on both paths, use if-else. Several independent if statements can each run; they do not automatically form a choose-one structure. This distinction matters when two reminders can both apply to the same student.

Examples

Show one optional reminder

The true comparison enters the block and prints Review. Execution then reaches the ordinary Done statement. Two lines appear because the second line is outside the conditional block. Try forty to see the optional first line disappear.

A false condition skips only its block

Forty is not less than forty, so the reminder block is skipped. Done still appears. The if does not terminate main or suppress unrelated later output. The comparison uses the same passing boundary as the first example.

A negative value is still true

The first condition treats negative five as nonzero and enters. The second explicitly checks its sign and also enters. These are independent decisions, so both messages print. Writing a descriptive comparison is clearer than relying on a bare balance for a financial rule.

Boundaries and alternatives

A semicolon immediately after the condition is an empty statement. It becomes the entire controlled action, and the following block runs unconditionally. This is easy to miss because the indentation may still look correct. Read the closing parenthesis and the next character when diagnosing an unexpected action.

A condition can use logical AND to require several facts. Input checks often use if to end the program after a failed read. The scanf lesson explains the returned assignment count. Once that check passes, a later if can safely inspect the newly read variable.

Keep conversion success separate from an academic rule such as the passing threshold.

Common mistakes

Writing an empty controlled statement

Remove the semicolon between the closing condition parenthesis and the opening brace. Use a warning-enabled build to catch suspicious indentation, then trace a false case to verify the fix.

Expecting a one-time if to repeat

An if checks once; it does not revisit the condition automatically. Repeated checking needs a loop, taught in the loop overview. A variable update inside the block does not create repetition.

Questions to ask while reading

QuestionRule and reason
Which scalar condition skips an if block?Zero. Only scalar zero is false.
What groups several statements under one if?Braces. The braced block is one compound statement.
Does an ordinary if automatically recheck its condition?No. Repetition requires a loop.
Where does execution go after a false if with no else?To the statement following the controlled statement. It skips only the controlled statement.
What does a semicolon immediately after if(condition) control?An empty statement. The following visible block is then independent.
Can two independent if blocks both run?Yes. Each checks its own condition.
Why check scanf before comparing its destination?The destination may not have received valid input. Use values only after successful assignments.

Distinguish skipping from stopping

On a false condition, the program skips the controlled block and continues after it. If you want to stop the current function, the selected block must explicitly return. A low mark warning and an invalid input exit therefore have different effects even when both use if. Trace the next executable statement on each path before deciding whether an action is optional or terminating.

Version notes

The if statement and scalar truth rule are available in C89 and continue in C17. C99 allows declarations mixed with statements inside blocks. This lesson uses C17 and always writes braces around controlled actions.
