Introduction

A small menu asks you to type one for a balance and two for help. These choices are exact values, rather than intervals such as marks at least forty. A switch statement selects a starting label by matching an integer expression with a case constant.

Think of a row of labeled starting points. Switch jumps to the matching label, then ordinary execution continues from there. A break tells it to leave the switch. Without that break, control can continue through later labels.

Understanding both selection and continued execution is essential to reading switch correctly.

Syntax and reading guide

switch (choice) {
    case 1:
        puts("Balance");
        break;
    case 2:
        puts("Help");
        break;
    default:
        puts("Unknown choice");
        break;
}

The controlling expression has integer type, including character and enum types after the appropriate promotions. Each case needs an integer constant expression. A variable value is not a valid case label.

Follow the values and decisions

Switch evaluates its controlling expression once, then looks for a matching case. If none matches, a default label provides the optional fallback. If there is no match and no default, control skips the body. Default may appear at different source positions, but placing it last usually makes the menu easier to read.

Case labels do not end preceding cases. After a matching label, statements run until a break, return or another control transfer changes the path. Reaching another case label during ordinary execution does not perform a new comparison. This continued execution is fall-through.

Intentional fall-through is useful for sharing one action between labels. Put cases one and two together before a common statement when both menu options mean the same thing. Accidental fall-through happens when an independent case forgets its break and unexpectedly performs the next case's work. Mark intentional behavior clearly and keep unrelated actions separated.

For a calculator, a character such as '+' is a valid integer constant expression. Switch on the operation character and perform the matching arithmetic. Division still needs a zero-divisor check inside its case. Switch selects an operation; it does not validate the operation's operands for you.

Boundaries and alternatives

Use an else-if ladder for ranges, floating comparisons, or unrelated Boolean questions. Switch fits exact integer choices. Strings cannot be used as switch values in C, and a C17 const int object is not generally an integer constant expression for a case label. An enum constant is suitable when it fits the required case rules.

Duplicate case values are invalid even if spelled in different bases. A case labeled ten and another labeled hexadecimal 0xA refer to the same integer value. A switch can contain at most one default. If a case needs local declarations in C17, put those statements inside a braced block after the label.

The block also keeps temporary names local to that case.

A break leaves the nearest enclosing loop or switch. If a switch sits inside a loop, its break normally leaves only the switch, so the loop may continue. The break and continue lesson traces that nesting separately.

Common mistakes

Expecting labels to stop execution

Labels name entry points. Add break after an independent action to leave the switch. Trace a middle case and observe whether it accidentally reaches later case actions.

Using a runtime variable as a case constant

A case value must meet integer constant-expression rules in C17. Use a literal, suitable enum constant, or a macro that expands to such an expression. Use if for a changing comparison value.

Questions to ask while reading

QuestionRule and reason
What kind of controlling expression does C switch accept?Integer type. Character and enum values fit through integer rules.
What must a case label contain?An integer constant expression. The label values are determined during translation.
What happens after a case action without a control transfer?Execution continues through following labels. Case labels do not block fall-through.
Which statement normally ends one independent case?break. Break leaves the nearest switch or loop.
What selects default?No matching case value. Default is an optional unmatched-value fallback.
Which is better for mark intervals?An else-if ladder. Ranges naturally use comparison conditions.
May case 10 and case 0xA coexist in one switch?No, their values duplicate. Case uniqueness is based on converted integer values.

Check an unmatched choice too

A menu can look correct when you test only its listed choices. Also try a value absent from every case. That run should reach default, or skip the switch when no default exists. Include a middle case to catch accidental fall-through into the next action.

Version notes

The C17 examples use conventional case labels and comments for intended shared cases. C23 adds facilities such as standardized fallthrough attributes and permits more label placements. Those additions do not make accidental fall-through a good menu design.
