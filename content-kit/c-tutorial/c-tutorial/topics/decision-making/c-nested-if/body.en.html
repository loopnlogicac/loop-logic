Introduction

A lab assistant first checks whether you are registered. Only then does it make sense to check whether your marks qualify for a certificate. A nested if places one decision inside a branch of another. The inner question is reached only along the selected outer path.

Think of entering a building before checking a room. The room decision assumes you passed the entrance check. Nesting is useful when later questions depend on earlier answers. Too many levels can become hard to follow, so you will also compare nesting with a combined logical condition.

Syntax and reading guide

if (registered) {
    if (marks >= 40) {
        puts("Eligible");
    }
}

Each opening brace needs a matching closing brace. Indent one extra level inside each block. An else matches according to this structure, not according to the visual distance from an if.

Follow the values and decisions

For the registration example, trace all three meaningful paths: unregistered, registered with a low mark, and registered with a passing mark. The inner comparison is skipped on the unregistered path. Writing those paths as a small decision tree helps you see whether every required message is covered.

To find the largest of a, b and c, first compare a with b. If a is at least b, the winner must be either a or c. Otherwise it must be either b or c. The inner comparison resolves the remaining pair.

Use inclusive comparisons to handle ties without leaving a result unassigned.

A leap year gives a useful nested exception rule in the Gregorian calendar. A year divisible by four is usually leap. But a century year divisible by one hundred is not leap unless it is also divisible by four hundred. Test the broad four-year condition, then inspect the century exception, then the four-hundred-year exception.

The years 1900 and 2000 show why the extra levels matter.

You can flatten a chain whose only action is inside the deepest true branch. The condition registered && marks >= 40 expresses the same entry requirement as the first nested example. Short-circuiting skips the mark question when registration is false. However, if each failed level needs a different explanation, nested branches can keep those messages clearer.

Examples

Check two dependent requirements

Registration is true, so control reaches the mark question. Sixty-five passes, selecting Eligible. The inner false message and outer false message belong to different paths. Explicit braces keep their ownership clear.

Largest of three including a tie

The a-versus-b comparison accepts equality and chooses the a/c pair. Nine exceeds four, so best receives nine. Every possible branch assigns best before the final print. The code finds a maximum value without claiming a unique winning variable.

A century exception

Nineteen hundred passes the four-year test but is a century year. It fails the four-hundred test, leaving leap at zero. The initialized flag covers all paths that do not explicitly set it to one.

Boundaries and alternatives

Do not use calendar intuition as the whole leap-year rule. A year ending in double zero is exactly the case that needs the four-hundred test. Try 2024, 1900, 2000 and 2023. Each exercises a distinct route in the decision tree.

A decision depth is the number of nested choices on a path. When that depth grows, consider early validation checks that return on failure. The remaining normal path can then stay less indented. Later lessons on functions show how a helper can name a complex decision without exposing every detail at its call site.

Common mistakes

Leaving the largest value unassigned on a tie

Use >= when selecting the winning pair, or define a clear equality branch. Test all-equal values as well as two equal maxima. The numeric largest value is defined even when there is no unique winner.

Flattening branches that need different failure messages

A combined AND condition tells you whether all requirements passed, but not which failed. Keep separate checks when the user needs a specific registration or marks explanation.

Questions to ask while reading

QuestionRule and reason
When can an inner if be reached?Only through its enclosing branch. The outer decision controls entry to the inner decision.
What is a useful way to trace nested decisions?Draw each condition as a branch in a tree. A path shows which questions actually execute.
How should largest-of-three code handle equal maxima?Still assign the shared maximum value. A maximum value exists even without a unique winner.
Is every year divisible by four a Gregorian leap year?No, century exceptions apply. Centuries must also be divisible by four hundred.
Which century is leap in the Gregorian rule?2000. Two thousand is divisible by four hundred.
When can nested true-only checks become one AND condition?When only the all-true path needs an action. AND preserves the required all-true selection.
What can reduce deeply indented validation code?Return early on invalid input. After rejecting invalid cases, the normal path can stay flatter.

Check paths rather than only conditions

A registered low-mark student and an unregistered high-mark student fail for different reasons. Test both paths when separate messages matter. Testing only a successful student does not show whether the two failure explanations belong to the correct nesting levels. A small decision tree makes those missing cases visible.

Version notes

Nested if statements use the same grammar as ordinary if statements in C89 through C23. The leap-year calculation is a Gregorian calendar rule rather than a feature of the C standard. All running examples use C17.
