Introduction

A for loop repeats a block of code a counted number of times. You use it when you know, before the loop starts, how many times the work must happen: print roll numbers 1 to 60, add the marks of 40 students, or show a multiplication table up to 10.

Without a loop you would write the same printf line again and again. With a for loop you write it once and tell C three things: where to start, when to stop, and how to move to the next step. All three sit together on one line, which makes the for loop the easiest loop to read when the number of repetitions is known.

The for loop is an entry-controlled loop. C checks the condition before each repetition, so if the condition is false at the start, the body never runs at all. The while loop works the same way; the do-while loop is different because it always runs at least once.

Syntax

for (initialization; condition; update) {
    /* body: statements to repeat */
}
The three parts of a for loop header
PartRunsTypical jobExample
initializationonce, before everythingcreate or set the loop counterint i = 1
conditionbefore every repetitiondecide whether to run the body againi <= 10
updateafter every repetitionmove the counter to its next valuei++

The three parts are separated by semicolons, not commas. Any part may be left empty, but both semicolons must stay. If the body is a single statement the braces are optional, but always writing them prevents a whole family of mistakes shown later on this page.

How the for loop works

The for loop always follows the same four steps:

  1. Run the initialization once.
  2. Check the condition. If it is false (zero), leave the loop and continue with the code after it.
  3. If the condition is true (non-zero), run the body.
  4. Run the update, then go back to step 2.
        +----------------+
        | initialization |
        +----------------+
                |
                v
        +----------------+   false
   +--> |   condition?   | ----------> code after the loop
   |    +----------------+
   |            | true
   |            v
   |    +----------------+
   |    |      body      |
   |    +----------------+
   |            |
   |            v
   |    +----------------+
   +--- |     update     |
        +----------------+

Here is a trace of for (int i = 1; i <= 3; i++) so you can see the order of each step:

Notice that the condition is checked one more time than the body runs. The last check is the one that fails and stops the loop.

Variations of the for loop

Counting down and other steps

The update does not have to be i++. You can count down, or jump by any step:

for (int i = 10; i >= 1; i--)      /* 10, 9, 8, ..., 1 */
for (int i = 0; i <= 100; i += 5)  /* 0, 5, 10, ..., 100 */
for (int i = 1; i <= 1000; i *= 2) /* 1, 2, 4, ..., 512 */

Leaving parts empty

Any of the three parts can be empty. An empty condition counts as true, so for (;;) repeats forever until a break or return inside the body ends it. If the counter already has a value, you can also skip the initialization:

int i = 5;
for (; i > 0; i--) {
    printf("%d ", i);
}

Common mistakes

A semicolon after the header

A semicolon right after the closing parenthesis is an empty statement. It becomes the whole body of the loop, so the block below it runs only once, after the loop has finished. GCC warns about this with -Wall:

Off-by-one errors

for (int i = 1; i < 10; i++) runs 9 times, not 10. Decide first whether the last value should be included, then pick < or <=. A quick check: the loop from a to b with <= runs b - a + 1 times.

Changing the counter inside the body

Changing i inside the body as well as in the update makes the loop hard to follow and easy to break. Keep all changes to the counter in the update part.

Counting down with an unsigned counter

for (unsigned int i = 5; i >= 0; i--) never ends. An unsigned value is never negative, so when i is 0 and you subtract 1, it wraps around to a very large number and the condition stays true. Use a signed int for countdowns that must reach 0.

Watch the separators

Writing for (i = 0, i < 5, i++) with commas is a compile error. The header needs exactly two semicolons.

Best practices

  • Declare the counter inside the header (for (int i = 0; ...)) so it cannot be used by mistake after the loop.
  • Always use braces, even for one statement.
  • Use a for loop when the number of repetitions is known; use a while loop when the loop depends on input or an event.
  • Give the counter a meaningful name when the loop is long: student or row reads better than i.
  • Compile with -Wall -Wextra so GCC warns about empty bodies and misleading indentation.

Version notes

C89 vs C99 and later

Declaring the counter in the header (for (int i = 0; ...)) was added in C99. In C89 you must declare int i; at the top of the block and write for (i = 0; ...). With gcc -std=c89, a declaration in the header gives an error. Every modern compiler supports C99 and later, so this page uses the newer style. C11, C17 and C23 did not change the for loop.

Summary

The for loop puts initialization, condition and update on one line, which makes counted repetition clear and compact. The initialization runs once, the condition is checked before every repetition, and the update runs after every repetition. Watch out for semicolons after the header, off-by-one conditions and unsigned countdowns. Next, learn how to put one loop inside another in Nested Loops.
