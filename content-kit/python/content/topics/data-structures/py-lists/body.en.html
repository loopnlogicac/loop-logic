Keep related values together

A class register holds many roll numbers in a useful order. A Python list does the same for values. You can add an item, replace it, or remove it without inventing a separate variable for every roll.

A list is an ordered, changeable sequence. Ordered means each item has a position. Changeable means the same list can hold different contents later. Duplicate values are allowed, so two equal marks still represent two students.

Python lists can mix types, but a list of comparable marks is easier to process than unrelated values. Choose a name such as marks or rolls that tells you what each item means. Use direct iteration when you need every value and indexing when a position matters.

Create, select and replace

marks = [72, 85, 64]
first = marks[0]
marks[1] = 90
middle = marks[1:3]

Square brackets create the list and also select positions from it. A comma separates adjacent values. Index zero reaches the first item, while index minus one reaches the last. For a list of length n, valid positive indexes run from zero through n minus one.

A slice makes a new outer list containing selected items. Its start is included and its stop is excluded. Missing boundaries use the sequence ends in the chosen direction. A negative step walks backwards. Slices clip out-of-range boundaries, but a single invalid index raises IndexError.

Names point to lists

A list stores references to its items. Assigning the list to another name copies the reference, not all its contents. These two names are aliases: two ways to reach one object. Any edit through either name is visible through the other.

original ---> [10, 20] <--- alias
separate ---> [10, 20]

The copy method creates an independent outer container. With integers, replacing an item in that copy leaves the original slot alone. With nested lists, both outer containers still point to the same inner rows. This is called a shallow copy. Copy rows individually when you need a separate two-dimensional table.

For a rectangular table, matrix[row][column] first selects a row list and then an item inside it. The row and column indexes have separate limits. A table may also have rows of different lengths, so checking only the outer length cannot prove every column exists.

If you know C

A Python list grows automatically and can refer to objects of different types. Unlike a C array, it has no fixed declared element count. Index mistakes raise exceptions rather than granting access to unrelated memory. Python manages the storage lifetime.

Empty lists and growing work

An empty list has length zero and is false in a condition. Looping over it does no work. Before reading the last item or calling pop without an index, check whether an item exists. Removing an absent value raises ValueError, so use membership when absence is a normal case.

Reading a position takes constant time. Searching by value may inspect every item. Appending is constant time on average over many appends, although occasional resizing copies references. Inserting at the front or removing from the middle shifts later references and can take linear time.

Sorting compares items and usually needs work proportional to n log n. Mixed integers and strings cannot normally be ordered together. Keep data types consistent, or choose an explicit ordering rule after learning functions. Use sorted(values) when the original order must remain available.

Watch which object you change

Saving the result of sort

Writing marks = marks.sort() loses the list reference held by marks because sort returns None. Call marks.sort() by itself. The method communicates by changing the list, unlike sorted, which returns a new list.

Repeating one inner row

The expression [[0, 0]] * 3 repeats a reference to one row three times. Editing one cell then appears to change three rows. Create each row separately, as the final example does.

Deleting while moving forwards

Removing an item during forward iteration shifts the next item into its place. The loop may skip that item. Build a separate list of values to keep, or iterate over a copy when removal is necessary.

Portable list behavior

The list operations here work on Python 3.10 through 3.12. Their copy methods remain shallow; a newer interpreter does not make nested rows independent.

Choose order and ownership deliberately

Lists are useful when position and change both matter. Separate searching by value from selecting by index, and separate aliases from copies. Next, list comprehensions express many list-building loops as readable expressions.
