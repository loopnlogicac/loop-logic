Treat a small group as one value

A seat location needs a row and a column together. A course result needs a code and a mark together. A tuple groups these values in fixed positions, so you can pass or store the whole group as one object.

Tuples are ordered sequences, like lists, but you cannot replace, insert or delete their slots. This property is called immutability. Choose a tuple when the positions describe fixed roles. Choose a list when items form a growing collection, such as all marks in a class.

Both containers can hold duplicates and mixed types. Their difference is not whether the values are numbers or text. Their difference is whether the container's own positions may change after creation.

The comma makes the tuple

coordinate = 2, 5
single = (82,)
empty = ()
row, column = coordinate

Parentheses often make a tuple easier to recognize, especially inside another expression. For a nonempty tuple, commas are what perform the grouping. Without a comma, (82) is only the integer 82 surrounded by parentheses.

Creating a tuple from several expressions is called packing. Assigning its items to several target names is called unpacking. Unpacking evaluates the right side, then assigns its values in order. Each name can have a different meaning, which often makes a record easier to read than repeated numeric indexes.

Use indexing and slicing when you need only part of the tuple. A negative index counts from the end. As with lists, a single out-of-range index raises IndexError, while slice boundaries clip to the available sequence.

Fixed slots can hold changeable objects

Imagine the tuple as a tray with fixed labels on its compartments. You cannot replace which objects the compartments refer to. However, an object reached through a compartment may itself allow edits. A contained list can grow even though the tray remains unchanged.

record tuple: [roll reference | marks reference]
           |                 |
           v                 v
          12            [70, 80, 90]

Assigning record[0] = 15 would attempt to replace a tuple slot and raise TypeError. Calling record[1].append(90) reaches the list and asks that list to change. These are different operations, even though both start by looking inside record.

This distinction also explains dictionary keys. A hashable value supports a stable hash used for lookup and follows the equality rules required by that lookup. Integers and strings qualify. A tuple qualifies only if each of its items qualifies too. A tuple containing a list is therefore unsuitable as a key.

If you know C

A tuple can group values of different types, a little like a small C struct. Its fields are selected by position rather than declared names. Python unpacking also supports swapping without a temporary variable. Do not treat a tuple as a writable C array.

Pack and unpack a result

The comma packs two values into one tuple. Unpacking binds course and mark in order. The trailing comma in (82,) makes a one-item tuple rather than a parenthesized integer.

Unpack a flexible middle

The fixed ends become 60 and 90. A starred target collects the middle into a list. Swapping evaluates the right-hand values first, so no temporary name is needed.

Keep tuple slots fixed but edit a contained list

The tuple still refers to roll 12 and the same list. Appending changes that list rather than replacing a tuple slot. Immutability of the tuple does not freeze everything reachable from it.

Look up a seat by coordinate

The tuple (1, 2) acts as one dictionary key, so the pair identifies a seat. get returns the fallback for an absent coordinate. Dictionaries are key-to-value lookup containers, taught in their own lesson.

Match the shape of the group

Ordinary unpacking requires an exact count. Two target names need two values; three values raise ValueError rather than silently discarding the extra value. This catches changes in data shape early. Check the shape before choosing names for an external record.

A single starred target can collect a flexible middle, beginning or end. Its result is always a list, even when no extra values exist. With first, *middle, last, at least two source values are required. A pair leaves middle empty.

Swapping two names uses unpacking too. Python first evaluates right, left using the old bindings, then assigns the resulting pair to left, right. The operation swaps bindings; it does not mutate the two objects. The same idea can rotate three names, though clarity matters more than avoiding a temporary variable.

When a function returns multiple values, it commonly returns one packed tuple. The caller may save the whole tuple or unpack it immediately. The functions lesson develops this pattern using named parameters and return statements.

Do not confuse fixed with deeply frozen

Forgetting the single-item comma

If later code expects a sequence, writing (5) causes surprising behavior because it is an integer. Write (5,) to preserve the one-item shape. This matters when building collections of records that sometimes have only one field.

Using a list inside a tuple key

A coordinate tuple of integers is hashable, but wrapping a changeable list in parentheses does not make that list hashable. Convert the meaningful components to suitable immutable values before using them in a key.

Expecting named fields from numeric positions

A long tuple with many unrelated fields becomes hard to remember. Short pairs and triples are often readable. For larger records, consider dictionaries now and named record types in later Python study. Write unpacking names that explain each value.

Stable sequence rules

Tuple packing, starred assignment and the hashability rules used here are available throughout Python 3.10–3.12. A tuple containing a mutable list remains unhashable in each of these versions.
