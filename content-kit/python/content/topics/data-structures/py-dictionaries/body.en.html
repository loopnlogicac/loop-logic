Look up a value by its meaning

A marks list answers which value appears at position zero. A teacher usually asks a different question: what mark belongs to roll 18? A dictionary connects lookup labels, called keys, to associated values.

You can think of a dictionary as a register whose left column identifies an entry. Each key has one current value. Two students may share the same mark because values need not be unique. Repeating a key replaces the earlier association rather than creating a second row.

Use dictionaries for roll-to-mark records, item-to-price catalogues and word-to-count reports. A key describes which entry you want without requiring a numeric position. That often removes the need to keep two parallel lists synchronized.

Write keys beside their values

marks = {12: 72, 18: 85}
marks[25] = 91
saved = marks[12]
optional = marks.get(99, "missing")

Braces enclose dictionary entries. A colon separates a key from its value, and commas separate entries. Empty braces create an empty dictionary. Square-bracket lookup retrieves the value for one key; it does not refer to the key's insertion position.

Assignment through a key adds an absent entry or replaces a present value. Keys must be hashable, such as integers, strings or tuples of hashable components. Values may be any objects, including lists and nested dictionaries.

Use bracket lookup when absence means the data is wrong and should raise KeyError. Use get when a missing key is an expected situation. Without a second argument, get returns None for absence. An explicit fallback makes counting and optional labels easier to read.

Keys identify entries; views follow the mapping

Dictionaries use hashing and equality to locate keys efficiently. A typical lookup takes constant time on average, although collision-heavy cases can take longer. Repeated lookup by roll is therefore usually much faster than repeatedly scanning every record in a list.

A view follows the current dictionary rather than copying its entries at creation. If you save data.keys() and later insert a key, that saved view sees it. Use list(data.keys()) when you want a separate snapshot of the current keys.

Direct iteration over a dictionary visits keys. Iterating over items supplies two-value tuples that unpack naturally into key and value. Iterating over values is useful when the keys are irrelevant, such as summing quantities.

Dictionary iteration preserves insertion order. Replacing a value keeps its key in the same position. Deleting a key and inserting it again places it at the end. The first observed order is useful for some reports, but sorted(data) is clearer when the report requires alphabetic or numeric order.

If you know C

C arrays index by integer position; a Python dictionary can use a course code or coordinate as a key. You would commonly implement this lookup with a hash table in C. Python manages the table, but missing keys and shared mutable values still need thought.

A dictionary comprehension builds a mapping from an iterable in one expression. Put the generated key before the colon and the generated value after it. A trailing condition can exclude entries, as in keeping only expensive items for a discount.

If generated keys repeat, the later generated value wins. This matters when trying to invert a mapping whose values are not unique. To preserve every original key under a repeated value, build lists of keys as the final practice task does.

Counting takes average linear time in the number of observations because each observation performs a small number of dictionary operations. Sorting the distinct keys for a report adds work based on the number of distinct keys. Collection and display have separate costs.

A fallback of None can be ambiguous when None is itself a saved value. If the distinction matters, test key in data before reading, or use a separate marker object in a more advanced interface. Do not treat get(key) is None as proof that the key is absent.

Deleting an entry with del data[key] requires that key to exist. The pop method can remove an entry and return its old value, with an optional fallback for absence. These operations answer a different question from get, which leaves the mapping unchanged.

Handle missing keys and shared values deliberately

Incrementing before a count exists

The statement counts[word] += 1 first reads counts[word]. It fails on a word's first occurrence unless you initialize that key. Using get(word, 0) handles both first and later occurrences in one readable expression.

Testing the wrong side

The expression 80 in marks asks whether 80 is a key, not whether any student earned 80. Test marks.values() for that question. Remember that scanning values can take linear time because values do not have the key lookup structure.

Assuming an outer copy duplicates lists

copy makes a new dictionary whose values still refer to the same nested objects. Editing a shared list changes what both mappings can see. Create new inner lists when independent groups are required.

Changing the number of entries during traversal

Adding or deleting keys while iterating over the dictionary can raise RuntimeError. Collect keys to delete first, then remove them afterward. Replacing values for existing keys does not resize the key collection, though clear two-stage logic can still be easier to review.

Order is part of modern dictionary behavior

Insertion order has been a language guarantee since Python 3.7 and is available on the Python 3.10–3.12 baseline here. Dictionary views remain live views rather than snapshots.
