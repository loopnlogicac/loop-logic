অর্থ ধরে মান খুঁজে নাও

নম্বরের লিস্ট বলে শূন্য অবস্থানে কী মান আছে। শিক্ষক সাধারণত জানতে চান, রোল 18-এর নম্বর কত? ডিকশনারি খোঁজার লেবেল, অর্থাৎ key-এর সঙ্গে সংশ্লিষ্ট value রাখে।

একে রেজিস্টার ভাবতে পারো, যেখানে বাঁয়ের কলাম এন্ট্রি চেনায়। প্রতি key-তে বর্তমানে একটি value থাকে। দুই শিক্ষার্থীর নম্বর সমান হতে পারে; value আলাদা হওয়া বাধ্যতামূলক নয়। একই key আবার দিলে দ্বিতীয় সারি না হয়ে আগের সম্পর্ক বদলায়।

রোল থেকে নম্বর, পণ্য থেকে দাম বা শব্দ থেকে গণনার রিপোর্টে ডিকশনারি নাও। সংখ্যার অবস্থান ছাড়াই key বলে কোন এন্ট্রি চাই। পাশাপাশি দুই লিস্ট মিলিয়ে রাখার দরকারও অনেক সময় থাকে না।

Key-এর পাশে value লেখো

marks = {12: 72, 18: 85}
marks[25] = 91
saved = marks[12]
optional = marks.get(99, "missing")

Braces-এর ভেতর এন্ট্রি থাকে। কোলনে key আর value, কমায় এন্ট্রি আলাদা হয়। ফাঁকা braces ফাঁকা ডিকশনারি। Square bracket একটি key-এর value আনে; key কত নম্বর অবস্থানে ঢুকেছে তা নয়।

Key দিয়ে অ্যাসাইন করলে না-থাকা এন্ট্রি যোগ হয়, থাকলে value বদলায়। key hashable চাই: int, str বা hashable অংশের টাপল। value যেকোনো অবজেক্ট, লিস্ট আর nested dictionary-ও হতে পারে।

না থাকা মানে ডেটা ভুল হলে bracket lookup নাও; KeyError হবে। অনুপস্থিতি স্বাভাবিক হলে get। দ্বিতীয় আর্গুমেন্ট না দিলে get না-পাওয়ায় None দেয়। নির্দিষ্ট fallback দিলে count আর ঐচ্ছিক লেবেল সহজ পড়া যায়।

ডিকশনারি পড়ার উপায়
এক্সপ্রেশনফল
key in datakey আছে কি না
data.keys()key-গুলোর view
data.values()রাখা value-গুলোর view
data.items()key-value জোড়ার view

Key এন্ট্রি চেনায়, view বর্তমান মান দেখায়

ডিকশনারি hashing আর equality দিয়ে দ্রুত key খোঁজে। সাধারণ lookup গড়ে constant time, বেশি collision হলে সময় বাড়ে। তাই বারবার রোল খোঁজা সাধারণত প্রতিবার পুরো লিস্টের রেকর্ড ঘোরার চেয়ে দ্রুত।

View তৈরি হওয়ার সময় এন্ট্রি কপি করে না; বর্তমান ডিকশনারি অনুসরণ করে। data.keys() রেখে পরে key ঢোকালে সেই view-তেও দেখা যায়। ওই মুহূর্তের আলাদা তালিকা চাইলে list(data.keys()) নাও।

সরাসরি dictionary ঘুরলে key পাও। items ঘুরলে দুই মানের টাপল পাও; key আর value নামে unpack করা সহজ। key দরকার না হলে values ঘোরো, যেমন মোট পরিমাণ বের করতে।

ডিকশনারিতে ঢোকানোর ক্রম থাকে। value বদলালে key-এর অবস্থান থাকে। মুছে আবার ঢোকালে শেষে যায়। প্রথম দেখার ক্রম কিছু রিপোর্টে উপকারী, তবে অক্ষর বা সংখ্যা অনুযায়ী চাইলে sorted(data) বেশি পরিষ্কার।

C জানা থাকলে

C অ্যারে সংখ্যার অবস্থান ধরে চলে; Python dictionary-তে কোর্স কোড বা স্থানাঙ্ক key হয়। C-তে সাধারণত hash table বানাতে হতো। Python টেবিল সামলায়, কিন্তু না-থাকা key আর শেয়ার করা mutable value নিয়ে ভাবতে হবে।

খোঁজো, ঘোরো, বানাও, গোনো

উদাহরণে mapping আর value হিসেবে থাকা অবজেক্ট আলাদা দেখবে। ডেটা সংগ্রহের সময়কার ক্রম আর শেষ রিপোর্টের দরকারি ক্রমও আলাদা।

নম্বর খোঁজো আর বদলাও

আপডেটের আগে key 12 দেয় 72। না-থাকা 99-এ get missing দেয়, key যোগ করে না। 12-তে আবার অ্যাসাইন করলে value বদলায়; 25 দিলে শেষে নতুন এন্ট্রি।

Key, value আর জোড়া পড়ো

আগে রাখা keys view-তে পরে যোগ করা ruler দেখা যায়। values থেকে পরিমাণ আসে; মোট 21। items-এর জোড়া দুই target-এ খুলে ঢোকানোর ক্রমে আসে।

Comprehension-এ দামের mapping

শুধু notebook ছাড়ের সীমায় পৌঁছায়, তাই discounted-এ এক এন্ট্রি। দ্বিতীয় comprehension এক থেকে চার পর্যন্ত প্রতিটি সংখ্যার সঙ্গে তার বর্গ রাখে। কোলনে তৈরি key আর value আলাদা।

নতুন শব্দেও এরর ছাড়া গোনো

না-দেখা শব্দে শূন্য থেকে শুরু, আবার এলে এক বাড়ে। শেষ রিপোর্ট প্রথম আসার ক্রমে নয়, অক্ষর অনুযায়ী key সাজায়। book 2, pen 3, ruler 1।

বাইরের কপি আর ভেতরের শেয়ার আলাদা

lab-এর লিস্ট shallow copy-তে শেয়ার হয়, তাই original-এও 25 দেখা যায়। বাইরের এন্ট্রি আলাদা বলে নতুন key শুধু copied-এ।

একটি ঘটনা করে frequency table বাড়াও

কোনো মান কতবার আসে সেটি frequency। ফাঁকা ডিকশনারি দিয়ে শুরু করো। প্রতিটি শব্দে আগের count পড়ো, না থাকলে শূন্য। এক যোগ করে একই শব্দের key-তে নতুন count রাখো।

pen, book, pen পড়লে pen-এ দুই, book-এ এক। দ্বিতীয় pen আগের এন্ট্রি বদলায়। key দুটি, ঘটনা তিনটি। value-গুলোর যোগফল পড়া শব্দের সংখ্যা হওয়ার কথা।

Dictionary comprehension iterable থেকে এক এক্সপ্রেশনে mapping বানায়। কোলনের আগে key, পরে value। শেষের শর্তে এন্ট্রি বাদ দেওয়া যায়, যেমন ছাড়ের জন্য শুধু বেশি দামের পণ্য রাখা।

তৈরি key আবার এলে পরের value থাকে। value আলাদা নয় এমন mapping উল্টাতে গেলে এই নিয়ম জরুরি। একই value-এর সব পুরোনো key রাখতে লিস্ট বানাও, শেষ অনুশীলনের মতো।

প্রতি ঘটনায় অল্প dictionary operation হয় বলে গোনার সময় গড়ে ঘটনার সংখ্যার সমানুপাতে বাড়ে। আলাদা key sort করতে তাদের সংখ্যার ওপর বাড়তি কাজ লাগে। সংগ্রহ আর দেখানোর খরচ আলাদা।

None নিজে সেভ করা value হলে fallback None দ্ব্যর্থক। পার্থক্য লাগলে আগে key in data দেখো, বা উন্নত ইন্টারফেসে আলাদা marker object নাও। get(key) is None মানেই key নেই, এমন নয়।

del data[key]-এ key থাকা চাই। pop এন্ট্রি সরিয়ে পুরোনো value ফেরায়; না থাকলে বিকল্পও দিতে পারো। get কিন্তু mapping বদলায় না। তাই কাজগুলো আলাদা প্রশ্নের উত্তর দেয়।

অনুপস্থিত key আর শেয়ার করা value বুঝে নাও

Count তৈরির আগেই বাড়ানো

counts[word] += 1 আগে counts[word] পড়ে। key শুরু না করলে প্রথমবার ব্যর্থ। get(word, 0) দিয়ে প্রথম আর পরের ঘটনা এক সহজ এক্সপ্রেশনে সামলাও।

ভুল পাশে খোঁজা

80 in marks দেখে 80 key কি না, কেউ 80 পেয়েছে কি না নয়। সেটি দেখতে marks.values() নাও। value-তে খোঁজা linear time হতে পারে, কারণ key-এর lookup ব্যবস্থা সেখানে নেই।

বাইরের কপিতে লিস্টও কপি হয় ভাবা

copy নতুন dictionary বানায়, কিন্তু value একই nested অবজেক্ট দেখায়। শেয়ার করা লিস্ট বদলালে দুটো mapping দিয়েই দেখা যায়। স্বাধীন দল চাইলে ভেতরের লিস্টও নতুন করো।

ঘোরার মাঝে এন্ট্রিসংখ্যা বদলানো

একই dictionary ঘোরার সময় key যোগ বা মুছলে RuntimeError হতে পারে। আগে বাদ দেওয়ার key সংগ্রহ করে পরে সরাও। আগের key-এর value বদলালে key-এর সংগ্রহ বড় হয় না, তবে দুই ধাপের কাজ পড়তে সহজ হতে পারে।

আধুনিক ডিকশনারিতে ক্রমের নিশ্চয়তা

Python 3.7 থেকে ঢোকানোর ক্রম ভাষার নিশ্চয়তা। এখানকার 3.10–3.12-এও আছে। dictionary view বর্তমান মানই দেখায়, আগের মুহূর্তের কপি নয়।

প্রশ্নের সঙ্গে মেলে এমন key নাও

অবস্থান খোঁজার বদলে অর্থপূর্ণ key ব্যবহার করো। ঘুরতে view, ছোট করে বানাতে comprehension, না-থাকা count-এ get নাও। এবার স্ট্রিং নিয়ে আরও কাজ-এ টেক্সট পরিষ্কার আর শব্দের অ্যালগরিদমে কনটেইনার লাগাও।
