মান হিসেবে একটা নিয়ম দাও

এক report শব্দ দৈর্ঘ্যে, অন্যটি শিক্ষার্থী mark-এ সাজায়। Sort-এর প্রক্রিয়া একই, তুলনার নিয়ম বদলায়। Higher-order ফাংশন আর্গুমেন্টে ফাংশন নেয় বা ফলে ফাংশন ফেরায়।

Python-এ ফাংশন অবজেক্ট। ভেরিয়েবল, কনটেইনারে রাখা, অন্য ফাংশনে পাঠানো যায়। বন্ধনী ছাড়া নাম অবজেক্ট বোঝায়; বন্ধনী কল করে তার ফল দেয়।

এতে কাজ আর চালানোর সময় আলাদা। Helper হিসাব নিয়ে কখন বা কতবার চালাবে ঠিক করে। চুক্তি সহজ রাখলে flexibility readability বাড়ায়।

ফাংশন পাঠাও, দরকারে কল

def double(number):
    return number * 2

def apply_twice(function, value):
    return function(function(value))

result = apply_twice(double, 5)

ফাংশন প্যারামিটার callable double পায়। আগে value-তে, তারপর মাঝের ফলে আবার চালায়। সাধারণ Python syntax-এ ফাংশন-valued parameter-এর আলাদা declaration নেই।

Callable বন্ধনী দিয়ে কল করা যায় এমন অবজেক্ট; এখানে প্রধান উদাহরণ ফাংশন। Helper-এ আর্গুমেন্ট-ফলের চুক্তি তবু চাই। apply_twice এক-আর্গুমেন্ট callable চায়, যার ফল আবার কলের উপযোগী।

double(5) পাঠালে callable নয় integer যাবে। Helper সেটিকে কল করে TypeError পাবে। Call site-এ বন্ধনী দেবে কি না ঠিক করার আগে গ্রহণকারী কী চায় দেখো।

একই প্রক্রিয়া আর বদলানো নিয়ম আলাদা

দুই দায়: বাইরের প্রক্রিয়া traversal, repetition বা ordering ঠিক করে; দেওয়া ফাংশন item-প্রতি হিসাব বা পরীক্ষা। Marks filter-এ traversal filter-এর, pass threshold predicate-এর।

Predicate এমন callable যার ফল truth টেস্ট-এ লাগে। Boolean return উদ্দেশ্য স্পষ্ট করে। ব্যাখ্যা লাগলে def body, পুরো rule ছোট হলে lambda।

চলে বলেই key ফাংশন-এ ইনপুট-প্রিন্ট লুকিও না। Sorting predictable comparison key দেবে। স্পষ্ট ইনপুট আর স্থির ফলের ফাংশন reusable tool-এ নিরাপদে পাঠানো সহজ।

C জানা থাকলে

Python ফাংশন পাঠানো C ফাংশন পয়েন্টার-এর মতো, তবে এখানে পয়েন্টার syntax লাগে না। Closure enclosing setting সঙ্গে নিতে পারে, global ভেরিয়েবল বা হাতে পাঠানো context structure কম লাগে।

বদলাও, বাছো, সাজাও আর configure করো

দেওয়া ফাংশনের contract আলাদা। map returned value, filter truth value, sorted key ব্যবহার করেও original item রাখে। Closure factory পরে ব্যবহারের configured rule ফেরায়।

Predicate দিয়ে মান বাছো

Predicate হ্যাঁ-না পরীক্ষার ফাংশন। ফল true হলে filter original মান রাখে। None দিলে মানের নিজের truthiness। Comprehension একই pass-selection rule বলে।

অর্থপূর্ণ key-তে record সাজাও

Key ফাংশন record-এর comparison value বানায়, returned record বদলায় না। Sort stable বলে সমান mark source order রাখে। Original list আগের ক্রমে।

আবার ব্যবহারযোগ্য threshold predicate ফেরাও

প্রতি factory call নিজস্ব enclosing limit-এর closure দেয়। পরে filter-এ পাঠানো যায়। Global লাগে না, দুই predicate ভিন্ন threshold রাখে।

Laziness আর stable order বোঝো

map এক বা একাধিক iterable-এর সংশ্লিষ্ট item-এ callable চালায়। কয়েক iterable হলে তত আর্গুমেন্ট নিতে হবে। Python 3.10–3.12-তে সবচেয়ে ছোটটি শেষেই iteration শেষ।

map আগে জমা list নয়, iterator ফেরায়। Iterator পরপর item দিয়ে কতদূর গেছে মনে রাখে। List করলে বাকি item consume হয়। একই exhausted iterator আবার list করলে empty।

filter-ও iterator। Predicate true হলে original item দেয়। Predicate-এর বদলে None truthy রাখে। Zero আর empty string-ও বাদ যায়, তাই সব false value বাদ চাইলে নাও।

ছোট transformation আর filter একসঙ্গে comprehension-এ পরিষ্কার হতে পারে। আগে named ফাংশন থাকলে map সুবিধা, যেমন parsing-এ int। কোনো spelling নিজে দামি অ্যালগরিদম দ্রুত করে না।

sorted-এর key ফাংশন প্রতি ইনপুট item-এ একবার comparison key পেতে চলে। ফলে original item-ই থাকে। কয়েক criteria হলে priority-র ক্রমে tuple component ফেরাও।

Python sorting stable: reverse=True-তেও equal key ইনপুটের আপেক্ষিক ক্রম রাখে। আগের অর্থপূর্ণ ক্রম tie-তে রাখতে ভালো। শর্তে অন্য tie rule থাকলে explicit secondary key।

Setting মনে রাখা নিয়ম ফেরাও

at_least factory enclosing limit পড়ে এমন nested ফাংশন বানায়। বন্ধনী ছাড়া accepts return করলে ফাংশন নিজে ফেরে। Caller রেখে পরে filter-এ দিতে পারে।

Factory শেষ হলেও closure defining binding পায়। আলাদা factory-তে আলাদা binding। তাই প্রতিবার global না বদলিয়েই pass আর distinction threshold পাশাপাশি থাকে।

Closure mutable অবজেক্ট-এর reference-ও রাখতে পারে। অবজেক্ট বদলালে পরের কল দেখে; frozen snapshot নয়। Rule live state পড়বে নাকি independent copy রাখবে স্পষ্ট বলো।

Lazy transformation error-ও দেরি করায়। পরের টোকেন invalid integer হলেও map(int, টোকেন) তৈরি হতে পারে। Consumer ওই টোকেন চাইলে conversion ব্যর্থ। শেখার সময় consumer কাছে রাখলে কাজ আর error-এর সময় বোঝা সহজ।

বারবার ব্যবহারে saved ডেটা নাকি saved recipe বেছে নাও। List করা মান আগেই হিসাব। নতুন map তৈরি করে এমন ফাংশন recomputation-এর recipe। মেমরি, changing ইনপুট আর আবার কাজ করা চলবে কি না-তে পছন্দ নির্ভর।
