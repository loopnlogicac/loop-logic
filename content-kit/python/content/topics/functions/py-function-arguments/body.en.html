Make the call explain its values

A receipt needs an item, a quantity and a price. Remembering the order is easy with three familiar values, but optional settings can make a call confusing. Python arguments let you supply values by position or by meaningful parameter names.

A function's parameter list is its interface: the agreement about what callers may supply. Good interfaces make common calls brief and unusual choices visible. Defaults handle ordinary cases, while keyword-only parameters can require clarity for options that are easy to confuse.

Argument binding happens before the body starts. If a required value is missing or a parameter receives two values, Python raises TypeError instead of guessing. These errors protect the agreement between the function and its callers.

Positions, keywords and defaults

def bill(quantity, unit_price=10, *, delivery=0):
    return quantity * unit_price + delivery

cost = bill(3, delivery=20)
other = bill(unit_price=15, quantity=2)

Positional arguments fill ordinary parameters from left to right. Keyword arguments use names, so their written order can differ from the definition. An ordinary positional argument must appear before ordinary named arguments in these straightforward calls.

A default supplies a value when its parameter is omitted. Explicit values override it, including zero, False or an empty string. Among ordinary positional-or-keyword parameters, required parameters cannot follow one with a default.

A bare star starts keyword-only parameters. They cannot be filled by position. A keyword-only parameter without a default is still required. This is useful for choices such as separator, strict mode or an output unit where a bare literal would be unclear.

Bind objects without copying them

Calls evaluate argument expressions and bind local parameter names to the resulting objects. Python does not automatically duplicate a supplied list. Reassigning a local parameter changes only that binding. Calling append through the parameter edits the shared list object.

Default expressions are evaluated when def runs. This rule is harmless for immutable values such as the integer 10. It becomes surprising when a list default is edited: omitted calls keep reaching the same saved list.

Use None as a marker when omission should create fresh state. Inside the body, test is None and then construct a list. Do not use a truthiness check for this purpose, because an explicitly supplied empty list is false but may be intentionally shared.

A caller who supplies a list should be able to predict whether it will change. State mutation in the docstring. If a function promises independence, copy the appropriate structure and remember that shallow copying does not duplicate nested mutable values.

If you know C

Python binds parameters to objects. Rebinding a parameter does not reassign the caller variable, but mutating a supplied list is visible to the caller. Unlike C function calls, Python supports named arguments and definition-time defaults without manual wrapper functions.

Require an explicit separator option

In the definition, stars collect arguments. In the call, *words expands the list and **options expands keyword entries. separator follows *words in the definition, so callers must supply it by name.

Collect extras and expand saved values

A parameter prefixed with one star collects extra positional arguments into a tuple. The conventional name is args, but any valid descriptive name works. A parameter prefixed with two stars collects extra keyword arguments into a dictionary, conventionally named kwargs.

Collection does not remove explicit parameters from the interface. If a function has label before *scores, the first supplied positional value binds label. Only remaining positional values enter scores. Named parameters already matched by the interface do not enter the extra-keyword dictionary.

The call side uses the same symbols for the opposite direction. One star expands an iterable into positional arguments; two stars expand a mapping into keyword arguments. The keys for keyword expansion must be strings. Duplicating a keyword across expansions raises TypeError.

An empty expanded list supplies no positional values. An empty expanded mapping supplies no keyword values. The function's ordinary required-argument rules still apply, so empty expansion does not make a required parameter optional.

Parameters after *args are keyword-only too. This lets a function accept many words while reserving separator as an explicit named setting. Keep such interfaces focused: accepting every possible argument without validation can hide spelling errors or incorrect assumptions.

A default can also capture a calculation earlier than intended. If a default expression calls another function, that call happens during definition. It does not happen anew whenever the argument is omitted. Move the calculation inside the body if each call needs a fresh result.

Before adding *args, ask whether callers naturally supply several separate values or already have one collection. A function accepting a list parameter may communicate the data model better than a variable-length signature. Expansion is useful when adapting an existing collection to a function whose interface genuinely takes separate arguments.

Flexible arguments do not replace validation. An arithmetic function may still require every collected value to be numeric. State that requirement and decide how unsupported option names are reported. Accepting arguments successfully only proves that binding worked; it does not prove that the supplied values make sense.

Defaults and flexible interfaces need care

Overwriting a caller's empty container

Using history = history or [] creates a new list when the caller supplies an empty list. That may violate an intended in-place interface. Test specifically for None so that omission and emptiness remain separate cases.

Giving one parameter two arguments

If the first positional value fills quantity, also passing quantity=2 is an error. Follow binding from left to right before considering extra arguments. Reading the function signature often resolves the error message immediately.

Hiding every option in kwargs

Explicit parameters document supported options. A broad **kwargs collection can accept a misspelled option silently unless the body checks it. Prefer named parameters for stable options and reserve extra keyword collection for a clear purpose.

Renaming a parameter can break keyword callers even when its position stays unchanged. Treat public parameter names as part of the interface. Good names clarify units and roles, such as unit_price rather than the vague value.

Portable argument binding

Keyword-only parameters, starred argument collection and call expansion shown here work on Python 3.10–3.12. A mutable default is shared by calls to the same function definition in all these versions.
