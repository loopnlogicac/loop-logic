কল দেখেই মানের অর্থ বোঝাও

রসিদে item, quantity আর price লাগে। তিন পরিচিত মানে ক্রম মনে রাখা সহজ, optional setting বাড়লে কল অস্পষ্ট। Python-এ position বা অর্থপূর্ণ parameter name দিয়ে আর্গুমেন্ট দিতে পারো।

Parameter list ফাংশনের interface: caller কী দিতে পারবে তার চুক্তি। ভালো interface সাধারণ কল ছোট, অস্বাভাবিক পছন্দ স্পষ্ট করে। Default সাধারণ case, keyword-only parameter সহজে গুলিয়ে যাওয়া option পরিষ্কার করে।

Body শুরুর আগেই argument binding। Required মান না থাকলে বা এক parameter দুই মান পেলে আন্দাজ না করে TypeError। এভাবে ফাংশন আর caller-এর চুক্তি রক্ষা হয়।

Position, keyword আর default

def bill(quantity, unit_price=10, *, delivery=0):
    return quantity * unit_price + delivery

cost = bill(3, delivery=20)
other = bill(unit_price=15, quantity=2)

Positional argument সাধারণ parameter বাম থেকে ডানে ভরে। Keyword-এ নাম লাগে, তাই লেখার ক্রম সংজ্ঞা থেকে আলাদা হতে পারে। এসব সরল কলে সাধারণ positional argument named argument-এর আগে আসবে।

Parameter বাদ দিলে default মান দেয়। Zero, False বা empty string-সহ explicit মান default বদলায়। সাধারণ positional-or-keyword parameter-এ default-ওয়ালার পরে required parameter আসে না।

একা star keyword-only parameter শুরু করে; position দিয়ে দেওয়া যায় না। Default না থাকলে keyword-only-ও required। Separator, strict mode বা output unit-এর মতো option-এ শুধু literal অস্পষ্ট হলে কাজে লাগে।

Copy না করে অবজেক্ট bind

Call argument expression হিসাব করে local parameter name-কে অবজেক্টে bind করে। দেওয়া list নিজে duplicate হয় না। Parameter reassign শুধু binding বদলায়; তার মাধ্যমে append shared list অবজেক্ট edit করে।

def চলার সময় default expression হিসাব হয়। Integer 10-এর মতো immutable মানে সমস্যা নেই। List default edit করলে চমক: argument বাদ দেওয়া কল একই saved list পায়।

বাদ দিলে fresh state চাইলে None marker। Body-তে is None দেখে list বানাও। Truthiness নয়, কারণ explicit empty list false হলেও ইচ্ছা করে share করা হতে পারে।

List দিলে সেটি বদলাবে কি না caller বুঝতে পারবে। Docstring-এ mutation বলো। স্বাধীনতার প্রতিশ্রুতি দিলে উপযুক্ত structure copy করো; shallow copy nested mutable মান duplicate করে না মনে রাখো।

C জানা থাকলে

Python parameter অবজেক্টে bind করে। Rebinding caller variable reassign করে না, কিন্তু দেওয়া list mutate করলে caller দেখে। C-র মতো manual wrapper ছাড়াই named argument আর definition-time default দেয়।

আসল কলে binding-এর সিদ্ধান্ত

Shared-default প্রোগ্রামের interface ইচ্ছা করে খারাপ, আচরণ তবু নির্ধারিত। None-ভিত্তিকটির সঙ্গে তুলনা করো। শেষ উদাহরণগুলো সংজ্ঞায় argument জড়ো আর কলে container expand আলাদা করে।

Position বা নামে কল

প্রথম কলে default unit price। Keyword কল লেখার ক্রম নয়, parameter name ধরে। একই কলে keyword option-এর আগে positional item থাকতে পারে।

Shared mutable default দেখো

Default list প্রতি কল নয়, def চললে তৈরি। তাই দ্বিতীয় কল আগের 12 দেখে। Explicit empty list আলাদা অবজেক্ট। Copied return value প্রতিটি stage স্পষ্ট দেখায়।

প্রতি কলে নতুন default list

History না দেওয়া None বোঝায়। প্রতিটি omitted call নতুন list। saved দিলে ইচ্ছা করে share হয়, তাই returned list আর saved দুটোতে 5 আর 25।

বাড়তি মান আর named option জড়ো

scores extra positional argument-এর টাপল, details extra keyword-এর dictionary। বাড়তি না থাকলে empty container। নাম প্রচলিত, star তাদের ভূমিকা ঠিক করে।

স্পষ্ট separator option চাও

সংজ্ঞায় star argument জড়ো করে। কলে *words list, **options keyword entry expand করে। সংজ্ঞায় separator, *words-এর পরে, তাই নামে দিতে হবে।

বাড়তি নাও, রাখা মান expand করো

এক star-এর parameter extra positional argument টাপলে নেয়। প্রচলিত নাম args, তবে যেকোনো বৈধ descriptive name চলে। দুই star extra keyword dictionary-তে নেয়, সাধারণ নাম kwargs।

জড়ো করলেও explicit parameter বাদ যায় না। *scores-এর আগে label থাকলে প্রথম positional value label-এ, বাকিগুলো scores-এ। Interface-এ matched named parameter extra-keyword dictionary-তে যায় না।

Call side-এ একই চিহ্ন উল্টো কাজ: এক star iterable-কে positional, দুই star mapping-কে keyword argument করে। Keyword expansion-এর key string হতে হবে। Expansion জুড়ে একই keyword দিলে TypeError।

Empty list expand-এ positional মান নেই, empty mapping-এ keyword নেই। Required-argument নিয়ম তখনও চলে; empty expansion required parameter optional করে না।

*args-এর পরের parameter-ও keyword-only। এতে অনেক word নিয়েও separator explicit named setting রাখা যায়। Interface focused রাখো: validation ছাড়া সব argument নিলে spelling error বা ভুল ধারণা লুকায়।

Default চাওয়ার আগেও হিসাব ধরে রাখতে পারে। Default expression অন্য ফাংশন কল করলে সেটি definition-এর সময়, প্রতিবার বাদ দিলে নয়। প্রতি কলে fresh result চাইলে body-তে হিসাব নাও।

*args যোগের আগে ভাবো caller স্বাভাবিকভাবে কয়েক আলাদা মান দেয় নাকি আগেই collection আছে। List parameter data model বেশি স্পষ্ট করতে পারে। Interface সত্যিই আলাদা argument নিলে রাখা collection adapt করতে expansion ভালো।

Flexible argument validation-এর বদলি নয়। Arithmetic ফাংশন collected সব মান numeric চাইতে পারে। শর্ত আর unsupported option name কীভাবে জানাবে বলো। সফল binding শুধু argument নেওয়া গেছে প্রমাণ করে, মানের অর্থ ঠিক নয়।

Default আর flexible interface-এ সাবধান

Caller-এর empty container বদলে দেওয়া

history = history or []-তে caller empty list দিলে নতুন list হয়। In-place contract ভাঙতে পারে। শুধু None দেখলে omission আর emptiness আলাদা থাকে।

এক parameter-এ দুই argument

প্রথম positional value quantity ভরলে আবার quantity=2 error। Extra argument-এর আগে বাম থেকে ডানে binding ধরো। Signature পড়লে প্রায়ই message বোঝা যায়।

সব option kwargs-এ লুকানো

Explicit parameter supported option বলে। Body check না করলে broad **kwargs ভুল বানানের option নীরবে নেয়। স্থির option-এ named parameter, স্পষ্ট উদ্দেশ্যেই extra keyword collection নাও।

Position না বদলালেও parameter rename keyword caller ভাঙতে পারে। Public name interface-এর অংশ। অস্পষ্ট value-এর বদলে unit_price-এর মতো নাম unit আর role বোঝায়।

Portable argument binding

Keyword-only parameter, starred collection আর call expansion Python 3.10–3.12-তে চলে। সব version-এই একই সংজ্ঞার কলগুলো mutable default ভাগ করে।

পড়েই বোঝা যায় এমন কল

স্পষ্ট required value position-এ, clarity-র জন্য keyword, বাদ দেওয়া choice-এ safe default, সত্যি variable-length দরকারে star। পরের scope আর lambda দেখাবে ফাংশনের ভেতরের নাম কোথায় খোঁজা হয়।
