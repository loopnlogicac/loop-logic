The same spelling can name different values

Two classrooms can each have a student called roll 12 without referring to the same person. Names in Python also belong to contexts. A scope is the region whose name bindings Python considers when resolving a name.

Functions keep temporary names close to their work. That prevents a helper calculation from accidentally replacing unrelated names elsewhere. Nested functions add another useful layer: an inner function can read settings belonging to its enclosing function call.

Scope explains why a value inside a function may differ from one printed outside it. It also explains several errors that look like arithmetic problems but are really name-binding problems. Draw the enclosing scopes when a name's source is unclear.

Redirect rebinding only when necessary

visits = 0

def record_visit():
    global visits
    visits += 1

By default, assignment to a name in a function makes that name local throughout the function body. Reading a local name before its binding exists raises UnboundLocalError. Python does not fall back to a global value after deciding that the name is local.

The global declaration directs bindings for a named variable to the module level. The nonlocal declaration instead selects an existing binding in an enclosing function scope. Put declarations before using the affected name in that function.

Neither declaration passes an argument or returns a value. They change where name binding happens. For many calculations, accepting a parameter and returning a result is clearer than changing state outside the function.

Look outward through LEGB

LEGB names the ordinary lookup order: Local, Enclosing, Global, Built-in. First search the current function's local names, including parameters. Then search surrounding function scopes. Next search the defining module, and finally Python's built-in names.

In the first program, inner has its own amount and local_fee. The name rate is absent locally but present in outer, so that value is used before the module-level rate. The name len is found among built-ins because no nearer scope replaces it.

A nested function remembers its defining environment, not the local variables of whichever function calls it later. This is lexical scope. The returned counter keeps access to count even after make_counter has returned, which forms a closure.

A closure is a function that retains access to enclosing bindings it uses. Each factory call can create separate state. Two counters created by separate make_counter calls therefore need not interfere, even though they use the same source definition.

If you know C

C block scope and Python function scope do not match exactly. Python for and if statements do not create ordinary new local scopes. A returned Python closure can retain enclosing bindings; you do not return a pointer to an expired C stack local.

Trace the binding each function reads

Before tracing a printed value, label each relevant name L, E, G or B. For an assignment, also ask whether global or nonlocal changes its destination. The answer often predicts the result without running every arithmetic step.

Use a lambda as a short ordering rule

The key function returns a pair: negative mark sorts high marks first, then roll breaks ties. The named lambda returns its single expression automatically. For a reusable named calculation, def is usually clearer than assigning lambda.

Write short functions without hiding their rules

A lambda expression creates a small function from parameters and one expression. Its syntax is lambda parameters: expression. The expression's value is the result; no return statement is written. A lambda can be useful when passing a short rule to sorted.

The sorted key argument expects a function that produces a comparison key for each item. A key tuple can express primary and secondary ordering. Returning negative mark and positive roll gives descending marks with ascending rolls for ties.

Assigning a complex lambda to a permanent name is usually less readable than def. A named definition supports a docstring and several clear statements. Use lambda when the complete rule fits comfortably inside the surrounding call.

Closures save access to bindings rather than frozen snapshots of every value. Loop-created functions that read number later all observe the final number binding. This behavior also affects inner functions created with def; it is not unique to lambda.

A default such as number=number captures the current object when the function is created. This can be suitable for immutable loop values. Remember the earlier default-argument rules if the captured object is mutable: saving its reference does not make it an independent copy.

Ordinary if and for statements do not introduce a new function-local scope. A name assigned inside an executed branch can still be read later in that function. If the branch never executes, that binding may never be created. Initialize a result before branching when every later path needs it.

The word global refers to the defining module, not an application-wide shared namespace. If two modules each define count, their functions normally refer to their own module bindings. Importing a function does not move its defining global namespace into the caller's module.

Nested functions can read an enclosing name without nonlocal. The declaration becomes necessary when the inner function must rebind that enclosing name. A read-only threshold closure therefore needs no declaration, while an incrementing counter does.

Distinguish name changes from object changes

Using global as a repair for every error

A global counter is useful for demonstrating binding, but widespread shared state makes calls harder to reason about. First consider whether the function should receive the old value and return the new value. That design makes dependencies visible.

Expecting nonlocal to find a module variable

nonlocal needs a surrounding function binding. If none exists, the definition is invalid. Use global for a module binding only when that mutation is an intentional part of the design.

Confusing mutation with reassignment

Calling append on a list reads its name and edits the reached object. Assigning a different list to that name rebinds it. Only rebinding needs the declaration that selects an outer scope.

Shadowing useful built-ins

A local variable named list or sum hides the corresponding built-in through ordinary lookup. Calling sum later may then attempt to call an integer. Choose names such as total or numbers instead of masking the tool you still need.

Scope follows definitions

LEGB lookup, nonlocal and lambda behavior described here works on Python 3.10–3.12. Ordinary loops keep their target binding in the surrounding scope; comprehensions use a separate target scope.
