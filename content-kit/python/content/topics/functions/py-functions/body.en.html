Give a useful calculation a name

If several canteen purchases need the same bill calculation, copying the calculation invites mistakes. A function gives those steps a name. You supply values, the function performs its work, and it can send a result back.

Functions help you think about one task at a time. A function named bill is easier to recognize than repeated multiplication mixed with input and printing. When the price rule changes, one well-chosen definition can serve every caller.

Start with small functions that answer one clear question. A function may return a number, a Boolean, a string or a container. The caller can then decide whether to display that answer, save it or use it in another calculation.

Define parameters and return a result

def bill(quantity, unit_price):
    """Return the total price in whole taka."""
    return quantity * unit_price

cost = bill(3, 20)

The def keyword starts the definition. The function name is followed by parentheses containing parameter names. A colon introduces the indented body. A parameter is a local name ready to receive a value when the function is called.

An argument is a value supplied by a call. In bill(3, 20), the arguments are 3 and 20. They bind to quantity and unit_price in order. Expressions used as arguments are evaluated before the body starts.

A docstring is the string literal at the start of the body. Explain the function's purpose, expected input and important special results. Triple quotes are a common convention even for a one-line description. Unlike an ordinary comment, the docstring is available through Python's documentation tools.

Follow one call from input to result

  1. Python evaluates the call arguments.
  2. A new call binds local parameter names to those values.
  3. The body executes until return or the end of the body.
  4. The call expression produces the returned object for its caller.

For bill(3, 20), quantity becomes 3 and unit_price becomes 20. Multiplication gives 60, and return sends 60 back. The assignment then binds cost to that returned integer. A local name such as total is useful inside the call but is not automatically a variable outside it.

The return statement ends the current function call immediately. Statements later in that path do not execute. An early return is useful for invalid input or an empty collection because it can avoid a dangerous calculation such as division by zero.

If you know C

Python does not declare return types or parameter types in this syntax. Reaching the end returns None, unlike relying on an unreturned C value. A comma-separated Python return packs a tuple, so you do not need output pointer parameters for a small group of results.

Return reusable results

Notice which output lines come from callers and which come from inside a function. The same numeric result can be printed, added or saved. A display-only function instead communicates by an action and commonly returns None.

Return a canteen bill

The definition stores the function without calculating a bill yet. Calling bill binds its two parameters and returns the product. The second result can take part in addition because it is a value, not printed text.

Return more than one measurement

The comma packs the two measurements into a tuple. The first call unpacks that tuple into low and high. The one-item input has the same minimum and maximum, so pair is (50, 50).

Separate printing from returning

announce displays Mark: 80 but reaches the end without return, so its result is None. Saving a printed function result does not capture the displayed text. The identity check confirms the default return value.

Leave early when a calculation is unavailable

The empty list follows an early return before division. The nonempty list returns 80.0. Testing is None distinguishes an unavailable result from a valid numeric zero.

One call can return a group or no useful result

Returning multiple values normally means returning one tuple. The expression return low, high packs a pair. The caller can unpack that pair into two names or retain it as one object. The number of unpacking targets must match the result shape.

A function always produces a return value. Reaching the end gives None, and a bare return also gives None. None is a special object representing absence of a useful value. It is different from zero, an empty string and an empty list.

Printing is a separate action. Saving announce(80) saves the return value, not the characters displayed during the call. If a later calculation needs the mark, return the mark. If the purpose is displaying a message, name the function accordingly.

Document an optional result such as a mean of an empty sequence. The caller should test is None before numeric use. This makes the empty case visible instead of inventing a misleading average.

Make the function contract clear

Forgetting to call the function

The name bill refers to a function object; bill(3, 20) calls it. Parentheses matter. Function objects can be stored for later use, a topic developed in higher-order functions.

Returning only on one path

If one branch returns a number but another reaches the end, callers may unexpectedly receive None. Read every possible path and decide what result belongs there. Consistent documented results are easier to use.

Expecting local reassignment to change the caller's name

Parameters are local bindings. Assigning a new value to a parameter changes that local name. Editing a shared list through the parameter can change the caller's object. The arguments lesson explains this distinction alongside defaults.

Definitions and documentation

The def, return and docstring rules shown are stable on Python 3.10–3.12. Type annotations are optional and are taught separately; these functions use ordinary runtime values.

Name one task and state its result

Use def to collect a task, docstrings to describe its contract and return to deliver its answer. Decide explicitly how empty or unavailable results behave. Next, function arguments offer more ways to supply values without hiding that contract.
