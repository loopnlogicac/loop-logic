Build a small tool with persistent state

An expense tracker combines several Python skills around one useful question: where did the money go? You will build a menu-driven command-line program that adds expenses, summarizes categories and exports CSV. JSON keeps the records between runs. This is a small, local learning project for one user.

The project uses functions and dictionaries rather than a large class hierarchy. Each function has one responsibility: parsing, validation, storage, aggregation or interaction. That separation lets you check calculations without navigating the menu and check file handling without typing every command again.

Keep the smallest useful record

Each record has exactly two fields: category and paisa. category is normalized with strip and casefold so Food and food share a group. It must contain one to forty printable characters after normalization. Spaces and commas are allowed, which makes correct CSV quoting necessary.

paisa is a positive integer from one through 1000000000. The limit corresponds to ten million BDT per expense. Storing the smallest accepted money unit avoids decimal approximation during addition. The display function uses integer division and a two-digit remainder, so 1050 paisa appears as 10.50.

Amount text accepts digits with an optional one- or two-digit decimal part. Thus 10, 10.5 and 10.50 describe the same amount. Negative values, zero, scientific notation, nonfinite words and fractions of a paisa are rejected. The contract intentionally excludes refunds; supporting them would require a deliberate revision.

Separate commands from their calculations

The menu offers four choices: add, summary, export and quit. Add asks for category and amount, then validates both. Summary groups the stored paisa amounts and displays categories in sorted order. Export writes category and amount_bdt columns to expenses.csv beside the JSON file.

An unknown choice prints a short message and shows the menu again. End of input exits cleanly, including when an add command is unfinished. Input that has not produced a fully valid record never reaches storage. The program catches expected input and file errors while leaving programming defects visible.

The default JSON filename is expenses.json in your current folder. You can choose another path with --path, such as python tracker.py --path records.json after saving the full program as tracker.py. The parent folder must already exist. Export replaces the fixed sibling expenses.csv file, so use a dedicated project folder.

Build from totals to a complete interface

Summarize exact paisa values

Ten taka fifty paisa plus nineteen taka seventy-five paisa gives 30.25 BDT. Integer addition keeps every paisa.

Round-trip JSON and quote a CSV category

JSON preserves integer paisa. The CSV writer quotes a category containing a comma, so reading it restores one field.

Run the complete menu and persist each addition

Add food and travel expenses, read the category summary, export CSV, then quit. The default storage files live in the current folder.

Validate before replacing the saved record list

Startup distinguishes a missing JSON file from an unreadable or invalid one. Missing storage begins with an empty list. Invalid existing storage prints a failure and stops, preserving the existing bytes for investigation. Silently replacing corrupt data with an empty list would hide a problem and risk losing records.

JSON decoding proves only that the file has valid JSON syntax. validate_records checks that the top-level value is a list, every item is a dictionary, and the key set is exactly the expected pair. It also checks category normalization and exact integer paisa bounds.

Python's bool is a subclass of int, so isinstance(True, int) is true. A stored true value is not a valid one-paisa expense here. type(paisa) is int enforces the precise field contract. This is a domain-specific reason for exact type checking; most general Python interfaces should accept compatible behavior instead.

When adding an expense, the program builds candidate = records + [new_record]. It does not append to the live list first. After save_records returns successfully, records is rebound to the candidate. If saving fails, the previous list still drives the current summary.

save_records creates a temporary file in the destination's own folder. It writes and closes that file before replacing the destination. Creating the temporary file beside the destination avoids a cross-filesystem move in ordinary use. Finally cleanup removes a leftover temporary file if replacement did not complete.

This pattern reduces exposure to a partially rewritten JSON destination. It does not provide concurrent-writer coordination or a guarantee that every completed write survives sudden power loss. The project does not call fsync or implement transactions. Use a database and a stronger design when those requirements matter.

Use a parser and writer that understand fields

The JSON file is the saved application state. CSV is an export for a spreadsheet or another report. Do not treat the two formats as interchangeable by splitting lines or changing the filename extension. Each format has its own parser and quoting rules.

csv.writer handles a category such as food, campus by quoting the complete field. newline="" lets the CSV module control line endings, and explicit UTF-8 preserves text. The amount_bdt field is a formatted decimal string for a reader; exact integer paisa remains the JSON storage representation.

An empty tracker can still export the header row. Export failure prints a file-operation message without changing the JSON records. CSV export is a direct write, so a failure could leave a partial CSV. Export can be repeated; it does not replace the authoritative JSON state.

Exercise transitions across separate runs

Start in an empty project folder. Request a summary and confirm No expenses followed by Total 0.00. Add food for 10.50 and food for 19.75. Their category total must be 30.25, including after quitting and restarting with the same path.

Try 1.001, zero and a negative amount. Each should be rejected without adding a record. Try an empty category separately; that rejection occurs before an amount is requested. Finally, use a comma-containing category and read the export with csv.reader to confirm its field boundary.

Copy the JSON into a disposable folder before experimenting with corruption. Replace its list with an object, remove a required key or use true as an amount. Startup should report an error and preserve the file. To investigate a save failure, use a controlled test that makes replacement fail and confirm that Added never appears.

Protect the meaning of a successful command

Printing success before persistence completes

That message promises data was stored even if the write fails later. Publish the new list and success message only after save_records succeeds.

Converting decimal text through float

Binary floating-point can approximate a decimal before conversion to paisa. Parse the accepted text with Decimal and enforce at most two decimal places before making an integer amount.

Using one broad handler to reset storage

A read failure is not evidence that the user wants an empty history. Preserve the original file and report the issue. Only FileNotFoundError selects the empty starting state.

Keep the project small enough to explain

The complete tool joins exact money, validated records, file cleanup and menu interaction. You can extend it with dates or deletion after defining their contracts and tests. Finish the track with Python interview questions, where these design choices become short explanations.
