উত্তরের আগে execution বোঝাও

লিখিত Python পরীক্ষায় method name মনে রাখাই সব নয়। Shared অবজেক্ট trace, control-flow ব্যাখ্যা বা নির্দিষ্ট statement থেকে প্রোগ্রাম লিখতে হয়। এই bank-এ তিন যুক্তি একসঙ্গে চর্চা করো।

পাঁচ executable আউটপুট trace, conceptual ব্যাখ্যা, সম্পূর্ণ code-writing answer আর টেস্ট-design task আছে। আগে answer ঢেকে prediction আর কারণ লেখো, দুটো মেলাও। কারণ ছাড়া সঠিক আন্দাজ অন্য প্রশ্নে কাজে লাগানো কঠিন।

নাম থেকে অবজেক্টে তির আঁকো

List-পিছু এক box, ভেরিয়েবল name থেকে তির। Assignment নতুন box ছাড়া তির যোগ করতে পারে। Slice নতুন outer list, nested value shared হতে পারে। Mutation বা rebinding-এর ঠিক line-এ ছবি বদলাও।

Generator-এ কী consumed রাখো। list(generator) একইটিকে exhaustion পর্যন্ত এগোয়, পরে চাওয়ার unconsumed original রাখে না। Dictionary-তে insertion order আর key replacement value arithmetic থেকে আলাদা।

Try-finally-তে pending outcome ধরো: normal,return,exception। সেটি শেষের আগে cleanup। Finally-র return outcome বদলাতে পারে, প্রথম return জিতবে না ধরে block দেখো।

Contract ঘিরে উত্তর

আগে accepted ইনপুট আর required আউটপুট। ভাগ বা প্রথম item-এর আগে empty-র অর্থ। Shared score-এ tie rule। Valid ইনপুট promise হলে আউটপুট ভাঙা prompt নয়।

প্রোগ্রাম চাইলে main guard-সহ পুরোটি। ফাংশন চাইলে parameter আর return meaning। Helper print ছাড়া মান দিতে পারে; calculation-ইনপুট আলাদা হলে টেস্ট সহজ।

State-এর নাম আর update কেন উত্তর রাখে বোঝাও। Bound জরুরি হলে time-মেমরি। Filtered mean-এ selected total আর count দুটো, denominator-এ ভুল বেশি।

ভুল দেখে পরের practice

Alias-এ অবাক হলে list আবার reference আঁকো। Generator-এ iteration আবার এক মান করে এগোও। Final line মুখস্থের চেয়ে focused correction বেশি শেখায়।

টেস্ট-এ competing implementation আলাদা case। 39-40 strict-inclusive cutoff, all-negative list nonempty maximum আর ভুল empty result আলাদা। প্রতিটি case কোন ভুল ধরে বলো।

প্রতি line-এর কারণ দিতে তৈরি

অবজেক্ট change trace, ইনপুট promise আর হিসাবের কারণ বলো। পরের expense tracker-এ validation আর saved state কয়েক command-জুড়ে মেলাও।
