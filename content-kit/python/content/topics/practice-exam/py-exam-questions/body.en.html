Explain the execution before naming the answer

A written Python exam checks more than whether you remember a method name. You may need to trace shared objects, explain a control-flow path or write a short program from a precise statement. Use this question bank to practice those three forms of reasoning together.

The answered questions include five executable output traces, conceptual explanations, complete code-writing answers and a test-design task. Cover the answer first. Write your predicted result and a short reason, then compare both. A correct guess without a reason is harder to reuse in a different question.

Draw names pointing to objects

For list questions, draw one box per list and an arrow from each variable name. Assignment can add another arrow without creating another box. A slice creates a new outer list, while nested values may still be shared. Update the diagram at the exact line where mutation or rebinding occurs.

For generators, record which values have already been consumed. list(generator) advances that same generator until exhaustion. It does not preserve an unconsumed original for later calls. For dictionaries, keep insertion order and key replacement separate from value arithmetic.

For try and finally, track the pending outcome: normal continuation, return or exception. Cleanup executes before that outcome completes. A return inside finally can replace the pending outcome, so inspect that block rather than assuming the first visible return wins.

Build an answer around the contract

In code-writing questions, identify the exact accepted input and the required output first. Decide what an empty collection means before dividing or selecting its first value. State a tie rule when two records can share a score. If input is guaranteed valid, do not add prompts that violate the specified output.

Write a complete program with a main guard when asked for a program. When asked for a function, give its parameters and return meaning clearly. A helper can return a value without printing; keeping calculation separate from input makes it easier to test.

A clear explanation names the state and gives the reason an update preserves the intended answer. Add time and memory cost when bounds matter. For a filtered mean, explain both the selected total and the selected count, since the denominator is a common source of mistakes.

Use errors to choose the next practice task

If an alias trace surprised you, revisit lists and draw the shared references. If a generator trace surprised you, revisit iteration and advance one value at a time. A focused correction teaches more than memorizing the final printed lines.

For tests, choose cases that distinguish competing implementations. The pair 39 and 40 separates a strict cutoff from an inclusive one. An all-negative list separates a nonempty maximum from an incorrectly allowed empty result. Explain the particular mistake each case would reveal.

Prepare to defend each line

Trace object changes, state the input promise and justify the calculation. Next, combine these habits in the expense tracker project, where input validation and saved state must work together across several commands.
