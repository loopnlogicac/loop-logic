কোডে resource lifetime স্পষ্ট

ফাইল খুললে close-এর দায়। মাঝের হিসাব আগে return বা exception তুলতে পারে। Context manager block ঘিরে entry-exit গুছিয়ে lifetime দেখায়। with সেই protocol ব্যবহার করে।

ফাইল ছাড়াও temporary setting, lock বা matching finish লাগে এমন কাজে চলে। জোড়া কাজ: state-এ ঢোকো, কাজ করো, বেরোও। মাঝের কাজ failed হলেও জোড়া একসঙ্গে।

ভেতরের সব change নিজে undo নয়। ফাইল manager stream close করে, overwritten content ফেরায় না। Transaction manager rollback শুধু নিজস্ব contract বললে। with মানে সব reversal না ধরে exit আচরণ বলো।

Manager নিয়ে entered value bind

with expression as name-এর পরে indented block। Expression থেকে manager, তারপর entry। as __enter__-এর return পায়, manager নিজে নাও হতে পারে।

class Session:
    def __enter__(self):
        print("open")
        return "ready"

    def __exit__(self, exc_type, exc_value, traceback):
        print("close")
        return False

with Session() as state-এ state ready string। Exit-এর দায় manager-এর। Entered value না লাগলে as বাদ। Resource operation manager-এ হলে self ফেরানো প্রচলিত, বাধ্যতামূলক নয়।

Exit-এ self-এর পরে তিন exception argument। Normal end-এ সব None। Exception ছাড়লে type, value, traceback। Cleanup আর promised handling-এ যত লাগে নাও।

Entry, body আর exit ধরো

__enter__ সফল হলে block চলে, normal Python flow-এ ছাড়ার সময় __exit__, return বা exception-সহ। Block error চলবে কি না exit ঠিক করে। False বা None সাধারণত propagate।

Truthy exit block exception suppress করে; with-এর পরে handled-এর মতো চলে। ক্ষমতা বড়, ভুল সহজ। শুধু resource close হলে False/None, caller error দেখুক।

__enter__ raise করলে block শুরু নয়, ওই manager-এর __exit__-ও নয়। Entry-তেই আগে নেওয়া resource ছাড়তে হবে। কখনো না ফেরা partial entry ঠিক করতে exit-এ নির্ভর নয়।

manager expression হিসাব
    |
__enter__ সফল --> as target bind --> block চালাও
                                        |
                                    __exit__
                         false/None: error চালাও
                         true: block error suppress

C জানা থাকলে

C-তে failure cleanup লেবেল-এ যেতে পারে। Python manager paired entry-exit এক জায়গায়। Acquisition তবু সাবধানে, abrupt termination-এর পরে cleanup নিশ্চয়তা নয়।

Normal আর exceptional exit

ক্লাস manager entry-exit প্রিন্ট। দ্বিতীয়তে cleanup-এর পরে error চলে। Narrow manager এক category suppress। Generator-based contextlib temporary state ফেরায়।

আলাদা entered value ফেরাও

__enter__ Session নয় ready দেয়। Normal completion-এ exception type নেই, exit True প্রিন্ট করে।

Cleanup করেও error রাখো

Manager cleanup করে False। ValueError outer handler-এ, cleanup-এর পরে প্রিন্ট।

শুধু বাছা category suppress

ইচ্ছা করে KeyError suppress। অন্য category-তে condition false, propagate।

Failure-এর পরে setting ফেরাও

Yield করা dictionary block-এ exam দেখায়। Outer handler পড়ার আগে finally captured normal ফেরায়।

Nested resource-এর ক্রম

A আগে, B পরে খোলে। Block একবার, তারপর B আগে A পরে close, nested ownership মেনে।

এক yield-এ block boundary

contextlib.contextmanager generator ফাংশন-কে manager factory করে। Yield-এর আগে entry, yielded value as target। Block শেষে yield point-এ resume করে exit।

Success-failure দুইটিতে cleanup চাইলে yield try/finally-তে। Block error yield-এ generator-এ ফেরে। Propagate-এর সময়ও finally। শুধু yield-এর পরের code failure-এ বাদ যেতে পারে।

ঠিক একবার yield চাই। না করলে entry boundary দেয় না, error। দ্বিতীয় yield exit-এ শেষ হয়নি বলে error। আলাদা with-এ আলাদা invocation।

Generator ভেতরে block exception catch করে normal finish করলে suppress। শুধু log চাইলে re-raise। __exit__-এর মতো suppression contract চাই। Yield ঘিরে broad except caller-এর unrelated bug ঢাকতে পারে।

Decorator এখানে generator ফাংশন process করে with-এর protocol অবজেক্ট বানায়। আগের generator আর decorator ধারণার ব্যবহার।

খোলার উল্টো ক্রমে close

Nested with outer আগে, inner পরে; exit inner আগে outer পরে। এক with-এ কয়েক manager-ও একই nesting। এক resource অন্যটির ওপর নির্ভর করলে জরুরি।

Inner entry fail হলেও সফল outer exit করে। Failed inner নিজস্ব partial acquisition সামলাবে। কোন entry সম্পূর্ণ হলো অনুযায়ী দায় আলাদা।

Stream ফাংশনে দিলে ownership স্পষ্ট। Caller খুলে থাকলে আবার ব্যবহার চাইতে পারে। Borrowed stream helper close করলে contract ভাঙে। Transfer document বা opener-ই with সামলাক।

Manager অন্য resource ফেরাতে পারে: controller bookkeeping own, __enter__ open stream দেয়। as resource, original manager-ই __exit__ পায়। Target-এর API না চাইলে নিজে exit ডেকো না।

কেউ reusable, কেউ single-use। Generator-based manager অবজেক্ট সাধারণত একবার; fresh-এর জন্য factory আবার ডাকো। একই অবজেক্ট অন্য নামে দিলে নতুন lifecycle নয়।

Temporary state-এর টেস্ট-এ old value ধরে নতুন বসিয়ে finally-তে সেই old ফেরাও, আন্দাজের default নয়। Nested setting প্রতিটি level-এর দেখা state-এ ঠিকমতো ফেরে।

Cleanup-এর নিশ্চয়তার সীমা

with structured control flow। Normal path-এ exit, কিন্তু force kill বা power loss-এর পরে নয়। ফাইল close মানেই multi-ফাইল update atomic নয়। আলাদা নিশ্চয়তা।

Cleanup-ও fail করে। __exit__ নতুন exception তুললে সেটি immediate, original context-এ থাকতে পারে। Exit focused, unrelated হিসাব-format নয়। Independent বহু resource-এ ExitStack সাহায্য করে, পাঠের বাইরে।

Setting-এর ownership-concurrency অনুমতি থাকলেই temporary manager। এক thread-এর global change অন্যটি দেখতে পারে। এখানে local dictionary আর sequential code-এ restoration স্পষ্ট। Manager নিজে synchronization নয়।

Entry failure আর block failure আলাদা

Successful entry-র পরে raise exit পরীক্ষা। Entry raise-এ block শুরু নয়, exit নেই, আলাদা boundary। কয়েক resource নিলে দুইটিই টেস্ট, কোন acquisition সফল ছিল রাখো, সেগুলোই ছাড়ো।

Cleanup-only টেস্ট-এ block-এ পরিচিত ValueError, exit চলেছে record, একই error outer-এ মেলে। Cleanup আর propagation দুটো দেখা। Normal-only টেস্ট accidental truthy exit-এ সব error লুকানো ধরবে না।

Restoring manager-এ ভেতর-পরে মান, তারপর error-সহ আবার। Nested হলে আগে outer temporary, শেষে original। Private local name ছাড়াই public rule যাচাই।

Exit behavior বলো

সব __exit__-এ True

Block failure লুকায়। Cleanup-only-তে False। ইচ্ছা করে handled category-ই suppress, পরে caller কী ধরবে বলো।

as সবসময় manager ভাবা

__enter__ return-ই value। Return না থাকলে None। Manager-ই resource interface হলেই self।

Unprotected yield-এর পরে cleanup

Block error ordinary post-yield বাদ দেয়। Required restoration yield ঘিরে finally-তে।

Failed entry-র পরে exit ভরসা

__enter__ fail হলে __exit__ ডাকে না। Re-raise-এর আগে entry-তে partial acquisition undo।

আগে synchronous protocol

with আর contextlib.contextmanager Python 3.10–3.12-তে। Async-এ async with, __aenter__, __aexit__ আলাদা। উদাহরণে exception group বা নতুন suppression behavior লাগে না।

Acquisition-এর সঙ্গে স্পষ্ট exit policy

Manager entry, entered value আর exit handling বলে। ইচ্ছা না হলে failure রাখো, generator cleanup finally-তে। পরের type hint intended interface বলে static analysis-এ সাহায্য করে।
