দরকার হলেই পরের মান চাও

Marks ফাইলে লাখ লাখ line হলেও running total-এ একবারে এক mark লাগে। Iterator চাওয়ামতো পরের মান দেয়, কতদূর এসেছে তার state রাখে। পুরো list আগে না বানিয়ে বড় stream process করা যায়।

Iterable থেকে iterator পাওয়া যায়। List, string, ফাইল অবজেক্ট iterable। Iterator-ও iterable, তবে সাধারণত চলমান এক pass। Source আর বর্তমান pass আলাদা বুঝলে অপ্রত্যাশিত empty ফল বোঝা যায়।

Generator yield-সহ ফাংশন বা generator expression-এর সুবিধাজনক iterator। থেমে থাকা execution state Python রাখে। কোড মান তৈরির নিয়ম বলে, consumer কত মান চাইবে বাছে।

iter, next আর yield

iter(source) iterator দেয়। next(iterator) মান চায়, exhausted হলে StopIteration। next(iterator, default) তখন default দেয়। পার্থক্য জরুরি হলে valid item-এর সঙ্গে না মেশা default।

def squares(limit):
    for number in range(limit):
        yield number * number

values = squares(3)
first = next(values)
remaining = list(values)

yield থাকায় squares(3) কল লুপ না চালিয়ে generator ফেরায়। প্রথম next body শুরু। প্রতি yield এক মান দিয়ে থামে। পরের next local ভেরিয়েবল রেখে ঠিক yield-এর পরে চালায়।

Generator expression বন্ধনীতে: (mark * 2 for mark in marks)। List comprehension square bracket-এ সঙ্গে সঙ্গে পুরো ফল। দুটো transform-filter পারলেও timing-reuse আলাদা। গোল বন্ধনী tuple comprehension নয়, generator।

for-কে protocol ধাপে পড়ো

for source-এ iter, বারবার next, StopIteration-এ স্বাভাবিক শেষ করে। তাই list, ফাইল, range, custom iterator-এ একই syntax। আলাদা লুপ নয়, type protocol দেয়।

Custom iterator-এর __iter__ নিজেকে, __next__ পরের মান ফেরায়, শেষে StopIteration। Current position iterator-এ রাখো। Fresh iterator দেওয়া iterable independent pass দেয়, নিজেকে দেওয়া iterator একই pass।

consumer: next(g) ---> yield পর্যন্ত চালাও ---> মান
consumer: next(g) ---> yield-এর পরে চলো  ---> মান
consumer: next(g) ---> ফাংশন শেষ        ---> StopIteration

Generator-এ return শেষ করে। Completion বলতে body থেকে explicit StopIteration তুলবে না, বের হওয়া error আধুনিক নিয়মে RuntimeError। সাধারণ return বা শেষই সঠিক।

C জানা থাকলে

C লুপ-এ index হাতে রাখো। Iterator __next__-এর পেছনে progress রাখে। Generator yield-জুড়ে local state-ও রাখে, প্রতি pause-এর state structure হাতে লাগে না।

কখন আবার চলে দেখো

Countdown-এ protocol সরাসরি, yielding ফাংশন-এ কম bookkeeping। অন্যগুলো partial consumption, delayed effect আর endless source-এর bounded view দেখায়।

Countdown iterator বানাও

প্রথম next 3 নেয়। List 2 আর 1 নেয়, তারপর supplied default exhaustion জানায়।

Yielding square ফাংশন থামাও

প্রথম request zero। বাকি 1,4,9 নেয়; একই generator exhausted বলে পরের traversal empty।

Delayed execution দেখো

তৈরিতে body কিছু print করে না। প্রথম request start, দ্বিতীয় resume করে resume প্রিন্ট।

Result list ছাড়া filter আর sum

Generator sum-কে 40,75,90 দিয়ে 205। Sum exhaust করে, পরের list empty।

Endless source সীমিত

islice প্রথম চার multiple নেয়। এরপর generator তিন থেকে নয়, 15 থেকে চলে।

তৈরির সময় আর request-এর সময়

Lazy evaluation consumer চাওয়া পর্যন্ত হিসাব পেছায়। Generator বানালেই সব square হয় না। Result storage বাঁচে, না চাওয়া কাজ এড়াতে পারে। প্রতিটি requested calculation সস্তা নিশ্চিত নয়।

Timing-এ effect আর failure বদলায়। Body-র print resume-এ, কলের সময় নয়। Bad conversion iteration-এ উঠতে পারে। ঝুঁকির কাজ consumption-এ হলে সেখানেই handling।

Generator expression তৈরিতেই outermost iterable expression evaluate, iteration আর result পরে। সব কাজ delay করে বলবে না। সাধারণ list source-এ মূল বিষয় transformed result on demand।

Referenced mutable ডেটা consume-এর সময় দেখে, snapshot নয়। Request-এর মাঝে list বদলালে পরে ফল বদলায়। Stable snapshot চাইলে উপযুক্ত copy, মেমরি খরচ মেনে।

Lazy pipeline মেলে: valid mark filter, convert, sum। প্রতি stage পরেরটিকে এক item দেয়। Readable রাখো; বহু validation-branch হলে nested expression-এর চেয়ে named generator ভালো।

এক pass ভাবো, infinite কাজ বেঁধে দাও

list, sum, max আর লুপ consume করে। Exhausted generator আবার list empty। আরেক pass-এ ফাংশন থেকে recreate, বা repeated-use দরকারে list রাখো।

এক generator-এর দুই নাম position ভাগ করে। যেকোনো next একই অবজেক্ট এগোয়। বিপরীতে iter(a_list) দুবারে independent iterator। List reusable, প্রতিটির progress নিজস্ব।

Infinite counter উপকারী, তবে list স্বাভাবিক শেষ নয়। Finite লুপ, break বা islice-এ বেঁধে দাও, termination কোথায় বলো। Infinite filter-এ আর কোনো মান pass না করলে চিরকাল খুঁজতে পারে।

Suspended generator local reference রাখে। Local বড় অবজেক্ট মেমরি ধরে। Lazy মানে zero মেমরি নয়; state আর source ফলের list না থাকলেও বড় হতে পারে।

Resource-ও ভাবো। with-এর ভেতর line yield করা generator suspended-এ ফাইল খোলা রাখতে পারে। Exhaust বা close cleanup দেয়, তবে early-stop consumer ownership বুঝে সামলাবে। Context-managed outer কাজ lifetime সহজ করে।

Indexing, repeated traversal বা stable finite snapshot-এ list। এক-pass বা বড় stream-এ generator। সবসময় একটাই দ্রুত দাবির বদলে access requirement দেখো।

দুই pass আর shared cursor তুলনা

তিন mark-এর list-এ iter দুবার করো। প্রথম এগোলে দ্বিতীয় এগোয় না। এক generator দুই নামে দিলে একইটি এগোয়। পার্থক্য iterator অবজেক্ট count, ভেরিয়েবল name count নয়।

এক match পেয়েই consumer থামলে পরের কাজ বাঁচে। Passing mark generator-এ next প্রথম pass-এ থামে। কেউ pass না করলে পুরো finite ইনপুট দেখে default। Laziness কখন কাজ আর unused কাজ এড়াবে বদলায়, condition-এর correctness নয়।

max বা next-এর আগে empty ভাবো। Empty integer sum zero, max default ছাড়া ValueError, next default ছাড়া StopIteration। Problem-এর empty rule consumer-এ লেখো।

Debug-এ live generator list করে print করলে state বদলায়, পরে আবার consume আশা কোরো না। আলাদা generator inspect বা ইচ্ছা করে একবার materialize করে list পাঠাও।

Progress ধরো, আন্দাজ নয়

দ্বিতীয় পুরো traversal আশা

Generator এক-pass iterator। sum(g)-এর পরে exhausted। আবার বানাও বা একবার materialize।

Yield-এর বদলে list return

List return-এ আগে সব ফল। yield-সহ ফাংশন generator দেয়। শেষে list(generator) মিললেও interface-এর timing আলাদা।

পুরো লুপ body ঘিরে exhaustion ধরা

সাধারণত for StopIteration সামলাক। Manual next হলে নির্দিষ্ট handling, যেন unrelated error normal completion না লাগে।

Unbounded stream list

Materialize-এর আগে consumer bound। islice(source, 5) সর্বোচ্চ পাঁচ চায়, list(source)-এ সীমা নেই।

আধুনিক exhaustion rule

আচরণ Python 3.10–3.12-তে। Generator body থেকে StopIteration বেরোলে RuntimeError; ordinary __next__ স্বাভাবিকভাবে StopIteration তোলে। send, throw আর async iteration আলাদা protocol, একমুখী stream-এ দরকার নেই।

Generator থামানো এক-pass হিসাব

Iterator protocol consumer-কে পরপর মান দেয়। yield progress রাখে, lazy pipeline সব ফল জমায় না। Consumption ধরো, infinite source বেঁধে দাও। পরের decorator ফাংশন value দিয়ে call ঘিরে আচরণ যোগ করে।
