Describe the shape of text instead of one exact word

A course code may contain three uppercase letters followed by three digits. Testing one exact code does not check that shape. A regular expression, often called regex, describes a text pattern. Python's re module can search for it, extract matching parts or replace them.

A pattern is a small language with its own rules. Brackets, dots and repetition signs can have special meanings. Learn a few constructs and combine them carefully rather than memorizing a long expression you cannot explain. A readable pattern should state the intended input policy.

Regex is useful for structured text fragments, such as course labels inside a message. It is not the best tool for every text problem. Use str.replace for a fixed replacement, split for simple whitespace words and dedicated parsers for CSV or JSON. Pattern matching does not replace domain validation.

Build patterns from literal and special characters

Import re and pass a pattern plus the text to a search function. Prefer a raw string literal such as r"[A-Z]{3}[0-9]{3}". The r prefix reduces Python's interpretation of backslashes, leaving regex escapes for the pattern engine. It does not turn off regex syntax.

To match a literal dot, escape it in the regex, for example r"a\.b". For arbitrary literal text supplied as a value, re.escape prepares it as a literal pattern. Escaping for regex and escaping a Python string are different layers; raw strings help keep those layers visible.

Choose the matching boundary first

re.search scans for a match anywhere in the text. re.match attempts a match only at the beginning. Neither automatically requires the whole string to match. re.fullmatch is the clearest choice when validating an entire short label such as one course code.

A successful search returns a match object; failure returns None. Check that result before calling group. group(0) is the whole matched text, while span returns start and end positions. The end position is exclusive, matching ordinary Python slicing conventions.

re.findall collects matching results without returning match objects. With no capturing groups it returns full-match strings. With one capturing group it returns that group's strings. With several capturing groups it returns tuples of captured strings. Group design therefore changes the output shape.

If you know C

Python strings are Unicode text and re operates on that text. Do not assume character classes behave like ASCII byte checks in a C loop. Write [0-9] when the accepted domain specifically requires ASCII digits.

The shorthand digit class can match Unicode decimal digits beyond 0 through 9. Word and whitespace classes also follow Unicode behavior for string patterns by default. If your rule is an ASCII identifier, state that policy with explicit ranges or an appropriate flag instead of assuming the shorthand means English-only.

Capture only what the caller needs

Parentheses create capturing groups. Named groups such as (?P<department>[A-Z]{3}) let the caller use group("department") instead of remembering a number. Captures are useful when a pattern has several meaningful parts, such as department and course number.

Use a noncapturing group, written (?:...), when grouping is needed only for structure. This keeps findall result shapes and numbered groups from changing accidentally. Adding parentheses to improve precedence should not silently change the caller's data model.

re.sub replaces nonoverlapping matches and returns a new string. The original string remains unchanged. A replacement can be fixed text or a function receiving a match object. A function is often clearer when the replacement depends on captured values or needs numeric conversion.

A compiled pattern from re.compile can provide named reuse and clearer code. It exposes search, fullmatch, findall and sub methods. Compile when it helps organize a reused pattern; do not claim a large speed improvement without measuring the actual workload.

When replacement text comes from outside, remember that re.sub's string replacement has its own escape rules. A replacement function returning that text avoids treating it as a backreference template. re.escape is intended for patterns, not as a general replacement-template escape function.

Control repetition and validation scope

Repetition is usually greedy: it consumes as much as possible while allowing the overall match to succeed. A non-greedy form such as +? tries a shorter match first. Neither is automatically correct; the surrounding boundary decides which part of the text you actually want.

Prefer a precise character class to an unrestricted dot when the field has known content. For a bracketed ASCII identifier, describe the allowed interior rather than matching arbitrary text until some later bracket. This makes the rule easier to audit and can avoid surprising long matches.

Nested ambiguous repetition can require excessive backtracking on certain nonmatching inputs. Keep patterns simple and bound input sizes when handling untrusted large text. This introduction does not ask you to design a full email, URL or programming-language parser with one expression.

Regex validates text shape, not every meaning. A pattern can accept a date shaped as four digits, a hyphen, two digits and another pair, yet still accept an impossible calendar date. After extracting the parts, use datetime or explicit domain checks when validity matters.

For course labels, a pattern can verify three letters and three digits, but cannot know which courses are offered this semester. Look up the matched code in a course table afterward. Separate syntax recognition from the business rule.

Check the match and the language layer

Using match for a code hidden in a sentence

match starts at position zero. Use search when the code may appear later, or fullmatch when the entire input must be one code.

Calling group on None

A failed search returns None. Check the match object before reading groups. No match is an expected result, not necessarily an exceptional failure.

Forgetting that parentheses change findall

Capturing groups alter returned values. Use noncapturing groups for structure and test the result shape after modifying a pattern.

Overusing regex for fixed text

If you want to replace every literal comma with a semicolon, str.replace is clearer. Keep regex for tasks where its pattern language provides useful information.

Stay within the shared regex feature set

The patterns shown work on Python 3.10–3.12. Features such as atomic groups and possessive quantifiers arrived in Python 3.11 and are not required here. Raw-string syntax avoids invalid Python escape warnings, but a raw string still cannot end in a single unpaired backslash.
