কম্পিউটারকে কিছু বলতে শেখাও

ল্যাবের দরজার নোটিশ যেমন পরিষ্কার মেসেজ দেয়, প্রথম Python প্রোগ্রামও স্ক্রিনে তা করতে পারে। পরিচিত মেসেজ দিয়ে শুরু করো। তারপর একটি অংশ বদলে কী হয় দেখো।

প্রোগ্রামের একটি ইনস্ট্রাকশন হলো স্টেটমেন্ট। print কল করে মান দেখানো একটি স্টেটমেন্ট। Python সাধারণত ফাইলের ওপর থেকে নিচে এসব স্টেটমেন্ট চালায়। কোডের ক্রমেই মেসেজের ক্রম ঠিক হয়।

Python সেটআপ থেকে সেভ করা ফাইল চালাতে শিখেছ। উদাহরণে সেই ব্যবস্থা ব্যবহার করো। প্রোগ্রাম চলেছে মানে Python পৌঁছানো ইনস্ট্রাকশন বুঝে চালাতে পেরেছে। উদ্দেশ্যের সমস্যাটি ঠিক সমাধান হয়েছে কি না, তা আলাদা করে দেখতে হবে।

# A note for the reader

print হলো একটি বিল্ট-ইন ফাংশনের নাম। ফাংশন নির্দিষ্ট কাজ করে। প্রথম বন্ধনীর ভেতরে থাকে আর্গুমেন্ট, অর্থাৎ ফাংশনকে দেওয়া মান। কোটেশনের ভেতরের টেক্সটকে বলে স্ট্রিং। কোটেশন স্ট্রিংয়ের সীমানা বোঝায়; আউটপুটে তার অংশ হিসেবে আসে না।

কোড পড়ার মানুষের জন্য লেখা নোট হলো কমেন্ট। Python চালানোর সময় এটি বাদ দেয়। সিদ্ধান্তের কারণ বা উদ্দেশ্য বোঝাতে কমেন্ট দাও। শুধু print কথাটি আবার লেখার চেয়ে ফল টাকায় দেখাচ্ছ কেন বলা বেশি কাজে লাগে।

স্ট্রিংয়ের ভেতরে # সাধারণ টেক্সট। একই চিহ্ন কোটেশনের কারণে আলাদা অর্থ পায়। বড় আর ছোট হাতের অক্ষরও আলাদা: Print আর print এক নাম নয়। সাধারণ সোজা কোটেশন দাও; সাজানো বাঁকা কোটেশন Python স্ট্রিংয়ের সীমানা বোঝায় না।

টেক্সট, হিসাব আর ব্লক

print দেখানোর আগে আর্গুমেন্টের মান বের হয়। কোটেশন ছাড়া 7 + 5 দেয় 12। কোটেশনের ভেতরের "7 + 5" ওই পাঁচটি অক্ষরই রাখে। print দুই ধরনের মানই দেখাতে পারে।

সাধারণভাবে print শেষে নতুন লাইন দেয়। পরপর দুটি কল তাই দুটি লাইনে ফল দেখায়। সোর্সে ফাঁকা লাইন দিলে পড়তে সুবিধা হতে পারে, কিন্তু আউটপুটে নিজে থেকে ফাঁকা লাইন যোগ হয় না।

একসঙ্গে থাকা স্টেটমেন্টের দল হলো ব্লক। লাইনের আগে স্পেস, অর্থাৎ ইনডেন্টেশন দিয়ে Python দল বোঝায়। if True: সিদ্ধান্তের ব্লক শুরু করে। True হলো হ্যাঁ বোঝানো বুলিয়ান মান, তাই এই ব্লক সব সময় চলে।

সিদ্ধান্ত নিয়ে বিস্তারিত if, elif আর else-এ শিখবে। এখন হেডারের শেষে কোলন আর ভেতরের লাইনের আগে চারটি স্পেস দেখো। পরে স্পেস ছাড়া লাইন ব্লকের বাইরে। ইনডেন্টেশন বদলালে প্রোগ্রামের অর্থও বদলাতে পারে।

তিনটি ছোট ধাপ

স্বাগত আর মনে করিয়ে দেওয়া

প্রথম উদাহরণে কমেন্ট আর দুটি print কল আছে। চালানোর আগে কোন লেখা দেখা যাবে ভাবো। মেসেজ দুটি আসবে, কমেন্ট আসবে না। শুধু কমেন্ট বদলালে মেসেজও বদলাবে না।

অক্ষর দেখাবে, নাকি হিসাব করবে?

একই অঙ্কের মতো লেখা একবার কোটেশনে, আরেকবার বাইরে আছে। দুই লাইন মেলাও, তারপর সংখ্যা বদলাও। সোর্সের লেখা আর এক্সপ্রেশন থেকে পাওয়া মানের পার্থক্য এখানেই দেখছ।

ব্লক কোথায় শেষ দেখো

তৃতীয় উদাহরণে হেডারের নিচে দুটি মেসেজ আছে। শেষ মেসেজের আগে স্পেস নেই, তাই সেটি দলের বাইরে। True-এর জন্য ভেতরের দুটিই চলে। পরে শর্ত ঠিক করবে পুরো দল চলবে কি না।

এরর থেকে সূত্র নাও

এরর মেসেজ জানায় Python কেন এগোতে পারেনি। শেষ লাইন থেকে শুরু করো; সেখানে এররের ধরন আর সমস্যার কথা থাকে। তারপর দেখানো সোর্স লাইন আর নিচে চিহ্নিত জায়গা দেখো। ভুল পর্যন্ত পৌঁছানোর পথ রাখে বলে traceback-এ অনেক লাইন থাকতে পারে।

SyntaxError মানে সোর্স বোঝা যায়নি। কোটেশন বা শেষের বন্ধনী বাদ গেলে হতে পারে। দেখানো জায়গায় Python সমস্যা ধরলেও কারণ আগের লাইনে থাকতে পারে। সম্পর্কহীন কোড বদলানোর আগে আশপাশ পড়ো।

NameError মানে সেই জায়গায় চাওয়া নামের সঙ্গে মান যুক্ত নেই। print-এর বদলে pritn লেখা পরিচিত উদাহরণ। Python নিজে বানান ঠিক করে না, কারণ অন্য প্রোগ্রামে ভিন্ন বানানের নাম ইচ্ছা করেও থাকতে পারে।

সম্ভাব্য একটি কারণ ঠিক করো, সেভ করে আবার চালাও। এতে প্রতিটি পরিবর্তনের ফল বোঝা যায়। পার্স করার সময় syntax error হলে স্ক্রিপ্টের আগের print-ও চলে না। runtime error হলে আগের কোড ইতিমধ্যে ফল দেখিয়ে থাকতে পারে।

টেক্সটে কোটেশন না দেওয়া

print-এর ভেতরে কোটেশন ছাড়া শব্দ লিখলে Python নাম খোঁজে। সরাসরি টেক্সট চাইলে কোটেশন দাও। রাখা মান চাইলে আগে সেই নাম তৈরি করো; পরের পাঠে তা শিখবে।

প্রথম সাধারণ লাইনে ইনডেন্ট দেওয়া

unexpected indent মানে ওপরের স্তরের লাইনের আগে ভুল করে স্পেস পড়ে থাকতে পারে। লাইনটি ওই স্তরের হলে স্পেস সরাও। শুধু এরর সরাতে আসল ব্লকের স্পেস তুলে দেবে না।

সেভ করতে ভুলে যাওয়া

এডিটরে নতুন লেখা থাকলেও সেভ করা ফাইলে পুরোনো কোড থাকতে পারে। আবার চালানোর আগে সেভ করো। ফল না বদলালে ফাইলের path-ও দেখো।

Python 3-এর print নাও

এখানে প্রথম বন্ধনীসহ print কল Python 3-এর। Python 2-তে print স্টেটমেন্ট ছিল এমন উদাহরণ দিয়ে শুরু করবে না। এই কোড Python 3.10 থেকে 3.12-এ একইভাবে চলে।
