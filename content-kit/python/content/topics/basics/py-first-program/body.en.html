Make the computer say something

A notice on a lab door gives one clear message. Your first Python program can do the same on a screen. Start with a message you can recognise, then change one part and observe what happens.

A statement is an instruction in your program. A call to print is a statement that displays values. Python normally executes these simple statements from the top of the file to the bottom. Their order determines the order of the messages.

You already know how to start a saved file from Setting Up Python. Keep that setup nearby while trying these programs. A successful run means that Python could understand and execute the instructions it reached. It does not yet prove that the instructions solve the intended problem.

Read a print call

print("Your message")
# A note for the reader

The name print identifies a built-in function, a tool that performs a particular job. Parentheses contain its arguments, the values passed to that tool. The quoted text is a string, a value representing text. The quotes delimit the string and are not displayed as part of it.

A comment is a note for people reading the code. Python ignores a comment when executing instructions. Use comments to explain a choice or a purpose. A note saying why a result is labelled in taka is more helpful than a note repeating the word print.

The # character inside a quoted string is ordinary text. Quotes therefore affect how the same visible character is interpreted. Python also distinguishes capital letters: Print and print are different names. Use ordinary straight quote characters, since decorative quotation marks are not Python string delimiters.

Text, calculations and blocks

Python evaluates an argument before print displays it. An unquoted arithmetic expression such as 7 + 5 produces the number 12. A quoted expression such as "7 + 5" remains those five characters. The display call can accept either kind of value.

By default, print ends with a newline. Two calls usually produce two lines, even when their source lines are next to each other. A blank source line can improve readability without adding a blank line to the displayed result.

A block is a group of statements that belong together. Python uses indentation, the spaces before a statement, to show that grouping. A header such as if True: starts a decision block. True is the Boolean value for yes, so this particular block is always entered.

The decision itself is taught in if, elif and else. For now, notice the colon after the header and four spaces before its body. An unindented statement following the body is outside the block. Changing indentation can change the program's meaning.

Use four spaces for each indentation level. Configure your editor to insert spaces when you press Tab. Mixing tabs and spaces may make code appear aligned while Python sees inconsistent block boundaries.

Three small steps

A welcome and a reminder

The first example has a comment and two display calls. Before running it, predict which words will be visible. The two messages appear; the comment does not. Changing the comment should leave the messages unchanged.

Print characters or calculate a value

The second example uses the same arithmetic-looking characters twice. One argument is quoted and one is not. Compare the two displayed lines, then try another pair of numbers. This is your first distinction between source text and the value an expression creates.

See the edge of a block

The third example groups two messages beneath a header. The final message has no leading spaces and follows the group. Both inside messages still run because True selects that block. Later, a condition will decide whether a group runs at all.

Use an error as a clue

An error message reports what prevented Python from continuing. Start with its final line, which names the error category and describes the problem. Then find the indicated source line and any pointer beneath it. A traceback may contain several lines because it records the path to a failure.

A SyntaxError means Python could not understand the source. An unmatched quote or missing closing parenthesis can cause it. Sometimes the marked location is where Python noticed the problem, while the cause is on the previous line. Read nearby lines before changing unrelated code.

A NameError means a requested name has no binding in that context. Misspelling print as pritn is a common example. Python does not automatically correct names because a different spelling could be an intentional name in another program.

Change one likely cause, save the file and rerun it. This method gives you evidence about each repair. If a syntax error stops a script during parsing, its earlier display calls will not run either. A runtime error can happen after earlier instructions have already produced visible results.

If you know C

Python does not require a main function, semicolons after these statements or braces around blocks. Leading whitespace carries structural meaning. Preserve indentation when copying code into an editor.

Small spelling choices matter

Leaving text unquoted

Writing a word inside print without quotes asks Python to look up a name. If you intend literal text, quote it. If you intend a stored value, create the name first, as the next topic explains.

Indenting the first ordinary line

An unexpected indent often means a top-level line gained spaces accidentally. Remove them when the statement belongs at the top level. Do not remove spaces from a real block merely to silence a message.

Forgetting to save

An editor can show new text while the saved file still contains the old instructions. Save before rerunning. If a result refuses to change, check the file path as well as its contents.

Use Python 3 printing
