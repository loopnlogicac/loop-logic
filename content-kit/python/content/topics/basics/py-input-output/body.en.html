Turn a fixed calculation into a conversation

A bill calculator becomes useful when someone can enter a price and quantity. Input brings values into the program. Output sends results back to the person or another program. You need a clear agreement about both directions.

Input is data received by a program. Output is data it produces. In these examples, the terminal supplies input lines and displays printed results. A clear prompt helps a person know what to enter, while a precise result format helps them interpret the answer.

The first decision is whether a value is text or a number. A roll label containing 0017 may need its zeros. A price used in multiplication needs numeric conversion. The characters alone do not tell Python which meaning you intend.

Read a line and convert deliberately

label = input("Label: ")
count = int(input("Count: "))
measurement = float(input("Measurement: "))

The function input optionally displays a prompt, waits for a line and returns a str. It removes the trailing newline. It does not automatically strip every surrounding space or convert digits to numbers. A blank entered line becomes an empty string, not None.

The expression int(input()) first reads a line and then asks int to parse integer text. float can parse a decimal measurement. This nested form is short, but you can use separate names while learning: read the text, inspect it, then convert it.

Invalid conversion raises ValueError. For example, int cannot parse the text 3.5 as an integer. Converting through float and then int would truncate a numeric value; it is not a general repair for an invalid integer entry. Later, Exceptions teaches how to ask for a replacement entry safely.

Follow the data through a small bill

For a book bill, the person enters 60 and then 3 on separate lines. Each input call receives text. The conversions create integers, multiplication produces 180 and print displays the result. If the text were never converted, the intended numeric calculation would not follow.

Two strings added with + are concatenated. Thus the text 4 plus the text 2 gives 42, while their integer values add to 6. Python chooses operations from the operand types. A correct-looking line of digits can hide a missing conversion.

These exercises specify one value per line unless they say otherwise. Do not assume that input reads one whitespace-separated word. It reads the entire line. Reading several tokens from one line requires splitting that line, which is covered later.

Read and present useful values

Preserve a label exactly

The roll example shows both the stored label and its type name. Its zeros remain because no numeric conversion occurs. A label can look numeric while still being correctly represented as text.

Calculate a whole-taka bill

The book example converts both entries to integers. Whole taka keep this small money calculation exact. Read the prompts before typing so that price and quantity do not accidentally swap roles.

Choose separators and endings

The sep argument supplies text between print arguments. The end argument supplies text after the entire call. Their defaults are a space and a newline. Changing end allows another print call to continue the same displayed line.

Align and format a row

The marks example uses a field width and two decimal places. The number 7.5 appears as 7.50 with padding before it. The percent field shows how a stored fraction can be displayed in a familiar form without changing the stored value.

Use f-strings as readable templates

An f-string is a string prefixed with f that inserts values inside braces. Python evaluates each expression in braces when the string is created. Literal words outside the braces remain as written. This keeps a label close to the value it describes.

A colon inside a field introduces a format specification. The .2f form requests fixed-point text with two decimal places. A width such as 6 requests at least six characters, including signs and the decimal point. It does not cut off a longer number.

For text, < requests left alignment and > requests right alignment. In a receipt, a label might use width ten while an amount uses width six. Count the separator characters separately. Exact spaces matter when another program reads a fixed layout.

Formatting rounds the displayed value, not the underlying number into exact decimal storage. Recall Numbers and Arithmetic when choosing numeric types. Presentation and numeric correctness are related decisions, but one cannot replace the other.

If you know C

input does not behave like scanf with a numeric format. It first returns text, and int or float performs conversion separately. F-strings place values inside braces rather than requiring printf-style format arguments and addresses.

Keep the conversation contract clear

Expecting typed input to be printed again automatically

An interactive terminal may echo what you type. That echo is not a print call in your program. If a result must include the entered label, print the stored value explicitly.

Adding prompts to a numeric-only result

A problem may require only a sum. In that case, use input without a prompt and print only the sum. Interactive examples have prompts because a person benefits from guidance; exercise statements define their own required output.

Using input's argument as a default value

The text passed to input is a prompt, not a stored answer. The person must still supply a line. If a task needs a default, read the entry and choose that default deliberately.

Confusing blank input with end of input

Pressing Enter on a blank line returns empty text. Reaching the end of the input source raises EOFError instead. A program expecting more lines needs a defined policy for missing input, rather than assuming another blank line will appear.

Portable f-string syntax

These f-strings use syntax available before Python 3.10 and work on Python 3.12. Python 3.12 expands some f-string expression syntax, but none of those newer forms are needed here.
