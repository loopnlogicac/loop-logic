স্থির হিসাবকে কথোপকথন বানাও

কেউ দাম আর পরিমাণ লিখতে পারলে বিলের প্রোগ্রাম কাজে লাগে। ইনপুট মান আনে, আউটপুট ফল মানুষ বা অন্য প্রোগ্রামকে দেয়। দুই দিকেই কী আদানপ্রদান হবে পরিষ্কার থাকা দরকার।

প্রোগ্রামে আসা ডেটা হলো ইনপুট, আর তৈরি করা ডেটা আউটপুট। এখানে টার্মিনাল থেকে লাইন পড়া আর ফল দেখানো হয়। পরিষ্কার prompt বলে কী লিখতে হবে; নির্দিষ্ট ফরম্যাটে ফল দিলে অর্থ বোঝা সহজ।

আগে ঠিক করো মান টেক্সট, নাকি সংখ্যা। 0017 রোলে শূন্য দরকার হতে পারে। গুণে লাগবে এমন দাম সংখ্যায় বদলাতে হবে। শুধু অক্ষর দেখে Python তোমার উদ্দেশ্য জানে না।

লাইন পড়ে বুঝে রূপান্তর করো

label = input("Label: ")

input চাইলে prompt দেখায়, এক লাইন আসা পর্যন্ত অপেক্ষা করে, তারপর str ফেরত দেয়। শেষের newline সরায়। চারপাশের সব স্পেস সরায় না, অঙ্ককে সংখ্যাও বানায় না। ফাঁকা লাইন দিলে ফাঁকা স্ট্রিং আসে, None নয়।

int(input()) আগে লাইন পড়ে, তারপর পূর্ণসংখ্যার টেক্সটকে int করতে বলে। দশমিক মাপে float নাও। একসঙ্গে লেখা ছোট হলেও শুরুর দিকে আলাদা নামে টেক্সট পড়ে, দেখে, তারপর রূপান্তর করতে পারো।

রূপান্তর অবৈধ হলে ValueError হয়। যেমন int দিয়ে 3.5 টেক্সটকে পূর্ণসংখ্যা করা যায় না। আগে float, পরে int করলে ভগ্নাংশ বাদ যায়; ভুল পূর্ণসংখ্যার ইনপুট ঠিক করার সাধারণ উপায় এটা নয়। পরে এক্সসেপশন-এ নতুন ইনপুট চাওয়া শিখবে।

পূর্ণ টাকায় বিল

বইয়ের উদাহরণে দুই ইনপুট int হয়। পূর্ণ টাকায় এই ছোট হিসাব সঠিক থাকে। prompt পড়ে দাম আর পরিমাণ লেখো, যেন উল্টে না যায়।

নম্বরের উদাহরণে field width আর দুই দশমিক ঘর আছে। 7.5 সামনে ফাঁকা জায়গাসহ 7.50 হয়। শতাংশের ঘরে রাখা ভগ্নাংশকে পরিচিতভাবে দেখায়, মূল মান বদলায় না।

f-string দিয়ে পরিষ্কার ছাঁচ

শুরুতে f থাকা f-string-এ braces-এর ভেতর মান বসে। স্ট্রিং তৈরির সময় ওই এক্সপ্রেশনের মান বের হয়। বাইরের লেখা একই থাকে। ফলে মান আর তার লেবেল পাশাপাশি লেখা যায়।

ঘরের ভেতর কোলনের পরে format specification আসে। .2f মানে দুই দশমিক ঘরে fixed-point টেক্সট। width 6 মানে চিহ্ন আর দশমিক বিন্দুসহ অন্তত ছয় অক্ষর। বেশি লম্বা সংখ্যা কেটে ছোট করে না।

টেক্সটে < বাঁ দিকে আর > ডান দিকে সাজায়। রসিদে লেবেলের width দশ, টাকার ছয় হতে পারে। মাঝের separator আলাদা গুনবে। নির্দিষ্ট ফরম্যাট অন্য প্রোগ্রাম পড়লে স্পেসও গুরুত্বপূর্ণ।

ফরম্যাট দেখানো মান round করে, ভেতরে সঠিক দশমিক হিসেবে জমা করে না। টাইপ বাছতে সংখ্যা আর হিসাব মনে করো। সুন্দরভাবে দেখানো আর সঠিক হিসাব একে অন্যের বিকল্প নয়।

C জানা থাকলে

input সংখ্যার format-সহ scanf-এর মতো নয়। আগে টেক্সট ফেরত দেয়; int বা float আলাদা রূপান্তর করে। f-string-এ braces-এর ভেতরে মান থাকে; printf-এর মতো আলাদা format argument আর address দিতে হয় না।

কী পড়বে আর দেখাবে পরিষ্কার রাখো

লেখা ইনপুট নিজে থেকে আবার প্রিন্ট হবে ভাবা

টার্মিনালে টাইপ করা লেখা দেখা যেতে পারে। সেই echo তোমার print কল নয়। ফলে ইনপুটের লেবেল দরকার হলে নিজে প্রিন্ট করো।

শুধু সংখ্যা চাওয়া ফলে prompt যোগ করা

সমস্যায় শুধু যোগফল চাইলে prompt ছাড়া input নাও আর শুধু যোগফল প্রিন্ট করো। মানুষকে সাহায্য করতে ইন্টারঅ্যাকটিভ উদাহরণে prompt থাকে; অনুশীলনের আউটপুট তার নিজস্ব শর্ত মেনে চলবে।

input-এর আর্গুমেন্টকে ডিফল্ট উত্তর ভাবা

input-কে দেওয়া লেখা prompt, রাখা উত্তর নয়। মানুষকে লাইন দিতেই হবে। ডিফল্ট দরকার হলে ইনপুট পড়ে নিয়ম অনুযায়ী বেছে নাও।

ফাঁকা লাইন আর ইনপুট শেষ মেশানো

ফাঁকা লাইনে Enter দিলে ফাঁকা টেক্সট আসে। ইনপুটের উৎস শেষ হলে EOFError হয়। আরও লাইন দরকার হলে না-পাওয়া ইনপুটের নিয়ম ঠিক করো; আরেকটি ফাঁকা লাইন আসবে ধরে নিও না।

বিভিন্ন ভার্সনে f-string

এখানে Python 3.10-এর আগের f-string সিনট্যাক্স আছে, 3.12-এও চলে। 3.12-এ এক্সপ্রেশনের কিছু বাড়তি সুবিধা আছে, তবে এখানে লাগে না।

অর্থ বুঝে পড়ো, পরিষ্কার দেখাও

লাইন টেক্সট হিসেবে পড়ো, সংখ্যা দরকার হলেই রূপান্তর করো। পাঠকের জন্য ফরম্যাট, লেবেল আর separator বাছো। এবার অপারেটর-এ মান মিলিয়ে শর্ত লেখো।
