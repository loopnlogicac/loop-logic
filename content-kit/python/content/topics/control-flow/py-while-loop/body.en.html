Repeat until the situation changes

A person entering marks may not know in advance how many entries they will make. They can keep entering data until a special signal says to stop. A while loop expresses this kind of repetition through a condition.

A loop repeats a block of statements. Each repetition is an iteration. A while loop checks its condition before every iteration, so the body can run many times or never run at all.

The decisions from if, elif and else choose whether to act once. A loop returns to its condition and can choose the action again. Your design must explain what changes between those checks and why the repetition will eventually finish.

Initialise, test and make progress

remaining = 3
while remaining > 0:
    do_one_step
    remaining -= 1

The general body above stands for your repeated work. The initial assignment establishes a starting state. The condition decides whether another step is allowed. The update moves that state towards the stopping boundary.

A counter loop uses a changing number to track repetitions. A sentinel loop uses a special input value to signal completion. The same while syntax supports both; the difference is the reason the condition eventually becomes false.

Trace the final failed check

For a countdown starting at three, the body sees three, two and one. After printing one, the update makes the counter zero. The next check fails. The body never sees zero because the condition excludes it.

The condition is checked once more than the body runs in this normal completion. That final failed check explains why the counter remains zero afterwards. If the starting value were already zero, the first check would fail and no countdown numbers would appear.

A sentinel needs a clear data rule. If valid marks include zero, zero is a poor end signal unless the task deliberately excludes zero marks. The example uses -1, outside the ordinary marks domain. Check the sentinel before adding the input to the total.

A sentinel loop commonly reads once before entering and again at the end of the body. The first read provides a value for the first condition. The later read allows a new entry to change that condition. Forgetting the later read can repeat the same value forever.

Different reasons to stop

A counted countdown

The first program changes its counter by one each time. The visible Start message occurs after the loop, so it appears once. Keep the update indented inside the loop; moving it outside would prevent the condition from changing.

Add marks until the sentinel

The entry program counts real entries and totals them. It does not count -1. If -1 is the first entry, both count and total remain zero. The given program assumes that ordinary entries follow its stated marks rule.

Leave early after finding a divisor

The search program uses break as soon as a divisor is found. Its loop else reports that no candidate divisor was found only when repetition ends normally. The printed divisor three explains why fifteen is not prime.

A deliberately open-ended command loop

The command program repeats under the literal True condition. A stop command reaches break and ends the loop. Other commands are echoed. The loop is useful because it has a visible exit route, rather than because True can somehow become false.

Understand completion without break

The statement break immediately exits the nearest loop. A while loop may have an else block aligned with its header. That else runs when the condition becomes false, including when it is false on the very first check. It is skipped when break exits the loop.

Read while-else as “repeat, then handle completion without an early break”. It is not the opposite branch of a single if. In a search, break means success and else can mean no match. The meaning comes from how the loop uses break, rather than from a built-in idea of searching.

The statement continue skips the remaining body and returns to the next condition check. Be careful with counter updates below a continue: they may be skipped. If that update was the only progress step, the loop can become infinite. The for lesson shows a form where the next item is supplied automatically.

An infinite loop has no reachable normal stopping path for the current situation. Some programs intentionally run until an external event occurs. During learning, use small bounds or a clear command exit, and know how your terminal interrupts a running program.

If you know C

Python while also checks before the body, but it has an optional loop else. There is no built-in do-while statement. For work that must happen before checking an exit rule, while True with a carefully placed break can express the sequence.

Find the missing progress

Updating after the loop instead of inside it

Indentation decides whether a counter changes on every iteration. If the update is outside, a positive countdown may never reach it. Trace the state before assuming the machine is slow.

Counting the sentinel as data

Adding an input before checking for -1 pollutes the total. Compare first, then process ordinary values. Test an immediate sentinel to reveal this error quickly.

Attaching else to the wrong header

A loop else aligns with while. An else inside the body may belong to an if instead. Their meanings differ, so inspect the indentation before explaining a result.

A stable repetition form

while, break, continue and while-else have the behavior described here in Python 3.10 through 3.12. The important differences from C concern syntax and loop else, rather than a recent version change.
