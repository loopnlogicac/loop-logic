Choose an action from a condition

At a lab entrance, a notice may say that students can enter only during certain hours. The action depends on the situation. An if statement gives your program that ability to choose a path.

A condition is an expression whose truth value decides whether a block runs. A branch is one possible path through the decision. You can provide one branch, add alternatives or include a fallback for every remaining case.

The expressions in Operators provide the questions. The if statement attaches actions to their answers. Keep those roles separate: calculating whether a mark passes does not itself print a result or store a category.

Write aligned branches

if condition:
    first_action
elif another_condition:
    second_action
else:
    fallback_action

The names ending in action describe places for statements, rather than built-in Python commands. Each header ends with a colon. The statements underneath are indented one level. The if, elif and else headers align with one another because they belong to the same decision.

The word elif means “otherwise, if”. You may have several elif branches or none. The else branch has no condition and is optional. If every test fails and there is no else, execution continues after the decision without running a branch.

Use four spaces for each block level, including nested decisions. An indented suite is the group of statements under a header. The group may contain more than one statement, so a branch can update a value and print a message together.

The roles in a decision chain
HeaderWhen its body runs
ifWhen its condition is truthy
elifWhen previous tests failed and its own condition is truthy
elseWhen no earlier branch was selected

The first matching branch wins

For a marks category, begin by rejecting values outside the allowed range. Then test the highest category before lower thresholds. A mark of 85 satisfies both “at least 80” and “at least 40”. The order decides which label it receives.

Python stops checking a chain when a branch succeeds. Later elif conditions are not evaluated, and their bodies do not run. This is useful when categories should be mutually exclusive. If two actions may both be needed, use two independent if statements instead.

Boundary values reveal mistakes quickly. For a pass threshold of 40, try 39, 40 and 41. Also try invalid values such as -1 and 101. A check that accepts 120 as excellent has classified a threshold without validating the domain.

Truthiness lets a condition use values besides bool. Empty text, numeric zero and None are falsey. Nonempty text is truthy, including "0" and "False". If you read a yes/no word from input, compare its text deliberately instead of assuming its spelling controls its truth value.

Choose categories and messages

Validate a mark before classifying it

The first program places the invalid-range test before valid categories. The entered 80 receives Excellent because the upper category comes first. The labels are teaching examples, not a claim about an institution's official grade scale.

Provide a display-name fallback

The name program strips surrounding spaces before testing truthiness. An entry containing only spaces becomes empty. The else branch then greets a guest. Without stripping, that same entry would be nonempty and truthy.

Read a decision inside another

A nested condition is a decision inside a branch. The card example first asks whether a card exists. Only its yes branch asks about balance. The inner else aligns with the balance if, so it prints Top up first for a zero balance.

Choose one value with an expression

A conditional expression selects one value using the form yes_value if condition else no_value. It is useful for a short label. Only the chosen result expression is evaluated. Longer actions usually read better in ordinary indented branches.

Reduce unnecessary nesting

Nesting can mirror a problem naturally, as with card ownership followed by balance. Too many levels make paths difficult to follow. Sometimes combining conditions with and expresses the same rule more clearly. Keep separate branches when they need different explanations or messages.

Before writing code, list the categories in everyday words. Check whether they overlap and whether they cover every allowed input. Then choose an order. This prevents a common failure where the code looks tidy but silently omits a case.

Choose variable names that reveal the condition. A flag such as has_card reads as a yes/no question. A name such as x makes the reader reconstruct its meaning from earlier lines. Clear names can shorten a condition without hiding its rule.

If you know C

Python uses elif rather than else if, and indentation replaces braces. A conditional expression uses “a if condition else b”, not the C question-mark form. Put the intended yes value first when reading it aloud.

Find the branch that actually owns a line

Misaligning an else

A nested else belongs to the if at the same indentation level. Moving it by one level changes the decision tree. Draw the branch groups before editing spaces if the intended ownership is unclear.

Checking a broad threshold too early

If a mark of at least 40 is checked before a mark of at least 80, the higher category is never selected. Order thresholds from the most specific or highest case when the comparisons overlap.

Repeating if when only one category should win

Separate if statements can print several labels for one mark. Use elif when the choices are exclusive. Multiple if statements are correct when separate actions, such as logging and showing a warning, can both apply.

Writing an empty branch

A colon must be followed by a body. During development, pass can stand for an intentionally empty body. It does nothing and should not replace the actual action once your design is ready.

Decision syntax in Python 3

The if, elif and else forms and conditional expressions here work across Python 3.10 and later. The next lesson's match statement needs Python 3.10, but ordinary if remains suitable for many conditions.
