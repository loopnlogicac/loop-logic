শর্ত দেখে কাজ বেছে নাও

ল্যাবের নোটিশে নির্দিষ্ট সময়ে ঢুকতে বলা থাকতে পারে। পরিস্থিতি অনুযায়ী কাজ বদলায়। if স্টেটমেন্ট দিয়ে প্রোগ্রামেও কোন পথে যাবে ঠিক করো।

যে এক্সপ্রেশনের সত্য-মিথ্যা দেখে ব্লক চলবে কি না ঠিক হয়, সেটি শর্ত। সিদ্ধান্তের একটি সম্ভাব্য পথ হলো ব্রাঞ্চ। একটি পথ, কয়েকটি বিকল্প বা বাকি সব অবস্থার জন্য শেষের ব্যবস্থা রাখতে পারো।

অপারেটর দিয়ে প্রশ্ন তৈরি হয়। if দিয়ে উত্তরের সঙ্গে কাজ জুড়ে দাও। নম্বর পাস কি না হিসাব করলেই ফল প্রিন্ট বা ক্যাটাগরি সেভ হয় না; সেগুলো আলাদা কাজ।

ব্রাঞ্চ একই স্তরে সাজাও

if condition:
    first_action
elif another_condition:
    second_action
else:
    fallback_action

যেমন if mark >= 40:-এর পরে ইনডেন্ট করে print("Pass") লিখতে পারো। প্রতিটি হেডারের শেষে কোলন থাকে, ভেতরের স্টেটমেন্ট এক স্তর ডানে যায়। একই সিদ্ধান্তের if, elif আর else একই স্তরে থাকবে।

elif মানে “তা না হলে, যদি”। একাধিক elif থাকতে পারে, একটিও না থাকতে পারে। else-এ শর্ত থাকে না, এটিও চাইলে রাখবে। সব শর্ত ব্যর্থ আর else নেই হলে কোনো ব্রাঞ্চ না চালিয়ে সিদ্ধান্তের পরের লাইনে যায়।

প্রতি স্তরে চারটি স্পেস নাও, ভেতরের সিদ্ধান্তেও। হেডারের নিচের স্টেটমেন্টের দলকে indented suite বলে। এক ব্রাঞ্চে অনেক স্টেটমেন্ট থাকতে পারে, যেমন মান বদলানো আর মেসেজ দেখানো।

একটি ব্রাঞ্চ মিললে পরের elif-এর শর্তও আর পরীক্ষা হয় না, কাজও চলে না। শুধু একটি ক্যাটাগরি চাইলে এটাই দরকার। দুই কাজ একসঙ্গে লাগতে পারলে দুটি আলাদা if নাও।

সিদ্ধান্তের ভেতরে সিদ্ধান্ত

ব্রাঞ্চের ভেতরের সিদ্ধান্ত হলো nested condition। কার্ডের উদাহরণে আগে কার্ড আছে কি না, থাকলেই ব্যালেন্স দেখা হয়। ভেতরের else ব্যালেন্সের if-এর স্তরে, তাই শূন্য ব্যালেন্সে Top up first আসে।

এক্সপ্রেশনে একটি মান বাছো

Conditional expression-এর রূপ yes_value if condition else no_value। ছোট লেবেলে সুবিধা হয়। শুধু বেছে নেওয়া ফলের এক্সপ্রেশন হিসাব হয়। বড় কাজ সাধারণ ইনডেন্ট করা ব্রাঞ্চে পরিষ্কার পড়া যায়।

অপ্রয়োজনীয় ভেতরের স্তর কমাও

কার্ড তারপর ব্যালেন্সের মতো সমস্যায় nested সিদ্ধান্ত স্বাভাবিক। অতিরিক্ত স্তরে পথ বোঝা কঠিন হয়। কখনো and দিয়ে শর্ত মিলিয়ে সহজ করা যায়। আলাদা কারণ বা মেসেজ লাগলে ব্রাঞ্চ আলাদা রাখো।

কোডের আগে সাধারণ ভাষায় ক্যাটাগরি লেখো। একটির সঙ্গে অন্যটি মেলে কি না, সব বৈধ ইনপুট ধরা হয়েছে কি না দেখো। তারপর ক্রম বাছো। দেখতে গোছানো কোডেও কোনো অবস্থা বাদ পড়তে পারে।

has_card-এর মতো নাম হ্যাঁ-না প্রশ্নের অর্থ বলে দেয়। x হলে আগের লাইন থেকে অর্থ খুঁজতে হয়। পরিষ্কার নামে শর্ত ছোট হয়, নিয়ম লুকায় না।

ভেতরের else একই স্তরের if-এর। এক স্তর সরালেই সিদ্ধান্ত বদলায়। সম্পর্ক পরিষ্কার না হলে স্পেস বদলানোর আগে ব্রাঞ্চের দল আঁকো।

বড় পরিসরের শর্ত আগে দেখা

অন্তত 80-এর আগে অন্তত 40 দেখলে ওপরের ক্যাটাগরি আসে না। শর্তে মিল থাকলে বেশি নির্দিষ্ট বা ওপরের সীমা আগে রাখো।

একটি ফল চাইলেও বারবার if লেখা

আলাদা if-এ একই নম্বরে কয়েক লেবেল আসতে পারে। একটি চাইলে elif। লগ রাখা আর warning দেখানোর মতো আলাদা কাজ একসঙ্গে লাগলে একাধিক if ঠিক।

ব্রাঞ্চ ফাঁকা রাখা

কোলনের পরে কোড লাগবে। কাজ তৈরির সময় ইচ্ছাকৃত ফাঁকা ব্লকে pass দিতে পারো। এটি কিছু করে না; ডিজাইন প্রস্তুত হলে আসল কাজ বসাও।
