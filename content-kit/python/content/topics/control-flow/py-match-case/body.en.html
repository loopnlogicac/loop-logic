Match a value and its shape

A librarian might receive a request containing an action and a count: borrow, three books. Deciding how to respond involves both the action word and the structure of the request. Python's match statement can describe that shape directly.

Structural pattern matching selects code by matching a subject against patterns. A pattern can name a literal value, accept alternatives or unpack a structure. You can add a condition after a successful match. The subject is the value written after match.

Begin with fixed command words, then move to a two-part request. You do not need to learn every possible pattern at once. The most important early distinction is between a quoted literal and a bare capture name.

Unlike a simple equality chain, match can extract values while checking their arrangement. This becomes useful for structured messages. It is also easy to misuse when all you need is an ordinary interval comparison.

Subject, cases and fallback

match command:
    case "help":
        action_for_help
    case "quit":
        action_for_quit
    case _:
        fallback_action

The action names in this general form stand for your own statements. The match header ends with a colon. Each case is indented beneath match, and each case body is indented again. Quoted strings are literal patterns, meaning they match those exact text values.

The underscore is a wildcard pattern. It matches any subject without storing it in a name. Place an unguarded wildcard last, since it would accept every remaining subject. Python rejects later cases that are made unreachable by an earlier irrefutable pattern.

A capture pattern is a bare name such as received. It accepts the subject and binds that name to it. Even if the name already has a value, a bare name in this position does not compare against that value. This differs sharply from how a beginner may read case command_name.

Pattern first, guard second

Python evaluates the subject once. It then tries cases from top to bottom. If a pattern succeeds, its bindings become available to the case's guard. A guard is a Boolean condition introduced by if after the pattern.

A case is selected only when its pattern matches and its guard, if present, is truthy. When a guard fails, Python continues to later cases. Once a case is selected, its body runs and the whole match finishes. There is no automatic fall-through into the next body.

A tuple is a fixed group of values, often written with commas inside parentheses. Full tuple operations appear in Tuples. Here the pair ("borrow", 3) is enough to represent an action and a quantity.

The pattern ("borrow", count) checks a two-item sequence, requires the first item to equal borrow and captures the second item. A guard such as if count > 0 then decides whether that count is acceptable. The pattern and the guard do different jobs.

Sequence patterns can match suitable sequence shapes such as tuples and lists. They are not ordinary constructor calls. Strings are not treated as sequences to unpack by a sequence pattern. Matching a word therefore needs an appropriate literal or another explicit text condition.

Design patterns that readers can trust

Keep guards focused on validation, such as a quantity limit. A guard may execute ordinary Python expressions, so it can raise an error if captured values have unexpected types. Real interfaces often need stronger validation than these small examples. A structural match is not an automatic guarantee that every later operation is safe.

Alternative patterns that bind names must bind the same set of names on each side. Otherwise the selected body could not rely on a consistent set of values. Literal-only alternatives avoid that complication while you learn.

Do not treat capture names as private to a case. Names bound by successful patterns can remain available after the match. At the same time, avoid relying on partial bindings from a failed match attempt. Structure your code so the selected body uses the information it explicitly received.

Use a wildcard fallback when unknown input needs a response. A match with no successful case performs no body and continues after the statement. Silence can be acceptable internally, but a command menu usually benefits from an unknown-command message.

Compare the number of cases with the shape of the problem. A few literal commands are a natural use. Several unrelated numeric comparisons are usually clearer as if and elif. Rich patterns become valuable when extracting structure is part of the work.

If you know C

Python match is not a direct copy of C switch. It can capture pieces of structured values, and cases do not fall through. A break is neither needed nor permitted merely to leave a match outside a loop.

Read pattern syntax rather than guessing

Using an unquoted word as a constant

A bare word captures. For command menus, use quoted strings. More advanced constant patterns use qualified names, but do not invent that form before understanding why a bare name behaves differently.

Putting a catch-all first

An unguarded capture or wildcard always succeeds. Put it after more specific cases. The unreachable-case error is helping you find a decision whose later alternatives could never run.

Assuming a failed guard ends the match

A false guard rejects only that candidate case. Later cases are still considered. This allows a specific successful shape to fall through to an explanatory invalid-data case without running two bodies.

Using break as though match were a loop

A match statement finishes its selected case automatically. If it sits inside a loop, break exits that surrounding loop. That is a larger action than merely ending the case, so use it only when leaving the loop is intended.

Python 3.10 introduced matching

match-case was added in Python 3.10. Python 3.9 cannot parse this syntax, even when the selected path would never reach it. Run these programs with Python 3.12 or another compatible version from 3.10 onward.
