Keep one student’s data together

A student record needs a roll number and marks. Functions can pass those values separately, but the connection becomes harder to follow as the program grows. A class describes objects that hold related data and provide operations on that data. An instance is one particular object made from that class.

Think of the class as the design for a marks card. Each card follows the same design but holds its own marks. Making a second card should not erase the first card. Classes help you express this separation directly instead of maintaining several lists whose positions must always agree.

A class is useful when several functions repeatedly work on the same group of values. It is not a requirement for every small calculation. A function such as square(number) can stay a function. Choose a class when a clear object, such as a student or a balance, makes the program easier to explain.

Read a class definition from the outside

Use the class keyword followed by a name in CapWords style. The indented class body contains method definitions and sometimes class attributes. A method is a function attached to a class. Calling Student(12, 75) creates a Student instance and initializes it using the arguments.

class Student:
    school = "Campus"

    def __init__(self, roll, marks):
        self.roll = roll
        self.marks = marks

    def passed(self):
        return self.marks >= 40

The name self is a convention, not a reserved keyword. Keep the convention because other Python readers expect it. In self.roll = roll, the left side names an attribute on the instance. The right side is the parameter supplied to this call. These names can match without referring to the same storage.

The double underscores in __init__ identify a special method Python calls during construction. It prepares an already created instance; it does not return the instance. Return None implicitly. Returning another value from __init__ raises TypeError. More specialized construction belongs to later study, not to ordinary student records.

Follow references and attribute lookup

When you call student.passed(), Python finds the method and binds student as its first argument. You supply no extra self argument. Conceptually, Student.passed(student) performs the same ordinary method call. The result comes from the marks stored on that particular instance.

An instance attribute usually lives on one object. Assigning first.marks = 80 changes first, while second.marks can remain 55. A class attribute lives on the class and is available through instances that do not override it. The school name in the syntax example is suitable shared information.

For these plain classes, reading an attribute checks the instance before falling back to its class. Assigning instance.school normally creates an instance attribute that shadows Student.school. It does not update the class attribute. Changing Student.school changes the fallback seen by instances that have no school override.

first  ----> Student instance: roll=12, marks=80
alias  ----> same instance
second ----> Student instance: roll=25, marks=55
Student ---> school="Campus"

Assignment copies a reference, not the whole student. After alias = first, updating alias.marks also changes what first.marks reads. Construct a separate Student when you need independent state. A collection of objects may contain repeated references, so count objects and names separately when tracing changes.

If you know C

A Python instance can resemble a C struct together with functions operating on it. Python supplies self through method binding. You do not declare a pointer parameter or free the instance manually, but aliases can still observe the same mutable state.

Give every object a clear responsibility

Put per-object lists inside __init__, such as self.marks = []. This creates a fresh list for each construction. Writing marks = [] directly in the class body creates one shared list. Calling append through any instance then changes the same list unless an instance has replaced that attribute.

A class attribute is still useful for stable shared settings. Keep a pass threshold on Student if the same rule applies to all students. If different courses use different thresholds, accept the threshold as input or give each instance its own value. Decide ownership from the meaning of the data.

Methods should describe meaningful operations, such as deposit or passed. Avoid a method that unexpectedly edits several unrelated objects. Returning a calculated result makes it easy for the caller to choose whether to display, store or compare it. Printing inside every method mixes data behavior with presentation.

Validation belongs at a clear boundary. If your class promises nonnegative balances, reject invalid starting values and updates consistently. The exception lesson explains how to report such failures. For now, state the accepted domain and keep the examples inside it. Do not silently repair a negative value unless that is the documented rule.

Trace a change before adding another method

Suppose you have two students and an alias of the first. Write down each name and draw an arrow to its object. Then trace a marks update through the alias. Only the first student's marks change, because the second student has a separate instance. This small reference picture is more reliable than guessing from the number of variable names.

A method can use another method on the same object through self.method(). That keeps the operation attached to the current instance. Avoid creating a replacement object inside every update unless a new value is what the interface promises. A counter increment should normally update its counter, while a computed report can return fresh text.

Keep attribute names meaningful. A value named x gives little help in a student record, while roll and marks show the relationship immediately. You can inspect the same operation in a plain function and a method: the method makes the receiving object explicit through self, while the caller uses a shorter bound call.

Forgetting self in a method definition

A call through an instance supplies that instance automatically. A definition with no first parameter cannot accept it. Read the argument-count error and add self where the instance is needed.

Using a local name instead of an attribute

Writing marks = 90 inside a method creates a local variable. It leaves self.marks unchanged. Use the dotted form when the new value must survive after the call returns.

Sharing a list by accident

A mutable class attribute survives across instances. Moving its creation into __init__ gives each object a separate list. Copying a list at the wrong level can still leave nested values shared, as discussed in lists.

Calling an attribute like a method

If student.roll is an integer, student.roll() tries to call that integer and fails. Parentheses request a call; a dot alone requests an attribute. Read the class interface before guessing which form to use.

Use ordinary classes across Python versions

The class, __init__ and method patterns here work on Python 3.10 through 3.12. These examples use ordinary instance dictionaries. Other tools, including properties and slots, can change attribute behavior, so the simple lookup explanation is intentionally scoped to plain classes. Python does not enforce private access merely because a name begins with one underscore.
