এক শিক্ষার্থীর ডেটা একসঙ্গে

Student record-এ roll আর marks লাগে। ফাংশনে আলাদা পাঠানো যায়, কিন্তু প্রোগ্রাম বাড়লে সম্পর্ক বোঝা কঠিন। ক্লাস সম্পর্কিত ডেটা আর তার operation-সহ অবজেক্টের নকশা। ওই ক্লাসের নির্দিষ্ট একটি অবজেক্ট instance।

ক্লাস marks card-এর design ভাবো। প্রতিটি card একই design-এ নিজস্ব marks রাখে। দ্বিতীয়টি বানালে প্রথমটি মোছা চলবে না। Position সবসময় মিলিয়ে রাখতে হয় এমন কয়েক list-এর বদলে ক্লাস সরাসরি আলাদা record বোঝায়।

কয়েক ফাংশন একই মানের দল নিয়ে কাজ করলে ক্লাস ভালো। প্রতিটি ছোট হিসাবে বাধ্যতামূলক নয়: square(number) ফাংশনই থাকুক। Student বা balance-এর মতো স্পষ্ট অবজেক্টে ব্যাখ্যা সহজ হলেই ক্লাস বাছো।

বাইরে থেকে ক্লাস সংজ্ঞা পড়ো

ক্লাস-এর পরে CapWords নাম। Indented body-তে method আর কখনো ক্লাস attribute। Method ক্লাসে যুক্ত ফাংশন। Student(12, 75) instance বানিয়ে argument দিয়ে initialize করে।

class Student:
    school = "Campus"

    def __init__(self, roll, marks):
        self.roll = roll
        self.marks = marks

    def passed(self):
        return self.marks >= 40

self প্রচলিত নাম, reserved keyword নয়। পাঠক আশা করে বলে রাখো। self.roll = roll-এ বামটি instance attribute, ডানটি কলের parameter। নাম এক হলেও storage এক নয়।

__init__-এর দুই underscore বিশেষ method চেনায়। Construction-এ Python ডাকে, আগেই তৈরি instance প্রস্তুত করে, instance ফেরায় না। Implicit None রাখো; অন্য মানে TypeError। বিশেষ construction পরে, সাধারণ record-এ নয়।

Reference আর attribute lookup

student.passed()-এ Python method খুঁজে student-কে প্রথম argument bind করে। বাড়তি self দেবে না। ধারণায় Student.passed(student) একই ordinary call। ফল ওই instance-এর marks থেকে।

Instance attribute সাধারণত এক অবজেক্টের। first.marks = 80-তে second.marks 55 থাকতে পারে। ক্লাস attribute ক্লাসে, override না করা instance পায়। school এমন shared তথ্য।

এই plain ক্লাসে read আগে instance, পরে ক্লাস। instance.school assign সাধারণত Student.school ঢেকে নিজের attribute বানায়, ক্লাস বদলায় না। Student.school বদলালে override নেই এমন instance-এর fallback বদলায়।

first  ----> Student instance: roll=12, marks=80
alias  ----> একই instance
second ----> Student instance: roll=25, marks=55
Student ---> school="Campus"

Assignment পুরো student নয়, reference copy। alias = first-এর পরে alias.marks update first-এও দেখা যায়। স্বাধীন state চাইলে আলাদা Student। Collection-এ একই reference আবার থাকতে পারে, তাই নাম আর অবজেক্ট আলাদা গুনো।

C জানা থাকলে

Instance C struct আর তার ফাংশনের মতো ভাবা যায়। Method binding self দেয়। পয়েন্টার parameter ঘোষণা বা manual free লাগে না, তবে alias একই mutable state দেখতে পারে।

বানাও, বদলাও, ownership তুলনা

বদলানো attribute কোন অবজেক্টের আগে চেনো। প্রথমে আলাদা student, পরে state বদলানো method, ক্লাস fallback আর shared-list ফাঁদ। সব পরিবর্তন ইচ্ছা করে, Python-এ নির্ধারিত।

দুই স্বাধীন marks card

দুই কলে আলাদা marks। passed self.marks পড়ে, তাই roll 12 pass, roll 25 নয়।

Method-এ balance update

deposit existing wallet বদলায়। দুই নাম একই wallet পায়, তাই returned balance আর alias-এর মান 125।

ক্লাস default ঢেকে দাও

first-এর নিজের room B। second ক্লাস fallback-এ যায়, যার room এখন C। ক্লাসও C দেয়।

Shared আর independent list

a 75 append করলে shared ক্লাস list b দিয়েও দেখা যায়। Separate y-এর নতুন list করে, সেটি empty।

প্রতি অবজেক্টের দায় স্পষ্ট

নিজস্ব list __init__-এ, যেমন self.marks = []। প্রতি construction-এ fresh। ক্লাস body-তে marks = [] এক shared list। Instance attribute বদলে না নিলে যেকোনো instance-এর append একই list বদলায়।

স্থির shared setting-এ ক্লাস attribute ভালো। সবার নিয়ম একই হলে Student-এ pass threshold। Course-ভেদে হলে ইনপুট বা instance-এর নিজস্ব মান। ডেটার অর্থ থেকে ownership ঠিক করো।

Method deposit বা passed-এর মতো অর্থপূর্ণ কাজ বলবে। অপ্রত্যাশিতভাবে সম্পর্কহীন অবজেক্ট edit এড়াও। ফল return করলে caller দেখানো, রাখা বা তুলনা বাছে। সব method-এ print ডেটার আচরণ আর presentation মেশায়।

Validation-এর স্পষ্ট boundary চাই। Nonnegative balance বললে invalid শুরু আর update একইভাবে reject। Exception পাঠে failure জানানো আসবে। আপাতত domain বলো, উদাহরণ তার ভেতর। Documented rule না হলে negative নীরবে সারিও না।

আরেক method-এর আগে change trace

দুই student আর প্রথমের alias-এর প্রতিটি নাম থেকে অবজেক্টে তির আঁকো। Alias-এ marks বদলাও। শুধু প্রথমটি বদলায়, দ্বিতীয় instance আলাদা। নাম গুনে আন্দাজের চেয়ে ছোট reference ছবি নির্ভরযোগ্য।

self.method()-এ একই অবজেক্টের আরেক method চলে। Interface নতুন value না চাইলে প্রতি update-এ replacement অবজেক্ট কোরো না। Counter increment সাধারণত নিজের state বদলায়, report নতুন text ফেরাতে পারে।

Attribute name অর্থপূর্ণ: student-এ x অস্পষ্ট, roll আর marks সম্পর্ক দেখায়। Plain ফাংশন আর method তুলনায় method self-এ receiver স্পষ্ট করে, caller ছোট bound call নেয়।

নাম কোন অবজেক্ট পায় দেখো

Method-এ self বাদ

Instance call নিজে instance দেয়। First parameter না থাকলে নিতে পারে না। Argument-count error পড়ে instance লাগলে self যোগ করো।

Attribute-এর বদলে local name

Method-এ marks = 90 local বানায়, self.marks বদলায় না। কল শেষে মান থাকতে হলে dotted রূপ।

ভুলে shared list

Mutable ক্লাস attribute instance-জুড়ে থাকে। __init__-এ বানালে আলাদা list। ভুল level copy-তে nested মান shared থাকতে পারে, যেমন list পাঠে।

Attribute-কে method-এর মতো কল

student.roll integer হলে student.roll() integer call করে ব্যর্থ। বন্ধনী call, শুধু dot attribute। আগে interface পড়ো।

Python version-জুড়ে সাধারণ ক্লাস

ক্লাস, __init__ আর method Python 3.10–3.12-তে চলে। এখানে সাধারণ instance dictionary। Property আর slot আচরণ বদলাতে পারে, তাই সহজ lookup শুধু plain ক্লাস-এর। এক underscore private access enforce করে না।

নকশা আর প্রতিটি record আলাদা

ক্লাস মানের দলকে দরকারি interface দেয়। __init__-এ নিজস্ব state, self-এ access, ইচ্ছাকৃত sharing-এ ক্লাস attribute। পরের ইনহেরিট্যান্স আর পলিমরফিজম-এ কয়েক type এক operation দেয়।
