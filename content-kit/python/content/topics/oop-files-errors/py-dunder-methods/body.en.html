Let ordinary Python operations understand your object

A marks collection should fit naturally into Python code. You may want print(record) to show a useful label, len(record) to count marks, or one result to compare with another. Special methods are named hooks that connect your class to these existing language operations.

Their names begin and end with two underscores, so people call them dunder methods. Dunder means double underscore. These names have specific contracts. Inventing __average__ does not make Python understand a new average operator. Define an ordinary average method for behavior without a language hook.

Operator support should make the object easier to reason about. Adding two distances has a clear meaning. Adding two students usually does not. Before implementing an operator, describe what it means, which operand types it accepts, and whether it creates a new value or changes existing state.

Choose the hook that matches the operation

Define special methods in the class body, with self first for ordinary instance methods. A binary operation such as addition receives the other operand too. Python invokes the appropriate hook when the related operation is used.

Use the normal operation in calling code: len(collection), not collection.__len__(). The ordinary operation can enforce extra rules. For example, len rejects a negative result. Calling a special method directly bypasses some language machinery and makes the caller harder to read.

Distinguish display from debugging

__str__ aims at a reader using the object. A balance might display as 250 BDT. __repr__ aims at a developer inspecting it, perhaps Balance(250). A representation should be unambiguous when practical. It need not always be executable code, especially for resources or complex objects.

If __str__ is absent, the default string conversion can fall back to __repr__. The reverse is not a general rule: defining only __str__ does not supply a custom repr. Containers such as lists normally show the repr of their elements. This explains why printing an object and printing a one-element list can look different.

Both hooks must return strings. Printing inside __str__ and returning None is a mistake. The caller requested a text value, not an extra print effect. Return a formatted string and let print decide how to display it.

print(value)  --> str(value)  --> value type's __str__
repr(value)   -----------------> value type's __repr__
print([value]) ----------------> element repr inside list text

Special method lookup for implicit operations normally happens on the type. Assigning a new __len__ function to one ordinary instance is not a reliable way to change len(instance). Put protocol implementations on the class. This differs from treating every implicit operation as a plain instance attribute call.

If you know C

C operators do not call user-defined functions based on struct types. Python dispatches supported operations through type hooks. These hooks still need precise contracts; convenient syntax does not decide what adding your domain objects should mean.

Handle unsupported operands without lying

__add__ can return a new object containing the combined value. It should normally leave both operands unchanged unless a different policy is clearly documented. The distance example adds two distances and returns another distance. Adding an unrelated string is not a supported operation.

Return the singleton NotImplemented when the operand type is unsupported. This tells Python to try the other operand's reflected operation where appropriate. If neither side supports addition, the expression raises TypeError. NotImplemented is a value, not the exception NotImplementedError, which serves a different purpose.

Reflected methods such as __radd__ support an operation initiated from the other side. Their dispatch also considers subtype relationships. You need not implement reflected operations in every class. Keep the accepted combinations small and document them. Supporting Distance + Distance does not automatically support 0 + Distance.

For equality, returning NotImplemented lets the comparison machinery consult the other operand. If neither side supplies equality, Python falls back to identity-based equality. Unsupported ordering behaves differently: a less-than comparison generally raises TypeError after both relevant sides decline it.

Define __lt__ if sorting your objects has a natural strict order. sorted uses less-than comparisons. It does not require __le__ merely to sort, and defining __lt__ does not automatically generate every other comparison method. A result object can compare a tuple of fields, such as (marks, roll), when ties need an explicit rule.

Make separate protocols agree

A length should count what the object represents. For a group of marks, len(group) is the number of marks, not their total. Return a nonnegative integer. A negative result raises ValueError through len, while a non-integer result causes TypeError. For very large lengths, the platform's size limit also matters.

If a class defines neither __bool__ nor an unusual truth rule, Python can use __len__ for truth testing. Length zero is false and a positive length is true. This makes empty custom collections behave like empty lists. State this meaning before relying on if group in a caller.

Equality needs a coherent rule. Comparing only marks means two records with different rolls may count as equal. Comparing both fields means a different model. Choose from the meaning of the object rather than from which field is easiest to type.

Objects used as dictionary keys must keep a stable hash while stored. Equal objects must have equal hashes. Python normally makes a class unhashable when it defines __eq__ without a suitable __hash__. This prevents many accidental mistakes. Do not force a hash onto a mutable marks list to silence an error.

A non-mutating value object is often easier to reason about than a mutable arithmetic object. If addition returns a fresh distance, aliases of the old distance keep their value. If later methods can mutate that distance, equality and hashing decisions need review. The next lesson introduces data classes that can generate several common methods.

Trace dispatch with a minimal public contract

Consider how a caller will use the class before adding another hook. A marks group may promise only readable text and a length. Supporting addition would raise a new question: should it concatenate marks, add corresponding marks or add totals? If the meaning is unclear, keep a named operation instead of overloading plus.

For a distance value, addition has a clearer meaning. Test a supported pair, confirm both operands retain their original values, then test an unrelated type and expect TypeError from the complete expression. Returning NotImplemented directly from a hook is only one stage; the expression's final behavior is what the caller observes.

Ordering tests should include ties. Two records with equal marks can still differ by roll, so a declared tie-breaker determines their final sequence. If two records compare equal under your chosen fields, their position under stable sorting should not be presented as a new ordering guarantee supplied by identity.

A representation test should inspect meaningful values rather than an arbitrary memory address. For a small value class, repr can include its constructor-like name and fields. When a class handles large or sensitive data, choose a useful summary instead of dumping every contained value.

Return the right kind of result

Returning an integer from __str__

Even when the stored value is numeric, the display hook must return str. Use an f-string or str(value). Python will not silently convert the wrong return type for you.

Returning False for every unfamiliar type

That may block another type from offering a meaningful comparison. Return NotImplemented for an unsupported operand and reserve False for a supported comparison that is unequal.

Mutating operands during addition

A caller usually expects a + b to leave a unchanged. Construct a new result for this value-like design. If you support mutation through another operation, explain it separately.

Assuming one ordering method supplies all comparisons

__lt__ supports less-than; it does not automatically define less-than-or-equal. Test each public operation you promise. Avoid implementing more operators than your model needs.

Keep protocol contracts explicit

The hooks shown work on Python 3.10–3.12. NotImplemented must be returned to the operation machinery, not treated as a normal truth value; its boolean use is deprecated in the demonstrated runtime range. Generated representations should not be treated as a stable file format. Use JSON or another explicit format for persistent data.
