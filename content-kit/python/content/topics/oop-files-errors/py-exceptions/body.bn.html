ব্যর্থতার খবর caller-এ ফেরাও

Integer-এর জায়গায় শিক্ষার্থী seventy লিখলে int পারে না, অন্য সংখ্যা না দিয়ে ValueError তোলে। Exception ব্যর্থতা বোঝানো অবজেক্ট, যা বর্তমান execution path থামায়। উপযুক্ত handler recovery বা ব্যাখ্যা দেয়।

Exception সফল ফল আর failure আলাদা রাখে। Zero mark বৈধ, ভুল ইনপুটেও zero দিলে তথ্য হারায়। Caller আবার চাইবে, record বাদ দেবে নাকি থামবে বাছতে পারে।

সব জায়গায় সব exception ধরতে হবে না। যথেষ্ট তথ্য দিয়ে কাজে লাগে এমন response যেখানে সম্ভব সেখানে ধরো। Calculation invalid argument বাদ দেয়, UI ব্যাখ্যা করে। Development-এ অপ্রত্যাশিত programming ভুল দৃশ্যমান রাখো।

নির্দিষ্ট exception type মেলাও

ঝুঁকির কাজ try-তে, প্রত্যাশিত type-এর except পরে। as-এর নাম exception object পায়। Message ব্যবহারকারীকে সাহায্য করে, কিন্তু interpreter-এর exact wording-এ logic নির্ভর নয়।

try:
    marks = int(text)
except ValueError:
    print("Enter a whole number")
else:
    print(f"Read {marks}")
finally:
    print("Input attempt finished")

Exception, return, break বা continue ছাড়া try স্বাভাবিক শেষ হলে else। একই except-এ পরের কাজের error না ধরতে successful কাজ সেখানে। Normal Python mechanism-এ statement ছাড়লে finally, handled বা unhandled exception-সহ।

Except ক্রমে দেখা হয়। Specific subclass broad parent-এর আগে। except (ValueError, TypeError) tuple-এ কয়েক type এক response। except ValueError or TypeError ওই tuple নয়।

Handler না মেলা পর্যন্ত stack ধরো

Raise হলে ওই try path-এর বাকি statement থামে। কাছে handler, না মিললে caller-এ propagate, কয়েক কল পার হতে পারে। কোথাও না মিললে traceback-সহ error report-এ প্রোগ্রাম শেষ।

Traceback error পর্যন্ত active call দেখায়। শেষে type-message পড়ে প্রাসঙ্গিক ওপরের line দেখো। গভীর line কোথায় failed, আগের frame মান কীভাবে এল বোঝায়।

Except named class আর subclass ধরে। ZeroDivisionError, ValueError, TypeError, KeyError আলাদা। Broad Exception input failure-এর সঙ্গে wrong variable বা missing attribute bug-ও লুকাতে পারে।

C জানা থাকলে

C library প্রায়ই return code আর errno-তে ব্যর্থতা বলে। Python exception matching handler পর্যন্ত call boundary পার হয়। সফল ফল সুবিধা বলে failure path ভুলো না, recovery কোথায় ঠিক করো।

Success, recovery আর propagation

Conversion উদাহরণ interpreter-specific message ছাড়া success-failure তুলনা। পরে domain error, higher-level cause chain আর cleanup। Print order-এ branch বোঝো।

সফল আর ব্যর্থ conversion

75 else-এ, seventy except-এ। দুটো path শেষে finally message।

Withdrawal error raise আর catch

Rejected withdrawal balance ফেরায় না। Handler controlled message, valid withdrawal 60 দেয়।

Invalid input-এর cause রাখো

Outer ValueError domain বলে, __cause__ original ValueError রাখে। বদলানো traceback নয়, type প্রিন্ট।

Pending return-এর আগে cleanup

Return value প্রস্তুত, finally cleanup প্রিন্ট। শেষ হলে caller 42 পেয়ে প্রিন্ট।

পরিচিত built-in error আলাদা

Lambda ব্যর্থ operation loop-এ কল হওয়া পর্যন্ত পিছিয়ে দেয়। Named tuple handler তিন আলাদা category বলে।

Domain failure-এর স্পষ্ট নাম

Supported type-এর invalid value-তে raise ValueError("marks must be from 0 to 100")। Type-ই unsupported হলে TypeError। Caller যেন message search ছাড়া category আলাদা করে।

Custom exception domain-specific category: InsufficientFunds(Exception) rejected withdrawal। Empty body-তে pass যথেষ্ট। Requested-available amount-এর মতো structured detail লাগলেই attribute।

যেখানে rule ভাঙে সেখানে raise, অন্য action বাছার জায়গায় catch। Error print করে normal-looking success ফেরিও না, caller সফল ভেবে এগোতে পারে।

Handler-এর bare raise বর্তমান error traceback context-সহ আবার তোলে। Layer log/cleanup করেও recover না পারলে নাও। Low-level থেকে domain-এ raise NewError(...) from original explicit cause রাখে।

সাধারণ domain error সরাসরি BaseException নয়, Exception থেকে। KeyboardInterrupt আর SystemExit বড় control category, routine recovery ভুলে গিলবে না। Bare except সেগুলোও ধরে।

Cleanup ফল থেকে আলাদা

আগে নেওয়া resource ছাড়ার মতো exit-এ দরকারি কাজে finally। Try-র return-ও এর মধ্য দিয়ে যায়। Normal control flow-এ নির্ভরযোগ্য, abrupt process termination বা power failure-এ নিশ্চয়তা নয়।

Finally থেকে return দিও না; pending result বদলায় বা active error চাপা দেয়। Cleanup সেরে আসল ফল-error যেতে দাও। Cleanup-ও ব্যর্থ হতে পারে, সহজ রাখো আর API জানো।

ফাইলে manual close-এর চেয়ে with পরিষ্কার। ফাইল পাঠে ব্যবহার, পরে context manager-এ protocol। Suitable context manager না থাকলে try/finally কাজে লাগে।

pass-এ error চুপ

Empty handler ব্যাখ্যা ছাড়া partial state রাখে। স্পষ্ট harmless case-ই উপেক্ষা, নইলে report বা propagate।

ইনপুট reject-এ assert

Optimized execution assertion সরাতে পারে। Required validation-এ condition আর raise। টেস্টিং পাঠে assertion-এর জায়গা আসবে।

আগে সাধারণ exception handling

Class আর try/except/else/finally Python 3.10–3.12-তে চলে। Exception group আর except* 3.11-এ, পাঠের বাইরে। User-facing stable ব্যাখ্যা নিজের দাও, সব release-এ wording একই ধরো না।

অর্থপূর্ণ boundary-তে recovery

Expected named failure ধরো, rule ভাঙলে clear error, result না বদলে cleanup। পরের ফাইল handling structured input, cleanup আর explicit format মেলায়।
